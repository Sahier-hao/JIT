# 冻结实验口径

来源、标签和六字段依据见 [DATA.md](DATA.md)。以下方案在读取正式效果前已冻结于本 change 的 design D2–D4；没有根据结果改变阈值、过滤、模型或测试集合。

1. 校验完整原始表的唯一身份、UTC 秒和六个有限非负字段。先按发布者窗口、la>0、la+ld≤10000、nf≤100依次纳入，分别记录排除数。空 bugcount→0，非空必须为非负整数，bugcount>0→1；fixcount 不进模型。
2. 升序不同时间数组长度 G，第 floor(0.70G) 和 floor(0.85G) 个值（从零计数）为边界。同秒不拆分，三个集合非空且互斥，训练与测试须两类。train=8669、validation=1852、test=1853，验证仅作流程检查，不参加拟合、调参或重拟合。
3. 仅按 ns,nd,nf,ent,la,ld 顺序取六字段。五项计数固定 log1p，ent 不变；标准化只拟合训练。L2/C=1/lbfgs/max_iter=1000/tol=1e-4/class_weight=None/seed=2026/单线程。scikit-learn 1.9 的 L2 参数为 l1_ratio=0.0（penalty 已弃用）。不收敛失败，不发布半成功运行。按 classes_ 找标签1的概率。
4. ROC-AUC 与 AP 采用 scikit-learn 官方实现；AP 是 Average Precision，非梯形 PR-AUC。分类固定 p≥0.5，Precision=TP/(TP+FP)，Recall=TP/(TP+FN)，F1=2TP/(2TP+FP+FN)。同时保留混淆矩阵和正负数量。分母为零返回 null 与原因；本应用单类目标的 ROC-AUC/AP 也记录为未定义。AP 无信息参考为正类比例；全负预测参考不算第二个训练模型。
5. `Recall@20%LOC (risk-ranked)`：每条工作量为原始 la+ld，预算=完整测试总 LOC×0.2；风险降序→UTC秒降序→完整ID升序排列。依次纳入完整提交，下一条会超预算即停止，不跳过、不拆分。召回=入选正标签提交数/完整测试正标签提交数。首条超预算且有正标签时为0；总LOC为0或无正标签时 null 并注明原因。保存总量、预算、实际量和入选数。它不是风险密度排序，不称 Popt。
6. 源数据、模型、环境、训练代码、标签／字段／分区／模型协议通过 manifest 关联。同锁定环境独立重跑，分区完全一致、风险与已定义指标绝对误差≤1e-8；文件逐字节一致不作为跨环境要求。请求仅读模型与无标签输入，标签只在离线评价中读取。

手算预言：标签[1,0,1,0]，风险[.9,.8,.2,.1]，LOC[1,1,4,4]，ROC-AUC=.75、AP=5/6、P/R/F1=.5；20%预算2包含前两条，Recall@20%LOC=.5。测试还覆盖同分时间排序、首条超预算、单类、无预测正类、零工作量和非法风险。

这些检查证明实现遵守该回顾性方案，不证明训练标签在历史当时已经可知，也不证明特征提取无未来信息。逐条标签可获得日期、SZZ链路和发布者特征提取实现尚未重新审计；课程完整模型、Kamei14、解释、在线预测与非功能验收仍需后续工作。

## 方法清单与按声明校验

以上 1～6 条是**六字段逻辑回归这一条协议**的记录，原文保留、不因方法扩展而改写。方法成为具名声明后：

- 每个方法以具名条目声明类别（经典／深度）、冻结超参、所需依赖、复现口径与解释口径；未注册的方法名以 `ALGORITHM_UNKNOWN` 拒绝，不退回默认方法。
- 产物校验按该运行**声明的算法**比对超参，不再与模块级常量比较；按声明的**依赖**校验环境——声明的包必须被当前环境以相同版本满足，不要求与当前环境全等；按声明的**指标集**重算指标。因此新增方法、新增依赖或新增指标都不会作废既有运行。
- 运行声明的模型标识由 (schema, 方法) 共同决定；同一 schema 下可有多个方法。
- 已登记方法：`logistic-regression-l2-v1`（经典，六字段逻辑回归，本文件 1～6 条即其协议）、`decision-tree-v1`（经典，用于检验契约能否容纳第二个方法，不替换服务所用的运行）。
- 覆盖缺口：课程要求两类合计不少于八种、深度不少于四种；当前经典 2 个、深度 0 个，**尚未达标**，缺口如实记录、不以参数变体凑数。
- 预测解释仍未提供；注册条目中的解释口径字段为空并写明原因。
- 复现口径按方法声明：现有两个方法都声明数值容差（绝对误差 1e-8，文件逐字节一致不作为跨环境要求）；将来随机初始化的深度方法应声明自己的独立协议，不套用该容差。

## 环境声明与跨机器语义

以上各节描述的是**单机链路**：训练、校验与产物都发生在同一台机器上。训练改在另一台机器进行时（例如在有加速设备的机器上训练深度方法），环境声明的含义与校验方式按下述约定，避免把"同一台机器"这个假设写进校验：

- **环境声明是本运行的产出环境**，字段为 `trainingEnvironment`（无该字段的旧运行回退到 `environment`）。产方如实声明平台、Python 与所用框架版本，**包括本机没有的训练框架**；不得为了让本机校验通过而省略依赖——该声明是运行身份的一部分，改写而不重算身份会被判为身份不匹配。
- **本机验证环境另记，不进运行声明**：`cli verify` 的输出在 `verificationEnvironment` 中给出本次校验时的本机环境。两者分开保存，互不覆盖。
- **平台或 Python 与本机不同不是失败理由**，而是分类依据：与该运行声明的产出环境一致时按"本机产生"校验，不一致时按"外部产生"校验。
- **本机产生**的运行，其声明的依赖必须在当前环境中以相同版本被满足（即上一节所述，该节其余内容不变）；**外部产生**的运行不以此为条件——本机满不满足它的训练环境，与本机能否加载并重算它无关。
- **准入以行为为准**：能否在本机**实际加载**该模型，以及用运行自带的无标签输入**重算**出的风险是否落回其声明的复现口径之内。声明的完备性不替代实际的加载结果。
- **数值口径按方法声明，不套用统一容差**：重算风险与交付的参考预测按该方法声明的口径比较（现有方法为绝对误差 `1e-8`）。**随机初始化的深度方法必须自带自己的口径**——本机推理与产方推理的设备／精度可能不同，`1e-8` 对在加速设备上产生的参考预测不适用；声明为独立协议（非数值容差）的方法，本机**不套用统一容差、也不静默接受**，其比较方式在该协议冻结后接入。校验输出记录本次所用的口径。
- 因此交付的模型必须能在**无加速设备**的机器上加载；在加速设备上序列化的产物在本机不可加载时以 `MODEL_INVALID` 拒绝并指出原因，不静默跳过、不降级为仅收档。

## 深度方法的随机性与复现（add-deep-tabular-methods）

- 深度方法在同一冻结声明（种子、超参、epoch）下训练；**不使用早停**，验证分区不参与拟合或调参。
- 复现按**实测数值容差**判定：先用同一冻结声明独立训练两次，记录风险与各指标差，再在方法条目声明覆盖该观测上界的 `atol`；不声称逐字节一致，也不以序列化文件哈希相同作为复现依据。
- 深度模型作为可 joblib 序列化的流水线末步接入，加载与推理契约与经典方法相同；所需框架（`torch`）在方法条目中声明，缺失时以明确错误拒绝。

## effort-aware 指标：Popt 与 IFA（add-effort-aware-metrics）

11. `Recall@20%LOC (risk-ranked)` 保持原定义：风险降序、20% 预算、整条提交前缀停止。它**不是 Popt**，二者不得互相冒名或合并成同一指标名。
12. `Popt` 为**全成本范围、density-ranked** 的归一化面积：成本 `c = la + ld`；模型按 `risk / c` 降序，oracle 按 `label / c` 降序、worst 取 oracle 反向；`x = 累计成本 / 总成本`、`y = 累计正例 / 总正例`，从 `(0,0)` 起按梯形求面积，`Popt = (A_model − A_worst) / (A_oracle − A_worst)`。同分按 UTC 时间降序、标识升序。总成本为 0、存在零成本提交、无正例或 `A_oracle == A_worst` 时返回 null 与原因。
13. `IFA` 为既有风险序下**首个正标签之前的负标签条数**；首个即正例时为 0；没有正标签时返回 null 与原因。
14. 手算预言：标签 `[1,0,1,0]`、风险 `[.9,.8,.2,.1]`、LOC `[1,1,4,4]` → 面积 `0.775 / 0.825 / 0.175`、`Popt = 12/13 ≈ 0.923077`、`IFA = 0`；标签改为 `[0,1,1,0]` 时 `IFA = 1`。
15. 指标集按版本声明：`metric-set-v1` 不含 Popt／IFA，`metric-set-v2` 含；跨指标集的运行不可直接排名，比较报告必须声明该差异。

## 代码语义特征与离线比较（add-code-semantic-features）

16. Git 采集只有显式 `--with-text` 才写文本 sidecar；默认采集与同步不变。文本规则 `diff-bound-v1` 固定为文件路径升序、每文件最多 80 行、每提交最多 8 KiB、跳过二进制，并在每条记录保留 `truncated`／`skippedFiles`。数据集 `text` 块登记文本 SHA-256、字节数、记录数、规则版本及截断/跳过总数。
17. 嵌入表固定使用 `microsoft/codebert-base` revision `3b0952feddeffad0063f274080e3c23d75e7eb39`、mean pooling、最多 256 token、768 维，离线 CPU 单线程生成。`meta.json` 记录编码器、revision、维度、池化、最大长度、文本 SHA-256、嵌入 SHA-256 与数量；加载时逐项校验。
18. `kamei14-semantic-codebert-v1` 输入为 14 个专家字段后拼接 768 维语义向量（782 维）；`code-semantic-codebert-v1` 输入仅 768 维语义向量。标准化只作用于专家块，log1p 只作用于 schema 声明的计数类专家列；纯数值 schema 的路径与矩阵不变。
19. 三种方案必须在同一数据版本、同一时间切分与测试成员、同一 `metric-set-v2` 和同一方法下并列。报告只披露指标与失败，不据测试指标自动择优；任一方案失败或缺指标时，整体不得声明为可直接比较。
20. 语义运行仅用于离线评估。六字段单条 JSON 预测接口不接受语义模型；无登记文本的数据集（包括 OpenStack 快照）不得运行语义方案，不得伪造空文本或零向量。

## 大型公开 14 维基准（add-large-jit-benchmark）

21. 本轮大型基准固定为 JIT-Fine `data.zip` revision `584799fdec6095ab75a45fd2a5f8db5b12163aa5`、SHA-256 `9e5ca1a393b70ee7e87c410b162005958775f3f3732f9f83da9dd24a7dfe2b47`。适配器 `jit-fine-v1` 同时校验 train/valid/test 三个成员哈希；不匹配不得进入导入。
22. `kamei14-benchmark-v1` 固定 `ns,nd,nf,entropy,la,ld,lt,fix,ndev,age,nuc,exp,rexp,sexp` 共 14 个入模字段。`lt` 按非负实数处理，其余计数按 schema 约束；标签、项目、提交身份和时间不进入模型输入。
23. JIT-Fine 的 `is_buggy_commit ∈ {0,1}` 是标签来源；规范 CSV 的 `bugcount` 只是运输列。运行来源必须记录 `jit-fine-is-buggy-commit` 规则，不得改写为发布者 `bugcount`。源包未声明许可证，原始数据和规范化 CSV 不随仓库分发。
24. 源表 27,319 条中有 1,653 条因负 `lt` 或 `age` 被适配器显式排除，不裁剪、不补值；既有 `la > 0` 规则再排除 64 条，最终 25,602 条、2,217 个正例。时间切分为 train 17,912/1,751、validation 3,847/310、test 3,843/156（样本/正例）。
25. 九种已登记方法必须在同一基准、同一时间切分、同一 `metric-set-v2` 下运行。报告同时披露 AP、ROC-AUC、Recall@20%LOC、Popt、IFA、训练耗时和失败；不得根据测试指标自动选择、淘汰或登记默认模型。
26. 本基准不接入六字段 JSON 预测接口、用户仓库同步或管理员模型策略。它只产生离线数据、运行、报告与证据，不改变现有服务行为。

## 多项目训练与迁移比较（add-multi-project-training-comparison）

27. 多项目正式实验固定四个独立 `kamei14-git-v1` 数据集，并要求同一采集窗口、简化 SZZ 规则、schema 与 `metric-set-v2`。每个项目分别按 UTC 时间去重后执行 70%/15%/15% 切分；任何口径都只在该项目自身 test 上报告该项目指标。
28. `local` 只使用目标项目 train；`pooled` 使用四项目 train 并集训练一次并评价四个 test；`leave-one-project-out` 使用除目标外的三项目 train；`global+local` 使用相同留一全局训练集和目标本地 train，两个模型只在目标 validation 上选择融合权重后评价 test。
29. `global+local` 的全局权重取固定网格 `0.00, 0.05, ..., 1.00`，以目标 validation Brier 分数最小为准；同分取较小全局权重。test 标签不得进入拟合或权重选择，报告必须记录权重、验证样本数、验证正例数、Brier 与选择数据。
30. 每个方法、训练口径和指标以项目为等权单位汇总宏平均和总体方差。AP、ROC-AUC、Recall@20%LOC、Popt、F1 以低值为差，IFA 以高值为差；未定义指标不填零，汇总记录定义数量、参与项目与未定义原因。
31. 训练、预测、融合或评价失败必须保留方法、口径、目标项目、阶段、错误码和原因；单组合失败不阻塞其余组合，项目或方法只有部分成功时状态必须是 `partial`，不能计为完整。
32. 报告记录四份数据描述及 CSV 哈希、来源 URL、HEAD、分区身份摘要、训练项目集合、代码哈希、环境和耗时。报告不得包含自动默认、自动淘汰或“最佳方法”结论，也不得接入在线服务。
