分支分析用于回查某个分支的历史提交，生成固定的提交级模型分数。风险趋势只汇总同口径的成功分析，用来看已保存结果随时间的分布，不是真实缺陷率。

## 前置条件 {#before-start}

- 项目已经登记公开 GitHub 仓库，或当前服务端凭据可以读取该仓库。
- 当前用户至少有一个「可用于仓库分析」的兼容模型；本人模型需先登记，管理员开放模型需保持启用。
- 分支名称正确。留空时使用项目登记的默认分支。

如果模型选择器为空，继续阅读[模型列表为空](#/docs/faq?section=empty-models)。「检查分支更新」只检查远端跟踪分支并管理提醒，不会自动开始分析。

## 发起一次分支分析 {#run-analysis}

1. 打开项目，切换到「分支分析」。
2. 点击「分析分支提交」。
3. 选择分支，并在模型列表中选择明确可用的兼容模型。
4. 点击「开始分析」。

提交后任务依次经历排队、采集、登记和评分等阶段。页面顶部和右上角统一任务入口会显示服务端真实阶段；离开项目后仍可追踪到终态。

分析会固定你选择的模型。之后管理员修改默认模型，不会替换这次任务或已保存结果。失败重试也沿用原模型；原模型不可用时会要求重新选择，不会静默换模型。

## 打开并阅读结果 {#read-result}

成功分析会以固定结果卡和一条历史记录出现：

1. 在分析记录中找到成功结果，或在页面打开的当前结果中查看。
2. 看最上方的模型分数分布。分档阈值是 `0.25` 和 `0.10`；未评分单独计数，不并入低分档。
3. 查看「优先回查的提交」，再从「查看提交明细」打开该固定分析。
4. 使用搜索、日期和排序筛选提交。筛选只改变当前列表，不会重算分数。

页面显示「未评分」时表示该提交没有纳入当前模型的分数，不能当作 0 或低风险。覆盖不完整时，页面会说明范围；不要把缺失提交补成“没有问题”。

## 下钻一条提交 {#open-commit}

点击提交标题打开提交详情。详情可能包含：

- 固定分析中的模型分数和提交信息。
- 后续修复提交回找到当前提交的缺陷引入证据。
- 原始变更度量、模型与数据来源、解释方法与限制。
- 可用的模型解释。

证据状态可能是「有引入证据」「观察期内未发现」「观察期未满」或「观察覆盖未知」。这些状态只描述历史观察，不等于当前代码已被证明无缺陷。

需要检查某条提交的模型敏感度时，在详情中选择当前模型支持的解释方法并点击「生成模型解释」。解释绑定原分析、提交、模型和运行，刷新后可读取已保存结果。

## 查看风险趋势 {#risk-trend}

在「分支分析」切换到「风险趋势」：

1. 确认分支、模型与运行、特征 schema 和分档规则构成的可比口径。
2. 设置起止日期和按日、周或月聚合，生成视图。
3. 分别阅读「平均模型风险分」和「高分提交占已评分提交比例」两条单轴折线。
4. 展开逐周数据或点击时间段查看固定来源提交。

同一口径要求模型身份、运行、schema 和分档规则一致。不同口径不拼接，不用模型名称相似来猜同一口径。没有可拼接来源、来源被删除、内容指纹变化或同 SHA 冲突时，页面会说明不可用或拒绝整组，不能把失败视图当作 0。

趋势只使用本项目已保存的分支分析。来源分析未覆盖的时间段显示未知或空白，不画成 0，也不跨空档连线。已评分样本少于 20 时高分占比不显示。高分是模型分档，不是缺陷率。

分析有新结果时，旧固定视图不会自动纳入；需要时重新生成视图。日期按作者时间 `UTC+08:00`、左闭右开分桶。

## 常见失败和提示 {#failures}

| 页面提示 | 含义 | 下一步 |
| --- | --- | --- |
| 模型列表暂时不可用 | 模型目录接口读取失败 | 点击重新读取，再核对后端 |
| 没有可用模型 | 无可见、启用、ready 且 schema 兼容的模型 | 登记本人模型或请管理员开放 |
| 原选模型已停用、未开放或不可用 | 保存的模型选择不能继续 | 显式重选兼容模型 |
| 分析失败 | 采集、登记、评分或来源阶段失败 | 打开记录详情，修正后显式重试 |
| 没有同口径趋势 | 来源模型、运行、schema 或分档规则不一致 | 重新选择可比口径或单次分析 |
| 未评分提交 | 模型没有为该提交生成保存分数 | 人工阅读，不按 0 处理 |

下一步阅读[怎么看风险分和代码线索](#/docs/reading-results?section=commit-score)，避免把模型排序、静态规则和缺陷率混为一谈。
