## 公开仓库和私有仓库分别需要什么 {#private-repository}

公开 GitHub 仓库的 PR 列表和文件读取不需要浏览器保存 GitHub 令牌。私有仓库的 PR 同步会在服务端检查仓库可见性，并明确提示需要 GitHub 访问凭据。

当前实际行为是：服务端从 `JIT_GITHUB_TOKEN`、`GITHUB_TOKEN`、`GH_TOKEN` 或本机 GitHub CLI 读取凭据。个人中心的「关联 GitHub」用于检测本机是否已有可用凭据，不会把令牌写入浏览器。页面提示私有仓库时，先把有权限的凭据配置到运行后端的机器，再回到项目刷新 PR 列表。

如果配置后仍失败，服务端凭据可能无权读取该仓库，或 GitHub 暂时不可用。不要根据缓存中的旧 PR 列表推断访问权限。

## GitHub 授权后为什么仍然读不到 PR {#github-access}

依次检查：

1. 运行后端的环境是否真的设置了 GitHub 令牌，或本机 `gh auth status` 是否已登录。
2. 令牌是否对该仓库有读取权限。
3. 个人中心显示的是“已检测到授权”还是“未关联”。
4. 项目 PR 区域是否明确提示 `PR_PRIVATE_REPOSITORY`、限流或来源不可用。
5. 重新加载项目并点击「刷新 PR 列表」。

个人中心检测成功只说明服务端能读到某个 GitHub 账户；它不保证该账户拥有目标仓库权限。切换或撤销权限后需要重新检测。

## 模型列表为空怎么办 {#empty-models}

模型选择器只列当前用户可见、已启用、产物 ready 且与当前特征 schema 兼容的模型。列表为空通常有四个原因：

- 没有本人登记的模型。到「我的训练」完成训练，并对具体成功方法点击「登记到模型库」。
- 管理员开放模型为空或已撤销。请管理员在管理工作中确认模型已启用并开放。
- 模型不兼容当前仓库分析字段。查看模型详情中的 schema 与不兼容原因。
- 模型列表接口失败。点击「重新读取」；仍失败时检查后端服务。

原选模型停用、未开放或不再兼容时，页面会保留一个禁用项并要求重新选择，不会静默换成默认模型。详见[从数据到训练、预测与评估](#/docs/data-training-evaluation?section=paths)。

## 仓库读取限流怎么办 {#rate-limit}

项目概览和 PR 列表保留上次成功缓存，并说明限流或来源暂时不可用。可以：

- 稍后重新加载或刷新，不连续触发大量分析。
- 检查服务端 GitHub 凭据和剩余额度。
- 继续阅读已保存的固定 PR 快照，不把缺失条目当作已关闭或低风险。

限流不是低风险结论。若列表未完整加载，页面会显示覆盖边界。

## 分析失败后怎么重试 {#analysis-failure}

打开对应分析记录查看失败阶段、错误码和原因。分支分析、单 PR 分析和批量分析分别在原范围重试。重试沿用原模型；模型已停用或来源失效时，页面要求显式处理，不自动换模型。

如果失败来自会话、权限或 GitHub，先修复前置条件再重试。已有成功结果会继续保留，不会被失败任务覆盖。

## 为什么没有「去评估」或模型评估入口 {#evaluation-unavailable}

预测批次要进入正式评估，需要保存的风险、模型身份和可用的真实标签。只有同时包含可靠正例与负例的已保存批次才显示「去评估」；无标签、只有单一类别、手工特征或单条项目提交结果不进入正式评估。

训练结果要先在「我的训练」登记具体模型，再从训练记录进入「模型评估」。没有可评估训练、训练尚未成功或模型未登记时，页面会给出原因。标签状态和指标含义见[缺陷标签与评估指标](#/docs/labels-and-metrics?section=evaluation-metrics)。

## 文档里的操作打不开 {#docs-links}

文档可以匿名阅读，但具体项目、工作单和模型地址仍要求现有登录。点击后进入登录页是正常边界；登录后会回到可用目标。若地址指向已删除项目或未知文章，页面会显示空状态和返回入口。
