审查页面常同时出现提交分数、文件排序、静态规则命中和行级研究排序。它们回答的问题不同，不能互相替代。

## 提交级风险分是什么 {#commit-score}

提交级风险分是模型根据该提交的变更与历史特征给出的 0 到 1 排序分数。它是一个未经当前仓库概率校准的模型估计，不是“有 80% 概率存在缺陷”。

例如页面显示 `0.80`，更稳妥的理解是：在这次固定模型的排序中，这条提交应优先核对。0.80 不表示八成的提交会坏，也不表示审查者已经有缺陷证据。页面使用 `0.25` 和 `0.10` 两个分档阈值；低分也不代表安全。

适用条件：

- 该提交属于当前固定分析范围，并且已由页面显示的模型评分。
- 分数只对当前模型、特征 schema 和当前提交有效。
- 模型未提供、分析未完成或提交未评分时，页面显示未知或未评分，不能用 0 代替。

下一步动作：先打开分数较高的提交，阅读真实 Diff；有作者说明时对照目标；再决定是否记录问题。分数不能单独作为合并、阻断或缺陷结论。

## 文件阅读顺序怎么看 {#file-order}

PR 文件列表可以按风险或路径排序。按风险时，文件依据“该文件涉及的已评分提交中的最高分”排列，用于安排阅读顺序。

这只是排序参考，不是文件级缺陷概率。一个文件排在前面的原因可能是它被高分的提交触及，而不是文件本身已经被证明有问题。旧分析或没有提交到文件映射的数据，可能只能保持路径顺序并显示说明。

下一步动作：从高分文件开始，但仍以 Diff 和证据为准；需要时切回按路径阅读，避免遗漏同目录中的实现与测试。

## 代码线索先看哪一层 {#code-clues}

PR 预览和工作单里的“代码线索”可能是提交级分数、文件阅读顺序、静态规则命中或行级研究排序。先看页面写明的来源和覆盖，再决定下一步：

- 提交级分数用于决定先看哪条提交。
- 文件顺序用于决定同一提交中先打开哪个文件。
- 静态规则标记具体源码模式，需要阅读上下文。
- 行级研究只排序支持语言的新增行，不写入草稿。

任何一层都不等于“确认缺陷”。把线索转成问题时，必须补上实际代码位置、观察到的行为和人工判断。

## 静态规则命中是什么 {#static-rules}

在 PR 预览或工作单选择文件后，点击「检查当前文件」可以读取当前固定版本的静态规则结果。规则在 Diff 或固定源码的行号旁显示标记，点击可查看原因和建议。

当前规则包括可变默认参数、裸 `except`、`eval/exec`、`subprocess(shell=True)`、缺少 Loader 的 `yaml.load`、`requests(verify=False)` 与 `tempfile.mktemp`。文件列表同时保留规则命中、无命中和未覆盖状态。

这些是源文件中的静态模式命中，不是模型概率，也不是已确认缺陷。规则可能误报，也可能覆盖不到当前文件。下一步动作是阅读命中位置的上下文，确认输入来源、调用者和测试；需要时把该位置加入问题草稿并写明证据。

## 行级研究排序是什么 {#line-research}

代码阅读区可能提供「行级排序（研究）」或「行级证据」。首版研究排序只对当前固定 PR 快照中真实新增或修改的 JavaScript／TypeScript 行排序，使用这些行的文本与结构特征。

页面固定标注“研究排序，不是缺陷概率”。点击结果只定位到该行，不会修改草稿、提交分数、默认模型或合并状态。支持的语言或新增行不足时，页面会说明原因，不会静默换用另一个模型。

下一步动作：把行级结果当作阅读提示，不当作自动定位结论。真正的问题仍需代码证据和人工判断。

## 解释、修复证据和分数不要混在一起 {#explanation-and-evidence}

| 页面信息 | 说明 | 不能推断 |
| --- | --- | --- |
| 提交风险分 | 模型对该提交的排序估计 | 真实缺陷概率 |
| 模型解释 | 输入特征对当前分数的敏感度 | 缺陷原因或因果 |
| 缺陷引入证据 | 后续修复回溯到当前提交的历史证据 | 当前 PR 一定需要修复 |
| 静态规则命中 | 源码中的规则模式 | 行级概率或已确认缺陷 |
| 行级研究排序 | 新增行的研究性排序 | 行级缺陷概率 |

固定版本很重要。作者推送新代码后，新的分数、新的规则结果和新的行级候选不能覆盖旧轮判断；需要复核时从新版本重新核对。

## 什么时候应该忽略分数 {#when-to-ignore}

- 提交未评分，或模型未就绪、已停用、与新 schema 不兼容。
- 分析覆盖不完整，页面说明缺失范围。
- 分数来自不同模型、运行或分档口径，却被拿来比较趋势。
- 行级研究结果被用于替代人工代码阅读。

这些情况下继续人工审查是正确路径，而不是等待一个不存在的高置信度结论。
