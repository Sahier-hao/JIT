PR 审查分成只读详情和个人工作单。只读详情用于快速核对固定快照，工作单用于记录阅读进度、问题草稿、代码证据、作者更新后的复核和最终 Markdown 意见。

## 只读预览先看什么 {#preview}

在项目「PR 审查」选择 PR 后，先进入只读详情：

1. 核对 PR 状态、作者说明、基准与目标分支、文件与提交覆盖。
2. 看「模型分数」是否有结果，以及固定的是哪个模型。
3. 按风险或提交顺序浏览提交；点开一条提交后只显示它触及的文件。
4. 选择文件，在 Diff、基准源码和目标源码之间核对实际代码。

只读详情不写入个人草稿，也不能在这里选择模型或发起分析。需要记录判断时点击「创建审查工作单」。

## 工作单和代码证据 {#work-order}

工作单绑定当前固定版本。左侧文件列表、Diff 和问题面板共同工作：

- 点击代码行可以固定证据到基准侧或目标侧，并关联当前问题。
- 「检查当前文件」会读取当前版本的静态规则结果；命中表示规则模式，不是确认缺陷。
- 文件可以标记「已阅读」「需要复查」「暂未覆盖」。
- 问题可以关联实现与测试文件，同一问题可保存多条位置证据。

记录问题时至少写清：具体位置、实际行为、预期行为、证据和仍需验证的部分。提交分数只帮助你安排阅读，不能代替问题描述。

## 草稿、保存和账户隔离 {#draft}

草稿保存当前浏览器已确认账户下的 PR、固定版本、问题、证据、阅读状态和结论。页面提示保存失败时，正在编辑的文本仍留在本页，可以重试或「导出完整草稿」。

「导出完整草稿」生成包含各轮记录的本地 JSON，不包含凭据。它不是给作者看的最终审查意见。恢复备份时先预览归属和差异，默认不覆盖当前判断；不同账户的备份需要明确确认。

登录身份未确认、退出或会话失效时，页面撤下旧账户内容并停止旧页面保存。迟到请求不会写入新账户。

## 作者推送后如何复核 {#updates}

1. 在工作单点击「检查 PR 更新」，或在项目 PR 列表刷新个人工作。项目开启自动跟踪时，服务端也会生成站内提醒。
2. 新版本存在时，工作单提示新轮次；当前阅读不会自动被切换。
3. 点击「开始复核新版本」后，新基准和目标代码单独保存。
4. 已变动的已读文件需要重新核对；相关问题保留旧判断和旧证据，并标记待复核。
5. 填写复核理由，确认旧问题是否已解决、暂缓或撤回。

新旧轮次分别保存。新分数、新提交或代码删除不会自动关闭旧问题，也不会用新版本覆盖旧证据。基准变化可能使原先已读范围失效，需要重新核对。

远端关闭或合并后，个人结论和草稿仍保留为历史。个人关注、暂停和结束状态不等同于 GitHub 正式评审人状态。

## 输出意见和导出 {#export}

在「输出意见」选择本轮结论并填写说明，点击「检查版本并预览意见」。确认时会再次核对远端；如果发现新版本，需要先复核或明确按旧版本交付。

保存后可「下载 Markdown 意见」或复制意见。导出内容包含实际代码版本、已读和未覆盖范围、人工问题、建议和证据位置；个人笔记不会自动附带。首版不会把意见发送到 GitHub。

## 哪些内容按版本或轮次保存 {#revision-data}

| 内容 | 保存口径 |
| --- | --- |
| PR 标题、作者说明、文件 Diff | 每个固定快照 |
| 问题、证据、阅读状态 | 创建问题时的版本及当前轮次 |
| 作者更新后的复核 | 新轮次，不覆盖旧轮 |
| 本轮结论与 Markdown | 当前固定版本 |
| 个人笔记和反馈 | 当前账户的本地工作单 |

需要核对历史时，从版本与说明入口切换已保存轮次，不要用最新 Diff 解释旧问题。

## 常见失败 {#failures}

- **读取失败**：当前地址和本地工作保留，使用「重新读取」。
- **保存失败**：不要立即刷新；重试或导出完整草稿。页面明确说明尚未保存时，不能假定已落盘。
- **证据位置不可读**：原版本和位置仍保留，页面会说明不能打开，而不是替换成新代码。
- **工作单提示待复核**：先确认旧问题是否仍成立，再决定解决或保留。

需要理解分数和规则命中时，打开[怎么看风险分和代码线索](#/docs/reading-results?section=commit-score)。
