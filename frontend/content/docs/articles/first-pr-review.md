这篇指南带你从零完成一次公开 GitHub PR 的只读审查，留下带代码位置的问题，并导出 Markdown 意见。示例地址会变化，因此文中给出选择 PR 的条件，不依赖某个固定链接。

## 开始前先准备什么 {#before-start}

- 本机后端和前端已经启动，并且你知道当前产品的访问地址。
- 有一个可访问的公开 GitHub 仓库，仓库中存在开放、非草稿的 PR。
- 有一个本机用户账户。没有账户时可在登录页切换到注册。
- 模型分数是可选线索。没有可用模型时，仍可阅读 Diff、记录问题和导出人工审查意见。

如果没有可用模型，先在「我的训练」完成一次可训练数据上的训练并「登记到模型库」，或请管理员开放兼容模型。模型列表的排查见[模型列表为空](#/docs/faq?section=empty-models)。

## 选一个适合练习的公开 PR {#choose-pr}

选择示例 PR 时优先满足这些条件：

| 条件 | 原因 |
| --- | --- |
| 仓库公开、许可允许阅读 | 不需要私有仓库凭据 |
| PR 开放、非草稿、改动较小 | 教程可以在一次阅读中完成 |
| 至少修改一个文本文件 | 能展示 Diff、行号和代码证据 |
| 作者说明清楚 | 可对照作者目标检查实现 |
| 不含密钥、客户数据或真实账号 | 练习记录不会带入敏感信息 |

可以替换成任意符合条件的公开 PR。不要为了练习向陌生仓库提交评论；本产品的首版只在本地保存和导出意见，不会自动发到 GitHub。

## 登录并添加项目 {#add-project}

1. 从 `#/` 选择「用户工作区」。
2. 登录已有账户，或切换到注册并建立本机账户。
3. 进入[项目](#/projects)，点击新建项目，填写仓库地址，例如 `https://github.com/owner/repository`。
4. 确认后进入项目工作台。

添加项目只登记仓库，不会自动开始分支分析。首次进入后先看「概览」的仓库信息即可。

## 打开 PR 并判断有没有模型线索 {#open-pr}

1. 在项目页切换到「PR 审查」。
2. 如果列表未刷新，点击「刷新 PR 列表」。该动作只读取远端 PR 列表，不会拉取分支代码或运行模型。
3. 选择目标 PR，点击「查看 PR」。
4. 先阅读标题、作者说明和文件范围，再判断页面顶部的「模型分数」区域。

可能出现三种情况：

- **已有分数**：看到「有分数」、最高分和模型名称。分数只用于安排核对顺序。
- **尚无分数**：仍可点击「创建审查工作单」并人工阅读代码。若要补充模型线索，可在 PR 列表选择兼容模型后分析。
- **分析失败或模型不可用**：保留人工审查；不要等待或假定低风险。按页面原因处理，模型列表问题见[常见问题](#/docs/faq?section=empty-models)。

## 创建个人工作单 {#create-work-order}

在只读预览点击「创建审查工作单」，页面进入当前固定 PR 版本的个人工作单。

工作单把每轮代码版本和个人记录分开保存。作者之后推送新版本时，旧问题、旧证据和旧结论不会被自动改写。首版草稿保存在当前浏览器的已确认账户下；退出或切换账户后，不会继续展示上一账户的草稿。

## 用代码证据记录一个问题 {#record-evidence}

1. 在文件列表选择要阅读的文件。
2. 在 Diff 中点击实际有疑问的新增行或删除行；点击行号会把位置固定到基准侧或目标侧。
3. 在问题面板填写「问题、疑问或建议」，选择记录类型。
4. 在「人工判断」写清当前证据能支持什么、还需要什么。
5. 必要时展开「关联实现与测试文件」，把同一问题的相关文件放在一起。
6. 在「位置与证据」中为每条代码位置补充证据说明，例如「异常分支未覆盖」「这里改变了公开参数含义」。

只写“可能有问题”不能形成可复核证据。更有效的记录是：代码位置 + 实际行为 + 为什么可能出错 + 还缺什么验证。

如果页面提示「尚未保存」，先重试保存；需要离开时用「导出完整草稿」保存本地 JSON 备份。完整草稿与最终 Markdown 意见不是同一种文件。

## 导出 Markdown 审查意见 {#export-markdown}

1. 点击工作单顶部的「输出意见」。
2. 选择本轮结论：建议修改、本轮审查完成或暂缓并说明原因。
3. 填写说明与未完成事项，点击「检查版本并预览意见」。
4. 核对预览中的固定版本、问题、代码位置和未覆盖范围。
5. 点击「确认保存本轮结论」。
6. 在已保存结论下点击「下载 Markdown 意见」。

下载成功后会得到本地 `.md` 文件。首版不会自动发送到 GitHub，也不会代表远端已批准或合并。个人笔记默认不会自动附带；需要分享时先检查预览内容。

## 常见失败和下一步 {#failures}

| 现象 | 处理 |
| --- | --- |
| PR 列表提示私有仓库 | 先看[私有仓库访问](#/docs/faq?section=private-repository)，确认服务端凭据后再重试 |
| 模型列表为空 | 训练并登记兼容模型，或请管理员开放模型 |
| GitHub 限流 | 保留上次缓存，稍后重试；不要用缓存缺失推断 PR 已关闭 |
| 分析失败 | 打开分析记录查看阶段和原因，修正后显式重试 |
| 登录失效 | 重新登录；原账户的未保存恢复副本不会写入新账户 |
| 无法导出 Markdown | 先确认本轮结论已经保存；未完成时可用「导出完整草稿」保留工作 |

完成后，继续阅读[怎么看风险分和代码线索](#/docs/reading-results?section=commit-score)理解页面上的分数、规则命中和研究排序分别意味着什么。
