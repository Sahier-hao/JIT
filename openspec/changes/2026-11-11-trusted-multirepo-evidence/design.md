# 设计：可信模型证据与多仓库闭环

## Context

产品已有九种训练方法、内置九模型包、项目分析与行级研究预览。此前的验收停在“功能可用、小样本通过”，缺少三类可核对证据：新环境导入是否完整、分析标签是否来自模型真实成员、多个仓库与完整候选集上的效果是否可测。本轮在此基础上补齐数据与模型证据链，不重做登录、入口、模型卡等既有能力。

## Goals / Non-Goals

**Goals**

- 内置模型包在声明的支持环境下完整导入，失败可定位，历史失败逐项解释。
- 项目分析与趋势的提交分区来自冻结成员，未知谱系如实降级。
- 多仓库真实数据可批处理、可恢复、可核对来源与标签。
- 固定协议下产出多方法、仓库内时间外与留一仓库评价，以及完整候选集上的行级定位指标。
- 上述事实接回现有数据、训练、模型与项目页面，形成可重复使用的闭环。

**Non-Goals**

- 不承诺行级模型进入产品分析、PR 审查或默认模型。
- 不把弱标签当作人工金标准，不声称真实缺陷检出率。
- 不扩成多租户项目权限系统；普通用户与管理员边界沿用现状。
- 不追求模型必须战胜简单基线；负结果同样是有效结论。

## Decisions

### D1 复现校验比较“同类对同类”

产物中的指标与时间桶聚合是冻结参考预测的函数，不是本机重算的函数。校验分两层：模型重算对比参考预测，按方法声明容差；记录的派生聚合对比参考预测，严格相等。这样既保留跨 CPU/框架版本的数值容差，又保留对篡改的可检测性。备选方案是放宽指标比较容差，但指标对风险排序敏感（一个并列反转可改变第四位小数），无法用风险空间的容差表达，且会削弱篡改检测。

### D2 谱系核对集中在一个模块

`model_lineage` 同时服务项目分析与风险趋势：加载模型、读切分成员、核对策略与成员摘要、核对数据版本。迁移 030 之前的运行没有策略摘要，改为按“成员数 = 声明计数”核对，并在覆盖说明里标注 `memberVerification`。备选方案是让每个调用方各自实现，会出现两套口径，已有审计已证明两处判断不一致。

### D3 分区语义显式命名

`train/validation/test` 只表示成员；`excluded` 表示不满足纳入规则；`notIncluded` 表示满足规则但不在本次训练成员；`holdout` 是训练截止后的时间视图；`unknown` 表示无法核对谱系。留出数量与分区分布来自同一批提交，避免“数量来自时间过滤、分布来自标签”的不同总体。

### D4 批处理复用既有采集与 SZZ

批处理只负责编排：任务清单、固定 revision、阶段进度、失败与恢复。标签仍由既有 `collect` 与 `szz` 生成，产出新的数据版本；旧版本文件不改写。恢复以内容身份（仓库、revision、参数、SZZ 版本）判定，重复提交返回同一批次。

### D5 实验矩阵先冻结再运行

数据版本、成员指纹、特征、预处理、超参数与种子在看到评价结果前固定。随机方法与随机基线使用 42/43/44 三个种子；确定性方法只运行一次。失败格保留，不静默替换仓库或模型。

### D6 完整候选集与抽样研究分离

完整候选集从真实 diff 导出，逐行记录身份与标签状态；旧抽样结果保留为历史对照，不与完整总体混算。不可覆盖的正例计入覆盖率，不换成全文件总体。

### D7 触发与 IDE 只读、默认不阻断

CI 入口只上传报告，不评论、不设合并门禁；触发时固定 base/head 与模型身份，fork 事件不接触凭据。扩展在身份或工作树不一致时拒绝定位并说明原因。

## Risks / Trade-offs

- 旧模型没有成员摘要，只能做计数核对；比摘要弱，覆盖说明会单独标注，不当作等价。
- 多仓库采集受网络、限流与磁盘预算影响；不足门槛的仓库进入不足清单，不降低门槛凑数。
- 完整候选集评价计算量高于抽样；以仓库和提交分块执行，失败可重试。
- 触发与 IDE 的远端条件可能不可用；交付可执行配置并明确标注未验收部分。

## Migration Plan

- 数据库：无新增迁移时保持原状；若批处理需要新表，按既有迁移编号追加，升级前用 SQLite backup 生成一致副本。
- 模型与数据：不改写既有产物与版本；内置包与旧模型身份保持，新包版本另行发布。
- 回退：停止新后端，恢复升级前数据库与对应代码；数据与模型目录不被覆盖，可直接回退读取。
