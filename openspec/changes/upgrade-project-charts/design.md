# Design

## Context

仓库概览与项目风险趋势是两个独立的数据面：前者读取 GitHub 公开事实，后者只聚合项目自身成功的分支分析。当前两者都由手写 SVG/CSS 绘制，图表能力（悬停、响应式、主题）各自维护；活跃度数据受限于最近 100 条提交的抓取窗口。

## Goals / Non-Goals

- Goals
  - 仓库活跃度获得足够的观察跨度（近一年），并能清楚区分完整周与进行中的本周。
  - 两类图表共享一套渲染、主题与交互实现，视觉一致、可键盘操作、带等价数据表。
  - GitHub 统计接口不可用时仍能展示可解释的活跃度，不画零值或示例数据。
- Non-Goals
  - 不改变风险趋势的分桶、去重、口径与来源规则。
  - 不引入客户端状态管理或改变数据获取层。
  - 不迁移管理员验证报告页的历史趋势图（其图表语义不同）。

## Decisions

### D1 使用 ECharts 6 的模块化构建与 SVG 渲染器

只注册折线、网格、提示与轴指示器模块，渲染器选用 SVG：产物比完整包小，在 jsdom 测试环境中不依赖 Canvas 实现，同时保留 ECharts 的坐标轴、提示与响应式能力。图表颜色从现有 CSS 令牌读取，主题切换时重建配置，不引入第二套配色。

### D2 活跃度读取 GitHub 默认分支最近 52 周统计

`GET /repos/{owner}/{name}/stats/commit_activity` 一次返回 52 周的周起始时间与提交总数；相比分页抓取提交列表，请求数与限流压力更可控。统计接口可能返回 202 或解析失败，此时回退到已有的最近 100 条提交的 12 周聚合，并把覆盖范围写回 `activityCoverage`（`last-52-weeks` / `last-100-commits`）。服务端缓存格式升级为 v4、前端本地概览快照键升级为 `overview-v2`，旧缓存自动失效并按需重取。

### D3 保留风险趋势的交互契约

ECharts 负责渲染与悬停提示；图表容器保留键盘入口（左右方向键移动所选时间段、Home/End 跳转、回车下钻），点击数据点仍调用原下钻逻辑，等价数据表继续作为无鼠标与读屏路径。未知分数保持空值断线，不补零。纵轴上限按数据收紧到 0.25 的整数倍（仍从 0 起），避免常见的小比例挤在底部；上限与刻度始终可见。

### D4 主题与可访问性

统一从 `--project-series`、`--line`、`--fg-3` 等现有令牌取色，并监听 `data-theme` 变化重建图表；单序列不显示图例，图表标题说明度量；每个图表下方保留覆盖范围说明与等价数据表。分类色采用已验证的六色顺序，浅色下低对比色相由图例文字和表格补偿。

### D5 语言构成使用环形图并限制分段

语言构成是部分与整体的关系，改用环形图；按字节排序最多展示六个分段，超过六种时前五种保留、其余聚合为「其他」，避免颜色继续增加。HTML 图例逐项列出语言、占比与字节数，颜色只作辅助识别；同时提供等价数据表。概览布局改为卡片按自身高度排列，不再被相邻长卡片拉伸。

## Risks / Trade-offs

- GitHub 统计接口对部分仓库首次请求返回 202 或较慢：以回退数据兜底，并在界面标注覆盖范围；不把它当作完整历史。
- ECharts 增加前端依赖体积：采用按需注册模块并只进入项目页异步分块，首包不引入。
- jsdom 无布局尺寸：图表初始化使用容器测量值并提供显式宽高回退，测试不依赖具体像素。
- 当前周数据不完整：曲线包含进行中的本周，提示中明确标注，避免把下降误读为提交减少。
