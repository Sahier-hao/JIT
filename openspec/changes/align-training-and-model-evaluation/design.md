## Context

现有训练执行器已保存 `splitPolicy`、分区样本、阈值预览、逐轮历史和模型运行谱系；用户训练页面也已有排队、取消、重试、损失曲线和登记入口。评估能力则分散在训练比较与“模型试算”中，现有用户训练登记按整个实验批量执行，历史预测批次的阈值预览又把所有 `0/1` 标签视为同一总体。

本次设计需要在既有数据、模型身份和风险算法上补齐工作流。训练切分仍由 UTC 时间去重组和固定成员摘要决定；模型仍由显式登记进入模型库；评估只读取已保存风险或冻结产物，不重新训练、不改变默认模型，也不自动选择“最佳模型”。

## Goals / Non-Goals

**Goals:**

- 用一个可校验的切分策略对象统一预设和自定义比例的预览、任务身份、执行和重开显示。
- 把训练成功与模型登记分开，并允许对每个成功方法登记明确模型。
- 用一个独立评估页面承接训练固定分区和已保存预测批次，显示统一身份、阈值、标签资格和指标。
- 为正式评估与探索性复核建立硬边界，并兼容旧预测批次。
- 让真实隔离浏览器旅程成为切分、训练、登记、评估和故障状态的交付证据。

**Non-Goals:**

- 不修改分类算法、特征定义、风险分数含义、默认模型或已有发布门槛。
- 不引入随机切分、重叠分区、自动调参、自动择优或跨方法统一排名。
- 不为旧预测批次补造成熟状态、真实标签或正式评估结论。
- 不把模型登记、阈值评估或“模型详情”变成可修改模型内容的功能。

## Decisions

### 1. 切分策略是一个规范化对象，而不是新的一套切分实现

API 继续接受既有 `splitPreset`，并新增可选的 `splitRatios`。两者互斥；未提交时仍使用 `temporal-70-15-15`。后端将两者规范化为同一策略视图：

```json
{
  "kind": "preset",
  "id": "temporal-70-15-15",
  "ratios": {"train": 70, "validation": 15, "test": 15}
}
```

或：

```json
{
  "kind": "custom",
  "id": "temporal-custom-65-20-15",
  "ratios": {"train": 65, "validation": 20, "test": 15}
}
```

比例必须是正整数且合计 100。实际成员仍按 UTC 去重时间组排序，并以当前确定性规则计算边界，因此目标比例与实际样本比例可能因时间组大小略有差异，页面必须同时显示二者。自定义策略的规范 ID 写入既有 `split_preset` 字段，完整比例、边界、计数和成员摘要写入既有 `split_policy_json`，不新增数据库列。

预览响应增加实际策略对象和 `memberSha256`。执行训练后比较产物中的成员摘要与预览策略；不一致时失败且不登记模型。这样既不复制切分算法，也能证明预览与执行一致。

替代方案是新增一张切分策略表，但当前策略已经能由数据版本、准入身份、比例和算法版本确定，新增表只会扩大迁移范围。

### 2. 训练可用性采用明确的最小门槛

三档都必须包含样本；训练集、验证集和测试集都必须同时包含正例与负例。该规则同时服务训练、验证集阈值探索和正式测试，避免出现无法计算完整指标却进入正式评估的“成功训练”。失败响应包含具体分区、样本数、正例数和建议修改的比例，不改用其他预设。

自定义比例只改变成员边界，不改变训练算法、特征 schema、类别策略或发布算法。重试复用原策略，不读取当前默认比例。

### 3. 训练成功与模型登记是两个状态

训练任务成功后保留未登记状态，只有用户显式选择某个成功方法并完成目录准入后，才产生可选模型。每次实验可包含多个方法，因此登记 API 必须携带明确的 `taskId`；服务端验证该任务属于当前用户、状态成功、尚未登记且产物可验证。登记失败只影响该模型，不改变整个实验的训练结果。

前端使用新的明确操作「登记到模型库」。目录返回的 `modelId`、`runId`、方法、schema 和数据版本写回该训练任务，然后训练详情才出现「评估本次训练」。重复登记按原运行身份幂等复用，不按指标自动选择其他方法。

既有实验级批量登记入口保留为兼容路径时可继续用于管理员或旧客户端，但用户工作流 MUST NOT 在未选择方法时调用它。新的精确登记路由加入 OpenAPI，由清单工具重新计算当前操作数。

### 4. 独立评估页面复用已有评分和冻结产物

新增用户路由 `#/model-evaluation`，不改写已有预测批次 URL。页面包含两个来源：

- `training`：携带 `experimentId`、`taskId` 和 `modelId`，读取冻结分区与保存的风险。
- `prediction`：携带 `batchId`，读取已保存批次，不重新调用模型。

训练来源复用实验比较读取和阈值评估接口；阈值评估接口从一个或两个不同任务中选择，保持现有双模型比较行为，同时允许单模型正式复核。验证集用于选择缺陷阈值，测试集仅用冻结分数、固定成员摘要和用户确认后的固定阈值计算。

预测来源复用批次详情。创建新批次时增加标签资格和可靠阈值摘要；旧批次没有该摘要时按原标签预览保持可读，但明确标为探索性复核。前端不批量下载两万条记录自行计算正式指标。

替代方案是新建统一持久化评估资源，但当前需求只要求可重开已有结果和核对口径，冻结训练产物与不可变预测批次已经提供事实来源。

### 5. 正式评估采用可靠标签白名单

统一评估合同包含：

```json
{
  "mode": "formal",
  "partition": {"kind": "test", "memberSha256": "..."},
  "threshold": 0.62,
  "labelPolicy": {
    "version": "mature-binary-v1",
    "included": ["positive", "mature-unobserved"],
    "excludedCounts": {"immature": 3, "unknown": 2, "unrecorded": 1}
  },
  "sampleCounts": {"included": 40, "positives": 8, "negatives": 32},
  "metrics": {"precision": 0.5, "recall": 0.75, "f1": 0.6},
  "unavailableReason": null
}
```

`positive` 和已证明成熟的 `unobserved` 可进入正式二元总体；`immature`、`unknown` 与 `unrecorded` 不作为负例。排除后缺少任何一类时返回 `formalAvailable=false`，但可保留明确标注的探索性视图。旧批次、旧模型或旧数据集不推断成熟状态。

### 6. 页面以同一状态机保护对象切换

训练、训练详情和评估页面都以实验/任务/批次标识作为请求代际。来源、模型、阈值选择变化时中止旧请求；即使底层请求不可取消，也要丢弃不属于当前代际的响应。状态区分排队、运行、成功未登记、已登记、失败、取消和中断。

训练损失只在存在逐轮记录时绘制；经典方法完成后显示“没有逐轮记录”。所有图表使用同一渲染数据生成等价表格，表格是数据事实来源，图是辅助视图。文案统一使用「登记到模型库」「模型详情」「缺陷阈值」；算法库解释怎么训练，模型库展示当前可用的登记模型。

## Risks / Trade-offs

- [严格的最小样本与类别门槛会拒绝部分小型数据集] → 返回精确分区统计和建议比例，不退回不可信的正式指标。
- [目标比例与时间组实际比例不完全相同] → 同时显示预设比例和实际分区计数，以成员摘要而非仅比例判断身份。
- [单个评估接口承担训练和批次两种来源，合同容易混杂] → 使用共享指标字段和明确的 `source`、`mode`、`partition`、`labelPolicy` 判别字段，不把缺失字段当作默认值。
- [精确登记改变旧前端实验级批量行为] → 新用户调用必须携带 `taskId`；旧批量路径仅作受控兼容，不进入新页面，测试覆盖新路径与重复登记。
- [旧预测批次无法追溯成熟状态] → 保持只读为探索性复核，不回填、不改写历史内容。
- [OpenAPI 新增精确登记与预测评估操作会改变总数] → 清单和矩阵均从 OpenAPI 生成，当前 113/109 基线在新契约生成后自然更新，禁止另存固定副本绕过漂移检查。

## Migration Plan

1. 先扩展切分策略解析和只读预览，保持旧预设与省缺参数行为不变。
2. 增加训练任务的规范化策略字段输出和失败原因；旧任务缺失策略时按原记录显示，不重新计算成员。
3. 增加精确模型登记路由并更新 OpenAPI；旧批量登记暂时保留但不作为新页面主路径。
4. 为新建预测批次保存标签资格和可靠阈值摘要；历史批次不迁移。
5. 增加模型评估页面、路由和文案；旧 `/my-predictions/:batchId` 地址继续打开原批次。
6. 重新生成前端 API 类型、操作清单和四类场景矩阵，更新集成报告与冻结证据。

回滚时保留已保存任务、批次、模型和评估结果；前端可回退到原训练/试算页面，后端新增字段在旧消费者中忽略。不得删除或重写已登记模型及历史批次。
