## MODIFIED Requirements

### Requirement: ITD-01 95 个业务 API 操作清单

交付包 SHALL 以人工维护的 OpenAPI 契约作为事实来源，从契约生成当前业务 API 操作的机器可读清单，并在清单中记录源契约 SHA-256、生成时间、总操作数、业务操作数以及 4 个独立列出的 admin 认证操作。本 change 增加精确模型登记操作后，当前基线 SHALL 与生成结果一致：103 个总操作、99 个业务操作和 4 个 admin 认证操作，不得继续使用旧的 95/99 计数。

每项业务操作 MUST 记录方法、路径、operationId、认证/角色边界、风险等级和至少一个对应测试或明确的未覆盖原因。清单与契约的操作数量、方法、路径或 operationId 不一致时 MUST 校验失败并列出漂移项。更新 OpenAPI 后 SHALL 重新生成清单、类型和矩阵，不得只修改文案计数。

#### Scenario: 清单完整

- **WHEN** 审核者在当前提交运行清单工具
- **THEN** 得到 103 个总操作、99 个业务操作和 4 个 admin 认证操作
- **AND** 每项业务操作都有方法、路径、operationId、角色、风险和测试映射

#### Scenario: admin 认证单独说明

- **WHEN** 清单统计业务 API 操作数量
- **THEN** setup、login、session、logout 在单独章节列出
- **AND** 不将其静默计入或丢弃

#### Scenario: 契约漂移

- **WHEN** OpenAPI 新增、删除或改变操作而清单或类型未同步
- **THEN** 校验失败并列出新增、缺失、重命名和计数漂移
- **AND** 不继续生成“完整覆盖”结论

### Requirement: ITD-04 测试工具与框架

交付包 SHALL 提供可重复执行的工具入口，从 OpenAPI 生成当前操作清单、校验业务操作数与四类矩阵、运行后端/接口/前端/浏览器测试，并输出机器可读结果。工具 MUST 从生成清单取得期望业务操作集，MUST NOT 在矩阵校验器中另写一个会漂移的固定业务操作总数。

工具 MUST 复用现有 pytest、OpenAPI 契约测试、前端单元测试和 Playwright 隔离服务测试；空套件、缺失映射、陈旧测试节点或静默跳过 MUST 使校验失败。当前改动新增或改变的训练、切分、模型登记和评估旅程 SHALL 使用真实隔离服务，验证生成清单、四类场景矩阵、受影响测试、typecheck、lint、build、OpenAPI 类型检查和浏览器截图的一致性。

#### Scenario: 从契约生成清单

- **WHEN** 审核者在干净检出上运行清单工具
- **THEN** 从 `docs/api/openapi.yaml` 生成当前业务操作清单并报告 admin 认证排除项
- **AND** 矩阵直接以该清单为期望范围

#### Scenario: 覆盖校验

- **WHEN** 某操作或某类场景缺少映射
- **THEN** 校验失败并指出操作、场景类别和缺失原因

#### Scenario: 工具失败

- **WHEN** 依赖安装、测试执行、结果解析或证据冻结失败，或证据指向旧提交
- **THEN** 命令以非零状态结束并保留日志
- **AND** 不生成通过报告

#### Scenario: 真实训练评估旅程

- **WHEN** 浏览器测试运行训练与评估链路
- **THEN** 使用真实隔离后端、独立数据库和产物目录完成切分预览、训练、登记、评估和故障恢复
- **AND** 不以拦截或伪造业务 API 响应替代正式联调证据
