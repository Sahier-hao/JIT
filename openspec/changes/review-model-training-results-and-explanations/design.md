## Context

训练实验 API 已返回 `metricsByPartition`、实际参数、状态、错误和耗时，管理员任务详情也能展示三档指标；缺口集中在管理员实验比较页和用户训练页没有完整呈现这些事实。解释能力当前固定使用 `occlusion-mean-v1`，持久化主键为 `(sync_id, commit_id)`，因此同一提交只能保存一份解释。

本设计基于现有训练、模型目录、固定分析和证据机制增量演进，见 `proposal.md`。不改模型风险算法、训练注册表、默认模型或审查工作流。

## Goals / Non-Goals

**Goals:**

- 让管理员和普通用户从同一实验契约核对 train/validation/test 三档指标及实际训练参数。
- 建立可扩展的解释方法目录，允许同一提交保存和比较多种解释。
- 以确定性、可安装、适合 CPU 本机服务为约束，先交付两种语义不同的解释技术。
- 保持旧训练记录、旧解释、旧 API 调用和已保存结果可读。

**Non-Goals:**

- 不新增训练方法、不自动超参数搜索、不根据验证或测试指标自动选最佳方法。
- 不实现 SHAP/LIME 的通用采样平台，不引入 GPU 解释服务。
- 不把解释扩展为因果分析、缺陷确认或代码行定位。
- 不改变模型风险、项目分析、PR 审查和个人审查状态。
- 不在本 change 中实现 IDE 或集成测试交付；它们作为后续独立 change。

## Decisions

### 三档指标由现有比较契约直接驱动界面

实验 API 已经返回三档指标，PR1 不新增训练任务字段，只把共享的三档指标展示组件用于管理员实验页和用户训练页。比较导出继续使用同一 JSON，避免页面显示与导出各算一套。

替代方案是新增比较专用 API；当前数据已经完整，新增 API 只会增加身份漂移和重复校验，因此不采用。

### 解释方法使用独立注册表而不是继续写死单一方法

新增解释方法声明，至少包含：

- `occlusion-mean-v1`：模型无关；以训练分区均值为基线，输出风险概率变化。
- `linear-logodds-v1`：仅适用于逻辑回归；用模型系数乘预处理后输入与基线的差，输出 log-odds 贡献。

每个声明包含方法标识、显示名称、适用范围、贡献单位、基线口径、计算成本、确定性和限制。模型是否支持方法由模型估计器和 schema 共同决定。未知或不兼容方法直接拒绝。

替代方案是直接引入 SHAP 或 LIME。这会增加依赖、安装和随机采样复杂度，且当前表格模型可用精确线性分解与模型无关遮挡覆盖两类不同语义；后续可继续增加方法而不改接口。

### 同一提交按方法保存解释

持久化键从 `(sync_id, commit_id)` 扩展为 `(sync_id, commit_id, method)`。旧记录迁移时使用其已保存方法；没有方法字段的旧记录按当时默认 `occlusion-mean-v1` 保留。同一方法重复生成幂等返回，新方法生成不覆盖其他方法。

替代方案是用一个 JSON 字段保存方法数组。这样会让并发更新互相覆盖，也无法按方法独立校验和查询，因此不采用。

### 旧接口保持兼容，新增方法选择能力

保留现有单数解释 GET/POST 路径的默认行为，并增加可选方法参数和按提交列出全部已保存解释的能力。请求未指定方法时继续走默认遮挡法；已有客户端无需同步升级。

替代方案是直接替换为集合 API。这样会破坏现有提交详情和 PR 预览调用，因此不采用。

### 前端使用方法选择、条形图和等价表格

解释结果按方法切换显示，条形图使用贡献绝对值排序，表格保留本次值、基线、带符号贡献和方法单位。多个方法并列时只比较方向、主要特征、排序稳定性和限制，不把概率变化与 log-odds 相加或共享排名。

替代方案是只展示表格。表格保留为无障碍等价内容，但图形更能呈现贡献方向与相对大小，因此图形和表格同时保留。

### 三个 PR 按依赖拆分

1. PR1：训练三档比较呈现，只改前端和契约测试，可独立交付。
2. PR2：解释后端方法注册、线性贡献算法、迁移、API 和持久化，不改前端。
3. PR3：解释前端方法选择、图表和多方法比较，消费已稳定的后端契约。

每个 PR 都必须单独通过自己的单元与回归检查；PR3 完成前 change 保持活动。

## Risks / Trade-offs

- [两种方法的贡献单位不同] → 在方法目录、图表、表格和导出中固定标注 `probability` 或 `logit`，禁止跨方法求和。
- [线性分解只在预处理后成立] → 对逻辑回归复用实际流水线变换，贡献和必须等于输入与基线的 log-odds 差。
- [旧解释迁移后方法身份不完整] → 保留原 payload，迁移只补默认方法键；读取不重新推理。
- [多方法导致 UI 信息过载] → 一次只展示一个方法的详细图，其他方法只显示摘要，显式点击切换或并列。
- [新增方法扩大解释攻击面] → 方法必须白名单、模型支持判定、输入边界和错误降级复用现有规则。

## Migration Plan

1. 在应用启动前备份 SQLite 目录库。
2. 新增迁移 040：创建带方法键的解释表，复制旧记录，使用已保存方法或默认遮挡法回填，再替换旧表。
3. 旧 payload 保持不变；重复迁移幂等。
4. 回滚时恢复迁移前数据库备份；已保存解释、训练记录、模型和风险不重算。
5. 发布前在数据库副本上验证迁移前后旧解释数量、同步/提交归属和 payload 哈希不变。
