# Proposal

## Why

当前系统把仓库审查、历史验证、手工特征预测和资源维护放在同一层，且仓库、分析批次与页面上下文未稳定绑定；单纯改样式无法解决“看的是谁的数据、下一步做什么”的问题。两项旧 change 已按实际状态带缺口归档，现在需要以整体任务和数据关系重新设计产品，并把已经实现的后端能力接入可验证的完整流程。

## What Changes

- 建立“仓库工作区 / 实验室 / 设置”的空间边界：普通用户从仓库接入、分析状态、提交详情走到审查计划；模型登记、历史验证、手工预测与结果重开各归其位。
- 将仓库与最近成功分析作为稳定上下文；请求中的同步与可查看的成功结果分别展示，支持按分析身份查询和回到同一视图，解决失败换分支、迟到响应与翻页期间重新同步导致的数据混用。
- 重做接入引导、提交列表—详情、审查计划及实验室页面，建立统一的文字、状态、反馈、主题和密度规则。原型是交互方向，不要求沿用旧三栏、组件结构、CSS 或静态示例布局。
- 补齐真实使用需要的提交标题、可选作者和原始提交外链；原始度量与模型解释明确分开。可选信息缺失如实呈现，不将原型内容写成真实数据。
- **BREAKING（界面导航）**：新路径按仓库/分析和实验对象组织；旧模型、预测结果、历史验证和同步链接提供显式兼容映射，已保存 batchId 重开与公开历史访问继续可用。
- **BREAKING（展示与本地计划格式）**：风险改用明确的模型分数，仓库提交总数不称“待审”；仓库审查计划升级为带分析来源的条目，旧 localStorage 保留并提供受控迁移，禁止无提示继承旧分数。
- 承接审计中的排序、成功视图分支、上下文隔离、预算/解释误报、断点与验证覆盖缺口；不把旧任务勾选视为已有验收。

## Capabilities

### New Capabilities

- `workspace-navigation`: 产品空间、对象路由、返回与刷新恢复、连接设置及旧链接兼容，保证用户始终知道当前任务和数据对象。

### Modified Capabilities

- `repository-collection`: 仓库实体、最近成功分析上下文、按指定分析读取、稳定服务端查询及提交显示元数据。
- `commit-risk-review`: 来源边界、分数语义、可扫描查询、详情及原始改动入口、带版本来源的审查计划与旧存储迁移。
- `interface-presentation`: 提升中文阅读层次，以任务为主的可适配工作区和一致素材规则，取消对固定三栏及自绘技术的不必要绑定。
- `model-prediction-workbench`: 实验室内独立可达的模型、手工预测和结果重开入口，集中设置连接凭据，保留已实现的推理与保存契约。
- `defect-trend-dashboard`: 把固定历史趋势归入历史验证，下钻始终返回同一历史运行而非当前仓库，保留公开可达、缺失反馈和等价文本视图。

## Impact

- 前端：重新划分空间与领域模块；重构 App/AppShell/navigation、仓库加载、列表详情、shortlist、接入、模型/预测/结果/趋势页及样式。保留有效功能与测试意图，不要求保留旧文件边界。默认复用现有 React/TypeScript/Vite 工具链，不为换框架而迁移。
- 后端与契约：复用 FastAPI/SQLite、现有采集训练与推理链；增量增加成功分析上下文、可选视图参数、显示元数据与错误状态，必要时新增向前兼容迁移。无需重训历史模型或重新采集生产仓库。
- 兼容：旧公开历史入口、旧六字段模型、目录权限、解释响应和保存结果不可变规则继续有效；受保护请求仍服务端鉴权，凭据不进入 URL 或存储。
- 验证：真实本地 Git 夹具与隔离目录库、双仓库/双分析/失败分支/迟到响应、历史下钻、模型预测重开、键盘与两桌面视口、存储迁移和离线资源。模型效果与界面验收分别报告。
- 文档：保留原需求/设计模板，实施时同步产品状态、路由与 OpenAPI；审计依据见 [收尾报告](../../../docs/审计/2026-10-19-change-closeout.md)。
- 本轮不新增账号、多用户审查结论、跨设备计划、完整训练任务平台、模型自动比较排名、内置代码 diff 编辑器或尚无真实接口支撑的图表。实验室先完整承接已有能力，扩展通过可追溯的接口继续演进。
