# Design

## Context

动机与范围见 [proposal.md](proposal.md)。现状和验收边界见 [收尾审计](../../../docs/审计/2026-10-19-change-closeout.md)。旧两项 change 在 `2026-10-19` 带未完成任务归档，delta 未同步；所以新规划依据当前主规格和已验证源码，不依赖旧 delta 已成立。

当前可复用：FastAPI/SQLite 仓库、作业和提交；真实采集—登记—选择模型—打分链；分页 API；持久模型目录；六字段预测、支持的归因和不可变结果重开；公开历史批次、趋势及旧模型兼容。React/TypeScript 前端已有凭据代次、取消请求、查询状态、错误反馈与本地清单机制。仓库详情目前不提供独立成功视图分支，作者名未落提交库，仓库归因未提供；实验室也没有多运行目录、全量预测历史或训练任务 API。

会话原型仅确立安静、可读、列表与详情协作、仓库/实验分离的方向。其样例作者、示例 diff、两套假设评估数据、手机布局与按钮不能当成正式接口或全部产品需求。设计需要覆盖真实长标题、旧记录、无凭据、采集中、错误、空结果和迟到响应。

## Goals / Non-Goals

**Goals:**

- 以对象与任务组织整个产品，明确项目、成功分析、提交、模型、保存结果之间的关系。
- 普通用户走通接入—查看分析—选择提交—核对改动—形成审查计划；实验用户独立使用现有模型与验证能力。
- 先修复来源一致性和状态语义，再形成可复用的视觉与交互规则。
- 改导航同时保留真实接口、旧模型、权限、历史数据和保存结果的可用性。

**Non-Goals:**

- 不把审查计划扩成团队工单或已审结论，不增加账号和跨设备同步。
- 不迁移技术栈作为独立目标，不强制复刻旧侧栏、三栏、组件文件或原型的每个尺寸。
- 不新增完整训练/实验调度平台、自动模型排名或代码编辑器；不重训模型以证明界面改变有效。

## Decisions

### D1 对象模型先于页面

```text
Repository --> Sync job (requested branch, stage, error)
           --> Successful analysis (syncId, actual branch, data, model)
                --> Commit list / detail / source summary
                --> Personal review plan (browser + origin + analysis)

Lab --> Public historical run --> Replay / summary / trends
    --> Registered model --> Manual feature prediction --> Saved batch

Settings --> Connection (memory only) / appearance
```

请求作业和成功分析是不同对象。当前最新请求可以失败，而用户仍查看上一次成功分析；顶部必须分别显示二者。选择“查看最新成功分析”时才改变分析身份；新作业完成只提示可切换，不自动替换当前列表、详情或计划。

考虑过只保存 selectedRepositoryId：它无法保证翻页、详情和统计跨请求的一致性，也无法解释旧计划的分数来源。采用 repositoryId + viewSyncId 的完整键，前端请求代次另含 credentialGeneration。

### D2 产品空间与页面责任

| 空间 | 页面/主任务 | 数据边界 |
| --- | --- | --- |
| 仓库工作区 | 项目入口、接入、作业状态、提交列表/详情、审查计划 | 选定仓库与成功分析 |
| 实验室 | 公开历史验证/趋势/回放、模型目录及受控登记、手工预测、打开保存结果 | 数据/运行、模型或 batchId；不继承仓库效果含义 |
| 设置 | 连接凭据、外观与密度 | 应用级设置；凭据仅运行内存 |

仓库没有数据时打开接入/状态入口；不以一个巨大的零指标仪表盘充当首页。项目切换器可遍历所有仓库页，不能永远只展示 API 第一页。日常导航不要求理解 schema、产物候选或训练参数；高级分析策略仍可核对与显式选择。

实验室先承接已有能力。公开历史服务只提供一个配置运行时，直接展示它，不创造原型中的运行列表。模型目录只能展示各自真实可得来源和状态；没有评价摘要就标注未提供，不从公共历史摘要借指标。保存结果只提供已知编号/链接重开，直到另一个 change 真正实现全量历史查询。

### D3 可恢复的对象路由

使用现有 hash 部署方式，重建路由模型；不必为本轮加入路由框架。路径由一个模块产生与解析，不在页面拼接散落 mode/sync 条件。

| 新路径 | 用途 |
| --- | --- |
| `#/projects` | 项目入口；根路径首次进入这里 |
| `#/connect` | 接入新仓库与新作业进度 |
| `#/repositories/{id}` | 解析最新成功分析后 replace 为规范地址；没有分析时展示状态 |
| `#/repositories/{id}/analyses/{syncId}/commits` | 固定分析的提交列表 |
| `#/repositories/{id}/analyses/{syncId}/commits/{sha}` | 同一分析的详情；宽屏嵌入侧区，窄屏独立呈现 |
| `#/repositories/{id}/analyses/{syncId}/plan` | 该分析的个人计划 |
| `#/lab/history/{runId}/commits`、`.../trends` | 同一公开历史运行的验证和下钻 |
| `#/lab/demo/commits` | 明确标识的人工演示，版本来自演示文件 |
| `#/lab/models`、`#/lab/predict` | 模型与手工特征预测 |
| `#/lab/results`、`#/lab/results/{batchId}` | 按编号打开与同一保存结果 |
| `#/settings/connection`、`#/settings/appearance` | 设置与原目标返回 |

在标签页 sessionStorage 中可记非秘密的最近规范仓库目标；无法读写则继续正常导航。搜索/筛选草稿与已打开详情按对象键保存在本次运行状态。URL 的起止日期仍按现有 CRR-05 初始化，手工修改后的刷新仍遵循现有地址种子规则。不要以列表排序第一项作为丢失上下文的替代。

旧路径兼容由单独 adapter 负责：旧模型/预测/结果/趋势/验证直达新同源目标；带 sync 的地址先查询其真实 repositoryId 再转换；旧 shortlist 根据显式 mode/sync 或可验证的最近上下文恢复。没有足够身份时显示来源选择，不能猜仓库。保留有效日期，不保留凭据；未知参数或不存在对象有明确反馈，映射后 replace 防止浏览器后退循环。

当前 `/api/review-batch` 只返回服务配置的历史运行。新历史地址中的 runId 必须与响应匹配；旧运行不再供给时说明不可用，不悄悄展示新运行。不新增能读取任意服务器路径的“实验记录 API”。

### D4 成功分析契约与查询固定

增量扩展现有 API，不另建一套采集/打分服务：

| 契约 | 增量行为 |
| --- | --- |
| `GET /api/v1/repositories` | 保留分页与既有字段，补可解释的最新作业/成功分析概要 |
| `GET /api/v1/repositories/{id}` | 可选 `viewSyncId`；返回与所选成功作业绑定的 `viewContext`，并单独返回 `latestSync` |
| `.../{id}/commits`、`.../commits/{sha}`、`.../summary` | 可选同一 `viewSyncId`；返回仓库和分析身份供前端核对 |
| 创建/查询同步 API | 保留现有授权、输入、策略、幂等进行中作业与错误行为 |

`viewContext` 至少包含 repositoryId、syncId、branch、completedAt、headCommit、datasetVersion、modelId、runId、modelStrategy、degradeReason、distributionRule 与 limitations；缺失可选字段使用 null 和原因。HEAD 必须来自采集产物记录的真实 HEAD，不按最大提交时间猜测。`latestSync` 包含其自己请求分支、创建时刻、状态、阶段与失败原因；不能用它的字段补齐旧分析。

未传 viewSyncId 时保持旧客户端读取最新成功视图的行为。传入时校验作业存在、属于仓库且已完成；建议错误码分别为 `REPOSITORY_ANALYSIS_UNKNOWN`、`REPOSITORY_ANALYSIS_UNAVAILABLE`，沿用既有错误信封与成员鉴权。成功分析固定查询仍可直接复用 repository_commit 的 sync_id，统计由同一集合求出。

新迁移 005 只增加必要可选显示字段（例如提交 author_name、作业 completed_at）；上下文尽量从成功作业/受控产物派生，避免复制一个独立 mutable “分析表”。新作业完成时原子提交结果和完成时间；旧记录缺失值如实返回未提供。已有 defaultBranch 等字段不突然改语义，标注不应作为成功分析分支使用。

时间排序修正为 epoch DESC、commit_id ASC；风险排序继续 risk DESC、epoch DESC、commit_id ASC。将此排序变化写入 OpenAPI 和回归，API 数值、模型输入和既有预测身份不变。列表 total、详情和分布均来自所选分析，不能重复取最新仓库计数。

### D5 提交详情帮助用户回到改动

采集链已经读取作者与标题，但仓库提交库尚未保存作者名。新记录可增量写入 authorName；旧记录缺失不强制重新采集，不把邮箱作为显示名。可选元数据不进入模型 features、不改变已登记 schema 或历史数据集 hash。

首版原始改动入口只支持经过规范化的公开 GitHub 仓库 HTTPS 提交页，完整 SHA 必须与当前记录一致；本地路径和不支持的站点给出复制完整 ID 与原因。不要拼接含 userinfo、令牌或任意脚本 scheme 的地址，不在页面加载时抓取外站。外部链接由用户显式打开，不增加内置 diff 编辑器。

仓库未返回解释时只显示原始度量和解释未提供。实验室手工预测已有 PEX 响应时按真实状态、方法和方向展示，不能因为原型没有该区就删掉已实现解释。

### D6 审查计划及存储迁移

计划属于 browser + origin + sourceContext。仓库键包括 repositoryId/viewSyncId/datasetVersion，历史键包括 project/datasetVersion/runId，演示保持项目/版本边界。选择记录至少为 `{commitId, sourceContext, addedAt}`，顺序按用户加入；同一对象重复加入幂等。存储 v3 使用独立命名空间，不删除原 v1/v2 键。

旧键只有 syncId 时，先核对该作业与当前分析的归属；无法核对就显示待迁移说明，不遍历旧键后统一塞到当前仓库。迁移预览数量与来源，用户确认后迁入；重复迁入去重，异常可继续本次内存计划。服务端分页下不能用当前一页删除所有未加载条目，恢复时按分析身份读取条目详情并明确失效项。

新分析 B 不继承 A 的分数或计划；用户可以保持 A，或明确切到 B（有自己的计划），再返回 A。暂不做跨分析合并和批量复制，避免未经比较的分数替换。

预算不再是主流程硬件：先准确显示已选条数与有记录的变更总量；缺失行数计为未知，不按零累加。只有后端真的提供固定分析全集总变更行数及规则时，后续才可展示预算。当前不新增预算选择器，也不把 Recall@20%LOC 直接说成用户计划完成率。

### D7 前端模块与视觉系统

保留现有框架与有价值契约校验，按任务建立 workspace、lab、settings 领域边界。建议独立路由/上下文模块、领域 I/O adapter、查询与计划状态、展示组件；App 只组合空间，避免把旧 mode 分支带入新壳。旧 DOM 测试保留行为意图，必要时重写选择器；不为了保住 CSS 类名复制旧布局。

```text
App shell
  Workspace context --> Project picker + analysis identity
  Repository tasks  --> Commit list <--> selected detail
                    --> Review plan
  Lab routes        --> History / models / manual prediction / saved result
  Settings          --> Connection / appearance + return target
```

主要中文字 14px 起，辅助中文至少 12px；标题约 24–28px。颜色以中性表面与少量选中强调为主，风险分数单独标明单位和未校准性质；品牌绿色不能用于暗示低分安全。使用统一间距/排版/表单/反馈 token。主题和密度保留，密度只调间距；完整哈希、schema 和限制进入一层披露，不隐藏来源性质。

1280/1440 桌面重点检验列表与详情的阅读；空间不够时转明确详情视图，保留上下文和返回焦点，不让空计划长期占据右侧。窄屏纵向重排，关键功能不能消失。所有生产资源本地打包；可以保留自绘图标，也可整套采用有许可的内置图标，不混用网格或为了自绘限制产品表达。

### D8 验证、分阶段集成与文档

先为 B-01/B-02、跨仓库/分析/凭据的迟到响应、旧计划迁移编写能失败的行为测试，再做对应实现。不要只断言新类名或重复实现细节。测试用本地 Git 小仓库、隔离数据库/受控真实模型和可识别行为夹具；真实 Git + API + 浏览器链与 mocked 状态用例分别说明。

| 必须验收的旅程 | 主要反例 |
| --- | --- |
| 接入—作业—仓库提交 | 初次无凭据、参数错误、失败重试、已有成功视图期间失败换分支 |
| 列表—详情—计划 | 两仓库、两分析、搜索后续页、同秒排序、空/错态、分页期间新同步、存储拒绝与迁移 |
| 历史验证—趋势—下钻—返回 | 原仓库不变、同运行日期、无聚合、服务更换历史运行后不静默替换 |
| 模型登记—手工预测—结果重开 | 成员/管理员边界、模型失效、支持与未支持解释、旧 batchId 重开不再推理 |
| 全局设置与旧地址 | 凭据清除/刷新、历史匿名可达、前进后退、旧 sync 归属、长标题与键盘焦点 |

完整检查包含后端行为/契约测试（不能因缺 PyYAML 隐藏跳过）、类型检查、前端测试、lint、构建、受影响全量 e2e 与隔离验收。浏览器服务用独立端口、目录库和进程生命周期，不复用/停止用户默认服务；保留已有受保护文件前后哈希比较。先修复测试运行环境和端口可配置问题，再把失败解释为产品缺陷。

运行输出只进入 `docs/evidence/_run/`；冻结与归档是后续显式步骤，不在新实施任务完成前冻结“全部成功”证据。需求与设计文档按原模板更新实现/目标状态；OpenAPI 写清新字段、可选参数、排序与错误。变更可以按后端契约、上下文/兼容、主要旅程、视觉/实验室、验证收尾形成可复核提交，不需要把旧两 change 的所有源码混成一个提交。

## Risks / Trade-offs

- [已有工作区未提交] → 实施第一步确认 Git 状态并保存可恢复的实现基线；不重置旧代码、不自动推送或混入无关改动。
- [新壳上线但对象仍错] → 以固定分析契约和跨上下文测试作为 UI 联调前置，不用页面名称代替数据隔离。
- [旧成功作业缺作者或完成时间] → 可选字段与明确原因，避免为了填满界面强制重采集或编造值。
- [导航变化破坏验收路径] → 对旧结果、sync、历史与趋势逐条做兼容及双视口回归。
- [模型目录与历史摘要不同源] → 实验室只展示各自真实数据；没有可用多运行接口时不设计虚假切换。
- [新设计变成另一个前端拼盘] → 按上述旅程完成垂直联调；不以“六个页面已画完”替代端到端验收。

## Migration Plan

1. 保存当前源码基线、核对两个旧归档与审计证据；确认实现时没有其他任务同时改同一工作区。
2. 先补独立成功分析上下文、固定查询、同秒排序与可选显示字段；旧客户端不传 viewSyncId 时继续工作。
3. 加新路由/adapter 和空间状态，先迁移项目与接入，再接列表—详情—计划；旧入口通过显式 resolver 兼容。
4. 迁移实验室与设置，保留模型、预测、结果、历史趋势和权限；完成 v3 计划的可预览迁移。
5. 清理已被新实现替代的 mode 分支、重复 CSS 与错误任务文案；保留行为回归和模板文档。
6. 全量验证通过并核对缺口后再提出规格同步、证据冻结与新 change 归档。

回退：通过保留的源码基线回退界面与 additive API 客户端改动；005 只加可空列，不通过删库/逆向迁移回退数据。旧 v1/v2 清单与不可变结果保留，新 v3 键在旧界面下被忽略。回退不得删除用户库、模型或其他既有证据。
