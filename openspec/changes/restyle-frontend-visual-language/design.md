# Design

## Context

见 `proposal.md`（Why / What）。影响本设计的既有约束：

- 前端为 React 19 + Vite，样式是三个全局 CSS 文件（`App.css` 499 行、`trend.css` 164 行、`index.css` 4 行），无 CSS 框架、无 CSS Modules。组件直接用 class 字符串拼样式。
- `frontend/README.md` 明确"不打包或请求外部字体与图标资产"，字体为系统回退栈，图标为自绘 SVG。
- 7 个 e2e 文件以类名与精确文本作为断言目标（`.commit-link`、`.risk-number`、`.model-card`、`.trend-table-wrap`、`.field-grid`、`.baseline-scores`、`.status-note`、`.result-section`，以及 `'100%'`、`'86%'`、`'0%'` 这类精确文本）。
- 规格硬约束：`CRR-01`（来源持续可见）、`CRR-03`（风险边界文案）、`CRR-12`/`MPW-11`（键盘与焦点）、`DTD-03`/`DTD-05`/`DTD-06`（观测与估计分离、文本视图、无横向滚动）、`MPW-02`（侧栏凭据入口）。
- 实测现状（用于设定目标值）：44 处字号 ≤11px；12 组文字对比度低于 4.5:1；181 个色值；1440×900 可见 6 行、1280×720 可见 3 行。

## Goals / Non-Goals

**Goals:**

- 把"好看"翻译成可验收的判据：对比度、字号下限、可见行数、色值收敛、材料统一。
- 令牌化到"新增页面只需组合现有令牌"的程度，避免第 6 个页面再长出一套私有样式。
- 在不改任何既有需求语义的前提下完成替换（纯呈现层变更）。

**Non-Goals:**

- 不引入 UI 组件库或 CSS 框架，不引入构建期样式方案（CSS-in-JS / Tailwind）。
- 不改后端、数据契约、`localStorage` 清单键与结构。
- 不改交互语义（排序规则、筛选语义、清单规则、下钻参数）。
- 不做响应式移动端适配；目标仍是 1280×720 与 1440×900 两个桌面视口。

## Decisions

### D1 令牌用 CSS 自定义属性，主题用属性选择器

`html[data-theme="..."]` 下定义约 26 个语义变量（表面 4、文字 4、线 3、语义色 4、风险 5、阴影 2、字体 3、圆角 2）。组件样式只引用变量，不写具体色值。

- **为什么**：零构建依赖，符合 `IP-04`；切换主题只是改属性，不需要重挂载组件；也便于在 e2e 中读取 computed style 做对比度断言。
- **否决的替代**：CSS-in-JS（新增运行时依赖）、Tailwind（引入构建期工具链且与"自绘材料"目标冲突）、SCSS 变量（需要预处理器，Vite 支持但仍是额外构建步骤）。

### D2 样式按层拆文件，保留全局类名

拆为 `styles/tokens.css`（变量）、`styles/base.css`（重置与排版）、`styles/components.css`（按钮、输入、面板、表格、抽屉、横幅、账本、图标容器）、`styles/pages/*.css`（每页布局）。类名保持现有语义名不变。

- **为什么**：e2e 直接引用类名；改名会让"样式回归"和"选择器失效"混在一起，掩盖真实问题。拆文件解决的是"181 个色值 + 3 个重复定义"的可维护性问题，与命名无关。
- **否决的替代**：CSS Modules（Vite 原生支持，但要全量改类名与断言，收益是作用域隔离，而本项目只有 6 个页面，隔离收益低于返工成本）。

### D3 字体只用系统字族，强调一律 700

栈：`'Segoe UI Variable Text' → 'Segoe UI' → 'Microsoft YaHei UI' → sans-serif`；等宽：`'Cascadia Mono' → 'Consolas'`。

- **为什么**：中文在 Windows 上只有 Regular(400) 与 Bold(700) 两档真实字重，500/600 是浏览器合成，笔画发虚——这正是"字不够深"的根因。因此层级只用 400/700 两档，靠字号与色阶补足。
- **代价**：层级表达少一档，需要更严格的字号阶梯（12/13/15/20/26/28）。
- **否决的替代**：打包 Noto Sans SC（违反"不打包外部字体"且增加产物体积）。

### D4 四套主题，风险色阶不进主题

石灰（暖中性+墨绿）、钢青（冷中性+深青）、炭黑（深色）、纸墨（单色）。每套约 26 个变量；风险琥珀阶只在深色主题下提亮，色相与深浅方向不变。

- **为什么**：`IP-06` 要求语义色跨主题稳定；如果风险色跟主题走，"同一颜色不同含义"就会出现。
- **否决的替代**：主题只改表面色（可选但收益小，用户感知不到"换主题"）。

### D5 图标：自绘 20 网格，方头端点

`Icon.tsx` 的 `viewBox` 由 24 改为 20，`stroke-width` 1.5，`stroke-linecap="square"`，矩形圆角 2，显示尺寸 16。图标集从 12 个扩到约 20 个（新增：设置滑杆、关闭、外链、复制、警告、信息、折叠箭头、筛选等）。

- **为什么**：圆头描边是"友好型"图标语言，与数据工具的气质不符；方头 + 统一网格让图标像工程符号而非插画。`IP-04` 要求同一网格与描边宽度。
- **风险**：手绘 20 个图标的一致性需要一次目视核对（见 tasks）。

### D6 图表继续手写 SVG，但换成制图语言

- 刻度画在轴外（5px 短线），网格只横向，基线为 1px 实线。
- 分区带用 **SVG `<pattern>` 斜线填充**表示"不参与估计"，评估窗口用实底 + 实边；纹理承载语义而非装饰。
- 标记用方块：实心=观测值，空心=估计值；保留图例与文字说明（`DTD-03`/`DTD-05`）。
- 文本视图（分桶表）保持键盘可达，列宽随视口收缩。

- **为什么**：现有"柱+圆点+虚线"是图表库默认长相；制图语言（轴外刻度、单向网格、纹理填充、方块标记）在不增加任何依赖的前提下把"图表"变成"图"。
- **否决的替代**：引入图表库（新增依赖、失去对文本等价视图与两个视口的像素级控制）。

### D7 侧栏双层结构，凭据留在侧栏

52px 图标轨（主导航）+ 188px 上下文栏（模式切换、分组导航、凭据入口、用户卡片），上下文栏可收起。设置面板为右侧覆盖层（约 400px），只承载外观偏好（主题、密度、侧栏模式）；团队凭据输入仍在侧栏。

- **为什么**：`MPW-02` 要求侧栏可输入凭据，把输入框挪进设置需要同批改规格，本变更不做；但把"外观"从侧栏挪走能显著降低侧栏噪声。
- **否决的替代**：侧栏完全收起为悬停展开（需要 pointer 语义，键盘体验差）。

### D8 分层披露分三层

1. 常驻：结论标签（来源性质、"模型估计 ≠ 已确认缺陷"）随页头出现。
2. 一层：详情/设置内一次展开即可核对的口径说明。
3. 折叠：数据版本、运行标识、schema、哈希、时区等来源明细。

- **为什么**：`IP-03` 要求结论常驻、完整来源一层可达；同时解决现状"四套横幅各自重复免责"的问题。
- **约束**：`CRR-01` 要求模式/项目/版本在各视图持续可见 → 版本号保留在页头元信息行，不压进折叠层。

### D9 数值格式化统一，与断言同批改

风险值统一两位小数（`65.0%`），表格与详情一致；`0%`/`100%` 边界保持 `CRR-03` 文案。

- **为什么**：现状 `65% / 61.8% / 58%` 混排，是"不够精密"的直接来源。
- **风险**：e2e 用精确文本匹配 `'100%'`、`'86%'`，必须同批更新为格式化后的文本，否则测试失败会掩盖样式回归。

### D10 密度与主题持久化

`localStorage` 键 `jit.theme`、`jit.density`；首屏在 `<head>` 内联脚本读取并写 `data-theme`/`data-density`，避免首帧闪白。

- **为什么**：`IP-05` 要求刷新后保留；内联脚本是唯一能避免 FOUC 的位置。
- **风险**：存储不可用（隐私模式）→ try/catch 回落默认值（`IP-05` 场景）。

### D11 风险编码：条 + 阈值刻度 + 分档色

风险列由三部分组成：等宽两位小数（右对齐）、4px 风险条、条上 60% 处的 1px 刻度；条色按风险档位取两档（`< 60%` 用 `--risk`，`≥ 60%` 用 `--risk-strong`）。

- **为什么**：现状 65px×4px 单色条在 5 个百分点差内肉眼难辨，且没有任何参照物；刻度给"高风险"一个可核对的界，分档色让排序理由可见。
- **约束**：低风险不使用绿色或任何"安全"语义色（`IP-06`、`CRR-03`）。

### D12 版式：合并顶栏、单视口、禁止嵌套滚动

删除独立的 64px 顶栏，面包屑与来源信息并入页头元信息行；工作台改为单视口布局（页面本身不滚动，只有表格区滚动）。

- **为什么**：现状 1280×720 下页面 chrome 占 428px、表格只剩 300px 且第 4 行被硬切，同时页面还在滚动——两层滚动相互抢滚轮，是最影响"出手感"的问题。
- **例外**：趋势页内容天然超过一屏，允许页面滚动，但表格区与图表区不得再各自内滚。

### D13 排版细则：等宽的使用边界与 CJK 字距

等宽只用于提交标识、哈希、KPI 数字与分档计数；**日期、标签、中文一律用无衬线**。中文字距不超过 `0.02em`。

- **为什么**：等宽字体的斜杠零会把 `2011-11` 读成"2811-11"（实测踩到），且小字号下等宽计数更容易糊；CJK 在 `0.08em` 以上会显得被拉开，是"不自然"的直接来源。
- **后果**：`IP-02` 的 10–11px 例外只允许落在标识与刻度上。

### D14 逐页布局

- 提交工作台：页头（元信息 + 标题 + 2px 线）→ 风险分布条 → 工具条 → 表格与详情同一窗格（内部 1px 分隔）。
- 历史趋势：页头 → 时间序列（**上：提交数柱，下：观测比例与风险中位，共享 x 轴**）→ 审查预算 → 分桶明细 → 来源与局限折叠。
- 模型中心：KPI 条 + 表格 + 右侧登记抽屉。
- 新建预测：左表单 / 右实时摘要两栏，底部 sticky 提交条。
- 结果页：顶部风险横幅（大号等宽数字 + 条 + 免责）→ 左身份 / 右来源。

风险色相在四套主题下均为暖橙红，方向一致；深色主题只提亮不换色相。

### 图标

20×20 `viewBox`、`stroke-width` 1.5、`stroke-linecap="square"`、矩形圆角 2、显示尺寸 16。所有图标来自 `Icon.tsx` 单一集合。

### 图表

刻度画在轴外（5px 短线）；网格只横向；基线 1px 实线；**斜线纹理 = 不参与估计的分区**，实底 = 评估窗口；标记为方块（实心 = 观测，空心 = 估计）。图例与文字说明保留。

### 状态、指标与标识

状态 = 6px 色块 + 文字；指标 = 账本式横条（1px 分隔）；标识 = 字标 + 细线。

### 密度档位

舒适：行高 40、表头 31；紧凑：行高 32、表头 27。密度只影响表格与列表，不影响页头、图表与抽屉。

### 交互反馈

- **hover 只改背景与颜色，不改尺寸**：导航与行的 hover 不得引起布局位移（否则列表在鼠标滑过时会抖）。
- **按下态有触感**：`translateY(1px)` 或 `scale(0.96)`，时长 120ms。
- **过渡 120–220ms**，缓动统一 `cubic-bezier(.22,.61,.36,1)`；面板滑入 220ms，其余 160ms。
- **焦点环 2px 强调色 + 2px 偏移**，在深色主题下不得低于 3:1 对比。
- **选中项用 3px 锚点条**（左缘），不靠整块填充，也不改变同级项的位置。
- `prefers-reduced-motion` 下以上全部关闭（`IP-07`）。

### 禁用清单

- 圆头端点图标、双色图标、filled/outline 混用
- 圆角胶囊标签、描边徽章
- 装饰性渐变、发光、投影（除设置面板的背板模糊与抽屉的一层阴影）
- 图表圆点标记、竖向网格
- 带底色的字符方块 logo、填充式字母头像
- 独立指标卡片（用账本替代）
- 硬编码色值（一律走令牌）
- 大于 6px 的卡片圆角

## Risks / Trade-offs

| 风险 | 缓解 |
|---|---|
| e2e 类名与精确文本断言大面积失败，掩盖真实回归 | 类名全部保留；只格式化文本，并同批更新断言；先跑一遍基线再改 |
| 对比度在深色主题下回退 | 令牌层集中定义，深色主题单独校验一轮；在 e2e 中读取 computed style 断言 ≥ 4.5:1（至少覆盖 8 处代表性文字） |
| 字号提升导致 1280×720 溢出 | 字号阶梯按容器收缩（表格用 `clamp` 或视口断点）；两个视口的既有断言保留并扩展到新页面 |
| 系统字体在 Win10 无 `Segoe UI Variable` | 回退到 `Segoe UI`；布局不依赖字体宽度（不用固定 px 假设文本宽度，用 `min-width:0` + 截断） |
| 主题切换首帧闪白 | `<head>` 内联脚本，先写属性再渲染 |
| 5 个页面一次性改写导致大面积视觉回归无法定位 | 分两批合入：第一批令牌 + 外壳 + 工作台，第二批其余 4 页；每批独立可回滚 |
| 手绘 20 个图标走形 | 统一 `viewBox`/描边/端点，集中在一个文件，逐图在 16px 下核对 |
| 验收要跑通就得先修登记入口（后端） | 第二批次实测发现：本机 `artifacts/baseline` 的 summary 是具名 schema 之前的形态（无 `model` 段），而 `catalog.register` 直接读 `summary['model']`，因此通过 HTTP 登记旧 baseline 会 500。**这属于既有的登记侧缺陷，不在本变更的呈现范围内**，但 `MPW-04` 的验收必须能跑通，故经确认后做了一处**最小容错**：缺失 `model` 段时按声明的方法回落身份（id/name 取 `algorithmVersion`），不改任何 API 与数据契约；另加一条后端用例覆盖旧形态。若评审要求严格"不动后端"，可把这处容错拆成单独变更再合并。 |

## Migration Plan

1. 第一批（可独立合入与回滚）：令牌层 + 基础排版 + 图标集 + 侧栏外壳 + 提交工作台（列表、详情、清单）+ 设置面板。
2. 第二批：历史趋势、模型中心、新建预测、结果页。
3. 每批执行 `npm run typecheck && npm test && npm run lint && npm run build` 与 `npm run test:e2e`；两批之间不合并。
4. 回滚：纯样式变更，`git revert` 单批 commit 即可；无数据迁移、无 `localStorage` 结构变更。

## Open Questions

- 默认主题选定（石灰 / 钢青 / 炭黑 / 纸墨）——不影响规格与任务拆分，可在实现时确定。
- 团队凭据是否最终迁入设置面板——需要同批修改 `MPW-02` 的呈现约定，留待后续变更决定。
