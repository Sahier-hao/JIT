## Context

现有 `repository_sync` 已有队列、单工作器、取消、超时、恢复和强制训练路径；强制训练直接调用 `build_run` 与模型目录登记。管理端目前只能查看已登记模型和候选，没有独立训练任务领域。新任务必须复用已验证训练步骤，同时不能把管理员实验塞进项目分析的历史语义和权限范围。

## Goals / Non-Goals

**Goals:**

- 新增独立持久化训练任务、单工作器执行器和控制 API。
- 让管理员选择数据集、方法和指标集，并查询真实指标与运行/模型谱系。
- 复用训练执行器到用户仓库强制训练，保持现有同步行为。
- 使用前向迁移、进程树所有权和重启恢复保证任务结果可信。

**Non-Goals:**

- 不新增管理员前端页面、训练队列可视化或图表。
- 不把项目分析记录转换为管理员训练任务。
- 不根据指标自动切换默认模型或实现超参搜索。
- 不支持任意本地路径、客户端上传模型或浏览器指定产物目录。

## Decisions

### D1. 独立 training_task 表承载管理员任务

任务保存数据集版本与描述文件路径/哈希、方法、指标集、状态、阶段、取消与重试关系、运行、模型、产物 key、指标和失败诊断。独立表避免改变 `repository_sync` 的历史行、项目结果和状态机；`parent_task_id` 仅用于新任务的重试谱系。

### D2. 服务层与隔离执行器共享训练核心

提取 `TrainingExecutor`，统一完成建跑、完整产物校验和模型目录登记。`SyncService` 与 `TrainingTaskService` 只负责各自的任务状态和调用方边界。管理员任务使用独立子进程和单工作器；项目同步仍保留自己的 `syncId`、超时、降级与结果发布。

### D3. 任务创建先校验数据集和方法

创建时只接受已登记数据集版本和已注册方法，保存描述文件哈希。相同数据集、方法和指标集已有活动任务时复用该任务。输出 key 由任务身份派生，只允许位于配置的 artifact root 下，不接受客户端路径。

### D4. 取消和重试采用终态保护

排队取消立即进入 cancelled；运行取消记录请求并停止子进程树。失败、取消、中断允许显式重试并创建新的排队任务，父任务保留。成功或活动任务重试被拒绝；所有迟到执行结果不能覆盖终态。

### D5. API 只暴露稳定业务事实

列表与详情返回任务参数、状态、阶段、失败原因、指标、数据版本、`runId`、原产物 run ID、模型 ID、产物 key 和 schema。失败任务不补造指标。所有训练任务路径加入管理员保护规则，公众模型选择接口保持原字段。

## Risks / Trade-offs

- [训练进程占用单工作器导致排队] → 状态和队列位置如实返回，取消排队任务立即释放队列。
- [模型登记自动建立首个默认模型] → 保留既有目录契约，但绝不按测试指标改变默认；报告明确任务不是自动择优。
- [共享执行器重构影响仓库同步] → 保留 synced 任务自己的状态与异常文字，并增加项目强制训练回归测试。
- [管理员关闭服务导致任务中断] → 启动时把旧活动任务标记 interrupted，不自动续跑。
- [大数据集深度方法运行较久] → 执行器设置可配置时限，超时终止进程树并保留可诊断失败。

## Migration Plan

新增 migration 018 和 `training_task` 表；初始化前自动备份旧数据库。旧 `repository_sync`、模型、数据集与管理员设置不迁移或改写。回滚应用版本时保留新表，不影响旧版读取既有表。
