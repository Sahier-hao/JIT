# 设计：行级基线训练

## Context

`line-szz-v1` 已提供逐行文本、上下文、语言、行级启发式与提交级特征。需要一个最小但诚实的训练与评估流程，先回答“能否学到信号”，而不是直接上线。

## Goals / Non-Goals

**Goals**

- 用固定种子、明确切分训练逻辑回归基线，报告可复现指标。
- 防止同一提交的行同时出现在训练与测试。
- 区分“仓库内随机切分”和“跨仓库留出”，不把前者当作泛化能力。

**Non-Goals**

- 不登记模型、不改默认模型、不接产品页面。
- 不做深度模型、AST/token 级特征或超参搜索；这些留到基线有信号之后。
- 不用测试集调阈值或选特征。

## Decisions

1. **输入**：`--input` 可重复，读取 `line-szz-v1` JSONL；`repo` 字段缺失时从 `datasetVersion` 推导，仍无法确定则拒绝。
2. **负例**：行级样本支持 `same-file` 负例——从正例所在提交、同一文件的未标记行抽样，使正负例共享提交与文件，去掉“提交类型/文件类型”捷径；默认 `added-line` 保留原分布。
3. **特征**：`TfidfVectorizer(analyzer="char_wb", ngram_range=(3,5), min_df=2, max_features=30000)` 作用于行文本 + 前后文；数值特征含行长、缩进、空行/注释标记与结构计数（条件/循环/返回/调用/赋值/比较）；语言 one-hot。提交级 14 维特征默认不纳入，只有 `--include-commit-features` 时加入；缺失按 0 处理并在报告中说明。
4. **切分**：`--test-repo` 时按仓库留出（训练其他仓库、测试该仓库）；否则按 `commitId` 分组 80/20，报告训练/测试的提交与仓库数。禁止按行随机切分。
5. **语言**：评估按 `--language` 过滤；跨语言混训会把语言/项目差异当成信号，报告必须按语言分别呈现。
6. **模型**：`LogisticRegression(class_weight="balanced", solver="liblinear", max_iter=2000, random_state=seed)`；默认按仓库平衡样本权重（`--no-repo-balance` 关闭）；不调阈值，固定 0.5 报告精确率/召回率，同时给出 PR-AUC 与 Brier。
7. **报告**：JSON 含输入文件、样本/提交/仓库数、切分方式、特征维度、正负例、指标与限制；单类测试集时指标写 `null` 并说明原因。
8. **可复现**：固定种子；报告记录特征参数、模型参数与 scikit-learn 版本。
9. **不写回**：不修改 JSONL、数据集、目录库或模型目录；模型只保存在内存，可选 `--model-output` 另存 joblib。

## Risks / Trade-offs

- 文本特征会记住项目命名与模板，跨仓库指标可能显著低于仓库内切分；报告必须并列两种结果。
- 行级负例只来自新增行，分布与全量代码行不同，不能外推为“所有行”的风险。
- 逻辑回归是基线，非线性模式可能学不到；先确认有信号，再考虑树模型/深度模型。
- 样本以 cc-switch 为主时，跨仓库测试可能只反映单一项目的写法。
