## Why

仓库同步训练、PR 批量分析和管理/审查页面的日常操作仍存在会改变结论可信度的缺口：训练只计算了 90 天截止时间，却没有把近期数据排除在实际训练之外；「分析全部 PR」只读取本地缓存、吞掉单条失败，并用量冒充成功；单 PR 与批量 PR 接口的错误没有进入统一错误信封；管理训练页任务详情返回、失败恢复和分页不完整；点击旧版本证据会被带回提交列表。这些问题会让用户看到与实际执行不一致的状态，或无法回到原始代码。

## What Changes

- 仓库同步训练把「窗口内最新提交往前 90 天」的截止时间传入共享训练执行器，先排除近期提交再切分、训练与验证；近期提交仍用本次模型打分。产物记录截止时间、可训练样本数和各分区数量。管理员普通训练不传截止时间，保持原行为。
- 单 PR 分析、批量 PR 分析和批次进度接口纳入统一错误处理，非法参数、项目不存在、来源不可用、模型不可用时返回结构化错误和 requestId；增加路由覆盖检查，防止新增接口漏接错误信封。
- 「分析全部 PR」改为持久化批次：从远端分页获取开放 PR 清单并固定候选范围；批次开始时解析并固定真实兼容模型；逐条刷新快照后按「同快照同模型在途/成功复用、快照变化新建、用户主动重试失败/取消/中断」处理；记录逐条状态，提供批次进度与仅重试失败项；重复点击返回同一活动批次；服务重启后未完成批次标记为中断。
- 管理训练页在任务切换和返回列表时清除旧详情，失败与轮询失败提供真实重新请求，接入任务分页，离开页面取消请求与定时器。
- PR 工作单区分「普通切换版本」和「点击证据跳转」：点击证据直接打开旧版本、文件、基准/目标侧和行号；无法读取时保留原定位与版本并显示原因，不用新版本代码代替。
- 前端 PR 审查页读取批次真实进度，展示已提交、复用、失败和待处理数量，只重试失败项。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `repository-collection`：训练截止时间必须实际约束训练、验证与测试分区，并记录实际样本量。
- `project-pr-tracking`：批量分析全部 PR 必须是可追踪、可恢复、固定模型的持久批次，而不是缓存数量回执。
- `admin-training-workspace`：训练任务列表与详情必须正确切换、分页并在失败后恢复。
- `review-revisions`：点击旧证据必须打开所属版本和位置，且不得冒用其他版本代码。
- `focused-project-review`：PR 分析与批次接口必须返回带 requestId 的结构化错误。

## Impact

- 数据库：新增 PR 批次及逐条结果表，使用前向迁移；同步训练沿用既有 `repository_sync` 字段，不修改历史作业与产物。
- 后端：调整 `TrainingExecutor`、仓库同步训练调用、PR 分析路由与错误路由、PR 批量批次服务；管理员训练和既有模型行为不变。
- 前端：项目管理页批量入口、PR 审查页批次进度、管理训练页、PR 工作单证据跳转。
- 兼容性：不改已保存模型、数据集、历史分析、个人草稿和默认模型；旧批次缺失时按无批次处理。
- 验收：覆盖完整调用链、批次状态推进、失败恢复、管理员权限和跨版本定位；验证记录写入 `docs/`。
