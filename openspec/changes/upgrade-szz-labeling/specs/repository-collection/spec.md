## MODIFIED Requirements

### Requirement: RCL-04 简化 SZZ 标签

系统 SHALL 按显式规则识别修复提交并回溯其引入的代码，将引入提交标为缺陷引入。默认规则为 `szz-line-v1`：对修复提交的唯一父提交做带重命名/复制检测的 diff，只取被删除或修改的行区间，用 `git blame -M -C` 回溯到引入提交，并保存引入提交中的原始行号区间与父提交行号区间。`szz-simple-v1` 作为兼容规则保留，按文件级最近一次变更回溯。回溯 MUST 只使用当前提交父链上的历史；无法证明父链关系 MUST NOT 把该提交标为引入。每个正例 MUST 保存可复核证据：修复提交、候选引入提交、文件路径、行号区间（行级规则）、证据时间和观察终点；同一提交由多个修复、文件或行区间产生证据时 MUST 分别保存，MUST NOT 互相覆盖。标签状态 MUST 区分有证据正例、未观测和未成熟；未命中 MUST 记为未观测到缺陷引入并注明其含义，MUST NOT 称为已证实无缺陷。标签规则 MUST 有版本标识并随产物记录。产物与报告 MUST 标注实际使用的规则，MUST NOT 宣称实现完整 SZZ。

#### Scenario: 回溯到引入提交

- **WHEN** 一个修复提交删除了若干行，且这些行在父提交中有更早的变更提交
- **THEN** 这些行的引入提交被标为缺陷引入，并保存修复提交、引入提交、路径、引入提交原始行号区间、父提交行号区间与规则版本

#### Scenario: 没有可回溯的修复提交

- **WHEN** 采集范围内没有命中修复规则的提交
- **THEN** 全部标签为未观测到并注明含义，不把结果称为已证实无缺陷

#### Scenario: 规则可复核

- **WHEN** 查看产物中的标签说明或任一正例证据
- **THEN** 可见修复提交识别规则、回溯范围、规则版本和该正例的修复与引入位置，并可据此复核

#### Scenario: 引入候选必须属于父链

- **WHEN** 文件的最近一次变更来自并行分支或合并点，而不是修复提交的父链
- **THEN** 该候选不被标记为缺陷引入，产物记录无法确定父链关系的原因，不用其他提交替代

#### Scenario: 未成熟标签

- **WHEN** 提交时间距离观察终点不足声明的成熟期，且采集范围内尚未观测到修复
- **THEN** 该提交标为未成熟而不是未观测或已证实无缺陷，并记录观察终点与成熟期

#### Scenario: 同一提交多条证据

- **WHEN** 同一提交被多个修复提交、多个文件或多个行区间分别标记
- **THEN** 每条证据分别保存，查询时全部可见，不因后写入的证据覆盖先前证据

#### Scenario: 行级回溯到具体行

- **WHEN** 使用默认 `szz-line-v1` 且修复提交修改了源码行
- **THEN** 证据包含引入提交中的原始行号区间和修复前父提交中的行号区间
- **AND** 只有落在采集窗口内的引入提交获得正例标签

#### Scenario: 重命名后的文件

- **WHEN** 文件在修复前被重命名，修复提交修改的是新路径
- **THEN** 行级回溯仍能追到重命名前的引入提交，并存下当前路径与旧路径

#### Scenario: 回滚与纯新增修复

- **WHEN** 修复提交是回滚提交，或只新增代码而没有删除/修改行
- **THEN** 回滚提交不作为修复提交；纯新增修复不产生引入行证据，不计入正例

#### Scenario: 文档与测试路径

- **WHEN** 修复提交只修改文档或测试路径
- **THEN** 不把文档/测试行标为缺陷引入，被过滤的路径数量记入统计

#### Scenario: 回溯上限

- **WHEN** 一个修复提交的删除行或修复提交数量超过声明上限
- **THEN** 只回溯上限内的部分，标记产物已截断并显示，不伪造其余证据

### Requirement: RCL-06 采集证据与限制披露

采集 SHALL 记录所用 git 版本、仓库地址或路径、采集时的 HEAD、提交范围、纳入与排除数量以及耗时。产物、运行记录与查询响应 MUST 如实标注两项限制：特征为提交级聚合、标签使用声明中的 SZZ 规则及证据范围。使用本地仓库缓存或复用已保存特征时，产物与分析记录 MUST 说明缓存命中或特征复用来源，MUST NOT 把复用结果表述为重新采集，也 MUST NOT 因复用省略原有限制说明。

#### Scenario: 记录采集证据

- **WHEN** 采集完成
- **THEN** 产物包含 git 版本、仓库标识、HEAD、范围、纳入与排除数量

#### Scenario: 限制随结果披露

- **WHEN** 消费该数据集生成的运行或预测结果
- **THEN** 可看到「提交级聚合」与实际标签规则（行级或简化）的说明，不被表述为完整 SZZ 或文件级样本

#### Scenario: 披露缓存与特征复用

- **WHEN** 分析使用了本地仓库缓存或已保存特征
- **THEN** 产物或分析记录标明复用来源，并继续展示提交级聚合与实际标签规则的限制
