# 升级缺陷引入标签为行级 SZZ

## Why

后续要推进到代码行级的缺陷预测，标签必须能追到“引入缺陷的具体行”，只到提交级的文件回溯不够。当前默认的 `szz-simple-v1` 只记录“修复提交 → 文件最近一次变更”，不处理删除行、重命名、跨文件传播和 issue 关联，也没有行号证据。行级 SZZ 是行级预测的前置条件，不是可选的展示改进。

## What Changes

- 新增 `szz-line-v1` 并设为仓库采集默认规则：识别修复提交，对其父提交做带重命名/复制检测的 diff，只取被删除/修改的行，用 `git blame -M -C` 回溯到引入提交。
- 证据保存修复提交、引入提交、路径、引入提交中的原始行号区间、修复前父提交中的行区间与修复时间，供后续行级预测直接使用。
- 排除合并提交、回滚提交、文档/测试路径与二进制文件；限制单个修复的回溯范围并在截断时如实记录。
- 保留 `--szz simple` 作为文件级兼容规则；旧数据集与旧模型不迁移、不覆盖。
- 数据集详情新增标签与 SZZ 读数：修复提交数、被标为引入数、证据对数、未回溯行区间、跳过文件、窗口外引入、成熟期与截断状态。
- 更新采集说明、界面文案与产品文档，明确这是“行级 SZZ”，仍不是完整 SZZ。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `repository-collection`：RCL-04 支持行级回溯与行号证据，保留简化规则作为兼容；RCL-06 按实际规则披露标签与限制，不把任一种表述为完整 SZZ。
- `admin-training-workspace`：数据集详情展示标签质量与回溯覆盖，不能只显示“简化 SZZ”四个字。

## Impact

- 后端：新增 `backend/jit_baseline/szz.py`；`collect.py`、`cli.py`、`store.py`、`suite.py`、`multi_project.py`。
- 前端：数据集详情、构建数据集说明、运行记录限制文案。
- 数据：新采集默认生成 `szz-line` 数据集；旧 `szz-simple-v1` 数据集、模型、分析与指标保持不变。
- 训练：新标签需要重新训练才能进入模型；本次不自动重训、不替换默认模型。
