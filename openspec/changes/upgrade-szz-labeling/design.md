# 设计：行级 SZZ 与标签质量读数

## Context

采集管线目前用 `_History.file_last` 做文件级回溯：修复提交涉及的每个文件，取父链上最近一次修改该文件的提交。它无法回答“哪一行被引入”，也没有行号证据。后续行级缺陷预测需要逐行标签，因此新增行级规则，同时保留旧规则以维持历史数据集的可比性。

## Goals / Non-Goals

**Goals**

- 从修复提交的删除/修改行回溯到引入提交，并保留引入提交中的原始行号。
- 对重命名、复制、回滚、合并、文档/测试与二进制路径给出明确处理方式。
- 每个标签有可复核证据；无法回溯、被过滤、超出上限的部如实计数。
- 旧数据集与旧模型保持不变；新规则只用于新采集。

**Non-Goals**

- 不实现 issue tracker 全量关联、跨仓库搬运或人工逐条复核；这些仍列为限制。
- 不自动重训现有模型，不替换默认模型，不迁移旧数据集。
- 不改动特征口径（仍为提交级 Kamei 14 维）。

## Decisions

1. **修复提交识别**：沿用 `fix/fixes/fixed/hotfix/bug/bugfix/defect/issue` 关键词，并补充 `fixes/closes/resolves #N`；排除标题以 `Revert` 开头的回滚提交与合并提交。关键词误报仍是主要噪声源，在限制中披露。
2. **行级回溯**：对修复提交与其唯一父提交做 `git diff --unified=0 -M -C`，只取 `-` 侧行区间；用 `git blame --line-porcelain -M -C -L` 在父提交上回溯每个区间，保留 blame 头中的原始行号（引入提交版本）与父提交行号。
3. **路径过滤**：跳过文档、示例、测试、fixture 与二进制/锁文件；修复同时改源码和测试时只回溯源码。被过滤数量记入统计，不静默。
4. **重命名与复制**：diff 与 blame 都启用 `-M -C`；证据保存当前路径与旧路径（若有），重命名场景用合成仓库测试覆盖。
5. **边界与上限**：单个修复最多 50 个行区间、2000 行；最多处理 2000 个修复提交；超限置 `truncated` 并在数据集详情显示。单个区间失败记 `unresolvedRanges`，不伪造引入提交。
6. **标签语义**：只有落在采集窗口内的引入提交标 1；窗口外引入单独计数；未命中仍为“未观测”，未成熟仍按 90 天判断。多修复/多文件命中分别保存证据。
7. **兼容与版本**：`szz-line-v1` 为新默认，`szz-simple-v1` 通过 `--szz simple` 保留；数据集描述记录 `label.kind`（`szz-line` / `simplified-szz`）与规则版本。旧数据集内容不变，模型只在用新数据集训练后变化。
8. **质量读数**：数据集列表/详情投影增加 `label` 与 `szz` 统计；详情展示规则、修复提交、被标为引入、证据对数、未回溯、跳过、窗口外、成熟期、截断。简单规则缺少的字段显示为“—”，不伪造为 0。
9. **训练兼容**：`suite.label_semantics` 识别 `szz-line`；多项目训练接受两种标签种类，但仍要求来源是 Git 仓库采集。

## Risks / Trade-offs

- 行级回溯只处理删除/修改行；纯新增式修复不会产生引入行，可能漏标，已在限制中说明。
- 关键词识别仍是噪声源；没有 issue 关联时，标题含 fix 的文档/重构可能被计入修复提交（路径过滤可减少一部分）。
- blame 在每个修复提交上运行，较大的修复会变慢；通过区间/行数/修复数上限约束，并记录截断。
- 新标签改变“真值”，新模型指标不能与旧数据集直接比较；旧数据集与旧模型保留，比较时必须注明规则版本。
- 行号证据依赖 blame 的重命名检测；极端历史改写或跨仓库搬运仍可能回溯到错误提交，需人工抽样复核。
