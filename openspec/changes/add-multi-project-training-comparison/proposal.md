## Why

现有 `run-suite` 只能对单个数据集训练方法，`compare-projects` 只能并列各项目独立训练的指标，无法回答模型在多个项目间共享数据、迁移到未见项目或融合全局与本地信息后是否更稳定。需要将前一轮确定的四个公开 Git 项目正式落成可重复的多项目训练与迁移比较能力。

## What Changes

- 固定采集 `apache/commons-lang`、`vuejs/core`、`redis/redis`、`scikit-learn/scikit-learn` 四个公开仓库的同一三年窗口，使用 `kamei14-git-v1`、提交级特征和简化 SZZ 标签。
- 为每个项目建立独立时间切分，并实现四种训练口径：项目内 `local`、合并训练 `pooled`、留一项目 `leave-one-project-out`、全局与本地融合 `global+local`。
- 对每种方法和训练口径产出逐项目指标，并汇总宏平均、总体方差、最差项目和结构化失败记录。
- `global+local` 的融合权重只能使用目标项目验证段选择，禁止使用测试集调参。
- 保持跨项目结果解释边界：宏平均用于总结本组四个项目，不把不同项目的正例比例当缺陷率，不自动选模型或宣称某方法普遍最佳。
- 本轮仅实现离线实验与报告，不新增服务默认模型、训练 API 或管理员前端。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `multi-dataset-evaluation`: 在既有单项目套件与跨项目并列报告之上，新增四项目训练口径、逐项目迁移结果、宏平均、方差、最差项目和失败隔离要求。

## Impact

- 数据：新增四个公开仓库的固定窗口采集产物、数据集描述文件和来源修订记录；原始 CSV 保持在可重建的本地采集目录，仓库只提交描述与证据。
- 后端：新增多项目训练编排、四种训练口径、聚合报告及 CLI 入口；复用现有 schema、时间切分、九种方法和 `metric-set-v2`。
- 实验：新增四项目、多方法的实际训练报告和冻结证据；具体方法子集必须写入报告，未运行的方法不得伪装为成功或失败。
- 兼容性：既有 `run-suite`、`compare-projects`、运行产物和服务接口保持不变。
- 不影响：API、前端、默认模型、用户仓库同步和在线预测。
