## Context

现有多数据集能力已经能通过 `run-suite` 为单个项目训练全部方法，并通过 `compare-projects` 并列项目内结果；但每种结果都来自目标项目自己的训练分区，不能区分共享训练、冷启动迁移和全局加本地融合。四个固定公开项目都将使用 `kamei14-git-v1`，因此可以在不改变模型输入 schema 的前提下扩展实验编排。

## Goals / Non-Goals

**Goals:**

- 固定四项目队列和数据版本，分别建立相同规则的时间切分。
- 用统一比较报告表达四个训练口径的逐项目结果和跨项目汇总。
- 将失败、未定义指标和不可用项目保留为可诊断记录。
- 支持复用现有九种方法，同时允许实际实验选择明确的方法子集以控制运行时间。

**Non-Goals:**

- 不改变九种方法的冻结超参、指标定义或特征 schema。
- 不把不同项目的正例比例解释为缺陷率。
- 不训练服务默认模型，不增加 API、训练任务持久化或管理员页面。
- 不把简化 SZZ 宣称为完整 SZZ。

## Decisions

### D1. 四项目使用独立数据集并固定共同窗口

四个项目分别登记，不合并为一个大 CSV。原因是要保留来源、许可证、项目头和独立切分身份，并避免把项目身份当作模型特征。四份描述文件作为一次实验的共同输入；项目名、URL、revision、CSV 哈希和版本均进入报告。

### D2. 先切分，再按口径组装训练成员

每个项目先用现有时间切分规则生成 train、validation、test。`local` 只用目标 train；`pooled` 使用四份 train 的并集；`leave-one-project-out` 使用除目标外的三份 train；`global+local` 复用留一全局训练集，并额外用目标 train 训练本地模型。所有项目的评价只读取目标 test。

### D3. global+local 使用验证集选择固定网格融合权重

对目标 validation 的风险分别在固定权重网格 `0.00..1.00` 上计算 Brier 分数，选用分数最低的权重，随后一次性应用到目标 test。网格固定、选择过程记录在报告中。选择验证集而不是测试集，避免用未来评价数据调参；不为每个项目重新拟合 meta-model，降低小样本过拟合风险。

### D4. 汇总采用项目宏平均和总体方差

每个方法、口径和数值指标以项目为等权单位计算宏平均和总体方差，防止大项目仅因提交数多而支配汇总。最差项目按指标方向选择；未定义指标不填零，宏平均记录实际参与项目数。AP 作为主要诊断指标同时列出，但不据此自动选择或推荐方法。

### D5. 报告与运行产物分层

报告写入机器可读 JSON，包含数据版本、切分身份摘要、训练来源、融合权重、逐项目指标、汇总统计和失败。模型二进制与原始采集 CSV 不进入 Git；证据目录只冻结报告、输入描述、来源哈希和必要验证结果。实际正式实验默认选择五种经典方法，深度方法仍可显式加入，避免把未运行的深度方法写成失败。

## Risks / Trade-offs

- [项目正例率低导致某些指标不稳定] → 保留样本数、正例数、方差和最差项目，不以零值补齐；不宣称普遍泛化效果。
- [四项目语言和演化方式不同] → 统一 schema 只保证输入形状，报告披露项目差异，跨项目结论限定为迁移实验观察。
- [global+local 融合权重在小验证集上波动] → 使用固定粗网格并披露验证样本与 Brier；不使用测试集调参。
- [深度方法运行成本高] → CLI 支持全部已登记方法，正式证据明确记录实际方法子集；未选方法不记为失败。
- [SZZ 标签与特征均为简化或提交级] → 继续复用现有限制文本，在所有报告与证据中披露。

## Migration Plan

这是纯离线增量。新增报告和 CLI 不改既有数据集、运行或服务接口；若实验失败，可删除未提交输出并重跑，既有 `run-suite` 与 `compare-projects` 不受影响。
