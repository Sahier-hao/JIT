# Design

## Context

`docs/当前产品.md` 是产品行为的单一事实来源，但已膨胀到 50 KB，包含重复段落、历史命令、模型盘点与死链。根目录 README 仍指向旧入口和旧采集口径。`docs/audits/` 与 `docs/审计/` 并存，两个模板文件没有任何正文。文档之间没有索引，也没有自动链接检查，新增入口和端点只能靠人工记忆。

## Goals / Non-Goals

**Goals**

- 让 README 与 `docs/README.md` 成为可用的导航入口。
- 让 `docs/当前产品.md` 回到 20 KB 以内，行为事实完整、无逐字重复、无死链。
- 让运维命令、离线研究细节各有唯一归属，不再堆在产品总览里。
- 用脚本持续校验当前文档的相对链接。
- 用一份分层清单固定四类入口与端点的边界、兼容别名和退役条件。

**Non-Goals**

- 不改变任何页面 URL、后端路径、错误码、权限或数据结构。
- 不删除仍被测试、规格或离线脚本依赖的兼容入口。
- 不重写历史审计与冻结证据中的当时路径。
- 不把项目改为多租户隔离，不调整模型身份或默认模型规则。

## Decisions

1. **单一事实源分层。** `docs/当前产品.md` 只保留当前行为与边界；运维命令进入 `docs/运维与升级.md`；离线报告、行级研究与扩展进入 `docs/离线与研究.md`；历史验证进入 `docs/审计/`；提案与设计进入 OpenSpec 归档。每类信息只有一个主位置，其他位置只链接。
2. **链接检查默认只覆盖当前文档。** 冻结证据（`docs/evidence/`）、汇报材料（`docs/汇报/`）与历史审计/计划保留当时的代码路径，默认不参与死链判定；需要全量核查时使用 `--include-evidence`。当前范围是 README、AGENTS、docs 顶层文档、`docs/架构/` 与当日审计/计划。
3. **入口清单只记录、不改变契约。** 清单按核心项目与 PR 审查、用户自助建模、管理员维护、离线研究四层归类；兼容别名保留，并写明替代入口、依赖与退役条件。删除仍被测试或规格依赖的入口不在本阶段进行。
4. **文档工具无第三方依赖。** `check_docs_links.py` 只使用标准库，按 Markdown 相对链接解析、跳过外部 URL 与页内锚点，输出文件与行号并以非零退出码失败，便于本地和 CI 直接运行。
5. **模板删除以引用清理为前提。** 删除两个空模板前，先改写产品需求/设计文档中的“原件保留”表述并更新所有非历史引用；冻结证据中的哈希清单保持原样。

## Risks / Trade-offs

- [精简文档可能丢失细节] → 细节迁移到运维、离线研究、审计与 OpenSpec 归档，产品总览保留结论与链接；逐项链接由脚本校验。
- [历史审计死链被忽略] → 只在默认检查范围中排除；`--include-evidence` 可全量列出，历史记录保持原貌。
- [入口清单可能过期] → 清单记录生成日期与退役条件；新增入口仍须先在 `docs/界面入口清单.md` 登记，路由重构时同步更新。
- [删除模板影响旧引用] → 已更新产品文档与 backend/README；历史证据中的文件名作为哈希记录保留，不代表当前文件存在。

## Migration Plan

- 无数据库或运行时迁移。文档移动使用 `git mv` 保留历史；删除的模板文件在审计记录中说明。
- 回退只需恢复文档与脚本文件。
