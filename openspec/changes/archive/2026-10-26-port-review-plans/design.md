# Design

## Context

现有个人计划按项目、分析和数据版本保存在浏览器，计划视图可跨分页读取所选提交。固定分析包含实际模型与运行身份，服务端已有成功状态及归属信息。动机见 proposal.md；实际验收见 docs/审计/2026-10-26-review-plan-portability.md。

## Goals / Non-Goals

**Goals:** 让同一固定分析的个人选择可以备份、预览并恢复；校验和写入失败均不破坏原计划。

**Non-Goals:** 不做账户同步、团队共享、跨分析映射、云端个人计划持久化或模型推理，不把备份中的字段作为分析结果。

## Decisions

1. **只备份引用。** 使用 jit-review-plan-v1 格式，包含完整来源和提交标识，不含风险、标签或解释，以免导入覆盖服务器已保存事实。来源使用原模型及运行，而非当前默认。
2. **服务端一次快照核对。** 公开校验接口强制指定 viewSyncId，在同一只读事务核对项目、成功状态、来源和全部提交。相比逐条查询，减少跨页请求并保证整份成功或失败；不需要可加载的模型产物。
3. **预览与确认分开。** 文件只用于预览，确认时再请求校验，防止预览期间分析被删除；当前页面的来源变化会取消请求并隔离结果。
4. **先保存再更新页面。** 合并现有选择与备份，保留已有条目时间；本地写入成功才更新内存。相比替换整个计划，合并可避免误清空，并可重复恢复。
5. **双端限制。** 文件读入前检查大小，服务端按流计数最多 1 MiB；列表最多 5000 条，拒绝重复、未知及多余字段。即使绕过浏览器也不能接受无界请求。

## Risks / Trade-offs

- [备份不携带实际分析数据] → 恢复依赖原分析仍在服务端；删除分析后明确拒绝。
- [本地存储不可读或拒绝写入] → 保留原值，提示恢复权限或空间后重试；不冒称恢复成功。
- [确认后其他窗口修改计划] → 合并时读取当前已保存选择，不声称提供跨窗口事务或账户同步。
- [旧分析缺少模型元数据] → 接受与已保存空值一致的来源，不猜测模型。

## Migration Plan

无新增数据库迁移，使用既有固定分析数据。保持计划 v3 键和条目结构，不批量改写本地存储；原有旧格式迁入入口继续工作。回退代码仍可读取已合并计划，JSON 文件作为独立备份保留。
