# Design

## Context

仓库分析已保存模型、运行、分数及输入度量，现有手工预测具备遮挡归因。仓库提交使用固定分析视图，详情需继续遵守项目和分析身份隔离。动机见 proposal.md；实际验收见 docs/审计/2026-10-25-repository-explanations.md。

## Goals / Non-Goals

**Goals:** 将既有归因能力接入仓库提交，明确触发、身份、保存、错误恢复和基线来源。

**Non-Goals:** 不训练解释专用模型，不计算因果关系、缺陷结论或行级定位，不改写历史风险，不改变浏览器计划存储键。

## Decisions

1. **读取与生成分开。** GET 仅查询，POST 显式生成；均强制传 viewSyncId。相比打开历史时自动推理，可以保留历史读取的确定性及模型缺失时的可用性。
2. **绑定原模型并复核原分数。** 仅加载已保存 modelId，接受其目录运行或产物运行身份，按原 schema 投影特征，重算须在数值容差内等于原分数。拒绝当前默认替代，避免说明另一模型的行为。
3. **复用单特征遮挡。** 使用模型绑定数据集均值，缺失字段显式归零，至多保留五个非零影响；响应保存 schema、模型哈希、基线数据及缺失字段。数据集均值不宣称为单独训练划分均值；贡献非可加因果分解。
4. **独立持久化成功事实。** 新表按分析与提交复合键保存响应，以外键级联清理。生成在单服务锁内串行，成功结果直接返回，失败可主动重试。相比改写全部提交 JSON，此方式不触碰原分数或采集字段。
5. **前端核对完整来源。** 响应同时核对项目、分析、提交、模型、运行、数据版本和分数。组件取消过期请求，生成期间防重复，保持既有计划上下文。

## Risks / Trade-offs

- [遮挡推理增加前向次数] → 只按需对单提交执行，复用已保存成功结果；当前单实例部署串行生成。
- [原模型或特征不完整] → 返回可公开原因，保留原风险；恢复原产物后允许重试。
- [绑定数据均值缺失] → 明确零值或混合基线和字段，不借其他数据版本。
- [多进程部署重复推理] → 当前单后端实例约束不变；跨实例任务协调需要独立设计。

## Migration Plan

升级前通过 SQLite backup 保存数据库，并保留相配模型目录；停止该部署后端再运行 catalog-init。迁移 010 新建空解释表，旧提交首次读取为尚未生成，不自动批量计算。升级副本验证现有共享列、行数及外键。

回退时先停止新后端、另存升级后数据，再恢复升级前数据库与对应代码，避免旧代码读取新目录版本。不得清空现有分析或模型产物。
