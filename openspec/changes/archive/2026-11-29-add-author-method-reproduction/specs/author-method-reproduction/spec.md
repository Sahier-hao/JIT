# Spec Delta

## Purpose

为五套公开 JIT 方法提供来源可核验、输入输出可追踪、失败可续跑的作者协议复现能力，并把原生方法结果与本地迁移实验结果分开报告。

## ADDED Requirements

### Requirement: AMR-01 作者来源与运行身份固定

每个方法 MUST 固定作者源码仓库、revision、数据来源、不可变快照及校验值、原始划分、标签口径、依赖、预训练权重、随机种子和运行命令。代码、数据和权重 MUST 分别记录使用与分发条件；缺失、哈希不符或许可未核验的材料 MUST 阻止声明该材料已复现。

#### Scenario: 产出一份方法运行清单

- **WHEN** 准备运行任一作者方法
- **THEN** 清单包含源码 revision、数据与权重哈希、划分、标签、依赖、种子和完整命令
- **AND** 代码、数据、权重各有独立的来源、许可和可用状态

#### Scenario: 固定材料不匹配

- **WHEN** 数据、权重或源码 revision 与清单不一致
- **THEN** 运行拒绝开始并指出具体材料与期望值，不使用其他快照替代

#### Scenario: 数据或权重不随仓库分发

- **WHEN** 作者材料没有明确再分发许可
- **THEN** 仓库只保存来源、哈希、获取说明与派生统计，不提交原始大文件

### Requirement: AMR-02 五方法必需输出

系统 SHALL 提供 Kamei、DeepJIT、JITLine、JIT-Fine、JIT-Smart 的独立可运行入口。Kamei、DeepJIT 与 JITLine MUST 输出提交分；JITLine、JIT-Fine 与 JIT-Smart MUST 输出行级排序或逐行分；Kamei 与 DeepJIT 的行级栏 MUST 明确标为“方法只提供提交预测”。JIT-Fine 与 JIT-Smart MUST 使用代码表示与所需标签，MUST NOT 以纯表格适配结果冒充原生方法。

#### Scenario: 方法不提供行级输出

- **WHEN** 查看 Kamei 或 DeepJIT 的结果
- **THEN** 提交分与方法身份存在，行级栏显示方法不提供该能力

#### Scenario: 原生代码表示缺失

- **WHEN** JIT-Fine 或 JIT-Smart 缺少固定的 CodeBERT 权重或源码文本输入
- **THEN** 两方法报告输入或权重阻塞，不用表格特征或另一模型生成替代结果

### Requirement: AMR-03 作者配置与迁移配置隔离

每次作者协议复现和本地迁移实验 MUST 具有独立运行标识、方法版本和配置。更换编码器、损失、标签、特征定义、样本总体或切分 MUST 形成新的迁移版本并列出改动；迁移结果 MUST NOT 计入原论文复现。

#### Scenario: 使用作者配置

- **WHEN** 运行声明作者配置
- **THEN** 报告显示作者方法版本、原始数据划分和协议参数

#### Scenario: 形成本地迁移

- **WHEN** 需要更换语言、编码器、特征或标签
- **THEN** 新运行获得独立版本与改动清单，原作者结果保持不变

### Requirement: AMR-04 真实数据运行等级

系统 SHALL 将接口测试、真实数据小样本端到端、作者协议复跑和正式评价分别记录。只有实际读取固定数据、完成预处理、加载或训练目标模型、产生真实输出并运行评价的步骤 MAY 标为真实数据运行；模拟输出和成功加载权重 MUST NOT 标为完整复现。

#### Scenario: 完成小样本端到端

- **WHEN** 固定数据子集完成入口、预处理、模型、预测与评价
- **THEN** 结果标为真实数据小跑，并记录抽样规则、样本数和未覆盖范围

#### Scenario: 只通过接口测试

- **WHEN** 测试只替换模型或使用固定响应
- **THEN** 结果仅标为接口测试，不计入真实数据复现

### Requirement: AMR-05 行级归因与位置映射

行级结果 MUST 保留提交、文件、侧别、候选行索引和可取得的真实 Git 行号；JITLine 的词元归因 MUST 保留原始词元到行索引的映射。重命名、删除侧、截断、无法匹配、无候选和没有真实行号 MUST 显式计数或返回原因，MUST NOT 根据路径或文本猜测行号。

#### Scenario: 词元聚合为行

- **WHEN** JITLine 产生词元归因
- **THEN** 每个词元可追溯到候选行，行分由声明的聚合方法产生
- **AND** 结果同时保留真实 Git 行号或明确的无行号原因

#### Scenario: 截断或无法映射

- **WHEN** 输入长度截断，或归因词元无法匹配候选行
- **THEN** 该行进入覆盖统计并记录原因，不伪造分数

### Requirement: AMR-06 统一评估与比较边界

提交级与行级报告 MUST 记录指标定义、测试成员、标签和样本量。工具 MUST 分开报告“已知含正例提交内的排序”和“筛查提交后能否抓到正例”；行级报告 MUST 区分 Top-K 命中与固定行预算找回的正例数，并说明并列与预算取整规则。

#### Scenario: 提交级评估

- **WHEN** 多个方法在同一测试成员和标签上评估
- **THEN** 报告包含 AP、ROC-AUC、阈值精确率与召回率，以及声明的行预算指标
- **AND** 数据、成员或协议不一致时不生成统一排名

#### Scenario: 行级评估

- **WHEN** 行级方法在含正例提交上评估
- **THEN** 报告 Recall@1/5/10、MRR、首个正例检查行数、预算召回与基线
- **AND** 完整候选、共同可评分范围和不可覆盖行分别统计

### Requirement: AMR-07 可续跑证据与阻塞记录

每次真实运行 SHALL 保存原始预测、日志、指标、环境、材料哈希和下一可执行任务。依赖、设备、样本或许可阻塞 MUST 定位到方法、阶段和具体原因；已完成的方法或语言 MUST 保持可续跑，不得因另一组合失败而伪造全量完成。

#### Scenario: 设备不足

- **WHEN** 深度方法因无 GPU 或内存不足无法完成作者协议全量训练
- **THEN** 保存小跑结果、设备信息和未完成阶段，并继续运行其他可执行方法

#### Scenario: 从已有产物续跑

- **WHEN** 再次执行同一方法
- **THEN** 复用同哈希材料与已完成阶段，只继续缺失阶段，不覆盖已登记结果
