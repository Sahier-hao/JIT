# Proposal

## Why

仓库已有 Kamei 表格训练、完整候选行导出和 JIT-Fine 数据适配，但尚无五套公开方法的作者源码复现入口，也未把“作者协议复跑”“在本项目数据上的迁移实验”和“仅完成接口/小样本验证”分成可核验的证据。没有这层基线，后续多语言比较与产品接入无法说明分数究竟来自哪套方法、哪份输入和哪次真实运行。

Kamei 论文的近期作者经验是带时间衰减的累计量，而当前 `kamei14-git-v2` 的 `rexp` 是近 90 天提交计数。两者不能共用字段名或模型，需要保留既有历史模型，同时新增独立 schema、采集口径和新模型产物。

## What Changes

- 新增五方法复现目录与统一运行协议，固定作者源码 revision、数据/权重来源与哈希、原始划分、标签规则、依赖、种子和命令。
- 交付 Kamei 作者 12 字段实验配置、14 字段统一对照，以及按论文时间衰减定义计算 `rexp` 的 `kamei14-git-v3` 独立 schema。
- 交付 DeepJIT 的提交说明与 diff 原生推理/训练入口，优先验证作者 Zenodo 数据与预训练权重，并记录论文描述与作者代码的预处理差异。
- 交付 JITLine 的提交级随机森林分类，以及词元归因聚合到行的排序；输出保留提交分、行级排序、词元与行索引/真实 Git 行号映射状态。
- 交付 JIT-Fine 的 CodeBERT 语义向量与 14 维专家特征融合的提交预测和作者注意力行级定位入口；代码表示缺失时明确失败，不以表格适配结果冒充原生方法。
- 交付 JIT-Smart 的提交标签与行标签联合训练、提交分和逐行分；支持作者项目内与跨项目切分，分别保存任务、覆盖和评估。
- 所有方法输出原始预测、日志、运行 manifest、指标和限制；统一区分接口测试、真实数据小跑、作者协议复跑和正式跨语言评价。
- 新增可复跑 CLI、示例输入输出、来源审计、失败/阻塞记录和一份总入口证据报告。

## Capabilities

### New Capabilities

- `author-method-reproduction`: 固定并运行五套公开 JIT 方法，保留作者来源、预处理、预测、行级映射、运行身份、指标与复现等级。

### Modified Capabilities

- `feature-schema-versioning`: 新增 `kamei14-git-v3`，记录 `rexp` 的连续时间衰减口径，并与 `kamei14-git-v2` 的 90 天计数口径及模型身份隔离。
- `repository-collection`: 采集可选择 v2 或 v3 的 `rexp` 口径；v3 使用父链历史上作者提交的时间衰减累计，既有 v2 数据与模型不重算、不改写。

## Impact

- 后端新增作者方法复现模块、CLI、来源清单、数据适配、五方法运行器、指标与证据输出。
- 特征注册、仓库采集与描述文件增加 v3；现有 v2 schema、CSV、模型、训练任务、项目分析和历史结果保持兼容。
- DeepJIT/JIT-Fine/JIT-Smart 需要 PyTorch 与预训练权重；原始大体积数据和权重不随仓库分发，以哈希、许可和获取命令复现。
- 不改变当前默认模型、发布资格、项目分析默认流程或行级研究产品门槛；本阶段产物为离线研究复现，不自动登记为可服务模型。
