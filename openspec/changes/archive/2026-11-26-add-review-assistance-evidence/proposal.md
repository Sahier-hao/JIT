# Proposal

## Why

审查辅助目前有三处证据缺口：行级研究仍只有抽样代理指标，且研究预览无法解释单行为何被排在前面；提交解释只有特征键和原始摘要，历史修复证据也不能从提交详情或 PR 只读视图直接定位到修复 diff 的文件与行号；静态修复建议只覆盖三条 Python 规则，规则升级时也没有明确隔离旧结果。

## What Changes

- 对冻结行级研究模型执行完整候选集、按仓库留出的影子评估，报告 Recall@1/5/10、MRR、首个正例检查行数与随机/文件顺序基线，并用固定门槛决定是否允许产品接入。
- 研究预览按行返回截距与前三项特征贡献，保留原排序分数；前端展开显示中文特征名、本次值、权重、贡献和其余贡献合计，固定标注不是缺陷原因。
- 提交解释新增只由已保存贡献项生成的中文模板摘要；旧解释缺少新字段时回退原摘要，不重算或改写。
- 提交详情、PR 只读详情和离线 PR 报告统一展示已保存的历史修复证据，并链接到修复提交 diff 的对应文件与行号；证据只读，不生成补丁。
- Python 静态规则新增 `subprocess(shell=True)`、缺少 Loader 的 `yaml.load`、`requests(verify=False)` 与 `tempfile.mktemp`；规则/分析器版本升级，旧 v1 结果按原版本只读展示并标记，不与新结果混用。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `line-level-prediction`: 新增完整候选集影子门槛与研究预览的逐行特征贡献。
- `prediction-explanation`: 新增由已保存贡献项生成、兼容旧解释的模板摘要。
- `code-candidate-location`: 扩展高置信 Python 规则并隔离新旧规则版本。
- `pr-check-report`: 离线分析包与报告携带只读历史修复证据。
- `public-pull-request-review`: PR 只读详情展示历史修复证据和旧规则结果状态。
- `focused-project-review`: 提交详情展示只读后续修复证据及修复 diff 行号。

## Impact

- 后端：行级影子评估与打分响应、提交解释、PR 快照分析、离线报告、Python 静态规则及其测试。
- 前端：行级研究页、提交详情解释与证据、PR 只读详情、候选建议、API 契约类型。
- 数据与模型：不修改既有模型产物、默认模型、项目分析分数或历史解释；新增字段向后兼容。
- 文档：`docs/当前产品.md`、`docs/离线与研究.md` 与 2026-11-26 四份审计记录。
