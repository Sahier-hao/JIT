# Design

## Context

行级研究模型是独立系数产物，不能登记为产品模型；提交解释和 PR 候选已经有稳定身份与保存边界。本次需要在不改变默认模型、历史分数和分析路径的前提下，增强三条审查辅助能力，并让旧解释与旧候选继续可读。现有接口与数据库结构足以承载新增字段，不需要改写既有记录。

## Goals / Non-Goals

**Goals:**

- 用同一冻结行级模型给出可复现的完整候选集定位结论。
- 让行级研究分数可分解、提交解释可读，并补齐历史修复证据的可达性。
- 扩展确定性 Python 建议，同时把新旧规则结果按版本隔离。
- 保持所有新增字段可选或向后兼容，不改变已有模型和分数。

**Non-Goals:**

- 不把行级排序接入项目分析、PR 合并决策或默认模型。
- 不生成、应用或验证补丁，不把历史修复当作模型建议。
- 不重训练模型、不调参、不重新计算旧解释或旧候选。
- 不引入第三方解析器、网络依赖或新的模型服务。

## Decisions

### 冻结模型影子评估

影子评估直接加载已提交的系数模型，在完整候选 JSONL 上按仓库留出计算定位指标。随机基线使用固定种子，文件基线按路径和行号排序；门槛要求两个此前未见、样本充足的仓库在五项指标上同时优于所有基线。选择“严格失败即不产品化”而不是综合平均，是因为单项平均会掩盖 Recall@1 或首行体验的退化。（详见 `docs/审计/2026-11-26-行级定位影子评估.md`。）

### 顶三贡献与完整分解

检测接口返回绝对贡献最大的前三项供阅读，同时返回全部贡献合计和未展示余项。这样既满足展示规模，又能用“截距 + 全部贡献 = 原始 logit”验证分解恒等；只返回前三项会让可选加法无法闭合。原始 `score` 和排序保持不变，模型产物不重新导出。

### 生成时摘要，读取时回退

模板摘要只在解释成功生成时从已保存贡献项构造，并随解释 payload 保存。历史 payload 缺少字段时不在读取阶段补算，前端回退到原摘要。这样避免旧解释因当前代码或标签变化而改变含义。（详见 `docs/审计/2026-11-26-提交解释与历史修复证据.md`。）

### 修复证据锚点由后端计算

GitHub 文件 diff 锚点按路径生成，前端没有可靠的同步哈希工具；由后端在读取已保存证据时附加锚点更简单，也保持前端只负责验证和渲染。修复行使用 `parentRanges` 的左侧 diff 行，引入行保留 `lineRanges`，避免把引入提交行号错误地当作修复 diff 行号。

### 规则版本隔离

新增规则使用新的分析器和规则版本，旧版本运行保持独立主键。读取时优先当前版本，没有当前版本才回退到旧版本，并在响应标记 `legacy`。选择“按旧版本读取”而不是迁移旧候选，是因为候选的规则版本、证据和保存事实必须保持原义。（详见 `docs/审计/2026-11-26-修复建议规则扩展.md`。）

## Risks / Trade-offs

- **旧行级样本不足** → 报告保留不适用和样本不足状态，不用小样本仓库凑门槛。
- **顶三贡献被误读为全部原因** → 页面固定说明不是缺陷原因，并显示其余贡献合计。
- **路径哈希锚点变化** → 没有锚点时仍保留提交链接；不猜测新路径。
- **旧候选与新规则并存** → 响应明确 legacy 状态，重新检查才写入新版本。
- **跨模块展示重复** → 提交详情和 PR 只读视图复用同一修复证据组件，后端统一返回同一证据结构。

## Migration Plan

- 无数据库迁移；新增响应字段均可选或可空，旧记录不重写。
- 新分析使用 `python-ast-v2`；旧 `python-ast-v1` 运行保留，可继续只读。
- 回滚时旧前端忽略新增字段；新规则写入的候选仍可按规则版本识别，不影响历史解释或分数。
