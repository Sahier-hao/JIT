## MODIFIED Requirements

### Requirement: PPT-02 快照、意图与任务复用

后台发现 SHALL 读取真实开放 PR 并固定 base/head 快照；分析意图由基项目、PR、快照、真实模型与评分契约确定，同快照同模型 MUST 复用在途或成功任务，显式更换模型或新快照才产生新意图。批量分析 SHALL 是可查询的持久批次：提交前显示开放 PR 真实总数，允许选择全部、前 N 个或当前页并在创建时固定范围；批次固定真实兼容模型，逐条复用或入队，区分待处理、已入队、复用、失败、跳过、取消与中断，发现不完整或部分失败 MUST 如实显示，重复发起返回活动批次。批次 SHALL 支持取消，取消后停止提交后续条目，未提交条目标记已取消，已入队任务继续独立显示。失败与中断 SHALL 分开重试；已完成 PR SHALL 允许换用不同兼容模型重新分析并保留旧结果，同快照同模型 MUST NOT 重复执行。

#### Scenario: 重复检查同一快照

- **WHEN** 同一 PR 快照与模型已有在途或成功任务
- **THEN** 不重复入队，复用原任务或结果

#### Scenario: 作者推送新版本

- **WHEN** 远端 head 变化形成新快照
- **THEN** 产生新意图并排队，旧结果保留为历史

#### Scenario: 显式更换自动模型

- **WHEN** 用户明确更换项目自动模型
- **THEN** 同快照下产生新意图，旧模型结果仍可读且不覆盖当前分支结果

#### Scenario: 批量分析全部 PR

- **WHEN** 用户选择模型并确认「分析全部 PR」
- **THEN** 批次从远端分页获取开放 PR 快照，并返回可查询的批次标识
- **AND** 已成功且快照未变化的 PR 复用结果，其余按规则入队；进度显示实际入队、复用与失败数量

#### Scenario: 提交前预览批量范围

- **WHEN** 用户打开「分析全部 PR」并选择模型
- **THEN** 界面显示当前开放 PR 的总数和本次将处理的数量
- **AND** 用户可以选择全部、前 N 个或当前页，超出上限的输入被拒绝并说明合法范围

#### Scenario: 批次范围固定

- **WHEN** 用户以「前 50 个」创建批次，之后远端新增或关闭了 PR
- **THEN** 批次只处理创建时固定的前 50 个条目，新 PR 不自动加入，也不因关闭而从已处理记录中消失

#### Scenario: 选择本仓库模型批量分析

- **WHEN** 项目当前结果来自本仓库训练的模型
- **THEN** 该模型作为批量入口的默认选项，批次内所有条目使用同一模型身份

#### Scenario: 无本地缓存或超过一页

- **WHEN** 项目从未检查过 PR，或开放 PR 超过一页
- **THEN** 批次读取全部远端分页，不把本地缓存当作完整清单

#### Scenario: 发现范围中断

- **WHEN** 获取开放 PR 清单中途失败
- **THEN** 批次标记范围未完整获取，不显示「全部完成」，已处理条目仍可核对

#### Scenario: 部分成功与失败重试

- **WHEN** 批次中部分 PR 入队或复用成功、部分失败
- **THEN** 逐条显示实际状态，失败项提供仅重试失败项的入口，成功项不重复入队

#### Scenario: 只重试失败项

- **WHEN** 批次同时存在失败和中断条目，用户选择重试失败项
- **THEN** 只重新提交失败条目，中断条目保持原状
- **AND** 中断条目另有独立入口，由用户明确选择后才重新提交

#### Scenario: 取消批次

- **WHEN** 用户确认取消一个进行中的批次
- **THEN** 批次进入已取消，停止发现和提交后续条目，尚未提交的条目标记为已取消
- **AND** 已入队的单 PR 任务继续执行并各自显示真实状态，不因取消批次被静默终止

#### Scenario: 取消不可自动恢复

- **WHEN** 用户读取已取消批次，或服务重启后再次打开项目
- **THEN** 批次保持已取消，不自动重新提交剩余条目
- **AND** 用户可重新发起一个新批次，原批次记录保留

#### Scenario: 已完成 PR 换模型重新分析

- **WHEN** 用户对一个已完成的 PR 选择与当前结果不同的已登记兼容模型
- **THEN** 创建一条新的 PR 分析记录，原模型结果仍可读
- **AND** 新结果完成后，列表显示所选模型身份与对应分数

#### Scenario: 重新分析不重复执行同一模型

- **WHEN** 用户对已完成的 PR 选择与当前结果相同的模型
- **THEN** 复用现有完成结果，不创建重复任务

#### Scenario: 模型失效

- **WHEN** 批次固定的模型在提交或重试时停用或不可用
- **THEN** 对应条目明确失败，不替换为其他模型

#### Scenario: 重复点击批次入口

- **WHEN** 同一项目已有活动批次时再次点击「分析全部 PR」
- **THEN** 返回同一批次及其真实进度，不创建重复活动任务

#### Scenario: 中断任务

- **WHEN** 服务停止导致 PR 分析或批次未完成
- **THEN** 记录显示「已中断」或「待恢复」，不显示「分析中」，可重新发起批量分析补齐

### Requirement: PPT-05 暂停、取消与重启

项目暂停 SHALL 停止后续检查和新入队，但 MUST NOT 取消已提交任务；关闭或合并的 PR SHALL 停止后续自动分析并保留历史。用户取消或中断的意图 MUST NOT 因下一轮轮询自动复活，需主动重试或新版本。服务停止或休眠期间 MUST NOT 承诺检查。批次取消 SHALL 只影响该批次后续的发现与提交，MUST NOT 改变项目级自动分析开关，也 MUST NOT 取消已提交的单 PR 任务；取消后批次 MUST 保存已处理条目的真实结果，重新发起 SHALL 创建新批次而不是复活旧批次。

#### Scenario: 项目暂停
- **WHEN** 用户暂停项目跟踪
- **THEN** 不再检查或入队，已提交任务继续并记录终态

#### Scenario: 取消后轮询
- **WHEN** 用户取消某意图后下一轮检查
- **THEN** 同一意图不自动重建，需用户主动重试或等待新版本

#### Scenario: 重启恢复
- **WHEN** 后端重启且存在遗留检查
- **THEN** 过期租约收敛为中断，不自动重跑旧意图

#### Scenario: 取消批次不影响自动分析
- **WHEN** 用户取消一个手动批次，而项目同时启用了自动分析
- **THEN** 自动分析开关与固定模型保持不变，后续轮询继续按原规则运行

#### Scenario: 取消后重新发起
- **WHEN** 用户取消批次后再次点击「分析全部 PR」
- **THEN** 创建新的批次并重新固定模型与范围，旧批次的条目和结果仍可查询
