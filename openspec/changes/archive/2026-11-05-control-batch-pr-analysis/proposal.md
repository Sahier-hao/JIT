## Why

「分析全部 PR」当前一次覆盖项目全部开放 PR：sub2api 有 1,058 个开放 PR，用户无法在提交前看到规模或设置范围，批次开始后也没有取消入口，只能重启服务中断。失败重试同时包含失败和中断条目，已完成 PR 也没有换模型重新分析的路径，导致批量入口难以在真实大型仓库上安全使用。

## What Changes

- 批量入口在提交前展示当前开放 PR 的真实总数与预计处理量，并允许选择范围：全部、前 N 个或当前页；范围在批次创建时固定并写入批次记录。
- 新增批次取消：停止后续条目提交与刷新，尚未提交的条目标记为已取消；已入队的单 PR 任务不因取消批次被静默终止，继续如实显示各自状态。
- 失败重试拆分为「仅重试失败项」与「重新分析中断项」两个入口，不再用一个按钮同时重试两类条目。
- 已完成的 PR 提供「换模型重新分析」：选择与当前结果不同的已登记兼容模型后创建新分析并保留旧结果；同一快照与同一模型仍复用，不产生无意义重算。
- 批次与条目状态如实呈现范围、已取消、中断和实际模型身份，异常继续使用既有结构化错误信封。

## Capabilities

### New Capabilities

无新增能力；本次只调整已有项目 PR 批量分析的行为。

### Modified Capabilities

- `project-pr-tracking`: 批量分析增加提交前范围预览与上限、批次取消、失败与中断分开重试、已完成 PR 换模型重新分析，并明确取消后已入队任务的独立状态。
- `focused-project-review`: PR 批量分析接口的错误协议扩展到新的范围、取消和重新分析参数，非法范围与不可取消状态必须返回可执行错误。

## Impact

- 后端：PR 批量分析创建、进度、重试与取消接口；批次持久记录增加范围与取消字段；单 PR 分析支持显式指定不同模型并保留历史。
- 前端：项目 PR 审查的批量入口、批次进度栏、PR 行操作与错误提示。
- 数据库：`pr_batch` 增加范围与取消相关字段的前向迁移；旧批次按「全部范围」兼容读取。
- 契约与文档：更新 OpenAPI 与 PR 审查使用指南；新增批次范围、取消、重试与重新分析的行为测试。
- 兼容性：既有批次、已完成结果和自动分析状态语义不变；未指定新参数时保持原「全部开放 PR」行为。
