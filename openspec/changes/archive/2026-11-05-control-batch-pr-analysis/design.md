## Context

项目 PR 批量分析已经是持久批次：创建时固定模型，分页发现全部开放 PR，逐条刷新快照后复用或入队，进度来自实际条目。现有实现有三个直接约束：批次范围只有「全部」；批次没有取消状态和控制接口；重试接口不分失败与中断。真实仓库（sub2api 有 1,058 个开放 PR）表明，一键全部范围会让用户在数小时内无法止损，而失败与中断混在一起重试会重复提交大量可恢复条目。

单 PR 分析接口已经支持按模型创建分析，同一快照不同模型会自然产生新意图；缺少的是已完成后「换模型重看」的入口，以及同模型复用规则在 API 层的显式说明。

## Goals / Non-Goals

**Goals:**

- 批次创建前显示真实规模并允许固定范围：全部、前 N 个、当前页。
- 提供可重复调用、幂等的批次取消，停止后续发现与提交并保留真实结果。
- 把失败项与中断项的重试入口分开。
- 让已完成的 PR 可以选择不同模型重新分析，同时保留旧结果。
- 保持自动分析、既有批次和已完成结果的语义不变。

**Non-Goals:**

- 不改变单 PR 分析的采集、特征、模型或打分口径。
- 不在本次实现批次暂停/恢复、断点续传或跨项目批量。
- 不实现按 PR 风险或标签自动挑选批量子集。
- 不改变自动分析的轮转、预算和固定模型规则。

## Decisions

### D1. 范围在创建时解析并固定为条目

批次表保存范围类型（全部 / 前 N 个 / 当前页）、N 与页号。创建时解析出本次要处理的 PR 编号并逐条写入批次条目，之后远端新增或关闭 PR 不改变已固定条目。选择「全部」时保持现有完整分页发现；选择「前 N 个」时按远端返回顺序读取到 N 个即停止发现；选择「当前页」时只刷新该页并固定该页编号。这样取消、重试和进度都以条目为准，不受远端顺序变化影响。

否决方案：创建时只存范围参数、执行时再展开——远端顺序变化会让「前 N 个」在不同时刻指向不同 PR，进度也无法稳定对账。

### D2. 取消是批次级状态，不是删除

批次新增「取消请求时间」与终态「已取消」。取消接口只写请求并唤醒批次线程；线程在每轮发现或提交前检查取消标志，停止后续动作，并把仍为待处理的条目标记为已取消。已入队的单 PR 任务不取消，继续按自己的状态机执行并如实显示。取消请求幂等：重复调用返回当前批次状态；已完成或未请求取消的中断批次拒绝取消并返回冲突错误。取消后再次发起会创建新批次。

否决方案：取消时级联取消全部已入队任务——单 PR 任务属于用户已提交的工作，静默取消会丢失可完成的结果，也不符合现有单任务取消需要显式确认的行为。

### D3. 重试按条目状态分组

重试接口接受重试范围：失败、中断，默认失败。前端在批次栏提供两个独立入口，只有对应条目存在时才显示。重试只为选定状态的条目重新提交，已提交或已完成的条目不重复入队；单条重试沿用同快照、同模型与既有显式重试语义。

### D4. 已完成 PR 的重新分析只允许换模型

已完成行提供「换模型重新分析」，复用单 PR 分析接口并显式传入不同模型。同一快照不同模型会由既有意图规则产生新任务，旧结果保留。若用户选择与当前结果相同的模型，服务端返回现有结果或说明无需重复执行，不创建任务。这样不引入「同模型强制重跑」的新状态，避免重复消耗采集与打分资源。

### D5. 前端以真实条目状态驱动操作

批量入口在打开时读取开放 PR 总数，范围选项与数量提示来自该次真实读取；不把本地缓存页当作总数。批次栏按状态显示取消入口、两个重试入口和范围说明。PR 行按分析状态显示分析、重试、换模型重新分析或仅查看，轮询沿用现有批次与运行中状态刷新。

## Risks / Trade-offs

- [远端顺序不稳定导致「前 N 个」含义变化] → 创建时固定编号，批次详情显示实际范围；用户在创建前看到的是当时读取的数量。
- [取消与提交线程竞争] → 取消只写标志和终态请求，由线程在安全点收敛；重复取消幂等，终态批次返回冲突而不改状态。
- [大量已入队任务继续运行，用户以为已经全部停止] → 批次栏明确区分「批次已取消」与「仍有个别 PR 任务在执行」，并保留每个任务的独立状态。
- [换模型重新分析产生多条历史] → 每条记录保留模型身份与完成时间，列表按最新结果展示，旧结果可打开；不覆盖或删除。
- [新增字段影响旧批次读取] → 迁移把旧批次范围视为全部，旧批次取消字段为空，读取与进度行为不变。

## Migration Plan

新增前向迁移，为 `pr_batch` 增加范围类型、范围数量、页号、取消请求时间和取消完成时间字段，并为旧批次写回「全部范围」。迁移前按既有流程备份数据库；旧批次、旧条目、已完成结果和自动分析配置不改写。回滚应用版本时保留新字段，旧版本读取既有列不受影响。
