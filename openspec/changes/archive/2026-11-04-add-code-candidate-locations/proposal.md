# Proposal

## Why

模型分数是提交级的，只能告诉审查者“先看哪次提交”，不能指出具体核对哪一行。直接把提交分数拆成行级“缺陷概率”会制造未经证据支持的精确定位。需要把可复核的静态分析候选位置与模型风险分开呈现，并明确覆盖边界。

## What Changes

- 新增静态分析候选位置：绑定固定快照的侧别、文件路径、行号、规则标识与版本、消息和证据。
- 候选位置与模型分数分开展示，不换算成行级缺陷概率，也不改写提交风险。
- 首版只注册受支持的 Python AST 规则；其他语言明确标记未覆盖。
- 分析器需要完整文件内容时，先取得固定 SHA 的内容；内容不可用则标记未分析，不生成候选。
- 审查者可对候选位置标记确认、驳回或暂缓并填写理由；判断保存在个人工作单。
- 首版不自动生成或应用修复补丁。

## Capabilities

### New Capabilities

- `code-candidate-location`: 固定版本的静态分析候选位置、证据、覆盖边界和人工确认。

### Modified Capabilities

- `public-pull-request-review`: 在 PR 工作单中把代码候选位置与模型线索分开呈现。

## Impact

- 新增静态分析模块、候选持久化与 PR 快照关联。
- 前端：[PullRequestJourney.tsx](../../../frontend/src/pages/PullRequestJourney.tsx)、问题与证据组件。
- 模型分数、个人草稿格式和既有分析结果保持不变；候选位置不进入模型输入。
