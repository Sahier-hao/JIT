# Design

## Context

PR 快照保存补丁和文件元数据；完整文件内容由 `pr_review.context()` 按固定 SHA 从 GitHub 取得并缓存到 `pr_file_content`。候选分析需要完整内容，不能在只有补丁时猜测行号。个人草稿保存在浏览器，服务端只保存共享快照与候选。参见 proposal.md。

## Goals / Non-Goals

**Goals:**

- 候选位置绑定固定快照、侧别、路径、行号和规则版本。
- 内容未取得时明确标记未分析，不生成候选。
- 候选与模型分数分开存储和展示。
- 人工判断留在个人工作单。

**Non-Goals:**

- 不实现跨语言全覆盖，也不保证零误报。
- 不自动生成或应用修复补丁。
- 不把候选位置变成模型输入或训练标签。

## Decisions

**分析器适配层。** 定义接口：输入侧别、路径、固定 SHA 和完整内容，输出规则标识、规则版本、行号、消息和证据摘要。首版注册 Python AST 规则（裸 `except`、可变默认参数、`eval`/`exec` 使用），其他语言标记不支持。分析器版本随结果保存。

**触发与内容来源。** 候选分析在用户显式请求，或该文件完整上下文已经取得时执行；不在快照创建时仅凭补丁执行。内容未取得时记录 `not-analyzed` 及原因；读取失败保留原因，不生成候选。

**候选持久化。** 新增 `pr_candidate_run` 与 `pr_candidate` 表，按快照、侧别、分析器版本和规则保存候选与覆盖说明。同一快照与分析器版本重复请求复用结果；分析器版本变化产生新结果，不覆盖旧结果。候选只引用快照内容，不写模型分数。

**个人判断留在浏览器。** 确认、驳回、暂缓及理由写入现有个人工作单，按快照、侧别、路径、行号、规则和轮次隔离；候选标识稳定，重开后仍能对应。导出与备份包含这些判断。服务端不接收个人判断。

**工作单分开展示。** 工作单增加「代码候选」区域，按文件和规则筛选，点击定位到固定侧别与行号；模型线索区域保持原样。未分析文件在覆盖说明中列出。

## Risks / Trade-offs

- [静态规则误报] → 候选只作线索，必须人工确认；界面不称为缺陷。
- [语言覆盖有限] → 明确列出支持语言和未覆盖文件，不用未分析推断无候选。
- [完整内容读取受限流影响] → 复用 `pr_file_content` 缓存，读取失败显示原因并保留未分析状态。
- [候选数量过多] → 按文件、规则和严重度筛选；首版规则保守。
- [个人判断与服务端候选版本不一致] → 个人判断保存候选标识与快照，重开时核对；不一致时提示复核。

## Migration Plan

1. 新增候选运行与候选表迁移；既有 PR 快照、分析和模型分数不变。
2. 旧快照没有候选结果时显示未分析，不自动补算。
3. 回滚时停止生成候选；已保存候选保留，不影响模型分数。
