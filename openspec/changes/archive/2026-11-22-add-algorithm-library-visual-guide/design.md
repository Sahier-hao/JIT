# Design

## Context

见 `proposal.md`。训练方法接口已经返回 `guide`、`requires`、`preprocess`、`explanation` 和参数声明；现有弹窗只展示部分文字。新增页面需要复用这份声明，并避免在训练流程中引入第二套参数或算法选择状态。

## Goals / Non-Goals

**Goals:**

- 以独立路由和导航提供完整算法图库。
- 用方法结构元数据驱动可访问的示意图，保持 9 种方法可比较。
- 在桌面采用列表与详情的连续工作区，在窄屏改为上下布局。

**Non-Goals:**

- 不增加新的算法、训练能力、自动推荐或自动调参。
- 不把图示解释成训练性能结论。
- 不替换训练弹窗中的快速说明。

## Decisions

### 方法目录补充视觉元数据

为每个注册方法增加结构化 `visual`：图表类型、输入、输出和阶段名称。前端只负责按类型渲染，不维护另一份算法说明。替代方案是前端按方法 ID 硬编码全部文案；这会让算法注册表与页面说明分叉。

### 新页面复用方法目录而非新增接口

`#/algorithms` 直接读取 `/api/v1/training-methods`，显示默认 schema 与依赖可用性。页面是只读图库，不保存表单。替代方案是单独提供算法百科接口；会增加重复数据源。

### 结构图采用可访问的 DOM/CSS 图

每种方法使用节点、箭头和层结构表达算法形状，并提供 `role="img"` 与等价文字标签。相比生成图片，DOM/CSS 图能随主题和窄屏调整，也能参与自动化可读性检查。

## Risks / Trade-offs

- 9 种方法结构图可能在小屏拥挤 → 采用可换行节点、短标签和上下布局。
- 视觉元数据可能与训练实现漂移 → 元数据和方法注册表同文件维护，并由目录 API 测试检查。
- 图示可能被误读为性能证据 → 页面只说明结构和适用边界，不展示虚构准确率或排序。
