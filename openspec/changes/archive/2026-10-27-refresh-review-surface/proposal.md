# Proposal

## Why

审查工作区现在能跑通真实 PR，但表面仍然像原型。审查队列把「我的审查」渲染成居中大标题加一句说明，真正要判断的内容（待审工作单、进度、未关闭问题）被压在下面；进入工作单后，代码只占中间约 560 像素，长行折成三段，差异是纯文本、没有行号也没有语法高亮，点行加证据时整行在旧、新两个行号栏同时高亮，用户无法确认自己指向的是删除前还是修改后的那一行。文件路径被挤成 `api.p y` 这样的折行，项目详情页还出现重复标题和左侧绿边卡片。

这些不是审美问题：审查者的任务是在有限注意力下判断一处改动是否可信，代码与证据的可读性直接决定判断质量。表面不统一、控件尺寸与状态反馈不一致，会让用户把注意力花在辨认界面上。

## What Changes

- **审查队列**：`我的审查` 改为可扫描的工作队列——顶部是接入输入与「检查关注工作更新」，下面是按分组排列的工作行（标题、来源、状态、进度、未关闭问题、检查时间、下一步动作），不再使用居中的标题区块。
- **工作单三栏**：左「文件与进度」、中「代码」、右「问题与人工记录」；进入工作单时收起左侧工作区导航，把宽度让给代码，代码栏在 1440 宽视口下不少于 780 像素。
- **差异阅读器**：语法高亮、按文件分区、行号栏区分旧行与新行、支持统一/并排切换、完整上下文与标记已读；点击行号把证据固定到对应侧的行，并显示当前证据位置。
- **组件层**：引入 antd 作为基础控件（按钮、输入、下拉、分段、标签、抽屉、提示、弹层），主题令牌从现有 CSS 变量读取，保证切换主题与密度时控件跟随；图标统一用 `@ant-design/icons`。
- **表面统一**：页头、栏头、状态徽标、空态、加载与失败提示统一为同一套间距、字号与边框规则；文件路径按尾部截断，不再出现被吃掉的字符。

### Modified Capabilities

- `interface-presentation`: 新增审查队列与工作单的表面要求——代码优先的三栏结构、差异阅读器的行号与证据定位、队列行的信息层级，以及控件与主题令牌的一致性。

## Impact

**前端**：`pages/PullRequestJourney.tsx`（队列与工作单）、新增 `ui/CodeDiff.tsx` 与 `ui/AntdProvider.tsx`、`styles/workbench.css`、`AppShell.tsx`（路由标记与导航收起）、`main.tsx`（Provider 挂载）。

**依赖**：新增 `antd`、`@ant-design/icons`、`react-diff-view`、`refractor`；`react-diff-view` 需要 `gitdiff-parser` 提供的差异结构，`refractor` 需要自建类型声明。

**契约**：不变。接口、快照结构、草稿存储格式与导出内容都不改动，`localStorage` 中的旧草稿仍可继续读取。

**测试**：类型检查与构建；队列与工作单在 1280×720、1440×900、约 390 像素宽下的截图核对；点击行号、切换统一/并排、文件切换、证据跳转、抽屉关闭与草稿恢复的人工走查。

**风险**：antd 的默认样式与既有 CSS 变量体系存在冲突，需要把令牌桥接进 `ConfigProvider`；`react-diff-view` 不渲染 hunk 头，需要自行补一行；语法高亮只覆盖已注册语言，未覆盖的文件类型退回纯文本。
