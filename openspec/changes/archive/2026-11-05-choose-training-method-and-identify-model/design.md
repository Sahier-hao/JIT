## Context

系统已有九种注册方法，管理员训练任务可以选择方法和指标集；项目分析的自动与强制训练路径仍在创建作业时固定逻辑回归，模型名称也只带仓库、逻辑回归与时间范围。特征 schema 覆盖六字段与十四字段两套口径，仓库采集固定使用十四字段，但名称不体现字段数，用户难以判断一个模型实际使用了哪套特征。同步作业记录已经保存策略、模型和数据集，缺少方法字段，无法在重试和结果页保持方法身份。

## Goals / Non-Goals

- 让项目分析在自动或训练时选择已注册方法，并在创建时完成兼容性与依赖校验。
- 方法和特征口径贯穿请求、作业、重试、结果与模型登记。
- 模型显示名能直接区分方法、schema 与字段数。
- 未选择方法、旧作业与旧模型保持原行为。

**Non-Goals:**

- 不实现超参搜索、自动方法选择或按指标推荐方法。
- 不改变方法注册表、特征 schema、训练分区与指标口径。
- 不把方法选择开放给 PR 单条或批量分析；PR 分析仍只使用现成模型。
- 不改变默认模型、模型启停和自动分析固定模型规则。

## Decisions

### D1. 方法在创建时校验并固定

创建分析请求增加可选的方法标识。服务端只接受已注册方法，并在创建时检查：方法与当前采集 schema 的入模宽度兼容、方法声明的预处理能作用于该 schema、方法要求的运行依赖已安装。任一不满足即拒绝创建并给出具体原因。校验发生在作业入队之前，避免排队后才失败。管理员训练任务已有的方法校验与执行路径复用，不复制第二套训练逻辑。

否决方案：先入队、训练阶段再校验——用户要等待排队和采集后才知道方法不可用，失败成本高且难以解释。

### D2. 未选择方法时保持逻辑回归

请求缺少方法字段时使用逻辑回归，与当前行为一致。作业记录同时保存请求方法和实际使用的方法；旧作业在迁移中写回逻辑回归。按原参数重试时沿用原方法，方法不可用则失败并要求重新选择，不回退到默认方法。这样「默认兼容」和「失败不静默替换」同时成立。

### D3. 方法身份写入作业与模型身份

同步作业新增方法字段，作为请求快照的一部分保存。训练使用该方法；模型登记继续保存算法版本与 schema。模型显示名由仓库、方法显示名、schema 与入模字段数、数据范围组成；详情展示方法、schema、字段数、数据集版本、运行与同步作业。名称只用于识别，不作为唯一身份，模型仍以目录分配的标识为准。

### D4. 自动降级不伪造方法

自动策略在样本不足时降级到现成模型，此时用户选择的方法没有执行。作业记录保留请求方法，同时记录实际路径为现成模型和降级原因；界面明确说明「选择了某方法但未训练」。不把现成模型登记为用户所选方法的产物，也不生成该方法的模型名称。

### D5. 前端方法列表来自真实可用性

分析表单在自动或训练模式下读取方法目录，显示已注册、与当前 schema 兼容且依赖可用的方法；默认逻辑回归。不可用方法可以显示但禁用并说明原因，也可以不显示，但不得让用户选择后才失败。选择现成模型时隐藏方法选择，避免把两个决定混在一起。

## Risks / Trade-offs

- [深度方法训练时间与内存显著高于逻辑回归] → 创建时提示方法类别与依赖，保留作业超时和取消；不因选择方法绕过超时。
- [依赖未安装导致方法列表与实际能力不一致] → 以服务端真实环境检查为准，前端只展示服务端返回的可用性。
- [模型名称变长] → 名称用于识别，详情承载完整谱系；列表可截断显示，但保留方法与字段数关键字。
- [旧作业没有方法字段] → 迁移写回逻辑回归，读取与重试行为不变。
- [方法选择扩大用户误用范围] → 默认逻辑回归，方法只在训练模式出现，失败不自动换方法。

## Migration Plan

新增前向迁移，为同步作业增加方法字段并写回逻辑回归；旧作业、旧模型、默认模型与自动分析配置不改写。迁移前按既有流程备份数据库。模型名称按读取时生成，不重写历史产物；旧模型缺少方法字段时按登记信息显示，不补造。回滚应用版本时保留新增列。
