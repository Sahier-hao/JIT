# Proposal

## Why

代码评审员需要从一批提交中找到优先审查对象，并能查看风险依据、保留自己的审查选择。本项目从空白目录重建，先交付可运行的桌面评审原型，验证这条用户链路，为后续公开数据集与真实模型接入建立可验收的界面基线。

## What Changes

- 新增中文桌面评审工作台：单项目风险列表、提交详情和优先审查清单，支持提交标识搜索、提交时间筛选、风险排序及清单加入、移除、返回详情。
- 提供确定性的演示数据，持续标明演示模式；分数、解释和时间仅用于交互验收，不冒充真实预测、已核验标签或实验结果。缺失分数显示“暂无预测”。
- 覆盖空列表、筛选无结果、信息缺失、数据加载失败和清单保存失败的可观察反馈。
- 将完整链路的正常、边界和异常场景，以及桌面可操作性证据纳入验收；任务勾选、构建成功或 OpenSpec 校验通过均不能单独证明功能合格。
- 本次提案建议默认：同一浏览器保存个人清单，以演示数据版本区分记录；使用紧凑列表与右侧详情布局。这些是待评审的规划选择，不是此前用户已确认的细节。

### Scope and boundaries

本 change 是前端交互原型增量。它不覆盖公开数据集导入、真实模型训练与推理、正式模型解释、模型比较、实时提交或 PR 接入、任意仓库导入、登录与多人协作、跨设备清单同步、行级缺陷定位、移动端完整体验或公网部署。

完整 MVP 后续应接通真实数据和模型，并验收实际风险评审链路；课程所要求的模型种类、数量与正式测试另行安排。依据用户在本次探索中转述的教师确认，自行通过 SZZ 构建数据集属于可选扩展。本提案不将这一确认扩大为其他课程要求的豁免。

## Capabilities

### New Capabilities

- `commit-risk-review`: 评审员浏览提交风险、查看来源与解释、维护个人优先审查清单的完整交互；本次先建立明确标注的演示模式。

### Modified Capabilities

无。当前主规格为空。

## Impact

- 当前目录没有业务代码或应用框架；所有实现从本项目新建，不继承旧项目的代码、架构、技术栈或 OpenSpec 产物。
- 本轮仅生成本 change 的规划产物。进入 apply 后，预计新增 `frontend/` 应用、行为测试和交付说明；技术选择、成本及替代方案见 `design.md`。
- 不新增后端、数据库或外部业务 API，也不提前为整个系统设计表结构和接口。演示数据的来源标识需与未来真实数据模式保持清晰边界。
- 验收证据与规格场景、实现任务建立映射；本 change 验收不代表课程完整 MVP 或最终交付已完成。
