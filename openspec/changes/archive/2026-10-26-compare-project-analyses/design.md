# Design

## Context

项目已有独立成功分析、固定详情与历史记录。原分数和采集度量已保存，模型产物可能在后续不可用，当前结果指向也可能变化。动机见 proposal.md；实际验收见 docs/审计/2026-10-26-analysis-comparison.md。

## Goals / Non-Goals

**Goals:** 用明确的双分析身份核对覆盖和原分数，保持原结果及审查上下文。

**Non-Goals:** 不重新评分、不按差异评价模型效果、不比较缺陷标签或推断代码增删，不合并个人计划，不跨项目比较。

## Decisions

1. **双固定身份与只读快照。** 接口要求 baseSyncId 和 targetSyncId，在一次只读事务核对项目与成功状态并读取必要字段。相比引用动态当前结果，书签和重复读取保持同一来源；不依赖模型产物。
2. **提交标识并集。** 共同提交对照保存风险和度量，单侧成员缺失风险与差值为空。差值为目标减基准，输入度量或规模不同也列为变化；标签和其他评价信息不参与。
3. **互斥计数与稳定分页。** 按变化、仅目标、仅基准、一致分组，组内按差值绝对值与提交标识排序。全局计数不随筛选改变，分页针对筛选集合。
4. **来源公开但维护不公开。** 只返回核对所需的模型运行身份、已登记名称元数据和分析参数，不开放管理员产物或验证记录。名称直接从保存元数据读取，不调用会加载模型的目录查询。未知身份不宣称同模型，模型不同持续显示差值局限。
5. **独立路由与请求隔离。** 历史记录进入 compare 地址，详情跳转显式绑定某侧分析；前端校验全部身份、分数差与分页契约，切换时取消旧请求。

## Risks / Trade-offs

- [重复分析的模型或范围不同] → 两侧来源并排展示，并说明单侧覆盖和分数变化不能当作质量结论。
- [并集读取有内存开销] → 沿用单次分析最多 5000 提交的边界，返回筛选后的分页，不提供无界导出。
- [某侧被删除] → 整体返回不存在和重读入口，不展示残留另一侧。
- [极小数值差] → 比较使用明确数值容差，页面小于显示精度时说明，不伪装成显著改善。

## Migration Plan

无新增迁移，不写入原分析或当前结果。新页面仅依赖既有成功记录；撤回代码不影响分析、解释和个人计划数据。旧记录缺失元数据以未记录呈现，不补造来源。
