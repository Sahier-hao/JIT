# Proposal

## Why

项目分析在单 worker 中顺序执行，长时间采集会阻塞后续请求，用户无法取消误提交的分析。阶段切换时才检查超时，也无法及时终止阻塞的 Git 命令。

## What Changes

- 支持取消排队与运行中的分析；重复取消幂等，已结束分析拒绝取消。
- 运行任务通过独立进程树执行，取消、超时或服务正常退出时终止本次工作，保留已有成功结果。
- 返回真实排队位置、开始时间、执行截止时间和取消请求时间；排队时间不消耗执行时限。
- 项目页提供取消确认、取消中反馈、记录保留和原参数重试，日期恢复保持原分析窗口与模型身份。
- 迁移 009 增加任务控制字段和取消终态，保留原作业、提交、模型及管理员数据。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `repository-collection`: 分析取消、执行时限、队列状态和终态保护。
- `focused-project-review`: 取消交互、状态刷新和取消后按原范围重新分析。

## Impact

后端同步编排、私有分析进程、迁移 009、取消 API 与错误契约；前端项目页、请求层、作业解析与重试表单；产品运行说明、OpenAPI 和隔离回归。无需新增依赖，不改变模型训练参数与预测定义。
