# Spec Delta

## ADDED Requirements

### Requirement: RCL-19 可取消分析与终态保护

普通项目分析 SHALL 支持取消排队和执行中的作业。排队取消立即成为 cancelled；运行取消 SHALL 保存请求并在停止本次执行后结束。重复取消 MUST 幂等；已完成、失败或中断的作业 MUST 以 409 拒绝，未知作业 MUST 返回 404。取消 MUST 保留历史记录、选定模型身份和既有成功结果，不允许迟到的成功或失败覆盖终态。

#### Scenario: 取消排队作业
- **WHEN** 用户取消尚未开始的分析
- **THEN** 返回已取消状态，该分析不再执行，其他排队分析继续按顺序处理

#### Scenario: 取消执行中的分析
- **WHEN** 用户在采集、登记、训练或评分期间提交取消
- **THEN** 响应包含取消请求时间，停止本次执行及其子进程后记录 cancelled，期间不允许删除该记录

#### Scenario: 重复取消与完成竞争
- **WHEN** 相同取消请求重复到达，或取消与完成同时发生
- **THEN** 已取消或取消中的请求幂等；完成先提交时取消返回 409，取消先提交时迟到结果不能发布

#### Scenario: 取消保留来源与历史
- **WHEN** 项目已有成功分析 A，新的分析 B 被取消
- **THEN** A 的提交、分数、模型和当前结果指向保持不变，B 保留原参数供重新分析

### Requirement: RCL-20 执行时限与进程退出

分析 SHALL 从实际开始执行起计算执行时限，排队时间不计入。到期 MUST 停止本次分析进程及其子进程，记录 SYNC_TIMEOUT 并释放执行位置；超时结果 MUST NOT 成为成功结果。服务正常退出 MUST 停止其拥有的分析，重启后遗留任务明确中断；已请求取消的遗留任务 MUST 保留取消意图。执行进程意外退出 MUST 保存可诊断原因。

#### Scenario: 阻塞采集超时
- **WHEN** Git 命令或分析计算超过本次执行截止时间
- **THEN** 本次进程树被停止，作业以 SYNC_TIMEOUT 失败，下一项可执行，旧成功结果保留

#### Scenario: 服务退出与重启恢复
- **WHEN** 服务正常退出，或重新启动时发现未完成作业
- **THEN** 正常退出停止自有执行；遗留作业标为 interrupted，已请求取消的作业标为 cancelled，不自动重跑

#### Scenario: 执行进程意外退出
- **WHEN** 分析进程退出但未保存业务终态
- **THEN** 作业记录 SYNC_WORKER_EXITED，可重新发起分析，队列不会永久占用

### Requirement: RCL-21 队列与控制信息可查询

分析查询 SHALL 返回真实待执行顺序、开始时间、截止时间和取消请求时间。队列位置 SHALL 从 1 开始，执行中和已结束作业位置为空；取消排队项后其他项的位置 SHALL 更新。详情、全局记录、项目记录与项目最近作业 MUST 使用一致含义；位置 MUST NOT 被表述为预计等待时长。

#### Scenario: 查询并取消排队项
- **WHEN** 多个分析排队且其中靠前的一项被取消
- **THEN** 后续查询中的待执行位置向前更新，开始执行后位置为空且有实际开始与截止时间
