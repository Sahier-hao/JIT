# Design

## Context

现有前端已经使用 shadcn/ui 的 Button、Card、表格和弹层组件，并通过 Tailwind 工具类组合用户工作区、项目、审查和管理页面。问题来自组件语义的混用：shadcn Button 默认带控件高度，而项目卡片、数据版本和 PR 待处理项把它当成可承载多行内容的容器；同时部分双栏区域没有明确限制内容的最小宽度。详见 proposal.md 和本 change 的 `interface-presentation` delta。

## Goals / Non-Goals

**Goals:**

- 让可点击的多行卡片、列表项和文件项按内容自然撑开，保持可见边界和焦点区域一致。
- 消除项目、数据、训练、PR 审查及管理/审查工作单的页面级横向溢出，并让窄屏布局明确纵向重排。
- 继续使用现有 shadcn/ui、设计令牌和 Tailwind 工具类，统一容器的 `min-width`、换行和内部滚动规则。
- 用真实浏览器在桌面和 390px 视口验证修正后的页面。

**Non-Goals:**

- 不改变后端 API、数据库、模型身份、账户隔离或业务状态机。
- 不重新设计产品信息架构，不新增页面级 CSS 体系或第三方 UI 库。
- 不以全局 `overflow-x: hidden` 掩盖未解决的子布局溢出。

## Decisions

### 1. 将 Button 限定为操作控件，多行内容使用自然高度

卡片或列表项仍可使用 Button 作为交互入口，但必须显式覆盖固定尺寸（例如使用 `h-auto` 和适当的垂直内边距），或将内容放在语义链接/容器中并让内部动作独立存在。这样保留 shadcn 的焦点、禁用和主题行为，同时避免默认 `h-9` 把内容裁在 36px 高度内。直接修改 Button 的默认高度会影响所有普通表单操作，因此不采用全局改变默认尺寸的方案。

### 2. 在双栏和卡片网格边界上使用最小宽度约束

所有会参与 flex/grid 收缩的内容列加入 `min-w-0`，长标题和标识在内容列内使用 `truncate`、`break-all` 或水平滚动容器。桌面双栏保留业务信息密度，窄屏通过现有断点改为单列；不使用页面级隐藏溢出来处理布局问题，因为它会裁掉代码、表格和长来源。

### 3. 共享视觉令牌保持不变，只修正组合方式

继续复用 `src/index.css`、`styles/tokens.css`、shadcn/ui 基础组件和既有间距工具类。布局修正通过组件 className 和少量共享辅助类完成，不引入页面专用样式表，也不改变主题色、密度字号或风险语义。

### 4. 验证以页面级溢出和关键用户旅程为门槛

单元测试覆盖可复用布局约束和关键页面的渲染回归；Playwright/真实浏览器检查项目列表、数据版本、训练实验、PR 审查、项目详情、管理页及窄屏视口的 `scrollWidth`、可见操作和多行内容边界。这样可以发现仅靠 TypeScript、构建或 DOM 快照无法表达的覆盖问题。

## Risks / Trade-offs

- [Risk] 为多行操作项取消固定高度后，列表整体高度会增加。→ 只让内容自身自然撑开；长列表继续在既有列表容器内滚动，并用视口检查确认不会遮挡后续操作。
- [Risk] 部分长标题在窄屏仍需要截断。→ 保留 `title`/可访问名称或在详情入口提供完整内容，优先保证页面无横向溢出和操作可达。
- [Risk] 页面数量较多，局部 className 修正可能遗漏同类模式。→ 用源码扫描定位固定高度 Button 承载多行内容，再用全路由浏览器检查补充验证。
- [Risk] 现有 ECharts chunk 与 lint 警告会继续存在。→ 将其作为既有非阻断项记录，不把它们混同为本 change 的布局失败。

## Migration Plan

不涉及数据或接口迁移。代码发布后由 Vite 热更新或重新构建即可生效；如需回退，恢复本 change 修改的前端文件和 OpenSpec delta，不需要数据库回滚或停止其他服务。
