# Proposal

## Why

真实页面审查发现，多处把多行卡片或列表内容放进带固定控件高度的 shadcn/ui Button，导致项目卡片、数据版本、训练实验和待处理 PR 内容溢出、互相覆盖，PR 页面还会出现页面级横向滚动。前端已经统一到 shadcn/ui，需要把组件使用方式和共享布局约束补齐，避免同类问题继续扩散到用户区、审查区和管理区。

## What Changes

- 为卡片、列表行和可点击内容建立稳定的容器用法，避免固定高度控件承载多行内容。
- 修正项目列表、数据工作区、训练工作区、PR 审查列表及管理/审查工作单中已发现的溢出、裁切、覆盖和宽度撑破问题。
- 统一工作区外壳、工具条、卡片网格、列表行和表格容器的 `min-width`、换行、内部滚动与窄屏重排规则。
- 在 1280×720、1440×900 和 390px 视口下验证主页面、长标识和多行状态信息，不改变业务 API、账户隔离、模型身份或数据语义。
- 增加针对布局容器和响应式边界的回归检查，并记录真实浏览器审查结果。

## Capabilities

### New Capabilities

- 无

### Modified Capabilities

- `interface-presentation`: 修改页面级横向溢出、工作区详情适配、统一控件尺寸与视觉基线的呈现要求。

## Impact

- 影响 `frontend/src/components/ui/button.tsx` 的使用约束及用户工作区、项目、数据、训练、模型、审查和管理页面的布局组合。
- 影响前端布局回归测试、页面级样式检查和真实浏览器验收；不新增运行时依赖，不修改后端接口或数据库。
- 需要新增一份前端布局审计记录，说明问题来源、修改范围、视口验证结果和仍存在的非阻断构建/lint 警告。
