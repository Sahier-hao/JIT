# Spec Delta

## MODIFIED Requirements

### Requirement: IP-08 页面级无横向滚动

界面 SHALL 在 1280×720、1440×900 与 390px 视口下不产生页面级横向滚动，长标识、长原因与完整来源 MUST 在容器内折行或截断并保留可读的完整值。多行卡片、列表行和操作区 MUST 由内容自然撑开或在自身容器内滚动，不得由固定高度控件裁切内容。

#### Scenario: 两个目标视口
- **WHEN** 在任一目标视口打开每个页面并展开最长内容（完整来源、长提交标识、长原因）
- **THEN** 页面横向滚动宽度不大于视口宽度，被截断的值可通过其完整形式核对

#### Scenario: 窄屏长内容
- **WHEN** 在 390px 视口查看长项目名、数据版本、提交标题或多行状态
- **THEN** 内容在页面或所属面板内换行、截断或滚动，主要操作仍可见，页面没有横向溢出

### Requirement: IP-10 工作区与详情适配

仓库工作区 SHALL 以提交列表和所选详情为核心，提交详情在对话框或面板中按需打开。目标桌面视口容纳列表—详情协作，宽度不足时 SHALL 变为明确的详情页面或面板并提供返回。列表、详情、卡片和操作行 MUST 不因固定控件高度或内容长度互相覆盖；页面 MUST 无横向溢出，长标题可核对完整内容，对话框关闭后焦点回到合理触发位置。

#### Scenario: 两个桌面视口查看真实长内容
- **WHEN** 在 1280×720 或 1440×900 搜索、选提交并阅读长详情
- **THEN** 关键文字与操作可达，列表和详情身份一致，无页面级横向滚动

#### Scenario: 窄屏详情返回
- **WHEN** 宽度不足并打开详情后返回列表
- **THEN** 恢复原仓库、分析、筛选与选择；页面可纵向重排，操作不被隐藏或裁切

#### Scenario: 多行列表项
- **WHEN** 项目、数据版本、训练实验或待处理 PR 的标题与元信息需要两行以上显示
- **THEN** 列表项完整显示在自身边界内，下一项从前一项的底边之后开始，操作按钮不覆盖内容

### Requirement: IP-16 工作区控件一致性

工作区内的可编辑控件必须（MUST）来自同一套组件表面：输入框、下拉、数字输入、开关、按钮与折叠面板在审查队列、项目列表、项目详情、分析、验证报告、对比、趋势、管理区与审查工作单抽屉里保持相同的高度、边框、焦点环和禁用态。页面不得（MUST NOT）渲染浏览器原生文件选择控件；需要选择文件时，由按钮触发隐藏的输入框。同一动作在主工作区与管理区使用同一按钮层级，主操作使用产品既有的深墨色，强调色只用于选中态、链接与状态提示。带图标的按钮必须（MUST）声明可访问名称，读屏与自动化测试读到的按钮名不得包含图标文本。承载多行内容的可点击卡片、列表项和文件项 MUST 使用自然高度，并保持内容与焦点区域一致。

同一行内的多个筛选与排序控件 SHALL 共用一种"控件可见边界"的约定：分组互斥的选项用一个带可见轨道的分段控件承载，选中项有实体底面；取值多于三项或文案较长的选择 MUST 收成一个带菜单的按钮，按钮文案反映当前选择，菜单项互斥且当前项带选中标记。工具条中的控件 MUST 与下方列表保持不小于 16px 的间距，MUST NOT 让控件看起来悬浮在内容之上。

#### Scenario: 项目详情页的仓库更新

- **WHEN** 用户展开「更新设置」并编辑跟踪分支、检查频率、时间窗口或提交上限
- **THEN** 每个控件显示为统一组件，聚焦时出现同一焦点环，禁用时呈同一禁用态
- **AND** 「立即更新」与页头「开始分析」显示为同一层级的按钮

#### Scenario: 审查抽屉里的备份与恢复

- **WHEN** 用户打开「版本与说明」再进入「草稿备份与反馈」
- **THEN** 页面只显示「导出完整草稿」与「选择备份以预览合并」两个按钮
- **AND** 浏览器原生「选择文件」控件不出现在任何位置

#### Scenario: 管理区登录

- **WHEN** 未登录用户进入管理工作区
- **THEN** 账户名、密码与确认密码使用统一输入框，提交使用统一按钮
- **AND** 页面上不出现装饰性英文眉标或居中大标题

#### Scenario: 两个汉字的按钮

- **WHEN** 管理区渲染「刷新」按钮
- **THEN** 按钮的可访问名称为「刷新」，中间不插入空格

#### Scenario: 带图标的按钮

- **WHEN** 用户用读屏软件或自动化测试查找「新建项目」按钮
- **THEN** 该按钮的可访问名称就是「新建项目」，不包含图标名称或图标占位文字

#### Scenario: 分析页工具条

- **WHEN** 用户在分析页同时看到搜索框、起始日期、结束日期与排序下拉
- **THEN** 这四个控件的可见高度一致，搜索框文字不被放大镜图标遮挡
- **AND** 点击「清除筛选」后所有控件回到未筛选状态，控件高度不变

#### Scenario: 同一行的筛选与排序

- **WHEN** 用户查看 PR 审查列表的工具条
- **THEN** 互斥的范围选项显示在一个可见轨道内的分段控件中，选中项有实体底面与边框
- **AND** 排序显示为一个带下拉菜单的按钮，按钮文案是当前排序（「排序：按最近更新」或「排序：按风险最高」）
- **AND** 工具条与下方列表之间的间距不小于 16px，控件不遮挡列表首行

### Requirement: IP-30 统一的视觉基线与表面层级

界面 SHALL 以统一的字号、行高、间距、圆角与阴影档位呈现同一层级的内容：页面标题、区块标题、正文、元信息与表格数字在各页面使用相同档位；页面底色、下沉区、卡片与强调面保持可辨且层级一致。卡片网格、列表行与工具条 MUST 使用相同的间距和边界规则，内容长度变化不得改变控件语义尺寸或造成相邻内容覆盖。密度切换 MUST 只调整间距，不改变字号档位的语义。

#### Scenario: 同一层级跨页面一致

- **WHEN** 比较项目、审查、报告与管理页面中同层级的标题、正文和元信息
- **THEN** 字号、行高、字重与间距处于同一档位，没有页面自成一格

#### Scenario: 表面层级可辨

- **WHEN** 查看包含页面底、下沉区、卡片与选中态的页面
- **THEN** 各层表面与边界可区分，同一层级在不同页面的处理一致

#### Scenario: 密度切换保持档位

- **WHEN** 在默认与紧凑密度之间切换
- **THEN** 行距与内边距变化，字号档位与语义不变，主要文字仍满足可读性下限

#### Scenario: 长内容不改变控件语义尺寸

- **WHEN** 同一页面同时出现短标题和长标题的卡片或列表项
- **THEN** 两者使用相同的表面、内边距和交互层级，长内容只增加自身高度或在自身容器内滚动
