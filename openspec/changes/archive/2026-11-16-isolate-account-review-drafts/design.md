# Design

## Context

动机见 [proposal.md](proposal.md)。`prReview.ts` 当前使用 `jit:pr-review:works:v1` 全局键，PR 身份为仓库与编号；工作单已有 revision 冲突保护、按快照保存的轮次、备份合并及反馈。`userClient.ts` 已有会话查询与账户变化通知，服务端以不可修改的用户名识别普通用户。现状依据见 [计划依据](../../../docs/审计/2026-11-15-next-changes-baseline.md)。

## Goals / Non-Goals

**Goals:**

- 以已核验账户作为个人工作单的外层命名空间，保留内部 PR 与快照身份。
- 在账户切换和会话异步竞争中保护旧草稿，并限制写入目标。
- 为旧存储和备份提供显式、可取消、可重试的迁移。

**Non-Goals:**

- 不上传笔记、提供服务器同步、共享团队工作单或改造项目所有权。
- 不承诺 localStorage 对浏览器开发者工具、同源脚本或本机持有人保密。
- 不新增密码、会话 token 或管理员凭据的本地存储。

## Decisions

### 1. 复用服务端账户身份

会话已确认后使用服务端返回的用户名作为当前部署内稳定身份；当前系统没有用户名修改或账户删除复用能力，无需为了命名空间新增数据库标识。显示名称、URL 参数和备份声明均不能改变当前身份。将会话状态明确为核验中、已登录、未登录及核验失败，未知状态不读取工作单。

前端会话接口及其解析器明确约束已登录身份非空、未登录无个人身份；若实现发现需要增加公开字段，须同步 API 契约及服务端测试。已有用户名足以满足行为时不做无关迁移。

### 2. 命名空间与编辑上下文同时绑定账户

新键采用版本化前缀与编码后的稳定账户身份；PR key 和快照结构继续复用。所有读取、保存、导出、合并和事件处理显式接收账户上下文，不在存储函数内部回读一个随时变化的全局用户名。

组件挂载时记录账户和会话世代号；每次异步回调、自动保存、版本更新或备份确认前重新核对。世代变化即取消请求、卸下旧视图，并拒绝迟到写入。各账户保留原 revision 冲突校验；不能因为增加账户键而移除多标签页冲突保护。React 查询缓存及审查列表状态随账户切换失效或按账户分键。

登录、退出、401 和已有账户变化事件统一进入会话控制。通过同源跨标签页提示触发重新向服务端核验，不相信事件携带的自报用户名；页面恢复焦点及个人工作入口也重新核验。收到变化提示至核验结束期间暂停写入，不承诺浏览器尚未观察到 cookie 变化时的瞬时跨标签页同步。

### 3. 旧数据保持无归属，迁移由用户主动选择

旧 v1 键不修改、不删除，也不在登录时自动枚举其个人正文。用户主动选择“导入本机旧工作单”后，先读取并校验原数据，显示当前目标账户与条目，再复用现有逐项冲突合并。成功写入目标后记录源内容哈希作为该账户导入回执，避免重复导入堆叠；原数据仍可作为恢复来源。

首次登录自动认领会把共享浏览器历史错误分配给某个人，因此不采用。也不通过清空 localStorage 来实现退出隔离。

### 4. 备份增加归属提示，保持显式可移植

导出的新备份包含格式版本与非凭据账户提示，继续保存 PR、快照及内容；旧 v1 备份兼容读取为归属未知。导入永远以当前已核验账户为目标，不使用备份身份写其他键。来源不同或未知时在既有预览中明确提示目标并要求确认，随后沿用来源核对、冲突选择、1 MiB 限制与幂等合并。

修改备份结构时采用新格式标识或向后兼容的明确版本，不无提示改变旧解析语义。个人正文不发送给公开快照核对接口。

### 5. 账户切换时保留未保存内容

主动退出前若存在尚未保存文本，提供保存、导出或取消退出的必要操作。外部退出、401 或会话核验变化时立即隐藏旧正文，将当前编辑快照保留在原账户绑定的恢复上下文；存储可用时写入原账户恢复副本。无法持久化时标明未保存，仅在原账户重新核验后恢复或导出，不让 B 的页面展示 A 的未保存内容。

不保证配额耗尽后强行关闭浏览器仍能恢复纯内存文本；此限制沿用现有写入失败语义，应提供当下可用的导出路径。恢复副本及提示不可变成跨账户内容通道。

## Risks / Trade-offs

- [浏览器本地存储并非安全保险箱] → 文档只承诺应用层账户隔离，权限仍由服务端负责。
- [旧工作单归属无法证明] → 不自动分配，保留源字节，通过显式导入和确认目标恢复。
- [其他标签页保存晚到] → 请求世代、账户绑定、会话重新核验和 revision 共同防护。
- [身份切换时写入失败] → 原账户恢复上下文、失败状态及导出，禁止写入新账户作为兜底。

## Migration Plan

1. 发布能够同时识别旧 v1 与新账户命名空间的代码，先只读识别旧数据，禁止自动搬移。
2. 同一账户先验证创建、刷新续审、作者新版本、备份恢复和结论导出，再验证 A/B 切换与跨标签页迟到回调。
3. 提供显式迁移入口，写入与冲突确认完成后记录回执；原 v1 存储及已导出文件不删除。
4. 回退版本前先导出新空间记录，不能把多账户记录合并回旧全局键；旧程序不识别新键时只能说明不可见，不能删除新数据。
