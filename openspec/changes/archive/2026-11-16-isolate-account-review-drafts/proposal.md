# Proposal

## Why

普通用户已有独立账户，但个人 PR 工作单仍按浏览器全局键保存，同一浏览器切换账户可能继续显示或改写此前的工作。需要将个人草稿、阅读进度和反馈与当前已确认账户绑定，同时保护升级前没有账户归属的记录。

## What Changes

- 已登录账户在当前浏览器内分别保存个人 PR 工作单，未知或失效会话不加载其他账户草稿。
- 账户切换时清理旧视图并阻止旧异步请求、定时保存和其他标签页把内容写入新账户空间。
- 保留旧全局工作单，提供显式导入预览、冲突合并及失败恢复，不把旧数据自动分配给首次登录者。
- 继续支持同一账户续审、版本复核、备份恢复、Markdown 交付和私有反馈；个人文本仍不上传。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `personal-review-work`: 按账户隔离本地续审状态，保护账户切换、旧记录迁移与显式备份恢复。
- `user-accounts`: 向客户端提供经服务端确认的个人工作空间身份及失效语义。

## Impact

涉及 `frontend/src/prReview.ts`、`userClient.ts`、账户状态与路由、PR 工作单、审查列表、备份和相关测试，以及必要的会话响应契约。只增加本浏览器内的应用隔离，不承诺同源 localStorage 对本机持有人保密，不引入服务器草稿同步或团队协作。
