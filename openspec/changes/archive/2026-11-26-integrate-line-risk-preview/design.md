# Design

## 接入位置

入口放在 PR 代码阅读区，和现有「检查结果」「问题草稿」并列。只读详情与个人工作单共用 `ReviewCode`，因此两处获得同一入口，不复制实现。

## 数据路径

1. 从 `PRFile.patch` 解析目标侧新增/修改行。
2. 读取固定快照的目标源码，调用现有 `/api/v1/research/line-model/score`。
3. 只保留真实新增/修改行，按排序分降序展示前 10 行。
4. 点击结果只设置当前代码位置，不打开问题草稿、不保存任何内容。

不新增后端接口，避免把研究模型写入目录库或产品训练链路。

## 约束

- 只支持 JavaScript/TypeScript；其他语言明确说明不覆盖。
- 只使用完整 diff 的新增侧行；未取得完整源码时显示提示，不把整份文件冒充当次改动。
- 分数仍来自弱标签与正负抽样，未校准，不是缺陷概率。
- 不改变提交级风险、默认模型、项目分析结果或合并状态。
- 模型失败时不回退到提交级分数或其他语言模型。

## 验证

- 纯函数测试覆盖语言识别、diff 新增行解析和排序过滤。
- 组件测试覆盖研究标签、只显示改动行、特征贡献展开和定位回调。
- 集成测试覆盖从代码阅读工具栏打开页签。
- 运行前端 `typecheck`、聚焦测试、完整单测和构建。
