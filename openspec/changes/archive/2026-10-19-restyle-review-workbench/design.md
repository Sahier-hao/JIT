# Design: 评审台界面重构

## Context

现有前端已经有设计令牌（`frontend/src/styles/tokens.css`，石灰主题）、骨架（`shell.css`）、组件（`components.css`）、页面（`pages.css`）与工作台（`workbench.css`），但骨架是「图标轨 + 上下文栏」两列，工作台是占满宽度的六列表格，来源切换是「历史数据 / 示例数据 / 仓库同步」三段按钮，主入口是公开数据集回放。

本轮重构要把它变成评审工具：仓库维度、扫描优先、结论可带走。设计稿已迭代到 v9（浅色统一版 + 深色可选），关键决定都已确认。

## Goals / Non-Goals

**Goals**

- 评审台以仓库为入口，公开数据集回放降级到「管理 → 验证数据」。
- 一屏内能回答「这个仓库有多少待审、风险分布如何、我该先看哪几条」。
- 列表可扫描：行首风险色条、标题、元信息、风险百分比 + 细条、变更行、文件数。
- 右侧常驻审查队列，带预算（已用行数 / 总预算）。
- 浅色为默认主题，深色可选；舒适/紧凑两档密度；两者都要在刷新后保留。
- 落实 `interface-presentation` 的 IP-01～IP-11。

**Non-Goals**

- 不做移动端布局；1280 以下只保证不横向滚动与可用。
- 不做用户在服务端的「已审/未审」状态（清单仍在 localStorage）。
- 不改后端打分为主逻辑。
- 不做图表库；趋势页沿用既有实现。

## Decisions

### D1 设计令牌整体替换

`tokens.css` 重写，键名保持（`--canvas`、`--rail`、`--sunken`、`--card`、`--fg*`、`--line*`、`--brand*`、`--risk*`、`--r*`、`--sh-*`），值换成 v9 的冷灰体系：

| 键 | 浅色 | 深色 |
| --- | --- | --- |
| `--canvas` | `#F7F8FA` | `#0B1120` |
| `--rail` | `#FFFFFF` | `#070C16` |
| `--fg` | `#0E1524` | `#E8EEF6` |
| `--fg-3` | `#6C7686` | `#7C8DA6` |
| `--line` | `#EDEFF3` | `#1B2436` |
| `--brand` | `#1D4ED8` | `#7BA3F7` |
| `--risk` / `--risk-mid` / `--risk-high` | `#B7791F` / `#B54708` / `#B42318` | 同色相提亮 |

主按钮改为近黑（`#0E1524`），蓝色只用于选中态、链接与焦点环。风险三色保持暖色方向（IP-06），深色只提亮不换色相。

字号阶梯（IP-02 下限 12px 不适用于等宽标识与表头）：

| 用途 | 字号 |
| --- | --- |
| 页面标题（仓库名） | 22px / 650 |
| 区块标题 | 13px / 600 |
| 列表标题 | 13px / 550 |
| 正文与元信息 | 12–12.5px |
| 表头 | 11px / 500 |
| 等宽标识 | 11.5px |

间距用 4 的倍数；内容区左右边距 32px（1280 下 24px）。

### D2 字体

- 新增 `frontend/public/fonts/inter-latin.woff2`（Latin 子集，约 48KB，OFL-1.1）与 `frontend/public/fonts/LICENSE.txt`。
- `@font-face` 声明在 `base.css`，`font-display: swap`，`unicode-range` 限定 Latin 区段，中文自动落到 `--sans` 回退链（`Microsoft YaHei UI` 等）。
- 不加任何 `@import url()` 或 CDN 引用（IP-04）。

### D3 骨架

```
grid-template-columns: 220px minmax(0,1fr)   /* 1280 以下 */
grid-template-columns: 220px minmax(0,1fr) 320px  /* 1440 及以上，右侧队列常驻 */
```

- 侧栏：品牌字标 + 仓库列表（可滚动，含「+ 接入仓库」）+ 三组导航（评审 / 数据 / 管理）+ 底部凭据。
- 右侧队列：`aside.review-queue`，1280 以下改为 `<dialog>` 抽屉，由工具栏的「审查队列 N」按钮打开。
- 顶栏取消；面包屑并入内容区首行，密度与主题切换放右上角。

### D4 评审台布局

1. 标题区：仓库名 + 一行同步摘要（`最近同步 10-18 19:32 · main 分支 · 26 个提交待审`）+ 右侧风险分布（分段条 + 图例）。
2. 提示条：一行结论（风险是估计、不等于已确认缺陷、排序依据）。
3. 工具栏：搜索（标识或标题）、起止日期、排序、清除筛选；右侧显示时区口径。
4. 列表：`grid-template-columns: minmax(0,1fr) 132px 96px 108px 40px`，行高 58，行首 3px 风险色条。
5. 分页：`第 x–y 条，共 n 条` + 上一页/下一页；每页 20 条。
6. 详情：右侧抽屉 480px，Esc 关闭，焦点返回触发元素。

### D5 审查队列

- 数据来源：`localStorage` 存 `{id, addedAt}`，仓库维度 key 含 `repositoryId`（换仓库不继承清单）。
- 面板显示：条数、已用行数、预算、占比、逐条（标题 + 风险）。
- 预算口径：`ceil(0.2 * 该仓库视图总变更行数)`，与后端 `Recall@20%LOC` 同口径；总行数取 `/api/v1/repositories/{id}/summary` 返回值，缺失时降级为「预算未知」而不是猜。
- 空态：一行可执行提示（「从左侧列表挑几条加入」）。

### D6 详情抽屉

- 风险结论块：百分比 + 一句「模型估计的缺陷风险，未经概率校准」。
- 归因：把 `occlusion-mean-v1` 的字段名映射成中文短语（`nf` → 改动文件多、`la` → 新增行多、`ndev` → 多人参与、`ent` → 改动分散、`exp` → 作者经验多），按绝对值排序取前 5，正负用方向与颜色区分。
- 规模：8 项两列（文件、子系统、新增行、删除行、参与作者、距上次改动、改动分散度、作者历史提交）。
- 限制：一句「这不是结论」+ 标签说明（简化 SZZ、新提交尚无标签）。

### D7 来源模型

- 评审台数据源只有一种：`/api/v1/repositories/*`。
- 「管理 → 验证数据」页：保留公开数据集回放与演示，用既有 `/api/review-batch` 与 `/demo-dataset.json`，作为模型查证入口；页面上明确标注「验证用，不参与评审」。
- 删除 `App.tsx` 的「历史/演示/仓库」模式切换；保留 `?mode=` 参数只为验证页服务。

### D8 迁移与兼容

- 旧的 `workbench.css`、`pages.css`、`shell.css` 按新结构重写，类名尽量保留语义（`row`、`list-head`、`pager`），减少测试改动面。
- 依赖「公开数据默认来源」的单测与 e2e 改为「验证数据页」；工作台用例改为「先选仓库」。
- 设计稿 `ui-demo-v2.html` 只作为视觉参照，不进入仓库。

## Risks / Trade-offs

- **移除主界面的公开数据回放**会改变课程验收演示路径。缓解：验证数据页保留全部能力，评审台空态直接给出「去接入仓库」与「先看验证数据」两个入口。
- **右侧常驻面板在 1280 下要收抽屉**，交互多一层。缓解：工具栏按钮显示条数，抽屉与常驻内容同源。
- **设计稿是静态 HTML**，真实数据的长标题、空字段会破坏节奏。缓解：标题单行截断 + `title` 属性，字段缺失走「未提供」。
- **字体子集只覆盖 Latin**，中文仍是系统字族，跨机器观感有差异。这是 IP-04 下的取舍，接受。

## Migration Plan

1. 先后端 `add-repository-workspace` 合入并可用。
2. 前端按「令牌 → 骨架 → 评审台 → 队列 → 详情 → 验证数据页 → 清理旧模式」顺序改，每步保持 `tsc` 与 `vitest` 通过。
3. e2e 跟随最后一步重写选择器。
4. 回滚：整份样式与页面在同一分支，回退该分支即可；后端接口不改。

## Open Questions

- 队列预算的「总预算」是否要允许用户手动改百分比（5/10/20/30）？当前固定 20%，与 Recall@20%LOC 对齐；先固定，后续再给选择。
- 模型页是否要合并进「验证数据」？当前保留独立入口，避免指标与验证混在一起。
