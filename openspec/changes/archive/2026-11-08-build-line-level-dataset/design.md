# 设计：行级样本导出

## Context

SZZ 证据以 `(introducedCommit, fixCommit, path, lineRanges, parentRanges)` 保存，正例只到“哪些行”。行级模型需要逐行样本、上下文和负例。导出层只读数据集描述、CSV 与仓库对象，不写数据库。

## Goals / Non-Goals

**Goals**

- 每个正例行可追溯到引入提交与修复证据。
- 负例来自同一数据集中标签为 0 的提交的实际新增行，按固定种子可复现。
- 输出稳定、可去重、带摘要，便于后续训练与复核。

**Non-Goals**

- 不训练模型、不评估模型，不生成新的登记数据集。
- 不做 AST/token 级特征工程；首版只提供文本、上下文、语言与提交级特征。
- 不跨仓库搬运证据；仓库路径必须可读。

## Decisions

1. **正例来源**：只使用数据集描述中的 `labelEvidence`；对每条证据取 `introducedCommit` 的 `path`（失败时回退 `oldPath`），按 `lineRanges` 逐行生成正例。行内容不存在时记入 `missingLines`，不补造。
2. **负例来源**：读取数据集 CSV，取 `label=0` 的提交，用 `git show --unified=0 --format=` 解析新增行（`+` 侧），按文件路径过滤文档/测试/二进制后抽样；每个提交最多取 50 行，避免大提交主导。
3. **比例与去重**：目标负例数 = 正例数 × `negatives_per_positive`；固定 `seed` 随机抽样；按 `(commitId,path,line)` 去重，正负例不共享同一条目。
4. **特征**：行级字段包括文本、前后各 N 行上下文、语言（扩展名映射）、缩进、长度、空行/注释启发式；提交级字段直接复用 CSV 中的 14 维 Kamei 特征，避免重复计算并保持口径一致。
5. **输出**：JSONL（`schema=line-szz-v1`）+ 同名 `.summary.json`；摘要记录数据集版本、正负例数、提交/文件数、上下文行数、种子、缺失行、跳过原因与被截断的提交。
6. **边界**：单次最多导出 20,000 个正例行与相应负例；超出标记 `truncated`。仓库不可读或 CSV 缺失时明确失败，不输出空文件冒充成功。
7. **不改事实**：导出不写回数据集、目录库或模型；同一输入与种子重复导出内容一致。

## Risks / Trade-offs

- 负例只来自“新增行”，不含未改动行的全量采样；分布与真实代码行不同，需在训练时说明。
- 行级特征首版较浅，可能不足以支撑高精度模型；后续可增加 AST/token/历史特征。
- 行号与路径依赖 blame 与重命名检测；证据缺失时只能跳过，不能猜测。
- 大仓库导出耗时与磁盘占用受上限约束，截断时摘要明确说明。
