## Context

当前 VS Code 扩展为 0.2.0 只读消费 `jit-commit-analysis-v1` 报告，支持导入、身份核对、跳转与复制生成命令，但缺少 CI 报告交接和真实仓库回归证据。`commit-analysis.yml` 已能在 PR 上使用固定模型包生成报告产物，但不评论 PR、不阻断合并。现有主规格 `ide-report-consumption` 已覆盖只读、身份核对和真实仓库状态，`continuous-regression` 覆盖 CI 回归，`pr-check-report` 覆盖报告身份与退出码；尚无集成测试交付能力。

当前人工 OpenAPI 契约包含 99 个操作（63 GET、33 POST、3 PATCH）；其中 4 个 admin 认证操作（setup、login、session、logout）不计入业务 API 清单，剩余 95 个业务操作构成本次集成测试范围。现有测试已覆盖 pytest、OpenAPI 契约、前端 Vitest 和 Playwright 隔离服务，但缺少统一的 95 项清单、四类场景矩阵和正式交付包。

## Goals / Non-Goals

**Goals:**

- 把 PR5–PR8 合并为一个可独立审查的 change 和一个 PR，形成同一份 API 清单、场景矩阵、联调与冻结证据。
- 让 CI 报告产物可以被开发者下载并在 IDE 中显式导入，真实仓库回归有可复核证据。
- 给出 Eclipse 与 Visual Studio 的成本、插件 API、协议复用与风险结论。
- 建立 95 个业务 API 操作的四类场景矩阵，并优先完成高风险接口。
- 用现有测试栈和证据冻结机制交付报告，不新建平行测试体系。

**Non-Goals:**

- 不实现 Eclipse 或 Visual Studio 插件，只交付可行性结论。
- 不改变模型风险算法、默认模型、训练算法、项目分析口径、PR 评论或合并策略。
- 不引入新的 XAI 方法、不把候选位置当作行级缺陷概率。
- 不要求每个操作都产生真实浏览器旅程；浏览器旅程只覆盖关键高风险链路，其余以真实 API/集成测试覆盖。

## Decisions

### 一个 change、一个 PR 承载 PR5–PR8

PR5 的 CI 报告交接与 PR6–PR8 的集成测试共享同一份报告身份、API 清单和证据冻结机制。拆成多个 PR 会让清单、矩阵和截图分散，难以证明同一提交下“清单—测试—报告—冻结”一致。替代方案是继续四个 PR；这会增加跨 PR 身份漂移和证据合并成本，因此不采用。

### 继续使用 `jit-commit-analysis-v1` 作为跨 IDE 协议

CI、VS Code 和未来 IDE 都消费同一份带仓库/提交/模型/覆盖身份的报告。Eclipse/Visual Studio 只做协议复用、插件 API 和成本调研，不维护第二套报告格式。替代方案是为每个 IDE 设计专用协议；这会扩大维护面和身份漂移，因此不采用。

### 95 项清单从人工 OpenAPI 契约生成并校验

清单工具读取 `docs/api/openapi.yaml`，输出全部操作，并显式排除 4 个 admin 认证操作（setup/login/session/logout），得到 95 项业务操作。每项记录方法、路径、operationId、认证/角色边界、风险等级和测试映射。运行时路由漂移继续由 `backend/scripts/check_openapi_paths.py` 检查；清单工具额外校验 95 项数量、方法/路径和 operationId 不漂移。替代方案是手工维护 95 行清单；容易出现遗漏和双重事实来源，因此不采用。

### 四类矩阵以“实际测试或人工复核的不适用”为格

四类场景定义为：正常、边界、异常/失败、并发/故障。高风险接口四类必须有可执行测试；其余接口至少正常与异常/失败，边界与并发/故障可标记不适用，但必须经人工复核并给出业务理由。矩阵生成器只把实际执行且通过的结果计为通过，失败、跳过和未执行都保留原因。替代方案是只统计测试文件总数；无法证明 95 个操作与四类场景的对应关系，因此不采用。

### 高风险优先级固定

高风险域依次为：认证与权限、同步与取消、训练、模型登记与策略、PR 分析与报告、数据集导入、解释生成。它们先完成四类场景，再进入其余接口。风险等级写入清单并由人工复核，不能为了凑覆盖率把高风险接口降级。替代方案是按路径字母顺序平铺；会让高风险接口滞后，因此不采用。

### 复用现有测试栈与证据冻结

后端使用 pytest 与现有测试夹具，接口契约复用 OpenAPI 校验，前端使用 Vitest，浏览器使用 Playwright 隔离服务；统一输出 JUnit、Vitest JSON、Playwright JSON、截图和请求记录。最终通过既有 `freeze-evidence` 生成 SHA-256 清单并由 `check-evidence` 校验。替代方案是新建独立集成测试框架；会增加重复工具和证据格式，因此不采用。

### CI 只交接产物，不改变合并门禁

`commit-analysis.yml` 继续使用固定的模型包、SHA-256 和模型 ID，成功时上传报告产物，失败时不生成替代报告；不评论 PR、不阻断合并、不修改分支保护。开发者显式下载并导入报告。替代方案是让 CI 直接评论 PR 或写入检查门禁；超出当前收益与权限边界，因此不采用。

### 真实仓库回归使用一次性本地 Git 仓库

用固定提交的一次性仓库生成报告，验证导入、身份核对、工作树修改、分支切换、重命名/删除和过期报告；截图与命令输出进入运行工作区。替代方案是只在夹具上测试解析；无法证明真实仓库中的定位与身份行为，因此不采用。

### Eclipse/Visual Studio 只交付结论

结论文档覆盖插件 API 可用性、报告导入/定位复用、安装与分发成本、维护风险和推荐顺序。没有实际插件时报告必须明确“未交付”，不能写成已支持。替代方案是同时做多套不成熟插件；维护成本高且难以验证，因此不采用。

## Risks / Trade-offs

- [95 个操作 × 四类场景工作量过大] → 先高风险、后剩余；不适用格必须人工复核，生成器只统计实际结果。
- [OpenAPI 与运行时路由漂移] → 清单校验叠加 `check_openapi_paths.py`，数量、方法、路径和 operationId 不一致即失败。
- [真实仓库回归受网络和本机状态影响] → 使用一次性本地 Git 仓库、固定提交和隔离端口，不依赖公网或个人数据。
- [CI 报告被误当成合并门禁] → 文档、测试和 PR 说明明确报告默认非阻断；工作流保持只读权限。
- [Eclipse/VS 结论被误读为已交付] → 结论和报告使用“可行性/未交付”措辞，验收检查禁止把调研写成插件完成。
- [AI 辅助测试来源不清] → 逐测试标注来源、归档完整提示词并建立人工复核；复用现有来源校验器并扩展检查。
- [证据数量大且易陈旧] → 统一从一个运行工作区生成、冻结并在报告中记录提交、环境和命令；旧结果不得冒充本次交付。

## Migration Plan

本 change 不修改数据库 schema、模型产物或默认配置，不需要数据迁移。若实现过程中新增清单/报告文件，只写入运行工作区和显式冻结目录；回滚时删除本次新增文件即可，既有训练、解释和模型数据不受影响。
