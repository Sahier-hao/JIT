# Design

## Context

动机与产品范围见 [proposal](proposal.md)，行为约定见 [公开基线规格](specs/public-data-baseline/spec.md) 和 [审查流程增量](specs/commit-risk-review/spec.md)。以下 Context 记录 proposal 时的状态，技术选择作为本轮固定方案实施。当前运行、数值复现与功能证据见 [验收记录](../../../../docs/evidence/connect-public-data-baseline-review/acceptance.md)，实现进度以 tasks 为准。

当前本项目只有桌面前端：`frontend/src/domain.ts` 校验身份与带时区时间，`useDataset.ts` 加载人工 JSON 并支持重试，`App.tsx` 和 `CommitDetail.tsx` 硬编码演示说明，清单按项目与版本保存在 localStorage。已有搜索、日期、确定性排序、详情焦点与清单行为可沿用；真实来源、模型关联和实验摘要尚不存在。上述观察来自当前文件，不继承旧项目架构。

依据分层：

| 类别 | 本设计使用的依据 |
| --- | --- |
| 课程明确要求 | 原始《2026-2027-1 软件开发与测试综合实训 项目要求》PDF，第 1 页列出 Kamei14、传统与深度学习两类至少八种模型、两类评价指标、预测解释与在线预测及前端；第 2 页列出至少 20 个关联用户故事、至少两项非功能要求及过程证据；第 3—4 页要求增量与正常、边界、错误验收。这些是最终交付要求，不全部塞入本增量。文件位于 `D:/code/mycode/jit-defect-prediction/docs/课程资料/`，只读使用。 |

## Goals / Non-Goals

**Goals:**

- 用清晰的数据、训练、评价、推理与界面边界支撑两份规格，尽量复用本项目已验收的交互。
- 让同一提交可追踪到原始行、固定分区、模型风险与实验记录；使服务恢复、数据校验失败与模式切换可测试。
- 将真实数据与小型测试夹具、人工演示及后续完整课程实验分开保存和标识。

**Non-Goals:**

- 不建设通用训练平台、持久业务数据库或任务系统；服务不接收用户上传、任意仓库或训练参数。
- 本轮不给原始特征补造缺失的 Kamei 字段，不通过模型系数、人工说明或发布者标签临时拼装预测解释。
- 不把版本校验、测试打勾或本 change 的归档视为完整课程交付验收。

## Decisions

### D1. 固定公开快照及发布者分析范围，采用六项原生字段

首选 [JITMovingTarget 发布者仓库](https://github.com/software-rebels/JITMovingTarget)，固定提交 `184403ad3734894c8417cbec72fdef3da5edc0b9`。这是 McIntosh 与 Kamei 2018 年论文 *Are Fix-Inducing Changes a Moving Target?* 的复现包；README 要求引用原论文。具体原始依据：

- [openstack.csv](https://raw.githubusercontent.com/software-rebels/JITMovingTarget/184403ad3734894c8417cbec72fdef3da5edc0b9/data/openstack.csv)：提交标识、Unix `author_date`、标签计数和原生度量。
- [load_data.r](https://github.com/software-rebels/JITMovingTarget/blob/184403ad3734894c8417cbec72fdef3da5edc0b9/scripts/load_data.r)：时间窗口、churn、标签二值化、缺失标签处理及字段显示语义。
- [experimental_settings.r](https://github.com/software-rebels/JITMovingTarget/blob/184403ad3734894c8417cbec72fdef3da5edc0b9/scripts/experimental_settings.r)：文件数与变更行数过滤上限，Author 与 Reviewer 字段分类。

2026-10-10 仅在内存只读核验得到：

| 项目 | 实测值／约定 |
| --- | --- |
| 原始 CSV | 4,448,994 字节；26,855 行，26,855 个唯一提交 |
| 原始 SHA-256 | `2b1d2128bee82e905b0233d6646c3fa88eed033e440482e2f89272a3dd436505` |
| 原始时间范围 | 2001-02-15T19:25:45Z 至 2014-10-22T01:58:04Z |
| `load_data.r` SHA-256 | `4be31b4663f2dfc677594ca278abfcd814d42d04f09b06be1a5b031c1aace475` |
| `experimental_settings.r` SHA-256 | `2d62ff540dc26ef05864d20862b2966e637eba34b9e66a09a06cdaa2837d3209` |
| 纳入规则 | `1322599384 <= author_date < 1393590700`，`la > 0`，`la + ld <= 10000`，`nf <= 100`；来自发布者规则，与标签和模型分数无关 |
| 纳入集合 | 12,374 行；发布标签正例 1,616；空 bugcount 9,812；这些是数据统计，不是模型结果 |

六项字段按固定顺序使用：`ns, nd, nf, ent, la, ld`，分别为发布者的子系统数、组件数、文件数、Entropy、增加行数、删除行数。`ent` 保留发布者原生值和名称，不声称已重建其计算公式或等同于完整 Kamei 熵特征。纳入集合的六字段无缺失、无非有限值，LA／LD 为非负整数；不需要填补缺失。其他历史和作者字段在原始全表各有 12,361 个空值，且 `rexp` 属 Reviewer、`arexp` 标为 Relative author experience，不能按名字猜测成 Kamei 的近期作者经验。因此本轮只选上述六项，不用额外列凑齐 14。

标签按已读发布者脚本：`bugcount > 0` 得到 1；零或空值得到 0，解释为“发布者未观测到缺陷引入”，而非证实无缺陷。非空标签必须为非负整数，否则失败。`fixcount` 不用于标签替代或模型特征。逐条 fix→introducing→issue 的证据未随本次所读 CSV 提供；保留原始行定位与论文引用，报告标注未自行复核，而不是声称完成 SZZ。源文件可公开读取和引用不等于已核验再分发许可；实现优先保留下载方式、哈希与引用，不将原始数据直接作为公开发布内容。

替代方案：ApacheJIT 有发布者论文与数据版本，但本轮尚未完成其原始 CSV 核验，不能据论文列表直接认定完整 14 维；JiTReliability 的候选文件虽列出 14 个别名，只读检查发现字段重复、计数与时间语义待复核。本次选择字段和原始转换可追踪的六字段方案，暂不承担额外语义修复成本。如默认来源不能满足此固定契约，先更新规划，不在 apply 中静默换数据或字段。

### D2. 以时间组冻结 70%／15%／15%，只在训练集拟合

先校验源文件身份和时间，再执行固定纳入规则，记录按顺序应用各过滤规则的排除数量。Unix 秒按 UTC 解读，界面仍按已有 Asia/Shanghai 展示与筛选。对纳入记录按 UTC 秒、完整标识排序，取不同时间值的升序数组，长度为 G；第 `floor(0.70*G)` 和 `floor(0.85*G)` 个值（从零计数）为两道边界。时间小于第一边界为训练，中间为验证，大于等于第二边界为测试，相同时间不拆分。

只读分区统计预计如下；apply 必须重新核验，不能直接把表中统计当成已经训练的结果：

| 分区 | 记录数 | 发布标签正例 | 边界 |
| --- | ---: | ---: | --- |
| 训练 | 8,669 | 959 | `< 2013-08-10T20:12:59Z` |
| 验证 | 1,852 | 371 | 前一边界起至 `< 2013-11-11T08:29:48Z` |
| 测试／回放 | 1,853 | 286 | 后一边界起，仍受纳入窗口上限约束 |

冻结成员清单、数据和规则后再拟合。训练和测试均需包含两类标签；空分区或不满足条件时失败，不随机重切。固定基线不调参，验证只检查流程和输出，不参与最终模型重拟合；测试只用于一次冻结方案的评价和回放。测试类别数仅用于核验指标能否定义，不用于选择特征、过滤条件或阈值。

标签来自后来的发布快照，缺少逐条修复可获得日期，因此即使时间顺序正确，也不能宣称训练标签在当时已经全部可知。摘要与报告必须写明“回顾性历史评价；未验证历史标签可获得性与在线效果”。不通过自建 SZZ 补救该限制，也不将其隐藏成已通过严格历史模拟。

替代方案：随机划分实现简单却会混入未来提交；滚动／跨项目评价更完整但会扩大模型与实验范围。本次使用一个固定时间实验作为明确起点。[scikit-learn 官方防泄漏说明](https://scikit-learn.org/stable/common_pitfalls.html) 支持先分区、仅用训练数据学习变换的处理边界。

### D3. 一个轻量 Python 管道和逻辑回归

建议用兼容当前机器的 Python、scikit-learn、NumPy 与必要的模型序列化工具；apply 创建项目内隔离环境并锁定实际依赖与解释器版本。当前有 Python 3.14，但本轮未验证机器学习依赖兼容性；在正式训练前作安装与小样例加载／拟合／推理检查，记录它属于技术试做，不将小样例结果当正式效果。

处理顺序为固定六字段选择 → 对五项计数 `ns/nd/nf/la/ld` 作固定 `log1p` 变换（ent 原值保留）→ 训练集拟合标准化 → 逻辑回归。原始度量另存，不能把标准化或 log 数值呈现为原始行数。没有缺失值填充、特征筛选、SMOTE、重采样或概率校准。

固定基线配置：L2，C=1，lbfgs，max_iter=1000，tol=1e-4，class_weight=None，seed=2026；记录求解器的实际参数、线程限制与环境。正类为标签 1，风险取其 `predict_proba`，不能按列位置猜测正类。模型不收敛视为流程失败，不能发布半成功产物或在看到测试效果后自动换参数。风险标为模型估计，不能暗示已校准或证实缺陷。

逻辑回归成本低、易复现，足以检验输入到风险链路；树模型、深度模型与完整比较留到后续。不先建设调参平台或给用户提供训练按钮。

### D4. 指标口径在测试前固定，区分模型效果与功能通过

- 不考虑工作量：ROC-AUC、Average Precision（AP），阈值 `p >= 0.5` 下 Precision／Recall／F1，TP／FP／TN／FN 和各类数量。AP 按 [官方定义](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.average_precision_score.html)，不混称梯形 PR-AUC。
- 工作量：`effort = 原始 la + ld`。`Recall@20%LOC (risk-ranked)` 使用与界面默认一致的风险降序、时间降序、标识升序；预算为测试总变更行数的 20%，依次纳入完整提交，遇到下一条会超预算即停止，不跳过大提交、不拆分提交、不根据标签排序。记录实际 LOC 和入选数量；首条超预算时入选集合为空。召回分母为测试正例提交数，不是缺陷计数之和。
- 参考值：记录正例比例作为 AP 的无信息参考，并给出全负预测参考的混淆矩阵和可定义指标；它不算额外训练模型。
- 分母为零的 Precision／Recall／F1 返回 null 和原因；F1 直接按 `2TP/(2TP+FP+FN)` 判断是否定义。单类目标的 ROC-AUC／AP、无正例召回、零总 LOC 的工作量指标也返回 null 与原因。真实固定批次需要两类；这些退化条件用独立小样例覆盖，不更改正式测试集。

这里的风险排序 LOC 指标不是风险密度排序或论文里的所有 effort-aware 指标，报告必须完整命名；Popt 与更完整比较仍是后续工作。无固定模型效果达标数字，允许如实报告差效果；本轮功能验收依靠数据真实性、计算正确、可复现和实际端到端行为。不得把“可运行”写成“优于基线”或课程模型要求已完成。

### D5. 用文件产物建立小型推理边界

建议新增 `backend/`，职责限制为数据处理、固定训练／评价、文件校验与只读服务，具体内部类名不进入规格。产物包含来源与质量记录、冻结分区、模型输入、独立评价标签、模型、逐提交参考预测、指标与运行 manifest。manifest 记录上述文件校验值、源代码与配置校验值、环境、参数、字段顺序、阈值、限制及生成命令。

运行标识由数据与纳入规则、字段／标签／分区规则、模型配置、环境和模型校验值共同确定；生成时间不决定上下文身份。重新序列化的文件不要求逐字节相同，但同数据和锁定环境重跑必须得到相同分区，风险与已定义指标绝对差不超过 `1e-8`。模型文件发生变化即独立上下文，不能冒用旧运行；复现比较保留数值证据。

服务使用 FastAPI，绑定 `127.0.0.1:8000`，只需一个产品接口 `GET /api/review-batch`。从已核验固定目录加载模型与测试输入，在风险请求中实际推理；不以参考预测 JSON 替代模型调用。评价标签独立保存，服务不读它们生成风险。返回同一次固定上下文的批次与摘要，避免两个独立请求拼接不同运行：

| 响应部分 | 最小内容 |
| --- | --- |
| 身份 | 契约版本、mode=`historical`、project、datasetVersion、runId、modelId／模型校验值 |
| 来源与摘要 | 发布者与固定地址／校验值、六字段、纳入规则、分区范围与数量、指标口径与结果、标签与解释限制 |
| records | 完整测试集合；id、UTC time、正类 risk、lines=`la+ld`、files=`nf`、六项原始 metrics；没有逐条标签、虚构标题或解释 |

启动时核验模型、输入与必要 manifest 校验值，加载后以单个运行快照供给；产物切换需重新启动服务。核验失败时服务保留明确的不可用状态，批次请求返回 503 及可区分的缺失产物、校验不匹配或模型错误；不将失败快照标为可用。推理失败返回 500，不能返回部分记录或旧批次。请求不写产物或训练，修复产物并重启服务后可重试。未知操作不触发任务。

前端使用相对 `/api` 地址，Vite dev 与 preview 同样代理本机服务，保留现有 4173 严格端口；[Vite 官方预览配置](https://vite.dev/config/preview-options) 支持 preview 代理。无需开放到局域网、增加账号或引入数据库／队列。

替代方案：静态导出预测最省后端成本，但无法验收“请求确实调用模型”；在 Node 中再实现或转换模型会增加两套数值行为。Python 管道与小型 HTTP 服务共享同一模型，额外成本限于依赖、文件校验和一个接口。

### D6. 以明确模式扩展现有界面与清单

保留当前视觉和三步审查流程。入口提供“真实历史回放／演示模式”选择，默认真实；失败时也能主动切换。演示 loader 适配旧固定 JSON，显式附上 demo 来源，保持原人工数据与同版本清单可用；真实来源不得靠标识格式或缺失元数据推断。

更新数据契约为显式模式与来源，真实响应必须校验所需记录、模式、运行、模型、六字段、摘要和数量一致性；原有风险边界反馈保留，真实批次非法风险整体不可用。旧请求通过现有过期响应机制与模式上下文忽略，切换后不保留旧详情或筛选作为另一来源的结果。

顶栏和详情持续显示来源；在现有布局增加可展开“基线记录”，展示来源、时间范围、六字段、模型、两类指标和限制，无需新训练页面。真实详情显示原始度量，解释“未提供”，缺失标题也“未提供”。指标不随搜索／筛选重算，注明是完整冻结测试批次的评价；个人清单不与标签或正式实验输入相连。

演示存储沿用现有 v1 项目＋版本键；真实使用带 historical、项目、datasetVersion、runId 的独立命名空间，界面 remount 键也包含此上下文。刷新同运行恢复；切换运行不会继承选择，返回原运行仍可恢复。保存失败与损坏处理继续按现有约定执行，不清理其他键。

## Risks / Trade-offs

- [六字段不满足完整 Kamei14，单模型不满足课程完整比较] → proposal 与摘要明确后续缺口；不得把本 change 通过写成课程最终完成。
- [发布者标签有漏报与延迟，未有逐条 SZZ 复核或特征 as-of 证明] → 保存原始标签规则与行定位，披露回顾性局限；模型风险供审查参考，不构成真实缺陷判定。完整历史有效性需要后续证据和独立规划。
- [数据过滤排除了极大或纯删除提交，结论不能外推全仓库] → 使用发布者固定条件，记录各排除数量与批次范围；不根据效果改过滤阈值。
- [六字段之外名称和单位容易误映射] → 本轮不使用经验／历史／审查字段，不称完整 Kamei 子集复刻；更换映射先更新规划。
- [1853 条真实记录比 12 条演示更长] → 验收两个桌面视口的完整批次与键盘操作，记录加载和核心操作实测；如存在阻塞，先做直接渲染优化，不自动扩张成分页平台或编造性能结果。
- [依赖兼容或数值环境差异] → 正式运行前锁定兼容解释器和依赖；小型试做与正式报告分开；复现按数值容差核验，不以仅模型文件存在作证据。
- [现有测试脚本可能覆盖旧证据目录] → apply 新增本 change 的独立证据输出方式，保留已归档的旧报告与原始哈希；新失败记录也如实保存。

## Migration Plan

1. apply 授权后先建立独立环境和固定下载／核验流程，完成数据质量与冻结分区记录，再进行正式训练与评价。源文件哈希或语义不符时停止对应步骤，先修订相关规划。
2. 保存经过校验的模型与 manifest，再接入本机服务与前端模式；全过程保留人工演示入口、旧数据和旧清单命名空间。
3. 运行数据／时间／泄漏／指标／模型一致性检查、服务真实调用检查和两种模式的桌面行为检查。端到端至少一次使用实际训练产物和 HTTP 服务，不拦截为人工风险响应。
4. 在 `docs/evidence/connect-public-data-baseline-review/` 保存命令、退出码、版本、源码与产物哈希、复现比较、截图和逐场景结果。新证据独立于旧归档；任务仅在相应实现与证据通过后勾选。
5. 回退时由用户明确选人工演示，或回退前端／服务版本；真实服务失败本身不能触发自动演示。其他运行与原演示清单保留。
6. 实现与功能验收通过后再按对应技能处理规格同步与 archive。若出现材料冲突或需求变化，先更新 proposal／specs／design／tasks，再继续实现。

无需要在实现前另请用户确认的材料范围问题。依赖具体补丁版本、报告排版和内部模块名可在 apply 中按本设计确定并记录；数据、字段、标签、分区或产品范围的变化需要先更新规划。
