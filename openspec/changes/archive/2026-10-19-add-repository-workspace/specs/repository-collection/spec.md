# Delta: repository-collection

## ADDED Requirements

### Requirement: RCL-10 仓库实体与同步归属

系统 SHALL 把仓库作为一等实体维护：以规范化后的仓库地址作为唯一键，记录显示名、默认分支、最近一次成功同步的时间与 HEAD、当前提交数、风险分布与最近一次同步作业标识。每个同步作业 MUST 归属到一个仓库；同一地址再次同步 SHALL 归入已有仓库，MUST NOT 因重复接入产生第二个仓库。

仓库的提交视图 SHALL 以该仓库最近一次成功完成的同步为准；更早的作业与它们的提交 MUST 仍可按作业标识查询，但 MUST NOT 与「最近一次」的提交混在同一仓库视图里。仓库视图 MUST 同时给出所用模型来源（本仓库训练或兼容的既有模型）与降级原因，缺失时 MUST 显示为未记录而不是留空。

#### Scenario: 同一仓库再次同步归入同一仓库

- **WHEN** 对已经同步过的地址再次发起同步并完成
- **THEN** 仓库列表里仍只有一条该仓库，其提交数、风险分布与最近同步时间更新为最新一次的结果
- **AND** 前一次作业仍可按作业标识查到，但不计入仓库视图

#### Scenario: 仓库地址写法不同仍归入同一仓库

- **WHEN** 同一地址分别以带 `.git` 后缀、尾随斜杠与不同大小写的协议/主机写法创建同步
- **THEN** 系统把它们规范化后归入同一个仓库

#### Scenario: 分支不同视为同一仓库的不同分支视图

- **WHEN** 同一地址先后以 `main` 与 `release/1.0` 两个分支同步
- **THEN** 仓库列表仍只有一条该仓库，详情中记录当前视图来自哪个分支与哪次同步

#### Scenario: 仓库没有任何提交

- **WHEN** 一个仓库的最近一次同步因为窗口内没有提交而失败或为空
- **THEN** 仓库列表返回该仓库并标注失败或空结果，提交数与分布为 0
- **AND** 查询其提交返回空页而不是错误
