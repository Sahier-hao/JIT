## Why

系统已经具备九种方法、14 维数据采集和训练任务，但交付阶段仍停留在“实验完成”：随仓库分发的九个模型全部是六字段模型，当前新项目默认使用的十四维 v2 数据没有开箱可用的正式模型；同时未成熟标签被当作负例，普通 accuracy 又会被 95% 以上的类别不平衡掩盖，无法证明模型达到了可交付质量。

## What Changes

- 以真实公开仓库构建的 `kamei14-git-v2` 数据集为当前 schema 基线，九种方法全部训练和记录；正式包至少覆盖四种经典方法和三种深度方法，共不少于八种合格模型。
- 将标签成熟状态写入数据集产物；训练和正式评价默认排除 `immature` 标签，并保留包含未成熟标签的敏感性报告。
- 为模型运行增加“训练完成、可登记、发布合格、用户可服务、默认候选”等相互独立的发布状态，训练成功不再直接等同于模型可交付。
- 定义 JIT 专用模型门槛：同时检查 AP、ROC-AUC、Recall@20%LOC、Popt、IFA、正例覆盖和相对无信息、时间、随机及成本感知基线的结果；普通 accuracy 只作诊断，不得单独判定通过。
- 生成当前 schema 的正式模型包和逐模型发布报告，包含数据版本、切分摘要、标签成熟规则、方法、依赖、指标、基线差值和不可发布原因。
- 新环境初始化 SHALL 能登记当前 schema 的正式模型，并提供人工批准的默认候选；不得按测试指标自动选择“最佳模型”。
- JIT-Fine、多项目和语义实验继续作为研究证据保留，不能因为离线运行成功就冒充可服务模型。
- 测试材料与 AI 提示词归档属于独立交付工作，不在本变更中混入。

## Capabilities

### New Capabilities

- `model-release-qualification`: 定义当前 schema 模型从训练运行到发布合格、可服务形式和默认候选的验收状态、指标门槛、基线比较与发布报告。
- `label-maturity-policy`: 定义未成熟标签在数据集产物、清洗、切分、训练与评价中的保留、排除和敏感性分析规则。

### Modified Capabilities

- `repository-collection`: 采集产物需要持久保存标签成熟状态和成熟观察边界，供后续训练和评价按同一规则消费。
- `model-catalog`: 模型目录需要区分发布合格与服务可用状态，并能初始化当前十四维 schema 的正式模型包。
- `training-task-management`: 训练任务需要记录标签成熟策略、发布的资格结果和不合格原因。
- `multi-dataset-evaluation`: 多数据集正式比较需要按项目执行发布门槛，报告最差项目和未通过原因，并将不合格结果排除出正式基线。

## Impact

- 数据：新采集 CSV 与描述文件增加标签成熟字段和排除统计；既有数据集继续按原声明读取，不回填未知状态。
- 训练：共享训练执行器增加成熟标签策略、发布资格计算和当前 schema 基线运行。
- 模型目录：新增发布资格、服务兼容性和正式基线模型包的查询与初始化状态；既有六字段模型和项目内模型保持可用。
- 前端：管理员训练、数据集、实验运行和模型卡展示成熟策略、发布门槛、逐项通过情况及不可发布原因。
- API 与 OpenAPI：增加发布资格摘要和模型包状态字段；不改变普通项目分析的模型选择边界。
- 数据与产物：需要真实公开仓库训练证据和当前 schema 模型包，不提交原始仓库、SQLite、未打包运行目录或模型二进制散文件。
- 兼容性：历史运行、指标集、旧模型身份和既有默认模型不被重写；新规则只作用于新训练和新发布候选。
