# Spec Delta

## MODIFIED Requirements

### Requirement: PPT-02 快照、意图与任务复用

后台发现 SHALL 读取真实开放 PR 并固定 base/head 快照。分析意图 SHALL 由基项目、PR、快照、真实模型与评分契约共同确定；同快照同模型 MUST 复用在途或成功任务，显式更换模型或新快照才产生新意图。PR 任务 MUST NOT 改变项目当前分支结果。PR 清单 SHALL 提供批量分析全部开放 PR 的入口，并允许先选择真实兼容模型；已有完成分析且快照未变化的 PR MUST 跳过。PR 分析任务 SHALL 显示在 PR 审查页的独立记录中，MUST NOT 混入项目分支分析记录。任务状态 SHALL 如实呈现排队、分析中、完成、失败、取消与中断，MUST NOT 把中断或取消显示为分析中。

#### Scenario: 重复检查同一快照
- **WHEN** 同一 PR 快照与模型已有在途或成功任务
- **THEN** 不重复入队，复用原任务或结果

#### Scenario: 作者推送新版本
- **WHEN** 远端 head 变化形成新快照
- **THEN** 产生新意图并排队，旧结果保留为历史

#### Scenario: 显式更换自动模型
- **WHEN** 用户明确更换项目自动模型
- **THEN** 同快照下产生新意图，旧模型结果仍可读且不覆盖当前分支结果

#### Scenario: 批量分析全部 PR
- **WHEN** 用户选择模型并确认「分析全部 PR」
- **THEN** 所有尚无完成分析的开放 PR 进入后台队列，已完成的 PR 跳过；PR 记录显示排队与进度

#### Scenario: 中断任务
- **WHEN** 服务停止导致 PR 分析中断
- **THEN** 记录显示「已中断」，不显示「分析中」，可重新发起批量分析补齐
