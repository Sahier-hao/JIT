# Spec Delta

## MODIFIED Requirements

### Requirement: PPR-04 独立模型线索

模型线索 SHALL 以「审查优先级」先于代码展示：提交按保存分数从高到低排列，文件按触及该文件的提交最高分排序，并标注仅用于排序，不是 PR 整体缺陷概率、文件级缺陷概率或行级定位。工作单 SHALL 提供提交队列；点击提交 SHALL 把文件列表限定为该提交触及的文件，并允许切回全部文件。文件风险与提交文件 MUST 只来自该快照提交的已保存分数与提交文件映射；旧分析缺少映射时 MUST 保持全部文件并说明不能按提交或风险筛选，不得猜测。模型分析 SHALL 由 PR 清单的批量入口发起，并允许先选择真实登记、兼容且已启用的模型；只读详情 MUST NOT 提供生成、重试或取消入口，只展示已保存结果。每份结果 MUST 显示实际使用的模型与固定目标 HEAD；返回的分析 HEAD、快照或模型不匹配时 MUST 不采用分数。模型失败 MUST 不阻断代码阅读和个人记录。旧关联只证明固定 HEAD 与已有快照关联，MUST 标注其不能证明独占基项目绑定或提交前模型绑定。

#### Scenario: 模型不可用
- **WHEN** 所选模型停用、缺失或推理失败
- **THEN** 列表或记录显示原因；已有人工文本与代码操作继续可用，不静默换模型

#### Scenario: 只覆盖部分提交
- **WHEN** 部分 PR 提交未取得模型分数
- **THEN** 显示覆盖计数及缺失，不把未覆盖条目当作低风险，原分析仍可单独打开核对

#### Scenario: 自动与手动结果并列
- **WHEN** 同一 PR 同时存在项目自动模型与用户手动模型的结果
- **THEN** 两者并列显示、互不覆盖，自动模型不写入个人轮次已选模型身份

#### Scenario: 旧关联限制
- **WHEN** 读取迁移前的 PR 评分关联
- **THEN** 标注其只证明固定 HEAD 与已有快照关联，不声称新契约的独占绑定或提交前模型绑定

#### Scenario: 覆盖不完整提醒
- **WHEN** 自动分析只覆盖部分 PR 提交
- **THEN** 提醒与线索区域明确不能视为低风险结论，保留覆盖计数与缺失范围

#### Scenario: 文件级风险映射缺失
- **WHEN** 分析来自旧任务或未记录提交文件路径
- **THEN** 文件列表保持原顺序并说明没有文件级排序依据，不按缺失分数推断低风险

#### Scenario: 风险排序先于代码
- **WHEN** 用户打开只读详情或工作单
- **THEN** 审查优先级与高风险提交先于文件 Diff 展示，文件列表默认按风险排序并可切回路径顺序

### Requirement: PPR-05 只读详情与显式开始审查

项目 PR 清单 SHALL 先打开只读详情，展示来源、模型风险概览、高风险提交、按风险排序的文件、作者说明和文件 Diff。只读详情 MUST NOT 提供模型选择、生成、重试或取消分析的入口；分析结果只读展示已保存的任务与分数。只有用户明确开始审查才创建工作单并写入「我的审查」；已有工作单 SHALL 显示继续审查。读取详情 MUST NOT 创建或改写个人草稿。

#### Scenario: 首次查看 PR
- **WHEN** 用户在项目 PR 清单选择一个尚未开始审查的 PR
- **THEN** 打开只读详情，展示来源和已保存的风险结果，不创建个人草稿，也不出现在「我的审查」

#### Scenario: 明确开始审查
- **WHEN** 用户在只读详情点「开始审查」
- **THEN** 创建固定快照的个人工作单并进入编辑视图，此前的只读浏览不产生草稿

#### Scenario: 已有工作单
- **WHEN** 该 PR 已有本浏览器工作单
- **THEN** PR 清单显示「继续审查」，打开后直接进入原工作单，不覆盖原轮次

#### Scenario: 读取只读详情失败
- **WHEN** PR 来源读取失败
- **THEN** 显示原因与重试/返回项目 PR 的入口，不创建个人草稿
