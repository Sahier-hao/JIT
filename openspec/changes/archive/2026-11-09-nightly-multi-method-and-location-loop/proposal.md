# 多方法实验、代码定位建议与提交触发分析的完整闭环

## Why

管理端目前一次训练只接受一个方法，超参数完全冻结，迭代方法不保存训练过程；比较依赖人工打开多个已登记模型，无法回答“同一份数据、同一组切分上，几个方法各自跑成什么样”。PR 侧只有静态候选位置，没有与规则对应的修复建议和用户闭环。研究侧的行级基线缺少可移植的复现清单和定位指标，也没有诚实的继续/暂缓结论。提交触发分析只有消费既有分析包的 CI 示例，缺少从明确 base/head 执行真实采集、推理和报告的入口。VS Code 侧没有任何消费方。本轮把这些缺口连成一条用户可走通、可复核的链路。

## What Changes

- 管理数据集详情支持一次选择多个方法并设置受控参数，创建持久实验组；每个子任务沿用现有训练执行链，冻结同一数据版本、切分、类别策略与种子。
- 方法参数采用按方法声明的白名单、类型与范围校验；默认参数不改变既有运行身份，显式参数写入运行配置、加载校验和模型卡。
- 迭代训练保存逐 epoch 训练损失与耗时，跨刷新可读；非迭代方法明确显示无逐 epoch 曲线。
- 实验详情展示各子任务状态、参数、切分身份、三档指标、耗时与失败原因，并支持导出比较记录；训练成功仍需显式登记，项目侧显式选用。
- PR 候选支持规则对应的修复建议、加入问题草稿、刷新恢复与快照更新后的保留语义。
- 行级实验提供可移植 manifest、分语言/仓库结果与定位指标，给出继续或暂缓产品化的证据化结论。
- 新增从本地 Git 仓库明确 base/head 触发真实特征采集、推理和报告的命令与 CI 示例。
- 新增 VS Code 只读扩展，显式导入检查包、核对仓库与提交身份、展示提交风险、候选与建议并跳转行号。

## Capabilities

### New Capabilities

- `multi-method-experiments`：固定数据版本与切分上的多方法实验组、子任务状态、比较与导出。
- `configurable-training-parameters`：受控参数声明、校验、运行身份与加载契约。
- `commit-triggered-analysis`：从明确提交范围执行真实采集、推理与报告的非阻断入口。
- `ide-report-consumption`：IDE 侧只读消费检查包、身份核对与代码定位。

### Modified Capabilities

- `code-candidate-location`：候选补充修复建议与问题草稿闭环，明确快照更新后的保留语义。
- `line-level-prediction`：补充可移植 manifest、分语言/仓库评估与定位指标、产品化结论边界。

## Impact

- 后端：训练任务、训练执行、产物校验、深度训练历史、候选规则、行级实验报告、PR 检查入口与 API。
- 数据库：新增实验组表与训练任务的参数/历史字段，前向迁移，保留既有记录与产物身份。
- 前端：管理数据集详情、实验详情、训练任务详情；PR 工作单候选面板。
- 新增 `vscode-extension/` 扩展源码与构建说明；新增 CI 示例工作流。
- 不改变默认模型、不自动登记训练产物、不自动阻断合并或修改远端代码。
