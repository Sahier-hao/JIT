## Why

批量分析同一个仓库时，每个 PR 都独立克隆仓库并遍历祖先历史；sub2api 的 31 个已完成 PR 已生成 32 个数据集版本和对应模型产物，冷启动的克隆与历史计算构成主要延迟。PR 分析产生的数据集没有来源标记，也没有保留策略，随着单 PR 分析继续增长，磁盘与目录会持续膨胀。

## What Changes

- 增加公开仓库的本地裸克隆缓存：同一仓库地址在有效期内复用本地副本，按需更新远端引用；缓存损坏自动重建，超过磁盘上限按最久未使用淘汰，采集结果与来源校验规则不变。
- 批量 PR 分析在同一批次内共享一个仓库副本，不再为每个 PR 重复克隆。
- 增加已保存特征复用：目标提交在同一仓库、同一特征 schema 下已有保存的特征时，直接用于 PR 打分，只补算缺失提交；复用结果注明来源，不重复登记内容相同的数据集版本。
- PR 来源的数据集描述与登记记录增加来源标记，区分分支分析与 PR 分析；旧记录按分支来源兼容读取。
- 增加 PR 数据集的保留与清理：默认保留最近 N 个版本，被模型、趋势视图或分析记录引用的版本不自动删除；管理员可显式清理并确认，清理结果可核对，分支分析数据集不参与自动清理。
- 管理区数据集查询按来源筛选并显示引用状态，普通项目工作区不暴露清理入口。

## Capabilities

### New Capabilities

无新增能力；本次修改采集、数据集登记与管理员维护的既有行为。

### Modified Capabilities

- `repository-collection`: 仓库采集增加本地缓存复用与已保存特征复用，明确复用不改变特征值、来源校验与失败语义；PR 分析在特征已保存时可跳过重复数据集登记。
- `dataset-registry`: 数据集描述与登记增加来源标记；新增保留与清理要求，规定引用保护、默认保留数量和不可恢复删除的确认边界。
- `admin-workspace`: 数据集清理与来源查询纳入管理员会话保护，普通项目分析不能触发删除。

## Impact

- 后端：采集器的仓库准备与特征来源选择；PR 批次执行共享仓库副本；数据集登记与清理服务；管理数据集查询接口。
- 存储：本地仓库缓存目录与磁盘上限配置；数据集描述文件与数据库新增来源字段；清理操作的事务与文件删除顺序。
- 数据库：数据集记录增加来源字段的前向迁移；旧记录写回分支来源。
- 前端：管理区数据集列表与详情显示来源、引用状态和清理入口；项目 PR 分析显示特征复用与缓存命中说明。
- 兼容性：采集出的 CSV、特征与标签口径不变；分支分析仍登记独立数据集；旧批次、旧模型与旧趋势视图保持可读。
