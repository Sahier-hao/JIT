## Context

PR 分析当前把每个 PR 当作一次独立的分支分析：克隆仓库、遍历祖先历史、登记数据集、打分。同一项目的多个 PR 共享同一份仓库历史，却重复承担克隆与历史计算；已完成分析保存的提交特征也没有被后续分析使用。数据集登记没有来源字段，PR 分析产生的版本与分支分析版本混在一起，无法按来源保留或清理。sub2api 的实测样本是 1,058 个开放 PR、31 个已完成分析产生 32 个数据集版本约 3.8 MB，延迟与目录增长都随 PR 数线性上升。

## Goals / Non-Goals

**Goals:**

- 同一公开仓库的重复分析复用本地仓库副本，避免每次全量克隆。
- 同一批次共享一次仓库准备，减少批量分析的重复 I/O。
- 目标提交已有同口径特征时直接复用，全命中时跳过重复数据集登记。
- 数据集标明分支或 PR 来源，并能按来源保留、查询与清理。
- 清理有引用保护、二次确认和可核对结果，默认不自动删除。

**Non-Goals:**

- 不改变 14 维特征、简化 SZZ 标签或风险分数的口径。
- 不实现跨仓库特征共享或跨 schema 特征迁移。
- 不改变模型训练、准入、默认模型或 PR 自动分析规则。
- 不对部分命中的提交做特征拼接；部分命中仍按整段重算处理。
- 不把本地缓存或数据集目录当作跨机器交付格式。

## Decisions

### D1. 本地裸克隆缓存按仓库地址隔离

缓存使用裸仓库，目录名由规范化公开仓库地址的哈希决定，配置项控制根目录、磁盘上限与最长有效期。命中时先更新远端引用并确认请求的分支和提交仍可读取；只允许公开 HTTP(S) 来源，本地路径与内网地址不进入缓存。缓存损坏、更新失败或与请求范围不一致时回退直连采集或明确失败，不使用其他仓库副本。超过磁盘上限按最久未使用淘汰，正在被批次或单任务使用的副本由租约保护。采集结果仍以 CSV、描述文件和来源校验为准，缓存只影响准备仓库的成本。

否决方案：直接缓存采集结果或数据集版本——范围、分支与元信息组合过多，命中率低且容易把旧结果当作新采集。

### D2. 批次内共享仓库租约

批次执行开始时为仓库获取一次租约，批次内所有 PR 条目复用同一副本；批次结束、取消或失败时释放。现有执行是单 worker 串行，租约只需引用计数和超时回收，不需要分布式锁。租约不改变单 PR 分析：单 PR 任务没有活动批次时自行获取租约，结束后释放。

### D3. 特征复用以全命中为前提

PR 分析先收集目标提交集合，在同一仓库、同一 schema 的已完成分析中查找这些提交的保存特征。全部命中时直接使用，不重新采集，也不登记内容相同的数据集版本；分析记录保存特征来源（原分析、数据集版本与 schema），界面显示复用说明。任一提交缺失或 schema 不一致时，整个 PR 按现有流程重新采集与计算，不做部分拼接，避免同一行特征混用不同历史口径。分支分析不启用跳过登记，仍生成独立数据集版本。

复用只复用特征，不复用风险分数：模型可能不同，分数必须由本次固定模型重新计算。复用记录不参与训练分区选择，也不改变模型身份。

### D4. 数据集来源标记写入描述文件与登记记录

描述文件增加来源类型与来源分析标识，数据库数据集记录增加对应列。旧记录在迁移中写回分支来源，读取时缺少来源字段按分支处理。来源标记只用于查询、保留与展示，不改变版本命名、唯一性或不可覆盖规则。PR 分析产生的数据集使用统一来源值，便于按项目统计。

### D5. 清理采用引用保护与两阶段删除

可清理版本必须同时满足：来源为 PR、未被模型、趋势视图、分析记录或导入过程引用、且超出保留数量。删除先在事务中移除数据集登记、提交、特征与标签证据记录，提交后再删除描述文件与 CSV；文件删除失败留下孤儿文件并记录为可重试清理，不把版本报告为成功删除。自动清理默认关闭，管理员启用后也只在服务启动或显式触发时执行，不在分析请求中隐式删除。

否决方案：直接按目录时间删除旧版本——无法识别模型或趋势视图引用，会破坏可追溯结果。

### D6. 缓存与保留参数可配置且有保守默认

仓库缓存目录、磁盘上限、缓存有效期、PR 数据集保留数量与自动清理开关通过配置提供。默认保留最近 10 个 PR 数据集版本，自动清理关闭；磁盘上限按 GiB 设置，超出时淘汰最久未使用且无租约的副本。配置变化不追溯删除既有数据，除非管理员显式执行清理。

## Risks / Trade-offs

- [缓存内容与远端不一致] → 命中后更新并校验目标提交；无法校验时回退直连或明确失败，不使用未经验证的副本。
- [特征复用引入口径漂移] → 只按仓库、提交与 schema 精确匹配，保存来源并继续披露原有特征限制；部分命中不做拼接。
- [清理误删仍在使用的版本] → 引用检查覆盖模型、趋势和分析记录，默认不自动删除，删除前二次确认并返回跳过原因。
- [磁盘上限淘汰正在使用的副本] → 租约保护活动副本，淘汰只作用于无租约且超过有效期的目录。
- [跳过数据集登记让分析记录缺少数据集引用] → 分析记录必须保存特征来源与 schema；界面显示复用来替代数据集链接，不伪造新版本。
- [旧记录缺少来源字段] → 迁移写回分支来源，查询与清理均按兼容规则处理。

## Migration Plan

新增前向迁移，为数据集登记记录增加来源类型与来源分析标识；旧记录写回分支来源。描述文件新增字段由新登记写入，旧文件缺少字段时读取为分支来源。仓库缓存目录为运行时数据，不进入迁移，首次使用按需建立。迁移前按既有流程备份数据库；回滚应用版本时保留新增列，旧版本读取既有列不受影响。清理操作默认关闭，升级后不会自动删除任何既有数据集。
