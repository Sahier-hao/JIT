# Design

## Context

分支分析页已经积累了两类问题：一是「当前结果」由多张卡片和多个下拉折叠组成，展开时页面突然变高；二是切到「风险趋势」后子导航被趋势视图接管，模型身份与查询窗口消失，没有可拼接来源时缺少回程。算法库是独立页面，与训练入口、训练记录和我的模型之间没有路径。

本次只改前端表现与路由，后端接口、数据库、模型和数据集都不变。现有测试覆盖项目页、分析结果卡、趋势视图、算法库与训练弹窗，可直接扩展。

## Goals / Non-Goals

**Goals**

- 当前分析结果合并为一张卡，分布图在上，优先回查与来源摘要在下，补充信息用对话框打开。
- 分析记录卡与结果卡同高、记录卡内滚动、每条记录可悬停，新结果自动回到最新一条。
- 风险趋势标题带上模型与查询窗口身份，没有可拼接来源时说明原因并保留回程。
- 图表跟随容器宽度，窗口缩放不再保持旧宽度或撑出横向滚动。
- 算法库方法可深链、可带着方法进入训练，训练与模型入口能回到算法说明。

**Non-Goals**

- 不新增后端接口、不改分数口径、分档阈值、模型选择或数据集切分。
- 不为趋势视图新增后端聚合；无来源状态只解释现有规则。
- 不把算法图库改成训练表单的一部分；它仍是独立页面。

## Decisions

1. **结果卡先图后表**：分布图放卡片顶部，优先回查与来源摘要依次下移，避免读者先看到列表再找分布。分布图用 0.05 一档的直方图，阈值 0.25 / 0.10 正好落在档位上，用颜色分段并配数量图例，使阈值语义由文字与计数共同承担。
2. **分布数据来自当前视图的完整提交集**：按 200 条一页读取该次分析提交，上限 800；提交数超过上限时退回服务端分档汇总并注明，不用样本冒充全集。这样既得到真实分布形状，又不新增后端接口。
3. **补充信息改对话框**：模型完整口径、原始变更度量、来源与局限、解释方法与来源都从按钮打开对话框，页面高度稳定；对话框内复用既有内容组件，不复制数据请求。
4. **记录卡与结果卡同高用 CSS 定位实现**：左栏单元格保持相对定位，记录卡绝对定位填满同一行高，行高由右栏结果卡决定；记录列表是卡内唯一的滚动区，底部固定总数。窄屏取消绝对定位，避免压扁内容。
5. **记录一次读取最近 100 次并去掉分页**：卡片内滚动取代翻页，避免在卡内切换页面丢失上下文；新记录出现时把滚动位置复位到最新一条。
6. **子导航抽到页面工具栏**：分析结果 / 风险趋势切换固定在工具栏左侧，主操作在右侧，状态词移入项目头部，三种视图共用同一位置，切换不再移动导航。
7. **趋势标题带口径身份**：标题显示分支、模型、聚合粒度、查询窗口与来源分析次数；无来源状态解释参与条件与限制，并保留返回分析结果的入口。未覆盖时间段只保留图内底纹、文字与一句覆盖说明，去掉无刻度的覆盖条带。
8. **图表按父容器测量宽度**：共享图表组件改为测量父元素宽度，容器加 `min-w-0` / `overflow-hidden`，ECharts 不再把首次宽度固化为最小内容宽度，窗口缩放后图表跟随重绘。
9. **算法库深链用路径，训练预选用查询参数**：方法地址为 `#/algorithms/{method}`，路由表与 `parseHash` 同步支持；「以此方法训练」跳到 `#/my-training?method=...`，训练弹窗按该方法预选，不可用或不兼容时给出真实原因。训练记录与我的模型的方法名直接跳到对应方法。

## Risks / Trade-offs

- **直方图需要读全提交**：分析提交数大时会多几次分页请求。用 800 条上限与分档回退控制成本，超过上限时明确标注统计口径。
- **绝对定位的对齐方式依赖双栏布局**：只在 `lg` 断点启用，窄屏回落自然高度；DOM 顺序仍是记录在前、结果在后，键盘与读屏顺序不变。
- **记录卡高度跟随结果卡**：结果卡很短时记录卡也短，但记录在卡内滚动，不会裁掉内容。
- **方法深链会改写地址**：在算法库内切换方法会更新地址，浏览器后退会回到上一个方法；这是可分享地址的代价，已在测试中覆盖。
- **去掉覆盖条带**：覆盖信息改由底纹与一句文字承担，若后续需要逐段精确覆盖，仍可从逐周数据表核对。

## Migration Plan

无部署或数据迁移。旧地址 `#/projects/{id}/trends` 继续可用；`#/algorithms` 仍打开算法库首页，新地址为增量。
