# 预测解释与服务可验证性

## Why

课程要求把「预测与解释」列为一个功能模块（缺陷概率与缺陷归因/解释），而当前服务对所有模型固定返回 `explanationStatus=not-supported`，前端只能显示「该模型的真实预测解释尚未接入」。同时，采集→登记→训练→预测这条核心链路只有手工冒烟记录，没有一条自动化端到端测试，也没有性能与安全证据；课程明确要求「至少覆盖 1 条核心端到端业务链路」与「至少两项非功能需求的验证证据」。功能缺口与证据缺口必须一起补，否则系统既讲不清一条预测为什么高风险，也证明不了自己对。

## What Changes

- 新增模型无关的特征归因：对已入模特征逐个用训练基线替换，按风险概率变化排序，输出影响最大的若干条（含特征名、当前值、基线值、变化量、方向），并给出可读摘要。
- 预测响应新增解释字段族：`explanationStatus` 由固定 `not-supported` 变为 `supported` / `not-supported` 两态，新增 `explanationMethod`、`explanation` 数组与摘要；未支持时仍保留明确原因。
- 已保存预测可重开解释：为预测记录持久化解释内容，历史批次（无解释）重开时仍按未支持展示，不改写既有结果。
- 前端预测结果与提交详情用真实归因替换「未支持」占位，保留无解释模型的回退文案。
- 新增一条自动化端到端测试：临时 git 仓库 → 采集 → 登记 → 入库 → 训练 → 预测，全程离线。
- 新增非功能证据：预测接口的 P95 延迟测量，以及无凭据 401、越权 403、不存在 404 的鉴权测试。
- 深度方法演示证据：在具备 torch 的环境中跑通四种深度方法并记录指标；环境不具备时不阻塞前几项。

**BREAKING**：无。新增字段与可空列；旧批次与未支持模型的行为保持不变。

## Capabilities

### New Capabilities

- `prediction-explanation`：一条预测如何得到可复现的特征归因、解释如何随结果保存与重开，以及无解释时如何如实标注。

### Modified Capabilities

- `feature-input-prediction`：FIP-06 从「一律返回解释未支持」改为「支持时返回真实归因，未支持时返回原因」，并约束解释不得冒充缺陷结论。
- `model-prediction-workbench`：MPW-08 的成功结果要求从「解释未支持必须展示原因」扩展为「展示解释或未支持原因」，覆盖前端对归因的呈现。

## Impact

- 后端：`prediction.py`、`algorithms.py`（登记各方法的解释口径）、`api.py`、`catalog_storage.py`、`artifacts.py`、新迁移 `003`（预测记录增加解释列）、训练产物增加特征基线。
- 前端：`predictionContract.ts`、`PredictionsPage.tsx`、`CommitDetail.tsx` 及其契约测试。
- 测试：新增端到端与归因测试，补充性能与鉴权测量；既有 260 项测试须保持通过。
- 文档：`docs/api/openapi.yaml`、`backend/README.md`、`backend/PROTOCOL.md` 同步解释契约与验证证据。
- 依赖：不引入新运行时依赖；遮挡法只用既有模型推理。torch 属可选环境依赖，仅影响深度方法演示。
