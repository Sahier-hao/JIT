# Proposal

## Why

模型目录把“没有所有者”当成默认共享：本机 34 个已登记模型中有 29 个没有所有者，登录用户因此会在分支分析、PR 分析和模型试算中看到大量并非自己登记的模型，其中多数还因 schema 或校验状态显示不可用。与此同时，「我的模型」只列本人模型，与选择器实际范围不一致；管理员没有“开放给用户”的显式操作，共享只能依赖隐式规则。

工作区其余部分也存在同类问题：模型选择器使用浏览器原生下拉或各自维护的下拉，日期仍使用原生日期输入，危险操作缺少统一确认；训练实验结果、PR 审查列表和风险趋势在信息层级与稀疏样本表达上不一致，用户需要来回猜测“哪些模型可用、先看什么、这些数字代表什么”。

## What Changes

- 模型共享改为显式白名单：新增 `model_share`，未开放的无归属模型不再自动进入用户列表；用户可见范围固定为“本人模型 + 管理员已开放模型”。
- 新增管理员开放/撤销接口与界面开关；开放要求模型可用，撤销后新选择不再出现，历史分析与评分保留。
- 服务端在所有显式选择模型的入口统一校验可见范围：分支分析、单个/批量 PR 分析、PR 自动分析设置与模型试算；不存在的模型继续由实际任务报告原因。
- 「我的模型」拆分为「我的模型」与「管理员开放」两组；共享模型只读，不提供训练数据入口；本人模型若已开放显示状态。
- 统一模型选择器：按来源分组，只列已校验、启用且 schema 兼容的模型；原选模型不可用时保留为禁用项，由用户明确重选。
- 统一工作区控件：日期改用日历弹层，范围滑块改用 Radix Slider，危险/不可逆操作改用产品内确认对话框；替换原生日期、原生 range、`window.confirm` 与散落的手写按钮/标签页。
- 训练实验结果改为“模型对比表 + 可折叠训练/验证指标 + 阈值调整”，不再要求逐项切换分区与指标才能看到完整对比。
- PR 审查页改为单张列表卡：状态筛选、排序和批量分析在卡内工具条，移除重复的右侧待处理栏；行操作统一层级。
- 风险趋势在已评分样本不足时给出明确提示；所有时间段的“高分占比”都不可用时不再渲染整块空图，改为紧凑说明；不可用缺口标注“比例不可用”，不再误写成“无已评分提交”。
- 「检查分支更新」固定显示在项目页签栏右侧，所有项目页签可见；PR 列表按钮改为“刷新 PR 列表”，只刷新远端 PR 列表。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `model-catalog`: 模型所有者与显式共享范围、用户可见模型、管理员开放/撤销、模型就绪诊断中的用户可选计数。
- `user-model-evaluation`: 我的模型来源分组、共享模型只读边界与模型试算可见范围。
- `interface-presentation`: 统一模型/日期/确认控件，仓库更新入口，趋势稀疏状态，PR 列表层级，训练实验结果比较呈现。
- `multi-method-experiments`: 实验比较以测试集对比表为主，训练/验证指标可折叠查看。
- `public-pull-request-review`: PR 审查页单列表与卡内状态筛选，移除重复待处理栏。

## Impact

- 后端：`backend/jit_baseline/ml/catalog.py`、`storage/catalog_storage.py`、`api/app.py`、`services/user_api.py`、`services/user_predictions.py`、迁移 `044_model_sharing.sql`、OpenAPI。
- 前端：模型选择器、我的模型、管理端模型设置、分支分析、PR 审查、风险趋势、训练结果、日期/滑块/确认框与数据集清洗日期字段。
- 数据：新增 `model_share` 表；迁移不自动开放任何模型，升级前留存目录库备份；不重写模型产物、既有分析或评分。
- 测试与文档：后端模型/预测/契约测试，前端全量与相关浏览器用例，`docs/当前产品.md` 与 `docs/审计/` 记录。
- 不改变特征口径、训练算法、风险分数含义或分档阈值。
