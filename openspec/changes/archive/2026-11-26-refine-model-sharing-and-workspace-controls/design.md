# Design

## Context

模型目录已有 `owner_user_id`，但可见性规则把“没有所有者”直接当成全局共享。本机 34 个已登记模型中 29 个没有所有者，它们全部进入普通用户的分析与试算选择列表。管理员端只有启停和默认模型，没有显式开放动作；用户端与管理端对“可见”的理解不一致。

工作区界面分散使用了原生下拉、原生日期输入、原生 range 和 `window.confirm`，同类动作在不同页面有不同层级。训练实验结果、PR 审查列表和风险趋势在信息密度与稀疏样本表达上各自演化，缺少一致的状态说明。

本次变更同时包含数据可见性规则、服务端授权和界面表现；不改变模型算法、特征口径、训练过程或风险分数含义。

## Goals / Non-Goals

**Goals**

- 让“哪些模型对哪个用户可见”成为可审计的显式事实，而不是所有者为空的副作用。
- 管理员可开放/撤销模型；用户只看到本人模型和已开放模型；所有服务端显式选择入口使用同一规则。
- 「我的模型」与选择器使用同一可见范围，并区分本人模型和管理员开放。
- 统一模型选择、日期、滑块和确认交互；同类动作在用户端与管理端保持同一组件语言。
- 训练结果、PR 列表和风险趋势在稀疏样本、空状态和操作层级上给出可核对的信息。

**Non-Goals**

- 不新增模型训练、自动调参、自动选择最优模型或修改风险分档阈值。
- 不把未开放模型自动迁移为开放；不重写既有模型产物、既有分析、PR 批次或试算结果。
- 不做多租户隔离；管理员仍可查看全部模型。
- 不把共享模型复制成新产物；不改变模型身份、runId 或数据集版本。
- 不引入新的前端状态管理框架或图表库。

## Decisions

1. **显式共享表，而不是继续依赖空所有者**
   - 新增 `model_share(model_id, shared_by, shared_at)`，与 `dataset_share` 同构。
   - 普通用户可见集合 = `owner_user_id = 用户` ∪ `model_share`。
   - 迁移只建表，不自动开放任何模型。这样管理员必须逐个确认哪些模型对用户可用，避免把历史测试模型再次暴露。
   - 被替代的旧规则是“所有者为空即共享”；该规则无法区分“系统内置模型”“历史测试模型”和“管理员有意开放”。

2. **用户会话优先于管理员会话**
   - 同一浏览器可能同时持有管理员会话和用户会话。已登录用户的模型选择列表按用户范围返回，不因为管理员 cookie 而看到全部模型；管理员目录使用 `/api/v1/models`。
   - 无用户会话的本机维护请求继续允许无归属模型，保留 CLI 和既有本地流程；这是本地维护例外，不进入用户界面。

3. **服务端统一授权，历史结果不重算**
   - 显式传入模型 ID 的分支分析、单个/批量 PR 分析、PR 自动分析设置和模型试算都调用同一可见性检查。
   - 未开放或属于他人的模型返回 `MODEL_FORBIDDEN`；不存在的模型交给实际任务报告 `NOT_FOUND`，保持既有错误语义。
   - 撤销开放只影响新选择；既有分析、批次和试算读取保存结果，不重新推理、不改写模型身份。

4. **开放是独立状态，不与启用混为一谈**
   - 开放要求模型 `state=ready`；停用模型即使保留开放记录也不会进入用户可用列表，重新启用后按原开放状态生效。
   - 撤销开放不删除模型，也不改变默认模型；管理员需要另行调整默认与启停。

5. **模型选择器按来源分组，原选不可用不静默替换**
   - 选择器只列 `state=ready`、`enabled` 且仓库兼容的模型；按“我的模型 / 共享模型”分组。
   - 原选模型不在可见范围时保留为禁用项，阻止提交并提示重新选择；不自动落到默认模型。
   - 同名模型附带短 ID，避免选择歧义。

6. **统一控件而不是逐页修补**
   - 日期使用 `react-day-picker` 的弹层日历，支持手动输入、最小/最大值、今天、清除和应用。
   - 范围滑块使用 Radix Slider；危险/不可逆操作用共享确认对话框替换 `window.confirm`。
   - 手写 tablist、按钮组和可点击卡片改为现有 `Tabs`、`ToggleGroup`、`Button`，保持可访问名称与焦点行为。

7. **界面层级按“结论 → 证据 → 明细”收敛**
   - 训练实验：模型对比表先给测试集指标，训练/验证指标与参数折叠在后；不再要求逐项切换分区与指标。
   - PR 审查：单张列表卡承载状态筛选、排序和批量分析，移除重复的右侧待处理栏；行操作保持同一层级。
   - 风险趋势：样本不足给出一句明确提示；比例不可用时用紧凑说明替代空图；缺口标签区分“无已评分提交”和“比例不可用”。

8. **诊断计数拆分“可分析”与“用户可选”**
   - `repositorySelectableModels` 表示仓库兼容的可用模型；`userSelectableModels` 表示其中已开放或属于某用户的模型。
   - 没有用户可选模型时给出 `NO_USER_MODEL`，避免管理员看到“有可用模型”但用户实际无可选。

## Risks / Trade-offs

- **旧工作流会短暂失去无归属模型**：依赖历史内置模型的项目在管理员开放前无法新建分析。迁移不自动开放，管理员需要逐个确认；已有结果仍可查看。这是本次最明显的行为变化，优先保证用户列表不再被测试模型污染。
- **共享模型可能暴露训练数据版本**：共享卡片展示训练数据版本标识，但不提供训练数据入口；管理员开放时应确认该标识可以公开给其他用户。
- **管理员同浏览器双会话**：用户范围优先可能让管理员在用户页面看不到全部模型；管理端目录不受影响，避免误把管理员视图当成用户视图。
- **撤销开放不回溯历史**：用户仍能打开旧分析与旧试算；这是“历史结果保留”的必然结果，文档和界面需明确。
- **统一控件增加前端依赖**：`react-day-picker` 与 `date-fns` 进入前端依赖；只影响日期选择，不引入服务端依赖。
- **PR 页移除待处理栏**：依赖右栏快速跳转的用户需要改用状态筛选；换来单一列表和更稳定的行操作层级。

## Migration Plan

1. 升级前按现有机制备份 `catalog.sqlite3`。
2. 应用 `044_model_sharing.sql`：创建 `model_share` 与时间索引，不写入共享记录。
3. 启动后所有用户只看到本人模型；管理员在「模型管理」逐个开放需要共享的模型。
4. 回滚时恢复升级前备份；新表不改变既有模型、分析或评分数据。
