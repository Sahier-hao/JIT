# Spec Delta

## Purpose

让用户在分析之前看到仓库自身的公开事实（元数据、语言、活跃度和最近提交），并清楚区分仓库活跃度、模型分数与缺陷率。

## ADDED Requirements

### Requirement: ROV-01 只读公开仓库事实

项目概览 SHALL 读取项目自身公开 GitHub 的元数据、语言、最近 12 周提交和最近提交，并显示读取时间；MUST NOT 读取标签、运行模型或生成风险分数。非 GitHub 项目 MUST 只显示基础信息并说明不支持仓库概览。

#### Scenario: 公开 GitHub 项目
- **WHEN** 用户打开已登记的公开 GitHub 项目概览
- **THEN** 看到仓库名、描述、默认分支、stars/forks/开放 issue、语言构成、最近 12 周提交和最近提交

#### Scenario: 非 GitHub 来源
- **WHEN** 项目来源不是公开 GitHub
- **THEN** 概览只显示已有基础信息并说明不支持仓库概览，分支分析仍可使用

### Requirement: ROV-02 缓存与失败可见

概览 SHALL 缓存读取结果并标注读取时间。GitHub 限流、网络失败或格式异常时 MUST 显示上次缓存或可读原因，MUST NOT 画空图或编造数据；显式刷新才重新请求远端。

#### Scenario: 缓存仍在有效期
- **WHEN** 用户在缓存有效期内重开概览
- **THEN** 直接显示上次结果与读取时间，不重复请求 GitHub

#### Scenario: 限流但已有缓存
- **WHEN** GitHub 限流而本地已有缓存
- **THEN** 显示缓存内容、读取时间和限流原因，允许稍后刷新

#### Scenario: 无缓存且读取失败
- **WHEN** 首次读取失败且没有缓存
- **THEN** 显示原因与重试入口，不显示零值图或示例数据

### Requirement: ROV-03 图表与等价表格

活跃度 SHALL 以单轴周提交柱图呈现，语言以横向条形或堆叠条呈现；两者 MUST 提供等价文本或表格、键盘访问和工具提示，并说明覆盖范围与“仓库活跃度不是模型分数或缺陷率”。

#### Scenario: 活跃度图
- **WHEN** 用户查看最近 12 周活跃度
- **THEN** 每周柱高对应提交数，可聚焦查看具体周与数量，并可打开等价数据表

#### Scenario: 语言构成
- **WHEN** 用户查看语言构成
- **THEN** 每项显示语言、百分比与字节数，不依赖颜色单独区分

#### Scenario: 覆盖范围
- **WHEN** 活跃度来自最近 100 条提交
- **THEN** 页面明确标注覆盖范围，不称为完整仓库历史

### Requirement: ROV-04 不改变分析

读取概览 MUST NOT 创建分析、改变当前结果、改写个人工作或触发模型。新建项目 SHALL 只登记仓库，概览 MUST 提供明确的首次分析入口，分析由用户显式发起。

#### Scenario: 新建项目
- **WHEN** 用户输入仓库地址建立项目
- **THEN** 只登记项目并进入概览，不自动产生分析记录或分析任务

#### Scenario: 概览读取
- **WHEN** 用户浏览或刷新仓库概览
- **THEN** 当前分析结果、分析记录和个人工作保持不变

#### Scenario: 发起首次分析
- **WHEN** 用户点概览的「发起第一次分析」
- **THEN** 打开分析对话框，由用户选择模型、分支、日期范围和提交上限
