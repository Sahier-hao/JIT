# Proposal

## Why

当前产品把项目分析、PR 工作单和仓库后台检查分散在不同入口：普通用户从 PR 开始，项目自身的分析结果无法形成连续风险趋势，PR 更新也只能在打开页面或手动检查时发现。以项目为中心的持续审查可以把这三条能力接到同一条用户旅程上，让评审者在离开页面后仍能跟进真实 PR，并从项目自身成功分支分析中判断风险变化，而不把 PR 试验或旧来源混入主线。

## What Changes

- 默认入口改为项目列表；项目页拆为概览（仓库信息）、分析（当前结果与分析记录双栏，页内切换「分析结果 / 风险趋势」）、PR 审查三个稳定子视图，风险趋势不再单列页签；项目列表内保留「我的审查」标签作为跨项目个人聚合；新 PR 从项目 PR 审查进入，旧 PR、分析与计划深链接继续可用。
- 新建项目只登记仓库，不自动开始分析；概览读取公开 GitHub 元数据、语言、最近 12 周提交和最近提交，并提供明确的首次分析入口。
- 新增项目自身风险趋势：只读取项目成功分支分析，按分支、模型与运行、特征 schema、分档规则划分可比口径；固定视图保存来源清单与内容指纹，同 SHA 去重，冲突或来源失效明确拒绝，未知桶与最小样本返回空值和原因。
- 新增项目级 PR 后台自动分析：项目显式启用并固定真实兼容模型；服务端发现并固定 base/head 快照，按意图去重、单 PR 单在途、持久轮转、临时重试与限流处理，暂停不取消已提交任务，取消或中断不自动复活。
- 分支检查改为只提醒：发现新 HEAD 只写项目动态和站内提醒，不自动创建分析；用户点「分析这次更新」后自行选择模型、日期和提交上限。
- 新增站内提醒：事件只写公开事实与固定引用，按幂等键去重；已读状态保存在当前浏览器，已读不等于已复核；提醒不自动创建或改写个人草稿。
- 分析任务记录用途、归属与来源：PR 任务属于基项目，代码来源保留实际 fork；只有分支任务推进项目当前结果。旧 PR 评分在迁移时冻结真实关联，读取时标注兼容边界。
- 数据库正向追加迁移 013–016；显式初始化旧库前生成一致的 SQLite 备份，备份失败阻止升级。旧项目已开启的分支自动分析迁移为只提醒，已提交或运行中的任务不取消；PR 自动跟踪默认关闭，旧当前 PR 指针不重置。

## Capabilities

### New Capabilities
- `project-risk-trends`: 项目自身成功分支分析的固定趋势视图、可比口径、去重、冲突与未知边界。
- `project-pr-tracking`: 项目级 PR 发现、固定快照与模型、后台分析队列、重试和暂停恢复。
- `project-notifications`: 项目公开事件的持久化、幂等去重、站内提醒与本地已读边界。
- `repository-overview`: 项目概览的公开 GitHub 元数据、语言、活跃度、最近提交、缓存与限流边界。

### Modified Capabilities
- `focused-project-review`: 项目页改为三子视图（概览、分析、PR 审查），风险趋势并入分析页内切换；默认入口改为项目；PR 来源记录不能按分支参数重试，旧当前 PR 指针需说明来源。
- `public-pull-request-review`: PR 发现与快照改为项目作用域；模型线索除用户主动请求外可由项目固定自动模型产生，并标注旧关联限制。
- `workspace-navigation`: 项目子视图、固定 PR 快照与趋势 viewId 的地址恢复和旧链接映射。
- `review-revisions`: 后台发现不自动改写个人轮次；个人暂停与项目后台暂停相互独立。
- `repository-updates`: 新建项目默认不分析；分支检查改为只提醒，不绑定模型或自动创建分析。

## Impact

- 后端：`sync.py` 的任务创建、完成与项目当前结果推进；`pr_review.py` 的项目作用域快照与旧评分读取；`catalog_storage.py` 与迁移 013–016；新增 `project_trends.py`、`pr_updates.py`、`repository_overview.py`、`repository_updates.py` 的只提醒事件；`api.py` 新增项目事件、PR 清单/跟踪、趋势视图与仓库概览接口；`api_errors.py` 错误范围。
- 前端：`navigation.ts`、`App.tsx`、`AppShell.tsx`、`pages/ProjectPage.tsx`、`pages/PullRequestJourney.tsx` 及新增项目活动、PR 清单、趋势组件与 client。
- 契约与文档：`docs/api/openapi.yaml`、`docs/当前产品.md`、`docs/PR审查使用指南.md`、`backend/README.md`、产品需求/设计/测试计划与本轮验收记录。
- 数据与运行：SQLite 迁移 013–015；仍为单后端、单分析 worker，不引入 Redis/Celery；PR 仅支持公开 GitHub。
