# Design

## Context

模型产物经目录登记后具有固定身份，分析记录保存实际模型及结果。管理员权限已覆盖维护路径。当前隐式目录顺序选择没有持久默认设置，任务只保存明确指定的身份；动机见 proposal.md。

## Goals / Non-Goals

**Goals:** 分离管理员策略与产物完整性；确保默认切换、排队、停用和重试具有明确来源；迁移保留模型、账户与结果。

**Non-Goals:** 不改变训练协议、评分阈值和既有分数，不按测试指标选优；维护者验证预测仍可加载停用产物，启停控制仓库新分析。

## Decisions

1. 策略存于独立 `model_policy`，默认值使用唯一单例行 `model_default`。状态 `ready/invalid` 仍表示产物完整性，`enabled` 表示新仓库分析准入。相比新增 `disabled` 产物状态，这避免重新登记意外清除停用决定。更改默认和启停用即时写事务提交，并发切换仍只有一个默认。
2. 已有目录迁移时一次性选择 ID 排序首个 ready 且 schema 兼容的模型，之后固定保存；空目录在首个兼容产物登记时建立初始默认。相比每次请求重新排序，这把原隐式选择转为可见且可修改的持久设置；不以指标或模型名称判断优劣。默认损坏保留原身份，要求恢复或管理员另设默认，不自动替代。
3. `requested_model_id` 保留用户原意，`resolved_model_id` 在入队时绑定实际现成模型候选。明确指定优先，强制训练不绑定默认，自动策略只在需要回退时使用绑定值。去重同时比较两个身份，默认修改后新请求不会复用使用旧默认的活动任务。相比执行时再找默认，这避免排队期间无声换模型。
4. 入队检查明确指定及现成策略模型；执行选取模型时再检查启用和完整性。停用后尚未开始使用模型的任务失败并保存原因；已经通过该检查开始使用模型的任务可以完成。历史读取不经过新分析策略门槛，因此停用不删除或重算结果。相比取消所有任务，这保留可核对的任务终态与已有工作。
5. 模型列表在文件验证后读取同一策略快照，防止单次响应出现多个默认。界面沿用现有卡片、字体、颜色和移动布局，默认标记靠近可用状态，动作置于身份信息之前。停用提供影响说明和确认；错误保留明确恢复入口。草稿和重试保留失效模型，禁止静默改选。
6. 模型加载使用每个目录实例最多 16 项的内存缓存，键包含产物目录和登记 manifest 校验值，可容纳当前九模型目录且保持容量上限。命中前后仍读取并核对全部服务文件 hash，模型身份、schema 和管理员策略继续核对；文件改变即拒绝，不以缓存替代完整性验证。相比每次解析相同历史数据及反序列化模型，这减少重复 CPU 和磁盘工作；相比按时间或文件 mtime 缓存，这不会让文件变更绕过校验。

## Risks / Trade-offs

- 默认模型变为损坏 → 现成策略明确失败；管理员恢复并重新登记或设置其他默认，已有结果不变。
- 浏览器模型列表过期 → 服务端在入队及执行时复核；用户刷新并重新选择，失败不伪装成功。
- 目录列表验证多个真实深度产物耗时 → 保持现有完整性校验，浏览器验证给出合理加载时间；此变更不引入缓存绕过。
- 停用与执行同时发生 → 以执行选取模型的检查作为边界，已开始使用的任务可完成；管理确认文字说明该边界。

## Migration Plan

1. 使用 SQLite backup 保存数据库和现有模型目录。
2. 暂停当前部署的后端后执行 `catalog-init` 应用迁移 008。独立策略表和作业绑定列保留旧记录与账户。
3. 启动新后端并由管理员核对初始默认；可改为其他已启用兼容模型。
4. 需要退回旧代码时，停止新后端并恢复升级前数据库备份；不能让旧版本直接读取迁移 008 数据库。升级后新记录应先另行备份保留。
