# Spec Delta

## MODIFIED Requirements

### Requirement: RCL-09 同步产物串联打分，并允许用户选择打分模型

同步成功后系统 SHALL 把采集产物登记为新数据集版本，并让该来源的提交在工作台获得风险值。创建同步时用户 SHALL 能选择打分模型的来源：自动（按数据量决定）、只用特征口径兼容的既有模型、或强制用该数据集训练；未选择时默认取自动。自动与建议判定 MUST 参考训练窗口内的提交数与正例数；样本不足且有可用的已绑定默认模型时 MUST 降级使用该模型并在作业与界面注明使用的模型、降级原因与"未在该仓库验证"，MUST NOT 静默产出无意义模型。用户强制训练时 MUST 给出训练区实际样本数与正例数；时间切分无法同时得到训练集与测试集的两类标签时 MUST 失败并建议改用既有模型。训练或打分失败 MUST 保留已登记的数据集版本供查询；MUST NOT 覆盖既有数据集版本或模型身份。

#### Scenario: 自动模式按数据量选择

- **WHEN** 用户未指定打分模型来源并提交同步
- **THEN** 系统在采集完成后按训练窗口的提交数与正例数决定训练或降级
- **AND** 作业记录实际执行的路径与判定依据，界面能说明为什么没有训练

#### Scenario: 数据充足时训练并使用本仓库模型

- **WHEN** 采集完成且训练窗口内的提交数与正例数达到门槛
- **THEN** 使用该数据集训练模型、完成准入登记，并用它给该来源的提交打分

#### Scenario: 样本不足时降级使用兼容模型

- **WHEN** 自动模式下训练窗口的提交数或正例数低于门槛，或时间切分后的测试段没有正例
- **THEN** 作业仍完成，改用提交任务时绑定的、已启用且特征口径兼容的默认模型打分；绑定模型不可用则明确失败
- **AND** 作业与界面注明实际使用的模型、降级原因，以及该模型未在此仓库验证、不展示公开数据集的测试指标

#### Scenario: 用户强制训练但样本偏少

- **WHEN** 用户选择强制训练而训练窗口的提交数或正例数低于建议门槛
- **THEN** 只要时间切分能得到训练集与测试集的两类标签，系统仍执行训练并完成登记
- **AND** 结果页显著标注训练区实际提交数、正例数与指标波动风险

#### Scenario: 强制训练无法切分时失败

- **WHEN** 用户选择强制训练，而时间切分后训练集或测试集缺少某一类标签
- **THEN** 作业失败并说明数据量不足、无法完成时间切分，建议改用特征口径兼容的既有模型

#### Scenario: 训练失败但保留数据

- **WHEN** 数据集登记成功而训练或打分失败
- **THEN** 数据集版本仍可查询，作业如实说明未产出可用模型

#### Scenario: 没有兼容模型时明确失败

- **WHEN** 数据不足以训练且用户选择只用既有模型，但模型目录中不存在特征口径兼容的可用模型
- **THEN** 请求或作业失败并说明缺少可用默认模型，不产出没有模型来源的风险列表

### Requirement: RCL-15 指定模型的来源一致性

分析创建 SHALL 接受明确 modelId，指定时使用 generic-model 策略并在入队前校验模型存在、已启用、可加载且 schema 可读取当前仓库特征。requestedModelId 与提交时绑定的 resolvedModelId MUST 持久化并共同参与活动任务去重；实际打分与结果 MUST 保存同一模型身份。指定模型失败 MUST 不静默换成其他模型。未指定时 SHALL 保留现有自动/强制训练策略。

#### Scenario: 指定真实深度或经典模型
- **WHEN** 用户选择兼容的已登记模型并发起分析
- **THEN** 请求和任务保留 requestedModelId，执行实际加载该模型，完成结果 modelId 与指定值一致

#### Scenario: 模型输入不兼容
- **WHEN** 请求指定不可用模型或不能读取仓库采集输入的 schema
- **THEN** 明确拒绝并说明原因，不回退其他模型或创建伪成功结果

#### Scenario: 不同模型不合并为同一活动任务
- **WHEN** 同一仓库、分支、范围、上限和策略分别指定两个不同模型
- **THEN** 不因其他参数相同而复用同一个活动作业；重复提交完全相同模型和参数时复用活动任务

#### Scenario: 指定模型的失败重试
- **WHEN** 用户恢复一条指定模型的失败任务并再次提交
- **THEN** 原指定或已绑定现成模型身份可核对和编辑；未修改模型时新任务继续使用同一 modelId，原失败记录不被覆盖

## ADDED Requirements

### Requirement: RCL-18 默认绑定与策略变化

系统 SHALL 以用户明确选择优先，现成模型策略及自动回退在任务提交时绑定默认模型。修改默认 MUST 不改变排队任务身份。绑定模型在执行选取时已停用或不可用 MUST 明确失败；已经开始使用的任务可完成。新分析拒绝停用模型，历史结果和审查计划 MUST 保持原模型身份。

#### Scenario: 默认改变后队列继续使用原模型
- **WHEN** 提交任务绑定模型 A 后，管理员把默认改为 B
- **THEN** 原任务仍使用 A；同参数的新请求绑定 B 且不复用 A 的活动任务

#### Scenario: 自动策略回退与强制训练
- **WHEN** 自动策略数据不足，或用户明确选择强制训练
- **THEN** 自动回退使用提交时绑定的默认且无默认时失败；强制训练保持既有数据条件判定，不因默认设置而改变训练来源

#### Scenario: 停用排队模型
- **WHEN** 任务绑定的模型在执行选取前被停用
- **THEN** 任务保存 MODEL_DISABLED 失败原因，用户重新选择后创建新任务；原任务不产生替代模型结果

#### Scenario: 历史和草稿保留原选择
- **WHEN** 结果对应模型被停用，或打开引用它的草稿和失败重试
- **THEN** 已完成记录仍可读取；原选择可见且标明不可用，用户重新选择前不能提交，不静默改用当前默认
