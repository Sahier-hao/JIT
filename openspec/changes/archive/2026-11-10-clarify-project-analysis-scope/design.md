# 设计

## Context

仓库分析有两种模型来源：`repository-trained` 用本项目历史提交训练，`generic-model` 使用目录中的现成模型。前者有数据集、时间切分与 90 天留出段；当前结果卡只显示算法名和总提交数，无法区分训练期与留出期。后端的 `repository_sync` 已保存模型、数据集、训练样本与切分预设，训练产物已保存 `split.json`、`metrics.json`、`summary.json`，数据集描述已保存纳入/排除与标签规则，因此无需重算或迁移。

## Goals / Non-Goals

- Goal：结果页先回答“谁产生了这个排序、用哪份数据、哪些提交是模型没见过的、模型在测试集上表现如何”。
- Goal：默认把留出段作为“新提交”视图，全部视图明确标注样本内提交。
- Goal：分数以未校准模型输出表述，给出阈值，不再叫概率或“高风险”。
- Non-Goal：改变模型、重新训练、修改分数或数据集；为留出段伪造指标；把训练期提交从“全部”中删除。
- Non-Goal：对 `generic-model` 强行展示不存在的训练集或切分。

## Decisions

### D1 口径由服务端一次性构造

新增 `analysis_scope.build_scope`：读取同步记录、数据集公开投影与训练产物，生成模型身份、数据集质量、切分数量/截止、测试指标、排除提交与各分区风险分布。`SyncService.analysis_scope` 以 `(syncId, completedAt, modelId, datasetVersion)` 为键缓存，不写库。

### D2 分区按时间边界与数据集纳入规则

- 训练：不晚于 `split.json` 训练段结束；
- 验证：训练结束之后、验证段结束之前；
- 测试：验证结束之后、测试段结束之前；
- 留出：不早于 `summary.json` 的 90 天留出起点；
- 未纳入：不满足数据集纳入规则（无新增行、变更/文件超限或 14 维特征缺失）；
- 已打分：现成模型分析，无训练分区。

项目详情与同步提交接口都返回 `partition`，前端不自行推算。

### D3 默认只显示留出，全部视图保留样本内

有留出段时默认 `holdout` 视图，分布、总数与“最该先看”只取留出提交；`test` 视图只看测试段；`all` 视图保留全部分析提交，但明确提示包含训练/调参时见过的提交，并给每条提交标分区。

### D4 分数语义改为阈值与未校准

分档仍沿用 `repo-distribution-v1` 的 0.25 / 0.10，但界面标题写“模型分数分布（未校准）”，标签写阈值本身，不再使用“高风险/中风险/低风险”。优先列表显示弱标签状态（有证据 / 未观测）并固定说明“分数是未校准的排序值，不是概率”。

### D5 数据集内联

结果卡直接显示数据集版本、纳入/原始、正例、标签规则、训练/验证/测试/留出数量与测试指标；保留“查看数据集”打开原有详情与下载。

## Risks / Trade-offs

- 新增口径会多读模型产物和模型身份，首次请求略慢：缓存后按同步身份复用。
- 留出段可能只有个位数样本：界面显示样本量与正例数，不把它包装成稳定指标。
- 全部视图仍可能让人误解：固定提示样本内与未纳入分区，并提供默认留出视图。
