# 项目分析结果口径与分区

## Why

项目分析页现在只显示“已分析提交 178、高风险 56、最该先看”和一个算法名，用户看不出：这是哪个模型、用哪份数据集训练、多少条参与训练/验证/测试、哪些提交是模型真正没见过的。结果卡把训练期提交与 90 天留出提交混在一起，并把未校准的模型分数按 0.25 / 0.10 分档称为“高风险”，容易被读成缺陷概率。

## What Changes

- 分析结果前增加“分析口径”：模型身份与策略、数据集版本与纳入/正例数、标签规则、训练/验证/测试/留出数量与截止日期、测试集指标与样本量。
- 每条提交带分区（训练、验证、测试、留出、未纳入数据集、已打分），提交明细页同样显示。
- 有留出段时默认只显示留出提交；提供“测试 / 全部”切换，全部视图明确提示包含训练或调参时见过的提交。
- “高风险/中风险/低风险”改为带阈值的“模型分数分布”，标题固定“未校准”，并说明不是缺陷概率。
- “最该先看”改为按当前视图取前三，显示分区与弱标签状态（有证据 / 未观测）。
- 数据集摘要直接显示在结果卡上，仍可打开原数据集详情与下载。

## Capabilities

### Modified Capabilities

- `focused-project-review`：分析结果必须交代模型、数据集、时间切分、留出与逐提交分区，默认区分样本内与样本外，分数语义必须明确为未校准排序值。

## Impact

- 后端：新增 `analysis_scope` 只读口径构造，项目详情返回 `viewContext.scope`，同步提交接口返回 `partition`；缓存口径，不重训、不写库。
- 前端：新增分析口径卡与视图切换，结果卡改为按分区展示；提交明细增加分区与口径摘要。
- 测试：新增后端分区/纳入规则测试、前端口径卡与解析测试，更新项目页与提交明细旅程。
- 不改变：模型训练、分数、数据集内容、目录库、默认模型与 PR 审查结果。
