## ADDED Requirements

### Requirement: MC-12 受控实验运行发现与生命周期

模型目录 SHALL 发现管理员配置的受控实验根中完整、可验证的运行，并区分实验运行与服务模型。每个实验运行 MUST 返回稳定候选身份、方法、schema、数据集版本、指标集、指标摘要、产物完整性、可服务兼容性、登记状态和不可登记原因。实验运行成功 MUST NOT 被表述为已经登记或可用于用户项目；不存在完整模型产物的报告 MUST NOT 生成实验运行候选。发现 MUST 只读取声明根内的 manifest 和摘要，不接受任意客户端路径。

#### Scenario: 完整套件运行出现在实验清单

- **WHEN** 受控实验根中存在带完整模型文件、manifest、摘要和指标的成功运行
- **THEN** 管理员可查询该实验运行及其数据集、schema、方法、指标、运行身份和 `experiment` 或 `promotable` 状态
- **AND** 该运行未登记前不出现在用户模型选择中

#### Scenario: 失败运行或报告型结果

- **WHEN** 套件方法失败，或目录中只有聚合报告而没有完整模型产物
- **THEN** 失败方法显示原失败原因，报告型结果不生成可登记模型候选

#### Scenario: 受控路径之外或产物不完整

- **WHEN** 请求引用任意路径、未声明根、缺失文件、hash 不符或 manifest 不一致的运行
- **THEN** 返回可定位拒绝，不读取根外文件、不发布模型、不伪造指标

### Requirement: MC-13 选择性登记、兼容性与目录就绪

管理员 SHALL 能对明确选择的实验运行执行单条或批量登记；登记 MUST 重新执行完整产物校验，并按原运行身份去重。可服务兼容性 MUST 由当前用户分析输入能力决定：声明离线或需要当前服务无法生成的输入时 MAY 保留为实验运行，但 MUST NOT 作为用户可选模型。登记 MUST NOT 自动按指标择优或设置默认；首个合法兼容模型可按既有规则建立初始默认。模型目录 SHALL 暴露未登记、可登记、已登记、不可兼容和缺少默认模型等就绪事实。

#### Scenario: 成功登记兼容运行

- **WHEN** 管理员选择一个通过校验且兼容用户仓库输入的实验运行并登记
- **THEN** 目录原子创建或复用模型身份，返回登记结果和模型详情入口
- **AND** 用户模型选择随后可读取该模型，默认模型仍遵守既有初始化规则

#### Scenario: 不可兼容或离线基准

- **WHEN** 管理员选择 benchmark-only、语义输入不可现场生成或 schema 不兼容的运行
- **THEN** 页面和 API 明确显示不可用于用户分析的原因，不把“已登记”冒充“可选择”

#### Scenario: 重复或并发登记

- **WHEN** 同一运行被重复或并发选择登记
- **THEN** 目录复用同一运行和模型身份，不产生重复模型或第二个默认

#### Scenario: 空目录就绪检查

- **WHEN** 产物存在但目录没有登记模型或默认模型为空
- **THEN** 管理端明确报告未就绪及可执行的登记路径，不把候选数量当作可用模型数量
