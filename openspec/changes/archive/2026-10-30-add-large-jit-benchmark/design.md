## Context

动机与边界见 [proposal.md](proposal.md)，行为契约见 [jit-benchmark-datasets](specs/jit-benchmark-datasets/spec.md)。

当前数据层要求每行是一个提交，包含 `commit_id`、`author_date`、`bugcount` 和 schema 所需来源列；OpenStack 固定快照只能使用其中 6 个字段。现有 `kamei14-git-v1` 已能表达完整 14 维，但其语义来自本地 Git 历史重算，不能直接复用到发布者预计算数据。现有 `run-suite` 能对单个数据集训练全部 9 个方法，`metric-set-v2` 包含 Popt 与 IFA。

公开候选中，JITMovingTarget 的 OpenStack/Qt CSV 缺少 `lt`，不满足完整 14 维；JIT-Fine 的复现包声明 `feature_size=14`，基于 LLTC4J 的行级数据，但字段顺序、来自行级标签的提交级转换和许可证尚未核实。原始 Kamei 数据是另一候选，但具体可下载快照也需审计。

## Goals / Non-Goals

**Goals:**

- 用同一审计矩阵判定 JIT-Fine/Kamei 候选，选出唯一满足完整 14 维和大型样本要求的来源。
- 把来源差异隔离在版本化离线适配器中，规范化为现有登记和训练可消费的提交级 CSV。
- 在不改变生产服务的前提下，生成九种方法的完整、可复现基准结果。

**Non-Goals:**

- 不实现用户仓库服务、管理员页面或在线接口。
- 不混合 JIT-Fine、Kamei、OpenStack 或 Qt 的标签。
- 不将 OpenStack/Qt 快照的 12 个可用字段补造成 14 维。
- 不依据测试结果调整方法超参、阈值或选择默认模型。

## Decisions

### D1. 审计是数据导入的前置闸门

候选必须在同一审计表中比较：

- 来源 URL、许可证、固定 revision 或版本、文件哈希与获取方式；
- 项目数、样本数、时间范围、样本单位；
- 14 个字段的原始列名、类型、缺失规则和语义；
- 标签字段、标签规则、正例率、行级到提交级的转换方式；
- 训练/测试切分可行性及是否满足“大型基准”门槛。

建议门槛为规范化后至少 5,000 条纳入提交、至少 500 个正例，且训练和测试均包含两类标签。门槛未满足时停止并报告，不为了完成流程降低到小样本数据集。

优先顺序为 JIT-Fine，其次原始 Kamei 数据。顺序只表示调研顺序，不代表预先选定；以审计证据为准。

### D2. 来源适配器与核心数据解析分离

导入采用显式来源适配器：

```text
pinned source bytes
  -> source adapter (jit-fine-v1 | kamei-vN)
  -> canonical commit CSV
  -> existing dataset manifest / registry
  -> existing run-suite
```

适配器负责读取来源格式、验证哈希、映射规范列和处理来源特有的标签转换；核心训练代码只消费规范 CSV。适配器版本、源文件哈希、源列映射和转换规则写入数据集描述文件的附加证据。

导入必须离线、确定性，并且先校验后原子发布。未知列、重复提交、无效时间、标签外值和缺失 14 维字段均在写出正式数据集前拒绝。原始大文件不强制入库；若许可证允许，可登记固定 URL 和哈希并按需下载。

### D3. 新 schema 固定 14 维完整输入

注册 `kamei14-benchmark-v1`，字段顺序固定为：

```text
ns, nd, nf, entropy, la, ld, lt, fix, ndev, age, nuc, exp, rexp, sexp
```

14 个字段全部作为专家特征进入模型。字段的源列与变换由 schema 声明，适配器只负责落成规范列；缺失字段一律拒绝。标签、提交标识和作者时间不进入模型输入。

即使字段名与 `kamei14-git-v1` 相同，也保留独立 schema，因为来源和变换契约不同；这样既有 Git 运行身份不会被改变。

### D4. 复用现有套件与指标集

导入完成后只运行现有九种具名方法，并使用 `metric-set-v2`。套件记录每个方法的成功运行或失败；比较复用现有同口径判断，不新增自动选优流程。测试结果只用于报告，不反馈到默认模型或生产登记。

### D5. 数据与证据分层

- 原始快照：记录 URL、license、SHA-256 和不可变 revision；只有许可证允许且体积合适时才提交。
- 规范化 CSV：是否提交按体积和许可证决定；若超过现行仓库预算，保留确定性导入命令和哈希，并在本地工作区运行。
- 运行产物：按现有 `backend/artifacts/` 规则保持本机可重建，不提交全部运行。
- 证据：审计报告、源映射、九方法汇总、失败和方法限制冻结到 `docs/evidence/add-large-jit-benchmark/`，不放入已归档 change。

## Risks / Trade-offs

- [JIT-Fine 是行级标签，无法可靠映射为提交级标签] → 审计未通过就拒绝，不自行定义会改变标签含义的聚合；回退审计原始 Kamei 数据。
- [候选来源许可证不允许提交数据] → 只记录固定来源和哈希，提供本地导入命令，不把受限原始数据放入仓库。
- [来源数据已含不可重算/语义不明的派生特征] → 逐字段核验并记录原始定义；不能核验则拒绝该字段或整个来源。
- [大型数据增加 CPU 训练时间] → 先运行经典方法，再运行深度方法；沿用现有超时与失败隔离，不能为追赶时间篡改协议。
- [单一时间切分导致波动] → 明确披露测试正例与样本量，不据此自动选择模型；多种子/多切分扩展留给后续 change。
- [新旧 schema 字段同名被误认为可互换] → 运行身份包含 schema 名，数据来源与适配器版本也进入 manifest。

## Migration Plan

这是纯增量的离线数据能力。先完成审计并确定来源，再注册 schema、导入数据和运行套件。若审计失败，不修改现有 schema、数据集或服务；回退只需删除本 change 生成的新 schema 与数据集产物，既有运行不受影响。
