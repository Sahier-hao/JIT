# 设计：发起分析的对话框入口

## Context

项目详情页在 1400px 以上是双栏（IP-18）：主栏放当前分析结果与分析记录，窄栏 360px 放仓库更新与发起分析。发起分析要填分支、起始/结束日期、提交上限、分析模型、模型策略六项，内联在窄栏里只能压成两列，控件被裁切；而且展开后窄栏比主栏高出约 300px，整页出现一段空白。

表单组件 `AnalysisForm` 已经自己管理会话草稿（`sessionStorage`，键 `jit:analysis-draft:<repositoryUrl>`），提交、错误、模型可用性也都在它内部。

## Goals / Non-Goals

**Goals**

- 窄栏里「发起分析」只占一段可读的参数摘要和一个主按钮，不再拉长页面。
- 摘要必须等于「现在点开始分析会用的参数」，不能与表单里的草稿脱节。
- 表单在对话框里获得足够宽度，字段单列可读，取消与提交始终可见。
- 草稿、失败重试、模型不可用这些既有行为不变。

**Non-Goals**

- 不重写表单的提交逻辑，也不改 `startRepositorySync` 的契约。
- 不为窄屏单独设计一套表单；窄屏下对话框铺满视口宽度即可。
- 不把「仓库更新」也搬进对话框。

## Decisions

1. **对话框而不是抽屉或内联展开。** 抽屉会盖住主栏、与右侧窄栏叠在同一侧；内联展开正是现在的问题。600px 宽的对话框能放下两列短字段加单列长字段，遮罩也让用户在提交前只面对这一个决定。
2. **摘要读草稿，而不是写死默认值。** 入口卡显示 `sessionStorage` 里的草稿合并默认值后的结果；对话框关闭时重新读一次。这样「分支 release、上限 200」这类改动会留在卡上，用户不必打开对话框才能确认。
3. **表单保持自管草稿。** `AnalysisForm` 继续负责草稿读写与提交，`AnalysisLauncher` 只负责开关、摘要与传入 `initial`。不引入新的状态容器，避免两处草稿不同步。
4. **`destroyOnHidden` 卸载对话框内容。** 关闭即卸载表单，避免上一次的错误提示或模型列表残留；重开时由草稿恢复字段值。
5. **重试时自动打开。** 「用这些参数重试」把失败记录的参数作为 `initial` 传入，入口卡随之打开对话框，用户确认后提交——比让用户先滚动找到展开区域再确认更直接。

## Risks / Trade-offs

- **多一次点击**：以前展开即可见字段，现在要多点一次「发起分析」。换来的是窄栏恒定高度与不被裁切的字段；发起分析本身是低频动作，这个交换划算。
- **摘要可能与对话框内的临时编辑不一致**：用户打开对话框改了分支但没提交就关闭，摘要只在关闭时刷新——提交或关闭都会刷新，不会长期不一致。
- **antd v6 的类名差异**：模态内容元素是 `.ant-modal-container`（不是 v5 的 `.ant-modal-content`），自定义样式与截图脚本都按 v6 写。
- **窄屏对话框高度**：字段单列后内容可能超过视口，对话框需要内部滚动，而不是撑破页面。

## Migration Plan

1. `AnalysisForm` 去掉内联展开与卡片外壳，只渲染字段区与页脚，新增 `onCancel`。
2. 新增 `AnalysisLauncher`（摘要 + 按钮 + `Modal`），在 `ProjectPage` 里替换原来的展开式表单。
3. 样式从 `.analysis-card` 迁到 `.analysis-launcher` / `.analysis-dialog`，删除窄栏里针对展开区的覆盖规则。
4. 更新两处测试的交互路径（先点入口按钮再断言字段），跑全量测试、构建与截图核对。

回滚：恢复 `ProjectPage` 里对 `AnalysisForm` 的直接渲染，并删除 `AnalysisLauncher` 与对应样式即可，契约与数据无变化。
