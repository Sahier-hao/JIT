# Design

## Context

用户数据工作区和管理端共享开关已经在 2026-11-17 的实现中存在，但工作树未提交、未做 OpenSpec 归档，也没有真实管理员会话的 UI 验收。现有主规格 `user-data-workspace` 已覆盖归属隔离、切分、训练和旧数据兼容，但没有描述“共享只来自管理员显式白名单”“用户自有版本禁止共享”和“时间事实与完整性字段”的返回规则。`interface-presentation` 也没有约束侧栏活动项的唯一性。

数据集版本可能只存在于描述文件而尚未导入目录库（如本机批次中的 scikit-learn、vue-core）。此时 `dataset_record` 没有记录，用户数据接口仍应返回可核验的登记时间与清单哈希，而不是空白。

## Goals / Non-Goals

**Goals**

- 保留 2026-11-17 的全部用户数据/训练/模型与管理共享行为。
- 让共享开关在真实 UI 中可开启、撤销、刷新保持，并对用户端产生正确的出现/隐藏效果。
- 让侧栏活动项与当前路由唯一对应。
- 让未导入目录库的描述文件也能返回稳定的时间事实与完整性字段。
- 清理工作树中的一次性产物，统一 Git 准入规则。

**Non-Goals**

- 不修改共享接口路径、错误码结构或权限边界。
- 不把项目改成多租户隔离，也不改变 `dataset_share` 表结构。
- 不重采、不删除任何已登记数据集，不调整成熟期或准入标准。
- 不在本阶段拆分后端 81 个平铺模块或前端路由（属于 Phase 2/3）。

## Decisions

1. **共享白名单由 `dataset_share` 表显式表达。** 用户端只把 `dataset_share` 中存在且无所有者的版本放入“共享数据”；未开放的全局版本不自动暴露。这样管理员关闭共享后用户端立即消失，且不需要额外的可见性状态。
2. **用户自有版本在存储层拒绝共享。** `set_dataset_share` 先检查 `dataset_owner`，有所有者即返回 `DATASET_OWNED`；前端开关对自有版本禁用并显示原因，避免“看起来能点、实际失败”。
3. **时间事实按来源分列。** `registeredAt` 来自 `dataset_record.created_at`，缺失时回退描述文件写入时间；`importedAt` 只在 CSV 导入路径与登记时间相同时返回；`ownedAt` 来自归属记录；`builtAt` 来自最近完成的构建任务。四者不合并成一个“创建时间”。
4. **完整性字段双路径。** 目录库已导入时读登记哈希；未导入时按描述文件内容计算 `manifestSha256`，`sourceSha256` 回退到清单声明的源文件哈希。
5. **详情组件按地址重挂载。** 管理数据集详情以 `key={dataset:version}` 绑定地址，避免同一组件实例在版本切换时保留旧 `useState`。这比在子组件内同步多个派生状态更简单，也避免旧版开关状态短暂残留。
6. **侧栏高亮收敛为纯函数。** 把“哪些路由属于项目导航”提取为 `projectsNavActive(route)`，由 AppShell 调用并用表单驱动测试；避免在 JSX 中维护一条不断增长的条件链。

## Risks / Trade-offs

- [用户自有版本共享被拒绝的反馈] → 开关禁用并显示固定原因；接口仍返回 `DATASET_OWNED`，防止绕过 UI。
- [描述文件写入时间不是分布式登记时间] → 仅在目录库无记录时使用，并在接口字段语义中明确它是文件登记事实；正常导入路径仍以数据库时间为准。
- [共享开关首次开启会导入描述文件] → 导入失败时接口返回错误且不写共享记录；管理员可重试，不会留下半共享状态。
- [清理缓存影响其他会话] → 保留 `backend/.cache/repositories` 克隆缓存与 `deep` 历史产物；`.dsh-tmp` 未删除；所有删除项均在 `.gitignore` 覆盖范围内且可由命令重建。

## Migration Plan

- 无数据库迁移。现有 `041_dataset_sharing.sql` 保持第 41 版。
- 升级前仍按既有 SQLite 备份路径备份 `backend/storage/catalog.sqlite3`；本阶段只做只读/副本验收，不升级本机库。
- 回退只需恢复工作树文件；本机目录库、模型包和数据集未被修改。
