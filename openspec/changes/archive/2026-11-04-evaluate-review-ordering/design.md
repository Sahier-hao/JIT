# Design

## Context

现有评估只包含原始分数、时间和随机三种顺序，预算在遇到第一条放不下的提交时停止。模型选中的提交平均更大，这个停止规则会放大不利结果。报告也没有模型相对简单基线的配对不确定性。参见 proposal.md。

## Goals / Non-Goals

**Goals:**

- 在相同标签、成本和预算下公平比较五种检查顺序。
- 预算按整提交填充，避免一条大提交提前结束评估。
- 用配对差值与不确定性表述模型是否优于简单基线。
- 策略集合在读取测试标签前固定，避免测试集选择偏差。

**Non-Goals:**

- 不训练新模型、不在评估中调参、不改变默认模型。
- 不把 LOC 等同于真实审查分钟。
- 不把离线结果表述为在线效果。
- 不在系统内强制“未来窗口”验收；它作为离线验证计划记录。

## Decisions

**五种顺序与确定性排序键。** 原始分数按风险降序、时间降序、提交标识升序；风险/成本密度按 `risk / max(cost, 1)` 降序，成本为零时按 `risk` 处理并在报告中注明；按改动量升序、时间降序、提交标识升序；随机顺序按固定种子和提交标识哈希。所有顺序都使用同一测试成员和同一标签。

**策略集合预先固定。** 评估代码在读取测试标签前确定策略列表、预算比例、随机次数和种子，并把它们写入报告。报告对模型与每个简单基线分别给出配对差值，不在测试分区上挑选“最强基线”后再比较。这样避免用测试集选择基线带来的偏差。

**整提交预算与敏感性结果。** 主结果按顺序扫描：提交放得下就选中并扣减预算，放不下就跳过继续扫描，直到列表结束或剩余预算小于所有剩余提交。另按“遇到第一条放不下就停止”重算一次，作为敏感性结果并列展示；两者使用同一预算和同一顺序。

**配对差值与不确定性。** 模型相对每个简单基线报告 Recall@20%LOC 的配对差值。按时间块（默认自然周）有放回重采样 1000 次，固定种子，计算差值的 95% 区间；同时报告每个策略的选中数量、使用行数和覆盖正例。随机策略的报告均值与标准差保留，但不称为置信区间。

**报告版本升级。** 新报告写入版本 2，包含五种顺序、两种预算规则、策略集合和配对结果；旧版本报告继续只读展示，但界面标注其不含成本感知基线和配对不确定性，不把旧结论与新报告混读。

**未来窗口是验证计划。** 至少三个仓库的冻结未来窗口写在 `docs/evidence/` 的验证计划中，记录仓库、时间窗、样本和正例；它不是系统必须执行的产品行为，也不由代码强制“不得调参”。报告只记录实际使用的窗口和是否已用于选择。

## Risks / Trade-offs

- [整提交预算可能留下无法利用的剩余预算] → 同时报告实际使用量和敏感性结果，不把预算使用率当作效果。
- [按周重采样在样本很少时区间不稳定] → 报告有效重采样次数和样本量，样本不足时返回未定义。
- [未来窗口依赖外部仓库] → 在验证计划中固定仓库清单和数据来源，报告不把回顾性窗口称为在线效果。
- [旧报告与新报告口径不同] → 版本字段和界面说明区分，禁止跨版本合并结论。

## Migration Plan

1. 报告版本升级为 2；读取端按版本兼容旧报告，旧报告只读展示并标注限制。
2. 不改变默认模型、在线预测或既有分析结果。
3. 新验收报告写入 `docs/evidence/`，不覆盖旧报告。
4. 回滚时恢复旧评估代码；已生成的 v2 报告保留但不用于结论。
