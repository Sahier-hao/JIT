## Context

训练方法目录已经返回参数标签、说明、默认值和范围，算法库也读取同一目录；训练弹窗目前只使用标签。提交级多方法解释已经支持目录、显式生成、独立保存、条形图、等价表格和并列核对。PR 固定快照保存完整 patch 及按需读取的文件内容，仓库提交记录保存文件路径和提交统计，但不保存固定提交的源码。

行级模型是 JS/TS 的固定系数逻辑回归研究产物，现有接口按提交的整段代码返回概率分数，没有候选行提取、特征贡献或固定 PR/提交身份。产品当前规范禁止它进入 PR/项目分析；本 change 在 `LLP-04` 和 `LLP-05` 中明确允许其作为独立研究证据出现在固定对象上，同时保持提交风险不变。

## Goals / Non-Goals

**Goals:**

- 在同一交付中完成参数说明、算法库定位、IDE 插件指南和 PR/提交分层证据链。
- 对固定 PR 和固定提交中的真实新增/修改行返回可复核的行级 `log-odds` 贡献。
- 用统一契约表达候选完整性、语言覆盖、不可用原因、单位和方法，避免前端猜测。
- 在桌面与窄屏提供条形图和信息等价的表格，并保持键盘、读屏和刷新恢复能力。

**Non-Goals:**

- 不修改提交风险、训练、默认模型、模型目录、模型选择或原解释结果。
- 不将行级模型提升为通用缺陷概率、根因定位或修复优先级模型。
- 不将概率贡献和 `log-odds` 合并，不为不同方法生成统一排名或“最佳解释”。
- 不由浏览器自行解析 Git diff、推断源码或读取当前工作树。
- 不接入自由生成式 LLM；摘要只做证据模板化。

## Decisions

### D1：固定对象证据使用服务端来源适配，不复制前端逻辑

新增只读行级证据服务，内部按资源类型适配 PR 快照和仓库提交，但共用同一候选提取、语言校验、特征计算和响应组装。PR 来源使用已保存的 `pr_snapshot.files[*].patch` 与按快照身份读取并缓存的 head 文件内容；仓库提交来源使用公开 GitHub 仓库 URL、完整提交 SHA 的 commit 文件和固定 SHA 内容接口。浏览器只提交资源身份和路径，不提交代码、行号、diff 或可替换 ref。

替代方案是在两个前端页面各自从 patch 计算候选，再调用现有粘贴代码接口；这会重复解析、无法验证固定源码，也会允许客户端伪造行号，因此不采用。

### D2：只有完整的新增/修改代码行才能成为候选

候选必须同时满足：路径为模型覆盖的 JavaScript/TypeScript 源文件；patch 完整且能解析出新侧行号；固定 SHA 的完整文件内容可读取且为 UTF-8 文本；单文件候选、总行数和字符数在现有上限内。删除行、二进制、生成目录、markdown/配置、重命名后不存在的新文件、截断 patch、截断源码和不支持语言分别返回稳定排除原因。

PR 保存的 patch 不完整时，不尝试用当前远端或其他提交恢复；仓库提交的 GitHub patch 缺失或被截断时，不根据 `addedLines` 或文件路径推测候选。一次请求只处理一个显式路径，避免为打开详情页批量读取大量远程文件；页面按真实文件列表选择路径。

替代方案是扫描整棵仓库或所有 PR 文件；这会使同一个页面请求的远程读取、时间和费用不可控，也无法稳定说明候选完整性，因此不采用。

### D3：行级解释使用可核对的系数分解

每行先使用训练时相同的特征实现计算特征值，得到：

```text
rawLogit = intercept + languageWeight + sum(featureValue * coefficient)
score = sigmoid(rawLogit)
contributionTotal = sum(featureValue * coefficient)
```

响应分别返回 `score`（概率）、`rawLogit`、`contributionTotal`、`intercept`、`languageContribution` 和按绝对贡献排序的前 3 个非零特征项。每个特征项返回人话名称、原始字段名、特征值、系数、带符号贡献和方向；未进入前 3 项的其他贡献以数量与合计值保留，保证分解可以核对。`explanationMethod` 固定为行级线性分解，`explanationUnit` 固定为 `logit`。

现有概率解释继续要求贡献有限且位于 `[-1,1]`；`log-odds` 解释和行级贡献只要求有限，绝对值大于 1 是合法结果。前端使用判别联合或独立类型，不复用概率字段的范围校验。

### D4：新增固定资源接口并保持现有预览接口兼容

- `GET /api/v1/pr-snapshots/{snapshot_id}/line-evidence?path=<path>&side=head`
- `GET /api/v1/repositories/{repository_id}/commits/{commit_id}/line-evidence?viewSyncId=<id>&path=<path>`

两个接口返回同一证据结构，包含资源身份、commit/ref、路径、side、语言、模型 artifact hash、候选覆盖、不可用原因和行结果。成功结果按 `score DESC, line ASC` 稳定排序；状态至少区分 `supported`、`unsupported-language`、`patch-incomplete`、`content-unavailable`、`no-candidates` 和 `model-unavailable`。无路径、路径越界、SHA 无效或对象身份不一致返回输入或上下文错误。

现有 `POST /api/v1/research/line-model/score` 保留并扩展同一行结果字段，作为独立研究预览；现有元数据和按方法解释接口保持兼容。仓库提交响应增加分析时保存的真实 `filePaths`，供详情页选择文件，不新增数据库表或改写历史风险。

### D5：证据链按来源组合，不制造统一“满分链路”

前端新增可复用的分组证据组件。固定仓库提交按“提交风险 → 提交级解释 → 行级研究证据 → 规则命中 → SZZ 历史修复证据”呈现；没有规则运行记录时该组明确说明不可用。固定 PR 快照按“提交风险 → 当前文件 diff/源码 → 行级研究证据 → 静态规则候选 → 覆盖说明”呈现；没有历史修复来源时不展示伪造的修复组。

行级区域同时提供按分数排序的行列表、选中行的前 3 项贡献条形图和等价表格，并单独显示概率分数与 `log-odds` 分解。全部证据来源、单位和不可用原因用文本表达；颜色不是唯一信息。PR 审查侧栏和提交详情复用同一行级组件，但各自保留对象级来源上下文。

### D6：训练参数说明与算法库使用同一目录并支持定位

训练弹窗直接渲染方法目录已有的说明、类型、默认值和范围，显示“默认/已修改”，提供恢复默认。参数区入口打开算法库并携带当前方法身份，算法库滚动并聚焦该方法的参数区域；独立算法库页面使用可选 `method` 查询参数恢复同一选择。说明和重置都只改表单状态，不提交训练。

### D7：插件指南是产品内的静态使用说明

增加 `#/plugins/vscode` 和主导航“IDE 插件”。页面用真实工作流说明报告生成、导入、身份核对和定位，展示只读信任边界与状态表。页面只链接实际存在的构建或安装位置；没有稳定下载源时展示命令和产物名称，不渲染无效下载控件。视觉素材优先使用实际扩展视图截图；若只能取得宿主截图，则只证明宿主可启动，不声称完整 GUI 旅程。

## Risks / Trade-offs

- GitHub 限流或仓库变为不可读会使新提交的行级证据不可用 → 返回来源错误并保持提交风险、已保存解释和静态候选可读，不切换到当前工作树。
- 固定提交需要额外读取 commit patch 和文件内容，打开详情的等待时间高于提交级解释 → 仅在用户展开行级区域时请求，按单文件路径限制，并使用短时请求级缓存。
- 现有部分 PR patch 不完整 → 明确标记不可用；不从完整源码猜测新增行，也不把全文件行当作提交候选。
- 行级模型只覆盖 JS/TS，覆盖范围远小于提交级模型 → 页面显示语言与覆盖原因，不把“不支持”呈现为“零风险”。
- 同一 change 同时涉及前端体验、后端读取和规范边界，回归面较大 → 任务按契约、后端、前端、E2E 顺序推进；最终仍只创建一个变更分支和一个 PR。
- 行级分数容易被误读为缺陷概率 → 所有接口与页面固定返回 caveat，标签始终使用“行级研究证据/特征贡献”，禁止“根因”“缺陷行概率”等文案。

## Migration Plan

没有数据库迁移。部署时先发布兼容的 OpenAPI 与后端接口，再发布前端；旧客户端继续使用现有提交级解释和粘贴代码预览。新接口失败不改变已有预测、解释记录、提交风险或模型策略。回滚前端可以隐藏新证据组件；回滚后端只需移除新路由，旧路径和产物保持可用。PR patch 与 `pr_file_content` 的现有持久化结构不变。
