## Context

PR 只读详情与固定提交详情已经保存行级研究证据，但证据接口在 `PrReviewService.line_evidence` 和 `commit_line_evidence` 中实时读取固定版本的完整源码，再把源码交给模型逐行打分。当前 `line-model-v1.json` 的 `positionFeatures` 为 `false`，`score_lines` 也不接收提交级特征，因此同一新增行的分数只由行内文本与结构决定。完整文件读取没有提高分数质量，却让公开 GitHub 限流、私有来源失效或文件过大时整块证据不可用。

前端同时承担三种证据：提交分数、特征解释、行级排序。原先的展示把方法选择、条形图、六位小数表格、基线说明和稳定性说明全部铺开，文件区右侧固定占用 31% 宽度，修复证据又直接堆在代码上方，主任务不突出。

## Goals / Non-Goals

**Goals:**

- 让同一固定 PR/提交的行级排序不依赖实时网络读取，失败时能给出具体原因。
- 让审查者先看到“第几行、排第几、为什么排这里”，再按需核对技术分解。
- 让模型解释首屏只保留结论和主要输入，多方法与技术元数据折叠。
- 让 PR 代码区默认以 Diff 为主，侧栏和修复证据按需展开。

**Non-Goals:**

- 不提升行级模型指标，不把研究排序包装成缺陷概率。
- 不改变提交风险、默认模型、模型目录或历史结果。
- 不新增行级模型训练、不重新训练现有产物。
- 不重构 PR 提交表、批量分析或后台任务流程。

## Decisions

### 决策 1：行级证据只用固定 patch 的新增行文本

`patch_candidates` 已经解析出真实的 `line` 与 `text`。新增 `score_patch_candidates` 复用 `_scored_line`，与 `score_lines` 共享 `line_logit` 与特征口径。这样：
- 候选仍来自固定 diff，不猜测行号；
- 同一行分数与整文件打分一致（当前产物关闭位置特征）；
- 不再请求 `/contents/`，限流和私有来源不会让排序消失。

拒绝在接口内构造伪完整文件。如果未来模型启用 `positionFeatures`，`score_patch_candidates` 抛出 `LINE_PREVIEW_CONTEXT_REQUIRED`，页面显示明确不可用，而不是用缺失位置特征打分。

### 决策 2：覆盖信息显式说明文本来源与上限

`coverage` 增加 `textSource: "patch"` 与 `usesFullFile: false`；候选超过 `MAX_LINES` 时返回 `content-unavailable` + `reason: "patch-candidate-limit"`。前端契约校验这两个字段，避免旧响应或另一实现悄悄切换口径。

### 决策 3：先结论后技术分解

行级面板的默认视图：
1. 候选行列表，显示行号、代码片段、排名和 0–1 研究分；
2. 选中行的排名、人话摘要、前 3 个行内特征条形图；
3. 可展开的“技术口径与完整贡献”，包含等价表格、`logit`、截距、语言项和其他贡献。

语言项对同一文件所有行相同，不能解释行间排序，因此不进入人话摘要与条形图；技术表格保留并标注“不参与行间比较”。完整表格仍在 DOM 中可访问，信息不少于图表。

### 决策 4：解释面板与 PR 版面按主任务分层

- 提交解释首屏显示模板摘要和主要特征；完整表格、基线、稳定性、方法与来源放入“完整依据”。
- 只有多于一个可用或已保存方法时显示方法下拉；多方法并列核对折叠。
- PR 文件阅读区默认隐藏右侧检查侧栏；打开「行级排序」或「检查文件」时才展开 340px 侧栏。
- 修复证据折叠为一行摘要；文件行不再显示没有单位、容易被误读为文件级概率的提交分。

## Risks / Trade-offs

- **只用 patch 文本会缺少上下文特征** → 当前产物没有上下文或位置特征；未来模型若改变口径会显式失败，不会静默降级。
- **折叠后表格不在首屏** → 表格仍在可展开区域内，且默认摘要直接给出排名与主要输入；可访问性测试覆盖展开后的表格。
- **默认收起侧栏可能多一次点击** → 行级排序和规则检查都是显式动作，按钮保留在文件头；读代码不再被侧栏挤压。
- **旧客户端不识别新增 coverage 字段** → 字段为附加字段；旧客户端忽略后仍可读取 `status`、`lines` 与原有字段。

## Migration Plan

无数据库迁移。新响应为附加字段，旧分析记录仍按原快照读取 patch；不需要重算历史分数。回滚时恢复源码读取路径会重新引入网络依赖，但不会破坏已保存结果。
