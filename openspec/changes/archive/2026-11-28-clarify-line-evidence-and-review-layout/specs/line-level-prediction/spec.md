## MODIFIED Requirements

### Requirement: LLP-05 行级模型研究预览

系统 SHALL 从固定行级实验导出可移植、经 `artifactSha256` 校验且不使用 pickle 的系数模型，并 MUST NOT 将其写入目录库或模型目录。系统 SHALL 提供只读元数据、按请求代码打分和固定 PR/提交候选证据接口，全部复用训练特征实现。证据 MUST 返回逐行身份、0–1 研究排序分、`log-odds` 贡献和覆盖状态，前 3 个非零贡献按绝对值排序；排序分与贡献 MUST 分字段且不可相加。系统 MUST 拒绝未覆盖语言、超限候选和不可读固定 diff，MUST NOT 为生成证据实时读取完整源码，MUST NOT 持久化请求代码或回退其他模型。若模型产物依赖完整文件位置特征，系统 MUST 以明确不可用状态失败。页面 MUST 展示样本、留出指标与限制，并标记“研究预览”“不是缺陷概率”。

#### Scenario: 读取研究模型

- **WHEN** 客户端请求行级研究模型元数据
- **THEN** 返回训练/留出摘要、指标、特征口径、限制和产物校验值

#### Scenario: 按行打分

- **WHEN** 用户提交 TypeScript 代码
- **THEN** 返回按分数降序排列的行号、代码、分数和前 3 个行级特征贡献，并跳过空行
- **AND** 响应固定说明分数不是缺陷概率、未校准、不参与提交风险

#### Scenario: PR 固定快照证据

- **WHEN** 用户打开一个具有完整 diff 的受支持语言 PR 文件
- **THEN** 系统只对固定快照中真实新增/修改候选行生成行级证据，并返回路径、侧别、候选覆盖和前 3 个特征贡献

#### Scenario: 固定提交证据

- **WHEN** 一个仓库提交能够解析到固定提交的合格代码候选
- **THEN** 行级证据绑定该提交、路径和行号，不读取当前工作树或替代为另一提交

#### Scenario: 贡献单位独立

- **WHEN** 响应包含 `log-odds` 行级贡献
- **THEN** 每个贡献只校验为有限数，贡献合计可由各行贡献核对，绝对值大于 1 不被错误拒绝
- **AND** 行分数仍作为 0–1 研究排序分单独展示，不与贡献相加

#### Scenario: 产物损坏

- **WHEN** 研究模型文件缺失、结构无效或校验值不匹配
- **THEN** 元数据、请求打分和固定对象证据接口返回明确不可用错误，不回退到其他模型或目录库模型

#### Scenario: 隔离于主流程

- **WHEN** 用户查看 PR 或提交详情
- **THEN** 行级研究证据不改变提交风险、解释方法目录、默认模型、模型目录或历史结果

#### Scenario: 只用 patch 文本打分

- **WHEN** 当前行级模型未启用位置特征且固定对象具有完整 patch
- **THEN** 系统直接使用 patch 新侧新增行文本打分，不请求完整文件内容
- **AND** 覆盖信息返回 `textSource: patch` 与 `usesFullFile: false`

#### Scenario: 模型依赖完整上下文

- **WHEN** 模型产物声明启用位置特征，而接口只有 patch 文本
- **THEN** 系统返回 `LINE_PREVIEW_CONTEXT_REQUIRED` 或等价明确状态，不伪造缺失上下文

#### Scenario: 候选超过上限

- **WHEN** 固定 patch 的可分析新增行超过研究预览上限
- **THEN** 返回明确的 `patch-candidate-limit` 原因和空候选列表，不截断后假装完整

#### Scenario: 不支持的语言

- **WHEN** 固定对象的语言不在模型覆盖范围，或固定 diff、候选行不可读取
- **THEN** 返回明确的不可用状态与原因，不使用其他语言模型、文件级指标或当前默认模型代替

### Requirement: LLP-09 PR 文件的行级研究排序

PR 文件视图 SHALL 对当前固定快照中真实新增/修改的 JavaScript/TypeScript 行提供只读研究排序；候选 MUST 来自完整 diff 的新侧行，MUST NOT 把删除行、整份源码或未覆盖语言凑入。排序只使用新增行文本与结构特征，MUST NOT 为生成排序实时读取完整文件。每条 MUST 显示行号、代码和 0–1 研究排序分，并固定标注“研究排序，不是缺陷概率”；点击只定位到该行，MUST NOT 创建或修改个人草稿、提交级分数、默认模型或合并状态。模型不可用、diff 不完整、候选超过上限或无新增行时 MUST 显示原因，MUST NOT 用其他模型或提交级分数替代。

#### Scenario: 显示当前文件新增行排序

- **WHEN** 用户打开一个含 JavaScript/TypeScript 改动的固定 PR 文件并选择「行级排序」
- **THEN** 只显示该文件真实新增/修改行，按研究模型排序分降序排列
- **AND** 固定说明研究排序不是缺陷概率

#### Scenario: 点击定位

- **WHEN** 用户点击一条行级排序结果中的「在代码中定位」
- **THEN** 代码区定位到该目标行
- **AND** 不创建或修改个人草稿、提交级分数和合并状态

#### Scenario: 不支持或不完整

- **WHEN** 文件语言不在模型覆盖范围、diff 不完整、候选超过上限或没有新增行
- **THEN** 显示具体原因，不把整份源码或其他分数当作行级结果
