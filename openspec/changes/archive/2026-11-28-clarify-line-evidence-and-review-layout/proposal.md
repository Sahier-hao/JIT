## Why

用户反馈当前 PR 审查有三个直接问题：行级预测“说不清楚”且经常显示不可用；模型解释把方法、单位、表格和局限堆在一起，读不出主要结论；PR 文件区、修复证据和侧栏同时占据版面，主任务被稀释。

其中行级证据还有一个真实缺陷：接口在每次请求时实时读取 GitHub 完整源码，公开仓库限流时异常被吞成 `content-incomplete`，页面只能显示“源码不可读取、不完整或超过限制”。但当前行级模型只使用行内文本与结构特征，不需要上下文，这个依赖既不必要，也让同一固定版本的结果受网络状态影响。

## What Changes

- 行级证据改为只对固定 patch 的新侧新增/修改行打分，不再实时读取完整文件；覆盖信息显式返回 `textSource: patch` 和 `usesFullFile: false`，候选超过上限时返回明确原因。
- 行级面板先回答“这一行在本文件排第几、为什么排在这里”；分数标注为 0–1 的研究排序分，不是缺陷概率。主要特征翻译成行内事实，语言项不参与行间比较；完整 `log-odds` 表格与截距口径放入可展开的技术细节。
- 模型解释先展示中文摘要和主要输入，完整表格、基线、稳定性、方法与来源放入“完整依据”；只有多于一种已保存或可用方法时才显示方法选择，多方法核对待折叠区不再占据首屏。
- PR 文件阅读区默认收起右侧检查侧栏，让 Diff 获得完整宽度；按钮统一为「行级排序」「检查文件」，侧栏页签改为「规则命中」「行级排序」「问题草稿」。
- 文件列表移除无标签的提交分数字和重复的“未覆盖”文字，排序仍按涉及提交的最高分；后续修复证据折叠为一行摘要，展开后才显示修复提交与行号。
- 点击行级结果中的「在代码中定位」直接滚动到对应 Diff 行，仍不写草稿、不改提交分数、默认模型或合并状态。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `line-level-prediction`: 行级证据只依赖固定 patch 文本，明确文本来源、候选上限和不可用原因；语言项不再被当作行间排名原因。
- `prediction-explanation`: 行级与提交级解释改为结论优先的展示顺序，完整表格和技术元数据折叠，但仍可访问且信息不少于图表。

## Impact

- 后端：`research/line_preview.py` 增加 patch 候选打分；`research/line_evidence.py` 移除完整源码依赖；`services/pr_review.py` 与 `services/commit_line_evidence.py` 不再请求文件内容。
- 契约：`docs/api/openapi.yaml` 的 `LineReviewEvidence.coverage` 增加 `textSource`、`usesFullFile`，生成的前端类型同步。
- 前端：PR 代码阅读区、行级面板、提交解释面板、修复证据区、文件列表与侧栏。
- 测试：后端行级预览、PR 行级证据、固定提交行级证据；前端行级面板、PR 预览、解释面板。
- 不改变行级模型产物、提交风险算法、默认模型、模型目录或历史分数；不新增数据库迁移。
