# Design

## Context

分支分析结果页此前提供个人审查计划：列表和详情可把提交加入清单，清单按浏览器与会话保存，并支持 JSON 备份导入导出。产品同时有 PR 工作单的个人轮次、问题与证据。2026-10-30 用户要求分支分析只承担风险度量与复盘，删除计划入口。约束是既有分析、模型与个人草稿不能因入口删除而丢失，旧地址仍需可解析。动机与范围见 proposal.md，行为契约见 specs/。

## Goals / Non-Goals

**Goals:**

- 让分支分析结果页只保留提交明细、筛选、分页与单条详情。
- 删除计划的服务端校验端点与前端存储、导入导出，避免两套个人选择并存。
- 旧 `/plan` 地址落到同一分析的提交明细，旧浏览器数据保留但不读取。

**Non-Goals:**

- 不删除 PR 工作单的轮次、问题、证据、交付或「我的审查」。
- 不清理浏览器中已保存的旧计划键，也不迁移为其他形态。
- 不改变分析、模型分数、解释或历史记录。

## Decisions

1. **服务端端点整体删除，不保留退役错误。** 调用方只有本产品前端，`/plan` 地址在前端映射为提交明细，没有外部客户端需要兼容。保留一个永远失败的端点会让 OpenAPI 与错误码继续暴露已不存在的概念。
2. **旧浏览器计划数据保留但不读取。** 直接删除 localStorage 会破坏用户数据；保留键名、不迁移、不展示，也不在界面声称该数据仍可恢复。
3. **提交详情改为对话框。** 列表作为主内容，详情按需打开，关闭后返回列表原筛选与分页；这样可以减少页面高度和滚动，也避免详情与列表争夺宽度。
4. **`/plan` 地址前向映射。** 旧书签仍解析为 `analysis` 路由的 `commits` 视图，不 404、不重建计划，保证已有链接不断。
5. **相关规格以 REMOVED 处理。** 个人清单、浏览器恢复与保存失败三条要求不再适用；搜索、排序、桌面可操作性与工作区适配改为只描述列表与详情，不保留悬空引用。

## Risks / Trade-offs

- [用户以为旧计划被删除] → 界面与文档说明分支分析不再展示计划、计划入口已移除；数据仍在浏览器，不主动清理。
- [残留规格措辞把个人选择称为计划] → 同步修改 `commit-risk-review`、`focused-project-review`、`interface-presentation`、`workspace-navigation`。
- [删除测试覆盖下降] → 以提交明细、详情对话框与旧 `/plan` 地址测试补足。
- [其他客户端仍调用旧端点] → 返回 404；当前无外部调用方，回退需同时恢复前后端。

## Migration Plan

1. 部署新后端与前端；无数据库迁移。
2. 旧 `/plan` 地址自动落到同一分析的提交明细。
3. 浏览器旧计划键保持原样，不读取、不改写。
4. 回退时恢复前后端代码即可重新读取旧计划数据（若用户未清除浏览器存储）。
