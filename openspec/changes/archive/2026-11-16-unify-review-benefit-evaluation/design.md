# Design

## Context

动机见 [proposal.md](proposal.md)。`metrics.evaluate` 的 `metric-set-v2` 使用 `whole-commit-prefix-stop`，矩阵直接复用该结果；`benefit.py` 的版本 2 主结果使用跳过超预算提交后继续，且已有密度、成本升序、200 次随机及时间块配对评价。应提取共同预算能力，避免再建第三套实现。已有差异与数据限制见 [计划依据](../../../docs/审计/2026-11-15-next-changes-baseline.md)。

## Goals / Non-Goals

**Goals:**

- 在同一输入下使不同报告入口得到一致主结果及敏感性结果。
- 用固定策略、配对区间和实际覆盖量说明收益，完整保留不利结果。
- 将协议和数据准入身份交接到证据索引与管理页面。

**Non-Goals:**

- 不增加预测算法、修改模型分数、选择默认模型或通过测试集调参。
- 不将离线弱标签指标解释为真实缺陷概率、在线节省时间或因果效果。
- 不在本 change 再定义观察窗口或重写前置 change 的数据准入模块。

## Decisions

### 1. 采用显式的新预算协议

新增 `review-benefit-v3` 协议与新版矩阵格式，原 `metric-set-v2` 和旧报告语义保持。共享的纯预算与排序计算接受显式规则，矩阵和收益报告共同调用；旧入口由其已保存版本选择历史规则，不能通过更换默认参数重算旧值。

成本固定为 `la + ld`，预算为测试总体成本的 20%，按整提交累计，放不下时跳过后续继续；另列前缀停止敏感性结果。模型按分数降序、时间降序、完整提交 ID 升序并列；其他策略同样固定并列规则。随机序使用稳定提交身份、固定种子与重复编号，不能依赖输入文件顺序。

如果成本为负或非有限则拒绝；总成本为零或存在零成本提交时，相关成本指标及密度结果为空并解释原因，分类指标和可定义的 IFA 可继续。不能用 `max(cost, 1)` 给新协议制造成本。Popt 使用同一套全预算曲线、理想/最差归一化规则并保存面积与退化原因。

### 2. 固定完整基线与配对不确定性

策略包含模型原分数、风险/成本密度、改动量升序、时间降序、随机顺序；原矩阵的改动量降序如保留，单独以历史或附加策略展示，不能替代成本升序。

沿用模型随机种子 42/43/44 和既有冻结参数。随机排序重复 200 次、基种子 2026。按仓库内 UTC 自然周分块，固定 1000 次配对重采样、95% 百分位区间；每次对模型和各基线使用同一抽样块并重新核算预算。协议冻结时间块、次数、种子与有效次数。同一提交的所有信息作为一组，不把候选行或多种子输出当作更多独立提交。

少于 5 个非空时间块或少于 5 个正例提交时，区间标为不足；点估计可定义时保留。重复抽样副本携带确定的出现编号，避免重复 ID 使排序不稳定。报告逐个给出模型相对全部基线的差值，禁止读取测试结果后择优挑基线。上述门槛是本新协议的预定规则，不是已有实验结论。

### 3. 数据准入是正式复评前置条件

正式真实复评必须使用 `separate-label-observation-window` 交付的观察、成熟和成员身份。开发共享算法可使用独立夹具；前置协议未就绪时，不用旧 `mature` 命名代替准入证明，也不先跑旧数据再宣称已完成新协议。

先使用前置 change 交付的 flask 与 axios 数据，执行四种现有方法和冻结随机种子的仓库内时间外评价。每仓库复评上限 2 小时，失败或超限保留为部分完成；不因结果差而换仓库。完整跨仓库迁移需要同语言至少三个合格仓库，条件未达到时输出不足记录，不能用两个跨语言仓库凑留一结果。

后续扩展回现有六仓库仅在拥有合格数据后执行，不能作为本轮无限重采任务。回顾性留一仓库不承诺模拟同时刻在线部署，报告保存实际来源时间范围。

### 4. 新报告绑定事实并保持只读展示

报告记录新格式、预算协议与哈希、数据文件/状态文件哈希、准入策略、切分成员、方法参数、种子、代码版本、环境和失败格。实验矩阵如果未保存可核验模型产物，明确为方法级证据，不附到某个现成模型的产物级收益结论。

证据索引同时识别新旧格式，继续按来源哈希判断陈旧或无效。管理模型卡和实验页面复用简洁的规则标识及不足原因，不新增用户侧实验维护入口。不混合不同协议的均值，也不对旧 JSON 做原地更新。

案例从固定测试成员按排序分歧预定抽取每仓库 5 例，保留实际提交、成本、标签证据、模型与简单基线位置。结构核验与人工判断分列；只有真实执行的人类审查才可产生人工耗时和采纳率，agent 不填写假想用户数据。

## Risks / Trade-offs

- [新旧召回数值不同] → 显示协议与差异来源，保留旧报告，不把差值写成模型变好。
- [小样本区间不可定义] → 保存数量和原因，点估计与不足结论并列。
- [预算工具重构破坏旧产物核验] → 历史协议显式适配，验证旧参考预测、旧报告读取及固定快照。
- [新数据不足以完成跨仓库评价] → 保留不足清单，先交付有效的两仓库时间外结果，不伪造完整矩阵。

## Migration Plan

1. 先合入并同步 `separate-label-observation-window` 的数据准入契约，核对其实际输出再接入。
2. 增量支持新报告格式和协议，旧格式只读兼容；不需要因新报告重写数据库或模型包。
3. 在独立运行目录生成新报告，确认身份和预算一致后显式冻结到新的 `docs/evidence/` 目录，实施日志置于 `docs/审计/`。
4. 回退时停止生成新格式，保留旧读取与全部历史文件；新格式如不可读则明确提示，不将其按旧规则解释。
