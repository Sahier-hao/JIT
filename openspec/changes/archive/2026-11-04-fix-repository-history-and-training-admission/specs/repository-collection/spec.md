# Spec Delta

## MODIFIED Requirements

### Requirement: RCL-03 Kamei 14 维特征计算

系统 SHALL 为每个纳入提交计算 Kamei 14 维代码变更度量的提交级取值，并在产物中记录每个字段的计算口径与所用历史范围。历史状态 MUST 以该提交的父提交为起点，并且只由该父提交的父链推进；采集只遍历非合并提交，合并提交 MUST NOT 进入记录或推进历史。该限制 MUST 随产物记录。无法计算的字段 MUST 记录为空值与原因，MUST NOT 填零、用同名异义列替代或推算。提交级聚合与论文的文件级样本单位不同，产物 MUST 显式标注该差异。

#### Scenario: 计算完整 14 维

- **WHEN** 采集一个历史完整的仓库范围
- **THEN** 产物包含 14 个字段的全部取值，且 `lt`（变更前文件规模）与 `rexp`（作者近期经验）由仓库历史计算而非留空

#### Scenario: 字段无法计算

- **WHEN** 某提交是仓库首个提交，没有父提交可提供变更前状态
- **THEN** 依赖父提交的字段为空值并附原因，不填零、不跳过该字段

#### Scenario: 口径可重算

- **WHEN** 按产物记录的口径对同一提交重算
- **THEN** 得到相同特征值，差异在声明容差内

#### Scenario: 并行分支不污染历史

- **WHEN** 两个提交共享同一父提交、分别位于不同分支，且作者时间顺序与拓扑顺序不同
- **THEN** 每个提交的文件规模、作者经验与近期经验只来自其父链，不包含另一分支的修改

#### Scenario: 作者时间倒置

- **WHEN** 子提交的作者时间早于其父提交
- **THEN** 历史仍按父链推进，不按时间排序把父提交排除或把子提交计入父提交历史

#### Scenario: 合并提交的限制

- **WHEN** 仓库包含合并提交，且合并分支带来了文件变化
- **THEN** 合并提交不进入记录、不推进历史，产物明确说明合并分支的变化不会汇入主线历史
- **AND** 不把该限制表述为已支持完整合并历史

### Requirement: RCL-04 简化 SZZ 标签

系统 SHALL 按显式规则识别修复提交并回溯其修改文件的上一次变更提交，将后者标为缺陷引入。回溯 MUST 只使用当前提交父链上的文件历史；无法证明父链关系 MUST NOT 把该提交标为引入。每个正例 MUST 保存可复核证据：修复提交、候选引入提交、文件路径、证据时间和观察终点；同一提交由多个修复或文件产生证据时 MUST 分别保存，MUST NOT 互相覆盖。标签状态 MUST 区分有证据正例、未观测和未成熟；未命中 MUST 记为未观测到缺陷引入并注明其含义，MUST NOT 称为已证实无缺陷。标签规则 MUST 有版本标识并随产物记录。产物与报告 MUST 标注该标签为简化 SZZ，MUST NOT 宣称完整 SZZ 实现。

#### Scenario: 回溯到引入提交

- **WHEN** 一个修复提交修改了若干文件，且这些文件在此前有变更提交
- **THEN** 这些文件的上一次变更提交被标为缺陷引入，并保存修复提交、引入提交、文件路径、证据时间和规则版本

#### Scenario: 没有可回溯的修复提交

- **WHEN** 采集范围内没有命中修复规则的提交
- **THEN** 全部标签为未观测到并注明含义，不把结果称为已证实无缺陷

#### Scenario: 规则可复核

- **WHEN** 查看产物中的标签说明或任一正例证据
- **THEN** 可见修复提交识别规则、回溯范围、规则版本和该正例的修复与引入位置，并可据此复核

#### Scenario: 引入候选必须属于父链

- **WHEN** 文件的最近一次变更来自并行分支或合并点，而不是修复提交的父链
- **THEN** 该候选不被标记为缺陷引入，产物记录无法确定父链关系的原因，不用其他提交替代

#### Scenario: 未成熟标签

- **WHEN** 提交时间距离观察终点不足声明的成熟期，且采集范围内尚未观测到修复
- **THEN** 该提交标为未成熟而不是未观测或已证实无缺陷，并记录观察终点与成熟期

#### Scenario: 同一提交多条证据

- **WHEN** 同一提交被多个修复提交或多个文件分别标记
- **THEN** 每条证据分别保存，查询时全部可见，不因后写入的证据覆盖先前证据

## ADDED Requirements

### Requirement: RCL-23 v2 采集的模型兼容与显式降级

新采集 SHALL 默认使用 `kamei14-git-v2` 并记录其历史规则版本。系统 MUST NOT 把绑定 `kamei14-git-v1` 的模型静默用于 v2 数据集；自动模式下没有兼容模型时 MUST 明确失败或降级并说明需要训练或登记 v2 模型，用户显式选择不兼容模型时 MUST 拒绝。旧 v1 数据集、旧模型和旧分析 MUST 保持可用，MUST NOT 因新采集默认值被改写或删除。

#### Scenario: 只有 v1 模型时分析 v2 数据集

- **WHEN** 新采集产生 v2 数据集，而模型目录中只有绑定 v1 的仓库模型
- **THEN** 自动模式明确说明没有兼容模型并失败或降级，不静默使用 v1 模型给 v2 数据打分

#### Scenario: 显式选择不兼容模型

- **WHEN** 用户为 v2 数据集显式选择绑定 v1 的模型
- **THEN** 请求被拒绝并说明 schema 不兼容，不创建成功结果

#### Scenario: 旧 v1 数据仍可用

- **WHEN** 升级后打开旧 v1 数据集、旧分析或旧模型
- **THEN** 原数据、原分数和原模型身份保持可读，不因 v2 默认值被重算或替换
