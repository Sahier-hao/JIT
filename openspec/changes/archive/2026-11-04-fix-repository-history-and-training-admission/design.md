# Design

## Context

`collect.py` 的 `_entries` 使用 `--no-merges` 遍历提交，但 `collect` 仍按作者时间排序，并让所有提交共用一份可变 `_History`。`sync.py` 的准入使用 `rawRecords`，训练执行器却重新解析并过滤。`collect_repository` 在登记前无条件替换目标 CSV。标签只保存二值结果和全局二值化规则。`sync.py` 的 `_generic_model` 只接受 `openstack-six-v1` 或当前 `kamei14-git-v1`。参见 proposal.md。

## Goals / Non-Goals

**Goals:**

- 非合并提交按父链拓扑推进，特征和标签不再混入并行分支。
- 标签证据、来源、规则版本和成熟状态可追溯。
- 准入、分区成员和训练统计一致。
- 命令行采集不覆盖旧文件。
- v2 采集与 v1 模型之间的不兼容显式可见。

**Non-Goals:**

- 不实现合并提交的多父状态合并；首版明确排除合并提交并披露限制。
- 不实现完整 SZZ、逐行 blame 或 issue 核验。
- 不原地重算旧数据集或重训旧模型。

## Decisions

**非合并提交的父链拓扑推进。** 保留 `--no-merges` 遍历，先读取每个提交的父提交，再按父先子后的拓扑顺序处理。每个非合并提交只有一个父提交，状态从父提交状态复制后叠加本提交的文件变化。合并提交不进入记录、不推进历史；合并分支带来的变化不会汇入主线历史，产物记录该限制。完整多父合并需要额外的状态合并和树读取，留给后续变更。

替代方案是遍历完整 DAG 并对合并节点取所有父的并集，但文件行数、作者集合和变更次数在多个父之间如何合并没有唯一答案，且大仓库代价高。首版选择明确、可验证的非合并语义，而不是混用两种说法。

**标签证据使用组合键和旁车。** 证据按数据集版本、提交标识、修复提交和文件路径分别保存，允许同一提交有多条证据。采集为正例生成 `*.label-evidence.jsonl` 旁车，描述文件记录路径、SHA-256 和条数；数据库导入旁车内容。成熟状态在查询时按观察终点和成熟期计算，避免导入时固化后过期。

**新口径使用 v2 schema，兼容性显式失败。** 新采集默认 `kamei14-git-v2`，字段仍为 14 维，但记录新的历史规则版本。绑定 v1 的模型不得用于 v2 数据集；自动模式下没有兼容模型时明确失败或降级并说明需要训练或登记 v2 模型。旧 v1 数据集、旧模型和旧分析保持原身份。

**准入与训练共用清洗结果。** 同步作业解析 CSV 后只生成一份清洗后候选集，准入、可训练数、正例数和截止时间统计都取自该集合；全量评分仍使用未过滤的评分记录。训练执行器重新从同一描述文件和 CSV 生成分区后，核对分区成员数与准入统计，不一致以明确错误失败。

**命令行复用不可覆盖发布。** 命令行和服务端走同一发布函数：先写临时文件，目标不存在时原子发布；目标已存在且字节不同时改用内容哈希版本，仍冲突则失败。登记只引用实际发布的路径。

## Risks / Trade-offs

- [合并分支历史不汇入主线] → 产物和界面明确披露，不称为完整历史；后续变更再支持多父合并。
- [v2 没有现成模型] → 自动模式明确失败或降级并提示训练/登记，不静默使用 v1 模型。
- [大仓库拓扑遍历和状态复制增加内存] → 只复制被触及路径，使用现有提交上限和执行时限保护。
- [证据旁车增加产物大小] → 只为正例写证据，记录条数和哈希，按需读取。
- [训练执行器与准入仍可能不一致] → 训练后核对分区成员，不一致即失败并保留数据集。

## Migration Plan

1. 注册 `kamei14-git-v2`，新采集默认使用 v2；v1 声明、旧数据集和旧模型不变。
2. 新增迁移创建标签证据表并增加来源列；旧行保持空值，查询返回未知。
3. 新采集生成证据旁车；旧数据集不补写、不重算。
4. 回滚时停止使用 v2 采集并恢复旧代码；已产生的 v2 数据集、证据和模型保留，不删除、不覆盖。
