# Design

## Context

上一轮（`add-historical-trend-dashboard`，已归档）把时间桶聚合离线产出并随 `/api/review-batch` 供给，趋势页是只读展示。可复用的现有事实：

- 每个桶已有 `start`／`end`（`UTC+08:00` 的区间端点）、`byPartition[train|validation|test]` 的样本数与正例数、`observedRate`、`risk`（`count`／`median`／`p90`，仅测试记录）。**没有期望风险（mean）**。
- `summary.split` 给出各分区的 `start`／`end`／`count`／`positiveCount`。
- 工作台的日期筛选（CRR-05）按 Asia/Shanghai 解释、含两端；查询状态目前完全由 `emptyQuery` 初始化，地址只承载 `?mode=demo`。
- 现有 `TrendPage` 的三处硬编码需要在本轮拆掉：分区中文名映射、`monthOf` 只取年月、估计只认 `risk.median`。

## Goals / Non-Goals

**Goals:**

- 让趋势视图成为动作入口：任一桶都能带着自己的时间范围跳到工作台。
- 让风险序列的覆盖范围可一眼核对（分区带），不再只靠说明文字。
- 给出一句可核对的洞察，并且**口径站得住**（不把中位数当期望、不让大桶自动胜出）。
- **可扩展**：新增一种洞察、新增/改名一个分区、把桶粒度从月改成周或季，都不需要重写 `TrendPage`。

**Non-Goals:**

- 不新增端点、不改聚合结构与最小样本规则、不改后端产物（因此本轮不引入 `risk.mean`）。
- 不把筛选状态写回地址（可分享筛选态留待后续）。
- 不用趋势数据给模型排名、择优或宣称校准结论。

## Decisions

### D1 地址筛选：初始化读取一次的"查询种子"

**选择**：工作台挂载时读取地址上的 `start`／`end`（`YYYY-MM-DD`）作为**初始**筛选；语义是"查询种子"——当前只认这两个键，其余键忽略。用户之后修改筛选**不写回**地址，因此刷新会回到地址给定的范围（这条行为写进了 CRR-05 场景）。范围与数据来源无关，两种模式下同样生效。

**忽略提示的落点**：使用独立提示（复用 `.notice` 一类的信息块），**不**复用日期错误区——后者表达的是"当前生效的筛选无效"，两者语义不同，混用会让用户以为列表中正在用的范围有问题。

**替代方案**：把筛选持续写回地址（可分享、可前进后退）——会扩大"地址只含 mode"的契约面，并牵出与清单上下文、浏览器历史的关系，超出本 change。

### D2 桶起止到日期：从桶自身端点派生，不假定粒度

**选择**：下钻范围 = `start` 的日期 至 `end 减一秒` 的日期。**不**出现"次月"这类假设：任何粒度的桶（周、季、自定义区间）都只要给出 `start`／`end` 即可下钻。

**替代方案**：按"桶起点当月 + 下月"推算（绑定月粒度，换粒度就要改代码，被否）；直接用 `end` 的日期（含两端会把下一段首日拉进来，被否）。

### D3 分区带：由运行摘要的分区集合驱动

**选择**：遍历 `summary.split` 的键画背景带与边界，标签用"中文名映射命中则用中文，否则用原始键名"的回退策略；分区数量与名称不写死。边界与风险序列覆盖范围必须能被文字核对。

**理由**：规格 DTD-08 明确分区的名称与数量取自运行摘要；写死三段会让未来增加分区（如外部 holdout）时静默错位。

**契约边界（实现时确认）**：既有 `historicalContract` 只接受 train／validation／test 三段，并校验三段计数之和等于纳入行数，因此放宽分区集合**不是**本轮能做的事。本轮的"数据驱动"指**渲染层不写死标签、顺序与边界位置**（遍历摘要的键、中文名未命中回退键名、按桶域裁剪），而不是允许任意分区集合；放宽契约要同时改 PDB／CRR 与后端聚合，属另一个 change。

**横轴随实现改为时间比例**：为了让"分区边界与摘要一致"成立，横轴必须按真实时间投影，而不是按桶序号等距。副作用：桶之间在时间上不连续时序列会在缺口处断开（而不是横跨拉一条线）——真实后端数据的桶是连续的，视觉上无差别；测试夹具用过不连续的桶来覆盖裁剪与断线。

### D4 偏差口径：率差 + 最小样本 + 估算器择优

**选择**：

- **度量**：`差异 = 观测正标签比例 − 估计风险`（都是 0~1 的率，量纲一致）；排序用 |差异|，并列按桶起点升序，保证确定性。
- **估计风险**：**择优取用**聚合里可用的统计量——若将来聚合提供期望风险（`risk.mean`）就用它；否则用 `risk.median`，并在界面把"估计正例数"标注为**基于中位风险的近似**（中位数 ≠ 期望）。
- **门槛**：只对样本数达到 `minSample` 且构成完整的桶参与排序；其余排除并说明原因，不当成"差异为零"。
- **展示**：同时给出观测正例数、估计正例数（近似）与率差，让读者能按数值核对。

**替代方案**：用绝对正例数差（`观测 − 估计`）排序——大桶天然占优，会把样本量差异讲成"异常"，被否；用相对差百分比——小样本噪声大，且对接近 0 的估计值不稳定。

**已知局限**：中位风险不是期望，用它乘样本数得到的正例数会有方向不确定的偏差；所以界面上它只是**辅助展示**，排序依据是率差，文案固定标注近似。

**择优缝要端到端可用**：`trendContract` 必须**接受可选的 `mean`**，否则后端将来真加了期望风险，整份聚合会被判为不合法、择优代码变成死代码。本轮已把该字段作为可选的前向兼容字段纳入契约（缺省时既有产物完全不受影响），因此接入 `mean` 只剩后端聚合与 PDB-21 的改动。

### D5 下钻控件放在文本视图里

**选择**：文本视图每行一个"查看该桶提交"按钮（可 Tab、有可访问名称）是下钻的**主入口**；SVG 上的点击只是鼠标增强。

**理由**：SVG 内部可聚焦元素对读屏器不可靠；文本视图本来就是本页的等价替代（DTD-05），把动作放在那里与既有约定一致。

### D6 洞察层做成可注册的检查项

**选择**：新增一个纯函数模块，定义 `insight = { id, kind, label, compute(aggregate) → { ranking, summary } | { unavailable, reason } }`；页面只负责把注册项渲染成"结论 + 排名 + 数值"，不包含任何具体洞察的计算。本轮**只注册一项**（估计与观测的偏差），但页面结构不随洞察种类变化。

**理由**：这是本 change 的可扩展性主缝——未来加"分区对比""风险集中度""拐点"等洞察时，只新增模块与注册项，不改 `TrendPage` 的布局与文案边界；同时避免把"某个洞察的算法"散落进组件。

**代价**：比写死一条多一点抽象；因此用测试固定缝的行为（新增一项不改变既有项的输出与语义），避免抽象白拿。

### D7 语义边界写死在文案里

**选择**：结论必须包含"诊断信号""风险未校准""不代表缺陷率"三重要点，且不得据此评判模型优劣（与 PDB-20 的立场一致）。页头结论只陈述数值关系。

**位置**：三要点作为**洞察面板顶部的一次性免责声明**对所有注册项生效（实现为 `INSIGHT_DISCLAIMER`），而不是在每个 `headline` 里重复；这样新增洞察不必各自复制免责文案，也不会因为漏写而越界。

### D8 哪些进规格、哪些只做设计

**选择**：规格只约束**可观察行为**（DTD-07 下钻范围含两端且不含下一段首日、DTD-08 分区取自运行摘要、DTD-09 用率差并标注近似）。注册表、估算器择优、数据驱动渲染这些是**内部结构**，写进设计与测试，不写成需求，避免规格被实现细节绑死。

## Risks / Trade-offs

- [中位风险被当成期望] → 排序用率差、估计正例数标注"近似"、并提供"有 mean 时优先"的择优路径；文案不出现"期望值"。
- [注册表过度抽象] → 本轮只注册一项，并用测试断言"渲染不依赖具体洞察种类"；若第二个洞察落地时抽象碍事，再简化。
- [桶结束端换算差一天] → 统一从桶端点派生（`end − 1s`），并对跨月、跨年、粒度非月以及"下一段首日恰有提交"加单测。
- [地址范围与演示模式组合出空列表] → 明确按空结果状态处理并给清除入口，不谎称加载失败。
- [刷新回到地址范围让用户意外] → 写进 CRR-05 场景与 README，说明"手动修改不写回地址"。
- [分区带在小屏挤压图表] → 分区带只做背景层，不占额外行高，两个验收视口回归验证。
- [分区边界可能落到桶域之外] → 绘制时按桶域裁剪分区带（不把域外区间画成半张图），并对"分区范围宽于/窄于桶域"加测试。

## Open Questions

- 是否把筛选写回地址（可分享、可前进后退）——留待后续 change。
- 聚合是否增加期望风险（`risk.mean`）以替换中位数近似——需要新的后端 change 与重跑，本轮先留出择优缝。
- 是否放宽分区集合契约（允许三段之外的分区）——需同时改 PDB／CRR 与后端聚合的计数自洽校验，属另一个 change。
