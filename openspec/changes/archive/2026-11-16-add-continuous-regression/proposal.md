# Proposal

## Why

现有 GitHub Actions 主要生成提交分析报告，后端回归、前端检查和扩展测试尚未形成持续反馈。需要让代码变更及时获得可定位的回归结果，并让完整与浏览器流程在独立环境中定期验证。

## What Changes

- 新增独立于模型风险报告的回归工作流，在 PR 和主分支推送时运行明确列出的关键测试、类型检查、构建和扩展测试。
- 定期及手动运行完整后端、前端和选定浏览器旅程，报告检查范围、退出状态、失败与跳过原因。
- 在干净检出和一次性目录中安装固定依赖、准备真实夹具，隔离端口、数据库、模型副本和输出。
- 测试失败保留非零状态并上传可定位日志；不使用模型风险分作为合并判据，不修改分支保护设置。

## Capabilities

### New Capabilities

- `continuous-regression`: 持续执行分层回归检查，保留可追溯结果和故障日志。

### Modified Capabilities

无。

## Impact

涉及 `.github/workflows/`、后端与前端验证脚本、测试夹具准备、VS Code 扩展测试和开发验证文档。复用现有 `verification-evidence` 的运行目录与归档保护要求。工作流无需本机服务、私有数据或密钥，不自动部署、评论 PR 或更改仓库保护规则；其他 change 的新用例在其合入后纳入检查。
