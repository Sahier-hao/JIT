# 项目详情页的记录与结果分区

## Context

项目详情页要同时回答两件事：这个仓库现在有什么结论、它是怎么一步步分析出来的。上一版把两者放进同一张卡片，记录一多就把页面拉长；发起分析占满窄栏，展开后把记录推出视口；记录行的动作排成一排，失败信息直接铺后端原文。

## Goals / Non-Goals

**Goals**

- 结果与记录各有边界，滚动其中一栏不影响另一栏的阅读位置。
- 分析记录卡高度固定，记录增加时页面不再跳动。
- 记录行的动作收敛到一个入口，删除与详情在浮层里完成。
- 失败记录只给一句可读结论，技术细节按需展开。

**Non-Goals**

- 不改同步接口、错误码与数据集版本命名。
- 不改队列页、分析页与管理区的表面。
- 不为项目页引入新的状态管理。

## Decisions

- **左右分栏而非上下堆叠**：结果是主内容，记录是时间序列；两者高度不可预测，横向分开后各自滚动，页面总高度稳定。宽度 `minmax(0, 1fr) 360px`，≤1180px 回退为单列。
- **记录卡固定 `min(560px, calc(100vh - 190px))`**：记录再多也在卡内滚动；列表末尾给出「已显示全部 N 次分析」，记录少时也有明确收束，不留空白。
- **标记列 + 内容列的网格**：节点与竖线画在 14px 标记列里，卡片间距处由 `::before` 的负 `bottom` 连接，最后一条不画线；当前结果用实心绿点与浅绿底。
- **动作收进「更多」菜单**：打开结果、对比、重试、取消、详情、删除都在浮层里；删除与详情用对话框，避免就地展开把卡片撑高。
- **失败信息只留一句**：`FAILURE_TEXT` 把错误码映射成一句中文结论，后端原文进「分析详情」；图标用警示三角，颜色只给图标。
- **风险分布用占比条**：四个数字给出绝对量，三条占比条给出比例，比圆环更容易横向比较。

## Risks / Trade-offs

- 固定高度在记录很少时会留白，用列表末尾提示收束；窗口高度小于 750px 时卡内滚动更频繁。
- 对话框里的删除与详情多一次点击，换来列表高度稳定。
- 深色主题的主按钮改为浅色反白，与浅色主题的深墨色不是同一颜色，但都保持最高对比。

## Migration Plan

前端单页改动，无数据迁移；旧的分析记录与新记录使用同一套接口与字段。
