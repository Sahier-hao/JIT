# Design

## Context

现有前端是 React 19 + Vite + HashRouter，入口、登录和业务页面都在 `Workspace` 中按路由切换；Markdown 已由共享组件渲染，但默认强制链接新开标签页且没有标题标识。当前产品行为以 `docs/当前产品.md`、`frontend/src/app/navigation.ts` 和实际页面为准，历史 PR 指南中的私有仓库说明已经过期。

文档必须匿名可读，不能把公开正文放进管理员或用户接口。首版只做随前端构建发布的静态内容，不建设独立文档站、CMS、多版本手册或服务端搜索。

## Goals / Non-Goals

**Goals:**

- 用 Git Markdown 和一份发布清单生成导航、目录、正文与搜索。
- 提供可刷新、可分享的文章和小节地址，并保持现有 HashRouter 与业务地址兼容。
- 在桌面和 390px 视口下完成匿名阅读、搜索、定位和业务帮助入口的真实浏览器验收。

**Non-Goals:**

- 不引入后端检索、数据库、CMS、文档版本选择、AI 问答或在线编辑。
- 不迁入管理员数据集、验证报告、模型维护资料、私有仓库资料或真实账号信息。
- 不改变项目、PR、模型、训练、评估和管理员的既有权限与写操作。

## Decisions

### 显式导入的公开内容清单

正文放在 `frontend/content/docs/articles/*.md`，发布清单位于 `frontend/src/features/docs/catalog.ts`。清单显式导入每篇 Markdown 的原始文本，并声明 slug、标题、摘要、分组和排序；未在清单中显式导入的文件不会进入 Vite 构建。相比 `import.meta.glob`，这能直接保证未发布文件不进入产物，而不依赖运行期过滤。

导航、文章切换、目录和搜索都从同一个 `DOC_ARTICLES` 读取。维护说明放在 `docs/文档中心维护.md`，并说明新增文章需要同时加入 Markdown 与导入清单。

### HashRouter 内的文档路由与查询参数

新增结构化路由 `{ name: 'docs', slug?, section? }`，对应 `#/docs[/:slug][?section=<id>]`。文档判断放在登录边界之前，使匿名访问不触发现有工作区重定向；现有 `parseHash` 继续负责兼容地址。小节使用查询参数而不是第二层页面片段，避免与 HashRouter 自带的 `#` 冲突。

文章 Markdown 的标题使用显式稳定标识，例如 `## 提交级风险分 {#commit-score}`。解析器同时为目录和搜索提取该标识；渲染时由共享 Markdown 的文档模式去掉花括号后缀并写入 `id`。定位通过 `scrollIntoView` 完成，无效标识只显示文章内的提示，不改变文章身份。

### 构建期内容与本地搜索

搜索索引在浏览器首次使用文档时由已导入正文解析得到，不请求服务端。索引按文章和小节保存标题、正文、标识和上下文。中文匹配使用规范化后的包含匹配；常用同义词表放在文档模块内，覆盖「风险分」「私有仓库」「模型兼容」「VS Code」。排序优先文章标题、其次小节标题、最后正文，并限制每个小节的摘要长度。

这种方式增加少量首包之外的文档分包体积，但避免了搜索索引与应用正文不一致，也无需维护第二份构建脚本。文档页面按路由懒加载，普通工作台首屏不加载文章内容。

### 复用 Markdown 与现有界面组件

扩展 `components/shared/Markdown.tsx` 的文档模式：支持标题标识、站内 `#/` 链接交给应用导航、外部链接继续新开标签页、表格外层可横向滚动。默认模式保持现行为不变，项目作者说明、PR 结论等调用方无需修改。

文档页复用 `EntryPage`、`EntryHeader`、`Button`、`Input`、`AppearanceControl` 和设计令牌。桌面采用三栏，窄屏把文章目录收进可展开导航；不新增页面级样式表。仅在 `content.css` 增加文档标题的滚动偏移和 Markdown 内容容器样式。

### 入口和上下文帮助

首页页头增加文字「文档」；登录工作区页头增加带书本图标的文档链接。分支分析的结果摘要处链接《怎么看风险分和代码线索》的 `commit-score` 小节；PR 预览和工作单共用的模型线索条增加「怎么看代码线索」，使用新标签页保留 Diff、文件和草稿；模型评估页头增加指标说明链接。所有帮助链接只导航，不触发分析、保存或权限操作。

### 内容真值与失败反馈

操作指南以当前代码为准：项目登记不会自动开始分支分析；模型必须已登记、启用、ready 且 schema 兼容；私有仓库 PR 通过服务端 GitHub 凭据访问，个人中心只检测本机已有凭据，浏览器不持有令牌；工作单草稿按账户保存在浏览器；导出 Markdown 属于本地下载，不自动发送 GitHub。文章不硬编码长期开放的示例 PR，而是给出选择条件与替换方法。

每篇操作指南统一包含前置条件、入口和步骤、成功反馈、常见失败和下一步。FAQ 直接链接文章中的相关小节。

## Risks / Trade-offs

- **正文过期风险** → 发布清单和正文同仓同 PR 更新；维护说明要求逐篇对照当前界面，验证失败反馈用小节锚点统一引用。
- **搜索对中文分词的局限** → 首版采用明确同义词和包含匹配，不用虚假的语义检索承诺；真实查询由测试和浏览器验收覆盖。
- **文档体积增长** → 使用路由级懒加载；只有明确导入的文章进入文档分包，管理资料永不进入。
- **帮助入口干扰审查操作** → 帮助使用新标签页或纯链接，不改变工作单状态；原标签页 Diff 与草稿由浏览器验收确认可继续使用。
- **Hash 路由前进后退** → 小节使用查询参数并监听路由变化；测试覆盖直接打开、刷新、后退与无效小节。

## Migration Plan

无数据库、API 或存储迁移。新增前端路由和静态内容，是一次向后兼容的功能发布；回滚只需撤下文档路由与入口，既有业务数据和权限不受影响。
