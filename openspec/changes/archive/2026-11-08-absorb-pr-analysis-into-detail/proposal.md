# 把 PR 分析的有效信息收进只读详情

## Why

PR 只读详情已经展示提交分数、改动规模、文件 Diff 和作者说明；顶部的「打开分析」跳到分支分析页后，标题变成“仓库分析 · 分支”，返回按钮回到项目而不是 PR，用户在同一份数据上丢失上下文。分析页对该场景真正独有的内容只有“这条提交为什么得这个分”的模型解释，以及大 PR 需要的提交搜索。把这两项直接放进只读详情后，跳转不再必要。

## What Changes

- 只读详情的风险概览移除「打开分析」链接，不再跳转到分支分析页。
- 只读详情的提交表提供按标题或 SHA 的本地搜索，与排序控件分列一组；搜索框与排序按钮同高，不再挤在标题行里。
- 选中一条已评分提交后，可直接展开该提交的模型解释：显示已保存解释或主动生成入口，生成不改变分数、不切换模型。
- 作者说明按 Markdown 渲染（标题、列表、行内代码、代码块、链接），不再显示原始标记；已保存的审查意见也使用同一套只读 Markdown 预览。
- 只读详情标明「只读预览」，主操作改为「创建审查工作单」；进入后工作单页标明「个人工作单」，两个模式不再靠页面内容自行猜测。
- 只读详情读取同一份固定快照分析的方式改为共享查询，同一快照只请求一次；旧版 HEAD 绑定的说明保留。
- PR 工作单同步使用同一份查询结果，移除原来的回调式数据传递。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `public-pull-request-review`：PPR-04 允许只读详情查看并主动生成单条提交的模型解释，但仍不提供模型选择、分析生成、重试或取消；PPR-05 明确只读详情内的提交搜索、解释入口，以及不跳转到分支分析页。

## Impact

- 前端：`PRModelClues`、`PullRequestPreview`、`PullRequestJourney`、新增的快照分析查询与 Markdown 正文组件。
- 依赖：新增 `react-markdown` 与 `remark-gfm`，不启用原始 HTML。
- 文档：`docs/当前产品.md` 的只读详情说明。
- 无后端接口、数据库迁移或模型产物变化；已有分析、分数、解释事实不被改写。
