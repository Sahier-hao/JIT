## Purpose

把"提交的代码语义"变成可追溯、可离线复用的特征：在 Git 采集数据上保存有界 diff 文本，用固定版本的预训练代码编码器生成嵌入表，并让专家特征与语义特征在同一训练、校验与评价口径下对照。

## ADDED Requirements

### Requirement: CSF-01 有界提交文本产物

当采集请求包含文本产物时，系统 SHALL 为每个纳入提交产出与 commit_id 一一对应的文本记录，包含提交标题与有界 diff 摘要；未请求文本的既有采集行为 MUST 保持不变。截断规则 MUST 固定可复现（每文件最多 80 行、每提交最多 8KB、跳过二进制文件），并 MUST 随产物记录规则版本与 SHA-256。同一仓库与范围重复采集 MUST 得到相同顺序与相同内容；二进制或超限内容 MUST 显式标记，不得静默伪造文本。

#### Scenario: 文本 sidecar 可复现

- **WHEN** 对同一仓库与同一时间窗口重复采集
- **THEN** 产出的文本记录顺序、截断结果与 SHA-256 一致
- **AND** 被截断或跳过的文件在记录中显式标记

### Requirement: CSF-02 嵌入表与溯源

系统 SHALL 用**固定 revision 的预训练代码模型**离线生成嵌入表，并按 commit_id 建立索引。元数据 MUST 记录编码器标识、revision、维度、池化方式、最大长度、文本产物 SHA-256 与嵌入表 SHA-256。加载时 MUST 校验这些值；编码器不可用、维度不符或嵌入缺失时 MUST 以明确错误拒绝，不得以零向量代替。

#### Scenario: 嵌入可追溯

- **WHEN** 加载某数据集的嵌入表
- **THEN** 元数据中的编码器与文本哈希与数据集声明一致，嵌入维度与 schema 声明一致

#### Scenario: 缺失或损坏的嵌入

- **WHEN** 某提交没有嵌入、嵌入表哈希不符或编码器 revision 不可用
- **THEN** 训练以明确错误失败，不补零、不退回其他编码器

### Requirement: CSF-03 语义输入契约

含语义的 schema MUST 声明语义块（编码器、维度、嵌入表引用）与专家字段；训练输入 MUST 为"专家字段按 schema 变换后 | 语义向量"，顺序固定。方法的输入形状 MUST 与声明一致；缺失语义而声明含语义的运行 MUST 拒绝，含语义但声明为纯数值的运行 MUST 拒绝。

#### Scenario: 矩阵按声明拼接

- **WHEN** 用 `kamei14-semantic-codebert-v1` 训练
- **THEN** 输入列数为 14 个专家字段加声明维度，顺序与 schema 一致
- **AND** 纯数值 schema 的运行不受影响

#### Scenario: 声明与产物不一致

- **WHEN** 运行声明含语义但数据集没有嵌入表，或数据集含语义而运行声明纯数值
- **THEN** 校验失败并指出不一致项

### Requirement: CSF-04 三方案同口径评估

系统 SHALL 在同一数据集、同一时间切分、同一标签与 `metric-set-v2` 下评估三种输入方案：专家-only、语义-only、语义+专家。三者 MUST 使用同一测试成员；报告 MUST 并列各自指标，MUST NOT 据测试结果自动选择方案，失败方案 MUST 保留失败记录。

#### Scenario: 三方案并列

- **WHEN** 在同一语义数据集上运行三种方案
- **THEN** 报告并列各方案的已定义指标与样本数，并声明测试成员一致
- **AND** 不出现"自动择优"或隐藏失败方案的结果

### Requirement: CSF-05 离线语义边界

语义运行 MUST 仅在离线评估中使用；不含文本的单条数值预测接口 MUST NOT 接受语义模型。无文本的数据集（如 OpenStack 快照）MUST NOT 被用于语义方案，除非另有文本来源登记。

#### Scenario: 无文本数据集

- **WHEN** 尝试在 OpenStack 六字段数据集上运行语义方案
- **THEN** 以明确错误拒绝，不生成伪造文本或空嵌入
