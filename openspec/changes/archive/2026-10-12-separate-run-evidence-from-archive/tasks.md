# Tasks

按 [design](design.md) 的方案实施；行为和失败条件以 [验证证据规格](specs/verification-evidence/spec.md) 为准。勾选进度由本轮实现和逐项证据核验更新。所有验证既要有命令退出码，也要有可复核的产物；测试通过不代替归档证据确实未被改写的比对结果。

## 1. 运行工作区与路径收敛

- [x] 1.1 建立 `docs/evidence/_run/` 与 `_run/fixtures/` 目录约定并加入 `.gitignore`；验证：创建目录后 `git status` 不显示运行工作区，且归档目录仍被跟踪。（VEV-01/D1）
- [x] 1.2 后端测试的证据根改为运行工作区，`runtime-context-fixture-batch.json` 写入 `_run/fixtures/`；验证：运行该测试后归档目录哈希不变，夹具出现在 `_run/fixtures/`，且测试原有断言仍通过。（VEV-01/VEV-04）
- [x] 1.3 前端新增共享模块导出运行工作区与夹具目录常量，`vitest.config.ts`、`playwright.config.ts` 与三个 e2e 规格改为从该模块导入；验证：类型检查通过，单元与浏览器检查结果落在运行工作区，夹具消费链路实际读到 `_run/fixtures/` 的文件。（VEV-01/VEV-04/D2）
- [x] 1.4 `verify.ps1` 的证据根与复现比较输出路径改为运行工作区，并更新 `frontend/README.md` 中写明证据输出位置与复验命令的段落；验证：脚本运行后全部输出位于 `_run/`，README 描述与实际一致。（VEV-01）

## 2. 冻结工具与完整性清单

- [x] 2.1 实现冻结子命令：把运行工作区中的证据写入 `docs/evidence/<change>/`，排除 `fixtures/`，并在报告中列出纳入条目；验证：对一个临时目标执行冻结，纳入条目正确且夹具未纳入。（VEV-02/D3）
- [x] 2.2 生成冻结清单（每个证据文件的相对路径与 SHA256、冻结时刻、来源运行标识）并提供校验入口；验证：单元测试覆盖一致通过、文件被修改、文件被删除、出现未登记新增、缺少来源信息五种情况，各自给出可定位结果。（VEV-03）
- [x] 2.3 处理冻结的边界行为：不删除目标目录中未纳入的文件，重复冻结结果可重复；验证：单元测试断言未纳入文件在冻结后仍存在，两次冻结产生一致清单。（VEV-02）
- [x] 2.4 编写冻结与校验的操作说明，写明冻结是归档前的显式步骤、不由测试或验证脚本触发；验证：按说明在真实目录完成一次冻结与校验，命令与结果可复核。（VEV-02）

## 3. 归档目录只读性

- [x] 3.1 `verify.ps1` 在开始与结束时比对受保护位置（已归档 change 的证据目录、`openspec/specs`、`openspec/changes/archive`、`openspec/config.yaml`、`frontend/public`）的哈希集合，运行期间出现新增、修改或删除即失败并逐项列出差异；基准取自本次运行开始时的实际状态，移除需要人工维护的 `protected-files.json` 及其校验。验证：运行**中途**改动一个受保护文件时脚本失败并指出该文件，还原后通过。（VEV-01/VEV-06/D4）
- [x] 3.2 移除 `verify.ps1` 中对已归档 change 的 `openspec validate`，确认主规格严格校验仍在；验证：脚本通过，检查记录中不再出现该归档 change 的校验条目，且主规格校验条目存在。（D5）
- [x] 3.3 让等待就绪的检查容忍未就绪并留出相称时限：服务轮询容忍已接受连接但正文为空或不可解析；界面重载后的断言先等列表就绪再断言，不把衍生产物当就绪判据。验证：单元测试覆盖空正文与不可解析正文之后转为就绪、以及始终不就绪时的超时失败；浏览器回归在重复运行下不再复现该超时。（VEV-05）

## 4. 端到端验证与证据

- [x] 4.1 执行后端检查、前端类型检查与行为测试、lint、构建及两视口浏览器回归，确认全部输出写入运行工作区；保存命令、退出码与环境信息。（VEV-01）
- [x] 4.2 核对两个已归档 change 的证据目录在整轮验证前后哈希完全一致，且没有任何测试或脚本曾写入该位置；保存比对结果。（VEV-01）
- [x] 4.3 对本次运行执行一次冻结到临时目标，核对快照内容、排除项与清单校验均符合规格；保存冻结报告与校验输出。（VEV-02/VEV-03）

## Workflow follow-up

- 实现与功能证据经复核后，等待用户明确指示，使用对应 OpenSpec 技能和 CLI 同步规格或 archive；不得将 archive 自身列为提前打勾的实现任务。
- 本轮不重写、不搬迁、不重新冻结两个已归档 change 的证据内容；已冻结的历史证据保持原样。
- `protected-files.json` 的合并与证据索引方式的调整均不在本轮，按 design 的 Open Questions 另行探索。
