# Proposal

## Why

基础控件统一后，页面、请求和领域状态仍分散在源码根目录，项目与 PR 页面承担过多职责。按业务模块收拢代码和测试，并让入口与布局职责明确，降低后续修改时的搜索和耦合成本。

## What Changes

- 在 `standardize-frontend-on-shadcn-ui` 完成、验证并归档后执行。
- 将路由、Provider 和应用入口集中到 `app`，全局布局放到 `components/layout`，跨模块组合放到 `components/shared`。
- 按项目、PR 审查、数据、训练、模型、账户和管理功能归并页面、请求、契约及其测试；跨业务基础设施留在 `lib`。
- 拆分项目页和 PR 工作流中的展示与操作区块，保留清晰的页面编排层；移除迁移产生的转发文件和重复外壳结构。
- 增加适度的依赖方向检查并更新前端目录说明，保持现有地址、API、权限、状态恢复和产品行为。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

无。本项为纯内部重构，使用 schema 支持的 `skip_specs: true`；既有界面、导航、管理权限和个人审查规格继续作为回归约束。

## Impact

仅影响前端源码位置、导入路径、模块边界、文档和测试定位，不需要后端或数据升级。保留业务身份、浏览器存储键及旧地址兼容；与前项独立提交及验证。
