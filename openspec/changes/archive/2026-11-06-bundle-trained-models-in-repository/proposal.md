## Why

上一轮已经实现模型包导出、校验和导入，但真实九模型 ZIP 位于被 Git 忽略的运行目录，合并后的仓库只有清单和 SHA-256。其他人拉取代码后没有模型产物，完成标准目录初始化仍会看到空模型目录，无法使用已经训练并验证的九种方法。

## What Changes

- 将已验证的九模型 ZIP 及其 SHA-256 sidecar 作为版本化发布包提交到仓库的受控目录。
- 扩展 `catalog-init`：完成目录库初始化后，若内置模型包尚未成功应用，则使用现有安全导入器校验并登记；导入不覆盖目标环境默认、启停或历史数据。
- 内置包缺失、哈希不符、部分模型冲突或依赖不可用时，初始化结果明确列出失败，不能把包内文件数量或清单冒充可用模型；已有成功模型和目录数据保持不变。
- 重复初始化同一已成功应用的包为幂等操作；新包版本可增补模型，但仍以原 `modelId` 和 `artifactRunId` 去重。
- 更新管理端可见性、部署文档和空目录验收，使拉取同一提交并执行标准初始化后可直接看到九个模型。
- **BREAKING** 此前的“任何模型二进制都不进入 Git”边界改为“原始运行目录和 SQLite 不进入 Git；经校验的压缩模型发布包可进入 Git”。

### Modified Capabilities

- `model-catalog`: 调整模型发布交付边界，增加仓库内置模型包的标准初始化、幂等导入、失败诊断和策略保留要求。
- `admin-training-workspace`: 增加从全新拉取仓库经标准初始化恢复九模型后的管理端可见性与用户选择核对。

## Impact

- 后端：`catalog-init`、模型包发现与导入、导入记录、CLI 输出和相关测试。
- 仓库与部署：新增受控模型包目录、约 5.93 MiB 的版本化 ZIP 与 SHA-256；原始 `backend/artifacts/`、SQLite 和运行期夹具继续忽略。
- 管理端：继续使用现有模型包导入记录、可见性和覆盖矩阵，不新增模型选择旁路。
- 数据兼容：不新增目录库结构；现有目录的策略和历史结果保留，新目录完成初始化后自动获得九模型。
