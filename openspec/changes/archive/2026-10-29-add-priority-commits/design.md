# 设计与取舍

## Context

结果卡信息量小：一个总数、三条占比、一行模型说明。卡片被拉高到与右栏等高后，中下部出现大片空白。

## Goals / Non-Goals

**Goals**：给结果卡补一条真正有用的下一步；避免为填满高度而加装饰或小字。

**Non-Goals**：不做完整提交表格（那是分析页的职责），不加新后端接口。

## Decisions

- 复用现有 `repository-syncs/{id}/commits` 接口，取前 60 条按风险降序取三条，避免全量拉取。
- 三条提交用短号 + 标题 + 分数三列，标题单行省略，分数用风险色。
- 请求失败或为空时不渲染该区块，页面不出现空标题。
- 卡片高度不再固定：由右栏记录列表撑开，左栏跟着拉伸，`justify-content: space-between` 均分余量。

## Risks / Trade-offs

- 分数最高的提交可能不是用户关心的文件，但它仍是「先看哪里」的合理默认。

## Migration Plan

纯展示层改动。
