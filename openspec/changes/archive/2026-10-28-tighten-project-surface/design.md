# 设计：收紧项目详情页的区块层级

## Context

项目详情页是「一个仓库一个工作台」的主入口：顶部是项目身份与「打开审查」，下面依次是仓库更新、发起分析、当前分析结果与分析记录。三块内容分别来自 `RepositoryUpdates`、`AnalysisForm` 与 `ProjectPage` 自身，历史上各自演进，标题、内边距与按钮权重都不同。

现有约束：

- 三个组件的可访问名称被测试锁定（`立即更新`、`重试更新`、`开始分析`、`打开审查`、`查看提交与审查计划`、`分析选项` 的 `aria-expanded`、`自动检查仓库更新` 复选框、`role=alert`）。
- 原生 `<input type=date>` 与 `<select>` 仍被测试用 `toHaveValue`、`selectOptions` 断言，本次不替换。
- 页面已引入 antd，主按钮统一为深墨色，绿色只留给链接、选中与状态。

## Goals / Non-Goals

**Goals**

- 三个区块共用一套标题规格与左边缘，整页字号收敛到 26 / 15 / 13 / 12。
- 同一信息只出现一次；错误信息与恢复动作贴在一起。
- 全页只保留两个深色主按钮，其余动作降为默认或链接按钮。
- 1440 与 390 两档都没有横向溢出。

**Non-Goals**

- 不重做分析记录列表的交互，不改变分页、删除、取消分析的确认流程。
- 不替换测试依赖的原生日期与下拉控件。
- 不改动仓库更新的轮询间隔与后端契约。

## Decisions

**1. 区块标题统一用 `.section-label`（15px/600 + 右侧动作），不再用卡片内标题。**
卡片只承载成组内容，标题一律在卡片外。这样「仓库更新」「发起分析」「当前分析结果」在同一列上左对齐，也避免了 18px 这种只出现一次的字号。

**2. 仓库更新收敛为单张卡片（`.update-card`）。**
状态带、开关、更新设置原本散落在卡片内外，靠背景色区分层级，导致卡片边界不清。改成一张 `1px solid var(--line)` 的卡片后，内部只用分隔线与留白分层。

**3. 错误信息并入状态带详情行，重试按钮升到区块标题右侧。**
原来红字在卡片外、按钮在卡片右上，两者相距约 180px，用户要先读红字再找按钮。现在标题行读「仓库更新未完成 + 重试更新」，状态带读原因，视线不用来回跳。失败态下按钮用主按钮，其余状态用默认按钮。

**4. 只读参数合并成一行摘要（`.analysis-disclosure-summary`）。**
四个灰底标签在视觉上等同于筛选器，但它们是只读参数。合并成「分支默认 main · 最近 90 天 · 最多 500 条 · 自动」后，一行读完，也去掉了四个独立底色块。

**5. 「不会覆盖当前结果」只保留在动作条里。**
原来区块标题右侧和卡片底部各说一次。动作条紧邻「开始分析」，说明的是按下按钮之后发生什么，比放在标题右侧更贴切。

**6. 「查看提交与审查计划」降为链接按钮。**
它与页头「打开审查」跳同一地址，页面上同时出现两个深色主按钮会让主操作失去唯一性。保留链接按钮，动作仍可发现，但不与「打开审查」竞争。

**7. 窄屏用网格而不是 flex 换行。**
`.update-band` 在 900px 以下改为 `grid-template-columns: auto minmax(0,1fr)`，统计三项 `grid-column: 1 / -1`。之前误用 `flex-direction: column`，导致 390px 下标题列被统计列挤成四行。

## Risks / Trade-offs

- **错误信息的可见性**：并入状态带后，错误不再单独占一行红字。缓解方式是状态带标题本身用 `--risk-high` 着色，图标同为警示色，失败时按钮升为主按钮。
- **卡片边界变多**：三块内容都变成带边框的卡片，页面线条比之前多。缓解方式是区块之间用 34px 留白，卡片内只用 `--line-soft` 分隔，避免同强度线条堆叠。
- **链接按钮的可发现性**：降级后「查看提交与审查计划」不如主按钮显眼，可能被忽略。可接受，因为页头已有等价入口。

## Migration Plan

纯前端样式与结构重组，无数据迁移。回退方式是还原这三个组件与两份样式表的改动。
