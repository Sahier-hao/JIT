# Design

## Context

现有预测服务以单条管理员请求为中心，不保存数据集范围内的阈值计数或 Top 风险归因；现有清洗预览只返回排除了多少条，不返回特征分布；算法目录只暴露名称、依赖和可用性。用户数据与模型已经有所有者隔离，训练产物与目录库也已经有稳定身份，因此本轮复用这些事实，不引入新的模型或数据来源。

## Goals / Non-Goals

**Goals:**

- 让普通用户在固定数据版本与固定模型上完成批量试算、阈值试算和风险归因。
- 让清洗预览回答“哪些记录被排除”以及“指定特征在前后如何变化”。
- 让算法和参数说明与真实训练注册表共用一份声明。
- 让 VS Code 扩展的报告生成入口更容易使用，并在 CI 中产出可安装包。

**Non-Goals:**

- 不新增自动超参数搜索、在线学习、PR 自动修复或行级概率换算。
- 不为没有源码快照的表格数据集补造代码位置。
- 不把用户导入数据的现有标签称为独立测试集或已验证真实缺陷率。
- 不在浏览器或扩展中自动执行后端 CLI。

## Decisions

### 用户预测批次使用独立持久化表

新增 `user_prediction_batch` 与 `user_prediction_record`，不复用单条 `prediction_batch` 的一对一唯一约束。批次保存所有者、数据版本、模型、阈值摘要和 101 档计数；逐记录表保存风险、标签状态、特征和可选归因。重开只读数据库，不重新推理。

替代方案是扩展现有单条预测表，但会破坏“一批一条”的旧约束并增加旧接口回归风险；独立表允许旧单条接口保持原语义。

### 批量范围明确上限并整体失败

一次最多 20,000 条提交；超过上限直接拒绝，不抽样。任一记录缺少入模字段时整批失败，避免页面把部分覆盖误读为全量结果。成功写入在一个事务中完成，避免出现有摘要无记录或部分记录成功的批次。

### 阈值指标由保存的计数数组计算

保存 0–1、步长 0.01 的真实正例与误报计数。页面滑动阈值时只重算展示指标，不重新推理，也不把工作点写回旧批次。这样同一结果的阈值交互可重复，且保留创建时阈值作为批次事实。

### Top 风险归因只覆盖有限记录

批量推理后仅对风险最高的 10 条记录计算遮挡式归因，避免对 2 万条记录执行大量单特征重推理。未计算或计算失败的记录明确显示“没有归因”，模型风险不变；归因摘要继续说明不是缺陷结论或代码定位。

### 清洗对比使用清洗前分位边界

预览先按清洗前每个入模字段计算分位边界，再把清洗前与保留记录分别落入同一组桶。这样可以比较真实分布变化，不会因清洗后重新分箱而掩盖排除位置。派生描述文件保存整体前后统计和逐特征桶，重开与导出仍可追溯。

### 算法说明来自方法注册表

算法摘要、收益、代价、适用场景、预处理、解释口径和参数标签放在后端方法注册表中，训练方法目录统一返回。前端算法库只读取该响应，不维护第二份参数范围或默认值。

### 扩展生成命令与 CI 打包

扩展向导只收集输入并复制命令，不执行终端命令。命令生成是纯函数并单独测试，报告解析仍保持只读。独立工作流在扩展目录变更时运行测试并上传 VSIX，避免把打包与主回归工作流耦合。

## Risks / Trade-offs

- 20,000 条上限可能拒绝较大的基准数据版本 → 返回明确上限和当前数量，后续可按性能证据另行提高。
- 逐记录持久化会增加数据库体积 → 只保存必要字段，归因只覆盖 Top 10，并提供明确的批次删除/保留策略后续扩展空间。
- 用户导入数据标签可能不成熟 → 页面展示标签状态分布和“按现有标签试算”的边界，不将其称为正式验证。
- 分位桶在不同版本间不是固定数值边界 → 对比以来源版本为基线，符合“清洗前后”语义；跨来源版本仍按 schema 与派生来源校验。
- 扩展命令复制依赖用户提供真实模型 ID → 向导明确提示从模型详情复制，并由后端在运行时验证模型身份。

## Migration Plan

- 新增前向迁移 `042_user_predictions.sql`；不修改旧预测表，不重写历史预测。
- 旧模型与旧数据所有者为空时继续按共享资源处理；用户预测只在新表中写入所有者。
- 回滚应用代码时保留新增表，不影响旧接口；如需回滚数据库，先备份目录库再移除新表。
