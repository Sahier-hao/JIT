# Spec Delta

## MODIFIED Requirements

### Requirement: IDC-04 安装与冒烟验证

系统 SHALL 提供扩展的构建、调试、报告命令生成与演示步骤。扩展 MAY 通过向导收集基准提交、目标提交、真实模型 ID、目录库和产物根目录并复制完整命令，但 MUST NOT 执行该命令或自动导入未经用户选择的报告。验证 MUST 至少覆盖构建、命令生成、报告解析与扩展宿主的实际冒烟；环境不支持宿主时 MUST 记录具体缺口，MUST NOT 宣称 IDE 旅程已通过。持续集成 SHALL 构建可安装的 VSIX 并作为构建产物上传。

#### Scenario: 构建成功

- **WHEN** 按文档执行扩展构建
- **THEN** 生成可安装的扩展包并记录构建输出

#### Scenario: 复制报告生成命令

- **WHEN** 用户选择复制报告生成命令并填写真实参数
- **THEN** 扩展只把命令写入剪贴板，提示用户手动运行后再显式导入报告

#### Scenario: 命令输入无效

- **WHEN** 模型标识为空或任一输入包含换行
- **THEN** 扩展拒绝生成命令并说明原因，不执行终端命令

#### Scenario: 宿主不可用

- **WHEN** 当前环境无法启动 IDE 扩展宿主
- **THEN** 记录不可验证的原因和已完成的构建/静态检查范围

### Requirement: IDC-05 真实仓库中的报告重复使用

VS Code 扩展 SHALL 在真实仓库中导入分析报告并核对仓库、提交与版本身份；工作树存在未提交改动、报告过期、分支切换、文件重命名或删除、路径越界与行号异常时 MUST 给出明确状态，不把候选定位到错误代码。用户 MUST 能显式重新核对、重新复制生成命令或重新导入更新报告。

#### Scenario: 工作树已修改

- **WHEN** 报告对应提交与当前 HEAD 一致，但工作树文件内容已改变
- **THEN** 扩展提示报告与工作树不一致，定位按报告快照只读展示并说明差异

#### Scenario: 分支切换后重复导入

- **WHEN** 用户切换分支后再次导入旧报告
- **THEN** 扩展显示身份不匹配与原因，拒绝把候选定位到当前代码

#### Scenario: 重新生成报告

- **WHEN** 用户确认旧报告已过期
- **THEN** 可以从扩展复制新的生成命令，手动完成后显式导入新报告
