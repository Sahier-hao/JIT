# Design

## Context

基线为 `792b5ab`。普通项目与维护功能共享访问边界，模型产物、目录登记和分析选择尚未完整连接。本变更增加独立管理员维护能力、真实模型选择及连续的项目分析交互，保留既有项目数据和模型身份。

## Goals / Non-Goals

**Goals:** 普通项目保持打开即用，维护能力要求真实管理员身份；使实际可用模型可选且来源一致；完成运行状态、失败恢复和记录管理的连续流程；保留数据和既有产物。

**Non-Goals:** 多用户项目隔离、团队邀请、跨设备计划、公网部署、训练调度平台、模型自动排名、GPU 实验或新仓库效果证明。

## Decisions

### D1 用户与管理员按任务分区，并在服务端授权

普通项目及固定分析保持现有地址。管理区使用 `#/admin/models`、`#/admin/datasets` 和 `#/admin/reports`；旧报告地址解析原运行后仍由管理区检查会话。后端对模型维护、候选、数据集、提交维护查询、维护预测/批次、schema 和历史验证接口检查会话。公开 `/api/v1/repository-models` 只返回模型选择必要字段，不公开完整维护记录。界面隐藏入口不能替代服务端控制。

### D2 本机账户和可撤销 cookie 会话

首次设置仅允许在无账户时建立一个管理员，无默认账户/密码。密码用独立盐与 PBKDF2-SHA256（600,000 次）保存；会话使用随机 token，数据库只存摘要，8 小时到期。cookie 为 HttpOnly、SameSite=Strict、`/api` 路径，HTTPS 下设置 Secure。退出和本机隐藏输入的密码重置撤销会话。登录按客户端限制尝试，维护写请求校验 Origin。账户与会话持久化，不向 localStorage 写秘密。选择服务端可撤销 cookie 会话，避免由浏览器保存长期 Bearer 凭证并自行判断权限。

### D3 方法、产物与模型是三种不同事实

算法注册表当前为 5 经典、4 深度；模型列表只统计真实校验登记的模型版本。候选发现不反序列化模型；登记复用完整文件/声明/参考推理校验，不自动训练。管理页分别展示方法支持、交付产物数量和 ready 模型数量，复现/测试目录不按文件份数计为模型种类。以目录库的校验状态决定可用性，避免把算法名称直接当成已交付模型。

四个原深度运行位于 `backend/.cache/deep/`，验证后原样复制到正式目录并登记，源文件哈希不变。随机森林、朴素贝叶斯和梯度提升树缺少正式交付产物，按既有固定数据/参数在 CPU 新建运行，不冒充历史 runId。最终本机 9 个模型的身份见 [模型清单](../../../../docs/evidence/2026-10-23-project-admin-model-workflow/models.json)。

### D4 指定模型贯穿请求、执行和重试

分析请求可提交 modelId，指定时使用 generic-model 策略，并在入队前加载校验模型与输入 schema。支持现有六字段及仓库采集十四字段 schema；不兼容直接拒绝。requested_model_id 持久化且参与进行中作业去重；执行加载明确指定的模型并保存实际 modelId。重试恢复同一模型参数，失败不退回第一个模型。未指定时保留已有自动/训练策略。

### D5 状态和历史恢复围绕项目对象

项目列表由服务端返回每个项目的真实 latestSync，不再依赖全局前 50 条任务猜测状态。项目变更事件刷新列表和侧栏，进行中作业定期更新；加载已有数据时保留页面。分析记录按每页 10 条查询；失败恢复参数到可编辑表单并保留原记录；删除先说明影响并防重复提交。新项目允许 defaultBranch 为 null；模型名称按保存的 modelId 读取。

### D6 增量迁移和已有产物兼容

迁移 007 只增加 requested_model_id、管理员账户和会话表。升级前使用 SQLite backup，升级后核对既有业务表和产物哈希。旧任务未指定模型时保留原策略；既有模型、成功结果和个人计划不因管理入口调整而删除。

## Risks / Trade-offs

- 普通项目公开访问 → 明确维护权限的本机边界，不将其描述为团队或多租户隔离。
- 权重/数据库不随源码交付 → 提供产物生成、校验和登记命令，部署时核对实际目录状态。
- 新仓库效果和概率校准尚未验证 → 展示模型来源及局限，不将功能验证表述为效果提升。
- cookie 和写权限依赖部署 Origin → 默认仅监听回环地址，维护写入校验来源；公网部署另行验证。

## Migration Plan

1. SQLite backup 后应用迁移 007，增加 requested_model_id、admin_account 和 admin_session。
2. 核对既有 16 个业务表/88,041 行共用列及 36 个受保护产物文件不变；登记模型前再次备份。
3. 通过既有 CLI/完整准入登记实际产物，确认各模型可用于输入 schema。
4. 启动自有本机预览并让用户首次设置管理员密码；不停止其他会话服务。
5. 回退源码时保留升级后的数据库及备份，不在共享工作区 reset 或删除新数据；需恢复库时先停止自有写服务并另存现状，使用已验证的备份。

实施命令、验证结果与日志见 [实施验证](../../../../docs/审计/2026-10-23-project-admin-model-workflow.md)。
