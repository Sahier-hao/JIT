# Spec Delta

## MODIFIED Requirements

### Requirement: RCL-05 采集产物与数据集登记

采集 SHALL 产出与具名特征 schema 对齐的表格文件和数据集描述文件，并通过现有登记入口登记。产物 MUST 记录字段定义、质量统计、提交时间范围与样本；质量统计 MUST 能从产物重算。同一来源、范围与标签观察策略重复采集 MUST 幂等；数据行与标签语义身份一致时，即使采集时间、HEAD 等非语义元信息不同也 SHALL 复用既有版本，MUST NOT 因此失败或新建重复版本；数据行或标签语义身份不同 MUST 形成新版本而非覆盖已有版本。版本冲突检查 MUST 保护原始 CSV；新 CSV MUST 完整写入后原子发布，目标已存在时不得替换。描述文件与登记记录 MUST 标明数据集来源为分支分析或 PR 分析，并记录产生它的分析标识；PR 分析在目标提交特征已全部保存且可复用时 MAY 不重复登记新数据集版本，但 MUST 在分析记录中保留特征来源与数据集引用；分支分析 MUST 继续登记独立版本。

#### Scenario: 采集并登记数据集

- **WHEN** 采集完成并登记产物
- **THEN** 数据集可按版本查询，描述文件包含字段定义、质量统计与时间范围

#### Scenario: 重复采集同一范围

- **WHEN** 以相同参数再次采集同一仓库同一范围
- **THEN** 数据行与标签语义身份一致时幂等返回既有版本；任一不同时新建版本并保留旧文件

#### Scenario: 仅采集元信息变化

- **WHEN** 同一提交集合被再次采集，只有采集时间或 HEAD 等非语义元信息不同，标签观察策略与内容身份一致
- **THEN** 复用既有数据集版本，不新增重复版本，也不让本次分析失败

#### Scenario: 原始文件先发生版本冲突

- **WHEN** 候选版本的 CSV 已存在且内容与新采集不同
- **THEN** 保留旧文件字节，尝试内容哈希版本；无法建立新版本则明确失败，不影响旧版本

#### Scenario: 描述或导入内容发生冲突

- **WHEN** CSV 内容一致但描述信息、标签语义身份或数据库导入内容与候选版本冲突
- **THEN** 保留原文件和已登记信息，沿用包含语义身份的内容哈希版本重试，仍冲突则拒绝覆盖

#### Scenario: 发布前中断或并发发布

- **WHEN** 新文件尚未写完时分析中断，或发布时目标文件已由其他执行建立
- **THEN** 未完成内容不替换正式目标；已存在目标必须重新核对字节，不能用本次临时文件覆盖

#### Scenario: 标记数据集来源

- **WHEN** 数据集由分支分析或 PR 分析产生
- **THEN** 描述文件与查询结果标明来源类型和来源分析标识
- **AND** 旧版本没有来源字段时按分支来源兼容读取

#### Scenario: PR 分析复用已保存特征

- **WHEN** PR 涉及提交在同一仓库、同一 schema 下均已有可复用特征
- **THEN** 分析直接使用这些特征完成打分，不重复登记内容相同的数据集版本
- **AND** 分析记录保留特征来源，界面可说明哪些提交复用了既有特征

#### Scenario: 观察策略变化但二元标签未变

- **WHEN** 相同 CSV 对应的观察终点、成熟期、标签规则或样本准入策略发生变化
- **THEN** 产生新的语义身份和数据版本，不复用或改写旧版本

## ADDED Requirements

### Requirement: RCL-28 提交纳入窗口与标签观察窗口分离

采集 SHALL 分别固定提交纳入窗口、修复观察窗口、仓库 revision 和成熟期。只有纳入窗口内的提交进入样本，观察窗口中位于纳入截止之后的修复仍可为这些提交提供证据；特征 MUST 仅使用对应提交父链中的历史。观察终点 MUST 有可核验的仓库历史与执行覆盖，MUST NOT 以当前日期或请求中的未来终点冒充已完成观察。

#### Scenario: 截止之后发生修复

- **WHEN** 一个纳入提交在样本截止之后、观察截止之前被修复
- **THEN** 该修复可为原提交提供正例证据，修复自身不因用于观察而进入纳入窗口
- **AND** 原提交特征不包含该修复或其他未来提交

#### Scenario: 观察边界不可核验

- **WHEN** 指定的 revision、历史完整性或观察范围无法核验
- **THEN** 产物明确标为观察不完整或采集失败，不声明该范围已充分观察

#### Scenario: 未提供独立观察终点

- **WHEN** 既有调用未提供独立观察终点
- **THEN** 记录实际执行的观察范围并据此计算成熟度，不自动增加虚构的观察时间

### Requirement: RCL-29 标签状态与准入信息可重建

新 SZZ 数据版本 SHALL 保存每条纳入提交的标签证据状态、观察边界和成熟准入结果，信息 MUST 在登记、导出及重新读取后可重建。标签语义身份 SHALL 包含观察策略、成熟期、规则版本和准入策略。零标签 MUST 继续解释为未观测；未成熟、观察未知或证据截断 MUST NOT 被描述为可靠负例或完整评价证据。

#### Scenario: 写出并重新读取

- **WHEN** 采集结果被登记、导出并从导出包重新加载
- **THEN** 同一提交的标签证据状态、成熟准入结果及其身份保持一致，不因只读取二元 CSV 而丢失

#### Scenario: 成熟期边界

- **WHEN** 提交距实际观察终点分别小于、等于和大于声明成熟期
- **THEN** 按固定 UTC 边界规则计算准入结果，规则与结果可以从版本内容重算

#### Scenario: 证据被预算截断

- **WHEN** SZZ 执行因修复数量、时间或行数预算提前结束
- **THEN** 保存实际截断和覆盖状态，不将名义观察终点作为完整证据覆盖声明
