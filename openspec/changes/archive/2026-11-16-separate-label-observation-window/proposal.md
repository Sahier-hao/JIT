# Proposal

## Why

Git 数据集的提交纳入窗口与标签观察窗口共用终点，成熟状态在写入二元标签 CSV 后未被训练和评价入口继续执行，观察不足的零标签可能进入测试。需要让成熟期成为可核验的样本准入规则，避免将尚未充分观察的提交当作可靠负例。

## What Changes

- 分开记录提交纳入窗口与修复观察窗口，固定实际可核验的仓库 revision、观察边界和成熟期。
- **BREAKING**：新 SZZ 训练与正式评价默认执行成熟样本准入；未知或截断版本不可冒充完整评价，旧数据仅按显式历史协议复现。切分预览与实际执行使用同一集合，评分范围不因训练排除而缩小。
- 将标签观察策略及其内容身份纳入数据版本和运行谱系；未知、截断和旧协议保留明确限制，不自动升级为可信数据。
- 以新版本重建有限的真实仓库样本，完成固定抽样核验并如实记录人工复核状态，保留旧数据、模型和历史结果。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `repository-collection`: 分离纳入与观察边界，保存可核验的成熟状态，并将标签语义变化视为新版本。
- `dataset-splitting`: 在切分前执行统一样本准入策略，记录排除原因、策略身份和实际成员。
- `dataset-registry`: 在数据详情及可移植导出中保留观察事实、成熟统计和旧版本限制。

## Impact

涉及 `backend/jit_baseline/collect.py`、`szz.py`、`datasets.py`、`data.py`、`splits.py`、`split_preview.py`、训练、同步与多仓库评价的数据入口，以及相应契约和数据详情。实验实施记录置于 `docs/审计/`，新证据置于 `docs/evidence/`。不新增特征维度，不替换默认模型；需要数据库升级时使用前向迁移和升级前备份。
