# Design

## Context

动机见 [proposal.md](proposal.md)。当前 `collect.py` 将样本窗口终点用作 `observedThrough`，`szz.py` 也按同一终点筛选修复；`_csv_bytes` 只保存二元标签。`split_preview.py`、`evaluation_matrix.py` 和训练产物入口重新解析 CSV，不能继续执行采集阶段的成熟状态。同步训练已有独立 holdout，需保留其与新准入规则的交集。现状核对见 [计划依据](../../../docs/审计/2026-11-15-next-changes-baseline.md)。

## Goals / Non-Goals

**Goals:**

- 让观察事实、样本准入、时间切分和运行身份在采集、登记、预览、训练与评价间一致。
- 保留原始样本用于评分和审计，合格训练集合单独生成。
- 使旧产物仍按原版本核验，新规则可以逐版本采用。

**Non-Goals:**

- 不增加模型输入字段，不重新解释发布者标签，不将未观测样本称为人工确认负例。
- 不重训既有交付模型、不修改默认模型，不保证所有仓库均能达到训练门槛。
- 不在本 change 改写预算评价算法；相关工作由 `unify-review-benefit-evaluation` 承接。

## Decisions

### 1. 分开固定样本与观察范围

样本窗口继续控制输出提交与特征，新增观察终点用于修复识别与回溯，二者绑定同一固定 revision。对纳入窗口之外、观察范围之内的修复，只保存其对纳入提交的证据。特征计算仍只使用各提交父链，不能看到未来修复。

同时保存请求终点、实际执行边界、revision、历史完整性与 SZZ 覆盖状态。没有已核验来源时，不能用当前时间或晚于缓存历史的请求日期撑长观察期；保守记录已核验历史边界，并把未证实部分标为未知。默认调用仍可省略独立观察终点，但只能声明实际观察范围。

仅把 `until` 往前移动仍会同时截断修复观察，因此不能解决右侧观察不足。

### 2. 用受哈希保护的版本元数据保存准入语义

CSV 的特征和二元标签列保持兼容。新 manifest 声明观察与准入协议，例如 `mature-observed-v1`，并通过按提交索引的状态旁车保存证据状态、成熟度与排除原因；旁车使用相对路径、文件哈希和内容身份。加载时从原始时间与观察声明重算，核对旁车，不仅信任一个 `mature` 布尔值。

数据版本语义身份纳入观察窗口、成熟期、标签规则、准入协议及状态内容。仅 CSV 一致不足以复用新协议版本；采集时刻等非语义元信息仍不制造重复版本。不把成熟状态加入模型特征，避免模型学习到标签生成信息。

### 3. 在切分前统一选择成熟样本

UTC 秒级判断 `observedThrough - commitEpoch >= maturityDays * 86400`；默认成熟期为 90 天，实际边界完整记录。正例和零标签采用同一时间准入规则，避免只提前纳入已发现问题的近期提交。所有训练与正式评价入口使用一个共享的准入过程，再按原有时间组预设切分；同步 holdout 等现有限制与准入集合取交集。

保存原始数、合格数、按原因排除数、合格成员哈希、各分区成员哈希及准入身份。采样和类别策略仍只在训练分区执行。被排除样本可以继续被已选兼容模型评分，不把评分集合等同于训练集合。

观察未知或 SZZ 截断版本不得产生完整可信评价。诊断可显式读取并标明受限；不足两类或时间组不足时返回原因，不补样本。自动分析的训练失败或回退遵循现有显式绑定模型规则，不能为了凑训练量扩大准入集合。

### 4. 旧协议兼容与外部交接

旧运行加载、参考预测与成员核验继续走其保存的原协议，不能因公共解析器升级改变历史指标。旧 SZZ 数据缺少观察事实时，新训练默认拒绝并给出重建路径；只有显式历史兼容参数可按旧规则复现，产物标为历史协议。发布者数据沿用其声明规则，不套用不存在的 SZZ 观察期。

数据详情、切分预览、权威 ZIP 与用户范围下载共用同一安全投影。需要持久化新字段时使用前向迁移；无需数据库字段时优先通过 manifest 与已有引用传递。不得将任意文件路径暴露给普通用户。

### 5. 有限真实重建与人工复核

先用确定性 Git 历史验证截止后修复、成熟边界、无修复、截断、重命名及重复登记。真实复建固定 flask 与 axios 两个现有仓库、revision 和预算；它们覆盖 Python 与 JS，避免一开始重采六仓库。每仓库最长 2 小时，超限记录受限状态，不无限追加预算。重建失败的仓库保留失败记录，不按结果替换。

从固定版本事先按时间分层抽取每仓库 10 条证据，保留修复、引入、路径、行号和判定依据。agent 可做对象及路径核验；需要人工判断的案例保持待复核，不伪造金标准。新数据、执行和复核记录写入本次独立证据位置，并作为下一 change 的交接清单。

## Risks / Trade-offs

- [成熟筛选后样本和正例减少] → 如实显示不足，保留评分能力与原协议，不缩短成熟期。
- [观察修复需要更长历史与运行时间] → 固定 revision、离线缓存和执行预算，保留中断及截断事实。
- [旧产物加载被公共解析改动影响] → 显式区分新准入与历史回放，验证现有模型包及参考预测。
- [版本只比较 CSV 而误复用语义不同数据] → 版本、幂等键和运行身份共同覆盖观察及准入内容。

## Migration Plan

1. 若需数据库升级，先对一致性副本验证前向迁移及升级前备份；正式开发库只在明确实施升级时操作。
2. 引入新协议的增量读取与写入，旧文件和引用保持原样。新建任务记录明确协议；旧任务按保存协议恢复。
3. 在隔离数据根目录重建两个固定仓库，校验状态、计数、导出重载及训练成员一致后交接。
4. 回退时停用本次新建任务入口，使用兼容读取旧协议的版本；不以旧代码直接打开已升级数据库，不删除新旧数据或覆盖模型产物。
