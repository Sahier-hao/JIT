# Proposal

## Why

课程项目要求原文点名的前端能力是"可视化前端（风险列表、**缺陷引入趋势看板**等）"，产品需求文档的 US-21 也写明趋势视图应展示"时间桶的样本数、观测正标签比例、风险分布、范围与时区"。现状是：前端只有静态的提交列表与详情，**没有任何随时间变化的视图**；后端 7 个端点里**没有任何聚合**。

这不是"少一个页面"那么简单，而是有一条结构性障碍：前端契约硬禁止逐条标签进入记录（`frontend/src/historicalContract.ts` 对每条记录断言不得出现 `label`／`title`／`explanation`），所以趋势图**无法由前端从现有数据推导**。同时，`summary.split[*].positiveCount` 已经证明"按分区聚合的观测标签"本来就是既有响应的一部分——趋势只是把聚合粒度从 3 个分区细化到按月的时间桶，性质相同。

反过来看价值：现有基线只能看到一个 1,853 条的静态批次，评审员与质量维护者看不到"观测与风险随时间如何变化"；答辩也缺一张能讲全局的图。而已纳入的 12,374 条记录横跨 2011-11 至 2014-02，这段观测趋势的成本几乎为零——解析阶段本来就为全部记录算好了标签。

## What Changes

- **离线聚合**：`run` 在写产物时按**月**聚合全部纳入记录，得到每个时间桶的样本数与观测正标签数；测试区间内额外汇总模型风险分布（中位数与高分位）。聚合值写入 `summary` 的**可选键**，逐条标签仍只留在产物目录，服务继续不读 `test-labels.json`。
- **最小样本规则**：桶内提交数低于阈值时，该桶的正标签比例以空值加原因表示，MUST NOT 呈现为 0%，避免稀疏桶把图读成"缺陷率极低"。
- **校验**：`verify` 增加按桶重算并与产物比对，与既有 `reference-predictions`／`metrics` 的重算同构。
- **服务**：新增启动时选择所供给运行目录的开关（默认仍是既有固定运行），使重跑出的新运行可以被供给；不改任何既有响应字段与语义，不新增端点。
- **前端**：新增独立的 `#/trends` 趋势视图，复用免凭据的 `/api/review-batch`；图表手绘 SVG 并配**同数据的数据表**；观测比例与模型估计必须分开标注。运行缺少聚合键时如实显示"未提供"，不报错、不回退、不影响其余视图。
- **明确不做**：不新增 HTTP 端点，不新增产物文件，不改既有响应字段的含义，不引入图表库或外部字体／图标资产，不改变 `records` 不含标签的既有约束。

## Capabilities

### New Capabilities

- `defect-trend-dashboard`: 历史观测与模型估计随时间的只读趋势视图——入口可达性与独立加载、聚合缺失时的如实呈现、观测与估计的分离、时间桶与样本不足规则、图表的等价文本视图与键盘／视口要求。

### Modified Capabilities

- `public-data-baseline`: 运行记录增加可选的时间桶观测聚合（含最小样本规则与不含逐条标签的约束），并新增服务所供给运行目录的选择；既有运行按自身声明继续可用。

## Impact

- **后端**：`backend/jit_baseline/artifacts.py`（`run` 写入聚合、`verify` 重算比对）、`backend/jit_baseline/api.py`（所供给运行目录的选择）；预计新增 `backend/jit_baseline/trends.py` 承载分桶逻辑。因训练代码指纹进入运行身份，**新运行的 `runId` 会变化**；既有运行仍按自身声明通过校验，归档证据不受影响。
- **前端**：新增趋势视图与契约解析（`TrendPage.tsx`、`trendContract.ts`，以及 `App.tsx`／`AppShell.tsx`／`navigation.ts` 的入口与路由），相应样式；既有取数、校验、清单与凭据逻辑不变。
- **数据与依赖**：不新增运行时依赖；数据文件本机已就绪，重跑 `run` 不需要网络。
- **产品文档**：随本 change 同步 `docs/产品需求文档.md`（US-21 的实现状态与验收说明）与 `docs/产品设计文档.md`（趋势视图与聚合契约的说明），保持"归档后规格与产品一致"。
- **验收影响**：`npm run typecheck`、`npm test` 与既有浏览器检查（两个视口、仅键盘、无障碍）必须继续通过；趋势视图需要新的截图与无障碍证据，写入运行工作区 `docs/evidence/_run/` 并按既有冻结流程归档。
