## Context

PR 3 已提供模型策略、候选登记、数据集摘要、训练任务 API 和模型目录；PR 4 需要把这些后端事实组织成可用的管理体验。当前前端 `AdminWorkspace.tsx` 同时承担认证、导航、模型、数据和动作逻辑，无法容纳详情与比较页面。

## Goals / Non-Goals

**Goals:**

- 将管理前端拆分为独立外壳和页面组件。
- 将训练任务、数据集版本、模型指标和比较变成可达、可刷新、可恢复的页面。
- 提供一个可重复的大型仓库 E2E，而不是依赖网络上的当前 HEAD。
- 让管理员从数据集直接创建训练任务，并查看成功、失败、取消和重试。

**Non-Goals:**

- 不改变训练任务或项目分析的后端权限与状态机。
- 不自动按指标推荐、排序或设置默认模型。
- 不在 E2E 中下载真实大型开源仓库；使用超过自动训练门槛的确定性本地仓库夹具。
- 不新增图表库或复杂可视化依赖。

## Decisions

### D1. 管理入口使用带资源的稳定 hash 路由

模型页、数据集页、任务页和比较页分别使用 `#/admin/models`、`#/admin/datasets`、`#/admin/training`、`#/admin/comparisons`。模型、数据集版本和任务详情使用路径参数；比较使用 `models` 查询参数。刷新与书签不会丢失当前资源。

### D2. AdminWorkspace 只保留认证和页面分发

拆出 `AdminModelsPage`、`AdminDatasetsPage`、`AdminTrainingPage`、`AdminModelDetailPage`、`AdminDatasetDetailPage` 和 `AdminComparisonPage`。共享 API 解析和展示控件独立放置，避免页面之间复制契约。

### D3. 模型详情读取现有运行摘要

新增管理员模型详情 API，在 `ModelCatalog.load_model` 已完成完整性校验后读取首选位置的 `summary.json`，返回指标、训练耗时、数据版本和运行谱系。评测指标来自模型自身训练数据，页面明确标注，不冒充当前项目在线效果。

### D4. 训练任务页面使用服务端事实和有限轮询

活动任务每 3 秒刷新；全部终态后停止。取消/重试调用现有 API。详情只在成功时展示指标和谱系，失败、取消和中断只显示原因与阶段。

### D5. E2E 使用超过门槛的确定性大型仓库夹具

夹具生成约 260 个提交、跨一年，保证最新 90 天 holdout 之外仍超过 200 条训练记录、20 个训练正例和至少 3 个测试正例。测试在隔离目录库内完成现成模型、自动训练、强制训练，并打开模型详情核对指标；不依赖 GitHub 网络或当前设备已有业务数据。

## Risks / Trade-offs

- [大型夹具增加 E2E 时间] → 仅创建小文件，单浏览器项目运行；其他响应式与策略 E2E 继续覆盖两种视口。
- [模型指标来自训练数据而非当前项目] → 模型详情明确标注数据版本与指标来源，项目结果只把模型作为打分来源。
- [多个详情页导致前端文件增加] → 按页面和共享契约拆分，避免单文件继续膨胀。
- [活动任务轮询频率过高] → 3 秒间隔且终态停止，使用 AbortController 清理。

## Migration Plan

前端为增量路由和页面拆分；模型详情 API 为只读增量。无数据库迁移，回滚前端和 API 不影响既有训练任务与项目记录。
