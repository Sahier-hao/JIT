# Design

## Context

动机与范围见 [proposal.md](proposal.md)，可验收行为见 [页面规格](specs/model-prediction-workbench/spec.md)。本变更涉及应用导航、受保护请求、输入及结果契约、浏览器测试和运行配置，存在权限与异步状态复杂性，因此需要设计文档。

已核对的实现依据：

- `frontend/src/App.tsx` 将 Sidebar 和 Workbench 放在同一模块，主视图依赖 `useDataset`；历史批次不可用时没有独立业务页面。当前使用 React 19、TypeScript 和 Vite，没有路由库。
- `domain.ts` 的 Dataset／Commit 及 `historicalContract.ts` 只表达历史与演示，记录强制要求提交时间；新接口允许缺失真实 SHA 和提交时间，不能直接套用既有解析器。
- `backend/jit_baseline/api.py` 已提供本变更所需六个路径。`catalog.py` 返回实际登记版本和候选；候选包含 `candidateId`、`displayName`、`manifestSha256`、状态和已解析方法／schema。登记响应区分 `created`；模型的 `state` 和 `jsonPredictionSupported` 是两个独立条件。
- `catalog_input.py` 严格要求单条原始六字段，`prediction.py` 原子保存后返回结果，按 batchId 查询直接读取保存快照，不要求重新加载模型。现有服务没有全量预测列表或角色查询接口。
- `team_access.py` 以两类服务端凭据鉴权，原历史 GET 无鉴权；本变更复用该边界，不引入个人账号与登录会话。
- `vite.config.ts` 当前代理固定指向 8000；`playwright.config.ts` 固定使用 4173、8000 并可能复用已有后端。新写接口验收必须使用独立库、产物副本及自有进程，不能沿用这种复用方式。

## Goals / Non-Goals

**Goals:**

- 在历史数据加载外建立应用级导航与内存凭据状态，新页面独立请求所需资源。
- 让创建请求、目录模型和保存结果分别有契约、来源与生命周期，避免历史字段约束或迟到响应污染。
- 通过现有后端实现真实闭环，测试准备和产品运行配置明确分开。

**Non-Goals:**

- 不改六个既有 API 的业务语义、认证机制或数据库结构，不把前端角色选择作为权限来源。
- 不将新结果强转为历史 Dataset，不向历史个人清单加入新预测，也不创建没有服务支持的全量历史页面。
- 不调整训练、阈值、特征定义或试验口径；完整产品范围之外的能力见 proposal。

## Decisions

### D1. 应用壳承载导航，原工作台保持自己的状态语义

将 Sidebar 与主导航提升为可复用的应用壳，历史／演示 Workbench 保留原查询、详情和清单逻辑。顶层管理页面选择及凭据，模型、预测和结果各自有资源状态；新页面不挂在历史 `ready` 分支内。

采用轻量 hash 导航：保留无 hash 的既有首页与 `?mode=demo`；新页面使用 `#/models`、`#/predict`、`#/predictions`（按编号打开）和 `#/predictions/{batchId}`。浏览器前进、后退和刷新解析同一地址。结果链接保留应用 origin／path，移除演示查询串，只带 hash 中批次身份，不含凭据或输入。历史／演示模式切换时回到对应旧入口，不留下误导的结果路由。未知路由给出返回入口。

选择 hash 是因为当前 dev／preview 不需要额外部署回退规则且没有路由依赖；完整路由库或重构旧工作台业务状态没有本轮收益。导航离开未完成表单会丢弃草稿，换模型时保留已填字段并重新校验；结果通过链接恢复，历史清单仍按既有 key 恢复。

### D2. 凭据只存应用内存，权限由实际响应确认

提供“团队访问凭据”的掩码输入、确认使用和清除操作，说明刷新后需重新输入。所有新 API 请求通过一个请求层附加 Authorization，旧历史 GET 不附加。不得使用 `VITE_*` 或其他构建常量注入真实凭据，不存 localStorage、sessionStorage、URL、错误对象、下载或日志。

模型中心与新建预测通过查询模型目录确认当前凭据可使用成员能力；结果页直接查询目标批次确认访问，不以目录可用为条件。模型中心有“管理登记”入口，用户主动打开时才查询候选；查询成功后显示管理员功能，403 显示权限提示并保留成员流程。界面不声称识别了具体个人，也无需为前端新增角色探测接口。更换或清除凭据时递增请求上下文代次、清除受保护缓存／结果和表单，丢弃旧响应，保留目标结果路由以便重新授权后重开；表单中已确认凭据不再可见。

替代方案是长期保存 token 或新增 cookie 会话服务，都会扩大当前认证与部署范围，故本轮不采用。该取舍意味着刷新可重开结果，但需重新输入由维护者提供的团队凭据。

### D3. 独立请求层和契约校验，不改历史解析协议

建议新增 `frontend/src/catalogContract.ts`、`catalogApi.ts`、`predictionContract.ts` 及凭据／请求状态模块，文件名可随既有风格微调。

| 页面动作 | 现有请求 | 关键处理 |
|---|---|---|
| 已登记模型 | GET `/api/v1/models` | 显示实际版本、空目录、不可用原因与支持状态，不对测试效果排序选优 |
| 管理员候选 | GET `/api/v1/model-candidates` | 只在明确进入管理员功能后读取，显示候选而非可用模型 |
| 校验登记 | POST `/api/v1/models/register` | 仅提交所选 candidateId 与其 manifestSha256，201／200 分别为新增／复用 |
| 输入说明 | GET `/api/v1/feature-schemas/{version}` | 与所选模型 schema 对齐，使用原始数值、如实列出缺失字段 |
| 创建单条预测 | POST `/api/v1/predictions` | 只提交所选 modelId、六字段、项目及记录元数据 |
| 结果重开 | GET `/api/v1/prediction-batches/{batchId}` | 只读保存结果，不先查询目录或加载当前模型 |

请求层统一解析服务端 code、message、details 和 requestId，提供页面可用的结构化错误，拒绝格式不合法的成功正文。所有查询可显式重试，两个 POST 均不自动重发。创建与登记操作分别维护在途标记，连续点击只触发一次；来源快照在提交瞬间固定，不能按响应时表单内容解释结果。

返回结果的契约至少检查：`mode=feature-input`、`sourceKind=client-features`、合法 UUID／hash、schema、恰一条记录、有限 [0,1] 风险、合法原始特征、可空元数据、创建时刻和解释未支持状态；模型内 schema／原产物身份须自洽。创建响应还核对所提交 modelId、项目、记录身份及六项值，允许服务端既有 trim／UTC 规范化。重开响应核对路由 batchId，不要求与当前目录模型匹配。复用风险数字格式化与图标，但不复用要求历史时间／标签指标的整套数据解析器。

### D4. 模型目录与候选登记分区显示

模型中心首先展示已登记目录。每个版本有名称、方法、schema、状态和预测支持说明，完整业务身份、原产物身份、hash、环境来源与局限放入可展开详情。无模型时引导管理员进入登记或联系维护者，不自动登记本机 baseline。

候选区仅显示后端允许的相对展示名称与已解析信息，不提供路径输入或上传控件。`invalid` 候选禁用登记并显示原因。管理员显式点击“校验并登记”，等待服务完成完整 verify；成功刷新目录并指出对应模型，失败保留诊断。409 必须刷新并重新选择，不能把刷新到的新 hash 自动带回 POST。同一候选的在途按钮禁用；已有身份复用不制造另一张模型卡。

### D5. 六字段表单与特征 JSON 是同一输入草稿

表单收集项目、记录编号，五项非负计数 ns／nd／nf／la／ld 和有限非负 ent；SHA、带时区 ISO 时间为可选。字段说明来自既有 schema，中文辅助文字不扩大未核验的字段物理含义。空字符串保持空白，显式校验后才转数值；计数需为 JavaScript safe integer，超界明确提示，不能在发送前悄悄舍入。后台仍是最终校验者。

粘贴框仅接受特征对象，例如六项键值，不接受包含 modelId／record 等完整请求包装。导入完全合法后才原子填表，不更改项目、记录元数据或模型。校验同时拒绝重复键，不能仅用会吞掉重复键的 JSON.parse 结果判断；实现一个仅服务该六数字对象的小范围严格解析／重复键检测路径，并用嵌套对象、转义等负例验证，不引入宽泛请求转换器。导入失败保留原草稿。该范围是本轮的具体交互默认，不是 CSV 或通用数据导入。

提交按钮只有在模型 ready、jsonPredictionSupported=true、schema 为 openstack-six-v1 且表单有效时可用。选择不支持模型时展示原因并保留草稿，不自动补全字段或换用模型。

### D6. 保存成功与无法确认保存分别呈现

成功 201 且契约核对通过后进入结果链接，页面使用保存快照呈现。提交时冻结输入并显示处理中；期间字段／模型编辑禁用，应用导航和清除凭据仍可用。离开后忽略旧响应，不能声称取消了服务端写入。

422 定位字段；模型缺失／失效提供重新查看模型入口；503 存储失败不展示本次风险。请求发出后连接中断或超时，或者 201 响应正文损坏时，只能提示“未能确认保存结果”：服务端可能已经提交，不能自动重试或断言没有结果。用户明确再次提交前说明可能创建另一批次。客户端重复点击保护不提供后端幂等保证，后端重复 POST 的独立批次语义保持不变。

### D7. 结果重开不依赖模型现在是否可用

结果页先展示记录／风险、原始特征及“用户提供特征 · 模型估计”，随后展示可展开完整来源与局限。提交时间和创建时间分开，无真实 SHA／时间则明确未提供，不展示历史测试集指标，不提供伪解释。

用户可复制结果链接或在“打开已有结果”输入 batchId。UUID 校验通过后只发 GET；重开不触发模型目录、schema 或当前模型健康查询，因此模型被删除或目录查询失败时过去的合法结果仍能查看。刷新后重新输入凭据，再读取同一链接。复制不可用时保留可手动复制的链接，链接不承诺绕过认证或跨主机可达。

未增加结果列表服务，因此本轮没有“所有历史预测”页，也不把浏览器缓存当成共享数据库历史。

### D8. 验证使用独立服务和真实模型副本

Vitest 覆盖契约、输入、认证清除、错误映射、请求竞争和重复操作保护。Playwright 沿用现有 Edge 两尺寸矩阵；可控响应测试覆盖坏正文、401／403、409、422、503、断线与迟到响应，同时增加独立真实服务的完整链路。

真实链路的准备脚本仿照 `backend/scripts/catalog_system_evidence.py`：复制现有已校验模型到独立临时产物根、显式初始化独立 SQLite、生成仅用于该次测试的内存凭据，通过 `create_app(directory=副本, database=临时库, artifact_root=临时根)` 启动自有本机服务，禁止复用开发者既有库或后台。测试校验登记、成员预测、相同链接刷新，以及停止／重启自有服务后重开；破坏或移走的也仅是产物副本。

为避开当前预览，测试参数化前端端口与 `/api` 代理目标，默认仍保持 4173／8000。代理目标从 Vite 进程环境读取，仅为本机测试地址，不把凭据打进前端包；独立测试入口使用严格端口及自己启动的进程，不停止或占用已有服务。旧浏览器套件也可在独立环境回归，保留原默认启动方式。

受保护请求测试关闭会记录 Authorization／输入值的浏览器 trace、HAR 或自动请求正文转储，证据只保留脱敏业务结果与截图。输出进入 `docs/evidence/_run/`，测试不写任何历史归档。严格 OpenSpec 校验属于规划验收；实现验收另跑前端类型／单元／构建、后端相关回归、两尺寸浏览器和真实服务重启链路。冻结与归档仍是后续显式操作，不在测试或启动中自动执行。

## Risks / Trade-offs

- [刷新后丢失凭据] 通过清楚说明和保留结果链接恢复操作；不引入长期保存秘密的机制。
- [没有角色查询接口] 成员查询确认通用访问，管理员候选操作由既有 403／成功响应确定权限，不缓存自报角色。
- [模型列表会核对真实文件，登记会完整校验] 显示等待和刷新入口，不逐键查询、不预加载多份模型，不用人工风险填充加载期。
- [请求断开但服务端已写入] 不自动重试 POST，显示保存状态未知；恢复批次仅使用已知身份，不承诺 exactly-once。
- [异步响应跨凭据／批次污染] 以资源身份、凭据代次和操作代次验证响应，GET 可中止，POST 的中止仅影响客户端等待。
- [JSON 解析吞掉重复键或数值丢失精度] 严格导入检测、原子填表及 safe integer 边界测试，失败保留草稿。
- [测试进程复用污染真实库／凭据泄漏到 trace] 独立端口／库／副本、只清理自己拥有的资源，禁用敏感跟踪和脱敏证据。

## Migration Plan

1. 实现时先建立请求与契约测试，再加入应用壳、新页面及隔离验收入口；不修改现有数据库版本。
2. 维护者按既有说明确认目录库已初始化、两类独立凭据已配置、模型产物存在；HTTP 启动仍不自动建库，进入页面也不自动登记模型。凭据通过主机环境配置，不写进文档示例值、命令参数或仓库。
3. 启动同样仅监听本机的前后端，管理员通过页面完成第一次登记，成员使用有效凭据预测并保留结果链接；README 给出可复制的普通启动步骤与不泄密的配置说明。
4. 回滚前端入口即可退回旧历史工作台；保留数据库、运行产物与已有结果。不删除成功预测、不重训或覆盖模型来回滚。

## Open Questions

无阻塞问题。页面命名与文案细节可在实现中沿用现有样式；表单优先、六字段 JSON 导入、凭据仅内存、hash 结果链接与不增加全量历史列表均按本设计执行。
