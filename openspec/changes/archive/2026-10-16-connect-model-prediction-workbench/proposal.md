# Proposal

## Why

已有后端支持模型候选发现与登记、模型目录、六字段单条预测及结果重开，但现有 React 页面只展示历史回放与人工演示，成员仍需手工调用接口。把这些能力接到同一工作台，让管理员和成员能通过页面完成从模型准备到预测结果重开的完整流程。

## What Changes

- 在现有工作台加入模型中心、新建预测和预测结果入口，沿用现有桌面布局与中文交互。
- 提供当前页面会话内的团队凭据输入与清除；后端继续以现有 Bearer 凭据判定权限，管理员可发现候选并显式校验登记，成员可查看模型及预测。
- 模型中心区分候选、已登记可用、不可用和不支持当前预测的模型，展示来源与原因；登记成功后刷新目录，不自动登记或按测试指标选优。
- 新建预测采用六字段表单，支持粘贴原始特征 JSON 填表；选择可用且支持预测的模型，校验输入后显式提交。
- 成功结果展示风险、输入及不可变来源，提供不含凭据的结果链接和按批次编号重开入口；重开只读保存结果。
- 加入加载、空目录、权限、字段、模型、存储及网络失败反馈，避免重复提交；在两种既有桌面尺寸下完成浏览器验收。
- 保留历史回放、演示、个人清单和原 API 契约。本轮不增加全量预测历史列表、CSV/批量输入、模型文件上传、训练、自动 Git 特征提取、真实解释或局域网部署。

## Capabilities

### New Capabilities

- `model-prediction-workbench`: 浏览器中的受权模型准备、模型选择、单条特征预测与结果重开流程，含导航、来源、错误和桌面可操作性。

### Modified Capabilities

无。复用 `model-catalog`、`feature-input-prediction`、`team-api-access` 的既有服务语义，既有 `commit-risk-review` 行为继续成立；新增页面要求由上述新能力承载。

## Impact

- 前端：调整 `frontend/src/App.tsx` 的应用壳与导航，新增独立的模型／预测契约、请求层、凭据状态及页面组件；保留原 `domain.ts`、历史契约和清单的上下文语义。
- 接口：复用六个现有 `/api/v1` 路径，包括候选、登记、模型、schema、创建预测和按编号重开结果；通过现有 Vite `/api` 代理访问，不新增业务接口或数据库迁移。
- 测试：扩展 Vitest 与 Playwright；以独立 SQLite 库和真实模型副本完成端到端登记、预测、服务重启及结果重开，避免写入开发者既有目录库或历史归档证据。
- 文档：实现时同步根目录／前后端 README、产品需求、产品设计、测试计划及错误码说明，保留既有文档结构，区分已实现与目标能力。
- 依赖：沿用 React、TypeScript、Vite、FastAPI 与 SQLite；不预设新增路由库、身份服务或外部模型服务。
