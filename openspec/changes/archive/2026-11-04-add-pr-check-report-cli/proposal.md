# Proposal

## Why

当前 PR 分析结果只能在网页工作台查看。开发者要在提交或 CI 阶段使用固定快照、模型身份和覆盖范围，必须手工打开页面并复制内容；而直接把风险分数做成合并门禁，又会把未经当前仓库验证的估计当作缺陷结论。需要一个离线、可追溯、默认非阻断的检查报告，让已有分析进入开发流程。

## What Changes

- 新增 `pr-check export`：从本机目录库的固定快照和分析导出可移植的分析包，包含身份、逐提交分数和可用候选位置，不含个人草稿。
- 新增 `pr-check report`：读取分析包或本机目录库，输出 JSON 或 Markdown 报告。
- 报告包含仓库、PR、基准与目标 SHA、模型与运行身份、评分覆盖、逐提交分数、可用时的代码候选位置和限制说明。
- 报告读取已保存分数，不要求模型当前可加载；身份缺失或不匹配时明确失败，不替换模型、不补造分数。
- 默认非阻断，退出码区分成功、分析缺失、身份不匹配和输入无效；不输出合并或通过结论。
- 默认不包含个人草稿、笔记和反馈；只有显式选择时才导出指定字段。
- 提供一个 GitHub Actions 示例，在已导出的离线分析包上运行；托管 CI 直连本机后端不在本变更范围。

## Capabilities

### New Capabilities

- `pr-check-report`: 固定快照的离线分析包导出、检查报告、身份与覆盖校验、退出码和个人数据边界。

### Modified Capabilities

无。

## Impact

- 新增命令行入口、分析包格式与报告序列化，读取现有 PR 快照、分析和候选位置。
- 不改变网页工作台、个人草稿和模型选择行为。
- 新增示例工作流和报告格式文档；不上传个人数据，不自动评论或合并。
