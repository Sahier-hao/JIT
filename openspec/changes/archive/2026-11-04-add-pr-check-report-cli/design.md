# Design

## Context

PR 快照、分析、分数和候选位置已保存在目录库中，但没有离线导出或报告入口；网页工作台不提供 CI 可直接消费的固定格式。个人草稿保存在浏览器，不在服务端。模型文件可能后来被移除，但已保存的分数和身份仍应可读。参见 proposal.md。

## Goals / Non-Goals

**Goals:**

- 从固定分析导出可移植分析包。
- 从分析包或本机目录库生成可追溯报告。
- 身份、覆盖和缺失信息如实呈现。
- 默认非阻断、无网络、无个人数据。

**Non-Goals:**

- 不实现托管 CI 直连后端、自动评论或合并门禁。
- 不重新推理、不训练、不选择模型。
- 不导出个人草稿，除非调用方显式选择。

## Decisions

**两个命令。** `pr-check export` 只读打开本机目录库，按快照与分析身份生成 `jit-pr-check-bundle-v1` 分析包；`pr-check report` 读取分析包或本机目录库，生成 `jit-pr-check-v1` 报告。导出和报告走同一身份校验与序列化路径，保证同一分析在两台机器上得到一致内容。

**分析包是 CI 的输入。** 包内包含快照身份、分析身份、模型与运行身份、逐提交分数、可用候选位置和覆盖说明，不含个人数据；记录格式版本和内容哈希。分析包是构建产物，不提交到源码仓库，示例工作流说明如何在上一步生成并传递。

**报告读取已保存分数。** 报告不加载模型、不重新推理；模型文件后来被移除或停用不影响已保存报告。身份缺失或不匹配时失败，不替换模型或改用最新分析。

**退出码。** 0 表示报告生成成功；2 表示分析缺失、未成功或覆盖不完整到无法形成报告；3 表示身份不匹配；4 表示输入无效或存储不可读。报告内容本身不输出通过、安全或可合并结论。

**个人数据默认剔除。** 导出和报告默认不读取个人草稿；个人草稿只存在浏览器，服务端没有对象。若调用方显式选择个人字段，报告记录实际包含字段，并仍然只写本地文件。

**CI 示例离线运行。** 示例工作流先执行导出，再执行报告，上传报告为构建产物，不设置必需检查、不评论 PR、不访问本机服务。托管 CI 的部署与认证另行设计。

## Risks / Trade-offs

- [分析包可能过期] → 包内记录快照、分析身份和生成时间，示例说明需与分析同步更新。
- [逐提交列表过大] → 设置上限并记录总数与截断原因，不静默丢弃。
- [本机目录库读取权限] → 只读打开，失败返回输入或存储错误，不尝试写入。
- [个人数据误导出] → 默认剔除并在报告中声明；显式选择才保留指定字段。

## Migration Plan

1. 新增命令、分析包和报告格式，不修改数据库结构。
2. 既有分析和快照可直接读取；缺失字段显示原因。
3. 新增示例工作流和文档，不影响现有网页流程。
4. 回滚时移除命令和示例；已生成的报告文件保留。
