# 项目详情页改为双栏工作台

## Why

项目详情页在宽屏下是一条通栏竖列：页头、仓库更新、发起分析、当前分析结果、分析记录依次铺满整行。1873px 视口下每张卡片被拉到约 1734px，同一行左右两端的信息因此隔了一千多像素——「仓库更新未完成」在左，三项统计在右，中间是空的。页面读起来松散，但字号与间距本身并没有问题，问题在于这一列没有宽度上限，也不区分主次。

三块内容的主次其实不同：当前分析结果与分析记录是用户反复回看的内容；仓库更新是背景状态；发起分析是偶发动作。把它们排成等宽的五行，等于让背景信息占用和主内容一样宽的位置。

## What Changes

- **宽屏改为双栏**：视口 ≥1400px 时，页头仍通栏，下面分左右两栏——主栏（1fr）放「当前分析结果」与「分析记录」，窄栏（360px）放「仓库更新」与「发起分析」。
- **窄栏内容纵向堆叠**：仓库更新的状态带在窄栏里改为「图标 + 文本」两行，三项统计由三列改成三行（标签左、值右）；发起分析的参数摘要换行到标题下方，表单字段单列，底部动作条改为「提示在上、按钮在下整宽」。
- **窄栏随滚动吸附**：≥1400px 时窄栏 `position: sticky`，浏览长记录列表时更新状态与发起入口保持可见。
- **窄屏保持单列**：视口 <1400px 时回到单列，顺序仍是「仓库更新 → 发起分析 → 当前分析结果 → 分析记录」，与改动前一致。
- **主栏去掉底部外边距**：分析记录成为主栏最后一块，页面底部不再多出一段空白。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `interface-presentation`：新增「项目详情页的双栏工作台」要求，规定宽屏分栏、窄栏堆叠、吸附与窄屏回退的行为。

## Impact

- 前端源文件：`frontend/src/pages/ProjectPage.tsx`（页头之后包出 `.project-layout`，`.project-rail` 放仓库更新与发起分析，`.project-main` 放结果与记录）。
- 样式：`frontend/src/styles/product.css` 新增 `.project-layout`、`.project-rail`、`.project-main` 与两条 `min-width: 1400px` 的媒体查询。
- 接口与数据不变：`/api/v1/repositories/{id}`、分析记录分页、更新设置与发起分析契约都没有改动。
- 测试：`ProjectPage.test.tsx` 依赖的标题、按钮与 `aria-expanded` 结构保持原样；全量 `vitest` 与 `build` 通过。
- 风险：1400px 是本页的分栏阈值，1280–1399px 仍是单列，用户在临界宽度缩放窗口时会看到一次重排。
