# 设计：项目详情页改为双栏工作台

## Context

项目详情页把五块内容排成一条通栏竖列。容器宽度来自 `.workspace-main` 的内边距与视口，没有上限，因此宽屏下每块都接近 1700px。上一轮已经把三块的标题、卡片边界与按钮权重统一（IP-17），但「等宽堆叠」这个结构问题没有解决：主内容与背景信息占用同样的宽度，行内两端的信息被拉得很远。

现有约束：

- `ProjectPage.tsx` 的 `#analysis-form-section` 被「用这些参数重试」通过 `scrollIntoView` 定位，容器结构可以变，id 必须保留。
- `ProjectPage.test.tsx` 依赖 `demo-project` 标题、`当前分析结果` 标题、`打开审查`、`全部项目`、`分析选项` 的 `aria-expanded`、`分支` 输入框、`开始分析` 与 `分析模型` 下拉。
- 仓库更新与分析表单都是自包含组件，只依赖父级宽度，没有固定宽度假设。

## Goals / Non-Goals

**Goals**

- 宽屏下让主内容与状态/动作分离，主栏承担结果与记录，窄栏承担背景状态与偶发动作。
- 每个区块回到自然宽度，行内不再出现一千像素以上的空档。
- 窄屏保持现有阅读顺序，不引入第二套移动端结构。

**Non-Goals**

- 不改动任何接口、分页逻辑与确认流程。
- 不为分析记录引入新的列表形式（仍是卡片行）。
- 不在本次引入页签或折叠式信息架构。

## Decisions

**1. 用 CSS Grid 的两栏，而不是把页面拆成两个组件树。**
DOM 顺序保持「仓库更新 → 发起分析 → 当前分析结果 → 分析记录」，窄屏天然就是现在的顺序；宽屏用 `grid-column` / `grid-row` 把 `.project-rail` 放到第二列、`.project-main` 放到第一列。这样不需要复制结构，也不需要为移动端写第二套标记。

**2. 分栏阈值取 1400px。**
按现有侧栏 236px 与主区内边距 80px 计算：1440px 下主栏约 724px、窄栏 360px；1280px 下主栏只有 564px，分析记录的操作按钮会挤成两行。因此 1280–1399px 保持单列，1400px 起分栏。

**3. 窄栏固定 360px。**
日期（`2026-10-28 23:01`）与「每 5 分钟」这类值在 320px 以下会折行；360px 能容纳状态带的两行结构与三行统计。

**4. 窄栏内的仓库更新改成纵向堆叠，而不是缩小字号。**
状态带在三列网格里会被压成每行一两个字（首轮实现确实出现过）。窄栏改用「图标 + 文本」两列，统计三项各占一行、标签左值右，字号不变。发起分析的参数摘要换到标题下方整行，表单字段单列，底部按钮整宽。

**5. 窄栏 sticky 吸附。**
分析记录可能很长，滚动时更新状态与「开始分析」应当保持可见。吸附只在 ≥1400px 生效，避免窄屏下遮住内容。

**6. 主栏最后一块去掉底部外边距。**
`.project-records` 在单列时保留 36px 间距，进入主栏后改为 0，页面底部不再多出空白。

## Risks / Trade-offs

- **临界宽度重排**：1400px 前后会从双栏跳到单列，缩放窗口时能看到一次明显重排。可接受，因为两档都可用，且 1400px 上下都不是常见停留宽度。
- **窄栏信息密度上升**：360px 里要塞下状态带、开关、设置入口与分析入口，垂直方向会比原来长。缓解方式是统计改为紧凑三行、摘要换行而不截断。
- **sticky 与长内容的相互作用**：窄栏比主栏短时吸附有效；若窄栏展开「更新设置」后比视口还高，吸附会把底部内容顶出可视区。当前展开态高度约 600px，仍小于常见视口，暂不处理。

## Migration Plan

纯前端结构重组，无数据迁移。回退方式是还原 `ProjectPage.tsx` 的容器与 `product.css` 的网格规则。
