# 设计与取舍

## Context

记录卡承担两件事：告诉用户「这个仓库分析过几次、现在看的是哪一次」，以及提供切换到另一次分析的入口。前一版把「当前」表达成单选圆点、把切换藏在菜单里，语义与成本都不对。

## Goals / Non-Goals

**Goals**：当前状态一眼可辨；切换当前结果一步完成；时间线在视觉上连续但不清空卡片；卡片高度稳定。

**Non-Goals**：不做拖拽排序，不做多选批量删除。

## Decisions

- **图钉而不是单选圆点**：图钉表达「钉住这一份结果」，与「选中一项表单值」区分开；`aria` 仍由隐藏 radio 提供，读屏语义不变。
- **整行可点击**：切换是记录行最常见的动作，藏进菜单会多两次点击；菜单保留同名项作为可发现的第二入口。
- **时间线按卡绘制**：容器级绝对定位的线无法被卡片遮挡，会横穿卡面；改由每条记录的标记列画线并延伸到下一条，卡片 `z-index` 盖住线，只在左内边距露出。
- **固定 520px**：取 520px 与「视口 − 190px」的较小值，五条记录正好排满；记录少时用 `justify-content: space-between` 均匀分布，避免底部出现一大块空白。
- **底部成组**：模型说明与页脚合并成 `.result-bottom`，用 `margin-top: auto` 贴底，滚动时主操作始终在卡片底部。

## Risks / Trade-offs

- 整行可点击与行内「更多」按钮存在嵌套交互，需要 `event.stopPropagation()` 保证菜单不触发切换。
- 图钉只出现在当前记录上，其他记录没有任何「可切换」的视觉提示，靠 hover 时标题变色与指针形状提示。

## Migration Plan

纯展示层改动，无数据迁移。
