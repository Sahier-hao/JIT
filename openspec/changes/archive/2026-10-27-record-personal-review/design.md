# Design

## Context

公开来源快照只保存可读取的 PR 事实，个人审查需要记录工作过程，不能借匿名公共 API 存储共享意见。动机见 proposal.md。

## Goals / Non-Goals

**Goals:** 原位置与判断可恢复；个人数据边界明确；可导出完整工作与独立交付内容。

**Non-Goals:** 身份账户、跨设备自动同步、团队共享及自动发送审查。

## Decisions

1. 浏览器以仓库与 PR 标识保存工作单，以快照标识保存各轮进度、问题和结论。文件补丁留在公共来源缓存，不重复塞入个人备份；读到哪里、问题编辑位置和人工文本留在本地。
2. 问题包含来源、关联文件、原版本证据、人工判断与带理由的状态。Diff 行号区分两侧；返回证据时读取原快照、定位行并高亮，无法取得时保留原位置。
3. 保存比较工作单修订号，防止其他页面更新被覆盖；写入失败时内存继续保留文本。相比静默最后写入获胜，显式冲突更能保护未完成判断。
4. 完整备份只在本地解析，来源核对只请求公开快照身份。合并默认保留当前字段，逐项选择冲突，缺失条目不删除。意见和选中反馈分别预览导出，个人笔记不自动附到对外内容。

## Risks / Trade-offs

- 浏览器清理或配额不足 → 保存状态常显，完整备份与重试入口可用。
- 旧证据超出已加载代码 → 尝试原版本上下文，失败说明边界，不以新代码替代。
- 个人内容可能敏感 → 仅在明确导出时生成本地文件，不提供公共意见写入接口。

## Migration Plan

新增独立的本地工作单格式，不改写旧提交计划。导入先检查格式、大小、版本与冲突，保留当前记录；不把备份导入当作创建公共来源或训练数据。验证见 `docs/审计/2026-10-27-pr-review-journey.md`。
