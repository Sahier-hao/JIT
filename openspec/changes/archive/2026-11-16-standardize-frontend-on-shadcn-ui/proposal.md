# Proposal

## Why

用户工作区和管理工作区目前混用自写控件、页面内控件与全局样式，相同动作的实现和外观难以一致维护。统一采用官方 shadcn/ui 组件及其组合接口，使筛选、表单、弹层、列表和状态反馈有稳定的共同基线。

## What Changes

- 在现有 React、Vite、Tailwind 工程内接入官方 shadcn/ui CLI 配置和 Radix 组件来源，按实际使用范围添加组件。
- 用户与管理页面直接使用标准组件接口；清理旧基础控件及其过渡适配，业务组合留在共享或业务组件中。
- 统一主题变量、按钮层级、表单尺寸、键盘操作与弹层焦点恢复；保留四种主题、两档密度及中文可读性。
- 按内容语义区分页内标签、路由导航、筛选单选和破坏性确认；保留分析、模型选择、错误重试与个人草稿恢复行为。
- 扩展样式来源检查，防止重新引入第二套基础控件；同步产品说明与界面规范。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `interface-presentation`：明确跨工作区控件的标准交互、组合方式及弹层和筛选的可访问一致性。

## Impact

影响 `frontend` 的依赖、CLI 配置、基础组件、主题、所有工作区页面、相关单元和浏览器验证，以及前端运行和界面规范文档。后端 API、数据库、模型与已保存业务数据不需要升级。此项完成并归档后，再实施 `organize-frontend-feature-modules` 的模块重组。
