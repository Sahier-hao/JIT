# Design

## Context

见 proposal.md 的问题说明。前端已使用 React 19、Vite 8、Tailwind 4、Radix、CVA 和 `cn`；当前无 shadcn CLI 配置。`src/ui/controls.tsx` 汇集多种自定义接口，页面另有直接绘制的控件。项目概览及趋势使用 ECharts，代码工作区使用 react-diff-view。主题与密度、按账户隔离的本地草稿、固定分析和 PR 快照均已有回归约束。

## Goals / Non-Goals

**Goals:** 官方来源可复核，基础控件使用官方组合接口；全部工作区在同一主题契约下保持一致，旧基础控件最终清零，已有交互和业务身份可恢复。

**Non-Goals:** 后端、认证协议、模型和存储迁移；更换图表与 Diff 引擎；新增产品流程或缩减主题。目录职责重组属于后续独立 change。

## Decisions

1. **在现有工程接入官方 Radix 版本。** 用 `components.json` 登记 `@/components/ui`、`@/lib/utils` 和 Tailwind 入口，经官方 registry/CLI 添加实际需要的组件。选择与现有 Radix 依赖相容的官方预设并记录实际版本和来源；不从零重写组件来模仿外观。统一采用标准 `variant`、组合子组件和受控事件。
2. **直接迁移调用方。** 输入清除、密码显隐、业务确认和请求加载等复合需求使用标准组件组合，放入共享或业务组件；基础组件不吸收仓库、模型、账户或任务状态。旧适配只允许存在于实施中，不能作为完成结果。隐藏文件输入及图表、Diff 内部元素按语义保留。
3. **一个主题契约。** 标准 shadcn 变量承载表面、文字、主次操作、边框和焦点，风险分档使用独立业务变量。迁移中旧变量可映射到同一组值，收尾删除失效映射。四主题和两档密度继续工作，主要中文至少 14px；第三方内容样式只作用于专用容器。
4. **保持控件语义。** 破坏性操作使用 AlertDialog；详情和表单使用 Dialog；侧面板使用 Sheet；页内内容用 Tabs，跨地址导航用链接，筛选用单选或 ToggleGroup。焦点恢复、禁用、单次提交和失败后保留表单均通过实际交互检查。
5. **以用户旅程验收。** 运行受影响测试及完整前端单元、类型、lint、样式、构建检查；使用隔离数据库、端口和模型副本运行项目分析/模型选择及 PR 续审浏览器回归。新增覆盖菜单键盘、弹窗焦点或迁移中发现的缺失行为的测试，不用只核对实现字符串的测试冒充行为验收。

## Risks / Trade-offs

- [官方组件 API 与既有接口不同] → 逐类修改调用方，核对字符串选择值、默认按钮行为、禁用和受控状态，最终检查零旧引用。
- [全局变量及 Tailwind reset 改变密集页面] → 保留字号、密度和风险语义约束，检查四主题、桌面与 390px 窄屏，第三方内容限定作用域。
- [弹层卸载或组件重组丢失草稿] → 以已有登录切换、分析弹窗重开、PR 草稿恢复与固定快照回归作为完成条件。
- [网络不可用导致官方来源无法取得] → 明确记录具体失败；不将手写仿制组件记为官方接入完成。

## Migration Plan

先接入配置和官方组件，再迁移用户页、审查和管理页，最后删除旧层及无用依赖并更新文档。仅更新前端源码与静态构建，无数据库迁移；回退使用该变更前的前端构建。实际命令、版本、检查结果与限制写入 `docs/审计/2026-11-16-shadcn-ui-migration.md`，不在设计中预填验证结果。
