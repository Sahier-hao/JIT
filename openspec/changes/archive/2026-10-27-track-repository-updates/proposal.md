# Proposal

## Why

仓库接入后需要持续反映代码变化。每次手动重填分析参数会打断重复审查，也容易把检查失败误认为没有更新。用户需要立即更新、可暂停的自动检查，以及保留原结果的新分析。

## What Changes

- 新项目默认准备首次分析，开启每五分钟的服务端定时检查；已有项目由用户开启。
- 项目页支持立即更新、开关、跟踪分支、固定模型和检查频率，并区分检查、分析、无变化和错误。
- 检查到新 HEAD 后生成独立分析；没有变化且此前成功时不重复分析，失败可重新检查。
- 审查固定结果时提示新成功结果，提供打开和对比入口，保留原计划。

## Capabilities

### New Capabilities

- `repository-updates`: 仓库检查设置、持久化调度、版本检测、固定模型分析及失败恢复。

### Modified Capabilities

- `focused-project-review`: 接入后自动准备结果，项目页增加持续更新，固定审查提供新结果入口。

## Impact

涉及项目 API、服务端调度和 Git 检查、项目接入与审查界面、迁移 011 及接口说明。复用现有分析队列和模型准入规则，不增加外部依赖。部署前需备份数据库并升级，保持单个后端进程；自动检查仅在后端运行期间执行。
