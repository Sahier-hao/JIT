# Proposal

## Why

现有清洗入口能过滤少量固定字段，但配方不可排序，多个规则只返回一次汇总，用户无法判断每一步排除了哪些记录，也无法在同一个视图中比较指定特征逐步发生了什么变化。这使“清洗与预处理”更像一次性开关，难以复核，也难以解释派生数据与来源数据的差异。

## What Changes

- 将清洗配方升级为可增删、可排序的 v2 操作序列，保留 v1 配方规范化与哈希兼容。
- 增加日期范围、固定数值区间和按分位区间过滤；继续支持去重与缺失字段过滤。
- 预览按每一步返回前后数据集统计、排除原因和逐入模字段分布，并保存到派生版本谱系。
- 用户端与管理员端使用同一预览组件，提供数据集变化图、指定特征分布图和逐步统计表。
- 配方绑定当前 schema，未知字段或非法边界在预览前拒绝。

### New Capabilities

### Modified Capabilities

- `dataset-curation`: 清洗配方由单次规则集合升级为可排序操作序列；预览和派生谱系增加逐步前后的数据集与特征事实。

## Impact

- 后端：扩展清洗配方校验、顺序执行、逐步统计和派生清单；不新增数据库表。
- 前端：重做用户端清洗窗口，管理员清洗窗口复用同一预览图表。
- 兼容性：v1 配方继续可预览、生成和幂等复用；新操作使用 v2，不替换来源版本。
- 验证：覆盖 v1 兼容、逐步过滤、分位边界、schema 校验、用户预览与操作排序。
