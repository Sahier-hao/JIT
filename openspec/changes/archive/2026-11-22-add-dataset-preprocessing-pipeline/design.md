# Design

## Context

清洗服务已支持预览、不可变派生、谱系和源版本保护，但执行器一次遍历所有规则，只保留首个排除原因；前端也只有固定开关和最终分位桶。派生版本需要继续兼容既有 v1 配方，同时让用户能配置常用过滤与异常值处理并检查每一步的实际影响。

## Goals / Non-Goals

**Goals:**

- 用有序操作序列表达清洗与预处理，并保持同源同配方幂等。
- 在预览和派生谱系中保存每一步前后的数据集及特征统计。
- 让固定区间、分位区间和日期过滤在预览阶段使用当前步骤的输入计算边界。
- 用户端与管理员端展示一致、可访问的逐步图表和表格。

**Non-Goals:**

- 不在本次引入特征值缩放、编码或缺失值填补；这些变换需要同步进入模型推理契约。
- 不改变特征 schema、训练切分、标签成熟策略或权限边界。
- 不重算或迁移既有派生版本。

## Decisions

### v1 与 v2 分离规范化

v1 继续输出原有字段形状与排序，确保历史配方哈希不变；v2 才接受日期、固定区间和分位区间。执行器按规范化后的规则顺序逐条应用，避免历史派生版本因格式迁移改变身份。

### 每一步都保存前后快照

预览响应增加 `steps`：每条规则保存应用时输入和输出的数据集统计、排除原因以及逐入模字段分位桶。最终 `stats` 与 `featureComparison` 保持兼容，前端可继续读取最终结果。派生清单保存同一结构，版本对比只读该事实。

### 分位边界由步骤输入确定

分位过滤在当前步骤开始时的有效数值上计算上下界，并记录在步骤详情中。只读预览和正式生成使用同一算法，不使用最终数据重新分箱，也不覆盖来源版本。

### 行处理先于值变换

常用预处理以行过滤表达：日期范围、固定范围、分位范围和缺失字段。这样派生 CSV 的字段语义不变，训练和项目推理仍读取相同 schema；不引入浏览器端临时标准化造成训练与线上推理口径不一致。

### 前后端共享一个预览契约

用户端与管理员端使用同一解析器和预览组件。图表由共享 ECharts 封装渲染，同时保留逐步表格，避免只靠颜色传达变化。

## Risks / Trade-offs

- 每步保存全部入模字段分布会增加预览响应体积；字段数受 schema 约束，当前规模有限，换取逐步可复核性。
- 分位过滤会依据步骤位置变化；界面必须显示步骤顺序和计算边界，避免用户把它理解为跨配方固定阈值。
- 去重仍依赖来源允许重复提交；当前登记流程通常已拒绝重复 ID，因此该操作主要用于兼容既有配方。
- 不提供缩放、编码和填补，避免派生数据与线上原始特征推理不一致；需要时应扩展模型预处理身份后再实现。
