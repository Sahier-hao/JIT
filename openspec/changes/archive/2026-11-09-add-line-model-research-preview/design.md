# 设计

## Context

`line-train` 已能按仓库留出训练并输出报告与 manifest；固定实验 A3 证明去掉字符 n-gram 后，TypeScript 紧凑模型在留出仓库 axios 上仍有 PR-AUC 0.706、ROC-AUC 0.695，测试集正例率 0.523。报告中的模型只在训练进程内存在，没有可移植产物，因此产品无法展示或试用。

现有产品边界是提交级风险 + 静态规则候选；行级研究结论为“暂不登记为通用逐行概率模型、不进入用户主流程”。本次只增加独立研究预览，不改变该边界。

## Goals / Non-Goals

- Goal：把固定实验配置（TypeScript、无文本 n-gram、无提交级特征、仓库平衡、按仓库留出）导出为可审计、可校验的系数模型。
- Goal：提供公开只读的元数据与按行打分接口，并明确输出“排序分数，不是缺陷概率”。
- Goal：在前端提供独立页面和产品入口，展示真实训练/留出指标与限制。
- Non-Goal：登记模型目录、设置默认模型、进入项目分析/PR 审查、持久化用户输入、支持任意语言、支持完整文件或 PR 候选集定位。
- Non-Goal：改变行级实验“暂不产品化”的研究结论或提交级风险口径。

## Decisions

### D1 用 JSON 系数而不是 pickle

导出 `line-preview-model-v1`：特征名、语言类别、系数、截距、输入 SHA-256、切分摘要、留出指标与限制。服务端只做点积与 sigmoid，不加载 pickle，也不依赖训练库即可审计。产物计算 `artifactSha256`，加载时重新计算并比对，不匹配即明确不可用。

### D2 训练与预览共用一套特征实现

把 `FEATURE_NAMES`、`STRUCT_KEYS`、`TEXT_PARAMS`、`structure()` 与 `numeric_values()` 移到 `line_features.py`，`line_train` 与研究预览都调用它，避免线上打分与训练口径漂移。研究预览只接受 `textFeatures=false`、`includeCommitFeatures=false`、`positionFeatures=true` 的紧凑模型；导出时校验系数数量与特征名一一对应。

### D3 打分只在请求内完成

`POST /api/v1/research/line-model/score` 接收 `{language, code}`，按行构造与训练相同的数值/结构特征，语言限定为模型训练覆盖的 TypeScript。跳过空行，按分数降序返回排名；单次最多 2,000 行或 200,000 字符。请求、代码和结果不写数据库、不写日志正文。

### D4 独立页面与隔离

新增 `#/research/line-model`，无需登录，使用独立页面外壳而不是用户工作区导航；产品介绍页提供单一入口。接口命名空间为 `/api/v1/research/*`，不进入模型列表、默认模型、项目模型选择、PR 分析或训练参数契约。

### D5 诚实标注

页面和接口都固定返回：分数来自正负 1:1 抽样与 SZZ 弱标签；未做概率校准；不是缺陷概率；定位指标是抽样代理；不参与项目分析。页面同时展示留出指标、随机基线、样本量与限制，避免只给一个分数。

## Risks / Trade-offs

- 用户可能把分数当作概率：用标题、徽标、分数列名、说明和限制四处固定标注，且不提供“概率”字段名。
- 模型只覆盖 TypeScript：接口拒绝其他语言并返回明确错误，不静默套用。
- 研究产物与训练数据分离：JSON 记录输入哈希与报告摘要，数据不入库；复现需按哈希准备同一份 JSONL。
- 公开接口可能被滥用：限制行数与字符数，计算为纯内存点积，不落盘、不调用外部服务。

## Migration Plan

无需数据库迁移。新增研究产物文件与只读路由；旧目录库、模型目录、项目分析和 PR 结果保持不变。删除或损坏研究产物时，页面与接口返回明确的不可用状态，不退回其他模型。
