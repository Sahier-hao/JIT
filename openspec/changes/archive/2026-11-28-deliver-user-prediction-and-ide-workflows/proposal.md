## Why

现有「模型试算」只能对整个数据版本批量评分，无法覆盖单条、项目提交、固定分区和无标签输入；结果与评估之间也缺少稳定交接。IDE 插件 0.3.0 已能提交后自动检查，但模型仍靠手填、没有提交级解释，且分数与可疑代码行术语不统一。

## What Changes

- 将「模型试算」升级为「缺陷预测」，保留 `#/my-predictions` 兼容地址，提供单条与批量两个入口。
- 单条支持数据版本选行、项目已保存分析提交和手工特征；批量支持完整数据版本、模型冻结分区、注册时间切分预设及无标签 CSV。
- 批次固化真实模型身份、来源、分区、切分预设和成员摘要；单条与批量复用同一 `predict_risks` 与特征顺序，缺字段、schema 不匹配或非有限数值明确失败。
- 结果表提供提交级预测分数、当前阈值分类、真实标签/无标签、来源、搜索、排序、分页、阈值重算、刷新重开和 CSV 导出；仅具备可用正负真实标签的批次提供评估入口。
- 新增 `#/my-evaluation` 只读承接页，稳定接收批次、模型、数据版本、分区和切分预设，展示阈值工作点、混淆矩阵及精确率/召回率/F1 曲线。
- VS Code 插件增加只读模型列表 CLI 与 QuickPick、提交级特征归因、只读解释文档，并统一为「提交级预测分数」「可疑代码行」。
- 项目 PR 列表展示自动分析使用的固定模型、head SHA、提交列表、最近检查时间和实时分析状态；后台自动发现后无需手点分析即可周期刷新。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `user-model-evaluation`: 增加单条/批量预测、固定分区、无标签输入、标签可用性、结果持久重开与只读评估交接。
- `ide-report-consumption`: 增加提交后自动检查的真实模型 QuickPick、提交级解释只读视图及统一术语/证据。
- `project-pr-tracking`: 增加自动分析结果的模型、head SHA、提交列表、最近检查和页面周期同步展示。
- `workspace-navigation`: 增加缺陷预测兼容地址和预测评估深链接的稳定恢复。

## Impact

- SQLite `045` 前向迁移、用户预测服务/API、OpenAPI 与生成类型。
- 缺陷预测页、预测评估页、项目 PR 列表、路由和导航。
- `jit_baseline.cli pr-check-models`、`pr-check-analyze` 报告扩展与 VS Code 扩展 0.4.0。
- 后端 pytest、前端 Vitest、隔离 Playwright、插件单测/打包/宿主冒烟尝试及审计证据。
