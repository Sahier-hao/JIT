## Context

现有目录库中预测批次只保存数据集级 batch、非空标签和少量模型身份；无标签输入、单条来源和固定分区无法安全表达。IDE 侧已有本地 `HEAD~1..HEAD` 自动检查和静态候选，但模型 ID 由手填，报告只有提交分数，没有归因和统一解释入口。项目 PR 自动分析已有持久 intent、快照和后台 worker，但列表响应未暴露固定 head 与提交列表。

## Goals / Non-Goals

**Goals:**

- 用一套表格推理服务覆盖单条、批量、分区和无标签 CSV，保证同模型同数据分数一致。
- 让无标签、未成熟标签和训练数据约束保持分离，评估只使用可用真实标签。
- 让插件模型选择和解释完全基于本地真实目录库与报告。

**Non-Goals:**

- 不新增自动超参搜索、模型替换、标签推算或把缺失标签补成 0。
- 不把预测报告内容变成可执行 HTML、命令或自动修复。
- 不把静态候选解释成行级缺陷概率，也不改项目 PR 的自动模型。

## Decisions

### 1. 单条与批量共用准备/推理/解释路径

所有入口先解析入模字段，再调用同一 `predict_risks`，归因复用 `attribution.explain`。批量与单条只在记录来源、标签可用性和批次元数据上不同；服务与隔离浏览器都直接比较同一记录分数。

### 2. `045` 重建预测表并保留旧批次

SQLite 无法安全去掉旧 `label NOT NULL` 和 `dataset_version NOT NULL`。迁移创建新表、复制旧批次、把旧 `immature/unknown` 标签转为 `NULL + unavailable`，再重命名。当前库升级前已生成备份；测试覆盖 v44 → v45 数据保留。

### 3. 分区来自可核对成员，不按日期猜

模型冻结分区读取模型产物 `split.json` 并核验 `memberSha256`；预设计算使用已注册 `splits.py` 时间切分。批次保存来源、预设、分区和成员摘要；成员不匹配整批失败。完整数据版本也保存成员哈希。

### 4. 标签可用性与评估资格分开

只有 `positive` 与观察期已满的 `unobserved` 视为可用标签；未成熟、未知和无标签记录不进入阈值统计。只有同时存在可用正负标签的批次提供评估入口。上传 CSV 不接收标签列，也不写回 `commit_record`。

### 5. 评估使用独立只读契约

`/prediction-batches/{batchId}/evaluation` 从保存分数重新计算阈值工作点，不调用模型。前端通过 URL 带入 `batchId/modelId/datasetVersion/partition/splitPreset` 并逐项核对批次，防止上下文替换。

### 6. 插件模型与解释都只消费显式事实

`pr-check-models` 只返回已启用、ready、提交采集 schema 兼容且能实际加载的模型。QuickPick 不可用时回退手工输入；不拼默认模型。`pr-check-analyze` 为评分提交保存可选解释，失败不改变分数；插件用只读虚拟 Markdown 文档展示，避免 Webview 执行报告内容。

### 7. PR 列表补充固定分析事实并周期刷新

PR 列表从 `pr_snapshot` 读取 head SHA、提交列表、完整性和检查时间；自动打分开启时页面以低频轮询读取本地缓存。后台仍负责远端检查与任务提交，页面不触发单 PR 分析。

## Risks / Trade-offs

- [20,000 条批次一次性生成 101 档阈值和归因] → 只保存分数/标签，阈值预览在服务端一次计算；归因仍限 Top 10。
- [旧批次标签语义与新表不同] → 迁移按状态显式转成 unavailable，并在重开时重算标签可用性和阈值预览。
- [模型冻结分区产物缺失或损坏] → 不提供模型分区，回退到显式时间预设；不能猜测成员。
- [页面轮询与后台自动分析同时运行] → 轮询只读本地缓存，不触发新的远端分析；前台仍可手动检查。
- [扩展宿主受本机 ACL 阻塞] → 已记录启动错误和可重试命令；不把单测、打包或 CLI 实测冒充宿主通过。

## Migration Plan

1. 备份 `backend/storage/catalog.sqlite3`。
2. 启动时应用 `045_prediction_modes_and_sources.sql`；失败回滚事务，不删除旧表。
3. 验证旧批次记录数量、模型身份、可用标签映射和重开行为。
4. 回滚时停止新服务并恢复备份；不手改现有预测记录。
