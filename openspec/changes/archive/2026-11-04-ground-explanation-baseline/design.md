# Design

## Context

`catalog_storage.feature_means` 目前按整个 `dataset_version` 聚合字段均值，可能包含验证、测试和近期提交。训练运行目录的 `split.json` 已经保存各分区的提交标识（`artifacts.py` 写入 `ids`），因此可以按训练分区成员过滤后计算均值，不需要新增数据库结构。参见 proposal.md。

## Goals / Non-Goals

**Goals:**

- 解释背景严格来自训练分区，并可核对哈希。
- 解释不稳定时如实标注。
- 旧解释保留原内容并标注背景未知。

**Non-Goals:**

- 不重新训练、不改变模型分数或标签。
- 不新增训练分区持久化结构。
- 不把特征敏感度表述为缺陷原因或代码定位。

## Decisions

**从运行目录读取训练分区成员。** 解释读取绑定运行的 `split.json`，取 `partitions.train.ids`；按这些标识从数据集版本查询字段均值。标识数量大时分块查询，避免单条 SQL 过长。`split.json` 缺失、训练分区为空或字段缺失时退回零基线并说明。

**背景哈希。** 对字段名和均值按固定顺序序列化为规范化 JSON，计算 SHA-256，随解释保存。重开时比较保存的哈希与当前计算值；不一致时保留原解释并标注背景变化，不静默重算。

**稳定性检查。** 对每个入模数值字段在合法范围内生成少量扰动（计数保持非负整数、比例保持有限值），重复计算贡献并比较主要特征排序。报告稳定、部分稳定或不稳定及变化范围；非法扰动跳过并记录。扰动次数和范围在解释方法声明中固定，结果随解释保存。

**旧解释兼容。** 早于训练分区背景的解释保留原内容，读取时返回背景未知或零基线状态，不按当前数据补算。

## Risks / Trade-offs

- [训练分区标识很多导致查询慢] → 分块查询并限制单次解释的字段数；结果随解释保存，不重复计算。
- [扰动计算增加解释耗时] → 限制扰动次数，结果保存后不重算。
- [背景哈希与当前数据不一致] → 保留原解释并标注变化，不用新背景覆盖旧结果。
- [旧解释没有背景] → 返回未知状态，不阻塞读取。

## Migration Plan

1. 解释保存内容增加训练分区身份、背景哈希和稳定性结果；无数据库结构迁移。
2. 旧解释按原内容读取并标注背景未知。
3. 回滚时停止读取新字段并恢复旧代码；已保存解释保留。
