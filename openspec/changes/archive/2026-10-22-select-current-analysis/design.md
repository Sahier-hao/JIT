# Design

## 接口复用而不是新端点

切换当前结果与重命名都只改项目的展示字段，`PATCH /api/v1/repositories/{id}` 已存在且被幂等使用。请求体含 `viewSyncId` 时走「切换当前结果」，否则走「改显示名」，避免多一个语义重叠的端点。

## 只改视图，不重算历史

`select_view` 校验记录属于该项目且状态为 `completed`，然后调用既有的 `repository_refresh(repository_id, sync_id)`：它按所选分析的提交重算 `commit_count`、风险分布、`head_commit` 与 `distribution_rule`，并把 `view_sync_id` 指向该记录。`latest_sync_id` 不动，因此「最近一次请求」与「当前结果」仍是两个独立概念。

## 失败与越权

- 记录不存在或属于其他项目：404 `NOT_FOUND`。
- 记录未完成：409 `CONFLICT_ACTIVE_SYNC`（已有错误码，提示「只有已完成的分析才能设为当前结果」）。
- `viewSyncId` 为空：422 `INPUT_INVALID`。

## 前端放置

- 项目页只做分析：记录行对「已完成且不是当前结果」的记录显示「设为当前结果」，成功后同时刷新详情与记录列表，顶部结果立即更新。
- 项目本身的管理（重命名、删除）移到项目列表页卡片的「管理」菜单，删除仍要求确认；项目页不再出现这两个按钮。
- 分析选项从折叠面板改为常显，字段与默认值不变，避免用户不知道可以设置什么。
- 审查页与项目页都提供返回上一层的链接（项目页 → 项目列表，审查页 → 项目页）。

## 测试

- 后端：切换成功、失败记录 409、跨项目 404、空值 422、未知项目 404；切换后计数与 `latestSyncId` 断言。
- 前端：记录行切换请求体；卡片菜单重命名/删除；项目页返回链接；分析选项直接可见。
