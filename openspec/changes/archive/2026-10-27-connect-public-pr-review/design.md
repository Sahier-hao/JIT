# Design

## Context

既有队列负责仓库采集和真实模型推理，普通审查与管理员维护已有服务端边界。PR 代码阅读需要在模型之外独立工作，见 proposal.md。

## Goals / Non-Goals

**Goals:** 公开来源真实可核对；版本与上下文固定；原模型与分析 HEAD 可追溯。

**Non-Goals:** 私有仓库接入、个人账户同步、直接发布 GitHub 审查及 PR 整体缺陷概率。

## Decisions

1. 使用 GitHub REST 读取公开 PR、文件及提交，限定官方 API 主机和 HTTPS。匿名限额明确失败，可配置服务端 JIT_GITHUB_TOKEN；即使配置令牌也拒绝私有来源。相较浏览器直连，服务端能统一来源校验、限额错误及缓存。
2. 迁移012保存基准和目标组成的不可变快照，读取文件前后核对版本。相同代码版本复用缓存，远端状态与检查时间单独保存，避免重写原作者说明和 Diff。
3. 上下文按保存 SHA 和文件成员身份读取、缓存；缺失侧、过大、二进制及不完整补丁单独显示。文件列表最多遵循 GitHub 接口范围，提交列表只声明实际加载数量。
4. 模型任务使用目标仓库及固定目标 SHA，沿用真实兼容模型入口。关联任务保存在独立表；只有任务实际 HEAD 匹配才返回覆盖的 PR 提交分数。用户主动触发，人工编辑不依赖模型服务。

## Risks / Trade-offs

- GitHub 限额或网络不可用 → 保留输入与保存来源，显示明确重试路径。
- 大 PR、二进制及原仓库删除 → 声明未覆盖内容，保存的 Diff 可读，不借用其他代码版本。
- 首版无跨设备账户 → 个人记录只在浏览器，不在公开来源表混入意见。

## Migration Plan

在数据库备份后应用012，新增来源、上下文及分析关联，外键随项目及任务清理。原模型、任务、数据和管理员账户不变。部署与回退见 `docs/当前产品.md`；验证见 `docs/审计/2026-10-27-pr-review-journey.md`。
