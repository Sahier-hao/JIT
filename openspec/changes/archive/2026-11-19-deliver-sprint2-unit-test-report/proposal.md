## Why

项目已有大量测试代码和运行结果，但 Sprint2 缺少考核文档要求的规范化单元测试交付包：核心函数与用例没有三场景映射，外部依赖未按单元层隔离，覆盖率、AI 来源、提示词和正式报告不可核验。该材料只需随 Sprint2 提交，不建立长期 PR 门禁。

## What Changes

- 新增 Sprint2 单元测试交付能力，明确后端核心逻辑与前端纯函数的单元测试边界。
- 建立核心函数清单及“正常、边界、异常”三类用例映射，补齐无法由现有测试证明的核心场景。
- 提供独立、可重复、不访问网络、正式数据库或正式模型包的快速单元测试入口，并记录相对实际成员的执行耗时。
- 生成后端和前端行、分支覆盖率，以及含提交、环境、命令、数量、耗时、覆盖率和来源比例的机器可读清单与 Markdown 报告。
- 为测试用例标注 `[AI生成]`、`[AI生成-人工修改]` 或 `[手写]`，归档提示词及核心断言人工复核记录。
- 使用现有证据冻结机制封存 Sprint2 最终报告、覆盖率截图和来源清单。

## Capabilities

### New Capabilities

- `unit-test-delivery`: 规定 Sprint2 单元测试的范围、三场景完整性、依赖隔离、速度、覆盖率、AI 来源审核和可追溯报告。

## Impact

- 影响 `backend/tests/`、`frontend/src/**/*.test.{ts,tsx}`、测试运行配置及 Sprint2 测试文档。
- 可能新增 `pytest-cov` 和前端 coverage provider 等测试依赖，并增加测试来源、提示词与报告目录。
- 不改变产品 API、模型训练、发布资格、运行服务或 `continuous-regression` 工作流。
- 不新增每次 PR 必须通过的覆盖率门禁或分支保护规则。
