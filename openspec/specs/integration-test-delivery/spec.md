# integration-test-delivery Specification

## Purpose

定义 Sprint3 可提交、可复核的集成测试交付：覆盖 95 个业务 API 操作、四类场景矩阵、高风险与剩余接口、前后端真实联调、并发与故障验证，以及可冻结的报告和来源证据。

## Requirements

### Requirement: ITD-01 95 个业务 API 操作清单

交付包 SHALL 以人工维护的 OpenAPI 契约作为事实来源，提供 95 个业务 API 操作的机器可读清单；每项 MUST 记录方法、路径、operationId、认证/角色边界、风险等级和至少一个对应测试或明确的未覆盖原因。4 个 admin 认证操作（setup、login、session、logout）MUST 单独列出并说明不纳入 95 项业务清单的原因，MUST NOT 被静默丢弃。清单与契约的操作数量或方法/路径不一致时 MUST 校验失败并列出漂移项。

#### Scenario: 清单完整

- **WHEN** 审核者打开 95 个业务 API 操作清单
- **THEN** 每项都能定位到方法、路径、operationId、认证/角色边界、风险等级和测试映射或未覆盖原因

#### Scenario: admin 认证单独说明

- **WHEN** 清单统计业务 API 操作数量
- **THEN** 4 个 admin 认证操作在单独章节列出，且不计入 95 项业务操作

#### Scenario: 契约漂移

- **WHEN** OpenAPI 新增、删除或改变操作而清单未同步
- **THEN** 校验失败并列出新增、缺失或变更的操作，不继续生成“完整覆盖”结论

### Requirement: ITD-02 四类场景矩阵

交付包 SHALL 为清单中的每个操作记录正常、边界、异常/失败、并发/故障四类场景格；每格 MUST 指向实际执行的测试或经人工复核的“不适用”原因。高风险接口 MUST 四类均可执行；其余接口 MUST 至少完成正常与异常/失败，边界与并发/故障可按业务状态标记不适用并说明理由。失败、跳过或未执行的场景 MUST NOT 计入通过。

#### Scenario: 四类格完整

- **WHEN** 审核者查看任一操作的场景矩阵
- **THEN** 正常、边界、异常/失败、并发/故障四格均有测试引用或人工复核的不适用原因

#### Scenario: 高风险接口四类可执行

- **WHEN** 操作被标为高风险（认证与权限、同步与取消、训练、模型登记与策略、PR 分析与报告、数据集导入、解释生成）
- **THEN** 四类场景均有实际测试结果，不以“不适用”替代并发/故障验证

#### Scenario: 失败或跳过

- **WHEN** 某场景失败、跳过或未运行
- **THEN** 矩阵保留状态与原因，不把该操作计为完整通过

### Requirement: ITD-03 高风险优先与剩余接口

交付报告 SHALL 按风险等级给出执行顺序和完成状态，先完成高风险接口，再补齐剩余接口。只有在高风险接口全部有实际结果后，报告 MAY 开始汇总剩余接口的完成情况；任何接口未覆盖时 MUST 显式列出，MUST NOT 用汇总数字掩盖缺口。

#### Scenario: 高风险先完成

- **WHEN** 报告进入剩余接口阶段
- **THEN** 高风险接口清单中的每一项都已有实际测试结果

#### Scenario: 剩余接口

- **WHEN** 完成剩余接口阶段
- **THEN** 每个剩余操作至少具备正常与异常/失败结果，边界与并发/故障缺口单独列出

#### Scenario: 不夸大覆盖

- **WHEN** 报告声明 95 个操作已覆盖
- **THEN** 机器可读矩阵能逐项证明，不能仅以测试文件数量或总断言数量代替操作覆盖

### Requirement: ITD-04 测试工具与框架

交付包 SHALL 提供可重复执行的工具入口，从 OpenAPI 生成清单、校验 95 项与四类矩阵、运行后端/接口/前端/浏览器测试，并输出机器可读结果。工具 MUST 复用现有 pytest、OpenAPI 契约测试、前端单元测试和 Playwright 隔离服务测试；空套件、缺失映射或静默跳过 MUST 使校验失败。

#### Scenario: 从契约生成清单

- **WHEN** 审核者在干净检出上运行清单工具
- **THEN** 从 `docs/api/openapi.yaml` 生成 95 项业务操作清单并报告 admin 认证排除项

#### Scenario: 覆盖校验

- **WHEN** 某操作或某类场景缺少映射
- **THEN** 校验失败并指出操作、场景类别和缺失原因

#### Scenario: 工具失败

- **WHEN** 依赖安装、测试执行或结果解析失败
- **THEN** 命令以非零状态结束并保留日志，不生成通过报告

### Requirement: ITD-05 前后端真实联调

交付包 SHALL 使用真实隔离后端与前端完成至少一个高风险域的前后端联调旅程；前端 MUST 请求真实 API 并核对响应身份、状态、错误信封和页面状态。正式联调证据 MUST NOT 以拦截或伪造 API 响应代替；测试夹具 MUST 与开发机数据库、模型和账户隔离。

#### Scenario: 真实链路

- **WHEN** 运行正式联调旅程
- **THEN** 前端通过真实隔离服务完成请求、展示结果，并保存请求记录与截图

#### Scenario: 错误传播

- **WHEN** 后端返回输入错误、冲突、服务不可用或存储失败
- **THEN** 前端显示对应状态与原因，不显示伪造成功

#### Scenario: 兼容性

- **WHEN** 联调完成
- **THEN** 既有 API 契约和旧前端调用仍可工作，联调未改变默认模型或风险口径

### Requirement: ITD-06 并发与故障场景

交付包 SHALL 覆盖并发重复请求、取消、重试、超时、服务不可用、存储失败和部分失败，并验证不会产生重复记录、错误终态、丢失已保存结果或虚假成功。迟到响应 MUST NOT 覆盖切换后的对象；失败恢复 MUST 保留原始错误并允许按契约重试。

#### Scenario: 并发重复请求

- **WHEN** 同一资源收到并发或重复创建/生成请求
- **THEN** 系统按幂等或明确冲突处理，不产生未登记的重复记录

#### Scenario: 取消与重试

- **WHEN** 用户取消或重试操作
- **THEN** 终态与重试结果符合契约，旧结果不覆盖新状态

#### Scenario: 故障恢复

- **WHEN** 服务或存储暂时不可用
- **THEN** 错误可定位，恢复后可重试，且不把失败计为通过

### Requirement: ITD-07 报告、来源与冻结证据

交付包 SHALL 生成与实际运行一致的机器可读结果和 Markdown 报告，记录提交、环境、命令、95 项清单、四类矩阵、通过/失败/跳过数量、高风险与剩余接口状态、AI 来源和人工复核。AI 生成或修改的测试 MUST 标注来源并归档完整提示词；每条核心断言 MUST 有审核人、日期和结论。最终材料 SHALL 通过 SHA-256 冻结清单校验，未登记、缺失或被修改的证据 MUST 使校验失败。

#### Scenario: 来源可追溯

- **WHEN** 某测试由 AI 生成或修改
- **THEN** 测试标记、提示词归档和人工复核记录可以互相定位

#### Scenario: 报告一致

- **WHEN** 审核报告与机器可读结果
- **THEN** 提交、环境、命令、数量和矩阵状态一致，旧提交或失败/跳过结果不冒充本次通过

#### Scenario: 冻结校验

- **WHEN** 对最终交付包执行冻结校验
- **THEN** 清单中的每个文件 SHA-256 一致，缺失、被修改或未登记文件均报告失败
