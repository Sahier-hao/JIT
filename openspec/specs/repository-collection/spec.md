# repository-collection Specification

## Purpose

让系统能从真实 Git 仓库采集历史提交，计算 Kamei 14 维代码变更度量并生成缺陷引入标签，产出可登记、可训练、可追溯的数据集，而不是只能消费发布者预先算好的文件。

## Requirements

### Requirement: RCL-01 仓库来源与采集范围

系统 SHALL 接受本地仓库路径或公开仓库地址作为采集来源，并记录仓库标识、采集的分支与提交范围、采集器版本。来源不存在、不是 Git 仓库或无法读取时 MUST 拒绝采集并给出可定位原因，MUST NOT 用其他仓库或空数据集冒充成功。对公开 HTTP(S) 来源，系统 SHALL 允许使用按仓库地址隔离的本地缓存副本：命中缓存时 MUST 先更新远端引用或验证目标提交存在，采集结果 MUST 与直连采集一致；缓存损坏、来源不可达或缓存与请求范围不匹配时 MUST 回退直连或明确失败，MUST NOT 使用其他仓库的副本。缓存目录 MUST 有磁盘上限，超过上限时按最久未使用淘汰，MUST NOT 因缓存淘汰删除已登记的数据集、模型或分析结果。

#### Scenario: 采集本地仓库的指定范围

- **WHEN** 指定一个可读的本地 Git 仓库与起止时间
- **THEN** 采集在该范围内完成，产物记录仓库标识、分支、起止时间与采集器版本

#### Scenario: 来源不可用

- **WHEN** 路径不存在、目录不是 Git 仓库，或远程仓库无法访问
- **THEN** 采集失败并指出具体原因，不产出空数据集或退回其他来源

#### Scenario: 同一仓库重复采集命中缓存

- **WHEN** 同一公开仓库在缓存有效期内被再次采集
- **THEN** 使用该仓库的本地副本完成采集，产物记录的信息与直连采集一致
- **AND** 不重复克隆整个仓库

#### Scenario: 缓存损坏或过期

- **WHEN** 本地缓存副本损坏、无法更新或与请求的分支和提交范围不匹配
- **THEN** 系统重新获取或回退直连采集，失败时明确说明原因，不使用其他仓库的副本

#### Scenario: 缓存超出磁盘上限

- **WHEN** 仓库缓存总量超过配置上限
- **THEN** 按最久未使用淘汰仓库副本，已登记数据集、模型和分析结果不受影响

### Requirement: RCL-02 提交遍历与身份

系统 SHALL 为采集范围内每个提交记录完整提交标识、作者标识、带时区的提交时间与变更文件清单。合并提交、空提交与无法解析的提交 MUST 按显式规则排除并计数，MUST NOT 静默丢弃；同一提交在同一数据集版本内 MUST 只出现一次。

#### Scenario: 遍历并记录提交

- **WHEN** 采集一个包含合并提交与普通提交的范围
- **THEN** 每个纳入提交有唯一标识、作者、时间与文件清单，被排除的提交有原因与计数

#### Scenario: 重复提交

- **WHEN** 同一提交因范围重叠被再次采集
- **THEN** 该提交在数据集版本内只出现一次，不产生重复记录

### Requirement: RCL-03 Kamei 14 维特征计算

系统 SHALL 为每个纳入提交计算 Kamei 14 维代码变更度量的提交级取值，并在产物中记录每个字段的计算口径与所用历史范围。历史状态 MUST 以该提交的父提交为起点，并且只由该父提交的父链推进；采集只遍历非合并提交，合并提交 MUST NOT 进入记录或推进历史。该限制 MUST 随产物记录。无法计算的字段 MUST 记录为空值与原因，MUST NOT 填零、用同名异义列替代或推算。提交级聚合与论文的文件级样本单位不同，产物 MUST 显式标注该差异。当同一仓库、同一特征 schema 的同一提交已有保存的特征时，系统 MAY 复用该特征用于新分析，但 MUST 记录复用来源，且复用值 MUST 与该口径重算结果一致；没有保存值或 schema 不一致的提交 MUST 重新计算，MUST NOT 用同名但不同口径的值替代。

#### Scenario: 计算完整 14 维

- **WHEN** 采集一个历史完整的仓库范围
- **THEN** 产物包含 14 个字段的全部取值，且 `lt`（变更前文件规模）与 `rexp`（作者近期经验）由仓库历史计算而非留空

#### Scenario: 字段无法计算

- **WHEN** 某提交是仓库首个提交，没有父提交可提供变更前状态
- **THEN** 依赖父提交的字段为空值并附原因，不填零、不跳过该字段

#### Scenario: 口径可重算

- **WHEN** 按产物记录的口径对同一提交重算
- **THEN** 得到相同特征值，差异在声明容差内

#### Scenario: 并行分支不污染历史

- **WHEN** 两个提交共享同一父提交、分别位于不同分支，且作者时间顺序与拓扑顺序不同
- **THEN** 每个提交的文件规模、作者经验与近期经验只来自其父链，不包含另一分支的修改

#### Scenario: 作者时间倒置

- **WHEN** 子提交的作者时间早于其父提交
- **THEN** 历史仍按父链推进，不按时间排序把父提交排除或把子提交计入父提交历史

#### Scenario: 合并提交的限制

- **WHEN** 仓库包含合并提交，且合并分支带来了文件变化
- **THEN** 合并提交不进入记录、不推进历史，产物明确说明合并分支的变化不会汇入主线历史
- **AND** 不把该限制表述为已支持完整合并历史

#### Scenario: 复用已保存特征

- **WHEN** 目标提交在同一仓库、同一 schema 下已有保存的特征
- **THEN** 新分析可以使用该特征，并记录来自哪个分析或数据集版本
- **AND** 复用值与该口径重算结果一致，缺失字段仍按原规则为空并说明原因

#### Scenario: 复用来源口径不一致

- **WHEN** 已保存特征来自不同 schema 或不同变换口径
- **THEN** 不复用该值，重新按当前 schema 计算，不把不同口径的字段混用

### Requirement: RCL-04 简化 SZZ 标签

系统 SHALL 按显式规则识别修复提交并回溯其引入的代码，将引入提交标为缺陷引入。默认规则为 `szz-full-v1`：修复提交优先用 issue/PR 关联确认（`fixes/closes/resolves #N` 与 GitHub issue/PR URL），关键词兜底；对唯一父提交做带重命名/复制检测的 diff，只取被删除或修改的行区间，用 `git blame -M -C` 回溯到引入提交，并保存引入提交中的原始行号区间与父提交行号区间。issue 元数据 MUST 以采集时快照保存；离线、未配置 token 或查询失败时 MUST 降级为关键词识别并记录，不得伪装成已关联 issue。`szz-line-v1` 与 `szz-simple-v1` 作为兼容规则保留。回溯 MUST 只使用当前提交父链上的历史；无法证明父链关系 MUST NOT 把该提交标为引入。每个正例 MUST 保存可复核证据：修复提交、候选引入提交、文件路径、行号区间、修复信号、issue 引用与快照、证据时间和观察终点；同一提交由多个修复、文件或行区间产生证据时 MUST 分别保存，MUST NOT 互相覆盖。标签状态 MUST 区分有证据正例、未观测和未成熟；未命中 MUST 记为未观测到缺陷引入并注明其含义，MUST NOT 称为已证实无缺陷。标签规则 MUST 有版本标识并随产物记录。产物与报告 MUST 标注实际使用的规则，MUST NOT 把标签表述为已人工确认或已穷尽全部 SZZ 变体。

#### Scenario: 回溯到引入提交

- **WHEN** 一个修复提交删除了若干行，且这些行在父提交中有更早的变更提交
- **THEN** 这些行的引入提交被标为缺陷引入，并保存修复提交、引入提交、路径、引入提交原始行号区间、父提交行号区间与规则版本

#### Scenario: 没有可回溯的修复提交

- **WHEN** 采集范围内没有命中修复规则的提交
- **THEN** 全部标签为未观测到并注明含义，不把结果称为已证实无缺陷

#### Scenario: 规则可复核

- **WHEN** 查看产物中的标签说明或任一正例证据
- **THEN** 可见修复提交识别规则、回溯范围、规则版本和该正例的修复与引入位置，并可据此复核

#### Scenario: 引入候选必须属于父链

- **WHEN** 文件的最近一次变更来自并行分支或合并点，而不是修复提交的父链
- **THEN** 该候选不被标记为缺陷引入，产物记录无法确定父链关系的原因，不用其他提交替代

#### Scenario: 未成熟标签

- **WHEN** 提交时间距离观察终点不足声明的成熟期，且采集范围内尚未观测到修复
- **THEN** 该提交标为未成熟而不是未观测或已证实无缺陷，并记录观察终点与成熟期

#### Scenario: 同一提交多条证据

- **WHEN** 同一提交被多个修复提交、多个文件或多个行区间分别标记
- **THEN** 每条证据分别保存，查询时全部可见，不因后写入的证据覆盖先前证据

#### Scenario: 行级回溯到具体行

- **WHEN** 使用默认 `szz-full-v1` 且修复提交修改了源码行
- **THEN** 证据包含引入提交中的原始行号区间和修复前父提交中的行号区间
- **AND** 只有落在采集窗口内的引入提交获得正例标签

#### Scenario: 重命名后的文件

- **WHEN** 文件在修复前被重命名，修复提交修改的是新路径
- **THEN** 行级回溯仍能追到重命名前的引入提交，并存下当前路径与旧路径

#### Scenario: 回滚与纯新增修复

- **WHEN** 修复提交是回滚提交，或只新增代码而没有删除/修改行
- **THEN** 回滚提交不作为修复提交；纯新增修复不产生引入行证据，不计入正例

#### Scenario: 文档与测试路径

- **WHEN** 修复提交只修改文档或测试路径
- **THEN** 不把文档/测试行标为缺陷引入，被过滤的路径数量记入统计

#### Scenario: 回溯上限

- **WHEN** 一个修复提交的删除行或修复提交数量超过声明上限
- **THEN** 只回溯上限内的部分，标记产物已截断并显示，不伪造其余证据

#### Scenario: issue 关联确认修复

- **WHEN** 提交说明包含 `fixes #12`，且对应 issue 快照带 bug 标签
- **THEN** 该提交按 issue 信号识别为修复，证据保存 issue 编号、标题、状态、标签与抓取时间
- **AND** 即使标题不含 fix 关键词也应识别

#### Scenario: 离线或查询失败

- **WHEN** 没有 GitHub token，或 issue 查询超时、被限流
- **THEN** 该提交降级为关键词识别，产物记录 issue 查询失败或不可用，不伪造 issue 快照

#### Scenario: 噪声提交

- **WHEN** 一个标题含 fix 的提交只改空白、只改重构/格式化或只改文档测试
- **THEN** 不产生引入行证据，并按排除/空白/仅文档分别计数

#### Scenario: 删除文件

- **WHEN** 修复提交删除了一个源码文件
- **THEN** 对被删除文件在父提交中的行做 blame，仍可标出引入提交，受行数与上限约束

#### Scenario: 人工抽样复核

- **WHEN** 管理员需要核对标签质量
- **THEN** 可从数据集描述导出复核表，逐条填写 verdict/note
- **AND** 复核结论不自动改写标签或模型

### Requirement: RCL-05 采集产物与数据集登记

采集 SHALL 产出与具名特征 schema 对齐的表格文件和数据集描述文件，并通过现有登记入口登记。产物 MUST 记录字段定义、质量统计、提交时间范围与样本；质量统计 MUST 能从产物重算。同一来源与同一范围重复采集 MUST 幂等；数据行一致时即使采集时间、HEAD 等元信息不同也 SHALL 复用既有版本，MUST NOT 因此失败或新建重复版本；数据行不同 MUST 形成新版本而非覆盖已有版本。版本冲突检查 MUST 保护原始 CSV；新 CSV MUST 完整写入后原子发布，目标已存在时不得替换。描述文件与登记记录 MUST 标明数据集来源为分支分析或 PR 分析，并记录产生它的分析标识；PR 分析在目标提交特征已全部保存且可复用时 MAY 不重复登记新数据集版本，但 MUST 在分析记录中保留特征来源与数据集引用；分支分析 MUST 继续登记独立版本。

#### Scenario: 采集并登记数据集

- **WHEN** 采集完成并登记产物
- **THEN** 数据集可按版本查询，描述文件包含字段定义、质量统计与时间范围

#### Scenario: 重复采集同一范围

- **WHEN** 以相同参数再次采集同一仓库同一范围
- **THEN** 数据行一致时幂等返回既有版本；数据行不同时新建版本并保留旧文件

#### Scenario: 仅采集元信息变化

- **WHEN** 同一提交集合被再次采集，只有采集时间或 HEAD 等元信息不同
- **THEN** 复用既有数据集版本，不新增重复版本，也不让本次分析失败

#### Scenario: 原始文件先发生版本冲突

- **WHEN** 候选版本的 CSV 已存在且内容与新采集不同
- **THEN** 保留旧文件字节，尝试内容哈希版本；无法建立新版本则明确失败，不影响旧版本

#### Scenario: 描述或导入内容发生冲突

- **WHEN** CSV 内容一致但描述信息或数据库导入内容与候选版本冲突
- **THEN** 保留原文件和已登记信息，沿用内容哈希版本重试，仍冲突则拒绝覆盖

#### Scenario: 发布前中断或并发发布

- **WHEN** 新文件尚未写完时分析中断，或发布时目标文件已由其他执行建立
- **THEN** 未完成内容不替换正式目标；已存在目标必须重新核对字节，不能用本次临时文件覆盖

#### Scenario: 标记数据集来源

- **WHEN** 数据集由分支分析或 PR 分析产生
- **THEN** 描述文件与查询结果标明来源类型和来源分析标识
- **AND** 旧版本没有来源字段时按分支来源兼容读取

#### Scenario: PR 分析复用已保存特征

- **WHEN** PR 涉及提交在同一仓库、同一 schema 下均已有可复用特征
- **THEN** 分析直接使用这些特征完成打分，不重复登记内容相同的数据集版本
- **AND** 分析记录保留特征来源，界面可说明哪些提交复用了既有特征

### Requirement: RCL-06 采集证据与限制披露

采集 SHALL 记录所用 git 版本、仓库地址或路径、采集时的 HEAD、提交范围、纳入与排除数量以及耗时。产物、运行记录与查询响应 MUST 如实标注两项限制：特征为提交级聚合、标签使用声明中的 SZZ 规则及证据范围。使用本地仓库缓存或复用已保存特征时，产物与分析记录 MUST 说明缓存命中或特征复用来源，MUST NOT 把复用结果表述为重新采集，也 MUST NOT 因复用省略原有限制说明。

#### Scenario: 记录采集证据

- **WHEN** 采集完成
- **THEN** 产物包含 git 版本、仓库标识、HEAD、范围、纳入与排除数量

#### Scenario: 限制随结果披露

- **WHEN** 消费该数据集生成的运行或预测结果
- **THEN** 可看到「提交级聚合」与实际标签规则（完整/行级/简化）的说明，不被表述为已人工确认或文件级样本

#### Scenario: 披露缓存与特征复用

- **WHEN** 分析使用了本地仓库缓存或已保存特征
- **THEN** 产物或分析记录标明复用来源，并继续展示提交级聚合与实际标签规则的限制

### Requirement: RCL-07 服务端同步入口与创建校验

系统 SHALL 提供经授权的同步创建入口，接受仓库地址、分支、起始日期、结束日期、提交上限与打分模型来源选择；起始日期与提交上限 MAY 缺省，缺省时采集全部历史并以执行保护上限为准。地址不可读、不是 Git 仓库、分支不存在或起止日期颠倒 MUST 在创建阶段拒绝并给出可定位原因，MUST NOT 创建注定失败的作业，MUST NOT 以空数据集冒充成功。

#### Scenario: 创建合法同步作业

- **WHEN** 成员提交一个可访问的公开仓库地址、分支与模型来源
- **THEN** 系统创建作业并返回作业标识与初始状态，不再要求用户改用命令行

#### Scenario: 省略范围时采集全部历史

- **WHEN** 成员只提交仓库地址、分支与模型来源，没有起始日期或提交上限
- **THEN** 系统按全部历史创建作业，不因缺少日期或上限拒绝

#### Scenario: 参数在创建时被拒绝

- **WHEN** 地址打不开、仓库不是 Git 仓库、分支不存在或日期颠倒
- **THEN** 创建失败并指明具体字段与原因；不产生作业记录，也不产出空数据集

### Requirement: RCL-08 同步作业状态与可操作失败

系统 SHALL 记录每个同步作业的状态、创建与更新时间、当前阶段与失败原因，状态至少区分排队、采集中、登记中、训练中、完成和失败。进行中的作业 SHALL 暴露真实阶段、排队位置、开始与截止时间，客户端据此显示阶段进度与已用时间，MUST NOT 把排队位置表述为预计等待时长。失败 MUST 说明失败阶段与用户可采取的下一步，MUST NOT 只返回无信息的通用失败。同一仓库同一参数在同一时刻 MUST 只存在一个进行中的作业，重复提交 SHALL 复用该作业而非并行采集。

#### Scenario: 查询进行中与完成的作业

- **WHEN** 客户端按作业标识轮询一个进行中的同步
- **THEN** 依次看到阶段推进与最终完成状态，并能据状态判断还需等待还是可以查看结果

#### Scenario: 阶段进度可见

- **WHEN** 作业从采集推进到登记、训练和评分
- **THEN** 客户端显示对应阶段与已用时间；排队时显示真实排队位置

#### Scenario: 失败给出阶段与下一步

- **WHEN** 克隆失败、没有可打标签的提交、训练样本不足或提交范围为空
- **THEN** 作业标为失败并说明发生在哪一步、用户可采取的下一步

#### Scenario: 并发重复提交合并

- **WHEN** 同一仓库与参数在作业未结束时被再次提交
- **THEN** 系统返回既有作业标识，不启动第二次采集

### Requirement: RCL-09 同步产物串联打分，并允许用户选择打分模型

同步成功后系统 SHALL 把采集产物登记为数据集版本并给提交打分。创建时可选择自动、只用兼容现成模型或强制训练；自动与强制训练 MAY 选择已注册、兼容且依赖可用的方法，缺省逻辑回归，选择现成模型时 MUST NOT 指定方法。方法 MUST 在创建时校验并固定，不满足 schema、输入宽度或依赖时 MUST 拒绝，MUST NOT 静默替换。自动判定按训练窗口提交数与正例数，样本不足且有默认模型时 MUST 降级并注明原因与“未在该仓库验证”；降级 MUST NOT 声称使用所选方法训练。强制训练无法切分时 MUST 失败。训练 MUST 以最新提交前 90 天为截止，分区统计 MUST 与真实成员一致。失败 MUST 保留数据集版本，MUST NOT 覆盖既有版本或模型身份。作业、结果与重试 MUST 保留方法身份，方法不可用 MUST 明确失败并要求重选。

#### Scenario: 自动模式按数据量选择

- **WHEN** 用户未指定打分模型来源并提交同步
- **THEN** 系统在采集完成后按训练窗口的提交数与正例数决定训练或降级
- **AND** 作业记录实际执行的路径与判定依据，界面能说明为什么没有训练

#### Scenario: 数据充足时训练并使用本仓库模型

- **WHEN** 采集完成且训练窗口内的提交数与正例数达到门槛
- **THEN** 使用该数据集训练模型、完成准入登记，并用它给该来源的提交打分
- **AND** 训练、验证与测试分区不包含截止时间及之后的近期提交

#### Scenario: 使用所选方法训练

- **WHEN** 用户在自动或强制训练中选择一个已注册且兼容的方法
- **THEN** 训练使用该方法，产物与模型登记记录该方法身份
- **AND** 结果页面显示实际方法与训练指标，不把它表述为逻辑回归

#### Scenario: 未选择方法

- **WHEN** 用户发起自动或强制训练但没有选择方法
- **THEN** 使用逻辑回归，作业与结果标明该默认方法

#### Scenario: 方法不兼容或依赖缺失

- **WHEN** 所选方法与当前 schema、输入宽度不兼容，或运行依赖未安装
- **THEN** 创建请求被拒绝并说明原因，不创建作业，也不改用其他方法

#### Scenario: 自动降级时不伪造方法

- **WHEN** 自动模式因样本不足降级使用现成模型
- **THEN** 作业仍完成并注明实际模型与降级原因
- **AND** 不声称已使用用户选择的训练方法训练

#### Scenario: 近期提交不参与训练

- **WHEN** 采集结果同时包含截止时间之前和之后的提交，且策略允许训练
- **THEN** 近期提交仍获得本次模型的风险分数，但不出现在训练、验证或测试分区
- **AND** 产物记录的截止时间、可训练样本数、分区数量与真实成员一致

#### Scenario: 样本不足时降级使用兼容模型

- **WHEN** 自动模式下训练窗口的提交数或正例数低于门槛，或时间切分后的测试段没有正例
- **THEN** 作业仍完成，改用提交任务时绑定的、已启用且特征口径兼容的默认模型打分；绑定模型不可用则明确失败
- **AND** 作业与界面注明实际使用的模型、降级原因，以及该模型未在此仓库验证、不展示公开数据集的测试指标

#### Scenario: 用户强制训练但样本偏少

- **WHEN** 用户选择强制训练而训练窗口的提交数或正例数低于建议门槛
- **THEN** 只要时间切分能得到训练集与测试集的两类标签，系统仍执行训练并完成登记
- **AND** 结果页显著标注训练区实际提交数、正例数与指标波动风险

#### Scenario: 强制训练无法切分时失败

- **WHEN** 用户选择强制训练，而时间切分后训练集或测试集缺少某一类标签
- **THEN** 作业失败并说明数据量不足、无法完成时间切分，建议改用特征口径兼容的既有模型
- **AND** 不通过扩大训练范围或加入近期提交来规避失败

#### Scenario: 训练失败但保留数据

- **WHEN** 数据集登记成功而训练或打分失败
- **THEN** 数据集版本仍可查询，作业如实说明未产出可用模型

#### Scenario: 没有兼容模型时明确失败

- **WHEN** 数据不足以训练且用户选择只用既有模型，但模型目录中不存在特征口径兼容的可用模型
- **THEN** 请求或作业失败并说明缺少可用默认模型，不产出没有模型来源的风险列表

#### Scenario: 按原方法重试

- **WHEN** 用户对失败作业按原参数重试
- **THEN** 新作业保留原方法与方法身份
- **AND** 原方法已不可用时明确失败并提示重新选择，不自动换成默认方法

#### Scenario: PR 分析复用特征并跳过重复登记

- **WHEN** PR 分析的目标提交均已有可复用特征，且本次不训练
- **THEN** 分析使用已保存特征完成打分，不重复登记相同数据集版本
- **AND** 记录固定模型、特征来源与打分覆盖，界面不把跳过登记表述为采集失败

#### Scenario: 分支分析仍登记独立数据集

- **WHEN** 用户发起分支分析
- **THEN** 采集产物仍登记为新的数据集版本，即使部分提交可复用既有特征
- **AND** 不因 PR 分析的跳过规则改变分支分析的登记与训练行为

### Requirement: RCL-10 仓库实体与同步归属

系统 SHALL 以规范化仓库地址维护唯一仓库实体，并把同步作业归属到该实体。同一仓库的重复同步和不同分支请求 MUST 不产生第二个仓库。仓库列表 SHALL 支持分页并给出总数；最近请求与最近成功分析 MUST 分别可核对，未成功过的仓库仍可查询并说明状态。

#### Scenario: 地址写法与重复同步
- **WHEN** 对同一仓库以 `.git`、尾斜杠和协议/主机大小写的等价地址重复发起同步
- **THEN** 返回同一仓库身份；各作业保留自己的参数和结果，仓库列表总数不增加

#### Scenario: 首次作业失败
- **WHEN** 新仓库的首次作业失败或范围为空
- **THEN** 仓库仍可查询，成功分析身份缺失、提交数为零，并有对应作业状态；不能冒充已有成功分析

#### Scenario: 仓库列表超过一页
- **WHEN** 仓库数量超过单页上限
- **THEN** 客户端可遍历后续页，总数与实际集合一致；同条件稳定分页不重复或遗漏仓库

### Requirement: RCL-11 成功分析上下文与最近请求分离

仓库详情 SHALL 分别披露最新请求状态和最近成功分析的身份、实际分支、完成时间、HEAD、数据版本、模型来源与局限。最新作业排队、失败或切换分支 MUST NOT 改写成功分析的来源说明。没有成功分析或旧记录未保存某值时 MUST 明确缺失与原因，不用最新请求时间补写。作业结束顺序与创建顺序不同时，成功视图归属 MUST 按明确的完成规则更新。

#### Scenario: 换分支后失败
- **WHEN** main 分析 A 已成功，随后 release 作业 B 失败
- **THEN** 可查看的提交仍来自 A，成功上下文的分支仍为 main；release 只作为 B 的请求分支展示

#### Scenario: 新分析成功
- **WHEN** release 作业 B 成功并成为最新成功分析
- **THEN** 当前成功上下文整体切换到 B，分支、数据、模型和计数来自 B，A 仍可按其分析身份查看

### Requirement: RCL-12 指定分析读取与一致性

仓库详情、提交列表、单条详情和分布查询 SHALL 支持显式指定成功分析身份，并在响应中返回同一仓库与分析身份。未指定时可读取最新成功分析；指定后 MUST 不随新同步自动切换。外仓库、未完成或不存在的分析 MUST 被拒绝并给出可定位错误，不静默改查最新分析。

#### Scenario: 翻页期间新分析完成
- **WHEN** 客户端固定 A 查询第一页，分析 B 完成后客户端继续固定 A 查询第二页、详情和分布
- **THEN** 四类结果仍属于 A，总数与分页一致，不混入 B 的提交或模型

#### Scenario: 非法分析归属
- **WHEN** 请求仓库 A 时指定了仓库 B 的分析身份，或指定进行中/失败的作业
- **THEN** 查询明确失败，不返回 B 的数据、不以 A 最新分析代替请求，也不披露无关资源的内容

### Requirement: RCL-13 服务端检索与确定性分页

仓库提交 SHALL 支持完整标识或标题片段搜索、日期范围、风险/时间排序及 limit/offset 分页。搜索与排序 MUST 覆盖所选分析全集。风险排序按有效分数降序、时间降序、完整 ID 升序；时间排序按时间降序、完整 ID 升序。同条件的总数与页内容 MUST 一致，查询中的 `%`、`_` 和反斜杠按字面匹配。

#### Scenario: 同秒不同风险的时间排序
- **WHEN** 两条提交时间相同，较大 ID 的风险更高，用户选择时间排序
- **THEN** 仍按完整 ID 升序确定先后，不用风险作为隐藏的同秒排序键

#### Scenario: 搜索后续页与特殊字符
- **WHEN** 搜索位于第五页的标题片段，或搜索包含 `%`、`_`、反斜杠的字面片段
- **THEN** 服务端在所选分析全集匹配，返回正确命中及 total；特殊字符不会扩展为通配匹配

#### Scenario: 空结果与页边界
- **WHEN** 分析有 26 条提交，请求 offset=20、limit=10，或筛选后没有命中
- **THEN** 前者返回 6 条且 total=26；后者返回空集合与 total=0，均不产生跨页重复或伪造条目

### Requirement: RCL-14 提交显示元数据与原始改动定位

仓库提交响应 SHALL 提供完整 ID、标题、时间、变更规模及可核验来源；采集确有作者显示名时 SHALL 提供可选作者名，不用邮箱或特征数值推断。支持的公开托管仓库可提供指向同一完整提交的 HTTPS 原始页面；本地仓库、不支持的主机或历史缺失信息 MUST 明确不可用，不生成伪造链接或示例 diff。

#### Scenario: 新旧记录兼容
- **WHEN** 新采集记录具有作者显示名，而既有记录未保存作者信息
- **THEN** 新记录显示真实作者名，旧记录显示未提供；不为旧记录改造模型输入、预测分数或数据集身份

#### Scenario: 原始提交入口
- **WHEN** 公开仓库有受支持且可安全构造的原始提交地址
- **THEN** 地址对应当前仓库与完整提交 ID，明确为外部页面且不含访问凭据；本地仓库保留复制完整 ID 的方式并说明无法外链

### Requirement: RCL-15 项目登记与重命名

系统 SHALL 允许只登记项目而不发起分析。同一规范化仓库地址 MUST 幂等复用既有项目：首次返回 201，重复返回 200，且 MUST 不产生分析记录。系统 SHALL 允许修改项目显示名；显示名 MUST 为 1 至 80 个字符，空白或超长 MUST 以 422 拒绝。

#### Scenario: 只登记项目不运行分析

- **WHEN** 客户端 `POST /api/v1/repositories` 提交公开仓库地址
- **THEN** 返回 201 与项目视图，`latestSync` 为空，该项目的分析记录列表为空

#### Scenario: 同址重复登记复用项目

- **WHEN** 同一地址在不同大小写或带 `.git` 后缀的情况下再次登记
- **THEN** 返回 200 与相同项目标识，不新增项目也不新增分析记录

#### Scenario: 修改显示名

- **WHEN** 客户端 `PATCH /api/v1/repositories/{id}` 提交合法显示名
- **THEN** 返回 200，显示名更新，仓库地址与分析记录保持不变

#### Scenario: 非法显示名被拒绝

- **WHEN** 显示名为空白或超过 80 个字符
- **THEN** 返回 422 `INPUT_INVALID`，项目名称保持不变

### Requirement: RCL-16 分析记录查询

系统 SHALL 提供按项目分页查询分析记录，按创建时间倒序返回。每条记录 MUST 包含状态、进行中的阶段、失败原因、提交范围、分支、数据集版本、模型与运行标识以及 requestId；分页 MUST 稳定，单页上限 100 条。

#### Scenario: 按项目倒序分页

- **WHEN** 客户端 `GET /api/v1/repositories/{id}/syncs?limit=&offset=`
- **THEN** 返回该项目的记录分页，按创建时间倒序，并带总数与分页边界

#### Scenario: 记录包含阶段与失败原因

- **WHEN** 项目中存在进行中与失败的记录
- **THEN** 进行中记录带当前阶段，失败记录带可读失败原因，已结束记录不带阶段

### Requirement: RCL-17 项目与记录删除

系统 SHALL 支持硬删项目（连带其分析记录与提交）与删除单条分析记录。存在进行中分析时删除项目 MUST 返回 409 `CONFLICT_ACTIVE_SYNC`。删除分析记录 MUST 只删除该记录：若记录是项目当前结果（`viewSyncId`），项目 MUST 回到无结果且 MUST NOT 自动回退到其他记录；项目最近请求字段 MUST 重算。删除不存在的项目或记录 MUST 返回 404 `NOT_FOUND`；进行中的记录 MUST 返回 409。

#### Scenario: 硬删项目

- **WHEN** 客户端 `DELETE /api/v1/repositories/{id}` 且项目无进行中分析
- **THEN** 返回 200，项目、其分析记录与提交均不可再读取

#### Scenario: 在途项目拒绝删除

- **WHEN** 项目存在进行中的分析时请求删除该项目
- **THEN** 返回 409 `CONFLICT_ACTIVE_SYNC`，项目与记录保持不变

#### Scenario: 删除当前结果记录回到无结果

- **WHEN** 删除项目当前结果对应的已结束记录
- **THEN** 项目 `viewSyncId` 与相关计数被清空，`latestSyncId` 重算，且不自动指向其他记录

#### Scenario: 删除旧记录不影响当前结果

- **WHEN** 删除一条不是当前结果的已结束记录
- **THEN** 返回 200，项目当前结果与提交统计不变

#### Scenario: 删除不存在或进行中的记录

- **WHEN** 删除不存在的记录或删除进行中的记录
- **THEN** 分别返回 404 `NOT_FOUND` 与 409 `CONFLICT_ACTIVE_SYNC`

### Requirement: RCL-15 指定模型的来源一致性

分析创建 SHALL 接受明确 modelId，指定时使用 generic-model 策略并在入队前校验模型存在、已启用、可加载且 schema 可读取当前仓库特征。requestedModelId 与提交时绑定的 resolvedModelId MUST 持久化并共同参与活动任务去重；实际打分与结果 MUST 保存同一模型身份。指定模型失败 MUST 不静默换成其他模型。未指定时 SHALL 保留现有自动/强制训练策略。

#### Scenario: 指定真实深度或经典模型
- **WHEN** 用户选择兼容的已登记模型并发起分析
- **THEN** 请求和任务保留 requestedModelId，执行实际加载该模型，完成结果 modelId 与指定值一致

#### Scenario: 模型输入不兼容
- **WHEN** 请求指定不可用模型或不能读取仓库采集输入的 schema
- **THEN** 明确拒绝并说明原因，不回退其他模型或创建伪成功结果

#### Scenario: 不同模型不合并为同一活动任务
- **WHEN** 同一仓库、分支、范围、上限和策略分别指定两个不同模型
- **THEN** 不因其他参数相同而复用同一个活动作业；重复提交完全相同模型和参数时复用活动任务

#### Scenario: 指定模型的失败重试
- **WHEN** 用户恢复一条指定模型的失败任务并再次提交
- **THEN** 原指定或已绑定现成模型身份可核对和编辑；未修改模型时新任务继续使用同一 modelId，原失败记录不被覆盖

### Requirement: RCL-18 默认绑定与策略变化

系统 SHALL 以用户明确选择优先，现成模型策略及自动回退在任务提交时绑定默认模型。修改默认 MUST 不改变排队任务身份。绑定模型在执行选取时已停用或不可用 MUST 明确失败；已经开始使用的任务可完成。新分析拒绝停用模型，历史结果和审查计划 MUST 保持原模型身份。

#### Scenario: 默认改变后队列继续使用原模型
- **WHEN** 提交任务绑定模型 A 后，管理员把默认改为 B
- **THEN** 原任务仍使用 A；同参数的新请求绑定 B 且不复用 A 的活动任务

#### Scenario: 自动策略回退与强制训练
- **WHEN** 自动策略数据不足，或用户明确选择强制训练
- **THEN** 自动回退使用提交时绑定的默认且无默认时失败；强制训练保持既有数据条件判定，不因默认设置而改变训练来源

#### Scenario: 停用排队模型
- **WHEN** 任务绑定的模型在执行选取前被停用
- **THEN** 任务保存 MODEL_DISABLED 失败原因，用户重新选择后创建新任务；原任务不产生替代模型结果

#### Scenario: 历史和草稿保留原选择
- **WHEN** 结果对应模型被停用，或打开引用它的草稿和失败重试
- **THEN** 已完成记录仍可读取；原选择可见且标明不可用，用户重新选择前不能提交，不静默改用当前默认

### Requirement: RCL-19 可取消分析与终态保护

普通项目分析 SHALL 支持取消排队和执行中的作业。排队取消立即成为 cancelled；运行取消 SHALL 保存请求并在停止本次执行后结束。重复取消 MUST 幂等；已完成、失败或中断的作业 MUST 以 409 拒绝，未知作业 MUST 返回 404。取消 MUST 保留历史记录、选定模型身份和既有成功结果，不允许迟到的成功或失败覆盖终态。

#### Scenario: 取消排队作业
- **WHEN** 用户取消尚未开始的分析
- **THEN** 返回已取消状态，该分析不再执行，其他排队分析继续按顺序处理

#### Scenario: 取消执行中的分析
- **WHEN** 用户在采集、登记、训练或评分期间提交取消
- **THEN** 响应包含取消请求时间，停止本次执行及其子进程后记录 cancelled，期间不允许删除该记录

#### Scenario: 重复取消与完成竞争
- **WHEN** 相同取消请求重复到达，或取消与完成同时发生
- **THEN** 已取消或取消中的请求幂等；完成先提交时取消返回 409，取消先提交时迟到结果不能发布

#### Scenario: 取消保留来源与历史
- **WHEN** 项目已有成功分析 A，新的分析 B 被取消
- **THEN** A 的提交、分数、模型和当前结果指向保持不变，B 保留原参数供重新分析

### Requirement: RCL-20 执行时限与进程退出

分析 SHALL 从实际开始执行起计算执行时限，排队时间不计入。到期 MUST 停止本次分析进程及其子进程，记录 SYNC_TIMEOUT 并释放执行位置；超时结果 MUST NOT 成为成功结果。服务正常退出 MUST 停止其拥有的分析，重启后遗留任务明确中断；已请求取消的遗留任务 MUST 保留取消意图。执行进程意外退出 MUST 保存可诊断原因。

#### Scenario: 阻塞采集超时
- **WHEN** Git 命令或分析计算超过本次执行截止时间
- **THEN** 本次进程树被停止，作业以 SYNC_TIMEOUT 失败，下一项可执行，旧成功结果保留

#### Scenario: 服务退出与重启恢复
- **WHEN** 服务正常退出，或重新启动时发现未完成作业
- **THEN** 正常退出停止自有执行；遗留作业标为 interrupted，已请求取消的作业标为 cancelled，不自动重跑

#### Scenario: 执行进程意外退出
- **WHEN** 分析进程退出但未保存业务终态
- **THEN** 作业记录 SYNC_WORKER_EXITED，可重新发起分析，队列不会永久占用

### Requirement: RCL-21 队列与控制信息可查询

分析查询 SHALL 返回真实待执行顺序、开始时间、截止时间和取消请求时间。队列位置 SHALL 从 1 开始，执行中和已结束作业位置为空；取消排队项后其他项的位置 SHALL 更新。详情、全局记录、项目记录与项目最近作业 MUST 使用一致含义；位置 MUST NOT 被表述为预计等待时长。

#### Scenario: 查询并取消排队项
- **WHEN** 多个分析排队且其中靠前的一项被取消
- **THEN** 后续查询中的待执行位置向前更新，开始执行后位置为空且有实际开始与截止时间

### Requirement: RCL-22 分支分析完成与失败提醒

分支分析进入终态时系统 SHALL 写入一条站内提醒：完成记录分支与已评分提交数，失败记录错误码与可读原因；取消、中断与 PR 分析 MUST NOT 重复写入同一提醒。提醒 SHALL 提供项目、作业与模型标识，并可从提醒打开固定分析；已读状态 MAY 只保存在当前浏览器。同一作业同一终态 MUST 只产生一条提醒。

#### Scenario: 分析完成

- **WHEN** 分支分析完成
- **THEN** 站内提醒出现「分析完成」，包含分支、评分提交数与模型，可打开该固定分析

#### Scenario: 分析失败

- **WHEN** 分支分析因超时、模型不可用或采集失败结束
- **THEN** 站内提醒出现「分析失败」与可读原因，不冒充部分成功

#### Scenario: 取消或中断不重复提醒

- **WHEN** 用户取消分析，或服务重启把作业标为中断
- **THEN** 不新增「分析完成」或「分析失败」提醒

### Requirement: RCL-23 v2 采集的模型兼容与显式降级

新采集 SHALL 默认使用 `kamei14-git-v2` 并记录其历史规则版本。系统 MUST NOT 把绑定 `kamei14-git-v1` 的模型静默用于 v2 数据集；自动模式下没有兼容模型时 MUST 明确失败或降级并说明需要训练或登记 v2 模型，用户显式选择不兼容模型时 MUST 拒绝。旧 v1 数据集、旧模型和旧分析 MUST 保持可用，MUST NOT 因新采集默认值被改写或删除。

#### Scenario: 只有 v1 模型时分析 v2 数据集

- **WHEN** 新采集产生 v2 数据集，而模型目录中只有绑定 v1 的仓库模型
- **THEN** 自动模式明确说明没有兼容模型并失败或降级，不静默使用 v1 模型给 v2 数据打分

#### Scenario: 显式选择不兼容模型

- **WHEN** 用户为 v2 数据集显式选择绑定 v1 的模型
- **THEN** 请求被拒绝并说明 schema 不兼容，不创建成功结果

#### Scenario: 旧 v1 数据仍可用

- **WHEN** 升级后打开旧 v1 数据集、旧分析或旧模型
- **THEN** 原数据、原分数和原模型身份保持可读，不因 v2 默认值被重算或替换

### Requirement: RCL-24 显式数据集构建任务

系统 SHALL 允许用户从公开仓库、分支和可选时间范围创建只采集并登记数据集的后台任务。任务 MUST 复用现有来源校验、Kamei 14 维采集、简化 SZZ、幂等版本与登记流程，阶段至少区分排队、采集中、登记中、完成和失败。成功任务 MUST 返回数据集版本、质量统计、来源和限制；MUST NOT 训练或选择模型、给提交打分、修改项目当前结果。系统 MUST NOT 接受用户上传 CSV、任意本地路径或外部预计算文件。同参数活动任务 SHALL 复用，失败 MUST 保留可操作原因。

#### Scenario: 从公开仓库构建数据集

- **WHEN** 用户选择当前项目的公开仓库、分支和范围并开始构建
- **THEN** 任务完成采集与登记并返回固定数据集版本
- **AND** 项目当前分析结果和模型选择保持不变

#### Scenario: 同参数重复构建

- **WHEN** 相同仓库、分支和范围已有活动任务或已有内容相同版本
- **THEN** 返回既有任务或复用既有版本，不并行采集或生成重复版本

#### Scenario: 构建失败

- **WHEN** 来源不可读、范围为空、特征计算失败或登记失败
- **THEN** 任务显示失败阶段和原因，不产出可训练的空数据集

#### Scenario: 禁止任意上传

- **WHEN** 客户端尝试上传 CSV、指定服务器文件路径或提交外部标签
- **THEN** 请求被拒绝，任务不创建
