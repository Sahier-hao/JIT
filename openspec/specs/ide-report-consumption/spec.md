# ide-report-consumption Specification

## Purpose
让 IDE 只读消费已生成的提交分析报告，在核对仓库与提交身份后展示风险、候选和建议，并拒绝在过期版本上定位。

## Requirements

### Requirement: IDC-01 导入与身份核对

IDE 扩展 SHALL 允许用户显式导入检查包或报告，并核对报告中的仓库标识、提交 SHA、文件路径与行号。报告与当前工作区或当前提交不匹配时 MUST 显示过期或不匹配状态，MUST NOT 在错误版本上标注位置。

#### Scenario: 身份匹配

- **WHEN** 用户导入与当前工作区仓库和提交一致的报告
- **THEN** 扩展展示提交风险列表与候选位置，并可跳转到对应文件行

#### Scenario: 身份不匹配

- **WHEN** 报告的目标 SHA 与当前检出不一致
- **THEN** 扩展显示不一致状态和原因，不标注代码行

#### Scenario: 文件已变化

- **WHEN** 报告中的文件路径在当前工作区不存在或行号超出范围
- **THEN** 该条目显示不可定位原因，不跳到错误位置

### Requirement: IDC-02 只读与不可信内容

扩展 MUST 只读消费报告，MUST NOT 修改源码、自动应用修复建议或执行报告中的命令与 HTML。报告中的路径、文本和链接 MUST 视为不可信数据，MUST NOT 被当作指令执行。

#### Scenario: 不自动修复

- **WHEN** 用户查看候选与修复建议
- **THEN** 扩展只展示建议和定位信息，不写入或修改源码

### Requirement: IDC-03 与 Web 同一口径

IDE 展示的分数、规则与覆盖 MUST 与 Web 报告使用同一份数据与定义，MUST NOT 把静态规则候选换算成行级缺陷概率，MUST NOT 补造缺失指标。

#### Scenario: 同一条目

- **WHEN** 同一报告在 Web 与 IDE 中打开
- **THEN** 两侧显示相同的提交分数、规则标识和覆盖说明

### Requirement: IDC-04 安装与冒烟验证

系统 SHALL 提供扩展的构建、调试、报告命令生成与演示步骤。扩展 MAY 通过向导收集基准提交、目标提交、真实模型 ID、目录库和产物根目录并复制完整命令，但 MUST NOT 执行该命令或自动导入未经用户选择的报告。验证 MUST 至少覆盖构建、命令生成、报告解析与扩展宿主的实际冒烟；环境不支持宿主时 MUST 记录具体缺口，MUST NOT 宣称 IDE 旅程已通过。持续集成 SHALL 构建可安装的 VSIX 并作为构建产物上传。

#### Scenario: 构建成功

- **WHEN** 按文档执行扩展构建
- **THEN** 生成可安装的扩展包并记录构建输出

#### Scenario: 复制报告生成命令

- **WHEN** 用户选择复制报告生成命令并填写真实参数
- **THEN** 扩展只把命令写入剪贴板，提示用户手动运行后再显式导入报告

#### Scenario: 命令输入无效

- **WHEN** 模型标识为空或任一输入包含换行
- **THEN** 扩展拒绝生成命令并说明原因，不执行终端命令

#### Scenario: 宿主不可用

- **WHEN** 当前环境无法启动 IDE 扩展宿主
- **THEN** 记录不可验证的原因和已完成的构建/静态检查范围

### Requirement: IDC-05 真实仓库中的报告重复使用

VS Code 扩展 SHALL 在真实仓库中导入分析报告并核对仓库、提交与版本身份；工作树存在未提交改动、报告过期、分支切换、文件重命名或删除、路径越界与行号异常时 MUST 给出明确状态，不把候选定位到错误代码。用户 MUST 能显式重新核对、重新复制生成命令或重新导入更新报告。

#### Scenario: 工作树已修改

- **WHEN** 报告对应提交与当前 HEAD 一致，但工作树文件内容已改变
- **THEN** 扩展提示报告与工作树不一致，定位按报告快照只读展示并说明差异

#### Scenario: 分支切换后重复导入

- **WHEN** 用户切换分支后再次导入旧报告
- **THEN** 扩展显示身份不匹配与原因，拒绝把候选定位到当前代码

#### Scenario: 重新生成报告

- **WHEN** 用户确认旧报告已过期
- **THEN** 可以从扩展复制新的生成命令，手动完成后显式导入新报告

### Requirement: IDC-06 CI 报告交接与跨 IDE 可行性

系统 SHALL 让 CI 以固定模型和明确提交范围生成 `jit-commit-analysis-v1` 报告产物；产物 MUST 记录仓库、基准与目标 SHA、模型与运行身份、覆盖范围和限制，供开发者下载并在 IDE 中显式导入。CI 分析失败时 MUST NOT 生成替代报告或把失败当作已交付；CI MAY 上传报告产物，但 MUST NOT 评论 PR、阻断合并或修改分支保护。真实仓库回归 MUST 使用 CI 或离线生成的报告核对仓库、提交与工作树身份；工作树修改、分支切换、文件重命名或删除、过期报告与重新生成 MUST 给出明确状态且不错误定位。Eclipse 与 Visual Studio 的交付 MUST 先给出成本、插件 API、`jit-commit-analysis-v1` 协议复用与风险结论；未实际完成插件时 MUST NOT 声明已交付。

#### Scenario: CI 报告交接

- **WHEN** PR CI 成功生成固定提交范围的报告
- **THEN** 报告产物包含身份、覆盖和限制，开发者可下载并在 IDE 中显式导入核对

#### Scenario: CI 分析失败

- **WHEN** CI 分析失败或缺少固定模型包
- **THEN** 不生成替代报告，失败状态保留，CI 不评论 PR、不阻断合并

#### Scenario: 真实仓库回归

- **WHEN** 在真实仓库导入报告并切换分支、修改工作树或使用过期报告
- **THEN** IDE 显示身份或版本不匹配并拒绝错误定位，恢复后可重新核对或导入新报告

#### Scenario: 跨 IDE 结论

- **WHEN** 审核 Eclipse 与 Visual Studio 的可行性结论
- **THEN** 文档给出成本、插件 API、协议复用和风险，并明确未交付完整插件

### Requirement: IDC-07 Web 端插件使用指南

系统 SHALL 提供可被主导航访问的 IDE 插件指南，说明当前支持的 IDE、报告格式、报告生成、显式导入、身份核对和代码定位流程。指南 MUST 区分能力说明、安装入口和实际可下载产物；没有稳定可下载的扩展包时 MUST 只展示真实构建或安装步骤，MUST NOT 显示无效下载入口。指南 MUST 说明只读、不联网、不执行报告内容、不修改源码的信任边界，并列出匹配、工作树改动、提交过期、Git 状态未知和文件不可定位等状态。

#### Scenario: 首次了解插件

- **WHEN** 已登录用户从主导航打开 IDE 插件指南
- **THEN** 页面按顺序展示生成报告、导入报告、核对身份和打开候选的步骤，并明确 VS Code 是当前已交付范围

#### Scenario: 无稳定下载包

- **WHEN** 当前交付不提供可由该页面稳定下载的 VSIX
- **THEN** 页面展示真实安装命令或构建产物说明，不显示看似可点击但没有目标的下载按钮

#### Scenario: 状态解释

- **WHEN** 用户阅读身份状态说明
- **THEN** 页面解释提交不匹配、工作树有改动、无法读取 Git 和文件行无效时为何拒绝定位

#### Scenario: 窄屏阅读

- **WHEN** 用户以 390px 宽度打开插件指南
- **THEN** 导航、步骤、命令和状态说明均可阅读且页面没有横向溢出
