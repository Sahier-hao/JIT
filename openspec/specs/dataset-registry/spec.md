# dataset-registry Specification

## Purpose

让数据集成为可登记、可按版本引用的事实来源：原始文件、校验值、schema 绑定与质量统计脱离运行产物独立保存，服务与后续运行都从同一份描述文件读取，从而支持新增数据集而不改代码。

## Requirements

### Requirement: DSR-01 数据集描述文件内容

系统 SHALL 为每个数据集版本保存一份描述文件，记录发布者、原始地址、不可变版本、文件 SHA-256、引用、schema 名称、字段定义、质量统计、提交时间范围与样本。描述文件是数据集事实来源，缺少必需字段或字段不可解析 MUST 拒绝登记。

#### Scenario: 登记完整描述文件
- **WHEN** 提交含来源、校验值、schema 与质量统计的完整描述文件
- **THEN** 登记成功并返回数据集名与版本名
- **AND** 再次登记相同内容得到逐字节相同的描述文件

#### Scenario: 描述文件缺少必需字段
- **WHEN** 描述文件缺少校验值、schema 名称或质量统计中的任一项
- **THEN** 拒绝登记并指出缺失字段，不写入部分描述文件

### Requirement: DSR-02 版本命名与不可覆盖

数据集版本名 MUST 由数据集名与时间范围组成，版本名 MUST 唯一；已登记版本以不同内容重新登记 MUST 被拒绝，新时间范围 MUST 形成新版本。描述文件与登记记录 SHALL 标明数据集来源为分支分析或 PR 分析，并记录产生它的分析标识；来源标记 MUST NOT 改变版本命名、唯一性或内容冲突规则。旧版本没有来源标记时 MUST 按分支来源兼容读取。

#### Scenario: 已登记版本内容变化
- **WHEN** 同一版本名以不同的文件校验值或质量统计重新登记
- **THEN** 拒绝并保留原版本，不覆盖已有描述文件

#### Scenario: 登记新时间范围
- **WHEN** 以未登记的时间范围登记同一数据集
- **THEN** 创建新版本目录，原版本保持可引用

#### Scenario: 来源标记不影响版本规则
- **WHEN** 同一版本名以相同内容、不同来源类型重新登记
- **THEN** 复用既有版本，不因来源标记产生重复版本或覆盖冲突

### Requirement: DSR-03 来源校验与不可用拒绝

登记 SHALL 重新计算原始文件的 SHA-256 与字节数并与描述比对；不符、缺失或不可读 MUST 拒绝登记并给出可定位原因，MUST NOT 静默修补或改用其它文件。

#### Scenario: 原始文件被修改
- **WHEN** 原始 CSV 内容与描述文件的校验值不一致
- **THEN** 拒绝登记并报告校验不匹配的文件名

#### Scenario: 原始文件缺失
- **WHEN** 描述文件引用的原始 CSV 不存在
- **THEN** 拒绝登记并报告来源不可用

### Requirement: DSR-04 具名 schema 绑定

描述文件 MUST 引用已注册的具名 schema，字段定义 MUST 与该 schema 声明一致（来源列、是否入模、变换方式）。未知 schema 或字段声明不一致 MUST 拒绝登记，MUST NOT 退回默认 schema。

#### Scenario: 引用未注册 schema
- **WHEN** 描述文件引用一个未注册的 schema 名称
- **THEN** 拒绝登记并报告未知 schema，不生成描述文件

#### Scenario: 字段声明与 schema 不符
- **WHEN** 描述文件把某字段标为入模，而 schema 声明其不可用或已退出模型输入
- **THEN** 拒绝登记并指出不一致的字段

### Requirement: DSR-05 质量统计可重算

登记 SHALL 记录原始行数、纳入行数、各排除规则计数与每字段缺失计数；统计 MUST 能从原始文件重算并保持一致，重算不符 MUST 拒绝登记。

#### Scenario: 质量统计与重算一致
- **WHEN** 按描述文件记录的规则重算原始文件
- **THEN** 行数、排除计数与字段缺失计数与描述一致

#### Scenario: 质量统计被手工改动
- **WHEN** 描述文件的纳入行数与按规则重算的结果不同
- **THEN** 拒绝登记并报告不一致的统计项

### Requirement: DSR-06 服务加载与拒绝启动

服务启动 SHALL 加载已登记的描述文件；描述文件缺失、校验失败或与所供给运行的声明不一致 MUST 拒绝启动并给出可定位原因，MUST NOT 退回内建常量或默认数据集。

#### Scenario: 描述文件缺失
- **WHEN** 服务启动时数据目录中没有已登记的描述文件
- **THEN** 启动失败并报告缺少的描述文件

#### Scenario: 描述文件与运行声明不一致
- **WHEN** 描述文件的数据集版本或校验值与运行声明不同
- **THEN** 拒绝启动并指出不一致的字段

### Requirement: DSR-07 数据集只读查询

系统 SHALL 提供数据集列表与版本列表查询，返回数据集名、版本、来源、校验值、schema 与质量摘要。查询结果 SHALL 标明数据集来源类型、产生它的分析标识、是否被模型、趋势视图或分析记录引用，以及是否属于可清理范围。未知数据集或版本 MUST 返回明确错误，MUST NOT 以空结果冒充成功。

#### Scenario: 查询已登记数据集
- **WHEN** 请求数据集列表或某个数据集的版本列表
- **THEN** 返回已登记条目及其 schema 与质量摘要

#### Scenario: 查询未知数据集
- **WHEN** 请求一个未登记的数据集或版本
- **THEN** 返回可区分的未找到错误，不返回空成功响应

#### Scenario: 按来源筛选
- **WHEN** 管理员按分支或 PR 来源筛选数据集
- **THEN** 只返回对应来源的版本，并显示来源分析标识
- **AND** 旧版本没有来源字段时按分支来源显示

#### Scenario: 查看引用状态
- **WHEN** 查询一个被模型、趋势视图或分析记录引用的数据集版本
- **THEN** 返回引用状态与引用类型，并标明该版本不在可清理范围

### Requirement: DSR-08 PR 数据集保留与清理

系统 SHALL 为 PR 来源的数据集版本提供保留与清理边界。默认保留策略 MUST 按项目保留最近的 N 个 PR 数据集版本，N 可配置且 MUST 有默认值；被模型、趋势视图、分析记录或已知导入过程引用的版本 MUST NOT 被自动删除，分支分析产生的数据集 MUST NOT 参与自动清理。自动删除 MUST 默认关闭，仅在管理员显式启用后按保留策略执行。管理员 SHALL 能查看可清理版本、显式清理并核对删除或跳过原因；删除 MUST 要求二次确认，MUST 同时移除数据集登记、提交与特征记录以及对应文件，失败时 MUST 保留未完成删除并如实报告。清理 MUST NOT 删除模型产物、已完成的 PR 分析记录或项目当前结果。

#### Scenario: 引用保护
- **WHEN** 一个 PR 数据集版本被模型、趋势视图或分析记录引用
- **THEN** 它不在可清理列表，自动与手动清理都跳过并说明引用类型

#### Scenario: 超出保留数量的 PR 数据集
- **WHEN** 某项目的 PR 数据集版本超过保留数量，且较早版本没有引用
- **THEN** 较早版本被列为可清理，默认不自动删除
- **AND** 管理员启用自动清理后才按策略删除，并记录清理结果

#### Scenario: 管理员显式清理
- **WHEN** 管理员选择可清理版本并确认清理
- **THEN** 删除对应登记记录、提交与特征记录和文件，返回实际删除数量与跳过原因
- **AND** 删除不可恢复，界面在确认前说明影响

#### Scenario: 分支数据集不受清理影响
- **WHEN** 管理员清理 PR 数据集
- **THEN** 分支分析产生的数据集及其版本保持可查询和可引用

#### Scenario: 清理失败
- **WHEN** 删除过程中文件或数据库记录失败
- **THEN** 保留未完成的版本并报告失败原因，不把部分删除表述为成功

### Requirement: DSR-09 项目分析数据集只读投影

系统 SHALL 允许普通用户从当前项目的一条成功分支分析读取其绑定数据集的只读摘要。服务端 MUST 使用项目与分析身份解析数据集版本，并校验分析存在、属于该项目、来源为分支且已成功；MUST NOT 接受任意文件路径、全局数据集枚举或由客户端指定的其他数据集版本。摘要 SHALL 包含数据集名、版本、schema、时间范围、纳入/原始/正例/排除统计、字段缺失、来源、标签规则、CSV SHA-256、字节数和限制。失败或跨项目分析 MUST 返回可定位错误，不退回项目最新结果或其他数据集。

#### Scenario: 从成功分析读取数据集

- **WHEN** 用户打开本项目一条已成功分支分析的数据集入口
- **THEN** 页面显示该分析实际绑定的数据集版本和可复核质量摘要
- **AND** 返回的数据集身份与该分析的 `datasetVersion` 完全一致

#### Scenario: 失败或跨项目分析

- **WHEN** 请求的数据集投影引用失败分析、其他项目分析或不存在的分析
- **THEN** 请求被拒绝并说明原因，不返回其他分析或最新成功分析的数据集

#### Scenario: 不暴露全局数据集库

- **WHEN** 普通用户未携带管理员会话请求全局数据集列表或其他项目的数据集
- **THEN** 服务端不提供全局浏览能力；管理员全量数据集接口仍要求管理员会话

#### Scenario: 数据版本不可用

- **WHEN** 分析记录存在但绑定数据集描述缺失、校验失败或未登记
- **THEN** 页面显示数据不可用及原因，不展示示例数据或另一版本替代

### Requirement: DSR-10 可校验数据集导出

系统 SHALL 为项目范围内的数据集版本提供权威 ZIP 与 XLSX 下载。ZIP MUST 包含原始 CSV、描述文件和 SHA-256 清单；XLSX MUST 包含数据工作表和元数据工作表。两个下载 MUST 使用包含数据集版本且适合识别完整哈希的文件名，服务端 MUST 在生成前重新校验源文件字节与登记 SHA-256。元数据 SHALL 包含版本、完整文件哈希、schema、时间范围、标签规则、数据限制与生成时刻。校验失败、文件缺失或版本不属于当前分析时 MUST 拒绝下载。

#### Scenario: 下载权威 CSV 包

- **WHEN** 用户下载当前分析绑定的数据集
- **THEN** 获得包含 CSV、manifest 和 SHA256SUMS 的 ZIP
- **AND** 包内文件哈希与页面显示的登记哈希一致

#### Scenario: 下载 XLSX 便捷视图

- **WHEN** 用户选择 XLSX 下载
- **THEN** 工作簿包含数据工作表和带版本、哈希、schema、标签与限制的元数据工作表
- **AND** XLSX 不替代权威 ZIP 的完整性身份

#### Scenario: 导出前文件损坏

- **WHEN** CSV、描述文件或决策旁车在登记后被修改或删除
- **THEN** 下载失败并指出不可用文件，不生成看似成功的部分导出

#### Scenario: 文件名可核对

- **WHEN** 用户同时下载两个数据集版本
- **THEN** 文件名包含各自版本和可区分的哈希片段，已下载文件不会相互覆盖

### Requirement: DSR-11 批处理数据版本的来源与重建

登记批处理产出的数据版本时，系统 SHALL 额外记录仓库、固定 revision、观察终点、SZZ 版本、成熟期与逐仓库计数，并保持与单项目版本的相同哈希与不可覆盖规则。旧版本标签 MUST NOT 被新 SZZ 规则改写；重建 MUST 生成新版本并说明与旧版本的关系。

#### Scenario: 重建旧 simple-SZZ 数据

- **WHEN** 使用完整 SZZ 重建同一仓库历史
- **THEN** 生成新的数据版本身份，旧版本文件与标签保持不变，两者可并列核对

#### Scenario: 源文件变化

- **WHEN** 同名版本的 CSV 内容或描述哈希与登记不一致
- **THEN** 登记失败并给出具体版本与哈希，不覆盖既有文件
