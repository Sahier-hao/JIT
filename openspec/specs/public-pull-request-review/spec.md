# public-pull-request-review Specification

## Purpose

让评审者从一个实际可访问的公开 GitHub 仓库或 PR 接手真实改动，在固定版本中核对作者说明、文件和代码，并可使用独立且可追溯的模型线索安排阅读。

## Requirements

### Requirement: PPR-01 公开来源接入与发现

用户 SHALL 能在项目 PR 审查中读取该项目已缓存的真实 PR 清单；旧 PR 深链接 SHALL 继续打开对应工作单。清单 SHALL 分页显示标题、作者、更新时间和状态，支持开放/历史与显式刷新；对已有保存分析的 PR，清单 SHALL 显示该快照提交的最高分数与评分覆盖数，并支持当前页按更新或按风险排序；未分析的 PR MUST NOT 被当作低风险，按风险排序 MUST NOT 声称覆盖全部 PR。读取缓存 MUST NOT 访问远端，MUST NOT 据缓存缺失判定 PR 已关闭。具体 PR 直接打开工作单。无需管理员凭据或特征文件，私有及不支持来源 MUST 明确拒绝。读取失败或限流 MUST 保留输入与重试入口，不伪装为空列表。

#### Scenario: 仓库没有开放 PR
- **WHEN** 公开仓库没有开放 PR
- **THEN** 显示明确空态并允许选择历史 PR 复盘，历史关闭或合并状态持续可辨

#### Scenario: 读取失败
- **WHEN** GitHub 不可访问或请求受限
- **THEN** 显示原因与 requestId，输入仍在，不能声称没有待处理工作

#### Scenario: 项目清单缓存
- **WHEN** 用户首次打开项目 PR 审查且尚未完成远端检查
- **THEN** 显示缓存时间或明确空态并提供显式刷新入口，不自动联网

#### Scenario: 分页未完成
- **WHEN** PR 发现分页尚未取完
- **THEN** 页面说明当前清单覆盖范围，不据未返回条目判定 PR 已关闭

#### Scenario: 按风险排序当前页
- **WHEN** 用户把已缓存的 PR 清单切换为按风险排序
- **THEN** 已有保存分析的 PR 按最高提交分排序，未分析或未取到分数的 PR 排在后面并明确不能视为低风险；页面说明排序只影响当前页，不声称是全部 PR 的优先级

### Requirement: PPR-02 固定来源与不可变快照

工作单代码来源 SHALL 包含所属项目、PR、基准及目标 SHA、分支、作者原始说明、提交和读取时间。PR 的所属项目与 head 代码来源 SHALL 分开记录：fork PR 属于基项目，代码来源保留实际 fork 仓库，MUST NOT 为 fork 另建可见项目。同一项目内重复读取相同基准与目标 MUST 复用原快照；不同版本单独保存。读取文件期间版本改变 MUST 拒绝混合快照并要求重读，原快照保持不变。新 PR 分析 MUST NOT 改写项目当前分支结果或默认分支。

#### Scenario: 准备期间作者继续提交
- **WHEN** 读取文件前后的远端基准或目标不一致
- **THEN** 不保存混合版本，显示版本变化，旧来源与个人草稿保持可用

#### Scenario: 重开历史版本
- **WHEN** PR 已有新版本，用户重开保存的旧版本
- **THEN** 作者说明、Diff 和来源身份属于该旧快照，不用当前远端代码替代

#### Scenario: fork PR 归属
- **WHEN** PR head 来自 fork 仓库
- **THEN** 任务归属基项目，代码来源保留实际 fork，不额外建立 fork 项目，项目当前分支结果不变

#### Scenario: 同名重复项目
- **WHEN** 两个项目的规范化 GitHub 地址相同但项目 ID 不同
- **THEN** 快照按项目隔离保存，不因唯一键冲突合并项目或改写原项目 ID

### Requirement: PPR-03 文件 Diff 与上下文

用户 SHALL 可按文件读取真实 Diff 以及固定 SHA 的上下文，识别新增、删除、重命名和不可展示内容。加载与未覆盖范围 MUST 可辨；不完整 Diff、二进制、过大文件或读取失败不能当作空变更或完整阅读。上下文 MUST 只接受该快照中的文件，不能通过任意路径借用其他来源。

#### Scenario: Diff 不完整
- **WHEN** 远端未提供完整补丁
- **THEN** 显示限制，允许按文件请求两侧上下文，未取得完整内容前不开放标记已阅读

#### Scenario: 删除或重命名
- **WHEN** 文件在某侧不存在或已重命名
- **THEN** 显示对应侧不存在及原路径，位置链接仍绑定正确的基准或目标 SHA

### Requirement: PPR-04 独立模型线索

模型线索 SHALL 以「审查优先级」先于代码展示：提交按保存分数从高到低排列，文件按触及该文件的提交最高分排序，并标注仅用于排序，不是 PR 整体缺陷概率、文件级缺陷概率或行级定位。工作单 SHALL 提供提交队列；点击提交 SHALL 把文件列表限定为该提交触及的文件，并允许切回全部文件。文件风险与提交文件 MUST 只来自该快照提交的已保存分数与提交文件映射；旧分析缺少映射时 MUST 保持全部文件并说明不能按提交或风险筛选，不得猜测。模型分析 SHALL 由 PR 清单的批量入口发起，并允许先选择真实登记、兼容且已启用的模型；只读详情 MUST NOT 提供模型选择、分析生成、重试或取消入口，只展示已保存的分数与任务。只读详情 SHALL 允许查看并主动生成单条已评分提交的模型解释；解释生成 MUST NOT 改变任何已保存分数、切换模型或构成新分析。每份结果 MUST 显示实际使用的模型与固定目标 HEAD；返回的分析 HEAD、快照或模型不匹配时 MUST 不采用分数。模型失败 MUST 不阻断代码阅读和个人记录。旧关联只证明固定 HEAD 与已有快照关联，MUST 标注其不能证明独占基项目绑定或提交前模型绑定。

#### Scenario: 模型不可用

- **WHEN** 所选模型停用、缺失或推理失败
- **THEN** 列表或记录显示原因；已有人工文本与代码操作继续可用，不静默换模型

#### Scenario: 只覆盖部分提交

- **WHEN** 部分 PR 提交未取得模型分数
- **THEN** 显示覆盖计数及缺失，不把未覆盖条目当作低风险，原分析仍可单独打开核对

#### Scenario: 自动与手动结果并列

- **WHEN** 同一 PR 同时存在项目自动模型与用户手动模型的结果
- **THEN** 两者并列显示、互不覆盖，自动模型不写入个人轮次已选模型身份

#### Scenario: 旧关联限制

- **WHEN** 读取迁移前的 PR 评分关联
- **THEN** 标注其只证明固定 HEAD 与已有快照关联，不声称新契约的独占绑定或提交前模型绑定

#### Scenario: 覆盖不完整提醒

- **WHEN** 自动分析只覆盖部分 PR 提交
- **THEN** 提醒与线索区域明确不能视为低风险结论，保留覆盖计数与缺失范围

#### Scenario: 文件级风险映射缺失

- **WHEN** 分析来自旧任务或未记录提交文件路径
- **THEN** 文件列表保持原顺序并说明没有文件级排序依据，不按缺失分数推断低风险

#### Scenario: 风险排序先于代码

- **WHEN** 用户打开只读详情或工作单
- **THEN** 审查优先级与高风险提交先于文件 Diff 展示，文件列表默认按风险排序并可切回路径顺序

#### Scenario: 查看提交级模型解释

- **WHEN** 用户在只读详情选择一条已有模型分数的提交并展开模型解释
- **THEN** 显示该固定分析已保存的解释，或提供显式的生成入口
- **AND** 生成结果只作为该分析的保存事实，原分数、模型身份和其他提交保持不变

#### Scenario: 解释不可用

- **WHEN** 原分析模型不可用、解释不支持或生成失败
- **THEN** 显示原因并保留原分数与代码阅读，不切换模型、不伪造解释

#### Scenario: 解释请求未完成时切换提交

- **WHEN** 用户在解释读取或生成完成前切换提交或快照
- **THEN** 旧请求结果不出现在新上下文，解释始终属于当前固定分析与当前提交

### Requirement: PPR-05 只读详情与显式开始审查

项目 PR 清单 SHALL 先打开只读详情，展示来源、模型风险概览、高风险提交、按风险排序的文件、作者说明和文件 Diff。作者说明 SHALL 按 Markdown 渲染标题、列表、表格、行内代码、代码块和链接，MUST NOT 渲染原始 HTML；作者没有填写时如实说明。只读详情 SHALL 提供按提交标题或 SHA 的本地搜索，并提供逐提交模型解释入口；搜索、排序与覆盖计数 SHALL 各归其组，控件同高且互不遮挡，也不遮挡表头。查看解释 MUST NOT 离开只读详情，只读详情 MUST NOT 跳转到分支分析页或其他分析视图。只读详情 MUST NOT 提供模型选择、分析生成、重试或取消分析的入口；分析结果只读展示已保存的任务与分数。只有用户明确创建审查工作单才创建工作单并写入「我的审查」；已有工作单 SHALL 显示继续审查。读取详情 MUST NOT 创建或改写个人草稿。

#### Scenario: 首次查看 PR

- **WHEN** 用户在项目 PR 清单选择一个尚未开始审查的 PR
- **THEN** 打开只读详情，展示来源和已保存的风险结果，不创建个人草稿，也不出现在「我的审查」

#### Scenario: 只读预览标识

- **WHEN** 用户打开尚未创建个人工作单的 PR 详情
- **THEN** 页面标明「只读预览」，主操作明确为「创建审查工作单」
- **AND** 创建后进入的编辑视图标明「个人工作单」

#### Scenario: 明确开始审查

- **WHEN** 用户在只读详情点「创建审查工作单」
- **THEN** 创建固定快照的个人工作单并进入编辑视图，此前的只读浏览不产生草稿

#### Scenario: 已有工作单

- **WHEN** 该 PR 已有本浏览器工作单
- **THEN** PR 清单显示「继续审查」，打开后直接进入原工作单，不覆盖原轮次

#### Scenario: 读取只读详情失败

- **WHEN** PR 来源读取失败
- **THEN** 显示原因与重试/返回项目 PR 的入口，不创建个人草稿

#### Scenario: 搜索提交

- **WHEN** 用户在只读详情输入提交标题片段或 SHA
- **THEN** 列表只显示匹配的已载入提交，并保留当前排序
- **AND** 没有匹配时明确说明，不展示其他提交代替

#### Scenario: 不离开只读详情

- **WHEN** 用户查看模型风险概览或某条提交的解释
- **THEN** 页面停留在当前 PR 只读详情，不跳转到分支分析页或另一来源的分析视图

#### Scenario: 作者说明是 Markdown

- **WHEN** 作者的 PR 说明包含标题、列表、行内代码或代码块
- **THEN** 只读详情按 Markdown 排版显示，不显示 `##`、`-`、反引号等原始标记
- **AND** 原始 HTML 不被执行或渲染；没有说明时明确说明作者未填写

#### Scenario: 工具条控件

- **WHEN** 用户在只读详情查看提交工具条
- **THEN** 覆盖计数、搜索框与排序按钮各归其组、可见高度一致
- **AND** 搜索框文字不被图标遮挡，控件不遮挡表头或列表首行

### Requirement: PPR-06 代码候选位置与模型线索分离

PR 工作单 SHALL 在模型风险线索之外单独展示静态分析候选位置，每条候选绑定固定快照的侧别、文件、行号和规则来源，并允许审查者确认、驳回或暂缓且填写理由。候选位置 MUST NOT 被换算成行级缺陷概率、提交分数或 PR 整体风险；模型分数也 MUST NOT 被表述为候选位置。部分文件或语言未分析时 MUST 明确说明覆盖范围，MUST NOT 把未分析当作无候选或无缺陷。

#### Scenario: 工作单同时显示两类线索

- **WHEN** 一个固定快照同时有模型提交分数和静态候选位置
- **THEN** 工作单分别显示两类线索及来源、版本和覆盖范围，不合并成单一风险值

#### Scenario: 候选位置缺少模型分数

- **WHEN** 某文件有候选位置但模型未覆盖该提交
- **THEN** 页面保留候选位置并说明模型未覆盖，不把缺失分数当作低风险

#### Scenario: 部分文件未分析

- **WHEN** 快照包含二进制、生成文件或不支持语言的文件
- **THEN** 覆盖说明列出未分析文件及原因，候选结果不声称覆盖全部文件
