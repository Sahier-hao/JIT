# product-documentation Specification

## Purpose
让首次接触产品的用户能完成一条真实审查流程，也让已有用户能从业务界面快速查到当前界面中的术语、分数、代码线索、标签和失败处理方式。

## Requirements

### Requirement: PD-01 公开文档路由

系统 SHALL 提供 `#/docs` 与 `#/docs/:slug`。两个地址 MUST 允许匿名访问，且 MUST NOT 依赖工作台项目、模型、报告或登录接口才能读取已构建的文章。

#### Scenario: 匿名直接打开文章

- **WHEN** 未登录用户在无痕会话直接打开 `#/docs/first-pr-review`
- **THEN** 页面显示该文章的完整正文、章节导航与本页目录
- **AND** 不跳转登录页，也不请求工作台项目或模型数据

#### Scenario: 后端不可用

- **WHEN** 文档页面已构建而项目、模型与报告接口均不可用
- **THEN** 文档首页、文章与本地搜索仍可读取和操作

#### Scenario: 未知文章

- **WHEN** 用户打开 `#/docs/not-a-published-article`
- **THEN** 文档外壳内显示文章不存在状态与「返回文档首页」入口
- **AND** 不显示其他文章冒充目标文章

### Requirement: PD-02 文档首页与分组入口

文档首页 SHALL 优先展示《完成第一次 PR 审查》，并 SHALL 提供「快速开始」「使用指南」「背景知识」「常见问题」四组导航。每组 MUST 至少包含一篇已发布文章及可点击入口。

#### Scenario: 首次访问文档

- **WHEN** 用户打开 `#/docs`
- **THEN** 首屏可见《完成第一次 PR 审查》及其入口
- **AND** 四个分组均显示真实文章链接

#### Scenario: 从分组进入文章

- **WHEN** 用户选择任一分组文章
- **THEN** 地址变为对应 `#/docs/:slug`，正文属于所选文章

### Requirement: PD-03 文档阅读布局

桌面文章页 SHALL 同时提供左侧文章章节导航、中间正文和右侧本页目录，并 SHALL 标出当前文章。窄屏 SHALL 折叠章节导航；在约 390px 宽度下，正文、表格、图片与代码块 MUST 可读，页面 MUST NOT 出现横向滚动，宽表格与代码 SHALL 只在自身容器内滚动。

#### Scenario: 桌面阅读

- **WHEN** 用户在桌面视口打开一篇含多个小节的已发布文章
- **THEN** 左侧章节、正文和右侧本页目录同时可见
- **AND** 当前文章在章节导航中有可辨认的选中状态

#### Scenario: 390px 阅读

- **WHEN** 用户在 390px 视口打开含表格、图片和代码块的文章
- **THEN** 章节导航可展开和收起，正文仍可阅读
- **AND** 页面级横向滚动宽度不超过视口宽度

### Requirement: PD-04 稳定小节地址

文章 SHALL 使用查询参数 `section` 和小节稳定标识形成可刷新、可分享的小节地址。直接打开、刷新以及浏览器前进后退 MUST 回到同一文章与同一小节；无效小节 MUST 保留文章并说明该小节不存在，MUST NOT 把地址解析成未知页面。

#### Scenario: 直接打开小节

- **WHEN** 用户打开 `#/docs/reading-results?section=commit-score`
- **THEN** 页面打开《怎么看风险分和代码线索》并定位到提交级风险分小节

#### Scenario: 刷新与前进后退

- **WHEN** 用户从文章顶部进入另一小节后刷新或使用浏览器后退
- **THEN** 文章身份不变，定位恢复为地址中的小节

#### Scenario: 无效小节

- **WHEN** 用户打开文章地址但 `section` 不存在
- **THEN** 页面继续显示该文章，并提示可返回本页目录重新选择

### Requirement: PD-05 本地中文搜索

文档 SHALL 提供不依赖服务端的本地中文搜索，覆盖文章标题、小节标题、正文与已登记常用同义词。标题和小节匹配 SHALL 优先于正文匹配；结果 MUST 带上下文摘要并可定位到命中文章小节。搜索 MUST 支持键盘选择、Enter 打开和 Escape 关闭，无结果时 SHALL 给出换词提示。

#### Scenario: 搜索真实术语

- **WHEN** 用户依次搜索「风险分」「私有仓库」「模型兼容」「VS Code」
- **THEN** 结果包含能回答该问题的文章或小节
- **AND** 选择结果后打开对应文章并定位到相关小节

#### Scenario: 键盘操作

- **WHEN** 用户输入查询后按方向键并在结果上按 Enter
- **THEN** 当前高亮结果被打开
- **AND** 搜索层可用 Escape 关闭并把焦点留在搜索输入框

#### Scenario: 无结果

- **WHEN** 查询没有匹配任何已发布内容
- **THEN** 页面明确显示没有结果并提示换用按钮名称、页面名称或术语

### Requirement: PD-06 内容来源与发布清单

文档正文 MUST 以 Git 中的 Markdown 为来源，并由专门的公开内容目录和发布清单声明文章标识、标题、摘要、分组与排序。导航、文章目录和搜索 MUST 共用同一清单与正文；未列入清单的内容 MUST NOT 进入构建产物或搜索索引。

#### Scenario: 发布一篇新文章

- **WHEN** 维护者加入 Markdown 并更新发布清单
- **THEN** 文章可以从稳定地址打开，并出现在声明的分组、章节导航与搜索中

#### Scenario: 未发布的内部资料

- **WHEN** 管理员数据集记录、验证报告、模型维护资料或私有仓库资料存在于仓库其他目录
- **THEN** 文档构建产物与搜索索引不包含这些内容

### Requirement: PD-07 首版文章集合

首版 SHALL 发布九篇中文文章：完成第一次 PR 审查、分析分支与查看风险趋势、处理 PR 与作者更新、从数据到训练预测与评估、在 VS Code 中检查提交、什么是 JIT 缺陷预测、怎么看风险分和代码线索、缺陷标签与评估指标、常见问题。

#### Scenario: 首版目录完整

- **WHEN** 用户浏览文档首页与章节导航
- **THEN** 九篇文章均有稳定地址和可点击入口
- **AND** 四组导航均有内容

### Requirement: PD-08 操作说明与事实边界

操作指南 SHALL 按「前置条件 → 实际入口和步骤 → 成功后看到什么 → 常见失败和下一步」组织。文档 MUST 使用当前界面的按钮与菜单名称，并区分提交级风险分、文件阅读顺序、静态规则命中和行级研究排序；私有仓库条件、模型兼容和标签成熟度 MUST 与当前服务行为一致。

#### Scenario: 第一次 PR 审查

- **WHEN** 用户照《完成第一次 PR 审查》操作
- **THEN** 文档说明可替换的公开示例 PR 条件、登录或注册、添加项目、查看 Diff、创建或继续工作单、记录带代码证据的问题以及导出 Markdown
- **AND** 说明模型不可用时仍可继续人工审查

#### Scenario: 模型兼容为空

- **WHEN** 模型选择器没有可用兼容模型
- **THEN** 常见问题与相关指南说明训练并登记模型、请管理员开放模型和当前原有模型不可用时需显式重选

#### Scenario: 私有仓库

- **WHEN** 用户同步私有仓库 PR 失败
- **THEN** 文档说明服务端 GitHub 访问前提、个人中心检测入口、失败反馈和权限范围
- **AND** 不宣称浏览器自行持有 GitHub 令牌

### Requirement: PD-09 业务页面上下文帮助

分支分析 SHALL 提供直达提交级风险分说明的帮助入口。PR 预览与审查工作单 SHALL 提供直达代码线索说明的帮助入口，并从新标签页打开以保留当前 Diff、选中文件和草稿。模型评估页有可辨认的指标解释位置时 SHALL 提供对应帮助入口。帮助入口 MUST NOT 改变原有业务权限或写操作。

#### Scenario: 分支分析查看分数说明

- **WHEN** 用户在有风险结果的「分支分析」打开帮助
- **THEN** 进入《怎么看风险分和代码线索》的提交级风险分小节

#### Scenario: 工作单保留现场

- **WHEN** 用户在有选中文件和问题草稿的 PR 工作单点击帮助
- **THEN** 文档在新标签页打开相关小节
- **AND** 原标签页中的 Diff、选中文件与草稿仍可继续使用

### Requirement: PD-10 文档内链接兼容

文档 Markdown SHALL 支持指向现有应用地址与登录流程的站内链接，并保持外部链接新开标签页。文档场景之外继续使用既有 Markdown 的链接行为；正文 MUST 继续禁止原始 HTML 执行，图片 MUST 使用随构建提供的公开资源。

#### Scenario: 文档进入需要登录的操作

- **WHEN** 匿名用户从文档点击需要登录的工作台地址
- **THEN** 使用现有登录流程，并在登录后保留可用目标

#### Scenario: 既有 Markdown 调用方

- **WHEN** 项目作者说明、PR 结论或其他既有页面按原方式渲染 Markdown
- **THEN** 链接仍新开标签页，正文 HTML 处理边界不变
