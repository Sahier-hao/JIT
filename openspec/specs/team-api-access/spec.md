# team-api-access Specification

## Purpose

为团队新增的模型目录、登记和预测接口建立明确的成员与管理员访问边界，让公共模型登记只能由授权维护者完成，并使失败诊断可以追踪而不会泄漏凭据或冒充已经建立个人账户系统。

## Requirements

### Requirement: TAA-01 新接口的两类凭据

系统 SHALL 为本 change 新增的接口校验成员或管理员 Bearer 凭据；凭据 MUST 为独立且不相同的部署配置，不内置默认秘密，不由客户端自报角色。配置缺失或两类凭据相同时，新接口 MUST 返回 503 ACCESS_CONFIG_INVALID，不降级为匿名访问；不建立个人账户、登录或会话。

#### Scenario: 有效成员与管理员凭据
- **WHEN** 请求使用已配置的合法成员或管理员 Bearer 凭据
- **THEN** 服务据凭据确定对应角色，而不是读取请求正文、查询参数或自报角色头

#### Scenario: 部署权限配置不完整
- **WHEN** 任一必需凭据未配置或两类凭据相同
- **THEN** 新接口拒绝服务并给出配置错误，不输出配置值，原历史接口不因此失效

### Requirement: TAA-02 管理员登记与成员预测权限

系统 SHALL 只允许管理员发现候选及登记模型；成员和管理员 SHALL 都能查询模型、查询 schema、创建预测与重开批次。缺少或无效凭据 MUST 返回 401 AUTH_REQUIRED；合法成员执行管理员操作 MUST 返回 403 ACCESS_DENIED，且不发现候选、加载模型或写入业务数据。

#### Scenario: 成员尝试登记
- **WHEN** 成员凭据请求候选列表或登记接口
- **THEN** 返回 403，候选信息不泄露，模型与运行目录不发生变动

#### Scenario: 匿名请求或角色伪造
- **WHEN** 无凭据、错误凭据、错误认证格式，或成员附带自报管理员角色
- **THEN** 无效认证返回 401，合法成员仍按成员权限处理，不能获得管理员操作能力

#### Scenario: 成员正常使用模型
- **WHEN** 合法成员或管理员查询模型／schema、提交合法预测或重开已保存批次
- **THEN** 服务按对应业务契约响应；两类凭据共享团队结果，不声称具有个人数据隔离

### Requirement: TAA-03 诊断可追踪且不含秘密

系统 SHALL 为新接口响应提供可关联的 requestId，并按角色、操作、结果及业务身份记录必要诊断。响应、日志、数据库记录、导出和测试证据 MUST NOT 包含 Bearer 凭据、完整认证头或服务器绝对路径。管理员与成员角色 MUST NOT 被描述为可识别具体个人的审计身份。

#### Scenario: 登记或预测失败
- **WHEN** 授权请求因输入、模型或存储问题失败
- **THEN** 错误含稳定 code、可公开 message 与 requestId，必要时按字段定位，诊断不含秘密及内部绝对路径

#### Scenario: 检查权限测试证据
- **WHEN** 汇总正常、401、403 与配置失败路径的日志和证据
- **THEN** 能按 requestId 关联操作结果，但不能从证据恢复真实配置凭据，也不归因于不存在的个人账户

### Requirement: TAA-04 原入口与本机维护权限兼容

系统 SHALL 保留原 GET /api/review-batch 的无鉴权、本机监听、响应及错误语义。CLI 登记 SHALL 以本机维护权限调用与 HTTP 相同的业务准入，不依赖团队 Bearer 凭据；其诊断 SHALL 明确标记 CLI 来源，不把本机维护通道开放为 HTTP 认证绕过。

#### Scenario: 原历史回放回归
- **WHEN** 团队凭据未配置，或成员使用既有历史回放及旧 CLI 命令
- **THEN** 原 GET 与 fetch、run、verify、compare、compare-methods、证据命令保持既有行为，历史请求不因新接口配置而要求登录或写入目录

#### Scenario: 本机维护者执行登记
- **WHEN** 维护者在服务主机通过 CLI 登记合法产物
- **THEN** 使用同样完整校验及持久身份规则，并记录本机 CLI 通道；HTTP 匿名请求仍返回 401
