# project-pr-tracking Specification

## Purpose
让项目在用户离开页面后继续发现真实 PR 更新，以固定快照和固定模型自动安排分析，并在资源、重试和暂停边界内保持结果可追溯。

## Requirements

### Requirement: PPT-01 项目级显式启用与固定模型

项目 PR 自动跟踪 SHALL 由项目显式启用，旧项目升级后默认关闭。启用时 SHALL 选择真实登记、兼容且已启用的模型并确认将处理的开放且非草稿 PR；管理员修改默认模型 MUST NOT 替换已保存的自动模型。PR 自动跟踪 MUST NOT 对非公开 GitHub 项目启用。

#### Scenario: 首次启用
- **WHEN** 用户在项目内选择模型并确认处理现有开放 PR
- **THEN** 保存跟踪配置并排队，确认内容显示数量、固定模型与资源范围

#### Scenario: 默认模型变化
- **WHEN** 管理员修改默认模型或停用原自动模型
- **THEN** 已保存的自动模型不变；原模型不可用时显式失败并等待处理，不静默替换

#### Scenario: 非 GitHub 项目
- **WHEN** 项目来源不是公开 GitHub
- **THEN** 跟踪接口拒绝启用并说明不支持，分支分析与趋势仍可用

### Requirement: PPT-02 快照、意图与任务复用

后台发现 SHALL 读取真实开放 PR 并固定 base/head 快照。分析意图 SHALL 由基项目、PR、快照、真实模型与评分契约共同确定；同快照同模型 MUST 复用在途或成功任务，显式更换模型或新快照才产生新意图。PR 任务 MUST NOT 改变项目当前分支结果。PR 清单 SHALL 提供批量分析全部开放 PR 的入口，并允许先选择真实兼容模型；已有完成分析且快照未变化的 PR MUST 跳过。PR 分析任务 SHALL 显示在 PR 审查页的独立记录中，MUST NOT 混入项目分支分析记录。任务状态 SHALL 如实呈现排队、分析中、完成、失败、取消与中断，MUST NOT 把中断或取消显示为分析中。

#### Scenario: 重复检查同一快照
- **WHEN** 同一 PR 快照与模型已有在途或成功任务
- **THEN** 不重复入队，复用原任务或结果

#### Scenario: 作者推送新版本
- **WHEN** 远端 head 变化形成新快照
- **THEN** 产生新意图并排队，旧结果保留为历史

#### Scenario: 显式更换自动模型
- **WHEN** 用户明确更换项目自动模型
- **THEN** 同快照下产生新意图，旧模型结果仍可读且不覆盖当前分支结果

#### Scenario: 批量分析全部 PR
- **WHEN** 用户选择模型并确认「分析全部 PR」
- **THEN** 所有尚无完成分析的开放 PR 进入后台队列，已完成的 PR 跳过；PR 记录显示排队与进度

#### Scenario: 中断任务
- **WHEN** 服务停止导致 PR 分析中断
- **THEN** 记录显示「已中断」，不显示「分析中」，可重新发起批量分析补齐

### Requirement: PPT-03 队列、轮转与并发边界

每个 PR SHALL 至多一个在途自动分析和一个最新待处理目标；每项目每轮最多深入20个PR并持久轮转，每项目每轮最多新增1个分析，全局自动排队上限2个。执行仍为单 worker；自动调度 MUST NOT 取消手动任务或插队已有分支任务。

#### Scenario: 快速连续推送
- **WHEN** 同一 PR 连续出现多个新版本
- **THEN** 仅保留最新待处理目标，旧的未开始自动请求标为过时

#### Scenario: 多个项目同时到期
- **WHEN** 多个项目在同一轮到期
- **THEN** 按持久游标轮转，不在一轮内深挖超过每项目上限

#### Scenario: 自动队列已满
- **WHEN** 全局自动排队达到上限
- **THEN** 新目标保持待处理，不突破并发限制或取消手动任务

### Requirement: PPT-04 重试、限流与失败处理

临时网络失败 SHALL 最多自动重试3次，默认间隔1/5/15分钟；限流 MUST 遵守 Retry-After 或重置时间。模型失效、来源失效或范围超限 MUST 保留失败和主动重试入口，不无限重试、不自动训练或换模型。同一失败阶段 SHALL 只提醒一次。

#### Scenario: 临时失败恢复
- **WHEN** 网络临时失败后恢复
- **THEN** 按退避重试原意图，成功后继续原快照与模型

#### Scenario: 限流
- **WHEN** 远端返回 429 或明确重置时间
- **THEN** 不早于该时间重试，不密集轮询

#### Scenario: 模型失效
- **WHEN** 固定模型停用或产物损坏
- **THEN** 任务失败并说明原因，等待用户处理，不自动换模型

### Requirement: PPT-05 暂停、取消与重启

项目暂停 SHALL 停止后续检查和新入队，但 MUST NOT 取消已提交任务；关闭或合并的 PR SHALL 停止后续自动分析并保留历史。用户取消或中断的意图 MUST NOT 因下一轮轮询自动复活，需主动重试或新版本。服务停止或休眠期间 MUST NOT 承诺检查。

#### Scenario: 项目暂停
- **WHEN** 用户暂停项目跟踪
- **THEN** 不再检查或入队，已提交任务继续并记录终态

#### Scenario: 取消后轮询
- **WHEN** 用户取消某意图后下一轮检查
- **THEN** 同一意图不自动重建，需用户主动重试或等待新版本

#### Scenario: 重启恢复
- **WHEN** 后端重启且存在遗留检查
- **THEN** 过期租约收敛为中断，不自动重跑旧意图
