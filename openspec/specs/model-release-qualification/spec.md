# model-release-qualification Specification

## Purpose

定义当前十四维 schema 的模型如何从一次成功训练运行转化为发布合格、用户可服务和人工批准的默认候选，避免把实验完成或可登记状态误报为可交付模型。

## Requirements

### Requirement: MRQ-01 当前 schema 正式模型覆盖

系统 SHALL 使用真实公开仓库构建的 `kamei14-git-v2` 数据集生成当前 schema 正式模型基线。基线 MUST 对当前注册的九种方法逐项尝试训练与完整校验，并至少交付四种经典方法和三种深度方法共不少于八种可服务模型；每个成功模型 MUST 使用同一数据版本、固定时间切分、同一标签规则和同一指标集，训练失败、校验失败或未通过发布门槛 MUST 保留逐方法原因且不计入交付数量。系统 MUST NOT 用六字段模型、离线 benchmark-only 运行或复现副本冒充当前十四维 schema 模型。

#### Scenario: 当前 schema 基线覆盖达标

- **WHEN** 管理员构建 `kamei14-git-v2` 正式模型基线
- **THEN** 九种方法均产生成功运行或结构化失败记录
- **AND** 至少四种经典方法和三种深度方法共不少于八种通过完整校验并标记为可服务形式

#### Scenario: 方法未形成当前 schema 产物

- **WHEN** 某方法只有六字段产物、离线基准产物或不可加载产物
- **THEN** 该方法不进入当前 schema 发布包，并显示具体不可发布原因

### Requirement: MRQ-02 JIT 专用发布门槛

发布资格 SHALL 由固定的发布策略计算。默认策略 MUST 在每个声明的目标测试项目上要求正例数不少于 20、AP 高于该项目的无信息基线、ROC-AUC 不低于 `0.65`；同时 MUST 要求跨项目宏平均 Recall@20%LOC 或宏平均 Popt 至少一项不低于同预算下的时间顺序和固定种子随机顺序。全部必需指标 MUST 有定义。系统 MUST 并列计算风险/成本密度基线，MUST NOT 使用普通 accuracy 单独判定通过。accuracy MAY 作为诊断字段返回，但响应和报告 MUST 同时显示多数类 accuracy 与正例比例，防止不平衡数据掩盖模型无效。

#### Scenario: 项目内排序优于无信息但整体不优于简单检查顺序

- **WHEN** 模型在每个项目上的 AP 与 ROC-AUC 达标，但宏平均 Recall@20%LOC 和 Popt 均低于时间与随机基线
- **THEN** 发布结果为不合格，并列出未通过门槛与对应基线差值

#### Scenario: 普通 accuracy 很高但小类召回很低

- **WHEN** 模型 accuracy 超过 80%，但 AP、Recall@20%LOC 或 Popt 未达到发布门槛
- **THEN** 模型不得标为发布合格
- **AND** 报告同时显示多数类 accuracy、正例比例及类别不平衡风险

#### Scenario: 指标无定义

- **WHEN** 测试集缺少正例、工作量条件不满足或基线无法计算
- **THEN** 发布结果不得通过，并记录具体未定义字段和原因

### Requirement: MRQ-03 发布报告与默认候选

每次正式基线 SHALL 产出机器可读和人工可读的发布报告，包含数据版本与哈希、切分策略、标签成熟规则、逐方法运行身份、依赖、指标、基线差值、发布资格、不可发布原因、服务兼容性和人工批准的默认候选。系统 MUST 区分“训练成功”“可登记”“发布合格”“用户可服务”和“默认候选”。默认候选 MUST 由人工显式批准，MUST NOT 根据测试指标自动选择；未通过发布门槛的模型 MUST NOT 成为正式默认候选。

#### Scenario: 训练成功但发布不合格

- **WHEN** 某方法完成训练、产物校验和模型登记，但未通过发布门槛
- **THEN** 报告显示训练成功和已登记，同时显示发布不合格及原因
- **AND** 该模型不作为正式默认候选

#### Scenario: 人工批准默认候选

- **WHEN** 管理员从发布合格的兼容模型中选择默认候选
- **THEN** 报告保存模型身份、批准人与批准时间
- **AND** 其他环境已有默认模型不被导入包静默覆盖

### Requirement: MRQ-04 正式模型包与可复现性

发布合格的当前 schema 模型 SHALL 被打包为带版本、清单、逐文件 SHA-256、依赖、数据集、schema、切分和发布报告引用的不可变模型包。重新执行相同数据、方法、切分、发布策略和锁定环境时 MUST 重算出相同分区，并在方法声明的容差内得到相同指标；任一门槛输入变化 MUST 重新计算发布资格，不得沿用旧通过状态。

#### Scenario: 导入当前 schema 正式模型包

- **WHEN** 新环境初始化包含当前 schema 模型包的受控仓库目录
- **THEN** 包内合格模型按原运行身份登记为可服务模型
- **AND** 管理员可读取对应发布报告和默认候选建议

#### Scenario: 数据或发布策略变化

- **WHEN** 数据集哈希、切分摘要、模型哈希或发布门槛与报告不一致
- **THEN** 模型不得沿用合格状态，必须重新校验和计算
