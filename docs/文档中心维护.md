# 文档中心维护

公开产品文档位于前端构建内，匿名可读，不经过后端接口。导航、正文和本地搜索共用 `frontend/src/features/docs/catalog.ts`，未在该文件显式导入的内容不会进入生产构建。

## 新增文章

1. 在 `frontend/content/docs/articles/` 新建 `<slug>.md`。slug 使用小写 kebab-case，发布后保持不变。
2. 在 `frontend/src/features/docs/catalog.ts` 增加该文件的 `?raw` 导入，并登记 slug、标题、摘要、分组和顺序。
3. 分组只能使用「快速开始」「使用指南」「背景知识」「常见问题」之一；同一 slug 不能重复。
4. 文章正文不写一级标题。页面标题取自发布清单，正文从二级标题开始。
5. 运行 `npm run check:docs`。测试会检查文章数量、slug 唯一、四组非空、小节标识和内部链接。

## 小节与地址

每个需要进入右侧目录或作为帮助目标的小节使用显式稳定标识：

```markdown
## 提交级风险分是什么 {#commit-score}
```

- 标识以英文字母开头，只使用字母、数字、`_` 和 `-`。
- 同一篇文章内不得重复；发布后不要随手改名。
- 文章地址是 `#/docs/<slug>`，小节地址是 `#/docs/<slug>?section=<id>`。
- 删除或重命名已被业务帮助链接、其他文章引用的标识时，必须同步修改所有引用。
- 无效小节会保留文章并显示提示，不会变成未知页面。

## 正文链接与图片

- 文档之间或进入工作台：使用 `#/docs/...`、`#/projects...` 等应用地址。文档模式会走现有 HashRouter 与登录流程。
- 外部网页：使用 `https://...`，渲染时自动新开标签页。
- 图片放在 `frontend/public/docs/`，正文使用 `/docs/<file>`。只使用公开示例或脱敏素材。
- 表格和代码块在窄屏容器内滚动，不要把超宽表格压成不可读的小字。

## 搜索

搜索覆盖标题、小节标题、正文和 `frontend/src/features/docs/docsContent.ts` 中的常用同义词。新增产品术语时：

1. 优先在正文中使用用户界面上的原始按钮名和状态名。
2. 将常见替代说法加入 `SYNONYMS`，例如“没有可用模型”对应“模型兼容”。
3. 至少用真实查询验证标题/小节优先、结果能定位，以及无结果提示。

## 发布前检查

```powershell
cd frontend
npm run check:docs
npm run typecheck
npm run check:styles
npm run check:modules
npm run build
```

浏览器至少检查：

- 无痕窗口直接打开 `#/docs` 和一篇带 `section` 的文章。
- 刷新、前进后退、未知文章和无效小节。
- 桌面三栏、约 390px 折叠导航，以及表格、图片和代码块无页面横向滚动。
- 「风险分」「私有仓库」「模型兼容」「VS Code」搜索并打开结果。
- 首页、工作区页头、分支分析、PR 工作单和模型评估的帮助入口。

生产构建的自动浏览器检查：

```powershell
cd frontend
npm run build
$env:JIT_FRONTEND_PORT='14273'
npm run preview
# 另开终端，在 frontend 目录运行：
node scripts/docs-acceptance.mjs
```

脚本使用隔离浏览器上下文和测试夹具，验证匿名阅读、离线接口、1280/390 布局、搜索、历史、业务入口及工作单帮助保留；输出在 `docs/evidence/add-product-documentation-center/`。

## 内容边界

不要把管理员数据集记录、验证报告、模型维护资料、私有仓库信息、真实账号或本机路径写入公开文章。产品行为以 `docs/当前产品.md` 和当前界面为准；历史指南中与当前代码冲突的描述不进入公开文档。
