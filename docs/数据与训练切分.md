# 数据构建、时间切分与趋势分区

## 数据构建任务

项目页的“构建数据集”只使用当前项目已登记公开仓库，不再接受第二个仓库地址。请求只包含分支、可选起止日期和服务端默认提交上限。任务复用现有来源校验、Kamei 14 维采集、简化 SZZ、幂等版本命名、描述文件登记与提交入库，但不会调用训练器、推理、项目当前结果或模型选择。

任务与 `repository_sync` 分离，持久化在 `dataset_build_task`：

- `queued`：等待数据集构建单工作器。
- `running` 且阶段 `collecting`：读取 Git 历史并计算特征与标签。
- `running` 且阶段 `registering`：写入不可覆盖 CSV、描述文件和目录库。
- `completed`：只返回 `datasetName`、`datasetVersion`、质量统计、来源版本、限制和是否复用同内容版本。
- `failed` / `cancelled` / `interrupted`：保留阶段和原因，可显式重试；不伪造空版本。

同仓库、分支、范围和上限的活动任务复用；相同内容版本再次构建时返回既有版本。失败不会修改项目当前分析、历史记录或模型选择。

## 时间切分预设

| 预设 | 时间组比例 |
| --- | --- |
| `temporal-70-15-15` | 训练 70%，验证 15%，测试 15% |
| `temporal-80-10-10` | 训练 80%，验证 10%，测试 10% |
| `temporal-60-20-20` | 训练 60%，验证 20%，测试 20% |

比例为默认，不是四舍五入承诺。系统对去重且排序后的提交时间组取 `floor` 边界，因此实际样本比例会受同一时间戳提交数量和类别可用性影响。一个时间组不能跨分区，三个分区必须非空，训练与测试必须各含两类发布标签。

未指定预设的旧调用解析为 `temporal-70-15-15`。任意日期边界、随机切分、分层随机切分和重叠分区在第一版中都会在创建任务前被拒绝。

## 预览与运行身份

管理员在数据集详情选择预设后，先读取 `/api/admin/datasets/{datasetVersion}/split-preview`。响应提供策略 ID、比例、UTC 时区、两个边界 epoch 与时间、train/validation/test 的起止时间、样本数、正例数、不可用原因、分区计数摘要和成员 SHA-256。

预览不创建任务、运行目录或模型。训练任务创建时再次校验同一策略，避免预览后数据损坏仍进入队列。

训练产物 `split.json`、`summary.json` 和 `manifest.config` 都记录策略 ID、比例、边界、分区计数和成员摘要。运行身份包含该策略，所以同一数据版本切换预设不会覆盖原结果。验证集可以参与既有模型选择背景；测试集不参与训练、阈值、融合权重或方法选择。

## 旧模型与迁移

- 旧运行保留原 `split.json` 和原指标，不重写模型文件。
- 未记录 `splitPolicy` 的模型继续可用于原历史结果，但项目趋势不会推断分区。
- 新分析未提交预设时保存默认 `temporal-70-15-15`，不把空值当作随环境变化的口径。
- 迁移 030 增加训练任务与仓库同步的预设和策略列；迁移 031 新增独立数据集构建表。

## 趋势分区标注

趋势页面会核对固定模型运行、当前项目数据版本、冻结切分策略和成员摘要。只有全部一致时，图表说明、图例、等价表格和提交下钻才显示分区：训练、验证、测试、近期未参与训练和分区未知。

使用仓库兼容的外部现成模型时显示“外部模型，无本项目切分标签”。同一固定趋势包含多次分析时，所有来源必须指向同一模型运行和同一训练数据版本；否则不择一猜测。分区标注不改变风险分数、高分占比或排序，也不表示真实缺陷概率。
