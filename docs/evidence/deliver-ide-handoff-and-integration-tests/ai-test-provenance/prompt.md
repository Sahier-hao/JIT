# 完整定向提示词

## 用户请求

“把之前计划中的 PR5 到 PR8 合成一个 change 并最终作为一个 PR 提交。”

附图中 PR5–PR8 的范围：

- PR5：CI 报告交接、真实仓库回归；Eclipse/Visual Studio 先生成可行性结论。
- PR6：95 个 API 操作清单、测试工具、测试框架和高风险接口。
- PR7：其余接口、前后端联调、并发与故障场景。
- PR8：联调截图、AI 提示词、人工复核、报告和冻结证据。

## 实现约束

- 一个 change、一个 PR，不拆回 PR5–PR8。
- 95 项业务 API = 当前 OpenAPI 99 个操作排除 4 个 admin 认证操作（setup、login、session、logout）。
- 四类场景：正常、边界、异常/失败、并发/故障。
- 高风险接口四类都必须有实际测试；其余接口至少正常与异常/失败，边界与并发/故障可用人工复核的不适用理由。
- 不修改模型风险算法、默认模型、训练算法、项目分析口径或 PR 合并策略。
- 测试必须真实执行；缺失映射、失败、跳过或空套件不得冒充通过。
- AI 生成或修改的测试必须保留来源标记、提示词和人工复核记录。

## 本次生成测试的目标

- 校验 95 项业务清单和 4 个 admin 认证排除项。
- 校验四类矩阵完整性、高风险约束、失败/跳过/陈旧测试节点和待复核状态。
- 校验 `jit-commit-analysis-v1` 报告交接与 CI 只读边界。
- 在一次性真实 Git 仓库中校验报告身份匹配、脏工作树、分支切换、过期报告、文件重命名和删除。
