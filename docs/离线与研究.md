# 提交解释、离线报告与行级研究

本页承接[当前产品](当前产品.md)中的离线集成细节；这些能力不进入在线项目分析或 PR 合并决定。

## 提交模型解释

在固定分析的提交列表点开一条提交，可先读取已保存解释，再显式选择该模型实际可用的方法生成。当前交付两种方法：`occlusion-mean-v1` 输出风险概率变化（`probability`），与模型无关；`linear-logodds-v1` 输出 log-odds 贡献（`logit`），只适用于输入 schema 受支持且估计器为二元逻辑回归的模型。读取详情不运行推理；生成仅使用该分析登记的模型、运行和字段并核对保存分数。每种方法独立保存、互不覆盖，重复生成同一方法幂等；原模型不可用或完整性校验失败时，已保存解释仍可读，未知或不兼容方法明确拒绝且不改变原风险。

每条解释最多展示五个非零影响，并给出本次值、基线、带符号贡献、方向、单位与稳定性；基线来自原模型训练分区字段均值，缺失字段退回零基线并显式列出。同一提交的多种解释可并列核对主要特征、方向和排序稳定性，但概率变化与 log-odds 单位不同，不能相加、不能共享排名，也不自动选择“最佳解释”。特征贡献不是缺陷根因、因果解释或代码行定位；遮挡法不能解释字段交互，线性分解要求输入与基线经过原 Pipeline 的实际预处理。接口为固定项目提交的 `/explanation`（可选 `method`）、`/explanations` 与 `/explanation-methods`，必须显式传入 `viewSyncId`；删除分析会一并清理解释。

## PR 检查报告

`pr-check-export` 从本机目录库的固定快照与分析导出可移植分析包，包含身份、逐提交分数、候选位置和覆盖说明，不含个人草稿。`pr-check-report` 读取分析包生成 JSON 或 Markdown，读取已保存分数，不要求模型可加载；身份不匹配时失败。命令默认不阻断合并、不评论 PR、不访问本机服务；退出码区分成功、分析缺失、身份不匹配和输入无效。

`pr-check-analyze` 从本地 Git 仓库明确的 base/head 执行真实特征采集、推理和报告，记录仓库与提交身份、模型运行与参数、逐提交分数、覆盖、候选与建议；同一范围与模型幂等，无变更、身份不一致、模型缺失和 schema 不匹配有明确退出码。CI 示例默认只上传报告，不评论、不阻断合并。

## 行级研究

行级研究保持离线：`line-train` 读取 `line-szz-v1` JSONL，输出报告与可移植 manifest（输入哈希、采样摘要、切分成员哈希、环境与复现命令），按语言/仓库报告 ROC-AUC、PR-AUC、Brier 与抽样负例定位代理指标。当前证据不足以承诺逐行概率，不登记为产品模型、不改默认模型、不进入项目分析或 PR 审查；研究预览 `#/research/line-model` 只展示固定实验口径并按行返回排序分数，固定标注“不是缺陷概率”。固定实验与结论见[行级实验复现](审计/2026-11-09-line-experiment-reproducible.md)与[研究预览](审计/2026-11-09-line-model-research-preview.md)。

## VS Code 扩展

`vscode-extension/` 提供只读扩展：显式导入报告，核对仓库提交与当前 HEAD，展示提交风险、候选与修复建议并跳转到文件行；身份不一致或行号过期时拒绝定位。报告中的路径与文本按不可信数据处理。「JIT: 复制报告生成命令」可收集基准/目标提交、真实模型 ID、目录库和产物根目录并复制 CLI 命令，但扩展不执行命令也不自动导入报告。扩展 `0.2.0` 由独立工作流运行测试、打包并上传 VSIX。
