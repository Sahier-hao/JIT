# JIT Review · 全局错误码表

版本：v1.0评审稿；核对日期：2026-10-12。本文集中定义产品HTTP及相关数据／模型CLI的错误含义；设计和[OpenAPI离线契约](api/openapi.yaml)引用码名和约束，不能各自维护冲突定义。验证证据工具的独立诊断不属于本文产品契约范围。

**当前已有**仅覆盖本机历史服务及已核对的数据／模型CLI；**计划**是共享目标的候选错误，尚未实现。CLI错误没有HTTP状态；任务GET返回failed状态的200记录不代表任务执行成功。

## 一、当前结构与映射

当前产品接口为`GET /api/review-batch`。错误响应只包含`error.code`和`error.message`；不增加候选details／requestId字段、不附旧批次或部分记录。以下为结构示例，非本轮live请求：

```json
{"error":{"code":"ARTIFACT_UNAVAILABLE","message":"产物不可用：model.joblib"}}
```

| 代码 | 已观察使用处 | 当前HTTP状态 | 含义与处理 |
|---|---|---|---|
| ARTIFACT_UNAVAILABLE | HTTP、产物CLI | 503（HTTP） | 必需manifest／输入／模型等文件不可读或缺失；核验并恢复原版本，verify后按需重启服务，再重试 |
| INTEGRITY_ERROR | HTTP、来源／产物CLI | 503（HTTP） | 文件或关联hash不一致；训练代码哈希是**溯源记录**，不再要求与当前文件逐字节相同（见 change `align-feature-and-model-definitions` 的 design D6），一致性由运行身份与声明算法版本约束；定位差异并恢复匹配版本，不能忽略校验或自动替换示例 |
| ARTIFACT_INVALID | HTTP、产物CLI | 503（HTTP） | 结构、运行身份、schema声明、入模字段与声明schema不一致、**运行声明的超参与该方法的注册声明不一致**、**本机产生的运行其声明的依赖缺失或版本不符**（外部产生的运行不以此为准入条件，见 [PROTOCOL](backend/PROTOCOL.md) 的「环境声明与跨机器语义」）、方法声明的依赖在本机未安装、分区或摘要关联不一致、**声明的时间桶聚合与重算结果或守恒核对不一致**；核验完整运行，避免拼接旧文件 |
| MODEL_INVALID | HTTP、模型CLI | 503（HTTP） | 模型加载／类型／输入维度或训练类别不合法；**交付的模型必须能在无加速设备的机器上加载**——在加速设备上序列化的产物在本机不可加载即属此类；使用可信且匹配环境的模型，不给默认分数 |
| INFERENCE_ERROR | HTTP、模型CLI | 500（HTTP） | 模型推理异常、正类识别失败、数量或风险不合法；记录原因、核验模型与输入，失败不发布批次 |
| SOURCE_UNAVAILABLE | 来源CLI | 无HTTP | 固定来源不可读／下载失败；恢复来源后重新校验，不改为合成数据 |
| DATA_INVALID | 数据CLI | 无HTTP | CSV编码／表头／标识／时间／特征／非空标签非法；定位原始行，修正来源或建立新版本，不静默删行 |
| OUTPUT_EXISTS | 产物CLI | 无HTTP | 指定运行目录已经存在；独立复现使用新目录，保留既有结果 |
| SPLIT_INVALID | 模型CLI | 无HTTP | 分区空、重复、时间组／顺序无效或训练／测试类别不足；重新核对预先定义的数据协议，不随机重切掩盖 |
| FEATURES_INVALID | 模型CLI | 无HTTP | 固定六字段矩阵为空、形状／类型／值非法；按该schema修正，不猜列名或补零 |
| MODEL_NOT_CONVERGED | 模型CLI | 无HTTP | 该方法按自身声明的收敛契约未收敛（如逻辑回归达到迭代上限）；保留失败，不在看过测试效果后自动换参数并沿用同一run |
| EVALUATION_INVALID | 评价CLI | 无HTTP | 标签／预测数量、风险或成本非法，或并列比较时没有可比较的运行；回到同一完整批次核对，不能丢掉失败样本后评价 |
| TREND_INVALID | 模型CLI | 无HTTP | 时间桶聚合的输入或声明不合法：分区缺失或为空、风险数量与测试分区不一致、风险非有限概率、标签不是0／1、最小样本不是正整数；修正数据或声明后重跑，不产出部分聚合 |
| METRIC_SET_UNKNOWN | 产物CLI | 无HTTP | 运行声明的指标集未注册；按已注册指标集修正或新建版本，不退回默认集合 |
| METRIC_SET_INVALID | 评价CLI | 无HTTP | 声明的指标集列了未定义的指标；修正指标集声明，不用部分指标通过校验 |
| REPRODUCTION_FAILED | 复现CLI | 无HTTP | 两次运行的**方法或指标集不同**、分区不同、指标定义状态不同，或风险／指标数值超出**该方法声明的复现口径**；核对输入、配置与环境，失败不称复现通过 |
| SCHEMA_UNKNOWN | 数据／产物CLI | 无HTTP | 请求的具名特征schema未注册；按已注册名称修正，不退回默认schema、不猜字段 |
| SCHEMA_FIELD_UNKNOWN | 数据／产物CLI | 无HTTP | 请求的字段名不在该schema的字段清单中；按注册表字段名修正，不猜别名 |
| SCHEMA_FIELD_UNAVAILABLE | 数据／产物CLI | 无HTTP | 要求使用在该schema中标记为不可得的字段（如`lt`、`rexp`）；按注册表结论处理，不用同名列或推算值替代 |
| ALGORITHM_UNKNOWN | 产物CLI | 无HTTP | 运行声明的**方法名**或算法版本未注册，或方法声明的估计器未实现；按已注册名称重建独立运行，不退回默认方法、不沿用旧版本名 |

依据：[API](../backend/jit_baseline/api.py)、[data](../backend/jit_baseline/data.py)、[model](../backend/jit_baseline/model.py)、[artifacts](../backend/jit_baseline/artifacts.py)、[trends](../backend/jit_baseline/trends.py)、[metrics](../backend/jit_baseline/metrics.py)。当前API启动失败需恢复产物并重启；浏览器单独重试不会更新失效Snapshot。

|---|---|---|

## 二、共享接口错误与后续候选

2026-10-14 后端增量已实现模型候选／登记／目录／schema／单条 JSON 预测／结果重开。
这六个接口使用成员／管理员凭据、`X-Request-Id` 与下述共享错误结构；其他目标接口仍未实现。
`INPUT_INVALID`／`INPUT_SCHEMA_MISMATCH` 为 422，候选变更为 409，模型／产物错误为 503，推理失败为 500。
原历史接口继续使用第一节原结构，不受新凭据或目录数据库配置影响。

| 新代码 | HTTP | 已实现含义 |
|---|---|---|
| STORAGE_UNAVAILABLE | 503 | 目录库缺失、版本不兼容、不可读／不可写、锁等待超时或提交失败；事务回滚，不返回已计算风险或成功登记 |

INPUT_LIMIT_EXCEEDED、CONTEXT_MISMATCH、MODEL_NOT_READY 已落地；下面表中训练／CSV／解释等场景仍为候选。
JSON 的实际正文上限为 64 KiB，不能用伪造 Content-Length 绕过。解释未接入使用 not-supported，不制造 failed 解释任务。

### 2.1 工作台客户端的处理约定（change `connect-model-prediction-workbench`）

2026-10-16 起模型中心、新建预测与预测结果页直接消费上述六个接口。客户端只按下列约定处理错误：

- 只显示服务端返回的 `error.code`、`error.message`、`error.requestId` 与 `error.details[].field/reason`，
  再补一句本端按码分类的标题；不编造原因、不展示服务端绝对路径或凭据。
  INPUT_INVALID／INPUT_SCHEMA_MISMATCH／INPUT_LIMIT_EXCEEDED／CONTEXT_MISMATCH→「需要修正输入或重新选择」；
  MODEL_NOT_READY／MODEL_INVALID／ARTIFACT_INVALID／ARTIFACT_UNAVAILABLE／INTEGRITY_ERROR→「模型当前不可用」；
  STORAGE_UNAVAILABLE／INFERENCE_ERROR→「目录存储不可用」；请求未达服务或正文不可解析→「无法连接服务」／
  「返回内容不符合约定」。
- 401 与 403 分开反馈：403 时管理员登记区不展示任何候选，也不发起登记；`CONTEXT_MISMATCH`（409）时清空
  已选候选、重新读取候选目录，**不把新的 manifest 校验值自动带回请求**。
- 创建预测与登记都**不自动重试**：只在拿到 201（登记复用为 200）且正文与该次提交的快照逐项一致时展示成功；
  断线、超时或正文不可核对时只说「未能确认保存结果」，请用户用批次编号去「打开已有结果」确认。
- 任何错误都不写入凭据、完整 `Authorization` 头或服务端绝对路径到日志、截图或 `docs/evidence/_run/` 下的证据。

目标错误保留`error: {code,message}`外层，建议允许details和requestId。details用于行／字段／记录定位，不含凭据或服务端绝对路径。以下仅为人工格式示例：

```json
{
  "error": {
    "code": "INPUT_SCHEMA_MISMATCH",
    "message": "输入字段与所选模型不匹配",
    "details": [{"recordId": "input-example-1", "row": 2, "field": "lt", "reason": "必需字段缺失"}],
    "requestId": "request-example"
  }
}
```

| 代码 | 状态／候选HTTP | 含义 | 客户端／服务处理 |
|---|---|---|---|
| NOT_FOUND | 计划，404 | 数据版本、schema、模型、run、batch或prediction不存在 | 检查完整标识；不返回另一资源冒充 |
| SOURCE_HASH_MISMATCH | 计划，422 | 导入CSV内容与来源声明hash不符 | 定位来源与声明，导入不ready；与当前服务503的INTEGRITY_ERROR区别按场景定义 |
| INPUT_SCHEMA_MISMATCH | 计划，422 | 字段、schema或模型契约不兼容 | 指出缺失／多余／类型／单位问题；不自动将六字段补成14维 |
| INPUT_INVALID | 计划，422 | ID重复、编码／CSV结构、数值／时间／标签或请求格式非法 | 指出记录／行／字段，整批失败而非部分成功；标签不能混入预测特征 |
| INPUT_LIMIT_EXCEEDED | 计划，413 | 文件大小、记录数超过候选配置上限 | 提示实际配置与拆分方式；不静默截断 |
| CONTEXT_MISMATCH | 计划，409 | 比较成员／schema／成本不一致，或解释和预测来源不匹配 | 不拼接或排名；按同一实验／预测重新查询 |
| MODEL_NOT_READY | 计划，503 | 所选模型状态或必要产物暂不可用 | 提示核验／恢复，不改用其他模型；输入保持可修正 |
| RUN_NOT_READY | 计划，409 | 所需成功实验、历史趋势或完整报告尚不可用 | 查询运行状态；不导出成功报告或空结果冒充 |
| EXPLANATION_FAILED | 计划，200状态记录中的code | 预测合法但解释计算失败／超时 | Explanation.state=failed，保留原风险并展示原因；不能填人工贡献 |

当前五个服务错误也可在新接口草案中按相同语义复用；复用不改变当前接口行为。训练阶段的CLI语义若映射到任务失败字段，需要保留code与原因，但查询该任务仍可返回200状态记录。

## 三、全局约束与复核

- row为逻辑CSV行号，表头是1，首条数据是2；field为规范字段名，recordId为已能识别的外部记录或提交标识。无法确定时可省略或为null，不能编造定位。
- 任意HTTP错误不带旧运行风险、人工分数或部分成功批次。合法预测的解释失败是独立状态，不改写风险。
- 指标未定义用`{value:null,reason:说明}`，不是服务异常；不可计算不能伪装成0。
- 多方法并列比较中"**不可直接排名**"是比较报告的状态（`directlyRankable: false` 与差异项），不是错误码：口径不一致时比较照常产出，但不得给出统一排名或择优结论；只有"没有可比较的运行"这类无法成立的情形才用`EVALUATION_INVALID`。
- OpenAPI的GlobalErrorCode枚举与本表一致；CurrentError只允许已观察的五个HTTP码，SharedError为候选契约。HTTP码、领域码和failed任务状态分别核对。
- 日志与导出使用requestId／runId／batchId／attemptId关联，错误文字可定位业务问题，认证材料保持脱敏。
