# 训练模型包部署与恢复

模型产物和 `backend/storage/catalog.sqlite3` 是本机运行数据，均被 Git 忽略。部署环境不能从代码推断模型已经存在，也不应复制整份 SQLite 目录库；使用带版本清单和 SHA-256 的模型包迁移明确选择的已登记模型。

## 边界

- 模型包只包含明确选择的已登记运行，以及每个运行的模型文件、`manifest.json`、摘要、数据集版本、schema、依赖声明、运行身份和逐文件哈希。
- 导出不包含 SQLite、项目、管理员账户、会话、源环境默认模型、启停策略或“最佳模型”标记。
- 导入会逐项重新校验文件、运行身份、完整产物和模型能否加载；有效项独立登记，冲突、损坏或依赖缺失项逐项失败。
- 包是发布资产，不提交 Git。`.sha256` 与包一起保存；发布后不修改同一包。
- 普通用户只能看到已登记、启用、产物可用且 schema 兼容的模型。完整产物或训练报告不会自动成为可用模型。

## 生成模型包

在训练环境的 `backend` 目录选择目录中已登记、确认要交付的模型 ID。管理员模型详情可核对 ID、运行身份和指标。

```powershell
./.venv/Scripts/python.exe -m jit_baseline.cli export-models `
  <MODEL_ID_1> <MODEL_ID_2> <MODEL_ID_3> `
  --database storage/catalog.sqlite3 `
  --artifact-root artifacts `
  --output ../release/jit-models.zip
```

命令输出 `packageSha256`、模型数、文件数、解压大小和包大小，并生成 `jit-models.zip.sha256`。输出已存在时拒绝覆盖；校验或写校验文件失败时不留下可误认为完整的包。

只导出标准服务模型，不把复现副本、离线基准、语义向量输入模型或聚合报告自动加入。若所选模型当前不可加载，导出失败。

## 发布和传输前核对

```powershell
$expected = (Get-Content .\jit-models.zip.sha256).Split()[0].ToLower()
$actual = (Get-FileHash .\jit-models.zip -Algorithm SHA256).Hash.ToLower()
if ($actual -ne $expected) { throw '模型包 SHA-256 不匹配' }
```

将 ZIP 和 `.sha256` 作为同一发布资产交付。不要通过 Git 提交模型、SQLite 或证据运行目录。

## 新环境或升级环境导入

1. 停止旧后端，避免导入与登记读写交叉。
2. 备份目标环境的 `catalog.sqlite3` 和全部被引用产物目录。
3. 用新代码执行目录库前向迁移。旧库升级会先在同目录生成 `catalog.sqlite3.before-v<旧版本>-<随机>.sqlite3`；备份失败则不升级。
4. 导入模型包并检查逐项结果。
5. 启动单个后端，核对管理页和用户模型选择。

```powershell
cd backend
./.venv/Scripts/python.exe -m jit_baseline.cli catalog-init
./.venv/Scripts/python.exe -m jit_baseline.cli import-models `
  ../release/jit-models.zip `
  --database storage/catalog.sqlite3 `
  --artifact-root artifacts
./.venv/Scripts/python.exe -m jit_baseline.cli serve --port 8000
```

导入命令返回 `completed`、`partial` 或 `failed`，并给出新建、复用、已登记、冲突和失败计数。重复导入同一包应复用相同模型和运行身份；已有目标策略不被源包覆盖。空目录中第一个合法兼容模型按既有规则建立初始默认。

依赖缺失时不会登记该模型。先在目标环境安装同一运行声明的 Python/包版本，再重新导入；不要修改包内清单或把失败模型手工写进目录库。

## 部署后核对

```powershell
$models = Invoke-RestMethod http://127.0.0.1:8000/api/v1/models
$coverage = Invoke-RestMethod http://127.0.0.1:8000/api/v1/models/coverage
$choices = Invoke-RestMethod http://127.0.0.1:8000/api/v1/repository-models
```

管理页应显示已登记数、`ready` 数、用户可选数、最近导入结果和逐项失败原因；训练覆盖矩阵应区分无产物、训练失败、完整未登记、已登记可用和不可服务。用户选择只包含 `repositoryPredictionSupported=true` 的真实模型。后端不可达时页面显示连接错误，不解释为“没有训练模型”。

模型 ID、`artifactRunId`、数据集版本和 schema 应与发布清单一致。包中记录的是源模型 ID；导入时保留该 ID 以保持谱系，不复制源默认和启停设置。

## 回滚

1. 停止新后端，另行保存导入后的目录库、产物和逐项导入记录。
2. 恢复部署前的 SQLite 目录库和对应产物目录。
3. 切换到与新数据库版本匹配的代码，再启动单个后端。
4. 重做模型选择、默认模型和用户可见性核对。

模型包不可变，可以重新导入，但已部分成功的数据不会因为重新导入而回滚。需要完整恢复到导入前状态时，必须恢复数据库与产物的同一份备份。
