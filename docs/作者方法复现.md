入口变更：`add-author-method-reproduction`。总证据见
[docs/evidence/add-author-method-reproduction/README.md](evidence/add-author-method-reproduction/README.md)。

本文记录 2026-11-28 在本机真实运行过的作者方法、数据、权重、结果和阻塞。作者源码、原始数据和权重不随仓库分发；仓库只提交来源、哈希、派生预测/指标和复跑命令。

## 统一入口

以下命令均在 `backend` 目录执行：

```powershell
./.venv/Scripts/python.exe -m jit_baseline.cli author-catalog
./.venv/Scripts/python.exe -m jit_baseline.cli author-prepare --method deepjit
./.venv/Scripts/python.exe -m jit_baseline.cli author-run --method deepjit --mode evaluate
./.venv/Scripts/python.exe -m jit_baseline.cli author-report --run <run目录>
```

实际材料、源码 revision 和哈希以
[`backend/jit_baseline/author_repro/catalog.json`](../backend/jit_baseline/author_repro/catalog.json)
为唯一机器可读清单。`author-prepare` 会核对源码 HEAD、数据/权重大小和 SHA-256/MD5；不匹配时返回 `AUTHOR_MATERIAL_HASH_MISMATCH`。

每次运行写入 `backend/artifacts/author-repro/<method>/<runId>/`（测试时可用 `--output` 指向隔离目录），包含：

- `run.json`：方法版本、运行等级、材料哈希、配置、切分、种子、环境和命令；
- `run.log`、`command.txt`；
- `metrics.json`、`predictions.jsonl`；
- 行级方法的 `line-predictions.jsonl`、`token-line-map.jsonl`；
- 模型方法的本机模型文件（`model.pt` / `model.joblib`）。

同一材料、配置和命令的运行身份稳定。重复写入非空目录会被拒绝，避免静默覆盖证据。

## `kamei14-git-v3` 时间衰减口径

论文的近期作者经验按时间衰减理解，而不是“最近 90 天提交数”。v3 定义为：

```text
rexp = Σ 1 / (1 + age_days / 365.25)
```

只累计当前提交父链上同一作者更早的提交。当前提交、未来提交、合并提交和并行分支不计入；作者时间倒置导致的负年龄被排除并计数。字段仍为 14 项，但 `rexp` 为实数，不是整数。

`kamei14-git-v2` 的 `rexp` 仍是近 90 天提交数，默认采集和既有历史模型不变。v3 使用独立 schema、数据集版本和新模型：

- 公开仓库：`pydantic/pydantic`，revision `328b88b52694a64ecd05f3acc92f2b6a160bc2ee`
- 窗口：2024-01-01 至 2025-01-01
- 原始记录 1,029，成熟合格 761，正例 93；未成熟排除 248
- 切分：`temporal-70-15-15`，训练 532（73 正）、验证 114（12 正）、测试 115（8 正）
- 模型：既有 `logistic-regression-l2-v1`，不是 Kamei 作者 12 字段模型
- 测试：AP 0.2901，ROC-AUC 0.5900，Recall@20%LOC 0.2500，Popt 0.8079

该结果只证明 v3 采集、成熟准入、冻结切分和独立训练链可用，不满足当前发布资格，也未登记为默认或用户可选模型。ROC-AUC 低于 `jit-release-v1` 的 0.65 门槛，不能据此宣称风险改善。

数据集描述、训练摘要和模型哈希保存在证据目录；v2 的 CSV、模型和分析未被改写。

## DeepJIT

作者网络、词典、消息/代码 padding 和作者权重均已真实运行：

- 作者 OpenStack 测试 1,331 条，163 个正例；
- 作者 `openstack_model.pt` 输出 AP 0.2506、ROC-AUC 0.7511；
- DeepJIT 论文/学位论文表中 OpenStack AUC 为 75.1，四舍五入差值为 0.0001；
- 未提供逐提交 LOC 成本，Popt 与 Recall@20%LOC 如实返回不可定义原因。

作者代码在训练优化器处把 `l2_reg_lambda`（默认 `1e-5`）传给 Adam，而 `learning_rate` 未被使用；端口保留 `author-code` 配置，并另提供 `paper-intent` 配置。小样本真实训练入口使用 128 条 OpenStack 训练提交、1 epoch 完成，产物标记 `real-smoke`，不是 25 epoch 作者训练复跑。

## JITLine

原 Zenodo 记录只提供代码和部分表，README 指向的 train/test pickle 不在记录中，因此不能声称原始项目划分复现。系统提供两个明确命名的数据版本：

- `jitfine-baseline`：JIT-Fine 作者固定的 JIT-Defect4J JITLine 基线输入；
- `released-openstack`/`released-qt`：从 JITLine 发布的 metrics 与完整行表重建，时间 80/20 切分，明确标为重建。

完整 `jitfine-baseline` 运行：

- 21 个 Java 项目，训练 16,374、测试 5,480，测试正例 475；
- 作者预处理、`min_df=3` 一元词袋、14 项变更度量、SMOTE(`k=9`)、300 树随机森林；
- AP 0.3957、ROC-AUC 0.8063、Precision@0.5 0.6387、Recall@0.5 0.1600、Recall@20%LOC 0.2547、Popt 0.8570；
- 对 10 个正确预测的正例提交执行 LIME，产生 594 条行排序、92 个行正例；
- Top-1/5/10 命中率 0.10/0.40/0.80，MRR 0.2351，前 20% 行召回 0.1957；
- 文件顺序基线在这个抽样集合上异常强（Top-1 1.0），原因为行表顺序与正例分布高度相关；不能把它当作真实文件阅读顺序。

发布 OpenStack 表重建版使用 2,000 条训练样本快速验证，测试 5,371、正例 500，AP 0.2776、ROC-AUC 0.7292；解释 1 个正例提交的 61 行，Top-5/10 命中率 1.0。两版结果不可互相冒名，也不能作为 JITLine 原论文固定划分的精确复现。

词元→行映射保留 `commitId`、`path`、表内 `idx`、词元位置和权重。作者数据不含真实 Git 行号，因此 `gitLine=null` 并给出 `author-table-has-line-index-but-no-git-line-number`；后续多语言真实 diff 接入再填真实行号。

## JIT-Fine

已实现原生 CodeBERT 输入拼接、14 维专家特征、融合分类头、BCELoss 和最后一层注意力到行的聚合。真实 CPU 小跑：

- 训练 8、验证 4、测试 16，1 epoch；
- AP 0.7514、ROC-AUC 0.7031（样本极小，不用于性能结论）；
- 2 个正确正例提交产生 93 条行排序、6 个行正例、682 个词元链接；
- Top-10 命中率 1.0、MRR 0.125、前 20% 行召回 0.1667；
- 相对随机基线（MRR 0.2161、前 20% 行召回 0.2133），本次小样本没有显示定位收益。

没有作者微调 checkpoint；作者协议为 50 epoch、最大序列 512、batch 24。当前机器仅有 CPU，完整协议未完成，运行清单记录 `hardwareBlocker`。不能用这组小样本数宣称复现论文性能。

## JIT-Smart

已实现共享 CodeBERT 提交分支、专家特征、HAN 行分支、focal loss 和 `0.3/0.7` 联合目标。项目内小跑：

- 训练/验证/测试 4/2/4，1 epoch；
- 提交分与 121 条逐行分同时产生，3 个行正例；
- 行 Top-1/5/10 命中率 0.5/1.0/1.0，MRR 0.625，前 20% 行召回 1.0；
- 文件顺序基线在该抽样上同为 1.0，不能据此宣称优于基线。

跨项目小跑以 `commons-math` 为目标测试项目，训练来自 `ant-ivy`、`commons-collections`、`commons-dbcp`、`opennlp` 等不同项目；测试 4 条、行候选 187 条、17 个行正例。提交分与逐行分均产生，但样本不足以做泛化结论。

作者的 50 epoch 联合训练和完整跨项目矩阵仍未在 CPU 上执行，记录为具体设备阻塞。行标签作者表提供文件和 `idx`，没有真实 Git 行号，因此同样输出 null 行号原因。

## 明确限制

- 以上分数不是产品公平比较：数据、成员、阈值和样本规模不同。
- Kamei 发布表没有作者身份历史，无法从该表重算 v3 衰减 `rexp`；v3 只在真实仓库采集上验证。
- JITLine 的 SMOTE 版本移除了已废弃的 `n_jobs` 参数；LIME 背景行抽样为 256，均记录为兼容改动。
- JIT-Fine/JIT-Smart 的 HAN/JIT-Smart 兼容端口分别采用可复现随机初始化和零初始状态，完整作者环境差异尚未全部消除。
- `line-predictions.jsonl` 的行索引来自作者表；真实 Git 行号需要后续多语言 diff 适配。
- 未将任何复现产物登记为服务默认模型；`kamei-v3-pydantic` 也未通过发布资格。
