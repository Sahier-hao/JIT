# PR 审查使用指南

## 从实际改动开始

从「项目」进入项目工作台，打开「PR 审查」子视图；也可以在项目列表的「我的审查」标签继续既有工作。项目 PR 清单列出实际 PR，可翻页、查看历史、显式刷新，并可按更新或按风险排序当前页；选择 PR 先进入只读详情，详情先展示模型风险概览、高风险提交和按风险排序的文件，点「开始审查」才创建工作单并出现在「我的审查」；已有工作单显示「继续审查」。关闭、合并与开放状态来自 GitHub，历史复盘不会冒充待合并工作。新项目默认开启分支检查，PR 自动分析需要在项目内单独启用。

读取失败或请求受限时，地址和原工作保留，可稍后重试。首版支持公开 GitHub 来源；私有仓库、个人账户同步、团队共享和直接提交 GitHub 意见尚不支持。

## 围绕问题核对代码

工作单显示作者说明节选、作者、PR 状态与阅读进度。「代码版本与作者原始说明」可核对完整说明、基准与目标 SHA、读取时间及提交覆盖。作者说明原文与规则生成的核对问题分开标识。

在左侧选择文件，阅读真实 Diff。点击代码行可以把位置加入右侧当前问题，同一问题可以关联实现与测试等多个文件。可编辑问题、补充人工判断、记录证据说明；也能建立不绑定行号的总体问题。

问题区分待确认问题、人工确认问题与一般建议。解决、暂缓或撤回前填写理由；原文和证据继续保留，也可重新打开。点击证据可返回原版本、原文件及行号；原内容不可读取时显示原因，不替换成新代码。

Diff 不完整时，按文件加载基准与目标的完整上下文。二进制、过大或非文本内容明确提示。只有完整读取的文件可以标记「已阅读」；这个标记不等于确认没有缺陷。可单独标记「需要复查」或「暂未覆盖」。过大 PR 的未加载文件及提交会计入未覆盖说明。

## 中断后继续

文件、问题编辑位置、正文、证据、个人笔记及阅读状态保存在当前浏览器，并按 PR 和代码版本隔离。切换页面或关闭后重开，可以继续此前工作。

浏览器写入失败时，页面明确显示「尚未保存」，正在编辑的文本留在本页。可以重试，或先导出完整草稿。其他页面已经保存更新时，不会静默覆盖新记录。

「导出完整草稿」生成此 PR 各轮的本地 JSON 文件，其中包含个人笔记、问题、反馈和结论。换浏览器或清理存储前请保留备份。恢复先核对公开来源与版本，展示每处冲突；默认保留当前内容，勾选后才采用对应备份字段。旧备份缺少的内容不会清空当前笔记和问题。确认前可以取消，重复导入不增加重复身份的条目。

## 作者更新后的下一轮

在工作单点击「检查 PR 更新」，或在项目列表的「我的审查」标签手动刷新个人工作。项目启用自动跟踪后，关闭页面期间由服务端检查并生成站内提醒；提醒只指向固定来源，不自动切换正在阅读的版本。发现新的基准或目标后，首页显示待复核；当前阅读仍保持原版本。点击「开始复核新版本」进入新轮。

变动的已读文件需要重新核对，未变文件显示原阅读出处。基准变化会使原已读范围重新核对。相关问题保留原判断、处理状态与旧证据，单独标记待复核；整体意见也需人工确认。新分数、新提交或代码删除不会自动解决意见。

服务端能取得提交比较结果时，会说明分叉或回退；无法对应两轮继承关系时明确显示未知。旧仓库或提交不可再取回时，只展示已保存的内容及读取边界。

远端关闭或合并后，工作默认进入历史入口，个人结论不会被修改。仍可主动继续历史复盘。个人关注、暂停和结束状态不代表 GitHub 的正式评审人分配。

## 输出本轮意见

结论选择和未完成说明会随当前版本草稿保存，重开可以接着填写。选择「建议修改」「本轮审查完成」或「暂缓」，填写本轮说明及未完成事项，点击「检查版本并预览意见」。预览包含实际代码版本、已阅读和未覆盖范围、人工问题、建议和代码位置；个人笔记不会自动附带。

确认前会再次检查远端。如果发现新版本或无法确认最新状态，需要先复核，或明确确认按当前旧版本交付。保存后可以复制或下载 Markdown，各轮结论分别保留。

意见尚未发送到 GitHub；个人完成状态不等于远端已批准或合并。首版由用户自行把确认后的内容交给作者。

## 模型线索和反馈

「审查优先级（模型线索）」置顶展示，提交按保存分数从高到低排列，文件按涉及提交的最高分排序，可在文件列表中切回路径顺序。工作单左侧是同一份提交队列，点击某条提交后文件列表只显示它触及的文件，点「全部文件」恢复；旧分析没有提交文件映射时保持全部文件并说明不能按提交筛选。线索可主动使用实际登记的模型生成；项目启用自动跟踪时，也可能已有固定自动模型的结果，两者并列显示、互不覆盖。任务固定 PR 目标 HEAD 与模型，结果只展示真正覆盖的 PR 提交分数。模型停用或失败时保留原选择和原因，人工代码阅读及笔记仍可继续。

分数用于辅助阅读顺序，未经当前仓库概率校准，不代表 PR 整体缺陷概率；提交级解释不能当作行级缺陷定位。原任务和解释可在固定分析中核对，模型与数据维护继续由管理员完成。

线索可以标记「有帮助」「无关」或「需要更多证据」并填写理由。反馈保存在个人工作单，不自动上传、公开给管理员、成为训练标签或修改模型。分享案例时先选择条目并预览字段，确认后生成本地文件；个人笔记及其他未选记录不会附带导出。

## 仓库概览与第一次分析

新建项目只登记仓库，不自动开始分析。项目「概览」显示 GitHub 仓库的公开元数据、语言构成、最近 12 周提交活跃度和最近提交；这些是仓库活跃度，不是模型分数或缺陷率。GitHub 暂时不可用时显示上次缓存或原因，不影响项目分析。

第一次分析由你点「发起第一次分析」；模型、分支、日期范围和提交上限在对话框里选择。分析结果和记录在「分析」页，概览页保持仓库基本信息不变。

「分支提醒」默认关闭。开启后定期检查跟踪分支，发现新 HEAD 只写项目动态和站内提醒，不会自动分析；点「分析这次更新」后再选择模型与范围。远端 HEAD 与当前分析一致时不重复提醒。

## 查看项目风险趋势

在项目「分析」页切到「风险趋势」，页面会按当前口径自动准备默认固定视图；也可以改选可比口径（分支、模型与运行、特征 schema、分档规则），设置起止日期与粒度后生成新视图。地址保留 viewId，重开读取同一份来源。已有新分析时页面只提示，点击「生成新的固定视图」才纳入；旧视图保持不变。

图分平均模型风险分与高分占比两张单轴折线，附等价数据表和固定来源提交列表；提交量在汇总与表格中。可用键盘方向键在桶间移动、Enter 下钻，点击任一行进入原分析提交。平均风险分按桶内已评分提交取平均，是模型估计；未知桶显示横杠而不是 0；已评分样本少于20时不画占比。高分是模型分档结果，不是真实缺陷率。来源删除或内容变化时视图明确不可用，需要重新生成；同 SHA 冲突时整组拒绝并列出冲突来源，可改用单次分析查看。

## 项目级 PR 自动跟踪

项目「PR 审查」页右上角的「自动分析」打开设置：选择固定自动模型并启用，首次会显示将处理的开放且非草稿 PR 数量，确认后才排队。默认每五分钟检查；只在后端运行期间执行，服务停止或休眠时不承诺检查。

自动任务固定快照和模型，改管理员默认模型不会替换它。同一快照与模型复用已有结果；每个 PR 最多一个在途自动分析和最新待处理目标，手动任务不会被自动调度取消。临时失败自动重试最多3次，限流按服务端返回的等待时间；模型或来源失效需要主动处理，不自动换模型。

「站内提醒」列出新 PR、版本更新、分析就绪、需处理失败及关闭/合并事件。已读只在当前浏览器保存，已读不等于已复核。点开提醒进入对应固定来源；分析覆盖不完整时会明确说明，不能当作低风险结论。个人「暂停关注」不影响项目后台；项目暂停停止后续检查和新入队，但不取消已提交任务。

## 分支提醒

项目页仍可发起指定范围的分析，查看及对比历史记录。新建项目不会自动分析；「分支提醒」默认关闭，需要时在项目页明确开启。检查只在后端运行期间执行，关闭页面后可继续，后端停止期间不执行。

「立即检查」读取跟踪分支的真实 HEAD。远端 HEAD 与当前分析一致时不重复提醒；发现新提交时只写项目动态和站内提醒，不自动建分析。模型、窗口和提交上限在「分析这次更新」或「发起分析」里选择。旧项目已开启的分支自动分析升级后改为只提醒，已提交或运行中的任务不受影响。

部署前按[当前产品](当前产品.md)备份数据库并升级至017；显式初始化旧库会先自动生成一份一致的 SQLite 备份，备份失败则不升级。再启动单个后端进程。个人工作单使用浏览器备份，不由数据库升级替代。
