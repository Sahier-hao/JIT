# 运维与升级

本页只保留本机升级、备份、回退、模型重建与故障处置命令。产品行为与入口见[当前产品](当前产品.md)，模型包交付见[模型包部署](模型包部署.md)。

## 升级前

1. 停止当前后端，确认没有排队或运行中的分析、训练与数据集构建。
2. 用 SQLite backup 备份 `backend/storage/catalog.sqlite3`；模型目录、`backend/model-packages/` 与数据集根共同保留。
3. 记录当前迁移版本与默认模型 ID。

`catalog-init` 在显式初始化旧库时会先在数据库同目录生成一致的 SQLite 副本（`catalog.sqlite3.before-v<旧版本>-<随机>.sqlite3`）；备份失败则不升级。

## 应用迁移与内置模型

```bash
cd backend
./.venv/Scripts/python.exe -m jit_baseline.cli catalog-init
```

该命令应用迁移、校验并登记仓库内置模型包，保留既有项目、分析、模型与管理员账户。包内相同运行身份会复用，模型或包版本变化才增补身份。

若不使用内置包：

```bash
./.venv/Scripts/python.exe -m jit_baseline.cli catalog-init --skip-bundled-models
$keys = 'baseline','decision-tree-v1','random-forest-v1','gaussian-naive-bayes-v1',
        'gradient-boosting-v1','mlp-v1','tabular-resnet-v1','ft-transformer-v1','wide-deep-v1'
foreach ($key in $keys) {
  ./.venv/Scripts/python.exe -m jit_baseline.cli register-model --run-key $key
}
```

## 重建单个模型

以下在 `backend` 目录执行，把方法名替换为实际标识：

```bash
./.venv/Scripts/python.exe -m jit_baseline.cli run --schema openstack-six-v1 --algorithm mlp-v1 --metric-set metric-set-v1 --output artifacts/mlp-v1
./.venv/Scripts/python.exe -m jit_baseline.cli register-model --run-key mlp-v1
```

已有目录不得覆盖；已有完整产物直接由管理页校验登记。深度方法需要已安装声明的 PyTorch 依赖，CPU 即可加载本轮产物。

## 启动与停止

```bash
cd backend
./.venv/Scripts/python.exe -m jit_baseline.cli serve --port 8000
```

```bash
cd frontend
npm run dev
```

本机部署只监听回环地址，维持单后端实例；多个后端不能共享同一任务库调度。服务正常退出会停止自有分析；重启会把遗留作业标为中断，不自动重跑。

## 回退

1. 停止新后端。
2. 另行备份升级后的数据。
3. 恢复升级前数据库与对应代码。
4. 启动升级前后端。

不要用旧代码直接运行新版本数据库。个人工作单还需在浏览器单独导出完整草稿。

## 管理员密码

```bash
cd backend
./.venv/Scripts/python.exe -m jit_baseline.cli admin-reset-password --username 账户名
```

按两次隐藏输入提示重置；原会话全部撤销，重新登录。密码不通过命令行参数传入。

## 数据与模型保护

- 删除数据集前检查 `dataset_references`；被模型、分析或趋势引用的版本不得删除。
- 用户自有版本不能开放共享；管理员共享只作用于无所有者版本。
- 模型目录库、模型包与数据库不进入 Git；Git 只保留经评审的冻结描述文件与交付包。
- 本机采集缓存（`kamei14-git-v2-*/`、`backend/.cache/repositories/`）可重建，不应作为交付物。
