# add-model-card-and-diagnostics 实施审计

## 结论

模型卡已成为普通用户和管理员共用的只读评估视图。普通用户可从项目分析表单的现成模型选择进入，
关闭后模型选择和草稿保持不变；管理员详情展示同一模型卡，并补充运行谱系、产物位置和身份。

## 三档诊断

新训练摘要保存 `metricsByPartition`、数据规模、切分规则和训练吞吐。train、validation、test
分别使用相同指标集与固定阈值，但训练档标记为“拟合诊断”，验证档为“模型选择背景”，只有测试档
承担“冻结泛化评价”。评价按原始 `split.json` 唯一成员进行，类别权重或采样产生的训练副本不会
重复计数。

新运行使用 `partition-diagnostics-v1` 写入配置和摘要；旧模型缺少训练/验证指标时仍可读取，不会
根据当前项目、当前在线结果或其他模型补值。

## 旧模型补充证据

新增离线 `diagnose-model`，报告绑定 `artifactRunId`、模型 SHA-256、数据 SHA-256、schema、
指标集、split 摘要和三档指标。报告缺失、损坏、运行身份不符或指标冲突时明确失败或显示“未记录”。

当前九模型已生成九份冻结分区诊断。校验确认运行身份、模型哈希、数据版本和 split 数量一致；
原模型文件与 manifest 未改写。

## 收益报告身份修正

审计发现旧 `benefit-evaluation` 九份报告绑定的运行身份和模型哈希与当前模型包不同，不能直接用于
当前模型卡。旧报告保留不动，本轮为当前九模型重新生成收益报告；模型卡只显示身份匹配的结论。
因此卡片会主动显示“模型分数低于风险/成本密度、时间顺序或随机顺序”等不利结果，不用于自动择优。

## 权限与字段

公开端点 `GET /api/v1/model-cards/{modelId}` 只返回模型卡字段，不包含本机绝对路径、SQLite、
候选运行、登记审计或维护动作。模型损坏或停用时返回原因并保留身份，不回退默认模型或其他模型。

## 边界

模型卡是回顾性评估和适用性核对，不是在线缺陷概率、概率校准或因果关系。管理员比较页仍只并列
同口径指标，不自动宣布最佳模型；旧收益报告继续作为历史证据，当前结果以匹配当前模型身份的报告为准。
