# 固定项目分析结果对比验收

日期：2026-10-26。范围：同一项目两次固定成功分析的只读对比、历史入口、筛选分页与原结果跳转。对应 change：`compare-project-analyses`。

## 实现范围

- 基准和目标必须明确、不同、属于同一项目且成功；在同一只读快照核对两侧来源与提交。
- 提交并集分类为仅目标、仅基准、分数或度量变化、一致，分类互斥且计数覆盖并集。差值为目标减基准，单侧分数及差值为空；不把缺失分数补零。
- 返回原模型、运行、已登记名称、分支、范围、数据及保存分数，筛选分页保持全局计数和稳定顺序。名称从登记元数据读取，不经过会加载模型的目录接口。
- 以双分析地址重开，分别进入某侧原提交。比较不改变当前结果、原风险、解释或个人计划，不读取标签、不加载模型或重新推理。
- 模型不同或身份未知时提示不能由差值评价模型优劣、风险改善或缺陷修复。单侧覆盖表示分析范围不同，不代表代码新增删除。

## 真实 Git 与浏览器流程

隔离后端 18491、前端 18492、Git HTTP 18493。进程内 URL 映射将 comparison.example 指向本地固定七提交仓库，不是公网验收；数据库和模型产物均为临时副本。没有拦截 API 响应。

两次分析通过真实 API 发起：基准使用已登记逻辑回归副本，日期输入 2024-01-01 至 2024-01-04；目标使用已登记决策树副本，日期输入 2024-01-02 至 2024-01-08。实际范围、原模型和运行身份保存在各自分析中，当前结果为目标分析。

| 流程 | 观察 |
| --- | --- |
| 历史入口 | 从基准成功记录点击与当前结果对比，进入包含两次正确身份的地址，未切换当前结果 |
| 覆盖与分数 | 仅目标 3、仅基准 1、共同分数变化 3、一致 0；并集共 7 条。两侧使用不同模型，页面持续显示局限 |
| 来源读取 | 两侧显示实际模型名称、分支和时间边界，结束时间明确不含；原模型与运行可展开核对 |
| 筛选与重开 | 仅目标筛选返回 3 条，保留全局计数；重新打开双分析地址读取同一来源 |
| 原结果跳转 | 同一共同提交分别进入基准和目标的固定详情地址，显示各自原分数与解释入口 |
| 当前结果保护 | 对比前后完整项目响应一致，viewSyncId 仍为目标分析；重复比较响应一致 |
| 模型不可用 | 在临时目录使两份模型副本不可加载，比较完整响应仍一致；随后恢复并核对副本内容与哈希 |
| 不经过目录加载 | 新浏览器会话只请求项目与比较业务接口，没有请求 repository-models，名称仍可显示 |
| 桌面与窄屏 | 1440px 和 390px 页面宽度等于视口，来源可读，比较宽表在局部区域滚动 |
