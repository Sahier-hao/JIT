# 个人审查计划备份与恢复验收

日期：2026-10-25 至 2026-10-26。范围：固定成功分析的计划 JSON 导出、来源校验、文件预览与合并恢复。对应 change：`port-review-plans`。

## 实现范围

计划备份格式为 jit-review-plan-v1，只含原项目、分析、数据、模型、运行及按加入顺序的提交标识。服务端在一个只读事务中核对成功状态及全部成员，不加载模型、不计算风险、不保存共享个人选择。请求流上限 1 MiB，条目最多 5000；重复、未知、多余字段及来源不符整份拒绝。

前端导出前请求校验；导入先预览已有与新增条数，确认前再次校验，写入成功才更新内存。合并保留已有顺序与时间，空计划可恢复；旧 v3 键和旧清单迁入兼容。取消、网络错误、文件失败、分析删除及写入拒绝不覆盖原计划，切换来源隔离迟到响应。

窄屏验收发现表格中绝对定位的无障碍文字缺少局部定位容器，使页面宽度扩展到 414px；表格滚动容器增加相对定位后，390px 视口的页面宽度保持 390px，441px 表格在 352px 局部区域内滚动。

## 真实浏览器与下载

agent-browser 使用真实页面与 API，没有拦截接口响应。隔离后端 18481、前端 18482、Git HTTP 18483；进程内 URL 映射将 plan.example 指向本地固定七提交仓库，模型和数据库使用临时副本。项目和分析通过实际 API 建立，浏览器负责选择、导出和恢复。

| 流程 | 观察 |
| --- | --- |
| 选择与导出 | 选择两条提交，校验后下载真实 JSON，文件来源和提交顺序与原分析完全一致，不含风险覆盖字段 |
| 清空后的预览 | 备份有 2 条、已有 0 条、新增 2 条；点击取消后仍为空 |
| 恢复 | 再次选择文件并确认，计划恢复为两条，顺序与备份一致 |
| 重复恢复 | 预览显示已有 2、新增 0；确认后完整 localStorage 字节与此前一致，时间不变 |
| 错误来源 | 修改备份 modelId，客户端拒绝，原计划不变 |
| 未知成员 | 合法来源但加入未知 SHA，后端返回整份拒绝，原计划完整保留 |
| 桌面和窄屏 | 1440px 与 390px 可操作；窄屏表格保持局部滚动，不产生页面横向溢出 |

初始自动化浏览器下载目录使用混合分隔符，Chrome 下载记录显示下载错误，未计为导出成功。改用新隔离会话和 Windows 原生路径的 Downloads 目录后，实际文件写入成功；随后复制到运行目录核对内容。中途测试服务退出后已仅重启本项隔离服务，重新读取固定分析并复核窄屏修复。

原始记录在 `docs/evidence/_run/review-plan-20261025/`，包括下载文件副本 `downloaded-plan.json`、`state.json`、`before-import-storage.json`、`after-restore-storage.json`、`after-repeat-storage.json`、`after-errors-storage.json`、桌面截图与 `preview-mobile-fixed.png`。这些是运行观察，不是冻结或外部评审证据。

## 数据和能力边界

无新增迁移，未升级本机原目录库或改动正式模型/数据产物。校验失败不删除或部分接受提交，恢复不会创建已删除的分析；同模型但不同分析也不能混入。依赖原分析仍存在，不提供跨分析迁移、账户同步或跨窗口事务。不把备份、计划及模型分数作为已确认缺陷结论。
