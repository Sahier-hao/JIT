# 修复建议规则扩展（2026-11-26）

## 规则

保留原有三条规则 ID、标题与行为：

- `py-mutable-default`
- `py-bare-except`
- `py-eval-exec`

新增四条高置信 Python AST 规则：

| 规则 ID | 命中条件 | 建议重点 |
| --- | --- | --- |
| `py-subprocess-shell-true` | `subprocess` 调用显式 `shell=True` | 改用参数列表，人工确认 shell 特性是否必要 |
| `py-yaml-unsafe-load` | `yaml.load` 未传第二个位置参数或 `Loader` | 显式选择与文档格式匹配的安全 Loader |
| `py-requests-verify-false` | `requests` 请求显式 `verify=False` | 核对证书与隔离测试边界，不默认关闭校验 |
| `py-tempfile-mktemp` | `tempfile.mktemp` | 改用原子创建临时文件的接口 |

每条规则都有确定性的 `title`、`rationale`、`manualChecks` 与 `example`；未知规则仍返回
`None`，不生成模糊建议或补丁。未新增第三方依赖、跨语言解析器、网络或模型依赖。

## 版本与历史结果

- 新分析使用 `ANALYZER_VERSION = "python-ast-v2"`、`RULE_VERSION = "2"`。
- `python-ast-v1` 的旧运行与候选保留在独立 `analyzer_version` 下，不迁移、不重写。
- 读取旧快照时优先返回当前 v2；没有 v2 时读取 v1，并在响应 `ruleSet` 中标记
  `status = "legacy"`、`ruleVersion = "1"`。
- 前端显示“旧规则结果，未重算”；不会把旧规则命中与新规则混列。
- 现有三条规则的 ID、模板与原文案未改，因此旧报告仍能解释。

## 前端

- `ReviewCandidates` 继续显示建议标题、示例与人工核对项。
- 新增规则无需专用 UI 分支；示例和核对项使用同一结构。
- 候选响应增加可选 `ruleSet`；旧响应或缺少该字段时按原界面渲染。

## 限制

- 规则是静态线索，不证明代码存在缺陷，也不替代语义分析和测试。
- `shell=True`、`verify=False` 在极少数隔离工具场景可能有明确理由，因此必须保留
  人工核对项，不自动改写。
- 旧 v1 结果只读展示；若要获得新规则结果，需用户对当前快照重新检查。
