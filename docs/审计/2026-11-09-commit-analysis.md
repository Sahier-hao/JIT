# 提交范围触发分析（2026-11-09）

## 实现

`pr-check-analyze` 从本地 Git 仓库的明确 base/head 执行：

1. 解析并核对 base 是 head 的祖先；相同提交或空范围以 `NO_CHANGES`（退出码 2）结束。
2. 沿第一父链重建历史状态，只为范围内提交计算真实 Kamei 特征；合并提交不进入评分。
3. 从目录库加载管理员明确选择的已登记模型；模型缺失/不可校验退出码 2，特征 schema 不能由提交采集生成时退出码 5。
4. 真实推理后生成 `jit-commit-analysis-v1` 报告：仓库与 base/head、模型身份与运行、实际参数、逐提交分数、覆盖与未解析历史、静态候选及修复建议。
5. 报告内容哈希覆盖除生成时间外的全部内容；同一仓库、范围与模型重复执行得到相同 `analysisId`/`contentSha256`。

默认只写报告：不评论 PR、不阻断合并、不修改远端配置，不包含个人草稿。

## 边界

- 特征依赖第一父链，合并提交不评分；历史重写后旧 base 可能不再是祖先，命令明确失败。
- 报告分数仍是提交级模型估计，不是缺陷概率；候选位置来自静态规则，不换算成行级概率。
- CI 示例 `.github/workflows/commit-analysis-example.yml` 已提供完整的检出、模型包校验、导入和分析步骤；**远端工作流尚未实际运行**，本地命令链已验证。
- 远端限流只影响 PR 来源的既有路径；本命令只读取本地 Git，不访问 GitHub。
