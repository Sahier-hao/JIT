# 页面加载性能优化

基线为 `main@a71e3bd`。本轮优化用户工作区的数据与模型列表读取，不改变模型准入、校验或打分语义。

## 实测瓶颈

本地服务冷进程直接调用后端服务（同一台机器）：

- `datasets.load_all()`（139 个数据集 manifest）：约 1.07 秒；数据集、模型试算等页面每次请求都会重新解析。
- `catalog.models()`（34 个模型，逐项加载并校验产物）：首次约 3.9 秒，第二次约 1.2 秒；用户模型列表、模型试算列表和项目模型选择都会调用。
- 其余接口较快：用户数据集视图约 75 毫秒、训练实验列表约 14–23 毫秒、项目列表约 28 毫秒、项目事件约 3 毫秒。

## 调整

- 数据集清单按“相对路径、修改时间、文件大小”签名缓存（LRU 8 项）；描述文件增删或修改会改变签名并触发重新解析，服务启动时已预热一次。
- 用户侧的模型列表与选择（我的模型、模型试算、项目分析模型选择）改为读取已保存的 `ready` 状态与当前策略，不再为每次页面加载完整校验全部模型产物；实际打分或分析加载所选模型时仍走原有的完整校验，产物被篡改时仍会拒绝并标记无效。
- 管理端 `/api/v1/models` 的完整模型校验保持不变。
- 模型试算的数据版本显示改为可读名称（如“Kamei 2013 · columba”），完整版本号仍由接口和详情页保留。

## 结果

- `datasets.load_all()`：首次 843 毫秒，缓存命中 11 毫秒。
- 用户模型试算的兼容模型列表：约 1.18 秒 → 3.4 毫秒。
- 用户模型列表读取：约 1.2–3.9 秒 → 4 毫秒。
- 相关后端测试通过：`test_datasets`、`test_user_predictions`、`test_catalog_api`、`test_model_catalog`、`test_model_policy`、`test_dataset_zip_import`、`test_project_datasets` 共 81 项，随后复核 10 项；`test_model_coverage`、`test_admin_workspace` 另 15 项通过。
- 前端全量：72 个文件、610 项通过；`typecheck`、`lint`、样式来源和模块边界检查通过；生产构建通过。

## 开发与预览

用 Playwright 在本地模拟接口下加载同一个模型试算页：

| 方式 | 脚本请求 | 脚本体积 | 文档加载 |
|---|---|---|---|
| 开发服务器 4173 | 104 个 | 约 25.6 MB | 236 毫秒 |
| 生产预览 4174 | 7 个 | 约 0.36 MB | 67 毫秒 |

本机可见时间分别为 1.16 秒和 0.96 秒（模拟接口，localhost）。开发模式仍会传输大量未打包模块；给用户演示或日常使用建议使用 `npm run build && npm run preview`。

## 边界

- 未使用真实登录会话测 HTTP 端点；耗时来自后端服务函数与浏览器内模拟接口，不作为端到端验收。
- 管理端完整模型校验仍是最慢路径，这是完整性要求的一部分。
- 缓存只信任文件签名；若文件内容被改写但同时伪造修改时间和大小，缓存不会察觉。这是本机缓存取舍，产物实际加载与打分仍会做完整校验。
