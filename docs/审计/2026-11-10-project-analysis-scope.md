# 项目分析结果口径与分区（2026-11-10）

本次重构解决一个具体问题：项目分析页把“项目自训模型的训练期分数”和“90 天留出提交的样本外分数”混在一个列表里，只显示算法名和总数，用户无法判断分数来自哪里、是否可信。

## 实际口径（claude-scholar）

- 模型：`b9b24d11-933d-497f-8a7b-ac976f0150df`，`claude-scholar · 逻辑回归 · L2 · 2026-01-25→2026-10-19`，策略 `repository-trained`，算法 `logistic-regression-l2-v1`，特征 schema `kamei14-git-v2`。
- 数据集：`kamei14-git-v2-claude-scholar-2026-01-25_2026-10-19`，标签规则 `szz-simple-v1`；原始 178 条，纳入 161 条（排除 12 条无新增行、1 条文件过多、4 条变更过大），正例 30 条。
- 切分：训练 105 / 验证 22 / 测试 23，测试截止 2026-07-02；90 天留出从 2026-07-21 起，11 条，正例 2 条。
- 测试指标：23 条 / 5 正例，ROC-AUC 0.778，Average Precision 0.733（无信息基线 0.217），Precision/Recall/F1 0.60，混淆矩阵 TP 3 / FP 2 / FN 2 / TN 16。
- 留出段没有可靠指标：只有 11 条、2 个正例，页面只展示数量与分布，不计算或暗示稳定性能。

## 分区规则

- 训练：不晚于 `split.json` 训练段结束；
- 验证：训练结束之后、验证段结束之前；
- 测试：验证结束之后、测试段结束之前；
- 留出：不早于 `summary.json` 的 90 天留出起点；
- 未纳入：不满足数据集纳入规则（无新增行、变更/文件超限或 14 维特征缺失）；
- 已打分：现成模型分析，没有训练分区。

分区由后端按同步记录、数据集投影和训练产物计算，项目详情与提交接口都返回 `partition`；前端不自行推算。口径按 `(syncId, completedAt, modelId, datasetVersion)` 缓存，不重训、不写库。

- 结果前新增“分析口径”卡：模型身份、数据集纳入/原始/正例、标签规则、训练/验证/测试/留出数量与截止、测试指标与样本量。

## 已知限制
