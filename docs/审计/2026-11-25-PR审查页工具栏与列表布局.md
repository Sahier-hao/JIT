# PR 审查页工具栏与列表布局

基线为 `main@a71e3bd`。本轮只调整项目 PR 审查页的前端信息层级与按钮组织，不改变 PR 同步、分析、批量分析或自动打分的语义。

## 问题

- 范围切换、分析状态筛选和排序与三个操作按钮混在同一行；按钮高度、变体和强调程度不一致，主操作与刷新操作并列。
- 每条 PR 是独立浮动卡片，行内状态、模型、风险和操作挤在一起；“换模型”与“查看 PR”的按钮权重随状态变化，缺少稳定层级。
- 最高风险只在文字里，行动作在右侧换行，窄屏下尤其零散。

## 调整

- 整个 PR 区域统一为一张卡片：顶部标题与操作、第二行筛选、分隔线列表、底部同步与分页。
- 操作按层级分组：
  - “自动打分”改为次级 ghost 按钮，状态用“已开启/未开启”徽标显示；
  - “同步”为带刷新图标的 ghost 按钮；
  - “批量分析 PR”作为唯一主操作。
- 筛选项集中到一条下沉带：开放/已结束/全部分段、分析状态下拉、排序菜单；排序只显示“最近更新/风险最高”与排序图标。
- 列表行改为同一张卡片内用分隔线排列：
  - 标题行带远程状态、草稿和分析状态徽标；
  - 作者、更新时间、模型、复用特征和最高风险放在元信息行；
  - 最高风险使用共享 `Risk` 组件，与风险编码规范一致；
  - 行内只保留轻量文字操作：“分析/重试分析”或“换模型”，以及带箭头的“查看 PR/继续审查”链接；行操作固定在标题行右侧，不再因风险条堆叠而错位。
- 批处理进度、远端检查提示和分析错误统一放在卡片内的提示带中，不再悬浮在列表外。
- 保留 `article` 行语义、现有按钮可访问名称和筛选控件名称，避免破坏已有浏览器旅程。

## 验证

- `npm run typecheck`、`npm run lint`、`npm run check:styles`、`npm run check:modules` 通过。
- `ProjectPullRequests.test.tsx` 13 项通过；前端全量 72 个文件、610 项通过；生产构建通过。
- 用真实 claude-scholar 项目数据在 1440px 和 390px 视口渲染：新卡片结构、筛选、状态徽标、风险条和行操作显示正常；390px 下文档宽度等于视口宽度，无横向溢出。
- 用浏览器检查保留的可访问名称：`同步 PR 列表`、`PR 自动打分设置`、`本页分析状态` 和 5 个“查看 PR”均可定位；行仍为 `article`。
- 浏览器渲染在 API 边界替换登录会话与响应，仅用于版式查看，不作为真实登录验收。

## 边界

- 没有后端、数据库或批次分析行为变更。
- 未运行完整 Playwright 验收套件；已检查其依赖的按钮名称、`article` 行语义和区域名称。
- 列表中的“已关闭”徽标仍按后端缓存的远端状态显示；点击“同步”才会刷新远端状态。
