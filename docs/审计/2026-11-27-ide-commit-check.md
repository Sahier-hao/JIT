# VS Code 提交后自动检查（2026-11-27）

## 实现

扩展 `0.3.0` 在原有报告导入之外增加提交后自动检查：

1. 启动时确认工作区是 Git 仓库根目录，记录当前 `HEAD`，通过内置 Git 扩展的 `onDidChange` 监听提交；Git 扩展不可用时回退到 15 秒轮询。
2. `HEAD` 变化后延迟 1.5 秒，对 `HEAD~1..HEAD` 运行本地 `pr-check-analyze`，报告写入扩展全局存储的 `reports/`，保留最近 20 份。
3. 状态栏显示本次最高提交分；达到 `jitCommitAnalysis.riskThreshold`（默认 0.5）时标黄并提醒，不阻断提交。
4. 静态候选写入 Problems，并按文件行号标出；工作树中已改动的文件不标报告行号，报告过期时清除诊断。
5. 「JIT: 配置提交后检查」保存模型 ID、Python、后端目录、目录库和产物根目录；「JIT: 检查最近一次提交」可手动触发。

## 外部仓库与解释器

- 被分析的仓库不需要包含 `backend`。后端、模型和目录库指向 JIT 项目即可，扩展把当前工作区作为 `--repo`，因此可检查任意本地克隆的仓库；不直接读取远端 GitHub。
- 配置时先复用已配置且可用的 backend，其次使用工作区自带的 `backend`，都没有时弹出目录选择器，标题说明“不需要在当前仓库内”。
- 解释器按「用户配置 → `backend/.venv` → `py -3`/`python`（Windows）或 `python3`/`python`」顺序探测，选中第一个可执行项；后端目录缺少 `jit_baseline` 或解释器不可用时，状态栏显示具体原因并提供「去配置」，不再只报 `spawn python ENOENT`。

## 边界

- 合并提交不评分；首个提交没有父提交，无法计算提交特征。
- 行级候选来自静态规则，不是模型行级概率，也不换算成缺陷概率。
- 模型解释仍由网页端生成；本版不带解释归因，也不做提交前暂存区预检。
- 自动检查只读取本地 Git 与本地目录库，不访问网络，不修改源码或提交。
