# 行级缺陷预测基线评估（2026-11-08）

## 目标

验证“完整 SZZ 行级标签 + 行级特征”能否训练出可跨项目使用的行级风险模型，而不是只在单个仓库内背答案。

## 数据与流程

- 完整 SZZ（`szz-full-v1`）：issue/PR 关联优先、关键词兜底、元数据行过滤、行级 blame。
- 行级样本：正例来自 SZZ 行号证据；负例采用 `same-file`（同一提交、同一文件的未标记行，文件内随机取样）。
- 切分：按仓库留出，或按提交分组；禁止同一提交跨训练/测试。
- 特征：代码文本与前后文（字符 n-gram）、行长/缩进/空行/注释、文件长度与行位置、结构计数（条件/循环/返回/调用/赋值/比较）、语言；默认不含提交级 Kamei 特征。
- 模型：逻辑回归，`class_weight=balanced`，按仓库平衡样本权重，固定阈值 0.5。

## 结果

### JS/TS 语言内

| 训练 → 测试 | ROC-AUC | PR-AUC | Brier | 精确率 / 召回率 |
| --- | ---: | ---: | ---: | --- |
| cc + axios → JIT | 0.735 | 0.750 | 0.209 | 0.702 / 0.527 |
| cc + JIT → axios | 0.674 | 0.683 | 0.232 | 0.672 / 0.534 |
| axios + JIT → cc-switch | 0.634 | 0.521 | 0.252 | 0.512 / 0.505 |

### 混合语言（含提交级特征对照）

| 设置 | ROC-AUC | PR-AUC | 结论 |
| --- | ---: | ---: | --- |
| cc + sub2api → JIT（代码特征） | 0.649 | 0.709 | 有弱信号 |
| cc + sub2api → JIT（加提交特征） | 0.461 | 0.545 | 提交特征泄漏，反而变差 |
| cc + sub2api + axios → claude（全语言） | 0.578 | 0.581 | 接近随机 |
| cc + sub2api + axios → claude（JS/Python/TS） | 0.598 | 0.595 | 略好，仍弱 |

### Python 语言内

| 训练 → 测试 | ROC-AUC | PR-AUC | 备注 |
| --- | ---: | ---: | --- |
| pydantic + flask → claude Python | 0.570 | 0.659 | 测试仅 30 行（17 正例），不可结论 |
| claude + flask → pydantic Python | 0.586 | 0.586 | 训练仅 47 行，不可结论 |

### 仓库内参照

| 设置 | ROC-AUC | PR-AUC |
| --- | ---: | ---: |
| cc-switch 按提交切分（旧负例） | 0.982 | 0.987 |
| cc-switch 按提交切分（同文件负例） | 0.826 | 0.912 |

仓库内指标明显高于跨仓库，说明模型主要记住了项目写法，不能当作泛化能力。

## 结论

1. **行级信号存在但弱**：JS/TS 语言内跨仓库 PR-AUC 0.68–0.75，高于随机；跨语言与 Python 仍接近随机。
2. **提交级特征是泄漏**：加入 `fix`、`la/ld` 等提交特征后跨仓库 ROC-AUC 从 0.649 降到 0.461，默认关闭是正确的。
3. **负例分布决定指标真假**：同文件负例若只取文件开头，会把“行位置”变成假信号（曾出现 0.86 的虚高），必须文件内随机取样。
4. **样本仍偏科**：JS/TS 只有 3 个有效仓库，Python/Rust 各只有 1 个，跨语言无法验证。
5. **不能上线**：当前证据不足以对所有语言承诺“逐行概率”；只能作为研究性基线。

## 决策与下一步

- 产品继续使用提交级风险与完整 SZZ 数据层；行级概率不接入。
- 若继续研究：每语言至少 3–5 个仓库、按语言分别训练与报告；补充 AST/token 结构特征；做概率校准与 Recall@预算；把“行级模型”限定为语言内实验能力。
- 复现命令见 `backend/README.md` 的 `line-dataset` 与 `line-train` 段落；本报告数字来自 `/d/tmp/rep-*.json` 实验报告。
