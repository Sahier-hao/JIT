## 0.4.0 补齐

### 模型 QuickPick

- 后端新增 `pr-check-models --database ... --artifact-root ... --json`；只返回已启用、ready、可加载且提交采集字段兼容的模型。
- 本机目录库实测 13 个：kamei14-git-v2 10 个、kamei14-git-v1 3 个；离线六字段/2013 模型未混入。
- 「JIT: 配置提交后检查」和「JIT: 选择模型」改为 QuickPick；CLI 不可用时才回退手工输入。
- Node 集成调用真实 CLI 成功解析模型数组；单测覆盖重复 ID、错误格式和默认/当前标记。

### 提交解释

- `pr-check-analyze` 为每个评分提交附带 `explanation`；失败降级 `not-supported`，不改变分数。
- 插件新增只读虚拟 Markdown 文档，从侧栏提交节点、通知和命令面板进入。
- 内容包含提交 SHA、模型身份、提交级预测分数、中文摘要和 Top 特征贡献；不渲染 HTML、不执行报告命令。

### 术语与证据

- 状态栏、tooltip、通知、树视图、Problems 和解释视图统一为「提交级预测分数」「可疑代码行」。
- Problems 条目显示规则 ID、命中证据、说明与建议，并支持跳转到文件和行号。

## 宿主冒烟阻塞

执行 `node scripts/smoke.js` 时 Electron 在加载扩展前失败：

```text
FATAL:electron\shell\browser\win\install_dir_access.cc:52
Sandboxed processes cannot read D:\develop\Microsoft VS Code\661626d0e7
its ACL has an entry for an AppContainer package SID but none for ALL APPLICATION PACKAGES
```

未宣称扩展宿主冒烟通过。修复该宿主机环境的命令（需要管理员确认）：

```powershell
icacls "D:\develop\Microsoft VS Code\661626d0e7" /grant *S-1-15-2-1:(OI)(CI)(RX)
```

然后重跑：

```powershell
$env:JIT_VSCODE_EXE='D:\develop\Microsoft VS Code\Code.exe'
node scripts/smoke.js
```

## 现场演示脚本

1. 打开真实 Git 仓库，执行「JIT: 选择模型」，用 QuickPick 选择真实模型。
2. 提交一次带有 `eval`/裸 `except` 的修改；不点「分析」。
3. 状态栏出现提交级预测分数；Problems 显示 `py-eval-exec`、`py-bare-except` 及命中证据。
4. 点击任一可疑代码行跳转到对应文件与行号。
5. 在侧栏提交节点/通知中打开「查看提交解释」，核对 SHA、模型、分数、中文摘要和 Top 贡献。
6. 明确边界：分数是模型估计，不是已确认缺陷；解释是特征敏感度，不是缺陷原因。
