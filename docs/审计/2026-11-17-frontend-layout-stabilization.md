# 前端布局稳定化审计

日期：2026-11-17
范围：`stabilize-frontend-layout-system`
对象：用户工作区、项目列表、项目 PR 审查、数据版本、训练实验、审查预览与管理/工作单布局组合

## 复现与根因

真实运行页面在项目列表、我的数据、我的训练和项目 PR 审查中出现了同一类问题：多行内容被放进 shadcn/ui `Button`，而 Button 默认带固定的 `h-9` 和 `whitespace-nowrap`。按钮的可视边界停留在单行控件高度，项目名、版本号、实验身份和待处理 PR 文本继续向卡片外绘制，造成卡片之间覆盖；PR 页面右侧列表还会把长标题撑出双栏边界。

## 修改范围

- 项目卡片、数据版本、训练实验、待处理 PR、PR 文件项、问题项、提交风险入口和模型覆盖入口改为自然高度，并在需要时允许换行。
- 项目 PR 双栏、审查预览、提交表格、用户/管理员外壳补充 `min-w-0` 和容器内横向滚动边界。
- 项目分析记录的可切换入口改为自然高度，避免历史记录标题与元信息被固定按钮高度裁切。
- 保持现有 shadcn/ui 组件、主题、密度、按钮语义、业务 API、账户隔离和模型身份不变。
- 扩展 `frontend/e2e/shadcn-workspaces.spec.ts`，覆盖项目、数据、训练、PR 待处理列表的内容边界和页面级溢出检查。

## 真实浏览器结果

在现有本地服务 `http://127.0.0.1:4173/` 和后端 `http://127.0.0.1:8000/` 上使用用户已有会话检查：

- `#/projects`：7 个项目卡片各自完整显示，项目名、URL、统计和底部动作落在卡片内部，下一行卡片从上一行底边之后开始。
- `#/my-data`：24 个数据版本在左侧列表中按独立行显示，长版本号在当前项内折行；右侧详情与训练区域没有被列表项覆盖。
- `#/my-training`：训练实验卡片显示完整的数据版本、状态、方法、切分和实验标识，卡片底边完整可见。
- `#/projects/8014faa6-8eec-5ed0-9f20-6f4d9344b12a/prs`：PR 主列表和「待处理 PR」侧栏各自保持在双栏边界内，侧栏条目不再互相覆盖，工具条和列表动作可见。

上述检查在当前 Edge 桌面窗口完成；页面截图和无障碍树均显示多行条目已回到自身边界。

提升权限后运行现有 shadcn Playwright 配置，结果为 `1 passed (1.1m)`，用例 `四主题和窄屏下的标准控件、分析草稿与角色工作区` 通过，实际覆盖 1440px 与 390px 视口、四个主题、项目/数据/训练/PR 页面和管理页面。

第一次在受限沙箱中运行时，Windows 拒绝了测试夹具创建数据集所需的硬链接并返回 `DATASET_UNAVAILABLE`；最小复现确认是 `os.link` 的 `WinError 5`。随后使用项目 `backend/.venv` 并在允许硬链接的提升权限测试进程中重跑，浏览器用例成功通过。

## 规格对照

- IP-08：多行卡片和列表项不再由固定高度控件裁切；桌面实时页面没有观察到页面级横向溢出。
- IP-10：项目 PR 双栏、数据/训练列表和审查预览的列表—详情边界保持清晰，操作不再覆盖内容。
- IP-16：多行可点击内容仍使用 shadcn/ui Button，但明确覆盖自然高度和换行行为，普通按钮尺寸保持不变。
- IP-30：共享令牌、颜色、密度和控件层级未改变；只修正布局组合、最小宽度和内容边界。

## 未解决的非阻断项

- lint 中仍有既有 React effect、Fast Refresh、ref 和依赖数组 warning；构建中仍有 ECharts 大 chunk 与无效动态导入 warning，均未阻断本 change 的布局验收。
