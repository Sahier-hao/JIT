# 提交解释与历史修复证据（2026-11-26）

## 现状审计

- 提交详情原先已展示正例的后续修复提交、路径与时间，但只链接到修复提交首页，
  `lineRanges/parentRanges` 在前端解析时被丢弃。
- PR 只读预览与工作单展示提交分数和候选，没有显示同一条历史修复证据。
- 离线 PR 检查包与 Markdown 报告没有携带修复证据。
- 提交解释已有遮挡均值与逻辑回归 log-odds 两种方法；结果按方法保存并绑定原分析、
  提交、模型和运行。原模型不可用时仍可读取旧解释。

## B1 解释可读化

- 新增 `featureSummary`：只从本次已保存的贡献项生成模板摘要，例如
  “本次分数主要受新增行数、目录数推高模型分数；子系统数、文件数拉低模型分数。”
- 中文名称复用现有前端与文档口径：`nf` 文件数、`la` 新增行数、`nd` 目录数、
  `ns` 子系统数、`ld` 删除行数等，不新增同义标签。
- 摘要最多使用每个方向前两项贡献，不补充未出现在 `explanation` 中的特征；
  稳定性为 `unstable` 时追加“特征排序不稳定，不作为确定主因。”
- 原有 `explanationSummary`、方法、单位、基线来源、稳定性、模型身份与保存路径保持不变。
- 旧 payload 没有 `featureSummary` 时返回 `null`（而非重算），前端回退到原
  `explanationSummary`；数据库中的历史解释不会被改写。
- OpenAPI 将该字段声明为可选可空，旧解释仍符合新契约。

## B2 历史修复证据

- `RepositoryLabelEvidence` 前端契约补齐 `lineRanges`、`parentRanges` 与
  `diffAnchor`，并对行号范围做正整数校验。
- 后端按文件路径计算 GitHub diff 锚点 `diff-<md5(path)>`；`parentRanges` 表示修复提交
  左侧 diff 行，`lineRanges` 保留引入行。
- 提交详情与 PR 只读预览复用 `HistoricRepairEvidence`，链接到修复提交 diff 的对应文件
  和首个修复行；无锚点时仍保留提交链接。展示“修复 diff 行”“引入行”和日期。
- PR 快照分析响应在存在证据时附加 `labelEvidence`，不改变已有分数与文件映射。
- 离线 `pr-check-export` 在提交记录中附带同一证据；JSON 报告保留结构化字段，
  Markdown 报告增加“后续修复证据”表与 GitHub diff 链接。
- 该证据只读；不生成补丁、不自动应用，也不冒充模型建议。

## 限制

- SZZ 是弱标签；修复证据是历史关联，不是人工确认的缺陷因果链。
- GitHub diff 锚点依赖路径；路径变化时后端保留原路径证据，但不猜测新路径。
- 旧解释不会获得新模板摘要，直到用户对相应方法重新生成解释；历史分数与模型不变。
