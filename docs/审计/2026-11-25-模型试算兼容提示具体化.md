# 模型试算兼容提示具体化

基线为 `main@a71e3bd`。本轮只改“模型试算”的空状态提示与入口，不改变兼容性判定规则。

## 问题

空状态只写“没有 schema 兼容且已启用的模型”，没有说明需要哪个 schema、账户里已有哪些 schema 的模型，以及如何登记刚训练完的模型。

## 调整

- 空状态显示所选数据版本需要的特征 schema。
- 显示当前账户已启用模型的 schema 列表。
- 按特征 schema 查找同 schema 下“训练完成但尚未登记”的模型，显示数量并提供“去登记 N 个模型”，直接打开对应训练实验。
- 没有待登记模型时提供“去训练”，按当前数据版本打开训练创建入口。
- 模型下拉占位改为“没有兼容的已启用模型”。
- 数据版本下拉改用可读名称（如“Kamei 2013 · columba”）；完整版本号仍保留在接口与详情中。
- 兼容性仍由模型 `featureSchemaVersion` 与数据版本 schema 是否一致决定；同 schema 的其他数据集可以共用模型。

## 验证

- `npm run typecheck`、`npm run check:styles`、`npm run check:modules` 通过；`npm run lint` 无新增错误，保留既有警告。
- `npm test`：72 个文件、610 项通过（新增 1 项空状态与登记入口测试）。
- `npm run build` 通过，保留既有分块体积警告。
- 用真实账户数据渲染：
  - 登记后的 columba 数据版本可直接选到 FT-Transformer（schema `kamei14-2013-v1`）。
  - 用未登记快照渲染：提示显示所需 schema、已启用模型 schema `kamei14-git-v2、kamei14-git-v1`、3 个同 schema 待登记模型，并提供“去登记 3 个模型”。
- 浏览器渲染在 API 边界替换登录会话与响应，未走真实登录；不作为登录旅程证据。

## 边界

- 没有后端、数据库或模型产物变更。
- 不自动登记模型；登记仍需用户在训练实验页确认。
