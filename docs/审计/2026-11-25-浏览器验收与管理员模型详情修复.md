# 浏览器验收与管理员模型详情修复

基线为 `main@b65907d`。本轮未停止 `127.0.0.1:8000` 和 `127.0.0.1:4173` 上的现有服务，浏览器验收使用独立端口 `18830/18831`、一次性 SQLite、临时 Git 仓库和模型副本。

## 实际失败

首次运行 `npm run test:e2e:acceptance` 时，12 项中 5 项通过、4 项失败、3 项跳过。失败分为两类：

- 管理员模型设置在 390 像素视口下横向溢出。模型设置卡片的外层为隐式网格列，长训练数据版本号把内部列撑到 508px，而可用内容宽度只有 342px；`break-words` 又覆盖了预期的 `overflow-wrap:anywhere`。
- 两处浏览器选择器过严，以及一个依赖 `18860` 端口的 shadcn 用例被误放进主验收套件。页面实际内容与接口响应正常，不属于产品失败。

## 处理

- `AdminModelPolicyPanel` 改为显式单列可收缩网格，`dl` 内部也使用单列轨道；长字段、子项和值都允许收缩，并只保留 `overflow-wrap:anywhere`。
- `focused-review.spec.ts` 在允许重复文本出现的位置使用首个匹配；验证报告来源标识按实际组合文案匹配。
- `shadcn-workspaces.spec.ts` 加入主验收套件的排除清单，继续由 `playwright.regression-pr.config.ts` 的专用服务运行。

## 验证结果

- 窄屏探针：390 像素下文档宽度 390，模型目录 342px，设置卡片 342px，内部字段区 300px，无横向溢出。
- 定向浏览器：`focused-review.spec.ts` 与 `model-policy.spec.ts` 7/7 通过（4.0 分钟）。
- 主验收套件：11 项中 8 项通过、3 项按设计跳过、0 项失败（4.2 分钟）。
- 前端单测：72 个文件、609 项通过。
- `typecheck`、`lint`、样式来源检查、模块边界检查和生产构建通过；Lint 与构建保留既有警告。
- 远端手动完整回归在基线上成功：GitHub Actions run `45536594564`。
