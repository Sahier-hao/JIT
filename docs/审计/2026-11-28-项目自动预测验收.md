# 项目 PR 自动预测验收

## 实现与展示

- PR 列表响应补充 `headSha`、提交列表、`commitCount`、`commitsComplete` 和 `checkedAt`。页面在已有最高提交分与模型身份旁展示 head、提交数量、最近检查时间，并可展开提交列表。
- 项目自动打分开启时，PR 列表在本地缓存上低频轮询；后台仍由 `PullRequestUpdates.tick()` 执行远端发现和自动提交，页面不调用单 PR「分析」。
- 自动分析继续固定项目 `pr_watch.model_id`，不因管理员默认模型变化而替换。

## 自动化端到端验证

新增 `test_background_tick_discovers_new_pr_and_pushed_head_without_manual_analysis`：

1. 项目启用固定模型自动打分；
2. 后台 tick 先完成空范围检查；
3. 远端新增 PR #7，推进时钟后 tick 自动发现并排队；
4. 完成任务后 tick 观察结果，列表显示 `completed`、固定模型、head SHA 与提交列表；
5. PR head 更新为 `b*40`，再次 tick 自动创建新目标，页面显示新 head 与新任务；
6. 完成第二次任务后显示最终分数 `0.4`。

## 可复现演练命令

在具备 GitHub 凭据和网络的环境：

1. 准备专用仓库或明确目标 PR，不向主开发分支写测试提交；
2. 后端设置 `GITHUB_TOKEN`，启动隔离服务并创建/打开该项目；
3. 在「PR 自动打分设置」选择真实模型并启用；
4. 在远端创建新 PR 或向目标 PR 推送新提交；
5. 等待后台检查周期（默认 300 秒），记录：
   - 远端 head SHA/提交列表；
   - `pr_watch.last_checked_at` 与 `pr_auto_intent`；
   - 自动任务 `origin=automatic`、`requested_model_id`；
   - 页面显示的最高分、模型、head、提交列表与状态；
6. 将时间线和日志写入 `docs/audit/` 与 `docs/evidence/`，不得用本地模拟冒充远端事实。
