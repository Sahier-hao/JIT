# 账户个人审查记录隔离验收

日期：2026-11-16。实施范围：OpenSpec change `isolate-account-review-drafts`。个人正文仍只保存在当前浏览器，没有新增服务器草稿同步或团队协作。

## 1. 实现范围

- 会话状态明确为核验中、已登录、未登录和核验失败；客户端只用 `/api/user/session` 返回的普通用户名作为个人空间身份，显示名称、URL、管理员会话和客户端自报值都不参与。
- 工作单存储键升级为 `jit:pr-review:works:v2:<编码账户>`；读取、保存、事件与缓存显式接收账户上下文和会话世代号，不在存储函数内部回读全局用户名。
- 账户切换、退出、401 或会话失效时撤下旧视图；迟到的快照、保存、轮次和导入回调核对发起账户与世代号，不写入新账户。
- 保留账户内 revision 冲突保护和完整快照结构；问题、阅读进度、结论、候选判断和反馈全部随账户隔离。
- 保存失败或被动退出时，未保存内容写入原账户恢复副本；恢复副本只在原账户重新核验后可读取或导出，不成为跨账户通道。
- 旧 `jit:pr-review:works:v1` 保持无归属、只读、不删除；「我的审查」提供显式导入，先显示目标账户、条目和差异，确认后按现有合并规则写入，并记录源内容回执避免重复堆叠。
- 备份升级为 `jit-pr-review-v2`，包含非凭据账户提示；继续兼容 v1。跨账户或未知归属导入必须确认当前目标，实际写入仍只使用当前已核验账户。
- 同一账户的续审、作者新版本复核、备份合并、Markdown 导出一致保留。localStorage 仍不承诺对本机持有人或同源脚本保密。

## 2. 实际浏览器旅程

使用隔离持续审查服务（后端 18773、前端 18772、独立数据库、仓库与模型副本），两个真实注册账户 `alice-review`、`bob-review` 审查同一 PR：

1. A 登录后创建同一 PR 工作单，记录个人笔记「A 的私人笔记 · 晚点核对」；刷新页面并重新打开文件，笔记恢复。
2. 测试控制接口把远端 PR 从版本 25 推进到 26；A 点击「检查 PR 更新」并「开始复核新版本」，保存两个轮次，旧轮次和笔记保留。
3. A 打开「输出意见」，填写说明并预览 Markdown，确认保存结论；本地记录包含建议修改结论、说明和原笔记。
4. A 在个人空间退出登录；alice 存储键保留，页面不再展示 A 的内容。
5. B 注册并登录，打开同一 PR：显示「创建审查工作单」，不显示 A 的笔记或结论；B 创建自己的工作单并记录「B 的独立笔记」。
6. 此时浏览器同时存在 `...v2:alice-review` 和 `...v2:bob-review` 两个键，A 与 B 的笔记各自正确。
7. B 退出、A 重新登录并打开同一 PR：A 的笔记、两轮版本和结论恢复，B 的内容不出现。
8. 在 `#/reviews` 中构造一份旧 v1 工作单，确认首次登录不自动认领；点击「导入本机旧工作单」显示目标 `alice-review`、1 个条目和「已有工作单，1 处差异按当前判断合并」，确认后当前笔记保留、旧 v1 原字节未删除，并写入导入回执。
9. 保存失败场景通过恢复流程验证：一次作者更新期间写入被核验状态拒绝，页面显示恢复提示；恢复后写入账户键并清除恢复副本。
10. 外部会话失效：调用退出接口并触发账户变化事件，页面立即撤下旧工作单并显示登录页，本地账户键未被删除。

## 3. 已运行检查

- `npm run typecheck`：通过。
- `npm test`：55 个测试文件、399 项通过。新增账户隔离单元测试覆盖同一 PR 双账户互不影响、账户内 revision 冲突、旧数据不自动认领、导入回执、v2 备份归属提示与 v1 兼容。
- 持续审查页面、登录流程、PR 工作单、预览、项目列表、通知等既有组件测试通过；`src/prReview.test.ts` 10 项通过。
- 浏览器旅程使用真实注册账户与隔离服务；上文第 8、10 项分别通过显式构造旧键和会话事件完成，不是仅存储函数单测。
- 修复了浏览器验收中发现的抽屉不可见问题：原 Mantine Drawer 在该页面计算高度为 0、内容不可达；改为固定定位面板后「输出意见」「版本与说明」「个人草稿备份」可用。

## 4. 限制与未完成

- 没有执行两个真实浏览器标签页同时登录不同账户；跨标签页路径由 `storage`/账户变化事件触发重新核验的代码和会话失效旅程覆盖，未宣称完成真实双标签页并发测试。
- 未模拟浏览器存储配额耗尽后的强制关闭；保存失败时页面保留文本并提供导出，持久化失败的限制沿用既有语义。
- localStorage 不是安全存储；本变更只保证应用层账户命名空间隔离，不承诺同源脚本或本机持有人不可读。
- 未新增服务器同步、团队共享或跨设备迁移；个人正文不上传。
- 管理员会话不提供个人审查身份；仅有管理员会话时不加载任何个人工作单。
