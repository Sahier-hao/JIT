# 项目同步入口与 PR 刷新文案

基线为 `main@a71e3bd`。本轮只调整项目页的入口位置和按钮文案，不改变检查、同步或分析行为。

## 问题

- PR 列表里的“同步”容易被理解成同步整个仓库或拉取 main 分支；实际只刷新远端 PR 列表。
- 仓库级“订阅分支更新”只出现在概览页，进入 PR 审查或分支分析后看不到，用户不知道应该在哪里检查新提交。

## 调整

- 将 `RepositoryUpdates` 从概览页操作区移到项目页签栏右侧，在所有项目页签都可见。
- 触发按钮文案从“订阅分支更新”改为“检查分支更新”，保留状态“无新提交 / 有新提交 / 检查中 / 未完成”；弹窗内仍可开启定时订阅和设置跟踪分支。
- PR 列表按钮从“同步”改为“刷新 PR 列表”，并增加说明：只刷新远端 PR 列表，不拉取分支代码或运行模型。
- 这样项目页固定有两个不同层级的入口：
  - 页签栏右端：检查分支更新（仓库/分支级）；
  - PR 列表内：刷新 PR 列表、批量分析 PR（PR 级）；
  - 分支分析页：分析分支提交（实际采集与打分）。

## 验证

- `RepositoryUpdates`、`ProjectPage`、PR 页面和 shadcn 工作区测试的按钮名称已同步更新。
- 前端全量：73 个文件、612 项通过；`typecheck`、`lint`、样式来源、模块边界检查和生产构建通过。
- 用真实 claude-scholar 数据渲染：页签栏右侧显示“检查分支更新 无新提交”，PR 列表显示“刷新 PR 列表”，两者位置和语义分开；1440px 无横向溢出。
- 浏览器渲染在 API 边界替换登录会话与响应，仅用于版式查看，不作为真实登录验收。

## 边界

- “检查分支更新”只检查远端追踪分支是否有新提交，不会自动采集、训练或打分；实际分析仍需“分析这次更新”或分支分析页发起。
- 没有后端、数据库或模型产物变更。
