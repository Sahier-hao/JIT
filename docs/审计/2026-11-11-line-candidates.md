# 完整候选集与行级定位评价（2026-11-11）

评价总体事先确定为引入提交 diff 中全部合格新增/修改代码行（`introduced-added-lines-v1`），
不从标签挑选、补齐或删除。未在 SZZ 证据中的行是“未观测”，不是已证实无缺陷。

## 一、导出实现

`jit_baseline.cli line-candidates <manifest> --repo <缓存或本地仓库> --output <jsonl>`：

- 逐提交解析 `git show --unified=0 --find-renames=50%`，只取新增/修改侧（side=new）；
- 候选字段：仓库、revision、数据集版本、提交、路径、侧别、行号、文本、语言、标签状态与证据；
- 正例来自数据集描述的行级 `labelEvidence`，重命名时把旧路径证据映射到新路径；
- 排除计数：路径不在源码范围、空白/噪声行、二进制、空 diff、缺失 diff；
- 证据行不在候选总体中时记为“不可覆盖”并分类（`line-not-in-diff` 等），不换成全文件总体。

确定性小历史（真实 git 仓库，含新增/修改/重命名/删除/二进制）验证了行号推进、重命名映射与
不可覆盖分类；测试 `tests/test_line_candidates.py` 3 项通过。

## 三、评价协议

- 在同一完整候选总体上比较：结构基线（行长度）、关键词基线（`except`/`eval`/`exec` 等固定列表）、
  固定种子随机顺序（42/43/44）；
- 指标：按提交分组的 IFA（首个正例前检查的负例数）、Top-1/5/10 命中、候选行 10%/20% 预算的
  正例召回、候选规模与正例覆盖；
- 并列按 (提交, 路径, 行号) 固定顺序，预算按整行累计、不拆分；无正例提交单独计数。

指标只表述为弱标签上的排名评价，不等于真实缺陷检出率；不接入项目分析或 PR 审查。
