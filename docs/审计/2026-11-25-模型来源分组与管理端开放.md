# 模型来源分组与管理端开放

基线为 `main@a71e3bd`。本轮把“用户能选哪些模型”从隐式规则改为显式开放，并统一分析、PR 与试算的模型选择器；不改变模型产物、训练或评分算法。

## 问题

- `/api/v1/repository-models` 把 `owner_user_id` 为空的历史/内置模型直接并入每个用户的可选列表。本机 34 个模型中 29 个没有所有者，登录用户会在分析与 PR 对话框中看到大量并非自己登记的模型，其中多数还因 schema 或校验状态显示“不可用”。
- “我的模型”只返回本人模型，与选择器实际展示的范围不一致；页面也没有区分“本人训练”和“管理员开放”。
- 管理员端只有启停和默认模型，没有“开放给用户”的操作；模型共享只能依赖“无所有者即公开”的隐式规则。
- 分支分析使用原生 `<select>`，PR 批量分析与自动分析各自维护一套下拉，外观和信息层级不一致。

## 调整

### 显式开放

- 迁移 `044_model_sharing.sql` 新增 `model_share(model_id, shared_by, shared_at)`，与 `dataset_share` 同构。
- 普通用户可见模型 = 本人登记 ∪ `model_share` 中显式开放的模型。未开放的无归属模型不再自动进入用户列表。
- 已登录用户即使同时持有管理员会话，模型选择列表仍按用户范围返回；管理员会话主要影响管理端与写操作。
- 无用户会话的本机操作（CLI、既有本地流程）继续允许无归属模型，避免把本地维护误判为越权。
- 新增 `PUT /api/v1/models/{modelId}/sharing`，仅管理员可用。开放要求模型 `state=ready`；撤销开放不删除模型、历史分析与评分。
- `/api/v1/repository-models` 增加 `shared` 字段；`/api/v1/user/models` 返回 `mine` 与 `shared`，共享列表只包含可用且已启用的模型。
- `catalog.registered_models()`、模型详情和诊断列表统一返回 `shared`；就绪指标拆分为“可用于仓库打分”和“用户可选”，没有开放模型时给出 `NO_USER_MODEL`。

### 服务端选择校验

- 新增统一校验：显式选择的模型必须是本人模型或已开放模型，管理员不受限。覆盖分支分析、单个 PR 分析、批量 PR 分析、PR 自动分析设置和模型试算。
- PR 分析未显式传模型时先解析默认模型再校验，避免绕过选择列表使用未开放模型。
- 模型试算的创建与列表使用同一可见范围；历史批次读取不受影响。

### 界面

- 新增共享 `ModelSelect`：按“我的模型 / 共享模型”分组，只列已校验、启用且 schema 兼容的模型；重名模型附带短 ID。
- 原选模型不在可见范围时保留为禁用项并阻止提交，不自动替换。
- 分支分析、PR 批量分析、PR“换模型”和 PR 自动分析统一使用该选择器；PR 自动分析保留“显示不可用模型”的上下文。
- “我的模型”拆成“我的模型”和“管理员开放”两组；本人模型可打开训练数据，共享模型只提供模型卡。本人模型若已被开放，显示“已开放”。
- 管理端模型设置新增“开放给所有用户”开关、`已开放` 标记和“已开放”筛选；撤销开放前二次确认。模型来源显示为“用户 X”或“系统内置”。

## 本机数据核对

- 迁移后目录库版本 44，`model_share` 初始为空；34 个已登记模型中用户 `client` 可见 5 个（全部本人模型）。
- 这 5 个模型中可用于仓库打分的 2 个：`kamei14-git-v2` 与 `kamei14-git-v1` 的 Wide&Deep；其余为 `kamei14-2013-v1`，仅出现在本人模型列表。

## 边界

- 开放与启用是两个独立状态：停用模型即使保留开放记录，也不会出现在用户可选列表；重新启用后按原开放状态生效。
- 撤销开放只阻止新的选择；已有分析、PR 批次和试算记录继续可读，不重写模型身份。
- 单用户模型数量未增加配额；共享模型不复制产物，不改变训练或评分结果。
- 没有用户会话的本机请求（CLI、既有本地维护脚本）仍可读取无归属模型，避免把本地维护流程误判为越权；登录用户的界面与服务端校验使用“本人 + 已开放”范围。
- 历史无归属模型保留在管理端，管理员可按需逐个开放；迁移不自动开放任何模型。
