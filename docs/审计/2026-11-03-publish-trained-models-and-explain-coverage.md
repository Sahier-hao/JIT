# 模型发布、训练覆盖与可见性诊断

## 结果

九个已登记标准模型现在可以导出为带版本、逐文件哈希和 SHA-256 sidecar 的 ZIP 模型包。空目录库可通过维护命令导入并保持九个模型 ID 与产物运行身份；混合包中的有效项独立登记，位置冲突和损坏模型逐项拒绝。SQLite、模型二进制和运行期包均不进入 Git。

管理员模型页现在持续显示已登记、ready、用户可选、完整未登记和无效数量，并按数据集展示九种方法的覆盖网格。页面区分后端不可达、空目录、完整未登记、已登记不可服务；模型包面板显示最近导入的逐项失败原因。普通用户模型选择只包含产物重新校验通过、启用且 schema 兼容的登记模型。

## 关键实现

- 包格式 `jit-model-package` 版本 1，拒绝未知版本、越界/隐藏路径、链接、加密、重复、超限和未声明文件。
- 导出只接受明确选择的 ready 模型，生成 `packageSha256`、文件数、压缩/解压大小和 `.sha256`；sidecar 写入失败会删除不完整包。
- 导入复用现有 manifest、完整产物、模型加载和运行身份准入；新建、复用、已登记、冲突和失败逐项持久化。
- 源环境默认和启停策略不进入包；空目录首个合法兼容模型按既有规则成为默认。
- 覆盖矩阵为套件索引、完整运行和目录登记的只读投影，校验缺失或哈希不一致产物，不自动登记或择优。
- API 增加管理员覆盖查询和 readiness 诊断字段；公共模型选择与管理员“用户可选”集合使用相同 `modelId` 和 schema 规则。
- 迁移 021 只新增模型包导入与逐项结果表；旧库升级继续使用显式 `catalog-init` 和升级前 SQLite 备份。

## 隔离恢复

本机实际九模型发布包 SHA-256 为 `3c15b7d9453291ba5c106e09b93403e234c0c1c67c0413b2d3654820f3377d76`，包含 9 个模型、81 个文件和 18,881,077 字节解压内容。

隔离浏览器验收从真实产品目录重新导出九模型，清空一次性目录库和产物根后导入：9 个模型全部新建，源模型 ID 和 `artifactRunId` 保持不变，管理端与用户选择身份一致。随后导入三模型混合包，得到一个成功、一个位置冲突和一个文件损坏，整包 `partial`，成功项保持可用。

## 验证

- 后端：676 passed，1 skipped。
- 前端：45 个文件、344 passed；typecheck、lint、build 通过。
- Playwright：默认 16 passed；大型仓库训练、实验登记、专用模型包和专用预览分别通过。
- 模型包恢复截图覆盖 1280、1440、390 三种宽度，无页面级横向溢出；矩阵单元可用键盘进入模型详情。
- OpenSpec strict 校验通过。
