# expose-project-datasets 实施审计

## 结论

项目成功分析现在可以在一层交互内查看本次实际绑定的数据集，并下载可校验 ZIP 或 XLSX。
普通用户只能访问当前项目、当前分析绑定的单个版本；管理员数据集工作区、清洗、训练和全量
浏览能力没有开放给普通业务接口。

## 实现

| 范围 | 结果 |
| --- | --- |
| 数据集解析 | 服务端先校验项目与分析身份，再从成功分支分析记录读取 `datasetVersion`；失败或跨项目分析不退回其他版本 |
| 安全摘要 | 只投影版本、schema、时间、质量统计、来源、标签、限制、字节数和 SHA-256，不返回绝对路径或全局登记信息 |
| 权威导出 | ZIP 包含 CSV、portable manifest 与 `SHA256SUMS`；生成前重新校验 CSV、manifest 和决策旁车 |
| 便捷导出 | XLSX 使用 write-only 工作簿，包含 `data` 与 `metadata`，明确为派生视图而非权威身份 |
| 边界 | 总导出限制 64 MiB，XLSX 最多 100,000 行；缺文件、哈希错误、版本不匹配和超限均明确失败 |
| 前端 | 当前成功分析增加“数据来源”入口，显示摘要、限制及 CSV/XLSX 下载，不增加全局数据集导航 |
| 文档 | 当前产品、后端接口说明和开发验证已补充项目范围权限与权威性边界 |

## 回归修正

最终默认 Playwright 暴露了一个复用场景：同一数据集版本被后续分析复用时，服务端曾把
manifest 的原始 `sourceSyncId` 错当成当前分析身份并返回 409。实现已改为通过成功分析的
`datasetVersion` 解析绑定，保留原始来源供追溯，并增加 `REUSED_SYNC` 回归测试。

合并最新 `main` 后，新视觉层与项目页窄屏布局叠加，又暴露出仓库绝对路径不可断行导致页头
被撑到 476px 的问题。页头和项目路径现可收缩换行，结果操作区不再左移；受影响的四组项目页
浏览器用例全部恢复通过。

## 验证

- 后端全量：741 通过、1 项因真实源码数据集未配置而跳过。
- 前端 Vitest：46 个文件、358 项全部通过。
- typecheck、lint、build 通过；lint 与 build 仅保留既有警告。
- 默认 Playwright：17 通过、1 项按项目配置跳过、0 意外失败。
- OpenSpec strict：31 份主规格通过；本变更的归档验证通过。
- `git diff --check`：通过。

仓库全量归档扫描仍报告 3 个历史变更存在未完成任务；这 3 个变更早于本工作且不在本次修改
范围内，本变更自身没有未完成任务或规格错误。

最终证据见 [冻结目录](../evidence/expose-project-datasets/README.md) 与
[完整性清单](../evidence/expose-project-datasets/冻结清单.json)。

## 边界

本变更不实现用户上传 CSV、自助构建数据集、自动选择模型或自动覆盖默认模型。XLSX 不是
权威副本，离线后再分发时应以 ZIP 中的 CSV、manifest 和 SHA-256 清单核对完整性。
