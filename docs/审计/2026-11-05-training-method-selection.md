# 项目训练方法与模型身份验收（2026-11-05）

## 范围

对应 change `choose-training-method-and-identify-model`：项目分析选择训练方法、方法身份贯穿作业与重试、同步模型命名包含方法与特征口径。

## 实际验证

### 方法目录

本机 API 返回 `kamei14-git-v2` 下的 9 个已注册方法；逻辑回归、决策树、随机森林均报告可用，依赖缺失的方法返回原因且前端禁用。

### 决策树端到端训练

在临时目录生成 260 个提交的本地仓库，使用 `force-train` 与 `decision-tree-v1` 创建分析：

| 项目 | 结果 |
| --- | --- |
| 作业状态 | completed |
| 请求方法 | `decision-tree-v1` |
| 模型标识 | 已登记 |
| 模型名称 | `repo · 决策树 · CART · kamei14-git-v2（14 字段） · 2024-01-01→2024-10-08` |

作业记录保存请求方法；训练产物使用该方法；模型名称可直接区分方法与十四字段口径。使用同一仓库再次以默认方法分析时，缺省方法为逻辑回归，旧请求不携带方法字段的行为保持不变。

### 重试与降级

- 失败记录按原参数重试时前端预填并提交原方法；服务端重新校验方法，依赖缺失时返回 `METHOD_DEPENDENCY_UNAVAILABLE`，不自动替换。
- 自动模式降级为现成模型时不生成所选方法的训练产物或模型名称，作业保留请求方法并记录降级原因。
- 现成模型策略不能提交方法参数，服务端在创建前拒绝。

## 自动化

- 后端同步、训练、模型目录、项目 API 与 OpenAPI 测试通过；覆盖方法目录、默认方法、未知方法、依赖拒绝、命名、原方法重试与旧记录回填。
- 前端 `tsc -b` 与全量单元测试通过；覆盖方法选择、现成模型隐藏方法、不可用方法禁用、提交算法与重试预填。

## 边界

- 深度方法是否可用取决于运行环境是否安装声明的依赖，界面按服务端真实检查结果展示。
- 方法名称变长后列表可能截断；名称仅用于识别，模型身份仍以目录标识为准。
- 本次没有比较不同方法的实际指标优劣，也不据此改变默认模型。
