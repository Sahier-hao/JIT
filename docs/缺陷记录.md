## D-001 本机既有运行的模型 pickle 引用已删除符号，真实模式不可用

**现象**：本机 `backend/artifacts/baseline` 与 `backend/artifacts/reproduction` 的 `model.joblib` 无法加载。`python -m jit_baseline.cli verify` 以 `MODEL_INVALID`（"模型无法加载或类型无效"）退出；本机只读服务的真实模式在启动时判定产物不可用，`GET /api/review-batch` 返回 503，前端显示数据不可用。演示模式不受影响。

**复现条件**：

1. 在 `backend` 下执行 `python -m jit_baseline.cli verify`（默认运行目录 `artifacts/baseline`）。
2. 或在 `backend` 下执行 `python -m jit_baseline.cli serve` 后请求 `GET /api/review-batch`。

两者都报 `MODEL_INVALID`。**该缺陷先于本 change 存在**：把本 change 的源码改动临时收起（`git stash`）后，在 HEAD 状态执行同样命令仍报同一错误。

**根因**：`artifacts/baseline` 与 `artifacts/reproduction` 生成于 2026-10-10（manifest `generatedAt` 为 `2026-10-10T14:50Z`，运行标识 `a31140a9…`）。它们的模型 pickle 引用 `jit_baseline.model.log_counts`。d0370b7（`align-feature-and-model-definitions`）把该函数换成了模块级类 `Log1pColumns`，序列化引用因此失效。`artifacts/` 不进版本控制，而当时没有任何测试读取已提交的运行（所有产物测试都在临时目录现场重训），因此没有被自动发现；该 change 的 D7 又明确"不重写 baseline、运行标识不变"，把"仍然可加载"当作前提而没有验证。

**影响范围**：本机真实模式完全不可用；`frontend/scripts/verify.ps1` 的 `real-artifact-verification` 与 `independent-reproduction-comparison` 两步在 HEAD 状态即失败。

**处理**：按固定命令重建这两个运行（`python -m jit_baseline.cli run --output artifacts/baseline`，`… --output artifacts/reproduction`），重建前把旧目录备份到 `backend/.cache/pre-rebuild-2026-10-10/`。归档证据 `docs/evidence/` **未被修改**；重建运行与归档证据 `docs/evidence/connect-public-data-baseline-review/summary.json` 的 `datasetVersion` 相同、`features` 相同、冻结测试成员数相同，六个指标差为 **0.0**（要求 ≤1e-8）。重建后运行标识由 `a31140a9…` 变为 `07b6102b…`（声明中增加了 schema、方法版本与指标集三项），响应契约对前端保持兼容：`model.id` 仍为 `logistic-regression-six-v1`、六字段顺序不变、契约版本 1、1853 条记录。

**防复发**：本 change 新增"重建的六字段运行仍与归档证据同一数据版本、指标一致"的常驻回归（`backend/tests/test_artifacts.py`，读 Git 内的归档证据，不依赖本机产物），以及"本机既有运行仍可校验与复现比较"的用例。后者对**这一种**已知原因（pickle 引用已删除符号）跳过并给出原因，其它加载失败照常判为失败。

**遗留**：`backend/artifacts/development/model.joblib` 是同一批旧产物、同样引用 `log_counts`；它没有代码引用，README 只把它列为"技术与行为检查、不能作为正式效果"的目录，本次未重建。
