# 当前产品与开发入口

当前方向：以项目为中心的持续审查。入口先展示产品介绍页（`#/`），用户与管理员分别登录后进入各自工作区。普通用户建立项目、发起分支分析、查看风险趋势、跟进后台 PR 分析并处理站内提醒；进入具体 PR 后在个人工作单中阅读代码、记录问题、恢复草稿、复核更新并交付意见。项目分析提供辅助线索；管理员在独立工作区维护模型、数据、训练与验证记录。模型分数是未经校准的估计，不等于已确认缺陷。

开发任务按完整功能点组织，围绕用户目标贯通界面、接口、数据及模型行为，并覆盖权限、失败恢复和验证。参与者可以跨技术层完成任务，具体协作按功能需要安排。

## 公开文档

- `#/docs` 与 `#/docs/{slug}`：匿名可读的产品文档。首页突出《完成第一次 PR 审查》，并提供「快速开始」「使用指南」「背景知识」「常见问题」四组入口。桌面文章页使用左侧章节、中间正文和右侧本页目录；窄屏折叠章节导航。正文来自 `frontend/content/docs/articles/` 的 Git Markdown，导航、目录和本地中文搜索共用 `frontend/src/features/docs/catalog.ts`，不读取工作台项目、模型或报告接口。
- 小节使用稳定标识和 `?section=` 查询参数，例如 `#/docs/reading-results?section=commit-score`；刷新、前进后退和直接打开恢复同一文章与小节。未知文章在文档外壳内显示返回入口，无效小节保留文章并提示。
- 搜索覆盖文章标题、小节标题、正文和常用同义词，标题与小节匹配优先，结果带上下文并定位原文。搜索在浏览器本地执行，不调用服务端。
- 公开首页提供文字「文档」入口，登录工作区右上角提供文档入口；分支分析、PR 预览／工作单和模型评估提供直达相关小节的上下文帮助。文档内需要登录的操作继续进入现有登录流程，文档阅读本身不要求登录。
- 维护方式见[文档中心维护](文档中心维护.md)。管理员数据集、验证报告、模型维护资料、私有仓库信息和真实账号资料不进入公开构建与搜索。

## 用户工作区

- `#/`：产品介绍页，用「用户工作区」与「管理工作区」两个角色入口进入。`#/login?role=user|admin` 为统一登录页；首次无管理员账户时在同一页建立账户。
- `#/projects`：登录用户的项目列表，建立、重命名和删除项目。侧栏「审查」区并列提供「项目」与「我的审查」。新建项目登记 GitHub 仓库地址；私有仓库需要先在个人中心关联有权限的 GitHub 账户。
- `#/projects/{id}`：项目工作台，包含概览、分支分析、PR 审查三个子视图。
  - **概览**：GitHub 元数据、语言构成、最近 52 周提交曲线与最近提交。「刷新仓库信息」重新读取 GitHub 数据；「检查分支更新」检查远端追踪分支并管理提醒，入口固定在项目页签栏右侧，所有项目页签可见；「在我的数据中构建」打开预填当前仓库和默认分支的构建窗口。统计接口不可用时回退到最近 100 条提交的 12 周聚合并标注覆盖；缓存约 10 分钟，限流时保留上次缓存并说明原因。活跃度与语言构成提供等价数据表，不是模型分数或质量结论。
  - **分支分析**：用来回查分支的历史提交。当前分析结果合成一张卡：最上方是模型分数分布图（0.05 一档，按 0.25 / 0.10 分档着色，未评分单独计数、不并入低分档），其次是优先回查的提交与缺陷引入证据，最后是模型与数据来源摘要。证据状态区分有引入证据、观察期内未发现、观察期未满及观察覆盖未知。点击提交可打开固定分析中的详情，详情展示保存的后续修复提交与相关文件；原始变更度量、来源与局限、解释方法与来源放在对话框中查看，不在页面上原地展开。「风险趋势」查看同口径结果随时间的分布。「查看完整口径」在对话框中核对模型、数据、标签规则和历史训练结果的分区、指标。分档使用未校准的模型分数，阈值为 0.25 和 0.10。
  - **分析分支提交**：入口与当前分支作业进度均位于「分支分析」页。从概览的分支更新进入时会预填对应分支。提交时固定已登记的兼容模型，依次排队、采集、登记和打分。新建与重试均使用已有模型。旧训练作业可查看原有结果，原作业未绑定模型时重新打分需要手动选择。训练参数和数据切分在「我的训练」配置。
  - 运行中的分支分析、单个 PR 分析和 PR 批量分析批次会进入右上角统一任务入口，显示服务端真实阶段或批次处理数量；点击可直接返回对应分析页，离开页面后仍可继续追踪到终态。
- `#/projects/{id}/analyses/{syncId}/commits[/{commitId}]`：固定分析的提交明细、筛选与单条详情；`/plan` 兼容同一份明细。分支分析用于风险度量与复盘，不提供个人审查计划。正例提交详情可查看只读的后续修复证据，并跳转到修复提交 diff 的对应文件与行号。
- `#/projects/{id}/compare/{baseSyncId}/{targetSyncId}`：两次分析对比。展示两侧模型身份、运行、分支、数据与时间范围；共同提交显示原分数与目标减基准的差值，单侧覆盖不能理解为代码新增或删除。不同模型或身份缺失时明确提示，不据此判断模型优劣或风险改善。
- `#/projects/{id}/trends[/{viewId}]`：项目自身成功分支分析的趋势，并入分析页，「分析结果 / 风险趋势」切换在两种视图下位置不变。按分支、模型与运行、特征 schema、分档规则划分可比口径；同一口径按 SHA 去重，冲突整组拒绝（409）。固定视图保存查询、口径、来源与内容指纹，不复制分数；来源删除或指纹变化时明确不可用。时间按作者时间 UTC+08:00 左闭右开分桶，默认最近 90 天按周；标题同时显示分支、模型、聚合粒度、查询窗口与来源分析次数，避免与「分析结果」范围混淆。已评分样本少于 20 时高分占比为空并给出原因。平均风险分与高分占比分两张单轴折线展示，附等价表格与来源下钻；高分指落在 `repo-distribution-v1` 高分档，不是真实缺陷率。没有可拼接来源时说明原因与限制，并保留返回「分析结果」的入口。
- `#/profile`：个人中心兼容地址，打开右上角账户窗口；展示账户身份、数据版本、训练实验、模型数量与最近状态，可修改显示名称和密码。
- `#/notifications`：项目公开事件的站内提醒。分支分析完成或失败、PR 生命周期与 PR 分析就绪会写入事件；已读状态只保存在当前浏览器，已读不等于已复核。
- `#/algorithms`：独立算法库。按经典与深度方法分组，用结构图说明输入、处理阶段和输出，并展示适用场景、收益、代价、依赖、预处理、解释口径与可配置参数；不可用方法保留说明并显示真实原因。结构图只解释算法形状，不代表已验证性能。每个方法有独立地址 `#/algorithms/{method}`，可训练方法的「以此方法训练」返回「我的训练」并预选该方法；训练记录、我的模型中的方法名同样链回对应方法。
- 普通用户可在登录页注册本机账户（PBKDF2 加盐、8 小时 HttpOnly 会话、退出即撤销）。用户之间不可见、不可训练对方的数据集或模型；管理员仍维护全局数据集、默认模型和验证记录。用户可见的模型只包括本人登记和管理员显式开放的模型；没有所有者的历史模型默认不进入用户列表。

## PR 审查

- `#/projects/{id}/prs`：项目 PR 清单（开放/历史、分页与缓存时间）。「同步 PR 列表」读取当前远端范围，「本页分析状态」在同一列表内筛选未分析、分析中、可重试或已分析，数量只统计当前页。「PR 自动打分设置」管理后台分析。可按更新或风险排序当前页；已分析 PR 显示最高提交分、固定模型、head SHA、最近检查时间和可展开的提交列表。后台自动发现新 PR 或新 head 后，页面无需手点「分析」即可通过周期刷新看到排队、运行和出分状态。点开 PR 先进入只读详情：顶部一行显示分数覆盖、最高分与模型，下方是可搜索的提交风险排序，点开提交直接展开模型解释。作者说明按 Markdown 排版。
- 私有仓库同步失败时提示先关联 GitHub，并提供「关联 GitHub」入口；关联后只读取该服务端凭据有权访问的仓库。GitHub 限流或来源暂时不可用时保留上次 PR 清单与已保存快照。
- 只读详情不提供选择模型、发起或取消分析；点「创建审查工作单」或首次把候选加入问题草稿时创建个人工作单并进入「我的审查」。后台发现不会自动创建或改写个人草稿。
- `#/reviews`：跨项目查看当前已确认账户的新关注、继续审查、作者更新待复核、等待作者及暂停/历史工作，支持手动刷新。草稿和个人状态仅保存在当前浏览器并按键区分账户；旧全局工作单需显式导入。
- `#/reviews/{owner}/{repository}/{number}` 与项目内 PR 地址：固定 PR 版本、作者说明、文件 Diff、上下文、跨文件问题与证据、阅读进度、备份恢复、Markdown 结论及私有反馈。新旧轮次分别保存，远端更新不改写旧判断。个人工作单按服务端已确认账户隔离；切换、退出或会话失效会撤下旧内容，迟到请求不写入新账户；未保存文本保留在原账户恢复副本中。工作单头部可打开只读版本（`mode=preview`），已有工作单时不重复创建。
- 工作单先展示「审查优先级」，提交按分数从高到低排列；点击提交只显示它触及的文件，可切回全部文件。文件按涉及提交的最高分排序作为辅助。提交分数不等于 PR 整体缺陷概率，文件排序不代表文件级缺陷概率或行级定位。PR 文件阅读区的「行级排序（研究）」页签只对本次新增/修改的 JavaScript/TypeScript 行排序，标注“研究排序，不是缺陷概率”；排序只使用固定 patch 中新增行的文本与结构特征，不依赖实时读取完整源码。点击只定位到该行，不写草稿、不改提交分数、默认模型或合并状态。模型不可用时仍可阅读代码并记录人工判断。
- PR 预览和工作单均可点「检查当前文件」。文件列表保留当前固定版本中各文件的检查结果，支持区分规则命中、无命中与未覆盖。Python 规则命中在 Diff 或固定源码的行号旁显示标记，点击可查看代码证据和针对性建议；规则覆盖可变默认参数、裸 `except`、`eval/exec`、`subprocess(shell=True)`、缺少 Loader 的 `yaml.load`、`requests(verify=False)` 与 `tempfile.mktemp`。旧规则结果按原版本只读展示并标注“未重算”，不和新规则混用。Diff 外的结果可打开对应侧的完整上下文。加入问题草稿时保留可点击的原版本证据，重复加入会打开同一草稿。工作单可确认、驳回或暂缓候选。标记表示静态规则命中，源文件与远端 PR 由审查者自行处理。只读详情若存在已保存的修复证据，会显示修复提交、文件、引入行和修复 diff 行；修复提交属于当前开放 PR 时标为“PR 内后续修正”，明确不代表合并后修复或已确认缺陷。

## PR 后台自动分析与批量分析

- 项目显式启用后台跟踪，旧项目升级后默认关闭。启用时选择真实兼容模型并二次确认处理当前开放且非草稿的 PR；首次扫描合并为摘要事件，默认每五分钟检查，只后端运行时执行。
- 服务端固定 base/head 快照和模型；管理员改默认模型不替换已保存的项目自动模型。同一快照与模型复用在途或成功任务，显式更换自动模型才产生新意图。每个 PR 至多一个在途自动分析和一个最新待处理目标；快速推送使旧的未开始请求过时，运行中的旧版本可完成并作为历史保存。每项目每轮最多深入检查 20 个 PR 并持久轮转，每轮最多新增 1 个分析，全局自动排队上限 2 个，执行仍为单 worker。
- PR 审查工具栏的「批量分析 PR」一次安排多个开放 PR 评分，结果用于确定审查顺序。批次固定模型和范围，可选全部开放 PR、前 N 个开放 PR，或在开放列表中选择当前页。界面逐条区分待处理、已入队、复用和失败。范围不完整、部分失败或重启中断时如实显示。失败与中断项可分开重试，重试沿用原模型，重复点击返回同一活动批次。取消批次后，已入队任务继续执行。
- 临时失败最多自动重试 3 次，间隔 1/5/15 分钟；限流遵守 Retry-After 或重置时间。模型失效、来源失效等要求显式处理，不无限重试、不自动换模型。事件覆盖 PR 生命周期、PR 分析就绪失败和分支分析完成失败；覆盖不完整时明确说明，不能视为低风险结论。个人暂停只影响本浏览器待办，不关闭项目后台；服务停止或休眠期间不承诺检查。

## 用户数据、训练与模型

- **我的数据**只负责数据资产：列出本人构建或导入的版本，以及管理员显式开放共享的版本；支持导入 CSV 和 Kamei 2013 ZIP、从任意公开仓库构建（分支留空时使用仓库默认分支）、查看来源与质量、查看标签成熟度、导出 CSV 包、清洗派生和删除。
  - 项目快捷入口与直接从仓库构建复用同一个窗口。任务列表和顶部任务状态可打开准确的任务详情，详情链接可定位到最新一页以外的任务。旧项目构建任务链接自动进入「我的数据」。
  - 共享版本只读；未开放共享的全局版本不会出现在用户端；用户自有版本禁止开放共享。每人最多保留 12 个自有版本。
  - 清洗与预处理使用可排序的操作序列，支持去重、删除缺失字段、日期范围、固定数值区间和分位区间过滤；每个步骤独立记录前后行数、正例、排除原因和逐入模字段分布。预览以数据集变化图和指定特征分布图展示逐步差异，确认后生成不可变新版本并保留原版本。
  - 构建完成、CSV 导入、归属登记分别显示为不同时间事实，不合并成伪造的“创建时间”；列表返回 `fieldCount`、`manifestSha256` 与来源哈希。未导入目录库的版本以描述文件写入时间作为登记时间，并按文件内容计算清单哈希。
  - 选中 CSV 后先在浏览器核对表头。确认后上传 CSV 或 Kamei 2013 ZIP（上限 64 MiB），由 `POST /api/v1/user/dataset-imports` 创建后台任务。任务显示排队、校验、写入、登记和终态，按实际处理的文件和写入的提交记录更新进度。可收起窗口，从右上角任务入口或「导入记录」返回详情。相同文件的活动任务可复用，失败和中断保留原因并允许重新上传；任务记录上线前通过旧接口导入的版本，按来源文件和归属时间为历史记录还原，并与已有任务去重。
  - CSV 导入沿用来源的标签和字段口径。导入不会补造观察窗口或成熟标签，SZZ 数据需要满足训练准入才能训练。仓库构建任务独立管理，并保留取消和重试操作。
- **我的训练**是用户训练入口。首页显示当前训练进度，历史记录可按状态筛选、按方法或数据版本搜索。实验内可切换任务并查看排队、取消和重试状态。开始训练时直接列出该数据规范下可训练的方法并标出已选数量，所选方法显示算法摘要，可打开「算法说明」查看结构图、适用场景、收益、代价、预处理、解释口径和参数含义；参数表单仍提交实际数值。新深度训练按轮显示训练集和验证集的损失，使用最近几轮耗时估计剩余拟合时间。轮次完成后显示评估状态。新训练完成后可用验证集试算阈值和告警、误报、漏报数，试算仅作用于当前页面。至少两项成功时可比较和导出分区指标。要在项目中选用训练产物，先「登记本次模型」。同一用户同时最多一个活动实验、一次最多四个方法，参数规模受限。
  - 实验对比默认显示各模型的测试集 AP，可切换分区与指标。具备同一分区成员和阈值记录的两个模型可以共用验证集曲线。支持手动指定阈值、按验证集最高 F1 或按目标召回率选择各自阈值。点击评估后，服务端复用冻结测试分数和标签，显示选定阈值与默认 0.50 的分类指标及计数，并可随比较导出。管理员实验采用同一口径。
- **我的模型**分「我的模型」与「管理员开放」两组：前者只列本人登记的模型，后者只列管理员显式开放且可用、已启用的模型。每张卡标明「可用于仓库分析」或具体不兼容原因；旧版 `kamei14-git-v1` 和离线 `kamei14-2013-v1` 模型保留查看，并提供「用 v2 口径重训」入口。本人模型只在本人项目分析、批量 PR 分析与缺陷预测中可选，不能设为默认或操作他人模型；共享模型只读，不提供训练数据入口。提交他人或未开放模型 ID 会被服务端拒绝，不静默替换。分支分析、PR 批量分析和 PR 自动分析使用同一模型选择器，按来源分组并只列可用的兼容模型；原选模型不可用时保留为禁用项，由用户明确重选。
- **缺陷预测**（`#/my-predictions`，兼容旧地址）分「单条预测」与「批量预测」。单条可从本人可见数据版本选行、从用户项目已保存分析提交带入，或手工填写模型入模字段；批量可选择完整数据版本、模型冻结分区或 `splits.py` 已注册时间切分预设的指定分区，也可上传不含标签列的无标签 CSV。批次固化 `mode`、来源、`splitPreset`、`partition`、`memberSha256`、数据版本和真实模型 `modelId`/`name`/`method`/`runId`/`featureSchemaVersion`。单条与批量必须走同一 `predict_risks` 和 `in_model_names()` 推理路径，同一模型同一数据得到一致分数；缺字段、schema 不匹配或非有限数值整条/整批失败，不补零、不跳过，也不把无标签记录写成 `0`。结果表展示样本标识、提交级预测分数、按当前阈值计算的分类、时间/来源、真实标签或明确「无标签」，阈值调整、搜索、排序和分页只使用已保存分数；`batchId` 与右侧历史可刷新重开，不重新推理。仅同时包含可用正负真实标签的批次提供「去评估」，其余批次只查看或导出。
- **预测评估**（`#/my-evaluation?batchId=…&modelId=…&datasetVersion=…&partition=…&splitPreset=…`）是缺陷预测交接到模型评估的稳定只读地址。页面回显预测批次、模型、数据版本、分区和切分预设，使用已成熟且可用的真实标签重算阈值工作点、混淆矩阵、精确率、召回率和 F1 曲线；不重新调用模型，也不把未成熟或缺失标签纳入指标。无标签、标签只覆盖单一类别、手工特征或项目提交的单条结果不进入该评估。

## 管理工作区

管理员从登录页「管理员登录」进入独立外壳，不提供“返回用户工作区”入口；管理员身份不代替普通用户，未登录时返回登录页。

- `#/admin/models` 左侧显示可搜索、可按状态筛选的已登记模型，默认模型排在首位。选中模型后，可在右侧查看状态与基本信息、设为默认或启停，并决定是否「开放给所有用户」。开放只影响用户端新选择：普通用户可在分支分析、PR 批量分析和缺陷预测中选用；撤销后不再出现在选择列表，已有分析与评分保留。选中项由 `?selected={modelId}` 保留。查看详情、启用或设为默认时校验所选模型。「查看产物诊断」按需校验目录产物，弹窗内可切换目录状态、训练覆盖、模型包和本机产物。「登记实验产物」进入实验校验与登记。模型详情和实验详情可核对发布资格、发布报告及人工批准的默认候选。
- `#/admin/models/{modelId}`：复用用户模型卡的核心事实，补充运行谱系、产物位置、产物身份与训练环境；训练档为拟合诊断、验证档为模型选择背景、测试档为冻结泛化评价，缺失或旧模型显示原因。
- 模型卡同时展示冻结测试分区上的审查收益：相同 20% LOC 预算下，模型分数、风险/成本密度、改动量升序、时间顺序与固定随机顺序的 Recall@20%LOC、Popt、IFA、覆盖正例及相对简单基线的配对区间。报告只读，不训练、不用测试分区调参、不改变默认模型；版本 3 使用 `review-benefit-v3` 整提交预算、200 次随机与 1000 次 UTC 周块配对重采样。
- `#/admin/datasets`：左侧支持按名称、版本、字段规范、仓库和来源筛选，右侧显示所选版本的样本数、来源、时间、标签与共享状态。字段缺失、标签回溯、哈希、归属与引用按需展开。数据集和版本深链接仍在同一工作区打开。
  - 「用于训练」窗口加载已注册方法与切分预览，支持单方法训练和多方法实验。可核对三档边界、样本数、正例数与准入原因，再创建任务。无观察声明的旧 SZZ 版本可核对与评分，但不能创建新训练。
  - 管理员可显式开放/撤销无所有者版本的共享；用户自有版本不可开放。「更多操作」可清洗、派生和对比版本。目录顶部可预览和清理无引用的 PR 来源版本；清理不可恢复。
- 数据集详情支持「多方法实验」：先预览切分，再勾选多个方法和逐方法受控参数（如逻辑回归 C、树深度/叶下限、随机森林树数、MLP epochs/lr/batch_size），一次创建持久实验组。实验冻结数据版本、manifest 哈希、指标集、切分预设、成员指纹和种子；各方法使用相同三档成员，参数训练前锁定。产物只完成运行校验，管理员须在「实验登记」显式登记后，项目侧才能选择。
- `#/admin/training`：训练任务列表与详情。活动任务每 3 秒刷新，终态后停止；详情展示排队位置、阶段、失败原因、取消或重试、切分预设、实际参数、成熟策略、排除数、发布策略与资格、所属实验、成功指标和运行/模型谱系。迭代方法显示逐 epoch 损失，旧产物或非迭代方法如实说明无历史。
- `#/admin/experiment-runs`：盘点受控目录中的完整实验运行，区分未登记、已登记、产物无效、仅离线基准和当前输入不支持；展示发布资格、报告身份与批量登记结果。管理员必须显式登记后，用户模型选择才会出现。
- `#/admin/comparisons?models=…`：选择两个模型后读取详情，并列展示方法、schema、数据版本、运行和指标；口径不同或指标缺失会标注，不自动排序、不产生“最佳模型”。
- `#/admin/evaluation`：从侧栏进入「模型评估」，按需打开模型比较、多项目实验或验证报告。评估入口只加载导航；三个原地址和详情链接继续可用。
- `#/admin/experiments`：多项目实验报告列表，按完整、部分失败、失败和无效显示；同时列出固定目录中的多模型评价矩阵、`review-benefit-v3` 数据级收益报告与完整候选集证据。详情展示项目数据与来源、四种训练口径、逐目标项目指标、宏平均与总体方差、失败阶段与原因，以及全局+本地融合权重和验证集选择依据。报告以内容哈希标识，引用数据版本变化时标为陈旧；不重新训练、不改变默认模型、不宣布全局最佳方法。默认根目录为本机 `backend/artifacts/multi-project` 与仓库 `docs/evidence`，可用 `JIT_MULTI_PROJECT_REPORT_ROOT` 覆盖。
- `#/admin/reports`：历史模型验证、指标及下钻；旧 `#/reports`、`#/validation`、`#/trends` 继续映射到管理区域，服务端仍要求管理员会话。
- 密码以带独立盐的 PBKDF2 哈希保存；浏览器使用 HttpOnly、SameSite=Strict 会话 cookie，8 小时到期，退出立即撤销。本机部署只监听回环地址；首次账户由本机管理页面建立，没有默认密码。忘记密码时用 `admin-reset-password` 重置，命令见[运维与升级](运维与升级.md)。

## 采集、标签与切分

- 新采集默认 `kamei14-git-v2`：14 维提交级特征，历史只沿第一父链推进；合并提交不进入记录，合并分支变化不汇入主线。默认完整 SZZ（`szz-full-v1`）：修复提交优先按 issue/PR 关联确认，关键词兜底；删除/修改行用 git blame 回溯引入提交，证据保存修复提交、引入提交、路径、原行号区间与 issue 快照。排除回滚、重构、纯空白、文档/测试路径；离线或无 token 时退化为关键词识别并记录。`--szz line` 与 `--szz simple` 保留兼容。
- 采集分别固定样本窗口、修复观察窗口和 revision；观察截止可晚于样本截止，后续修复可为原提交提供证据，但未来提交不进入特征。逐提交标签状态、成熟期和准入策略写入受哈希保护的旁车；新训练与正式评价只使用达到成熟期的提交，正例与零标签同一时间规则；未成熟、观察未知或证据截断不进入完整可信评价，但仍可被兼容模型评分。旧 SZZ 数据默认拒绝新训练并提示重建。
- 旧 `kamei14-git-v1` 数据集、分析和模型保持可用；绑定 v1 的模型不会静默用于 v2 数据集，缺少兼容模型时明确失败或降级并说明需要训练或登记 v2 模型。
- 注册的时间切分预设覆盖 90/5/5、80/5/15、80/10/10、70/10/20、70/15/15、60/15/25、60/20/20 和 50/25/25，均按提交时间去重；省略输入使用 `70/15/15`。同一时间组只进入一个分区，拒绝任意日期边界、随机切分和重叠分区；验证集必须非空。训练、同步、CLI 与模型运行身份都保存预设、边界、三档计数与成员 SHA-256。详见[数据与训练切分](数据与训练切分.md)。
- 管理员或数据所有者可编辑清洗配方并先预览保留/排除数、规则命中、缺失、正例比例、时间范围，以及逐入模字段在清洗前后的统计与分位桶；确认后生成不可变派生版本，记录来源、配方、配方哈希、逐条去留和前后分布汇总。相同来源与配方重复生成幂等。

## 模型、默认与发布

- 代码支持多种算法不等于已有训练好的模型；磁盘存在产物也不等于目录库已校验登记。管理员登记后，兼容模型才出现在项目分析选项；复现目录不计为新模型种类。既有六字段 `openstack-six-v1` 包与当前 `kamei14-git-v2` 基线分开登记，不能互相冒充。详见[模型包部署](模型包部署.md)。
- `kamei14-git-v3` 仅用于当前研究的近期作者经验时间衰减实验，未登记为默认或用户可选模型；v2 的 90 天计数、既有数据和模型保持不变。复现边界见[作者方法复现](作者方法复现.md)。
- 现成模型选择支持 `openstack-six-v1` 和 `kamei14-git-v2` 的真实产物；`kamei14-git-v1` 和 `kamei14-2013-v1` 只保留历史/离线用途，不进入当前仓库分析。指定模型必须实际用于该次分析并写入结果来源，失败不静默切换。
- 管理员在模型卡片「设为默认」；未明确指定的策略与自动策略回退时使用默认。用户明确选择其他兼容、已启用模型时以用户选择为准；强制训练保持原策略。默认不是按测试指标选出的最优模型。
- 任务提交时保存用户指定身份和绑定的现成模型身份。排队后改默认不影响原任务，新请求使用新默认；失败重试保留已选模型，停用或不可用时提示重新选择，不自动替换。停用当前默认前必须先设另一默认；停用只影响新任务，历史分数与模型身份不变，产物不删除。
- 发布资格采用 `jit-release-v1`：每个目标项目至少 20 个测试正例、AP 高于无信息基线、ROC-AUC 不低于 0.65，并且宏平均 Recall@20%LOC 或 Popt 至少一项同时不低于时间顺序和固定种子随机顺序。accuracy 只作诊断。默认候选必须由人工批准。

## 提交解释、对比与离线集成

- 在固定分析的提交详情或 PR 只读预览中，可选择当前模型支持的方法，再点「生成模型解释」。结果绑定原分析、提交、模型与运行，按方法独立保存。刷新后可直接读取和切换已保存的解释，即使原模型已不可用。新解释附带由已保存贡献项生成的中文模板摘要；旧解释没有该字段时继续显示原摘要，不重算或改写历史结果。
- 遮挡均值基线显示替换单个输入字段后的概率分数变化。二元逻辑回归另支持 log-odds 分解，全部字段的贡献合计等于当前输入相对基线的 log-odds 差。基线使用可取得的训练分区均值，缺失的字段采用零并标明来源。每种方法按各自单位展示至多五项非零贡献，包含本次值、基线、方向和稳定性。解释用于核对模型对输入的敏感度，缺陷判断和代码定位仍由审查者结合证据完成。生成解释会核对原分数，保留原来的分析和评分。
- PR 检查报告、行级研究与 VS Code 扩展保持离线。扩展在提交后使用真实已登记模型运行提交检查，状态栏显示提交级预测分数，Problems 和侧栏显示可疑代码行及规则证据；模型选择只列已启用、ready 且支持提交采集字段的模型，CLI 不可用时才回退手工输入真实 ID。提交解释以只读文本展示模型身份、分数、中文摘要和 Top 特征贡献。行级研究模型不进入项目分析，但 PR 文件阅读区提供只读研究排序。细节见[提交解释、离线报告与行级研究](离线与研究.md)。

## 持续回归与规格

- `.github/workflows/regression.yml` 在 PR 与 main 推送运行关键层，每日及手动入口运行完整层；只读权限，不评论、不部署、不改分支保护，也不按模型分数决定合并。详见[持续回归](持续回归.md)。
- 必要验证包括真实状态推进、错误恢复、旧结果不混用、跨页面同步、历史分页、管理员会话与多模型来源一致性。完整规格位于 `openspec/specs/`。

运维与模型重建命令见[运维与升级](运维与升级.md)。
