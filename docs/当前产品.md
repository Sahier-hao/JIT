# 当前产品与开发入口

当前方向：以项目为中心的持续审查。入口先展示产品介绍页（`#/`），用户与管理员分别登录后进入各自工作区。普通用户建立项目、发起分支分析、查看风险趋势、跟进后台 PR 分析并处理站内提醒；进入具体 PR 后在个人工作单中阅读代码、记录问题、恢复草稿、复核更新并交付意见。项目分析提供辅助线索；管理员在独立工作区维护模型、数据、训练与验证记录。模型分数是未经校准的估计，不等于已确认缺陷。

## 用户工作区

- `#/`：产品介绍页，用「用户工作区」与「管理工作区」两个角色入口进入。`#/login?role=user|admin` 为统一登录页；首次无管理员账户时在同一页建立账户。
- `#/projects`：登录用户的项目列表，建立、重命名和删除项目；顶部有「项目」与「我的审查」标签。新建项目只登记公开仓库地址，不自动创建分析。
- `#/projects/{id}`：项目工作台，包含概览、分析、PR 审查三个子视图。
  - **概览**：GitHub 元数据、语言构成、最近 52 周提交曲线与最近提交；不随分析结果变化。统计接口不可用时回退到最近 100 条提交的 12 周聚合并标注覆盖；缓存约 10 分钟，限流时保留上次缓存并说明原因。活跃度与语言构成提供等价数据表，不是模型分数或质量结论。
  - **分析**：当前分析结果与分析记录双栏，页内切换「分析结果 / 风险趋势」。结果先展示本次口径：模型身份与策略（项目自训 / 现成模型）、数据集版本与纳入/原始/正例数、标签规则、训练/验证/测试/留出数量与截止日期、测试集指标及样本量；每条提交标注所属分区。存在留出段时默认只统计留出提交，可切换测试或全部；全部视图明确提示包含训练/调参时见过的提交。分档以未校准分数的 0.25 / 0.10 阈值展示，不称为缺陷概率。
  - **发起分析**：只选分支、模型来源、训练方法、时间切分预设和标签成熟策略；正式训练默认排除未成熟标签，显式包含只用于敏感性分析。可选择项目当前结果模型、管理员默认模型、实际登记的兼容模型，或自动/训练策略；选择现成模型时隐藏训练方法。作业页头显示排队、采集、登记、训练、评分五个阶段与已用时间；未指定起点时采集全部历史。
- `#/projects/{id}/analyses/{syncId}/commits[/{commitId}]`：固定分析的提交明细、筛选与单条详情；`/plan` 兼容同一份明细。分支分析用于风险度量与复盘，不提供个人审查计划。
- `#/projects/{id}/compare/{baseSyncId}/{targetSyncId}`：两次分析对比。展示两侧模型身份、运行、分支、数据与时间范围；共同提交显示原分数与目标减基准的差值，单侧覆盖不能理解为代码新增或删除。不同模型或身份缺失时明确提示，不据此判断模型优劣或风险改善。
- `#/projects/{id}/trends[/{viewId}]`：项目自身成功分支分析的趋势，并入分析页。按分支、模型与运行、特征 schema、分档规则划分可比口径；同一口径按 SHA 去重，冲突整组拒绝（409）。固定视图保存查询、口径、来源与内容指纹，不复制分数；来源删除或指纹变化时明确不可用。时间按作者时间 UTC+08:00 左闭右开分桶，默认最近 90 天按周；已评分样本少于 20 时高分占比为空并给出原因。平均风险分与高分占比分两张单轴折线展示，附等价表格与来源下钻；高分指落在 `repo-distribution-v1` 高分档，不是真实缺陷率。
- `#/profile`：个人中心兼容地址，打开右上角账户窗口；展示账户身份、数据版本、训练实验、模型数量与最近状态，可修改显示名称和密码。
- `#/notifications`：项目公开事件的站内提醒。分支分析完成或失败、PR 生命周期与 PR 分析就绪会写入事件；已读状态只保存在当前浏览器，已读不等于已复核。
- 普通用户可在登录页注册本机账户（PBKDF2 加盐、8 小时 HttpOnly 会话、退出即撤销）。用户之间不可见、不可训练对方的数据集或模型；管理员仍维护全局数据集、默认模型和验证记录。既有无所有者数据与模型继续作为共享资源。

## PR 审查

- `#/projects/{id}/prs`：项目 PR 清单（开放/历史、分页、缓存时间与显式刷新），可按更新或风险排序当前页；已分析 PR 显示最高提交分。点开 PR 先进入只读详情：顶部一行显示分数覆盖、最高分与模型，下方是可搜索的提交风险排序，点开提交直接展开模型解释。作者说明按 Markdown 排版。
- 只读详情不提供选择模型、发起或取消分析；点「创建审查工作单」或首次把候选加入问题草稿时创建个人工作单并进入「我的审查」。后台发现不会自动创建或改写个人草稿。
- `#/reviews`：跨项目查看当前已确认账户的新关注、继续审查、作者更新待复核、等待作者及暂停/历史工作，支持手动刷新。草稿和个人状态仅保存在当前浏览器并按键区分账户；旧全局工作单需显式导入。
- `#/reviews/{owner}/{repository}/{number}` 与项目内 PR 地址：固定 PR 版本、作者说明、文件 Diff、上下文、跨文件问题与证据、阅读进度、备份恢复、Markdown 结论及私有反馈。新旧轮次分别保存，远端更新不改写旧判断。个人工作单按服务端已确认账户隔离；切换、退出或会话失效会撤下旧内容，迟到请求不写入新账户；未保存文本保留在原账户恢复副本中。工作单头部可打开只读版本（`mode=preview`），已有工作单时不重复创建。
- 工作单先展示「审查优先级」，提交按分数从高到低排列；点击提交只显示它触及的文件，可切回全部文件。文件按涉及提交的最高分排序作为辅助。提交分数不等于 PR 整体缺陷概率，文件排序不代表文件级缺陷概率或行级定位。模型不可用时仍可阅读代码并记录人工判断。
- PR 工作单可对当前 Python 文件显式分析静态候选；候选绑定固定快照的侧别、路径、行号与规则版本并显示代码证据。首版只支持 Python，其他语言、二进制或不可读文件标记未覆盖。候选与模型分数分开展示，不换算成行级缺陷概率；对可变默认参数、裸 except、eval/exec 提供修复建议，可加入问题草稿并复用确认、驳回、暂缓与恢复。默认只预览，不自动修改源码或评论 PR。

## PR 后台自动分析与批量分析

- 项目显式启用后台跟踪，旧项目升级后默认关闭。启用时选择真实兼容模型并二次确认处理当前开放且非草稿的 PR；首次扫描合并为摘要事件，默认每五分钟检查，只后端运行时执行。
- 服务端固定 base/head 快照和模型；管理员改默认模型不替换已保存的项目自动模型。同一快照与模型复用在途或成功任务，显式更换自动模型才产生新意图。每个 PR 至多一个在途自动分析和一个最新待处理目标；快速推送使旧的未开始请求过时，运行中的旧版本可完成并作为历史保存。每项目每轮最多深入检查 20 个 PR 并持久轮转，每轮最多新增 1 个分析，全局自动排队上限 2 个，执行仍为单 worker。
- 「分析全部 PR」是持久批次：固定模型身份与范围（全部、前 N 个或当前页），逐条区分待处理、已入队、复用和失败。范围不完整、部分失败或重启中断时如实显示，不冒充完成，也不自动换模型；失败与中断项分开重试，重复点击返回同一活动批次。取消只停止后续提交，不级联取消已入队任务。
- 临时失败最多自动重试 3 次，间隔 1/5/15 分钟；限流遵守 Retry-After 或重置时间。模型失效、来源失效等要求显式处理，不无限重试、不自动换模型。事件覆盖 PR 生命周期、PR 分析就绪失败和分支分析完成失败；覆盖不完整时明确说明，不能视为低风险结论。个人暂停只影响本浏览器待办，不关闭项目后台；服务停止或休眠期间不承诺检查。

## 用户数据、训练与模型

- **我的数据**只负责数据资产：列出本人构建或导入的版本，以及管理员显式开放共享的版本；支持导入 CSV、从任意公开仓库构建、查看来源与质量、查看标签成熟度、导出 CSV 包、清洗派生和删除。
  - 共享版本只读；未开放共享的全局版本不会出现在用户端；用户自有版本禁止开放共享。每人最多保留 5 个自有版本。
  - 清洗使用独立预览窗口，支持去重、删除缺失字段、限制文件数/新增行数；确认后生成不可变新版本并保留原版本。
  - 构建完成、CSV 导入、归属登记分别显示为不同时间事实，不合并成伪造的“创建时间”；列表返回 `fieldCount`、`manifestSha256` 与来源哈希。未导入目录库的版本以描述文件写入时间作为登记时间，并按文件内容计算清单哈希。
  - 普通用户 CSV 导入走 `POST /api/v1/user/datasets/import`，只接受原始 CSV（上限 64 MiB），不创建构建任务，不补造观察窗口或成熟标签；缺少可核验标签证据时不能进入训练。
  - 构建与导入共用独立 `dataset_build_task` 生命周期：排队、采集中、登记中、完成、失败、取消、中断；同参数活动任务复用，失败保留阶段和原因，不登记空数据集。任务不接受服务器任意路径或外部预计算标签。
- **我的训练**是唯一训练入口：选择数据版本、时间切分和方法参数，支持单方法/多方法实验、真实逐 epoch 曲线、三档指标、比较导出、取消与重试；训练成功不自动登记模型，须显式「登记本次模型」。同一用户同时最多一个活动实验、一次最多四个方法，参数规模受限。
- **我的模型**只列本人登记的模型；这些模型只在本人项目分析中可选，不能设为默认或操作他人模型。用户模型列表包含共享模型与本人模型，不包含他人模型；提交他人模型 ID 会被服务端拒绝，不静默替换。

## 管理工作区

管理员从登录页「管理员登录」进入独立外壳，不提供“返回用户工作区”入口；管理员身份不代替普通用户，未登录时返回登录页。

- `#/admin/models`：查看登记模型、训练覆盖、最近模型包名称/SHA-256/导入结果、后端连接、空目录、完整未登记、产物无效与可选数量；展示发布资格、发布报告身份、读取错误和人工批准默认候选。可登记本机已交付产物、设置默认模型并启停其他模型。训练成功或登记成功不等于发布合格。
- `#/admin/models/{modelId}`：复用用户模型卡的核心事实，补充运行谱系、产物位置、产物身份与训练环境；训练档为拟合诊断、验证档为模型选择背景、测试档为冻结泛化评价，缺失或旧模型显示原因。
- 模型卡同时展示冻结测试分区上的审查收益：相同 20% LOC 预算下，模型分数、风险/成本密度、改动量升序、时间顺序与固定随机顺序的 Recall@20%LOC、Popt、IFA、覆盖正例及相对简单基线的配对区间。报告只读，不训练、不用测试分区调参、不改变默认模型；版本 3 使用 `review-benefit-v3` 整提交预算、200 次随机与 1000 次 UTC 周块配对重采样。
- `#/admin/datasets`：详情展示来源、时间范围、质量、schema、哈希、字段缺失、标签规则、观察窗口、成熟期、准入协议、原始/成熟合格数、未成熟排除、历史状态与 SZZ 证据是否被预算截断。
  - 可从固定版本选择已注册方法、切分预设、标签成熟策略和类别策略创建训练任务；训练前只读预览三档边界、样本数、正例数、准入统计和不可用原因，预览不产生任务或产物。无观察声明的旧 SZZ 版本可核对与评分，但不能创建新训练。
  - 管理员可显式开放/撤销无所有者版本的共享；用户自有版本不可开放。PR 来源版本可按保留数量预览并显式清理，被模型、分析或趋势引用的版本不进入清理列表，分支数据集不参与；清理不可恢复。
- 数据集详情支持「多方法实验」：先预览切分，再勾选多个方法和逐方法受控参数（如逻辑回归 C、树深度/叶下限、随机森林树数、MLP epochs/lr/batch_size），一次创建持久实验组。实验冻结数据版本、manifest 哈希、指标集、切分预设、成员指纹和种子；各方法使用相同三档成员，参数训练前锁定。产物只完成运行校验，管理员须在「实验登记」显式登记后，项目侧才能选择。
- `#/admin/training`：训练任务列表与详情。活动任务每 3 秒刷新，终态后停止；详情展示排队位置、阶段、失败原因、取消或重试、切分预设、实际参数、成熟策略、排除数、发布策略与资格、所属实验、成功指标和运行/模型谱系。迭代方法显示逐 epoch 损失，旧产物或非迭代方法如实说明无历史。
- `#/admin/experiment-runs`：盘点受控目录中的完整实验运行，区分未登记、已登记、产物无效、仅离线基准和当前输入不支持；展示发布资格、报告身份与批量登记结果。管理员必须显式登记后，用户模型选择才会出现。
- `#/admin/comparisons?models=…`：并列所选模型的方法、schema、数据版本、运行和指标；口径不同或指标缺失会标注，不自动排序、不产生“最佳模型”。
- `#/admin/experiments`：多项目实验报告列表，按完整、部分失败、失败和无效显示；同时列出固定目录中的多模型评价矩阵、`review-benefit-v3` 数据级收益报告与完整候选集证据。详情展示项目数据与来源、四种训练口径、逐目标项目指标、宏平均与总体方差、失败阶段与原因，以及全局+本地融合权重和验证集选择依据。报告以内容哈希标识，引用数据版本变化时标为陈旧；不重新训练、不改变默认模型、不宣布全局最佳方法。默认根目录为本机 `backend/artifacts/multi-project` 与仓库 `docs/evidence`，可用 `JIT_MULTI_PROJECT_REPORT_ROOT` 覆盖。
- `#/admin/reports`：历史模型验证、指标及下钻；旧 `#/reports`、`#/validation`、`#/trends` 继续映射到管理区域，服务端仍要求管理员会话。
- 密码以带独立盐的 PBKDF2 哈希保存；浏览器使用 HttpOnly、SameSite=Strict 会话 cookie，8 小时到期，退出立即撤销。本机部署只监听回环地址；首次账户由本机管理页面建立，没有默认密码。忘记密码时用 `admin-reset-password` 重置，命令见[运维与升级](运维与升级.md)。

## 采集、标签与切分

- 新采集默认 `kamei14-git-v2`：14 维提交级特征，历史只沿第一父链推进；合并提交不进入记录，合并分支变化不汇入主线。默认完整 SZZ（`szz-full-v1`）：修复提交优先按 issue/PR 关联确认，关键词兜底；删除/修改行用 git blame 回溯引入提交，证据保存修复提交、引入提交、路径、原行号区间与 issue 快照。排除回滚、重构、纯空白、文档/测试路径；离线或无 token 时退化为关键词识别并记录。`--szz line` 与 `--szz simple` 保留兼容。
- 采集分别固定样本窗口、修复观察窗口和 revision；观察截止可晚于样本截止，后续修复可为原提交提供证据，但未来提交不进入特征。逐提交标签状态、成熟期和准入策略写入受哈希保护的旁车；新训练与正式评价只使用达到成熟期的提交，正例与零标签同一时间规则；未成熟、观察未知或证据截断不进入完整可信评价，但仍可被兼容模型评分。旧 SZZ 数据默认拒绝新训练并提示重建。
- 旧 `kamei14-git-v1` 数据集、分析和模型保持可用；绑定 v1 的模型不会静默用于 v2 数据集，缺少兼容模型时明确失败或降级并说明需要训练或登记 v2 模型。
- 注册的时间切分预设覆盖 90/5/5、80/5/15、80/10/10、70/10/20、70/15/15、60/15/25、60/20/20 和 50/25/25，均按提交时间去重；省略输入使用 `70/15/15`。同一时间组只进入一个分区，拒绝任意日期边界、随机切分和重叠分区；验证集必须非空。训练、同步、CLI 与模型运行身份都保存预设、边界、三档计数与成员 SHA-256。详见[数据与训练切分](数据与训练切分.md)。
- 管理员可编辑清洗配方并先预览保留/排除数、规则命中、缺失、正例比例和时间范围；确认后生成不可变派生版本，记录来源、配方、配方哈希与逐条去留汇总。相同来源与配方重复生成幂等。

## 模型、默认与发布

- 代码支持多种算法不等于已有训练好的模型；磁盘存在产物也不等于目录库已校验登记。管理员登记后，兼容模型才出现在项目分析选项；复现目录不计为新模型种类。既有六字段 `openstack-six-v1` 包与当前 `kamei14-git-v2` 基线分开登记，不能互相冒充。详见[模型包部署](模型包部署.md)。
- 现成模型选择支持 `openstack-six-v1` 和 `kamei14-git-v1` 的真实产物；指定模型必须实际用于该次分析并写入结果来源，失败不静默切换。
- 管理员在模型卡片「设为默认」；未明确指定的策略与自动策略回退时使用默认。用户明确选择其他兼容、已启用模型时以用户选择为准；强制训练保持原策略。默认不是按测试指标选出的最优模型。
- 任务提交时保存用户指定身份和绑定的现成模型身份。排队后改默认不影响原任务，新请求使用新默认；失败重试保留已选模型，停用或不可用时提示重新选择，不自动替换。停用当前默认前必须先设另一默认；停用只影响新任务，历史分数与模型身份不变，产物不删除。
- 发布资格采用 `jit-release-v1`：每个目标项目至少 20 个测试正例、AP 高于无信息基线、ROC-AUC 不低于 0.65，并且宏平均 Recall@20%LOC 或 Popt 至少一项同时不低于时间顺序和固定种子随机顺序。accuracy 只作诊断。默认候选必须由人工批准。

## 提交解释、对比与离线集成

- 在固定分析的提交列表点开一条提交，可「生成模型解释」；读取不运行推理，生成仅使用该分析登记的模型、运行和字段并核对保存分数，保存至多五个非零特征影响、本次值、基线、方法和来源。归因说明单特征敏感度，不是缺陷结论或代码定位；原模型损坏、运行不匹配时显示原因并保留旧分数。
- PR 检查报告、行级研究与 VS Code 扩展保持离线，细节见[提交解释、离线报告与行级研究](离线与研究.md)。

## 持续回归与规格

- `.github/workflows/regression.yml` 在 PR 与 main 推送运行关键层，每日及手动入口运行完整层；只读权限，不评论、不部署、不改分支保护，也不按模型分数决定合并。详见[持续回归](持续回归.md)。
- 必要验证包括真实状态推进、错误恢复、旧结果不混用、跨页面同步、历史分页、管理员会话与多模型来源一致性。完整规格位于 `openspec/specs/`。

运维与模型重建命令见[运维与升级](运维与升级.md)。
