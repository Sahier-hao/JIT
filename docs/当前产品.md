# 当前产品与开发入口

当前方向：以项目为中心的持续审查。普通用户在项目工作台发起分支分析、查看项目自身的风险趋势、跟进后台自动分析的 PR 并处理站内提醒；进入具体 PR 后仍在个人工作单中阅读代码、记录问题、恢复草稿、复核更新并交付意见。项目分析提供辅助线索，管理员在独立工作区维护模型、数据和验证记录。

## 用户工作区

- `#/projects`（默认入口）：建立、重命名和删除项目，进入项目工作台；页面顶部提供「项目」与「我的审查」两个标签。「新建项目」在项目列表内以对话框完成，旧 `#/projects/new` 地址打开同一对话框。新建项目只登记公开仓库地址，不自动创建分析。
- `#/projects/{id}`：项目工作台，包含概览、分析、PR 审查三个子视图。「概览」是仓库基本信息（GitHub 元数据、语言构成环形图、最近 52 周周提交曲线、最近提交），不随分析结果变化；「分析」是当前分析结果与分析记录的双栏，并在页内切换「分析结果 / 风险趋势」；旧「分析记录」地址映射到「分析」。项目级 PR 自动跟踪从「PR 审查」进入，入口是页内工具栏的「自动分析」；项目页头部另有「分析全部 PR」，默认选中项目当前结果所用模型，也可选管理员默认模型或其他已登记兼容模型；批量分析返回持久批次，PR 审查页显示实际入队、复用、失败与待处理数量。「发起分析」只选分支、模型来源、训练方法与时间切分预设；自动或训练时可从已注册且依赖可用的方法中选择，未选择时使用逻辑回归，选择现成模型时隐藏方法；进行中的作业在页头显示排队、采集、登记、训练、评分五个真实阶段与已用时间，未指定起点时采集全部历史。页头另有「构建数据集」，只对当前项目公开仓库执行采集、简化 SZZ 和登记，完成后可显式前往数据集详情选择训练，不自动训练、评分或替换当前结果。
- `#/projects/{id}/prs`：项目 PR 清单（开放/历史、分页、缓存时间与显式刷新），可切换「按更新 / 按风险」排序当前页；已分析的 PR 显示最高提交分。选择 PR 先打开只读详情，详情顶部一行显示分数覆盖、最高分与模型，下方是可按标题或 SHA 搜索的提交风险排序；点开一条已评分提交可直接展开它的模型解释，不离开本页；作者说明按 Markdown 排版。点「创建审查工作单」才创建个人工作单并进入「我的审查」，已有工作单显示「继续审查」。后台发现不会自动创建或改写个人草稿。
- `#/projects/{id}/trends[/{viewId}]`：项目自身的分支分析趋势，界面并入「分析」页的「风险趋势」视图，旧地址仍可直达。未指定视图时按当前口径（优先当前结果所属口径）自动准备固定视图；地址保留 viewId，重开读取同一份固定来源。
- `#/projects/{id}/analyses/{syncId}/commits` 与 `/plan`：固定分析的提交明细、筛选与单条详情。`/plan` 兼容旧地址，显示同一份提交明细；分支分析用于风险度量与复盘，不提供个人审查计划。
- `#/reviews`：项目列表的「我的审查」标签，跨项目查看新关注、继续审查、作者更新待复核、等待作者及暂停/历史工作。提供手动刷新；草稿和个人状态仅保存在当前浏览器。
- `#/reviews/{owner}/{repository}/{number}`：固定 PR 版本、作者说明、文件 Diff、上下文、跨文件问题与证据、阅读进度、备份恢复、Markdown 结论及私有反馈。新旧轮次分别保存，远端更新不改写旧判断。
- `#/notifications`：项目公开事件的站内提醒。分支分析完成或失败会写入事件；已读状态只保存在当前浏览器，已读不等于已复核。
- 分析选项可以选择项目当前结果所用模型、管理员默认模型、实际登记的兼容模型，或使用自动/训练策略；指定现成模型时可打开只读模型卡核对方法、schema、数据规模、三档指标、限制和审查收益，关闭后模型选择与表单草稿不变。模型卡不提供启用、停用、设默认、登记或重训操作。自动与训练可选择已注册且依赖可用的方法，默认逻辑回归，方法不可用时不自动替换。界面不要求填写日期范围或提交上限。本仓库训练出的模型显示名包含仓库、方法、schema、入模字段数与数据范围，便于与其他仓库和特征口径区分。分数是模型估计，未经当前仓库概率校准。
- PR 审查以提交为审查单位：项目页「分析全部 PR」默认使用项目当前结果所用模型（也可选默认或其他兼容模型），再按所选范围（全部、前 N 个或当前页）提交后台分析；批次从远端获取固定范围的开放 PR，逐条刷新快照，同快照同模型的已完成分析复用结果、在途任务复用任务，快照变化才创建新分析。进行中的批次可以取消，取消只停止后续提交，已入队任务继续并保留结果。已完成的 PR 可换用其他兼容模型重新分析，旧结果保留。PR 审查页左侧是清单，右侧是 PR 分析记录，逐条显示状态、模型、最高提交分与时间；只读详情顶部以一行显示分数覆盖、最高分与模型，并在本页提供提交搜索和逐提交模型解释，不跳转到分支分析页。只读详情不提供选择模型、发起或取消分析的入口；工作单先展示「审查优先级」，提交按分数从高到低排列，点击提交只显示它触及的文件，可切回全部文件。文件按涉及提交的最高分排序作为辅助。提交分数不等于 PR 整体缺陷概率，文件排序也不代表文件级缺陷概率或行级定位。模型不可用时仍可阅读代码和记录人工判断。

具体操作见[PR 审查使用指南](PR审查使用指南.md)，实现及验证边界见[纵向验收记录](审计/2026-10-27-pr-review-journey.md)与[项目持续审查验收](审计/2026-10-29-project-continuous-review.md)。

## 项目风险趋势

- 只读取项目自身成功的分支分析；PR 分析、fork 试验和用途不明的旧记录不参与跨来源拼接。
- 可比口径按分支、模型与运行、特征 schema、分档规则划分；数据集版本每次采集都会变化，不作为分组键。
- 同一口径的重叠窗口按提交 SHA 去重，保留首次观测的原分析引用。同 SHA 的时间、特征或分数冲突时整组拒绝（409），列明冲突来源，可改为单次固定分析查看。
- 固定视图保存查询、口径、来源 syncId 清单与内容指纹，不复制分数。相同来源与查询复用同一视图；有新来源时只提示，显式刷新才生成新视图。
- 来源被删除或内容指纹变化时，旧视图明确不可用（409），不静默替换为另一份结果。
- 时间按提交作者时间、UTC+08:00、左闭右开分桶；默认最近90天按周。已评分样本少于20时高分占比返回空值和原因，不画成0。平均模型风险分按桶内已评分提交取平均，没有已评分提交时为空。未覆盖的桶标记未知，不据最早/最晚提交推断完整覆盖。
- 图分平均模型风险分与高分占比两张单轴折线，另附等价表格、键盘/触屏操作与原来源下钻；提交量保留在汇总与等价表格中。平均风险分是模型估计；高分指模型分数落在 `repo-distribution-v1` 高分档，不是真实缺陷率，也不读取简化 SZZ 标签。
- 只有所选模型确实由当前项目同一数据版本训练、且模型运行保存了可核对的冻结成员谱系时，才标出训练、验证、测试和训练截止后的“近期，未参与训练”。外部现成模型显示“无本项目切分标签”；旧模型或来源中混合多个数据版本时显示“分区未知”。分区只描述模型成员覆盖，不改变风险分数，也不能把训练截止后的提交归入测试集。

## PR 后台自动分析与站内提醒

- 项目显式启用，旧项目升级后默认关闭。启用时选择真实兼容模型并二次确认处理当前开放且非草稿的 PR；首次扫描合并为摘要事件。默认每五分钟检查，只在后端运行期间执行。
- 服务端固定 base/head 快照和模型；管理员改默认模型不替换已保存的项目自动模型。同一快照与模型复用在途或成功任务，显式更换自动模型才产生新意图。
- 手动批量分析使用列表入口，逐个固定快照并复用已完成结果；每个 PR 至多一个在途自动分析和一个最新待处理目标；快速推送使旧的未开始自动请求过时，正在运行的旧版本可完成并作为历史保存。不取消手动任务。
- 手动「分析全部 PR」是持久批次：默认使用项目当前结果所用模型，也可选管理员默认模型或其他已登记兼容模型；开始时固定真实模型身份与范围（全部、前 N 个或当前页），从远端获取该范围的开放 PR；逐条结果区分待处理、已入队、复用结果和失败。发现范围不完整、部分失败或服务重启中断时如实显示，不冒充全部完成，也不自动换模型；失败项与中断项分开重试，重复点击返回同一活动批次。取消批次停止后续提交，不级联取消已入队任务，也不自动恢复。
- 临时失败最多自动重试3次，间隔1/5/15分钟；限流遵守 Retry-After 或重置时间。模型失效、来源失效等要求显式处理，不无限重试、不自动换模型。
- 每项目每轮最多深入检查20个PR并持久轮转；每项目每轮最多新增1个分析，全局自动排队上限2个，执行仍为单 worker。
- 事件覆盖新 PR、版本更新、开放/关闭/合并、PR 分析就绪与需处理失败，以及分支分析完成或失败；事件只写公开事实与固定引用，不生成 PR 整体风险值。分析覆盖不完整时提醒中明确说明，不能视为低风险结论。
- 个人暂停只影响本浏览器待办，不关闭项目后台；项目暂停不取消已提交任务。取消或中断的意图不因下一轮轮询自动复活，需主动重试或新版本。服务停止或机器休眠期间不承诺检查。

## 管理工作区

- `#/admin/models`：首次建立管理员账户，后续登录；查看登记模型、数据集与方法训练覆盖、最近模型包的名称、SHA-256 和导入结果，以及后端连接、空目录、完整未登记、产物无效和用户可选数量。可校验并登记本机已交付产物、设置默认模型并启用或停用其他模型。`#/admin/models/{modelId}` 复用普通用户模型卡的核心事实，并补充运行谱系、产物位置、产物身份和训练环境。卡片分别展示训练档“拟合诊断”、验证档“模型选择背景”和测试档“冻结泛化评价”；缺失或旧模型未记录时显示原因。卡片同时展示冻结测试分区上的审查收益：模型分数、风险/成本密度、改动量升序、时间顺序和固定种子随机顺序在相同 20% LOC 预算下的 Recall@20%LOC、Popt、IFA 与覆盖正例，以及模型相对每个简单基线的配对区间。收益报告只读，不训练、不使用测试分区调参、不改变默认模型；没有报告时如实说明。报告版本 2 使用整提交预算和预固定策略；旧版本报告仍可只读查看并标注不含成本感知基线和配对区间。
- `#/admin/datasets`：已登记数据及版本。`#/admin/datasets/{name}/{version}` 展示来源、时间范围、质量、schema、哈希、字段缺失和简化标签限制，并可从固定版本选择已注册方法、时间切分预设和类别策略创建训练任务。训练前会只读预览三档边界、样本数、正例数和不可用原因；预览不产生任务或产物。列表可按分支分析或 PR 分析来源筛选；PR 来源版本显示产生它的分析和引用状态。PR 版本可按保留数量预览并显式清理，被模型、分析或趋势引用的版本不进入清理列表，分支数据集不参与清理；清理不可恢复。
- `#/admin/training`：训练任务列表与详情。活动任务每 3 秒刷新，终态后停止；详情展示排队位置、阶段、失败原因、取消或重试动作、时间切分预设，以及成功指标和运行/模型谱系。
- `#/admin/experiment-runs`：盘点受控目录中的完整实验运行。训练成功只表示运行完成；管理员必须选择后显式登记，用户模型选择才会出现。页面区分未登记、已登记、产物无效、仅离线基准和当前输入不支持，并逐条展示批量登记结果。
- `#/admin/comparisons?models={modelId},{modelId}`：并列所选模型的方法、schema、数据版本、运行和指标。口径不同或指标缺失会明确标注，不自动排序、不产生“最佳模型”。
- `#/admin/experiments`：已有多项目实验报告列表，按完整、部分失败、失败和无效如实显示；`#/admin/experiments/{reportId}` 查看项目数据与来源、四种训练口径、逐目标项目指标、宏平均与总体方差、失败阶段与原因，以及全局+本地融合权重和验证集选择依据。报告以内容哈希标识读取固定根目录中的冻结文件，不接受浏览器文件路径；不重新训练、不改变默认模型、不宣布全局最佳方法。缺失指标显示未定义。默认根目录为本机 `backend/artifacts/multi-project` 与仓库 `docs/evidence`，可用 `JIT_MULTI_PROJECT_REPORT_ROOT` 覆盖。
- `#/admin/reports`：历史模型验证、指标及下钻。旧报告地址继续映射到管理区域，服务端仍要求登录。
- 模型和训练指标来自模型自身训练运行的测试分区，不是当前项目在线效果。任务失败、取消或中断后可显式重试，不覆盖原记录；取消失败或重试失败仍在当前详情显示原因。
- 密码以带独立盐的 PBKDF2 哈希保存；浏览器使用 HttpOnly、SameSite=Strict 会话 cookie，8 小时到期，退出立即撤销。密码和会话不写入 localStorage。
- 普通用户可读取项目分析模型的必要选择元数据；管理模型详情、候选、数据集、历史验证、多项目实验报告及维护预测接口要求管理员会话。
- 本机部署仅监听回环地址。首次账户由本机管理页面建立，没有内置默认账户或默认密码。
- 忘记密码时，在本机执行 `python -m jit_baseline.cli admin-reset-password --username 账户名`，按两次隐藏输入提示重置；原会话全部撤销，重新登录。密码不通过命令行参数传入。

浏览器验收使用隔离目录中的 300 提交确定性大型仓库，实际采集并登记 `kamei14-git-v1` 数据集，再分别选择现有模型、自动训练和强制训练完成分析；随后从管理员模型详情、数据集详情和新建训练任务核对指标与谱系。该夹具不访问外部仓库，也不写入开发目录。

## 模型数量的真实含义

代码支持多种算法，不等于这些算法都已有训练好的模型；磁盘存在产物，也不等于目录库已经校验登记。管理员完成登记后，兼容模型才出现在项目分析选项。复现目录可能是同一模型的副本，不能计为新的模型种类。

2026-10-23 本机完整盘点及接入结果：**9 种方法、9 个可用模型版本**，不把复现目录和测试副本重复计数。

| 类别 | 方法 | 本次产物处理 |
| --- | --- | --- |
| 经典 | 逻辑回归、决策树 | 保留原模型，补齐目录登记和选择链路 |
| 经典 | 随机森林、高斯朴素贝叶斯、梯度提升树 | 既有代码和历史指标存在；缺少正式交付产物，本次按既有固定数据、参数在 CPU 生成新运行并校验登记 |
| 深度 | MLP、表格 ResNet、FT-Transformer、Wide & Deep | 从 `backend/.cache/deep/` 找回四个原训练产物，逐项校验并原样复制到 `backend/artifacts/` 后登记；原文件不变、没有重训 |

管理页同时展示 9 种方法的支持、分组训练覆盖和可用模型状态。项目选择器读取真实目录库，指定模型贯穿请求、任务与结果；仓库中的版本化 ZIP 通过标准目录初始化恢复模型，原始运行目录和 SQLite 不进入 Git，也不能把任意磁盘目录自动当作上线模型。此次本机接入不代表在新仓库上已验证模型效果。2026-10-31 对九个产物的冻结测试分区收益评估显示，按原始模型分数检查 20% 代码改动量覆盖的历史标记低于时间顺序和随机顺序；管理区模型详情如实展示该结果，不据此改变默认模型，详见[收益验收](审计/2026-10-31-model-benefit-evaluation.md)。模型包生成、内置包初始化、发布和回滚见[模型包部署](模型包部署.md)。

重建任一方法的本机产物并登记（以下在 `backend` 目录执行；把方法名替换为上表对应标识）：

```powershell
./.venv/Scripts/python.exe -m jit_baseline.cli run --schema openstack-six-v1 --algorithm mlp-v1 --metric-set metric-set-v1 --output artifacts/mlp-v1
./.venv/Scripts/python.exe -m jit_baseline.cli register-model --run-key mlp-v1
```

已有目录不得覆盖；已有完整产物直接由管理页校验登记。深度方法需要已安装声明的 PyTorch 依赖，CPU 即可加载本轮产物。

## 模型卡与三档诊断

普通用户模型卡端点按模型 ID 只读返回安全投影；模型卡入口位于项目“发起分析”的现成模型选择旁。公开字段不包含本机路径、SQLite、候选运行、登记审计或维护动作。模型产物损坏、停用或不可加载时保留身份并显示原因，部署方不能把默认模型或其他模型指标补进来。

新训练运行在 `summary.json` 保存 `metricsByPartition`、数据规模、切分规则和训练吞吐。三档指标使用相同指标集和固定阈值，但含义不同：训练档只用于拟合诊断，验证档用于模型选择背景，只有冻结测试档承担泛化评价。训练类别加权或采样只改变训练过程，三档评价仍按各分区原始唯一成员计数。

早期九模型未记录训练/验证预测，因此使用不可变补充报告关联原 `artifactRunId`、模型哈希、数据哈希和 split 摘要。报告只读，不改写原模型文件、hash、策略或历史结果；没有匹配报告的旧模型明确显示“未记录”。当前九模型的分区诊断位于 `docs/evidence/model-diagnostics/`，与当前模型包身份绑定的收益报告位于 `docs/evidence/model-card-benefits/`。旧 `docs/evidence/benefit-evaluation/` 继续作为历史评估证据保留。

全新环境只需执行标准目录初始化；迁移完成后会自动校验仓库内置九模型包并登记，其他机器因此能看到与管理端相同的模型列表：

```powershell
./.venv/Scripts/python.exe -m jit_baseline.cli catalog-init
```

若使用受控目录中另行交付的顶层运行产物，而不是仓库内置包，可跳过内置包后显式登记：

```powershell
./.venv/Scripts/python.exe -m jit_baseline.cli catalog-init --skip-bundled-models
$keys = 'baseline','decision-tree-v1','random-forest-v1','gaussian-naive-bayes-v1',
        'gradient-boosting-v1','mlp-v1','tabular-resnet-v1','ft-transformer-v1','wide-deep-v1'
foreach ($key in $keys) {
  ./.venv/Scripts/python.exe -m jit_baseline.cli register-model --run-key $key
}
```

登记只读取并校验现有产物，不重训、不复制模型文件；第一个兼容模型按既有规则建立初始默认。

现成模型选择支持 `openstack-six-v1` 和 `kamei14-git-v1` 的真实产物；其他 schema 标明不适用。指定模型必须实际用于该次分析，并写入结果来源。失败不静默切换。

## 默认模型和启停

管理员在模型卡片点击「设为默认」，未明确指定的现成模型策略以及自动策略需要回退时使用此默认。用户明确选择其他兼容、已启用模型时，以用户选择为准；强制训练保持原策略。默认不是按测试指标选出的最优模型。

任务提交时保存用户指定身份和绑定的现成模型身份。排队后改默认不影响原任务；默认变更后的新请求使用新默认。失败后「用这些参数重试」保留已经选定的现成模型，停用或不可用时提示重新选择，不自动替换。

停用当前默认前先设置另一默认。停用确认会说明影响：新分析不可选择；尚未开始使用模型的任务失败并说明原因，已开始使用的任务可以完成。历史提交、分数与模型身份保持不变，模型产物不会删除。启用操作重新检查实际产物及兼容性；重复登记同一模型不会取消停用设置。

默认模型损坏或缺失时，相关新分析明确失败；管理员恢复并重新登记或设置另一个可用默认。模型列表仍保留停用模型及其名称供历史溯源，但不把它列为可用分析选项。

## 本机升级和运行

升级前用 SQLite backup 备份 `backend/storage/catalog.sqlite3`，模型目录与数据库共同保留。运行 `backend/.venv/Scripts/python.exe -m jit_baseline.cli catalog-init` 应用至迁移 031，并在需要时校验、导入仓库内置九模型包。该命令保留既有项目、分析、模型和管理员账户；包内已存在的相同运行身份会复用，模型或包版本变化才增补身份。旧项目已开启的分支自动分析会迁移为“只提醒”：检查到新 HEAD 只写项目动态和站内提醒，不自动创建分析；已经提交或正在运行的任务不取消。显式初始化旧库时，命令会先在数据库同目录生成一份一致的 SQLite 副本（`catalog.sqlite3.before-v<旧版本>-<随机>.sqlite3`）；备份失败则不升级。旧项目不会因升级自动开启仓库提醒或 PR 自动跟踪；旧项目当前结果若指向 PR，升级不重置或删除，工作台说明来源并提供改选分支结果或发起分支分析的路径。升级前停止当前部署的后端，完成后启动新版本；旧代码不能直接读取新版本数据库。此前迁移 008 的初始默认规则保持不变：已有目录首次升级时固定保存 ID 顺序首个 ready 兼容模型，管理员应按需核对并按需修改。空目录首个兼容登记成为初始默认；后续登记和重复升级不重置已保存的默认。随后启动单个后端进程和前端；端口默认 8000 / 4173。模型交付使用[模型包部署](模型包部署.md)，不要把 SQLite 当作跨环境格式。

```
cd backend
./.venv/Scripts/python.exe -m jit_baseline.cli catalog-init
./.venv/Scripts/python.exe -m jit_baseline.cli serve --port 8000
```

```
cd frontend
npm ci
npm run dev
```

回退前停止新后端、另行备份升级后数据，再恢复升级前数据库及对应代码；不要以旧代码直接运行迁移 017 数据库。个人工作单还需在浏览器单独导出完整草稿。

## 仓库概览与分支提醒

PR 工作支持公开 GitHub 仓库及具体 PR 地址，私有来源暂不支持。GitHub 请求受限时保留输入及旧版本并显示重试；可由部署者配置服务端 `JIT_GITHUB_TOKEN`，令牌不进入浏览器、数据库或工作单备份，配置后仍拒绝私有来源。不要把令牌写入提交文件。

项目列表的「我的审查」标签提供手动刷新；项目显式启用的后台跟踪独立检查开放 PR。暂停、结束关注及历史状态单独显示。作者更新、基准变化、分叉或无法确认的继承关系均保留旧定位与判断；意见交付前再次核对版本。项目页的 PR 自动跟踪是独立设置：个人暂停只影响本浏览器待办，不会关闭项目后台；后台事件也不自动建立个人草稿。

独立的分支提醒在后端运行期间持续调度，关闭页面仍可继续。项目页可设置开关、跟踪分支和检查频率；检查只读取远端 HEAD，不要求模型、时间窗口或提交上限。发现新 HEAD 时写一条项目动态和站内提醒，不自动创建分析；用户点「分析这次更新」后只需选择分支与模型来源。远端 HEAD 与当前分析一致时不重复提醒；原模型不可用不影响提醒检查。服务停止期间不会检查。

项目「概览」读取公开 GitHub 元数据、语言构成、最近 52 周周提交统计和最近提交；统计接口不可用时回退到最近 100 条提交的 12 周聚合并标注覆盖范围。服务端缓存约 10 分钟。限流或网络失败时保留上次缓存并显示原因，不画空图；非 GitHub 项目只显示基础信息，不访问私有来源。活跃度曲线和语言构成都提供等价数据表；这些是仓库活跃度与 GitHub 字节统计，不是模型分数、缺陷率或代码质量结论。

## 分析队列、取消与重新分析

- 分析仍按单 worker 顺序执行。排队记录显示从 1 开始的待执行顺序，不代表预计等待分钟数；实际执行后可在详情中查看开始与截止时间。
- 在项目页的分析记录点击「取消分析」，确认后取消。排队记录立即结束；运行中先显示「正在取消」，停止本次分析及其 Git 子进程后成为「已取消」。取消中不开放删除入口。
- 已有成功结果、提交、分数和原模型身份保持不变。已完整登记的数据和模型也会保留；取消不会删除共享产物。相同取消请求重复提交幂等，分析已结束时提示刷新。
- 点击「用这些参数重试」先恢复分支与模型策略供编辑，再提交新分析；原取消记录保留。日期范围和提交上限不再是界面参数，未指定起点时采集全部历史。
- 默认执行时限为 600 秒，从开始执行计算，排队时间不计入；超时停止本次进程树并记录 `SYNC_TIMEOUT`。执行进程异常退出记录 `SYNC_WORKER_EXITED`，可根据请求编号核对。
- 服务正常退出会停止自有分析；重启将遗留作业标为中断，已提交取消意图的作业标为已取消，不自动重跑。部署维持单后端实例，不能让多个后端共享同一任务库调度。
- 重复采集先核对原始 CSV；同名不同内容使用新版本，旧文件不被覆盖。新 CSV 完整写入后原子发布；文件系统不支持所需硬链接时明确失败，不降级到覆盖写入。

对应变更见 [任务控制](../openspec/changes/archive/2026-10-25-control-project-analysis-tasks/proposal.md) 与 [采集文件保护](../openspec/changes/archive/2026-10-25-preserve-sync-dataset-files/proposal.md)，实际验证见 [任务控制验收](审计/2026-10-25-analysis-task-control.md)。

## 提交模型解释

在固定分析的提交列表中点开一条提交，详情以弹窗显示；在「模型解释」点击「生成模型解释」。读取详情本身不运行推理；生成仅使用该分析原来登记的模型、运行和字段，并核对保存分数。成功后保存至多五个非零特征影响、本次值、基线、方法和来源，刷新、重开或重复请求直接读取保存结果，不因默认模型变更而重算。

基线来自原模型训练分区的字段均值；训练分区成员不可用时退回零基线，页面分别显示训练分区均值、混合或零基线，并列出缺失字段。归因说明模型对单特征的敏感度，不是缺陷结论、因果解释或代码定位；分数未经当前仓库概率校准，解释不改变模型分数。解释同时保存训练分区背景哈希和合法扰动下的稳定性状态；排序不稳定时明确标注，不把主要特征表述为稳健原因。

原模型损坏、运行不匹配、字段缺失或重算不一致时显示原因并保留旧分数，不替换模型。管理员恢复原产物并校验登记后可重新尝试；读取网络失败可重新读取。删除分析会一并清理其解释。接口为固定项目提交的 `/explanation` GET/POST，必须明确传入 `viewSyncId`，不要求管理员登录；模型维护权限不变。

对应设计与范围见 [提交解释](../openspec/changes/archive/2026-10-25-explain-repository-commit-risks/proposal.md)，实际验证见 [解释验收](审计/2026-10-25-repository-explanations.md)。

## 采集口径与标签证据

新采集默认使用 `kamei14-git-v2`，字段仍为 14 维，但历史只沿第一父链推进；合并提交不进入记录，也不把合并分支的变化汇入主线历史，产物明确记录该限制。简化 SZZ 只沿当前提交的父链回溯；正例保存修复提交、候选引入提交、文件路径、证据时间和观察终点，同一提交的多条证据分别保存。标签状态区分有证据正例、未观测和未成熟；未观测不等于已证实无缺陷，未成熟标签不作为可靠负例。旧 `kamei14-git-v1` 数据集、分析和模型保持可用；绑定 v1 的模型不会静默用于 v2 数据集，缺少兼容模型时明确失败或降级并说明需要训练或登记 v2 模型。

## 数据集清洗与派生

管理员在数据集详情编辑清洗配方并先预览，查看保留/排除数、规则命中、缺失、正例比例和时间范围；确认后生成不可变派生版本，描述文件记录来源版本、配方、配方哈希和逐条去留汇总。原版本文件与描述不变；相同来源与配方重复生成幂等，配方不同生成新版本。派生版本按现有 `<数据集>-<起始日>_<结束日>-<哈希>` 规则命名，可像其他版本一样训练。

## 时间切分预设与显式数据集构建

第一版只注册 `temporal-70-15-15`、`temporal-80-10-10` 和 `temporal-60-20-20` 三个按提交时间去重的预设；省略输入仍使用原有 `70/15/15`。切分按去重时间组排序，同一时间组的提交只进入一个分区，拒绝任意日期边界、随机切分和重叠分区。训练任务、同步作业、CLI 和模型运行身份都保存预设、边界、三档计数与成员 SHA-256；切换预设会产生不同运行，旧模型继续按原有产物读取。

验证集可用于模型选择背景，测试成员在运行内只读，不因调参、融合权重或阈值选择改变。测试档继续承担冻结泛化评价；训练档只作拟合诊断。详细操作与故障原因见[数据与训练切分](数据与训练切分.md)。

项目“构建数据集”使用独立 `dataset_build_task` 生命周期和单工作器，状态区分为排队、采集中、登记中、完成、失败、取消和中断。同参数活动任务复用，相同内容版本复用；失败保留阶段和原因，不登记空数据集。任务只接受当前项目公开仓库、分支和可选时间范围，不接受 CSV 上传、服务器任意路径或外部预计算标签，也不写项目当前结果和模型选择。

## 项目数据集查看与下载

当前成功分支分析的结果卡提供“数据来源”入口。普通用户只能查看该分析实际绑定的单个数据集版本，不能浏览全局数据集库或指定其他版本；摘要包含版本、schema、时间范围、原始/纳入/正例统计、来源、标签规则、限制、CSV 字节数和完整 SHA-256。

“下载 CSV 包”生成包含 CSV、可移植 manifest 和 `SHA256SUMS` 的权威 ZIP；“下载 XLSX”生成带 data 与 metadata 工作表的便捷视图。XLSX 不能替代权威包进行完整性核对。当前单文件导出上限为 64 MiB，XLSX 数据上限为 100,000 行，超限返回明确错误。数据删除、文件缺失或哈希变化时入口显示不可用原因，原提交和风险结果仍可查看；管理员全量数据集、清洗、训练和清理能力保持不变。

## PR 代码候选

PR 工作单可对当前文件显式分析静态候选；候选绑定固定快照的侧别、路径、行号和规则版本，并显示代码证据。首版只支持 Python 规则，其他语言、二进制或无法读取的文件明确标记未覆盖。候选与模型分数分开展示，不换算成行级缺陷概率；未分析不等于没有候选或没有缺陷。首版不自动生成或应用修复补丁。

## 训练分区类别策略

管理员创建训练任务时可选择类别加权或采样，只作用于训练分区；验证与测试成员、标签分布保持不变。任务记录策略、参数、随机种子和处理前后的训练样本数、正例数；未选择时保持原行为，方法不支持所选策略时明确失败。

## 离线 PR 检查报告

`pr-check-export` 从本机目录库的固定快照与分析导出可移植分析包，包含身份、逐提交分数、可用候选位置和覆盖说明，不含个人草稿。`pr-check-report` 读取分析包生成 JSON 或 Markdown 报告；报告读取已保存分数，不要求模型当前可加载，身份不匹配时失败。命令默认不阻断合并、不评论 PR、不访问本机服务；退出码区分成功、分析缺失、身份不匹配和输入无效。

## 分支分析的定位

分支分析覆盖已合入主线的提交，用于项目风险分布、趋势与复盘，不承担 PR 的合并决定。「分析」页提供当前结果、提交明细、单条详情和模型解释；不再提供个人审查计划。旧版本保存在本浏览器的计划数据不会被删除，但当前界面不再展示或继续写入。PR 的审查进度、问题与证据在「我的审查」和 PR 工作单里。

文件最多 1 MiB、5000 条，不接受未知格式和重复条目。备份只恢复同一固定分析，不会重新创建已删除分析，也不提供跨分析迁移或账户同步。个人计划仍保存在浏览器；服务端只核对保存引用，不保存共享个人选择，也不加载模型运行推理。

对应范围与设计见 [计划备份](../openspec/changes/archive/2026-10-26-port-review-plans/proposal.md)，实际验收见 [计划恢复验收](审计/2026-10-26-review-plan-portability.md)。

## 对比两次项目分析

在项目「分析记录」中，对一条非当前的成功记录点击「与当前结果对比」：历史记录作为基准，当前成功结果作为目标。对比地址固定包含两个分析身份，可刷新和重开，不会切换项目当前结果。

页面展示两侧保存的模型名称与身份、运行、分支、数据和实际时间范围（结束时间不含）。共同提交显示原分数及「目标减基准」的差值，并标注度量变化；其余条目显示仅基准或仅目标分析覆盖，不能理解为代码新增或删除。可按变化、单侧覆盖或一致筛选并分页，分别打开某侧原提交继续审查和查看解释。

不同模型或未记录模型身份时明确提示：分数只作来源核对，不能由差值判断模型优劣、风险改善或缺陷修复。同模型的比较也不等于概率校准或效果验证。对比仅查询保存数据，不加载模型、不读取标签，不改写原分数、解释和个人计划。来源已删除、跨项目或未成功时整份拒绝，页面提供错误与重读入口。
