# 四个 change 的实施入口与提示词

## 执行顺序

| 顺序 | Change | 要解决的问题 | 依赖 |
| --- | --- | --- | --- |
| 1 | `separate-label-observation-window` | 观察不足的提交不再混入可靠训练和评价样本 | 无；优先执行 |
| 2 | `unify-review-benefit-evaluation` | 用同一预算规则判断模型能否帮助审查 | 正式复评依赖 1 的准入协议与实际数据 |
| 3 | `isolate-account-review-drafts` | 同浏览器不同账户的个人审查记录分开 | 与 1、2 无功能依赖 |
| 4 | `add-continuous-regression` | 每次改动自动检查，定期完整回归 | 可独立建设；最终覆盖已合入的新用例 |

默认依次实施。这里同时存在的是四份待实施规划，不是四个已完成 change；当前没有需要先归档的已完成本地变更。完成一个后同步其 delta、归档并处理对应 PR，再在包含前置实现的基线上推进下一个。不要只看到规划文件齐全就把它归档。

若安排多个 agent 并行实施 3、4，应分别使用独立分支和 worktree，并在开始前将对应规划文件纳入其工作基线；本轮新文档尚未提交，单纯创建新 worktree 不会自动带过去。不要在同一工作目录并发修改；合入时按顺序同步主规格、当前产品说明和检查清单。

## 通用实施约定

以下约定适用于本文件四段提示词；复制单段时保留其中对本文件的引用。

1. 工作目录为 `D:\code\jit-defect-prediction`。先读取当前 `AGENTS.md`、`docs/当前产品.md`、本文件、对应 change 全部规划、涉及主规格与当前实现。现状依据见 `docs/审计/2026-11-15-next-changes-baseline.md`，它不能替代当前代码检查。
2. 使用 `openspec-apply-change` 技能实施指定 change。先执行 `openspec status --change <name> --json` 和 `openspec instructions apply --change <name> --json`，按实际 schema 继续，不另建同名或近似 change。
3. 对规划中明确的普通实现选择自行处理。发现需要改变产品边界、破坏历史兼容或新增权限时，给出具体问题和建议；不能悄悄扩大范围。
4. 保护现有数据、模型和服务。测试使用独立数据库、模型副本、端口和临时目录；涉及升级先备份并在副本验证，不停止其他会话服务，不覆盖旧证据或未跟踪文件。
5. 真实推进正常流程、失败恢复、重复使用及与现有功能的连接。每组任务落地自身测试和文档，按实际结果勾选，不能以单个测试或任务勾选代替用户旅程。
6. 实验参数、样本、revision、预算和判断门槛在运行前固定。失败、截断、条件不足及不利结果照实保留，不换仓库凑结果，不伪造人工判定、用户耗时或远端通过。
7. OpenSpec 文件遵循配置与 CLI 模板。MODIFIED 保留被修改要求和全部既有场景，ADDED 使用独立要求；每个场景用四级标题及 WHEN/THEN。实施记录和日志放 `docs/审计/`、`docs/evidence/`，不写进 design 充当已完成证据。
8. 完成受影响检查与必要的实际旅程，逐项核对验收。缺少输入、认证或人工证据时给出具体阻塞和已完成范围，不能把未执行项写成通过，也不能为收尾而改验收线。
9. 实施和验证完成后使用 `openspec-archive-change` 同步 delta 并归档，按 AGENTS.md 创建或更新对应 GitHub PR；主规格同步如因前置变更冲突，先核对当前主规格并完整保留行为。认证阻塞要明确报告。
10. 仅提交本 change 的相关文件，保留其他待实施规划和用户改动。最终说明实现行为、实际检查、证据位置、未解决项、归档及 PR 状态，不只报告测试数量。

## 提示词 1：把标签观察和训练样本弄可靠

```text
请在 D:\code\jit-defect-prediction 实施 OpenSpec change：
separate-label-observation-window

先阅读 docs/计划/2026-11-15-change推进提示词.md 的通用约定，以及该 change 的 proposal、design、全部 specs 和 tasks。使用 openspec-apply-change 技能推进，严格执行项目 AGENTS.md 和配置 schema。

这项工作的目标是：分开“哪些提交进入样本”和“观察修复到什么时候”，让未成熟提交在切分、训练和评价中按同一规则处理。不能只增加一个字段或页面提示。正例与零标签采用同一时间准入，原有 holdout 继续取交集，原始评分覆盖保持可用。

请完成元数据和语义版本、状态导出重载、统一准入、切分预览与实际训练一致、旧模型与旧数据兼容、必要的管理/用户权限和浏览器旅程。按设计在隔离目录固定 flask、axios 的 revision 和窗口，分别在 2 小时预算内重建并交接实际合格数据；失败或截断如实保留。抽样核验与人工复核状态分开，不能编造金标准。

先检查当前代码再实施，持续完成本 change 的实现、恢复场景、检查和文档。交付数据与协议清单供下一 change 使用。达到验收后同步规格、归档并按约定创建/更新 PR；存在未完成项时保持真实状态并报告具体原因。
```

完成全部实际验收及文档后同步规格、归档并创建/更新对应 PR。不要扩大成新增算法、自动选择默认模型或行级产品化。

## 提示词 3：让不同账号的审查笔记真正分开

```text
请在 D:\code\jit-defect-prediction 实施 OpenSpec change：
isolate-account-review-drafts

先阅读 docs/计划/2026-11-15-change推进提示词.md 的通用约定，以及该 change 的全部规划。使用 openspec-apply-change 技能，遵守 AGENTS.md 和配置 schema。

目标是同一浏览器里 A、B 两个账户审查同一 PR 时，笔记、阅读进度、问题、结论和反馈分别保存。不能只给 localStorage 键拼用户名就收尾：账户身份必须经过服务端核验，切换账户时处理旧视图、迟到异步回调、自动保存、缓存和跨标签页事件。

旧全局工作单不要删除，也不要自动归给第一次登录的人。按设计实现显式导入预览、冲突合并、重复导入保护、旧备份兼容和写入失败恢复。工作单仍只存在本浏览器，不新增服务器同步或团队协作。

请用隔离账户和服务实际走通 A 保存、退出、B 同 PR 独立工作、A 返回续审，以及作者更新复核、备份恢复、旧记录迁移、跨标签页换号和延迟请求场景。保护未保存文本且不显示给其他账户。

完成必要测试、构建、浏览器验收和文档后同步规格、归档并按约定创建/更新独立 PR；如实报告实际执行范围。
```

## 提示词 4：把自动检查真正接起来

```text
请在 D:\code\jit-defect-prediction 实施 OpenSpec change：
add-continuous-regression

先阅读 docs/计划/2026-11-15-change推进提示词.md 的通用约定，以及该 change 的全部规划。使用 openspec-apply-change 技能，遵守 AGENTS.md 和配置 schema。

新增独立回归工作流，让 PR 和 main 推送执行关键后端、前端测试/类型检查/构建以及扩展测试；定期和手动完整层执行全部后端、前端、扩展及登记的浏览器旅程。已有模型风险报告继续独立运行，不以模型分数决定合并。

请先从干净检出验证依赖和夹具。不得依赖个人 SQLite、未跟踪数据、开发机模型目录或已启动服务。复用受校验模型包、固定数据和确定性 Git 夹具，在一次性目录和端口中运行。缺必需输入就明确失败，不靠 skip、continue-on-error 或改断言凑绿。

完成结果汇总、失败日志和浏览器 trace 收集，验证失败、超时、取消、端口冲突和再次执行。具备认证时观察真实 PR 关键检查；首次远端完整/定期运行依赖合入默认分支，按 follow-up 跟进，不把本地等价结果写成远端通过。不修改分支保护、自动部署或评论 PR。

完成本地及合入前可执行的验证、文档与格式校验后，按实际状态同步规格、归档和创建/更新独立 PR，清楚列出远端及平台边界。
```
