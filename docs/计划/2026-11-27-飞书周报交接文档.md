## 1. 前置：授权（每次开工先查）

所有命令都必须带 `--as user`。bot 身份看不到用户的云空间，`drive files list` 会**成功返回空列表**而不是报错，极易误判成"文件夹是空的"。

```bash
lark-cli auth status --json
```

检查两点：

- `identity` 是 `user`（不是 `bot`）；
- `identities.user.status` 为 `ready`，`tokenStatus` 不是 `expired`。

**token 大约一周就过期**（实测 10-06 授权、10-09 access 过期、10-16 refresh 过期；10-23 重授、10-30 又 expired）。`status` 显示 `needs_refresh` 时，下一次 user API 调用通常会自动刷新；如果仍是 `missing`，走设备码重授：

```bash
# 1. 发起，拿 verification_url 与 device_code（10 分钟有效）
lark-cli auth login --no-wait --json \
  --domain "docs,drive,wiki,base,sheets,markdown,contact,im,calendar,task"

# 2. 生成二维码（图片路径必须在 lark-cli 当前工作目录内）
lark-cli auth qrcode "<verification_url>" -o ./feishu-qr.png --size 320

# 3. 把 URL 和二维码发给用户，明确请其完成后告知；不要在同一轮阻塞等待

# 4. 用户确认后
lark-cli auth login --device-code "<device_code>"
```

成功标志：输出 `"event": "authorization_complete"`、`"missing": []`，再跑一次 `auth status` 确认 `identity` 为 `user`。

`--domain` 的逗号列表**必须整体加引号**（PowerShell 会把它当数组，导致 `unknown domain`）。

若 `auth login` 被 Bash 自动模式的分类器拦下：这是环境策略，不是命令错误。改成让用户在自己的终端执行，或写成脚本让用户跑；不要反复重试同一条命令。

## 4. 标准流程（含可直接执行的命令）

### 4.1 确定周期与命名

- 周期：**上周六 至 本周五**（例：2026-11-14 至 2026-11-20）。
- 文件名：`工作周报-YYYYMMDD`，取**本周五**日期（例：`工作周报-20261120`）。
- 本地时间用系统当前日期判断"本周五"。

### 4.2 取本周证据（先有事实，再写文档）

在仓库 `D:\code\jit-defect-prediction` 执行：

```bash
git log --since="<上周五 23:59>" --pretty=format:"%h|%ad|%an|%s" --date=format:"%m-%d %H:%M"
git log --since="<上周五 23:59>" --pretty=format:"%an" | sort | uniq -c      # 负责人归属
git log --since="<上周五 23:59>" --merges --pretty=format:"%h|%ad|%s" --date=format:"%m-%d" | grep -i "Merge pull request"
```

必看材料：

- `docs/审计/<本周日期>-*.md`：本周每项交付的实际行为、命令、数字、未完成项；
- `docs/evidence/`：verification.json、冻结清单、截图；
- 产品与验证口径：`docs/当前产品.md`、`docs/开发验证.md`、`docs/缺陷记录.md`、`docs/测试计划.md`；
- 已合并的 PR 号；
- `openspec/changes/`（未归档 = 仍在推进）与 `openspec/changes/archive/`（已归档数量）。

### 4.3 复制上一期

```bash
lark-cli drive +copy --token "<上一期 doc token>" --type docx \
  --folder-token "<04-工作周报 folder token>" \
  --name "工作周报-YYYYMMDD" --as user --json
```

返回 `file_token`（新文档）与 `url`。

**期初建骨架（只写计划、总结留空）**：改为复制模板（模板 doc token 见本机完整版 §2），步骤相同。

### 4.4 验证嵌入资源已独立（必做）

```bash
lark-cli docs +fetch --doc "<新 token>" --detail with-ids --as user --json
```

检查 `<sheet ... token="...">` 与 `<bitable ... token="...">` 是否都**不同于**上一期。
若相同，立即停止——说明是共享引用，继续改会污染上一期。

### 4.5 拿块 id

同一条 `--detail with-ids` 的返回里记下：

- `报告周期：` 所在的 `<p id="...">`（新文档若没有，就是 sheet 前那个空 `<p id="...">`）；
- 本周总结的 `<table id="...">`。

**每次 `block_replace` 之后块 id 会变**，后续每一步都要重新 fetch。

### 4.6 填本周计划（嵌入电子表格）

先读现状，确认表头与行数：

```bash
lark-cli sheets +csv-get --spreadsheet-token "<新 sheet token>" --sheet-id "LMRKR5" --as user --json
```

一次写满 `A2:F7`（6 行 × 6 列 = 36 格）。用 Python 生成载荷（Windows 必须设 UTF-8，否则 emoji 报 GBK 编码错误）：

```bash
cd "D:/code/jit-defect-prediction"
PYTHONIOENCODING=utf-8 python - <<'EOF' > cells.json
import json
rows = [
 ["事项一","❇️ 已完成",1,"荀浩","https://github.com/Sahier-hao/JIT","徐卓航"],
 ["事项二","🔛 进行中",0,"杨稳曌","https://...",""],
 # ……共 6 行
]
print(json.dumps([[{"value": v} for v in row] for row in rows], ensure_ascii=False))
EOF

lark-cli sheets +cells-set --spreadsheet-token "<新 sheet token>" --sheet-id "LMRKR5" \
  --range "A2:F7" --cells - < cells.json --as user --json
```

约定：

- 进度列文案与模板一致：`❇️ 已完成` / `🔛 进行中` / `⛑ 延期` / `🔹 未开始`（emoji 与空格都不要自造）；
- 已完成列写数字 `1` / `0`；
- 相关文档列一格多链接用换行 `\n` 分隔；
- 6 行必须写满；不足 6 项时补一行过程工作（归档、规格同步、文档收口），不要留空行。

### 4.7 填本周总结（文档原生表格）

先写 XML 到当前工作目录（`--content @./x.xml` 只接受 cwd 内的相对路径）：

```xml
<table><colgroup><col width="268"/><col width="247"/><col width="300"/></colgroup>
<tbody>
<tr><td vertical-align="top"><p><b>已完成内容</b></p></td><td vertical-align="top"><p><b>证明材料</b></p></td><td vertical-align="top"><p><b>待改进内容</b></p></td></tr>
<tr><td vertical-align="top"><p><b>主题一</b>：……</p></td><td vertical-align="top"><p><a href="https://github.com/Sahier-hao/JIT/pull/70">PR #70</a>；docs/审计/xxx.md</p></td><td vertical-align="top"><p>……</p></td></tr>
<!-- 共 4 行事项 -->
</tbody></table>
```

```bash
lark-cli docs +update --doc "<新 token>" --command block_replace \
  --block-id "<总结表 id>" --content "@./summary_table.xml" --as user --json
```

注意：

- 必须传**完整** `<table>`（含 `<colgroup>`、表头行、全部数据行），不能只传片段；
- XML 里的 `&` 写成 `&amp;`（如 `Wide &amp; Deep`）；
- 行数 = 表头 1 + 事项 4。

### 4.8 填报告周期（导语段）

位置在「本周计划」说明块之后、计划表之前。XML：

```xml
<p><b>报告周期：</b>2026-11-14 至 2026-11-20。本周……（3 句以内，含关键数字）。负责人按仓库能力席位记录，实名对应与截止时间由团队确认。</p>
```

```bash
lark-cli docs +update --doc "<新 token>" --command block_replace \
  --block-id "<报告周期 p 的 id>" --content "@./intro.xml" --as user --json
```

**从上一期复制的文档里已经带着上一期的「报告周期」段**：要**替换那一段**，不要往空段落里再插一段，否则会出现两个周期。
判断方法：fetch 后搜索文本包含 `报告周期：` 的 `<p>`，用它的 id 替换。

### 4.9 填下周计划（嵌入多维表格）

```bash
lark-cli base +field-list   --base-token "<新 bitable token>" --table-id "<table-id>" --as user --json
lark-cli base +record-list  --base-token "<新 bitable token>" --table-id "<table-id>" --as user --json
```

`record-list` 返回 `record_id_list` 与 `data`（同序二维数组）。字段名必须逐字匹配：

`计划` / `执行人` / `进度` / `相关附件（点击上传）` / `相关链接（粘贴云文档链接）`

更新已有 6 条：

```bash
lark-cli base +record-batch-update --base-token "<token>" --table-id "<table-id>" \
  --as user --json '{"update_records":{"recXXX":{"计划":"…","执行人":"…","进度":0,"相关链接（粘贴云文档链接）":"https://…"}}}'
```

不足 6 条时补：

```bash
lark-cli base +record-batch-create --base-token "<token>" --table-id "<table-id>" \
  --as user --json '{"create_records":[{"计划":"…","执行人":"…","进度":0,"相关链接（粘贴云文档链接）":"https://…"}]}'
```

**关键细节**：

- **进度字段是 0–1 的小数**：`0.4` = 40%，`0` = 0%。写 `40` 会被截成 0（已踩过）。
- 附件字段不要写值。
- `+record-batch-update` / `+record-batch-create` 的 `--json` **既是载荷参数又是输出格式简写**：同一条命令里只能出现一次（载荷那次），不要再追加输出用的 `--json`，否则报 `flag needs an argument: --json`。
- Windows 下含中文的载荷建议先用 Python 生成 JSON 文件，再 `--json "$(cat payload.json)"`，避免引号/编码问题。

### 4.10 回读验收（必做，`ok: true` 不等于写对）

```bash
lark-cli docs +fetch --doc "<新 token>" --as user --json
lark-cli sheets +csv-get --spreadsheet-token "<sheet token>" --sheet-id "LMRKR5" --as user --json
lark-cli base +record-list --base-token "<bitable token>" --table-id "<table-id>" --as user --json
```

逐项确认：

- `<title>` 是新日期；
- 周期是新周期，旧周期字符串不再出现，且 `报告周期` 只出现一次；
- 仍有 `<sheet>` 与 `<bitable>`，且 token 是新复制出来的；
- 总结表 `<tr>` 数 = 1 + 事项数（通常 5）；
- 文档里没有模板占位（`......`、`输入 @ 插入相关文档`）；
- 计划表 `actual_range` 为 `A1:F7`，6 行内容正确；
- 多维表格正好 6 条，字段与进度正确。

## 5. 写作口径（比命令更容易出错的部分）

- **只写能指到文件的数字**：测试数、耗时、指标、记录数必须来自 `docs/审计/`、`docs/evidence/`、`verification.json`；不要估算，不要用"约""大概"包装没跑过的结果。
- **计划与兑现对齐**：本周计划表的 6 行应来自上一期「下周计划」；写总结时逐项对照，完成写 `❇️ 已完成` + `1`，有进展未完成写 `🔛 进行中`，没动写 `⛑ 延期`。
- **待改进写真实短板**：不利结果、未合并分支、未验证路径、接近预算的性能、缺失证据，都要写；上期就保留了"模型打不过密度基线"的负结果。
- **不把未运行的事写成通过**：本地通过 ≠ 远端通过；未合入默认分支的 workflow 不会对 PR 触发。
- **不写工作时间、不写"夜间"命名**：只写工程事实。
- **负责人映射**：`Sahier-hao` / `Sahier` = 荀浩，`tide` = 杨稳曌，`徐卓航` = 徐卓航；协作方按实际参与者写。
- **团队负责人是荀浩**，周报由组长汇总；不要代签他人的验收结论。

### 本周总结的推荐骨架（4 行）

1. **模型与方法**：新增方法、同口径指标、最好/最差；
2. **数据与链路**：数据集、采集、解释与预算；
3. **产品**：工作区边界、记录与重试、真实库核对到的数字；
4. **工程与质量**：模型登记、迁移、测试数、规格校验、性能。

每行配 GitHub PR / 审计文档链接；「待改进」写 AUC/召回差距、未合并分支、未归档证据、性能余量。

## 6. 实战踩坑清单

| 坑 | 现象 | 处理 |
| --- | --- | --- |
| bot 身份 | 查询成功但返回空列表 | 所有命令加 `--as user` |
| token 过期 | `token_missing` / `identity: missing` | 走设备码重授，不要用 bot 兜底 |
| 从零建周报 | 只有文档原生表格 | 永远复制上一期或模板 |
| 复制后 token 没变 | 改到上一期 | 立即停止 |
| block id 复用 | `block not found` | 每次 replace 后重新 fetch |
| 表格传片段 | 解析失败或丢列 | 传完整 `<table>` 含 `<colgroup>` |
| `&` 未转义 | XML 解析失败 | 写 `&amp;` |
| 计划表只写 5 行 | 第 6 行残留旧内容 | 一次写满 `A2:F7` |
| 多维表格进度写 40 | 显示 0% | 写 `0.4`（0–1 小数） |
| 同一条命令两个 `--json` | `flag needs an argument: --json` | 只保留载荷那个 |
| 解析 JSON 时 `2>&1` | `json.load` 第 0 字符失败 | 数据走 stdout，提示走 stderr，分两次跑 |
| 绝对路径传给 lark-cli | `unsafe file path` | 先把文件放到 cwd，或 `--content` / `--cells` 用 `-` 走 stdin |
| Windows 控制台 GBK | emoji 触发 `UnicodeEncodeError` | `PYTHONIOENCODING=utf-8 python …` |
| 复制后有两个报告周期 | 旧周期段未替换 | 搜 `报告周期：` 定位旧段并替换 |
| 删除文档 | 退出码 10 | `drive +delete` 是 high-risk-write，必须先告知用户并取得明确同意再加 `--yes` |

---

## 7. 排查速查

| 现象 | 先查什么 |
| --- | --- |
| `--as user` 报未授权 | `lark-cli auth status --json`；`identity` 是否 `user` |
| 文件夹列表为空 | 是否漏了 `--as user`；换个 `folder-token` 再试 |
| `docs +fetch` 没有 id | 补 `--detail with-ids` |
| `sheets +csv-get` 报 sheet 不存在 | sheet token 与 sheet-id（`LMRKR5`）是否配错期 |
| 多维表格字段写不进去 | `+field-list` 核对字段名是否逐字一致 |
| 写入返回 `ok: true` 但内容没变 | 回读三段；很可能 block id 过期或写到了旧 token |

## 8. 交付时对用户说什么

- 给出周报链接（`url` 字段）；
- 说明三段分别是什么块类型（嵌入电子表格 / 文档表格 / 嵌入多维表格）；
- 说明本期计划的兑现情况（几项完成、几项进行中、几项延期）；
- 说明哪些内容未合并、未验证、证据未归档；
- 若同时生成了 PPT，给出 PPT 链接。
