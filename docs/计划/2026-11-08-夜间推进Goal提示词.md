二、优先级 A：打通多算法训练实验闭环，必须完成

目标旅程：管理员打开固定数据集版本 → 预览并选择时间切分 → 选择多个真实支持的方法 → 设置受控参数 → 一次提交实验 → 查看各子任务及真实训练过程 → 比较同一口径结果 → 显式选择产物登记 → 项目显式选择该模型进行分析。

1. 在现有管理数据集/训练工作区扩展，不另建平行系统。单方法训练继续可用；多方法实验复用现有训练执行链，设计持久实验组与子任务引用。
2. 实验创建时冻结数据版本、内容哈希、特征 schema、切分预设及实际成员指纹、类别策略、种子、方法和解析后的参数。各方法使用完全相同的 train/validation/test 原始成员。归一化、缺失值处理、采样等只在训练分区拟合/执行。
3. 参数采用按方法声明的白名单、类型、范围及组合校验，先支持少量有用参数，例如 LR 的 C、树的深度/叶子下限、RF 的树数、MLP 的 epochs/lr/batch_size。限制规模，避免无界网格搜索。不允许任意 estimator、Python 表达式或服务端路径。
4. 保留已发布方法和旧产物的冻结身份、参数与校验语义。新参数配置必须有独立、可核对的配置摘要和运行身份；不能修改全局注册表后让同一个旧模型标识指向另一套参数。请求、数据库、重试、worker、运行清单、加载校验和模型卡必须贯通实际配置。
   旧 v1 方法继续按原冻结参数严格校验；可配置训练采用版本化参数契约并贯通加载校验。固定 epoch 指每次运行开始前锁定次数且不早停，不要求新配置一律使用旧次数；只添加配置哈希而没有更新对应加载契约不算完成。
5. 多方法批次必须处理：双击/重复请求、排队、部分成功、单方法失败、取消、显式重试、刷新与重新打开、服务重启中断。批次失败或取消不破坏已成功产物。参数不同不得错误复用同一任务；重试保留原数据、切分、方法和参数。缺依赖或不兼容要明确显示，不自动换算法。
6. 训练过程来自真实执行。对 MLP 等迭代方法保存 epoch、聚合 train loss、时间；在工程代价合理时加入只读 validation loss。测试集不进入逐 epoch 监控，也不参与阈值/参数选择。保持现有固定 epoch 协议，不悄悄加入早停。记录应能跨刷新读取；失败/取消保留已有有效历史，并显示实际终态。
7. 非迭代方法显示真实阶段、耗时和最终诊断，明确其无逐 epoch 曲线；不能为决策树、朴素贝叶斯编造下降曲线。历史模型没有训练历史就显示未记录，不补画推测曲线。图表复用现有 ECharts 与组件风格，不为了图表引入新框架。
8. 比较页复用已有比较事实和指标定义，展示方法、实际参数、数据/切分身份、三档指标、耗时和失败原因；口径不同明确不可直接比较。优先展示 PR-AUC、ROC-AUC、MCC、F1、Precision/Recall 与已有成本感知收益指标中的可用项，未定义就说明原因。训练集指标不作为泛化证据，单样本预测不显示伪造的 AUC/F1。
9. 参数先冻结再训练。本夜不做自动超参搜索或按测试指标选冠军；若需要推荐，只能依照事先声明的验证分区规则，保留全部结果。测试指标只供冻结评价。不得因看到某个测试结果就反复换切分、种子、特征和阈值刷分。
10. 比较记录可导出，至少包含配置、数据/成员指纹、各任务和产物身份、指标、失败状态及版本信息。训练成功仍需显式登记，不能自动改默认模型。普通用户模型卡只暴露必要的安全投影。

A 的验收：至少 LR、DT、RF 与一个已安装的 MLP 方法完成真实执行；先用隔离确定性夹具验证流程，再对一个来源可核对、两类与三档样本足够的真实版本执行固定方案。人工/自动浏览器实际走通创建、刷新、离开重开、部分失败、重试、取消、结果比较、显式登记和项目选用；核对结果中的模型、方法、参数及切分身份。夹具的指标只能证明流程，真实数据的指标单独报告。依赖或真实数据不足时不得伪称相应验收通过，应继续处理可解决的原因并推进其他授权工作。

六、持续工作规则

1. 每轮按“实现/实验 → 受影响验证 → 阅读失败 → 修复 → 完整旅程 → 下一功能包”推进。一个模块验收完成就进入下一模块，不以“已提交”“tasks 全勾”“已归档”“PR 已创建”“后续建议”代替后续实施。所有阶段共用本 Goal，不能把某个 change 的完成当成总 Goal 完成。
2. 在 docs/计划/ 下维护一份简短的进展台账：当前任务、已验证事实、失败/阻塞、下一条可执行命令和证据路径。上下文压缩后从这里恢复，避免从头扫描。进展台账与面向产品的文档分开。
3. 普通实现决策和受影响检查自主完成。需要用户作出真正有后果的选择时，给出具体推荐并记录；用户睡觉时先推进不依赖该选择的任务，不把一个可隔离阻塞当成全项目无法工作。
4. 同一失败重复出现时，先读日志/源码定位并改变方法，不机械重试。网络、凭据、数据规模和算力限制分别处理。外部权限障碍不得绕过，也不得把尚未运行的验收标成成功。
5. 可以委派边界明确的子代理做互不重叠的实现、测试或审查；主代理负责集成与真实验收。不得让多个代理编辑同一文件、共用可写测试数据库，或启动冲突服务。委派后自己继续推进主线，不空等。
6. 工作期间持续给简短进展；结束时给一份总交付。目标是完成有价值且可核验的工作，不设毫无意义的最低 token 消耗或必须等到天亮的限制。

七、保护现有项目与数据

1. 遵守 AGENTS.md 的服务器权限边界：模型维护、全局数据集和实验管理仅限认证管理工作区；项目侧只暴露必要的绑定数据和安全模型投影。不要因为图片写“用户选择算法”就把管理接口匿名开放。
2. 现有项目、模型、运行、SQLite、原始/派生数据集及个人草稿必须保留。迁移用前向增量并先做一致备份；验证在可丢弃数据库、独立产物目录和独立端口运行。不停止其他会话服务，不做全库重置，不覆盖九模型包和旧证据。
3. UI 复用当前设计体系，保留必要状态与动作；不堆装饰小字，不新建重复入口。模型加载失败不能静默替换，旧模型缺历史不能伪造补齐。
4. 默认保持既有时间切分预设，不开放任意随机切分和任意上传带标签 CSV。若确有实现必要，先在设计里给出兼容方案，不能为套图而破坏当前数据治理。
