## 二、本次要做什么

把**有 shadcn 对应物的标准控件**改为以 shadcn/ui 官方组件源码为底，而不是继续维护手写实现；产品自有形状不强行套。

优先顺序：

1. **明显该换的**：`Drawer`→`Sheet`、`Popconfirm`→`AlertDialog`、`Segmented`→`ToggleGroup`、`Progress`→Radix `Progress`、`Alert`/`Tag`→`Alert`/`Badge` 结构。
2. **核心控件对齐**：`Button`、`Input`、`TextArea`、`Select`、`Checkbox`、`Switch`、`Dialog`、`DropdownMenu`、`Popover`、`Tooltip` 以 shadcn 源码为底，保留一层薄适配（variant 名称映射、`icon/loading`、`width`、`options` 等），或逐个更新调用点。
3. **数据结构对齐**：`Table`、`Card` 按 shadcn 结构组织，但继续使用 `h-row`、`px-cell-x`、`p-card` 等密度工具类。
4. **保留自写**：`PageHeader`、`SectionHeader`、`TabBar`、`Empty`、`Space`、`CodeDiff`、`chart`、`Icon`、`EntryChrome`、业务卡片。

## 三、硬约束

- **不要运行 `shadcn init`**。它会重写 `index.css`、引入第二套变量文件，和 `tokens.css` 的四主题契约冲突。只复制需要的组件源码并按现有令牌改造。
- 不新增页面级 CSS；`npm run check:styles` 只允许四个样式表。
- 不引入 shadcn 的 oklch 调色板；颜色一律走 `@theme inline` 的语义令牌。
- 保留四套主题、两档密度、焦点可见、`prefers-reduced-motion`。
- 页面-facing API 优先保持；确需改调用点时，改动要可审查，不顺手改业务行为。
- 保留现有测试契约；不要用放宽断言来掩盖行为变化。若组件角色变化（例如 `Segmented` 从 `radio` 变 `ToggleGroup`），先确认测试与无障碍语义，再同步更新。
- `Dropdown` 当前 `modal={false}`，测试依赖打开菜单时背景仍可访问；改 shadcn 结构时保留。
- Windows 上 `python3` 不可用，使用 `python`；Playwright 使用 `msedge`。

不要一次加齐未用到的包；每个包随对应组件一起加。

## 五、已知坑

1. `Button` 的 `href` 分支与 Radix `asChild` 需要 `Slot`，同时保持 `forwardRef`/React 19 ref 传递。
2. `Select` 测试此前从 `toHaveValue` 改为 `toHaveTextContent`；换成 shadcn Select 后仍要确认选中值可读。
3. `Segmented` 角色变化会影响 `ProjectPage` 等页面测试；先列出所有 `getByRole('radio')`/`button` 查询再改。
4. `Popconfirm` 从 Popover 换成 AlertDialog 后，触发器、焦点返回、Esc 行为要补测试。
5. `Drawer` 换成 Sheet 后，保留 `width`、`title`、`onClose` 语义；项目页、PR 工作单、交付/备份抽屉都依赖它。
6. `Progress` 换 Radix 后仍要保留 `role="progressbar"`、`aria-valuenow` 和现有测试断言。
7. shadcn 组件的默认 `className` 使用 `bg-background` 等变量；本项目已映射，但 `destructive` 对应 `risk-high`，不要直接用 shadcn 默认红色。
8. 动画：可以引入 `data-[state]` 过渡，但不要新增 `tailwindcss-animate` 之外的样式文件；`prefers-reduced-motion` 必须继续生效。
9. 视觉核对至少覆盖：入口、项目详情/分析、PR 列表/预览/工作单、个人工作区、管理端模型/数据集/报告，浅色与深色。
