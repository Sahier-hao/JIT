## 一、结论先行

上一轮只做到“shadcn 形态 + 手写实现”，这是不够的。标准控件应该直接以 shadcn/ui 官方组件源码为底，页面调用点跟着改；**不要以“保留旧 API”或“工作量”为理由继续维护自写控件**。自写组件不比 shadcn 原生好，也没有必要维护第二套。

本交接的口径是：**应改尽改**。凡是 shadcn/ui 有对应组件的，都用它的源码；没有对应组件的产品形状，也用 shadcn 的基础组件和工具类组合，不再保留自写控件；只有业务布局与第三方渲染保留。

## 二、当前状态

- 样式表 4 个：`src/index.css`、`src/styles/tokens.css`、`src/styles/base.css`、`src/styles/content.css`；CSS 约 716 行；preflight 已启用。
- 四套主题（`concrete`/`steel`/`charcoal`/`paper`）、两档密度（`comfortable`/`compact`）；`index.css` 的 `@theme inline` 已映射 shadcn 常用变量名。
- `src/ui` 目前是 Radix + CVA + Tailwind 的手写实现，不是 shadcn 源码。
- 没有 `components.json`，没有运行过 `shadcn init`，`package.json` 没有 `shadcn` 依赖。
- 测试基线：59 个测试文件、433 项；`typecheck`、`lint`、`build`、`check:styles` 通过；PR 续审浏览器旅程通过。

## 三、必须替换的组件

### 1. 直接替换为 shadcn 源码

| 当前 | 目标 | 备注 |
|---|---|---|
| `Button` / `IconButton` | shadcn `Button` | 用 shadcn 的 variant 名；`icon/loading/block` 改由调用点组合或扩展 CVA，不再保留旧 props 兼容层 |
| `Input` / `TextArea` / `NumberInput` / `PasswordInput` | shadcn `Input` / `Textarea` | 密码可见性、清除按钮作为业务组合，不再塞进基础 Input |
| `Select` | shadcn `Select` | 页面调用点改为复合 API；保留业务选项数据 |
| `Checkbox` / `Switch` | shadcn `Checkbox` / `Switch` | 直接用 |
| `Dialog` | shadcn `Dialog` | 页面调用点改为 Trigger/Content/Header/Title/Footer 组合 |
| `Popconfirm` | shadcn `AlertDialog` | 语义正确；触发、焦点、Esc 用原生行为 |
| `Drawer` | shadcn `Sheet` | 项目页、PR 工作单、交付/备份抽屉都改调用点 |
| `Dropdown` | shadcn `DropdownMenu` | 保留 `modal={false}` 的既有行为要求 |
| `Popover` / `Tooltip` | shadcn `Popover` / `Tooltip` | 直接用 |
| `Tag` | shadcn `Badge` | 删除 Tag |
| `Alert` / `InlineAlert` | shadcn `Alert` | 统一为一种 Alert |
| `Progress` | shadcn `Progress`（Radix Progress） | 直接替换 |
| `Segmented` | shadcn `ToggleGroup` 或 `Tabs` | 按语义选；页面调用点同步改 |
| `Table` | shadcn `Table` 原语 | 保留 `h-row`、`px-cell-x` 等密度工具类 |
| `Card` | shadcn `Card` | 保留 `p-card` 密度 |
| `Space` | 删除 | 调用点直接用 `flex gap-*` |
| `Icon` | 直接使用 `lucide-react` | 与 shadcn 一致；品牌标志可保留自绘 |

### 2. 产品形状：用 shadcn 基础组件组合，不保留自写控件

- `PageHeader`、`SectionHeader`：用 shadcn `Card`/`Badge`/排版工具类组合，或直接在页面内组合；不要再维护独立控件实现。
- `TabBar`：改用 shadcn `Tabs`（Radix Tabs），页面导航调用点同步改。
- `Empty`：用 shadcn `Card` + `Button` + 排版组合成业务组件；这是业务组合，不是替代 shadcn 的标准控件。
- `EntryChrome`、`AppShell`、业务卡片：布局组合，保留；但内部按钮、输入、对话框必须来自 shadcn。

### 3. 不替换

- `CodeDiff`：react-diff-view 负责代码差异渲染，保留。
- `chart`：ECharts 封装，保留（颜色继续走令牌）。
- 业务数据转换、路由、状态管理、请求层不动。

## 四、硬约束

- **不要运行 `shadcn init`**：会重写 `index.css`、引入 oklch 变量文件，与 `tokens.css` 的四主题契约冲突。复制组件源码，按现有令牌改造。
- 不新增页面级 CSS；`npm run check:styles` 只允许四个样式表。
- 颜色、圆角、字号、间距继续走 `tokens.css` 与 `index.css` 的 `@theme inline`；`destructive` 映射到 `risk-high`，不要用 shadcn 默认红色。
- 保留四套主题、两档密度、焦点可见、`prefers-reduced-motion`。
- **允许并鼓励改页面调用点**。不要为了少改调用点保留旧 props；业务行为不变，props 可以换。
- 测试断言可以随组件角色变化更新，但必须保留被测行为；不得用放宽断言掩盖回退。
- `Dropdown` 保持 `modal={false}`。
- Windows 用 `python`，不要用 `python3`；Playwright 用 `msedge`。

2. **表单与浮层**：Select、Checkbox、Switch、Dialog、AlertDialog、Sheet、DropdownMenu、Popover、Tooltip。
3. **清理**：删除 `Tag`、`InlineAlert`、`Segmented`、`Popconfirm`、`Drawer`、`Space`、`Icon` 等被替代的实现；全仓确认没有页面再引用旧导出。
4. **视觉与验收**：关键页面双主题截图、四主题契约测试、PR 续审旅程；更新 README、设计规范、审计记录。

每批独立提交，提交信息中文 + Conventional Commits 前缀；不要把所有批次压成一个巨大 diff。

## 七、已知坑

1. `Button asChild` 需要 `Slot`；同时处理 React 19 ref 传递。
2. shadcn `Select` 是复合 API；现有 `options` 数据要转成 `SelectItem`，页面测试的 `combobox` 断言要同步改。
3. `Segmented` 换成 `ToggleGroup`/`Tabs` 后角色变化，先列出所有 `getByRole('radio')`、`button` 查询再改。
4. `Popconfirm` 换 `AlertDialog` 后，触发器和焦点返回要补测试。
5. `Drawer` 换 `Sheet` 后，项目页、PR 工作单、交付/备份抽屉都要改；宽度、标题、关闭语义保留。
6. `Progress` 换 Radix 后保留 `role="progressbar"`、`aria-valuenow`。
7. shadcn 组件默认 `bg-background` 等变量已经映射；但 `primary` 是近黑按钮，`destructive` 是风险色，不要换成 shadcn 默认蓝/红。
8. 动画可用 `data-[state]` 过渡；不要新增 `tailwindcss-animate` 之外的样式文件；`prefers-reduced-motion` 必须继续生效。
9. 视觉核对至少覆盖：入口、项目详情/分析、PR 列表/预览/工作单、个人工作区、管理端模型/数据集/报告，浅色与深色。
